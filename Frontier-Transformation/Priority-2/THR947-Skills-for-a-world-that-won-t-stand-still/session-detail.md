Sarah 氏は、約 5,000 人の技術部門の人材育成を担当しています。新卒向けプログラム、AI Skills Navigator の活用、マネージャーによる実践的なワークセッション、失敗から得た教訓などを具体的に語っています。最も強調されたのは、**技術やツールよりも先に「人」に向き合う**という点です。画面を使ったデモは行われていません。

## 5. 発表内容の詳細

### 5.1 登壇者の紹介と背景

Sarah 氏は LexisNexis Risk Solutions に 12 年強在籍しています。入社時は Linux システムエンジニアとしてデータセンターで働き、その後は SRE（サイト信頼性エンジニアリング）や DevOps の役割に移り、社内の変革に関わってきました。約 2 年前に、現在のテクノロジー最適化ディレクターになっています。

この役割では、技術部門の全チームのスキル向上と、ツールやプロセスを使いこなすための支援を担当します。対象は技術部門だけで約 5,000 人を超えます。研修の種類は、ソフトスキル、技術、マネージャー向けなど幅広く、技術職の新卒採用プログラムである Tech Accelerate graduate program も運営しています。

### 5.2 解決したかった課題

最大の課題は、**全員が同じ出発点にいない**ことでした。スキルも自信の度合いも違い、AI の使い方もそれぞれ異なります。「自分の役割はどう変わるのか」を知りたい人も多く、これに答えるのは簡単ではなかったと Sarah 氏は説明しています。

そこで、役割とレベルに合わせて複数の研修・プログラムを用意しました。すでに使いこなしている上級者のチームにはセキュリティなどに重点を置き、まだ自信のない人には、まず簡単なことから試して慣れてもらう、という使い分けです。

### 5.3 新卒向けパスウェイ：Tech Accelerate graduate program

Tech Accelerate graduate program は、大学卒業直後のソフトウェアエンジニアを迎える、12 か月のローテーション型プログラムです。6 か月ずつ 2 つの異なるチームを経験します。インターンではなく、期間中ずっとフルタイム社員です。

特徴は次のとおりです。

- 初日から GitHub Copilot と Microsoft 365 Copilot、社内ツールを使える
- 実際のチームに配属され、スタンドアップにも参加し、意味のある仕事で貢献する
- Microsoft と連携し、入社時に GitHub の基礎研修やベストプラクティスの指導を受ける
- セキュリティ研修を多く受ける
- 12 か月を通じて、研修とアクセス権の提供に加え、実際のプロジェクトでの実践を行う

Jen 氏は、最初から土台を作る賢明な設計だと評価しています。

### 5.4 AI Skills Navigator と複数の学習形態の組み合わせ

Sarah 氏は、人によって学び方が違うため、早い段階から複数の形式を併用したと説明しています。対面のワークショップ、質問ができるライブセッション、自習の 3 種類です。

AI Skills Navigator は、全員に合わせた学習パスを個別に作るのは不可能だった点を補いました。例えば QA エンジニアが「AI は全く分からない。ここから始めたい。プレイリストを作って」と伝えると、その人向けのプレイリストが作られ、学び始める場所ができます。これにより、全員が初日から学習にアクセスできるようになりました。

もう 1 つ役立ったのは、Microsoft が技術部門の全マネージャーに向けて、AI Skills Navigator の使い方と、チームに使わせる方法を説明したことです。マネージャーはプレイリストを作ってチームに割り当てられ、チーム内で「このプレイリストは良かった、一緒にやろう」と共有もできます。Sarah 氏は、これにより自然発生的な学習が生まれたと述べています。

Jen 氏は、これを「高い技術と、高い人間的な関わり」の組み合わせと表現しました。AI Skills Navigator で規模を確保しつつ個別の要望に応え、そこにマネージャーが加わって、人が技術とともにどう学ぶかを見ることが、変革で最も成果が出る形だという考えです。

### 5.5 リーダーが来週カレンダーに入れるべきこと

「チームを AI に備えさせたいリーダーが、来週カレンダーに入れるべき 1 つの行動と、30 日以内に効果を見極める目印は何か」という質問に、Sarah 氏はこう答えています。

- マネージャーがチームとワークセッションを開く。ツールよりも人が大事で、一緒に手を動かして課題を解くときに最も成果が出る
- 実際に行ったワークショップも「課題を持ち寄り、ツールの使い方と解き方を示す」形式だった
- 題材は、繰り返しの多いプロセスにする。チームに「何にいら立っているか」「時間を取られている作業は何か」「今は手作業だが自動化したいことは何か」を尋ね、一緒に AI やツールでどう改善できるかを考える
- 効果が出ているかは、チーム内で結果として見える。結果が語ってくれる

### 5.6 マイクロウィンの例

Jen 氏は、変革というと大きな出来事を想像するが、成功しやすいのは 5 分単位のような**小さな成功（マイクロウィン）**を見つけたときだと述べ、例を尋ねました。

Sarah 氏は、ソフトウェア開発向けの AI ツールを展開する際に、チームが集まってモブ形式（全員で 1 つの課題に取り組む形式）で課題を解くワークショップを開いたと説明しています。最後に発表と共有を行うと、「普通なら 1 か月かかる作業が 2 日でできた」と話すチームが出て、気づきの瞬間が生まれ、そこから自然に広がっていきます。誰かが何かを作る、エージェントやスキルを作ってみて「これだ」と腑に落ちる。それをチームに共有すると、リーダーや研修担当ではなく、**同僚から伝わる**ため、変化が定着しやすい、という説明です。

Jen 氏は、共同作業の効用についても触れ、1 つのプロジェクトで一緒に取り組み、他の人のやり方を見ることで小さな成功が触媒になると述べました。

### 5.7 素早い失敗（フェイルファスト）の経験

Sarah 氏が挙げた失敗は、全員を対象にした大規模な研修では通用しなかった、という経験です。Copilot が登場したときは、全員向けの研修を数多く実施しようと意気込みましたが、「Copilot でできる素晴らしいこと」を並べるだけでは不十分で、実際のユースケースが必要でした。プロジェクトマネージャーの日常とソフトウェアエンジニアの日常はまったく違うからです。

そこで一度立ち止まり、**レベル別・役割別にグループ分けして、そのグループに焦点を当てた研修**に切り替えました。全員への一斉展開ではなく、ツールと、役割に応じて異なる人の使い方の両方を見る、というのが変革の大きな部分だったと述べています。

Jen 氏は、小さな学習と実践を繰り返す学び方に触れ、そうした小さな失敗から学び続ける姿勢が大きな成果につながると応じました。

### 5.8 やり直せるなら変えたいこと

Sarah 氏は、**最初に人に注力する**と答えています。最大の障害は人でした。不安や恐れなど、さまざまな感情があったためです。「新しいツールだから使って」と伝えるのではなく、まず役割がどう変わるのか、本人が何を経験しているのかを理解すべきだったと述べています。

伝えるべきメッセージは「AI が何をできるか」ではなく「AI があるから、あなたに何ができるか」です。最初から、その人たちが価値ある役割を担い、人が必ず関与し続け、支援する立場であることを明確に伝える必要があります。AI が来て全部やってしまう、という受け止め方を避けるためです。チームの働き方が根本的にどう変わり、互いにどう協力するかという**変更管理**が決定的に重要だった、と話しています。

Jen 氏は、変革を急ぐあまり人を後回しにしがちだと指摘しました。最も早く遠くまで進む組織は、安心できる環境と盛り上がりを作り、リーダーとチャンピオン（推進役）のグループが文化を支え、コミュニティとして盛り上がりつつ、失敗してよい・不安があってよい、と認めているという考えです。

### 5.9 これから先

Sarah 氏は、変化は避けられず、また変わるだろうと述べています。従業員に「居心地の悪さに慣れる」ことを促しており、研修の焦点が急に変わって新しいものが現れることもあります。そのため、変更管理や批判的思考といった、本人は技術的なスキルだと考えているソフトスキル系の研修を増やしています。

具体的には、考える演習を通じて、自分がコントロールできることとできないことを見分け、「空が落ちてくる、何も制御できない」という状態から、「できないことはできない。では、何をコントロールでき、何に影響を与えられるか」へ切り替える練習をしています。今後 1 年は、人に重点を置いて支援することが中心になると述べています。

Jen 氏は、技術部門は速い環境に慣れているが、今回の変革は IT 部門だけのものではなく、人事や財務など、そうした機敏さに慣れていない部門も含むと指摘しました。人間のスキルを土台にすることが、変更管理と機敏さを支えるという考えです。

### 5.10 質疑応答と案内

会場からの質問は、この録音には含まれていません。Jen 氏は、質問はステージ脇で受けると述べています。Sarah 氏の最後の発言は、Microsoft の支援への謝辞です。変革は支援がなければずっと難しかっただろう、と述べています。

Jen 氏は終わりに、Microsoft と協働する魅力として、次の大きなものを売り込むためではなく、スキル習得を通じて人々の人生を豊かにし、変えるために取り組んでいることを挙げ、「毎朝起きるのが楽しい」と語りました。そのうえで、次の案内をしました。

- QR コードから、**最高人事責任者向けの Frontier Transformation** の情報をいち早く受け取れる。IT 主導だけでなく人主導の取り組みでもあるため
- 会場のハブ（展示エリア）では、デモが見られ、AI Skills Navigator も体験できる。ビジネス上のニーズがあれば、AI Skills Navigator について個別の質問にも答える

## 7. 注意点・発表者の気付き

- 全員向けの一斉研修は効果が薄い。レベルと役割でグループ分けし、実際のユースケースで教える必要があった
- 最大の障害は人の不安や感情だった。AI ができることではなく、AI があるから本人にできることを、最初から明確に伝えるべきだった
- 研修の焦点は今後も急に変わりうる。変化に慣れる力を育てる必要がある
- ツールの紹介ではなく、実際の課題を持ち寄って一緒に解くワークセッションが成果につながる
- 変革は IT 部門だけでなく、人事・財務など、機敏さに慣れていない部門にも及ぶ

## 8. 利用者にとっての利点

発表で語られた効果と事例は次のとおりです。具体的な数値は、ここに挙げたもの以外は語られていません。

- AI Skills Navigator により、役割や経験が異なる技術部門（約 5,000 人超）でも、全員が初日から学習へアクセスできるようにした、と語られました
- マネージャーがプレイリストを作成・割り当て・共有でき、チーム内で学びが自然に広がった
- 新卒のエンジニアは、初日から GitHub Copilot と Microsoft 365 Copilot を使いながら、チームで実際の仕事に貢献できる
- モブ形式のワークショップで、普通なら 1 か月かかる作業が 2 日でできたと話すチームが出て、同僚による共有が広がる契機になった

## 9. まとめ

LexisNexis Risk Solutions の取り組みから見えるのは、AI スキル習得は技術の問題である前に、人と変更管理の問題だという点です。出発点の違う人たちに合わせ、役割・レベル別に研修を設計し、AI Skills Navigator で個別化を規模に乗せ、マネージャーが実際の課題を扱うワークセッションを開く、という組み合わせが語られました。

最初の一歩は、チームで繰り返しの多い作業を 1 つ選び、AI でどう改善できるかを一緒に試す、小さな成功の積み重ねです。そして、変化は続くという前提で、変化の中で自分にできることを見極める力を育てることが、今後の焦点として示されました。
