# THR959 Credly in action: Unlocking the full value of your credential

## 1. はじめに

このセッションは、デジタルバッジの発行基盤 Credly を担当する Pearson の Billy Greco 氏が、「AI が履歴書や面接の信頼性を崩した時代に、スキルの証明をどう検証可能にするか」を説明する約 20 分の発表です。Microsoft の認定（Certifications）が Credly 経由で署名付きの検証可能なクレデンシャルとして発行されていること、Microsoft の新しい Pro badge（GitHub Copilot の利用実績にもとづくバッジ）、企業向けの **Credly Workforce**、そして今後の **Pearson Wallet** が順に紹介されます。

## 5. 発表内容の詳細

### 5.1 Credly の概要

Greco 氏は、技術認定をこの 10 年以内に取った人なら、Google、AWS、Cisco、IBM のものでも、ここ数か月で再び Credly に戻ってきた Microsoft や、Anthropic のものでも、Credly のバッジを持っている可能性が高いと話します。Credly は、「検証された学習・研修提供者の世界最大のネットワーク」で、専門団体、技術認定の提供者、高等教育機関など**約 3,500 の機関**が、安全で検証可能なデジタルバッジの発行に使っています。これまでに **1 億 5,000 万回以上**、世界の数千万人に発行されています。

### 5.2 AI が壊した採用の信頼性

市場で見えている問題として、次の点が語られます。

- AI により、説得力のある主張を作るコストが崩れた。採用側は、求人 1 件ごとに、細かく調整された完璧な履歴書を数千通受け取る。
- 関連経験、履歴書の調整、誤字の無さ（注意深さ）といった従来のふるい分けが、使いにくくなった。
- 面接でも、候補者が AI でリアルタイムに答えを得ているのではないか、初日に出社してくる人が採用した人と同じか分からないのではないか、という不安がある。
- 背景調査会社の調査で、**採用担当者の 40%** が、のちに偽の身元を使っていたと分かった候補者を面接したことがある（前年は 30%）。
- Gartner の予測では、**2028 年までに、オンラインの候補者プロフィールの 4 件に 1 件が完全な捏造**になる。
- Google や McKinsey は、少なくとも 1 回は対面の面接を必須にする運用に戻した。

Greco 氏は、これを「とても高くつく対策」であり、クリーンな履歴書や筋の通った面接は、いまは AI で安く作れるため、かつての有効な目印ではなくなった、と見ています。

### 5.3 偽造しにくいもの：署名付きの検証可能なクレデンシャル

AI にとって偽造が難しいのは、「検証された権威から直接届く、署名付きのクレデンシャル」です。Credly では、スキルを実際に評価した組織からの署名付きの声明を偽造できません。Credly は、認定を発行する発行者のすべてを手作業でオンボードし、本人が名乗る組織であることを確認しています。たとえば Microsoft が、Azure Solutions Architect の試験に合格したかを判断すると、そのバッジを使って、検証可能で安全なデジタルクレデンシャルを発行できます。最も重要な認定の多くは、Pearson VUE が運営する、試験監督付きの対面の試験センターで提供されています。

Microsoft がこの結果に署名してクレデンシャルとして発行したとき、3 つのことが成り立つと説明されます（聞き取れた内容を整理したものです）。

1. 評価した組織（assessor）から来ており、Microsoft という実在する組織から来たものだと信頼できる。自己申告ではない。
2. 暗号で署名され、改ざんがあれば分かる。
3. その背後に、達成を表すスキルのデータを、単なる文字列ではなく**データとして**持っている。

### 5.4 Microsoft と Credly の取り組み

Greco 氏は、Microsoft が AI 時代の人材計画を語るときも、クレデンシャルを発行するときも、「肩書きではなくスキル」が軸だと述べています。Microsoft や Credly ネットワーク上の提供者から取得するすべての認定は、すでに（または近いうちに）Credly を通じて発行される、署名付きの検証可能なクレデンシャルになるとのことで、すでに世界の数百万人に起きていると説明します。

各バッジは、表すスキル、レベル、ステータス、有効期限などを構造化データとして持っています。学習者は取得して共有でき、雇用主は検証できます。

そして、Microsoft が発行を始めたばかりの **Pro badge** は、試験で答えた内容ではなく、**GitHub Copilot の実際の利用**にもとづくものです。Greco 氏は「知識の証明が、実績の証明になりつつある」と述べます。

ギャップはクレデンシャル自体ではなく、**多くの組織が、認定データを、従業員や求職者についての検証可能なデータとしてまだ使い始めていない点**にあります。バッジの保持者の同意にもとづいて、企業が簡単に使えるようにすれば、次の 2 つの問題を解決できると述べています。共有先は常にバッジの保持者が決めるという点を、繰り返し強調しています。

### 5.5 企業の 2 つの課題

| 課題 | 内容 |
| --- | --- |
| 組織の外側の問題 | 候補者の主張を信頼できるか。いまデータを検証しようとすると、高価な手作業の背景調査になる。リンクを追いかける、スクリーンショットを信じる、あるいは多数の発行組織から個別にデータフィードを受け取り、それぞれを独立して統合する必要がある。 |
| 組織の内側の問題 | CHRO などのリーダーから、組織の人々が何をできるのか分かっていないとよく聞く。L&D（学習・開発）、人員配置、コンプライアンスなどのシステムは、職務名や自己申告データで動いている。その上で事業変革を計画するのは、推測、データなし、あるいは職務名から推測したデータで計画することになる。職務名では全員が同じに見え、スキルの過大申告も過小申告もある。自分が思っているより高いスキルを持つ人もいて、その違いを見分けるのは難しい。 |

Greco 氏は、どちらも根本原因は同じで、「証明ではなく主張で動いている」ことだと述べます。ここから先の約 10 分は、現在 Microsoft と一緒に提供しているものと、市場を近い将来どこに進めたいかの話になります。

### 5.6 現在あるもの：Pro badge の画面と、バッジの検証

Greco 氏は、実際の画面を見せながら説明すると述べ、Microsoft のクレデンシャルを例にします。最初に示されたのは、先週、ある人に発行されたばかりの **GitHub Copilot の Pro badge**（スクリーンショット）です。試験の勉強をして受験する従来の監督付きの認定とは、まったく違う種類のクレデンシャルです。

仕組みは次のように語られています。

1. 学習者がオプトインする。
2. 学習者が普段どおり GitHub Copilot を使うと、Microsoft がバックエンドに作った評価フレームワークが、そのプラットフォーム内での行動を、バックグラウンドで継続的に評価する。
3. 一定の基準を満たすと、そのツールへの習熟を示すクレデンシャルが自動的に発行される。

Greco 氏は、少なくともプラットフォームやツールの利用については、近いうちにこれが「実績の証明」の姿になると信じていると述べます。人々は、試験のために勉強した内容ではなく、実際にできることの証明を取得し共有できる。仕事の流れの中での認定は、本物で、継続的で、毎日の学びに報いるものであり、それを検証可能で持ち運べるデータにできる点が、雇用主が求めるものだとしています。

Credly 経由で発行されるため、ほかの認定と同じ利点（メタデータと検証機能）があります。

- 発行するすべてのクレデンシャルのメタデータは構造化されており、**OpenBadges 3.0** 標準（"one at Tech's" と聞こえます。標準化団体の名称は音声認識の都合で確定できません）に基づく。
- 学習者が渡す、Credly がホストするリンクで、誰でもクレデンシャルが本物で改ざんされていないことを確認できる。データは Credly のデータベースにあるので、学習者は何もアップロードする必要がなく、検証する側も学習者と直接やり取りする必要がない。

ただし、バッジを個別に検証するのは、より大きな解決策の小さな一部にすぎません。もう一方が、雇用主の側です。

### 5.7 現在あるもの：Credly Workforce

**Credly Workforce** は、企業向けに最近導入された新しい製品モデルです。示された画面は、架空のデモ用アカウント **Acme Co** のもので、L&D、タレントマネジメント、コンプライアンスなどの管理者が見られるビューだと説明されています。画面の細かな内容は、音声からは確認できません。

仕組みは次のとおりです。

- Acme Co が、従業員を Credly のプロフィールで接続するよう招待する。
- 従業員が同意すると、その人の Credly プロフィールにある**公開バッジ**が、この UI で、または API や Webhook によるデータフィードとして、企業に届けられる。企業が使っている記録システムに直接取り込める豊富な API と Webhook がある。
- 前述のメタデータ（スキルデータ、レベル、有効期限、ステータスなど）もすべて付いてくる。企業は、一括かつ継続的に問い合わせられる。
- 一度、雇用主と従業員の間でデータ接続が結ばれれば、過去に取得した公開バッジも、今後取得するものも送られる。**非公開バッジは企業に送られない。**
- 特定の認定を探す場合だけでなく、「誰がどのスキルを持っているか」を、どの組織が評価したかを問わずに見る、スキルベースの見方もできる。

これは、個別の提供者から取り込む方法との違いでもあります。評価者や研修提供者が、自分たちの認定だけのフィードを送るパートナーポータルはありますが、企業は大量の個別の統合を作る必要があり、データ構造もそれぞれ違うため、変換や統合が必要になります。Credly Workforce は、**すべての認定を 1 つに集約し、標準化されたデータフィード**にするものだと位置づけられ、人員配置、コンプライアンスの準備状況、学習予算の使い道、社内異動の判断などに使えます。どの判断も、自己申告ではなく検証された実績にもとづき、学習者は、何を証明し、どのデータを共有するかを決められます。

### 5.8 これから：HR システムとの連携

次の大きなステップは、このデータを企業の記録システム（systems of record）に直接届けることです。企業が最も望むのは、ほかの従業員データがすでにある場所に届くことだとのことで、大手の HR プラットフォームとの標準的な連携を進めています。**SAP SuccessFactors と Workday が近く対応予定**です。品質の高い従業員データがあるプラットフォームであれば、認定データで充実させられる、という考え方です。

### 5.9 これから：Pearson Wallet

上の話は現在の従業員向けです。冒頭の採用の場面では、何千人もの応募者との永続的な接続は必要ありません。そこで登場するのが **Pearson Wallet** です。これは開発中の新しい製品で、**来年の前半に private preview（限定プレビュー）に移す**ことを目指しています。

Pearson は Credly 以外にも、直接提供する学習体験や、K-12、高等教育、専門職向け学習のパートナーを通じて、世界の数千万人の学習者と生涯にわたって関わっています。学位、政府発行の専門職ライセンスなど、人々が自分について持っている、または持ちたいデータは多く、**安全に保管・共有できる 1 か所**が求められているそうです。Credly が好まれるのも、すべてを集約できるからだと述べています。

- 学位やライセンスなど、ほかのデータ形式に対応する前に、まず Credly から始める。
- **来年の初めまでに、Credly で毎日発行される約 8 万件のクレデンシャルのほぼすべて**を、取得者が Pearson Wallet に**無料**で保管できるようになる。
- 既存のオープンソースの学習・教育記録ウォレットは、どれも空の状態から始まり、学習者が手作業でデータを集めて入力する必要がある。Pearson Wallet は、Credly の利用者基盤があるため、過去 10 年間に発行された **1 億 5,000 万個のバッジ**を、本物のモバイルウォレットの形で保持・共有できる。

具体例として、クラウドエンジニアの候補者 **Anna** が挙げられました。Anna は、Microsoft の認定、PMI の Agile Certified Practitioner の認定、新しい Anthropic の認定を持っています。いまでも、Credly の Web プロフィール（固有の URL）で共有できますが、受け取る側がデータを調べるには、バッジを 1 つずつクリックする必要があり、大量に見るのは困難です。また、採用担当者が公開 URL を見ても、確認した記録が残りません。

そこで目指すのは、Anna と、データの受け手（relying party）が、**すべてのクレデンシャルに対するリアルタイムの検証を一度に**行えることです。

- 学習者は、誰が、どのデータを要求しているかを知り、何を共有するかを決められる。
- 受け手は、クレデンシャルが本物であることの暗号的な証明と、確認を行ったという記録を得られる。
- すべてのモデルは、候補者の同意と、どのデータを誰が見られるかというプライバシー制御を前提とする。誰に、どの程度の詳細まで共有するかを、本人が決める。

### 5.10 これから：最高保証レベルの発行モデル

もう 1 つの課題が、身元です。一般的な名前の人が公開の Credly プロフィール URL を共有したとき、その人が本当にその認定を取った本人だと、どう分かるのか。この問題に、**来年の中ごろまでに** Wallet で対応しようとしており、「highest assurance credential issuance model（最高保証の発行モデル）」と呼んでいます。

- 重要度の高いクレデンシャルの発行者は、試験に合格した人や取得した人が、請求・共有する前に、**生体認証で本人確認**することを要求できる。
- その身元は、クレデンシャルに、さらに個々のデバイスにも紐づけられる。
- 再度チャレンジ（再認証）を求めることもできる。採用担当者などが、共有されたクレデンシャルが本人のものか確かめたいとき、その身元に対して再認証を求められる。
- 個人の身元に紐づくバッジは、偽造や複製が極めて難しくなる。

目標は、検証可能なクレデンシャルの共有を、**「タップして支払う」ほど簡単に**することです。タップして検証する、QR コードをスキャンしてすべてのクレデンシャルを同期する、といったことが応募プロセスでできるはずだと述べています。実現の方法は、採用プロセスにこの確認を組み込みたい企業と直接取り組むか、理想的には、求人サイトや ATS（採用管理システム）との連携で、人々が毎日使っている流れの中に組み込むことです。うまくいけば、履歴書の解析や高価な手作業の背景調査が減り、採用プロセスへの信頼が高まる、と述べています。

### 5.11 採用している標準

技術者向けの補足として、Credly と、近く Pearson Wallet は、オープン標準の上に作られています。

| 標準・仕組み | 役割 |
| --- | --- |
| W3C Verifiable Credentials | 署名され、改ざんが分かるデータモデル |
| OpenBadges 3.0 | その上に作られた、Credly で発行されるクレデンシャルの形式 |
| "OID for VCI" と "OID for VP"（聞こえた表記のまま） | ウォレットへのクレデンシャルの発行と、ウォレット内のデータの検証に使う標準プロトコルになる予定 |
| Status lists | 失効や有効期限の確認。発行元に問い合わせなくても、クレデンシャルが有効か確認できる |

### 5.12 聞き手への呼びかけと質疑

企業の採用プロセスを来週までに変えるよう求めることはできない、としたうえで、次に採用や人員配置の判断が机に届いたとき、あるいは自分が応募するとき、そのプロセスのどれだけが「主張」に依存しているかに気付いてほしい、と述べます。実際の検証済みデータだったら、判断やワークフローはどう変わるか、という問いです。証明はすでに存在しており、Microsoft などの認定や Credly で発行されたバッジは、スキルを評価した組織からの署名付き声明だとして、事業を率いる人は、年末までに 1 つの判断を変えられるはずだ、と述べています。AI への準備、人員配置、コンプライアンス、社内異動のいずれの判断でも支援できる、とのことです。

学習者に対しては、クレデンシャルを取得して共有することを勧めています。新しい Pearson Wallet で保管できるようになったら、Credly を通じて通知します。バッジが「LinkedIn の素敵なステッカー」以上の価値を持つこと、その背後に重要な判断に使える豊富なデータがあることを、市場に示す必要があり、そのための認知拡大だと説明しています。

最後に、質問を受けると呼びかけましたが、質疑の内容はトランスクリプトには含まれていません。Greco 氏は終了後も Skills Theater に残るとして、質問や想定しているユースケースがあれば声をかけるか、LinkedIn やメールで連絡してほしいと案内しています。

## 7. 注意点・発表者の気付き

- **共有の主導権は常にバッジの保持者にあります。** 企業に届くのは、従業員が同意した接続を通じた、**公開バッジのみ**です。非公開バッジは送られません。
- **Pearson Wallet と最高保証レベルの発行モデルは、まだ提供されていません。** Wallet は来年前半に private preview、最高保証モデルは来年の中ごろを目指す、という計画です。
- **HR システムとの連携（SAP SuccessFactors、Workday）は「近日対応予定」**という段階です。
- 公開の Credly プロフィール URL は、バッジを 1 つずつ見る必要があり、採用側が確認した記録も残りません。同じ名前の別人かもしれないという身元の問題も残ります。
- 従来の厳密な評価の役割は残ります。Pro badge は、ツールやアプリケーションの習熟について、仕事の流れの中で認定する形として語られています。
- 企業の採用プロセスはすぐには変えられないため、まず「どれだけが主張に依存しているか」に気付くことが勧められています。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **雇用主**：高価な手作業の背景調査や、リンク・スクリーンショットの確認が減る。複数の発行元から個別に統合する必要がなく、Credly Workforce の標準化された 1 つのフィードで、人員配置、コンプライアンスの準備状況、学習予算、社内異動の判断に、検証された実績を使える。
- **学習者**：認定を 1 か所で保管・共有できる。バッジを Pearson Wallet に無料で保管でき、共有する相手と詳細度を自分で決められる。
- **採用プロセス**：将来的には、履歴書の解析や手作業の背景調査が減り、採用に対する信頼が高まる（これらは目標として語られたものです）。
- 数値・事例は、市場の課題（40%、4 件に 1 件）、Credly の規模（約 3,500 機関、1 億 5,000 万回）、Wallet の対象（毎日約 8 万件）が語られましたが、導入企業の成果数値は語られていません。

## 9. まとめ

AI により、履歴書や面接のような自己申告のシグナルを偽造するコストが下がり、採用の信頼性が崩れています。Greco 氏は、これをデータの問題として捉え、スキルを評価した組織が署名した、検証可能なクレデンシャルを使うことを提案しました。

Credly はすでに、Microsoft をはじめとする提供者の認定を、署名付きの構造化データとして発行しています。GitHub Copilot の利用実績にもとづく Pro badge は、実績の証明の例です。企業側には Credly Workforce（同意にもとづき、公開バッジを API・Webhook・UI で届ける）、今後は SAP SuccessFactors と Workday との連携、候補者向けの Pearson Wallet（来年前半に private preview）、生体認証による最高保証の発行モデル（来年の中ごろ）が計画されています。標準は W3C Verifiable Credentials と OpenBadges 3.0 などのオープン標準です。聞き手には、判断のどこが「主張」に依存しているかに気付くこと、学習者には取得したクレデンシャルを共有することが呼びかけられました。
