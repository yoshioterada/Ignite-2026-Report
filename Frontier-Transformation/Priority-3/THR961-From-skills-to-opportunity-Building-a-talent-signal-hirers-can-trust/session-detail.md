# THR961 From skills to opportunity: Building a talent signal hirers can trust

## 1. はじめに

このセッションは、LinkedIn のプロフィールに載せるスキルを、「自己申告」から「検証された証拠」に変えるための **LinkedIn の Connected Apps（コネクテッドアプリ）** プログラムの紹介です。発表時間は約 14 分で、スライドと口頭の説明が中心です。

発表の問いは、「スキルを一覧に書くだけの状態から、仕事を得るための証拠に変えるにはどうすればよいか」というものです。例として、GitHub Copilot を毎日使っているソフトウェアエンジニアの Ellis（架空の人物）が取り上げられます。Ellis の GitHub Copilot での実際の作業をもとに、Microsoft が習熟度（proficiency）を評価し、本人が許可すれば、その結果が LinkedIn のプロフィールに信頼できるシグナルとして表示される、という流れです。公開から約 3 か月の初期成果と、質疑応答（Q&A）も含まれます。

## 3. 何に関する発表か

テーマは、LinkedIn のプロフィールにおけるスキルの信頼性です。LinkedIn が、Microsoft および GitHub と組んで、「ツールで実際に行った仕事」にもとづく証拠をプロフィールに表示する仕組みを作った、という話です。

発表の流れは次のとおりです。

1. 現在の LinkedIn のスキルの課題（自己申告にすぎない、数が膨大で採用側が見極めにくい）
2. 架空の人物 Ellis を使った具体例
3. 「スキルを学ぶ → 実際の仕事で証明する → プロフィールにつなぐ」という道筋
4. 3 つのステップ（作業・Microsoft による検証・プロフィールで共有）と、3 社の役割分担
5. メンバーがプロフィールに Connected App を追加する方法
6. GitHub Copilot 以外のパートナーと、プログラムの発展
7. 採用側（hirers）にとっての意味と、初期成果
8. 聴衆への呼びかけと Q&A

## 4. 発表者が伝えたいメッセージ

中心の主張は、**プロフィールのスキルは「申告（claim）」にすぎないが、ツールからの証明を付ければ「証拠（proof）」になる**ということです。

発表者は、冒頭で会場に挙手を求めています。まずスキルをプロフィールに載せている人に手を挙げてもらい、次に「そのスキルでテストされたら少し不安・恥ずかしい」人は手を挙げたままにしてもらう、という流れです。ここから、Python のようなスキルは 2 秒で追加でき、「追加は速いが、確認は難しい」という点を示しています。発表者は、これは誰かを責める話ではなく、むしろ多くの人は自分を控えめに書いており、問題は正直さではなく、プロフィール上のシグナルの質にあると述べています。

もう 1 つの主張は、これが採用する側だけでなく、メンバー自身にとっても利益になるという点です。資格のある人が、強いスキルも弱いスキルも同じ 1 本のフラットなリストに並ぶため見落とされる、という問題を取り上げ、特に career switcher（キャリアの転換者）や、従来型の経歴を持たない人に効果があると説明しています。

## 5. 発表内容の詳細

### 5.1 いまの LinkedIn のスキルの課題

発表者は、プロフィールのスキルは「主張」にすぎず、追加は簡単でも検証が難しいと説明します。規模も大きく、**3 億 8,000 万人のメンバー** がスキルをプロフィールに載せており、LinkedIn 上のスキルは **60 億件** あるとのことです。採用する側は、この膨大な情報の中から「どれを信頼できるのか」を判断しなければなりません。

その結果、採用側は確信が持てないとき、職種名、出身校、過去の勤務先といった代替指標（proxy）に頼りがちになります。発表者は、こうした指標は「正しい経歴」には有利でも、「正しいスキル」を示すとは限らず、適した候補者を見逃す可能性があると指摘しています。

### 5.2 Ellis の例

Ellis は、毎日 GitHub Copilot を使ってコードを出荷している、仕事のできるソフトウェアエンジニアです（架空の人物であると発表者が明言しています）。ところが彼女のプロフィールに載っているスキルは Python、JavaScript、Git の 3 つだけで、LinkedIn 上の数千、あるいは数百万人の候補者と同じに見えます。この情報から、採用側は彼女が実際に何をできるか理解できず、信頼もできません。発表者は、聴衆にも「誰にも Ellis のような知り合いがいるはず」と呼びかけています。

### 5.3 「申告から証拠へ」の道筋と 3 つのステップ

ギャップを埋める考え方として、発表者は次の道筋を示します。スキルを学び、日々の実際の仕事とツールでそれを証明し、その情報をプロフィールに持ち込む。ここから機会が開ける、という流れです。そのうえで、「今日家に帰って、あるいはいまノート PC を開いたらどうなるか」を、Ellis の具体例で説明しています。

1. **Ellis がいつもどおり仕事をする。** 彼女は GitHub Copilot で毎日コードを作り、レビューし、出荷しています。仕事そのものに語らせる、という考えです。
2. **Microsoft が検証する。** 裏側で、Microsoft が彼女の仕事を評価し、ツール内の実際の活動にもとづいて習熟度を割り当てます。
3. **Ellis が、その習熟度をプロフィールで共有すると決める。** 採用担当者が見る場所に、信頼できるシグナルが表示されます。

発表者は、彼女がテストを受けたり作業の流れを止めたりする必要はなく、GitHub での仕事が進むにつれて習熟度も更新されていく、と説明しています。「同じ Ellis、同じスキルだが、今はそれを裏付ける証拠がプロフィールに直接ある」という整理です。

この協業が成り立つ理由として、3 社が異なるものを持ち寄っている点が挙げられました。

| 担当 | 役割 |
| --- | --- |
| GitHub Copilot | 仕事をする場所 |
| Microsoft | 厳密さ（rigor）を提供する |
| LinkedIn | 機会が見つかる場所 |

発表者は、これを組み合わせることで、どの 1 社だけでも作れないものができると述べています。

### 5.4 メンバーの手順（プロフィールに追加する）

メンバー側の操作は、発表では「ほんの 1 分ほど。いまこの場でもできる」と紹介されています。語られた手順は次のとおりです。

1. プロフィールから、新しい **connected app** のセクションに進む。
2. **GitHub Copilot**（または、対応している数十のほかのアプリ）を選ぶ。
3. ログインして、LinkedIn のプロフィールに表示されるようプロビジョニングする。

これで完了です。情報はパートナーから送られ、その後もプロダクトを使い続けるかぎり、同期を保つための操作は不要だと説明されています。

発表者が気に入っている点として、これは自分で書いた「主張」とは見た目が異なり、各プロダクトから「あなたがそのプロダクトをどう使っているか」について **証明（attest）された情報** として表示される点が挙げられました。プロフィールを見る採用担当者などは、これを「検証された、できることの証拠」として信頼できます。

### 5.5 GitHub Copilot 以外のパートナーと、プログラムの発展

このプログラムは、コードに限らず、仕事に使う任意のツールやサービスで機能するよう作られているとのことです。スライドには、現在公開中のパートナーと、近日公開予定のパートナーの一覧が示されました（スライド上の個別の名前は音声からは確認できません。Q&A では、エンタープライズ向けの現行パートナーの例として Gong が挙がっています）。対象はマーケター、ビルダー、クリエイター、セラーなど幅広く、パートナーからの反応は大きく、参加待ちのウェイトリストもあります。多くのパートナーは、このプログラムを自社プロダクトの価値の延長として見ているそうです。ユーザーが仕事を完了するだけでなく、機会・つながり・会話のために設計されたプラットフォーム上で、それを見せられるからです。ツールやプラットフォームの提供側で参加に興味がある人は、セッション後に声をかけてほしいと呼びかけています。

パートナーの需要が高かったため、プログラム自体も進化しています。

| 時期 | 送れる情報 |
| --- | --- |
| 当初 | capability statements（能力の記述）と proficiency levels（習熟度） |
| 現在 | 上記に加えて、プロジェクト、記事、アクティビティの統計（フォロワー数や chess のスコアなど） |

スライドに表示される内容は、パートナーごとに完全にカスタマイズでき、各ツールにとって最も意味のあるものを表示できます。もちろん、すべてメンバーの同意（consent）にもとづきます。狙いは、プロフィールの 1 つの小さな画面に、できるだけ多くの文脈と証拠を載せることだと説明されています。

### 5.6 採用側にとっての意味

ここまでメンバー（求職者）とパートナーの話が中心でしたが、続いて採用側（hirers）の話に移ります。発表者によると、LinkedIn の採用側は、いまのところ主に「主張」を探しています。

LinkedIn は数年前から、メンバーが本人確認と勤務先を検証できるようにして、信頼性を高める取り組みを始めています。プロフィールの About セクションにある小さなチェックマーク（バッジとシールド）がそれです。今回はその次の段階として、スキルの信頼性を高め、信頼できるシグナルに変えようとしています。

Ellis のように、経歴が一流の職種名や学校を反映していない人でも、採用側は、どのような道筋を通ってきたかにかかわらず、資格のある人を見つけられるようになる、というのが発表者の説明です。発表者は「まだ初期段階だが、これが目指す方向だ」と述べています。

### 5.7 初期成果

公開してからまだ約 3 か月ですが、初期の結果は有望だと説明されています。

- Connected App（どのアプリでも可）をプロフィールに付けているメンバーは、付けていないメンバーに比べて、プロフィールの閲覧が **最大 3 倍**、リクルーターからのメッセージが **ほぼ 3 倍** になった。

発表者は、検証された証拠がプロフィールにあると、目に留まるだけでなく、人が実際に行動を起こしていると解釈しています。目指していたのは、人がより多くの機会につながれるようにすることだったと述べています。

### 5.8 聴衆への呼びかけ

発表者は、立場ごとに次のことを呼びかけています。

| 立場 | 呼びかけ |
| --- | --- |
| キャリアを築いている人 | 今日、GitHub Copilot とそのほかの仕事用アプリをプロフィールに接続する。パートナーでないアプリを使っている場合は、教えてほしい。「仕事に語らせよう」 |
| 採用・人材チームを率いる人 | レビューするプロフィールで connected apps を探す、または LinkedIn Recruiter で検索する。それは主張ではなく証拠である |
| パートナーになりうる事業者 | スライドのコードをスキャンして、LinkedIn connected apps パートナーに応募する |

### 5.9 Q&A

**Q1：Instagram は対応しているか。**（質問そのものは音声から聞き取りにくく、回答の内容から、Instagram が対象かどうかの質問と読み取れます。）
回答：現時点では対応していません。発表者は、質問者に Instagram の社員かと尋ね返したうえで、自分は社員ではないが、クリエイティブ寄りの人には役立つアプリになりうると述べています。プログラムは「多いほど良い」方針で、あらゆるプラットフォームを歓迎するそうです。クリエイターやセラーが自分の力を示すのに役立つなら、それを持ち込みたい、と答えています。

**Q2：職場のメールアドレスで接続することは許されるのか。また、シングルサインオン（SSO）の場合、組織としてどう接続を許可するのか。**
回答：LinkedIn はすでに多くの企業と提携しており、パートナーごと、会社ごとのケースバイケースだと説明されています。

- 会社のメールアドレスを使うか否かについて、LinkedIn 側の制約はありません。
- そもそも LinkedIn は、どのメールアドレスや、パートナー側のどのログイン情報を使っているかを知りません。それらはパートナー側で完結しています。
- 例として、現在あるエンタープライズ向けプロダクトの Gong が挙げられました。ユーザーは Gong の中で SSO によりすでにログインしており、そこから LinkedIn に接続します。LinkedIn 経由で認証すると、パートナーが情報を LinkedIn に渡します。
- LinkedIn に送られるのは、LinkedIn ユーザーとしての本人が、そのプラットフォームで何ができるかだけです。独自の機密情報は送られず、本人の身元や、パートナーに関連する会社の情報も送られません。
- プログラムの目標は、エンタープライズとコンシューマーの両方を対象にすることです。
- 質問の後半（メールアドレスがプロフィールと関連付けられている必要があるか）には、企業のメールアドレスをプロフィールに関連付ける必要はない、と回答しています。

**Q3：技術職として、どこで働いたかではなく、スキル・経験・目指す方向を前面に出すには、プロフィールをどうブランディングすればよいか。**
回答（発表者は「二つの観点で答える」と述べています）：

- LinkedIn のプロフィールで、いま最優先にしている目標は、従来の履歴書に近い現状から、「あなたが何者で、何ができるか」をより多面的に示せるようにすることです。
- 多くの人が気づいていないこととして、LinkedIn には projects（プロジェクト）や skills を追加できる。職歴と学歴だけではない内容を載せられる。
- リクルーターや採用担当者には、そうしたプロジェクトを、できることの実際の証拠として見てほしいと呼びかけています。
- Connected Apps の一部のパートナーでは、パートナーのプラットフォームから LinkedIn にプロジェクトを自動で接続できます。手動で追加することもできます。
- ヘッドラインやサマリーで、これまでの実績だけでなく、目標や志（ambitions）を語ることもできます。
- プロフィールには、「何をしているか」「何をしたいか」を載せられる場所が多くあり、Connected Apps はまさにそのためのものです。アカウントを接続すれば、それがプロフィールにも表示されます。

最後に司会者が、Megan 氏と Kelly 氏に拍手を求め、Microsoft、GitHub、LinkedIn の話を聞けるのが Ignite の良さの 1 つだと述べました。また、約 20 分後に、この日の午後の最後のセッションがあることを案内しています。

## 6. デモ・手順

このセッションでは、画面を使ったデモは行われていません（スライドと口頭の説明が中心です）。5.4 のメンバーの手順は、発表者がスライド上のイメージとともに口頭で説明したものです。画面上の具体的なボタン名や表示内容は、音声からは確認できません。5.3 の Ellis の 3 ステップも、実演ではなく、スライドを使った例示です。

## 7. 注意点・発表者の気付き

制約や失敗談として語られた点は少ないのですが、発表の中で次の点が明示されています。

- プログラムはまだ初期段階（「We're early」）で、公開から約 3 か月です。
- 紹介された成果数値（プロフィール閲覧が最大 3 倍、リクルーターからのメッセージがほぼ 3 倍）は、Connected App を付けたメンバーとそうでないメンバーの比較です。発表では、この比較の母数などの詳しい条件は説明されていません。
- 表示する内容はすべてメンバーの同意にもとづきます。
- 現時点で対応していないプラットフォーム（例：Instagram）もあります。

## 8. 利用者にとっての利点

発表で語られた利点を、立場別に整理します。

- **メンバー（求職者）**：作業の流れを止めたりテストを受けたりせずに、実際の仕事にもとづく習熟度をプロフィールに載せられる。設定は約 1 分で、その後の同期のための操作は不要。習熟度は仕事の進み具合に合わせて更新される。従来型の経歴でない人や career switcher が見落とされにくくなる。
- **採用側**：職種名・学校・過去の勤務先といった代替指標に頼らず、パートナーが証明した情報を信頼できる証拠として見られる。
- **パートナー**：ユーザーが仕事を終えるだけでなく、機会のためのプラットフォーム上でその成果を見せられる。表示する内容はパートナーごとに自由にカスタマイズできる。
- **実績**：Connected App を付けたメンバーは、プロフィールの閲覧が最大 3 倍、リクルーターからのメッセージがほぼ 3 倍。

## 9. まとめ

LinkedIn のスキルは、いまは 3 億 8,000 万人・60 億件規模の自己申告で、採用側には見極めにくく、メンバーも埋もれてしまいます。Connected Apps は、GitHub Copilot のようなツールでの実際の仕事を Microsoft が評価し、本人の同意でその結果をプロフィールに表示する仕組みです。メンバーは約 1 分で設定でき、以後は自動で更新されます。

プログラムは、当初の capability statements と習熟度から、プロジェクト、記事、アクティビティ統計へ広がっています。公開から約 3 か月で、プロフィールの閲覧が最大 3 倍、リクルーターからのメッセージがほぼ 3 倍という初期成果が出ています。Q&A では、LinkedIn がパートナー側のメールアドレスやログイン情報を知らず、機密情報も受け取らないことが説明されました。
