# THR941 Microsoft Marketplace: You don’t have to scale cloud and AI alone

## 1. はじめに

このセッションは、Microsoft Marketplace（以下 Marketplace）を「AI アプリやエージェントを導入するときの調達と発見の入口」として紹介する短い登壇です。AI を事業価値につなげたい企業が、自社で作る（build）か、市販のものを買う（buy）か、両者を組み合わせる（blend）か、という判断をどう行い、そのとき Marketplace がどう役立つかが中心の話題です。

後半では、最終ユーザーの顧客、チャネルパートナー、SDC/ISV（発表では "SDCs or ISVs" と並べて言及されており、SDC の定義は発表では説明されていません）のそれぞれにとっての Marketplace の価値が語られます。主な数字は、**8,000 件の AI アプリとエージェント**、**11,000 のモデル**、**140 を超える市場**、**4,000 件の Azure Benefit Eligible なソリューション**です。

## 4. 発表者が伝えたいメッセージ

Kevin 氏は、日々の顧客との会話では「AI への投資からどうやって実際のビジネス価値を得るか」が話題の中心になっていると述べています。Microsoft はその道のりを **frontier transformation**（実験から本当のビジネス価値へ向かう道のり）と呼んでおり、新しいソリューションやエージェントを 1 つ導入することではなく、AI を組織全体に組み込んで創造性、革新、成長を得ることだと説明しています。

そして、この道のりは Microsoft の製品だけでは完結せず、**エコシステムの力**が必要だという点が中心の主張です。Marketplace は、その企業とパートナー（SDC/ISV、チャネルパートナー）をつなぐ「スケールのエンジン」で、クラウドソリューション、AI アプリ、エージェントの**信頼できる唯一の入口**だと位置づけています。

AI-first であるとは、既存の仕事を速くするだけではなく、仕事のやり方を考え直し、これまで不可能だったことをできるようにすることだ、というのも Kevin 氏の主張です。その裏づけとして、Microsoft が今春に委託した調査が紹介されています（5.1）。

## 5. 発表内容の詳細

### 5.1 Frontier transformation と調査結果

Kevin 氏は、今春に実施した調査の結果を次のとおり紹介しています。

| 調査結果 | 数値 |
| --- | --- |
| 1 年前にはできなかった仕事を生み出している AI ユーザー | 58% |
| より価値の高い仕事に時間を使えるようになったと答えた人 | 66% |
| AI で全く新しい能力を引き出していると答えた frontier professionals | 80% |

登壇者は、こうした変化がすでに何度も起きており、1 社ですべてを提供することはできない、だからエコシステムが必要で、そこで Marketplace が登場する、とつなげています。

### 5.2 Marketplace とは

登壇者は Marketplace を、組織をパートナー（SDC/ISV やチャネルパートナー）につなぐ「スケールのエンジン」と説明しています。

- クラウドソリューション、AI アプリ、エージェントの、信頼できる単一の入口
- あらゆるユースケースに対する AI アプリとエージェントがそろい、クラウドソリューションと各業界にまたがる包括的なカタログがある
- 閲覧できるストアフロントだけでなく、**仕事をしている場所の中で**サードパーティのオファリングを探せる体験（in-product experiences）を提供する

### 5.3 AI・エージェント導入の 3 つの道

Kevin 氏の導入のあと、Amy 氏が 3 つのアプローチを詳しく説明しています。

| アプローチ | 向いている場合 | 得るもの | トレードオフ |
| --- | --- | --- | --- |
| **Build**（自作） | 要件が独特、事業にとって戦略的に重要、体験・データ・運用を厳密に制御したい | 最大限のコントロールとカスタマイズ | 時間と投資がかかる。開発、統合、テスト、保守、継続的なイノベーションを自分で担う |
| **Buy**（購入） | 事業にとって重要だが、差別化する必要まではない機能 | 実績のある価値、速い価値実現 | カスタマイズの自由度が下がる |
| **Blend**（組み合わせ） | 実績ある機能は買い、本当に差別化したい部分は作る | 購入の速さと、自作の柔軟性・制御の一部 | （発表では特に述べられていません） |

**Build**：Marketplace は、モデル、ツール、サービスへのアクセスを提供し、プロコードでもローコードでも開発を支えると説明されています。構築するソリューションに、**数千のモデル**で素早く関連性の高いコンテキストを与えられるとし、Anthropic、Meta、Cohere、OpenAI の主要なモデルを挙げています。問うべき質問は、「この機能は、自社で作って保守するに値するほど、自社にとって差別化できているか」です。

**Buy**：すでに存在するかもしれない機能を自作する代わりに、確立されたソリューションから始めるという考え方です。Marketplace では、**数千の AI アプリとエージェント**を探して調達できます。提供形態は顧客の要件に合わせて選べ、完全マネージドの SaaS アプリケーション、自分のテナントに直接デプロイするソリューション、Microsoft 365 Copilot 内のエージェントが挙げられています。Marketplace は、SaaS、マネージドアプリケーション、コンテナ、エージェントにわたる**数千**のすぐ使えるソリューションを提供し、スライドの例として Elastic、Harvey、Pinecone などが示されました。問うべき質問は、「実績のあるソリューションがすでにニーズを満たすなら、自作が本当に時間と投資の最善の使い道か」です。

**Blend**：買うか作るかの二者択一ではなく、実績ある機能は買い、差別化すべき部分を作る、という選び方です。例として、Marketplace の AI モデル、アプリケーション、エージェントから始め、自社のデータ、ビジネスロジック、ワークフロー、カスタム体験と組み合わせる、という使い方が挙げられています。「買うか作るか」ではなく、「何を作り、何を買い、どこを組み合わせるか」を問うほうが有用だと Amy 氏は述べています。

どのアプローチを取る場合でも、Marketplace の選択肢の幅が、自社のビジネスに最も合う AI 戦略を進める自信につながる、という説明です。

### 5.4 価値その 1：AI の意思決定を速める

ここから Kevin 氏が、最終ユーザーの顧客、チャネルパートナー、SDC/ISV のいずれの立場でも当てはまる Marketplace の価値を説明します。

- **カタログ**：どのハイパースケーラーよりも大きな、AI アプリとエージェントのカタログで、**8,000 件のソリューション**があり、さらに増えている
- **モデル**：Microsoft のモデルとサードパーティのモデルを合わせ、**11,000** にアクセスできる。これで中核となるインテリジェンスを構築できる
- **選択の自由**：作るか、買うか、パートナーと組むかを、顧客が決める
- **グローバル規模**：**140 を超える市場**の顧客と関わっている

Kevin 氏は、8,000 件超を可視化することはできないとして、AI-first の企業が取り組む代表的なイニシアティブを選んで示しています。例として、プロセスの AI による自動化、カスタマーサービスの変革、従業員の支援が挙げられ、エージェント、アプリケーション、スキルが Marketplace にそろっていると述べています。

また Marketplace は、AI アプリとエージェントだけでなく、セキュリティ、ストレージ、バックアップなどのコアインフラストラクチャにわたる**数万件のソリューション**を扱っています。CRM、ERP、コラボレーションなどの業務アプリ、ヘルスケアや金融サービスなどの業界向けソリューションもあり、クラウド支出の最適化を優先する支援もしていると説明されています。

> 補足：Kevin 氏は、Marketplace を戦略的調達の手段として使うことを、後のスライドで詳しく話すと述べています（5.6）。

### 5.5 価値その 2：インテリジェントな探索（intelligent discovery）

「数万件もあって、自分のニーズに合うものをどう探すのか」という質問がよく出る、と Kevin 氏は述べています。そこで用意されているのが、AI を使った **intelligent discovery** です。登壇者の説明では、使い方は次のとおりです。

1. 組織が、ストアフロントのインターフェースに、自然言語で「X に関するビジネス課題がある」「Y に関するソリューションを探している」と入力する
2. その入力と意図をもとに、Marketplace が検索を進め、ユーザーに一連の質問をして絞り込む
3. 推奨のソリューションが示される
4. その体験の中で、製品の説明や製品詳細ページが示される
5. 複数のソリューションを並べて比較できる（side-by-side の比較）

登壇者は、これにより比較を素早く、簡単に、効果的に行えると述べています。

> 補足：この説明はスライドと口頭によるもので、画面を使った実演ではありません。画面上の操作の細部は発表では示されていません。

### 5.6 価値その 3：戦略的調達と、クラウド・AI 投資の最大化とガバナンス

**Azure Benefit Eligible**：Marketplace のうち **4,000 件のソリューション**が Azure Benefit Eligible とされています。Azure Cloud Commits（発表では "MAC, Microsoft Azure Consumption Credits" と発音されており、名称は音声認識の都合で確定できません）という、Microsoft との既存のコミットメントを持つ企業は、そのコミットメントを、Marketplace 経由で調達するサードパーティのオファリングに充てられます。Kevin 氏はこれを「強力な仕組み」と述べ、アカウントマネージャーと一緒に、組織内のソリューションの対応づけ（マッピング）を行い、更新やアップグレードのサイクルで、Marketplace を**戦略的な調達手段**として、すでにある予算や義務を活用できると説明しています。

**投資の最大化とガバナンス**：

- Azure の co-sell 適格性に加え、Marketplace のソリューションは Microsoft のテクノロジースタック向けに作られている。そのため、導入までが速くなる
- Marketplace を使って、技術系・ビジネス系の意思決定者と調達部門をまとめることで、クラウド支出の管理、クラウドインフラの管理と、意思決定の加速を組み合わせられる
- SDC/ISV やチャネルパートナーにとっては、最終ユーザーが Microsoft との既存の財務・課金取引の関係を使って、自社の新しいソフトウェアを購入できるため、**クローズまでの時間が短くなる**

### 5.7 価値その 4：仕事の流れの中で提供される（Flow of work）

Kevin 氏は、Marketplace はストアフロントで閲覧できるだけでなく、日々使う仕事の流れの中でサードパーティのソリューションを見つけられる、と説明しています。Marketplace に出会える場所として、次が挙げられました。

- ストアフロント
- Teams
- Microsoft 365 Copilot
- Foundry
- Azure portal

### 5.8 価値その 5：購入方法

購入の簡素化にも取り組んでおり、チャネルパートナー、SDC/ISV、最終ユーザーの顧客が一緒になるときの柔軟性を高めていると述べています。

| 方法 | 説明 |
| --- | --- |
| セルフサービスのパブリックオファー（public offers） | Marketplace か Azure portal でアプリケーションを探し、購入し、数分でデプロイできる。多くの実務者が使うもので、開発者にとって強力だと述べている |
| プライベートオファー（private offers） | 非常に大規模な取引向けで、通常は価格や条件を個別に交渉する |
| チャネルパートナー経由 | 関わりたいパートナーを選んで、Marketplace を通じてソリューションを調達できる |

> 補足：プライベートオファーの説明の直後に文が途切れており（"We provide" で終わる）、追加の内容は聞き取れません。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- 8,000 件の AI アプリとエージェント、11,000 のモデルから、作る・買う・組み合わせるを自分で選べる
