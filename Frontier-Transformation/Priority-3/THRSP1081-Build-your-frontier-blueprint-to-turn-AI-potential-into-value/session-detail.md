# THRSP1081 Build your frontier blueprint to turn AI potential into value

## 1. はじめに

このセッションは、Kyndryl のコンサルティング責任者が、Copilot やエージェントを導入した企業が「実験」から「全社規模の運用」へ進むための進め方を紹介する約 24 分の登壇です。Kyndryl が顧客支援に使っている **Microsoft Frontier blueprint** というアプローチが中心で、ガバナンス、FinOps、技術基盤、人（ワークフォース）という 4 つの観点を同時に整える考え方が説明されます。

登壇者の主張は、AI の支出が増えているのに ROI（投資対効果）が測りにくく、エージェントが乱立し、シャドー AI も広がるという圧力の中で、**4 つの能力を一緒に前に進めない限り、Copilot とエージェントを規模に乗せることは難しい**というものです。後半では、blueprint の 5 つのステップと、3〜4 週間の標準エンゲージメントが示されます。Kyndryl のサービス紹介を含むセッションです。

## 3. 何に関する発表か

テーマは、AI の「ポテンシャル」を、Microsoft が言う frontier（フロンティア）な組織としての「価値」に変えるための現実的な進め方です。登壇者は、Copilot の導入が始まった頃から多くの組織と関わってきたと述べ、相談の中身が「Copilot をどう展開するか」「どう価値を出すか」から、「エージェントは自社にとって何か」「Copilot とエージェントで仕事のやり方をどう変えるか」へ移っていると話しています。

発表の流れは次のとおりです。

1. 組織にかかっている圧力（上からの ROI 要求と、下からの従業員の期待）
2. 調査の数字（Kyndryl の people readiness report）
3. frontier な組織に必要な 4 つの能力と、frontier firm の定義、E7 との関係
4. 立場ごとの問い（誰が何に悩んでいるか）
5. Frontier blueprint：成熟度評価、agent spectrum、5 つのステップ、3〜4 週間の進め方、アクセラレーター

## 4. 発表者が伝えたいメッセージ

登壇者は、AI の変化の速さは「桁外れ」で、組織は実験・PoC・パイロットから、AI を前提にした運用能力の構築へ移るよう迫られていると述べています。そして、次の 12〜18 か月で成功するのは、**明確なガバナンスと運用モデルを持ち、その出発点を決められた組織**だと考えています。

その鍵が、ガバナンス、FinOps、技術基盤、人の 4 つを並べて考えることです。どれか 1 つに成熟していても、4 つを合わせて見なければ、Copilot とエージェントのポテンシャルを規模で引き出すのは難しい、と繰り返しています。たとえば、最高の導入戦略と AI council があっても、ガバナンスのガードレールがなければ前に進めず、その逆も同じだという説明です。

## 5. 発表内容の詳細

### 5.1 組織にかかっている圧力

登壇者は、現場で見ている状況を次のように説明しました。

- **上からの圧力**：組織全体から、事業部門、ペルソナ、プロセスへと見る単位が下がり、ROI や価値、仕事がどう変わるのかを求める圧力が強まっています。
- **下からの圧力**：ChatGPT が登場してから約 4 年。個人生活で AI を使ってきた従業員が、職場でも同様の体験を期待しています。
- **現場の混乱**：ライセンスの混乱、ガバナンス問題、どのツールをいつ使うかという迷いがあります。Copilot を買ったものの、使われているか、価値が測れているかが分からない組織があります。全員にエージェント作成を許して「Wild West（無法地帯）」になった組織もあり、登壇者は前日に会った組織が 70,000 のエージェントを持っていながら、それぞれが何をするのか分かっていなかったという例を挙げました。また、厳しい（draconian）対応を取る組織もあるとして、"turned it on until they figure it out" と述べています（意味が取りにくいため原文のまま記します）。いずれにしても従業員は使いたがるため、組織が把握していなくても使われるシャドー AI が生まれる、という説明です。
- **エンドユーザー領域の従量課金**：クラウドインフラでは FinOps が定着していますが、従業員向けのツールでは長年「1 ユーザーあたり月額（または年額）」で考えてきました。それが、従量課金型の請求を従業員が発生させる形に変わり、組織は対応方法が分からず、従業員も自分の操作のコストを理解できません。Copilot Cowork や Autopilot などの試みで AI 支出は増える一方、ROI は定義も定量化も難しいままです。

### 5.2 調査の数字：Kyndryl の people readiness report

1 年前、Kyndryl は 8 か国のリーダー約 1,100 人（登壇者は "I think" と前置きしています）に people readiness report の調査を行いました。数週間前に最新版を公開し、今回は対象市場を広げて、**約 4,000 人のリーダー**に聞いたと述べています。

| 項目 | 数値 |
| --- | --- |
| パイロットや実験を超えて、ワークフローに AI を展開しているリーダー | 84% |
| 複数チーム間の引き継ぎが必要なワークフローの自動化に AI を使っているリーダー | 77% |
| 自社の従業員の準備が完全にできていると答えたリーダー | 33%（前年は 23%、10 ポイント増） |
| 1 年前より ROI を示す圧力が強まったと答えたリーダー | 約 60% |
| 前年に「役割と責任が変わると予想する」と答えたリーダー | 87% |
| そのうち、実際に役割・責任の見直しを行った割合 | 27% |

登壇者は、前年のリーダーのほぼ 90% が「1 年以内に役割が変わる」と答えたが、実際に行ったのは 27% で、大きな進展があるものの道のりはまだ長い、と話しました。また、AI 支出が増えて複雑になるなかで、リーダーは使った費用の価値を示す圧力を強く感じているとも述べています。

### 5.3 frontier な組織を作る 4 つの能力

成熟した組織では、次の 4 つが一緒に進んでいると、登壇者は説明します。

| 能力 | 内容 |
| --- | --- |
| ガバナンス | エージェントに所有者とライフサイクルがある。IT とセキュリティがすべてのエージェントを見通せる agent registry がある |
| 技術基盤 | 人だけでなくエージェントの行動も統制できる。エージェントが関わるすべてのものに、データ、セキュリティ、コンプライアンスの統制がかかり、自律的に動き始めても監査できる |
| FinOps | トークンや計算資源が従量課金になり、財務への影響が人数ではなく使用量に連動する。もはやライセンスコストを人数から割り出せないので、エージェントが手に負えなくなる前に統制を整える必要がある |
| 人（ワークフォース） | 実験と革新の余地を許す文化。従業員に、実験のための時間、支援、ガイダンスを与える |

「AI は魔法のように仕事を変えるのではない」というのが登壇者の考えで、ツールを渡すだけで従業員が仕事を変えることは期待できず、支援とガイダンス、それを後押しする組織文化が必要だと述べています。

### 5.4 frontier firm とは

Microsoft が使う frontier firm は、変革の旅の「行き先」を表す言葉です。登壇者は、本当に frontier な組織を次のように定義しています。

- **人が主導し、エージェントが運用する（human-led, agent-operated）**
- AI が、孤立したツールやパイロットではなく、ワークフローと意思決定に直接組み込まれている
- データ、システム、体験を統合した接続されたモデルがあり、ガバナンスと信頼が最初から組み込まれている（問題が起きてからの事後対応ではない）

frontier firm は Microsoft のスタック上に作られ、**E7** を構成する機能に支えられると述べています。具体的には、E5、Entra Suite（音声では "Entre Suite"）、Copilot、Agent 365、そして知能のレイヤーである Work IQ です。

ただし、すべての組織がこの構成になっているわけではありません。E3 にアドオン、または E5 にアドオンを追加した構成など、組織内に混在することもあり、同じ課題を抱えています。そこで Kyndryl のアプローチは、顧客の現在地に合わせ、**今のライセンスの範囲内でできること**と、E7 の道に進んだ場合の可能性の両方を示す、としています。

### 5.5 立場ごとの問い

登壇者は、frontier transformation の議論が「久しぶりに IT だけの話ではなくなった」と述べました。従来、Microsoft の AI ビジネスソリューションの話は CIO や IT が相手でしたが、今は多くの関係者が関わります。どの問いから始めても、同じ frontier という行き先につながる、という説明です。

| 立場 | 主な問い |
| --- | --- |
| 事業オーナー | どのユースケースやアイデアが、優先するに足る価値を生むか |
| オペレーション責任者 | どのワークフローを、単に自動化するのではなく、エージェント向けに再設計すべきか |
| 部門長・事業部門のリーダー | Copilot Cowork、スキル、プラグインをチームにどう持たせ、正しく使わせるか |
| AI の責任者 | あるユースケースを、プロンプト、Cowork のスキル、プラグイン、エージェントのどれにするか。コネクタは要るか。Fabric や Foundry を使う複雑なケースに移る時期はいつか |
| IT | 安全に拡大するための基盤が整っているか |
| セキュリティ | どの統制・ガバナンスのギャップから先に対処すべきか。このまま進んで安全か |
| 調達 | エージェントが全体のコストをどう変えるか。それを価値とともにどう測るか |
| HR・ワークフォース | 人の準備をどう進めるか。エージェント時代の仕事に必要なスキルと文化をどう作るか（AI のスキルではなく、人の観点で） |

オペレーション責任者の問いについて、登壇者は、「すべてをエージェントにすべきだ」と考える人から、10 年前に解決済みの自動化の課題（SharePoint のサイトテンプレート作成など）が持ち込まれる、とよく経験していると話しました。AI とエージェントを使う場面と、他のツールで自動化すれば済む場面を見分けることが重要だという趣旨です。部門長の問いでは、Cowork で、標準の Copilot で足りる作業にコストをかけてしまうことがある、と指摘しています。

### 5.6 Frontier blueprint：成熟度評価

Kyndryl の blueprint は、次の **4 つの領域**で成熟度評価を行います。

1. AI の機会と価値（ユースケースと価値モデル）
2. 技術的な準備（technical readiness）
3. デジタルトラストの基盤（適切なセキュリティがあるか）
4. ワークフォースの準備

結果は **1 枚のスコアカード**にまとめられます。現在地と次にやるべきこと、そして**ライセンスの上限、ライセンスプラン、最大の課題、最大の機会**に基づく優先順位が分かるようにするものです。「同じ旅は 2 つとない」ので、顧客の現在地に合わせて進めると述べています。

### 5.7 Agent spectrum

blueprint には、自律性が高まる連続体としての **agent spectrum** が含まれます。登壇者は、同じ Copilot でも、コストの意味合い、できること、向いているペルソナが段階ごとに異なると説明しました。

| 段階 | 説明 |
| --- | --- |
| Copilot Chat | ライセンスに含まれる。組織の全員が使えるべきで、多くのユースケースで有益 |
| Agent Builder | 従業員が自分の生産性のためにエージェントを作る |
| Cowork | 従量課金（metered billing）が始まる段階。作業を委任し、エージェントに引き渡せる。さらに一歩進んで、継続的に動く処理も設定できる（自動化）。コストは Copilot credits に関係する |
| Copilot Studio agents | 組織向けのエージェント。一部またはすべてのユーザーに公開し、さまざまなデータソースと対話できるようにする |
| Autopilot | より自律的。先回りして長時間かかる作業を行い、指示したタスクを、ユーザーが他の作業をしている間に終わらせる |
| Foundry の pro-code agents | プロコードで作るエージェント |

blueprint は、顧客がユースケースをこれらの段階のどれに当てはめるか、いつどの方法を選ぶかを判断できるよう支援します。

### 5.8 blueprint の 5 つのステップ

登壇者によると、5 つの接続されたステップは常に同じで、それぞれが次のステップの入力になります。

1. **ユースケースの特定と優先順位付け**：顧客の特定の事業部門と組み、ユースケースを洗い出し、優先順位を付け、どのツールに向くかを見ます。
2. **価値とコスト（経済性）のモデル化**：**アンカーとなる 1 つのユースケース**を深掘りして価値モデルを作り、コスト、価値、投資対効果の見通しを立てます。ペルソナ、プロセス、価値、実現可能性を検討し、プロセスを適切なエージェントの形（vehicle）に対応させます。続いて、シナリオごとのクレジット使用量を見積もり、コストと価値の関係を可視化し、顧客がこの考え方をたどれるよう支援します。
3. **技術基盤**：テナントの準備はできているか、リスクのあるデータはないか、適切なポリシーとガバナンス統制はあるか、Copilot を大規模に展開できるか、を確認します。登壇者が挙げた例は、MFA と "payment"（音声認識の都合で語が確定できません）によるデータと管理者ロールの保護、過剰共有（oversharing）の削減、テナント内コンテンツの分類、Power Platform の環境とコネクタ戦略です。
4. **ガバナンス**：セキュリティとコストの両面を見ます。目的は、**速度を出しつつ安全にする統制**で、生産性や革新を妨げる統制ではなく、組織のリスク許容度の中で適切なバランスを見つけることです。すべてのエージェントに、**所有者、アイデンティティ、ライフサイクル**を持たせます。所有者は、エージェントが何をするかを理解し、そのビジネスプロセスを担い、価値と ROI に責任を持ち、エージェントをいつ変更・廃止すべきかを判断できる人です。リスク階層別の承認、DLP、リスクに基づく環境モデル（エージェントをどの環境に置くかの判断）、予算、上限、チャージバックモデルも扱います。
5. **ワークフォースの準備と定着**：登壇者が「おそらく最も重要」と述べるステップです。Teams の会議議事録（登壇者は今も最も一般的な使い方の 1 つだと述べています）以上に使われるよう、定着させます。AI council、明確な責任、経営層のスポンサー、事業部門のオーナー、イネーブルメントとチャンピオンのネットワーク、エージェントに仕事を委任するための変革戦略などを整えます。また、**タスクではなく成果（outcome）に対してプロンプトする**ことを理解してもらう必要があるとも述べています（Copilot を使い始めると、プロンプトの仕方が変わるため）。

> 補足：発話では、アンカーのユースケースの深掘りと経済性のモデル化の境目が明確ではありません。後で「1 と 2 がユースケースとコストと価値」と説明されていることから、上のように 2 つ目にまとめました。

ステップ 1〜2 が「AI の機会と価値」、3 が「技術的準備」、4 が「デジタルトラスト」、5 が「ワークフォースの準備」に対応します。成熟度の道筋をこれらすべてで一緒に進める、という設計だと説明しています。

### 5.9 進め方（3〜4 週間のエンゲージメント）とアクセラレーター

最初は必ず blueprint から始めます。**標準で 3〜4 週間のエンゲージメント**で、テナントから取得したデータと、4 つの領域を横断した構造化されたワークショップの組み合わせで進めます。最後に、現在地と次にやるべきことを示す **readout（報告）**、つまり blueprint を共有します。

加えて、顧客に多い課題に対応した**アクセラレーター**があります。登壇者が挙げたものは次のとおりです。

- **FinOps**：多くの組織が今最も悩んでいる課題の 1 つ
- **導入（adoption）と有効化（activation）**：基盤が整っておらず、Copilot を適切に有効化してテナント設定を整える必要がある組織が今もある、という説明です
- **エージェント**：特定のワークフローやタスクを対象に、ガバナンスと展開モデルを検討する
- **機能別のワークフォース**：組織が Cowork をどう取り入れるか、機能別のユースケースをどう優先するか、スキルをどう作って日常業務に組み込むか、コストを管理しつつ安全にどう拡大するか

これ以外にも、複数のアクセラレーターがあるが、上記が今も支援を求められることが最も多い、と述べています。

## 7. 注意点・発表者の気付き

- **すべてをエージェントにしない**：10 年前に解決済みの自動化の課題までエージェントで解こうとする相談が多く、AI を使う場面と、他のツールで自動化する場面の見極めが必要だと述べています。
- **Cowork のコスト**：標準の Copilot で十分な作業を Cowork で行うと、不要なコストが発生し得ます。
- **エージェントの乱立**：全員にエージェント作成を許すと、70,000 のエージェントがあって何をするか誰も分からない状況になった組織の例があります。厳しい対応を取る組織でも、従業員が使いたがるためシャドー AI が生まれます。
- **セキュリティ統制とのバランス**：生産性や革新を妨げる統制ではなく、組織のリスク許容度の中で、安全に実験できる統制を目指すとしています。
- **AI は魔法ではない**：ツールを渡すだけでは仕事は変わりません。ガイダンスと文化が必要です。
- 登壇者は、4 つの能力のどれかだけが進んでも前進は難しく、ガバナンスと導入の両方が必要だと繰り返しています。
- 調査の数字（84%、77%、33%、約 60%、87%、27%）は Kyndryl の調査に基づく発表内容で、対象や設問の詳細は発表では示されていません。

## 8. 利用者にとっての利点

発表で語られた利点は、Kyndryl の blueprint を利用する場合のものです。

- 4 つの領域（AI の機会と価値、技術的準備、デジタルトラスト、ワークフォースの準備）での現在地と、次にやるべきことが、1 枚のスコアカードで分かります。
- 優先順位は、ライセンスの上限、プラン、最大の課題、最大の機会に基づいて決まります。
- 現在のライセンスでできることと、E7 に進んだ場合の可能性の両方が分かります。
- 1 つのアンカーとなるユースケースで、コスト、価値、ROI の見通しを持てます。
- 3〜4 週間の標準エンゲージメントで、現在地と次の行動を示す readout が得られます。
- 発表では、具体的な顧客の成果（導入後の数値）は紹介されていません。

## 9. まとめ

AI 支出が増え、ROI が測りにくく、エージェントとシャドー AI が広がる中で、組織はガバナンス、FinOps、技術基盤、人の 4 つを同時に整える必要がある、というのがこのセッションの主張です。Kyndryl の調査では、84% のリーダーがパイロットを超えて AI をワークフローに展開している一方、従業員の準備が完全にできていると答えたのは 33%、約 60% が ROI を示す圧力の増大を感じています。

Kyndryl の Frontier blueprint は、4 領域の成熟度評価と 1 枚のスコアカード、Copilot Chat から Foundry の pro-code agents までを含む agent spectrum、5 つのステップを、3〜4 週間の標準エンゲージメントで進めるものです。FinOps、導入と有効化、エージェント、機能別のワークフォースといったアクセラレーターも用意されています。
