## 5. 発表内容の詳細

### 5.1 導入: AI の波とパートナー

Stephen 氏は、スライドのハイテク業界の変遷を自身のキャリアになぞらえています（最初のメールは、ミニコンピューターにつないだグリーンスクリーンだったと言います）。現在の AI への投資は、過去のどの変化よりも速く、大きいと述べ、鉄道から産業革命まで遡っても、年単位だったものが月単位に、月単位だったものが週単位になっていると話しています。「バブルではないか」という議論にも触れ、**エージェント型 AI の未来はすでに来ており、今後さらに速くなる**と述べています。

IDC の調査については、世界の 500 社のパートナーが協力し、事業がどう変わりつつあるかについて強いフィードバックをくれたと説明しています。詳細な報告書は発表当日か翌日に公開される予定で、数字の解釈は人によるものの、その規模は驚くべきものであり、顧客を支援する機会が Microsoft にとってもパートナーにとっても次の成長だとしています。

約 5 か月前に Microsoft は「Frontier Company」を立ち上げ、Frontier transformation や Frontier ecosystem を語り始めました。同時に、パートナープログラムを通じた新しい認定（certification）と専門性認定（specialization）も導入しています（プログラム名は音声認識の都合で表記が確定できません）。

- **Frontier transformation engineer のバッジ**: 常時 3 万人を超える人が取得に取り組んでいると述べています（数字は約 1 週間前のもの）。意図的に高いハードルにしており、AI エンジニアを育てる知識移転を目的としています。
- **会社レベルの Frontier specialization**: 数日前の時点の正式な監査で、FPT と AdCore が初めて達成した、と述べています（社名は音声認識の都合で表記が確定できません）。達成間近の企業が会場にいるはずで、今後さらに増えると見ています。

これを近年で最も広範なスキル習得・イネーブルメントの機会と位置づけ、Microsoft は 1 対 1 から 1 対多まで大規模なプログラムを運営するのが得意だとも話しています。Justin Slade 氏（人名は音声認識の都合で表記が確定できません）のチームが広範なスキリングを担っています。

### 5.3 Microsoft のプラットフォームの全体像

Stephen 氏は、Microsoft が「パートナーとの go-to-market を簡素化しようとしている」と述べ、次の要素を順に挙げています。

- **Copilot**: Satya 氏が前日に Copilot を「AI operating system」と呼んだことに触れ、以前は「UI for AI」と言っていたと述べています。この 12 か月で、Copilot を通じて、チャットだけでなく co-work（共同作業）、コード作成、autopilot の設定までできるようになったと説明し、「AI in the flow of human work」のために使うとしています。
- **Agent 365**: AI の導入を承認する以上、観察、管理、コスト管理の方法を知っていなければならないとして、これらをまとめる **control plane** と説明しています。トークンを正しい人に、正しい理由で、正しいレベルで配るための FinOps 的なコスト管理がここに含まれ、エージェントに、人間のようにシステム内で動作するための適切な資格情報を与えることもできるとしています。
- **Microsoft IQ**: 12 か月前は Fabric IQ、Foundry IQ、Work IQ を語り、Build で Web IQ を発表しました。これらを単純化し、中核となる Microsoft IQ にまとめたという位置づけです。Microsoft IQ がもたらすインテリジェンスは Copilot から提供され、Agent 365 で可観測性を確保します。詳細は Matt 氏が説明するとしています。
- **セキュリティ**: セキュリティ責任者（Hayat 氏と聞こえます）の話に触れ、「perception」というプロダクトが長くプライベートプレビューだったが、Ignite で GA になったと述べています（製品名は音声認識の都合で表記が確定できません）。エージェント型の世界ではセキュリティの管理にもエージェント型の製品を使うべきだという考えです。
- **Azure**: これらすべての土台になるクラウドプラットフォームで、継続的により信頼でき、より安全になっているとしています。

### 5.4 パートナーが不可欠な理由（Matt 氏）

Matt 氏は、Mala 氏のパートナー基調講演で、「human ambition、intelligence、trust」の柱の下に、さまざまな IP とプラクティスの機会が紹介されたことに触れたうえで、全体を引いて見ています。プラットフォームがあっても、すぐに各地域、各業界、各規制、顧客固有のテクノロジー資産・業務プロセス・オペレーティングモデル・人材・文化に合致するわけではない、という課題です。

パートナーは、顧客が次のような問いに答えるうえで不可欠だとしています。

- 職場における人間の役割の将来
- インテリジェンスが自分たちにとって何を意味し、社内でどう複利的に積み上がるか
- 自社固有の差別化要素と能力を、人間とエージェントでどう成果につなげるか
- サイバー領域の非常に破壊的な新しい現実にどう向き合うか
- AI に関するリスクをどう管理するか
- 経済的な成果を出し、FinOps を企業規模でどう運用するか

### 5.5 パートナーにとって機会の大きい領域

Matt 氏は、下層にプラットフォーム（Copilot、Microsoft IQ、Agent 365、セキュリティの perception）があり、その上でパートナーが最も効果を出せる領域として、次を挙げています。Mala 氏のリストは網羅的だったとして、ここでは絞って紹介しています。

| 領域 | 説明 |
| ---- | ---- |
| Copilot とそのプラグイン | Copilot は企業で仕事をする場所になりつつある。汎用シナリオに強く、Microsoft ネイティブの統合ではコンテキストを活かせる。Copilot の周りにはプラグインのエコシステムが生まれる。再利用可能な IP のパッケージ化でも、顧客向けの個別開発でも機会がある |
| Cowork とコード | 人々の使える能力を変える。Judson 氏が NRF の基調講演の準備に Cowork を使った例に触れている。ソフトウェア開発者ではない人がコードで作る解決策を、企業内で制度化し、ガバナンスの下に置き、ベストプラクティスを広げ、進捗を測る機会がある |
| GitHub Copilot | 開発者向けだけでなく、開発者とともに AI SDLC を制度化したり、コードのマイグレーションとモダナイズを大幅に速めたりする機会がある |
| Microsoft IQ | すべての顧客が自分たちの IQ を持てる。すべてのパートナーも自分たちの IQ を持てる。コンテキストが大きな差別化要因になると見ており、再利用可能な IP とプラクティスの両面で機会がある |
| Fabric と IQ の接続 | データの話は、データと AI の話になる。データの上にオントロジーを重ね、ショートカットやミラーリングを使って Fabric OneLake にゼロ ETL でデータを取り込み、エージェント型の成果を出せる |
| Azure Catalyst | Azure にまだ載っていない IT 資産の移行。エージェント型の移行機能で、拡張可能なプラットフォームでもある。自社のプラクティスで、より速く、より良いマージンで成果を出せるほか、Catalyst 単体では対応しにくい移行困難なワークロードに、独自の IP を組み合わせられる |
| エージェント型 SOC | 攻撃者の動きが速くスケールも大きいため、すべての SOC にエージェント型のコンポーネントが必要になる。マネージドサービスや顧客側のセットアップ支援に機会がある |
| AI のリスク管理と FinOps | AI 自体のリスクを測り管理すること、コストを可視化・帰属・制御して事業上のメリットを示す FinOps のプラクティスと IP に機会がある |

エージェント型 SOC については、脆弱性が発見されてから悪用されるまでの時間の短縮だけでなく、侵害から横方向の移動やデータ流出までの速度も速まっているため、「エージェント型の攻撃者に対抗するにはエージェント型の SOC が必要」という説明です。

### 5.6 パートナー事例 1: Adobe CX Enterprise（Work IQ をプラグインとして利用）

Adobe がエンドユーザーであるマーケターに提供する、Adobe 独自のキャンバス（CX Enterprise）に、Microsoft の Work IQ をプラグインとして組み込んだ事例です。Adobe の課題は、広い企業の生産性領域のコンテキストを、マーケター向けの領域特化ソリューションにどう持ち込むか、でした。録画ビデオを Matt 氏が説明しながら進めました（詳細は 6.1）。

> 補足：Matt 氏は、これは「better together（組み合わせるほど良くなる）」の話で、Microsoft は M365 の汎用機能だけでは領域特化のマーケティング機能を出せず、Adobe 単独では豊富な企業コンテキストを用意できない、と説明しています。また、Adobe が所有・提供する体験であり、ユーザーを Microsoft のサービスに移動させず、コンテキストを利用できる点を強調しています。

### 5.7 パートナー事例 2: OneStream（Copilot Cowork のプラグイン）

こちらは Adobe の事例の逆で、OneStream が Cowork のプラグインとして、自社の領域特化の IP とデータで Copilot の体験を強化する例です。OneStream は財務データを行動につなげる製品と紹介されました。録画ビデオの内容は 6.2 に記載します。

Matt 氏は、AI が強力になるほど、データや行動が置かれていた個別のソリューションは意味を失う、というのがもともとの前提だと話します。この 2 つの事例について、これまで人が 1 つのシステムで洞察と行動を得て、別のシステムでまた洞察と行動を得て、つなぎ合わせる「swivel chair（回転いす）」作業をしていたところを、Microsoft が前面でも背面でも、パートナーが前面でも背面でも、ユーザーが複数のシステムをまたいで継ぎ目なく完結できる、と述べています。

### 5.8 パートナー事例 3: TCS の AI governance toolkit

TCS が Microsoft のプラットフォームの上に重ねる、AI ガバナンスのツールキットです。領域固有の制御、可観測性、リスク管理を AI ユースケースに加えます。柱は信頼と信頼性、ID とセキュリティ、FinOps と ROI で、これらは汎用的な関心事です。TCS は、汎用プラットフォームが標準では提供しない、領域に固有のモジュールを構築しています。例は製薬（pharma）の分野です。

- 製薬ユースケースに固有の DLP ポリシー
- 証拠の扱いと証跡（chain of custody）に対する FDA の期待の理解、証拠の強固な保持、そのための制御
- 製薬品に関する苦情（complaint）への固有のワークフロー（回答までの時間の管理、苦情データが改ざんされていないことの完全性の管理）

TCS は、再利用可能な IP と、ツールキットの周りのサービスを伴う center of excellence を顧客に持ち込み、TCS の領域知識と組み合わせて導入を支援します。顧客は成果をより早く得られ、TCS 側のビジネスとしても再現性・拡張性があります。ツールキットが入ると、同じユースケースが顧客の環境内でも再現・拡張できるようになる、という説明です。Matt 氏は、Microsoft が優れた汎用プラットフォームを提供する一方で、業界・規制・領域固有の要件が別に存在するため、IP とサービスの組み合わせでその信頼性の課題を解決する好例だとしています。

### 5.9 パートナー事例 4: Maven AGI

Maven AGI は 2023 年創業のスタートアップで、Microsoft for Startups プログラムから成長しました。Azure と Foundry の上に構築され、Teams と統合する、オムニチャネルのサポートソリューションです。顧客からは次の成果が報告されていると、Matt 氏は紹介しています。

| 報告された成果 |
| ---- |
| 自律的なチャット解決が 80% |
| ライブサポートが 4 倍高速 |
| 自律的な回答が 93%、応答の「rate」が 75% 低下（トランスクリプトでは「75% lower response rate」。音声認識の都合で「response time」の可能性は確定できません） |
| 1 時間あたりの解決件数が 25% 増加 |

スタートアップが大規模な顧客に、AI で非常に速くこうした成果を出せている点に触れ、「エンタープライズ向けの SaaS」だと述べています。

### 5.10 パートナーが取るべきアクション

Matt 氏は、スライド下部のアクションに注意を向けています。

- **顧客はパートナーに専門性と信頼性を求める。** パートナー自身がこれらを実践していると、顧客に解決策や答えを持ち込むときの信頼性が上がる。
- 自社内で **Customer Zero** になり、次の Frontier の目標は何かと自分自身に問い続ける投資は、やる価値がある。
- Microsoft はスキリングとコンテンツを提供している（スライドにリンクあり）。分かりにくいことがあればフィードバックを歓迎する。
- パートナーの成長を後押しし、立ち上げを助けるためのインセンティブと投資が、広く提供されている。GTM のリソースも利用できる。

### 5.11 Q&A

Q&A で出た質問は 1 件でした。

**質問**: Frontier の話に関連して、アプリケーション層に複数の SaaS プロバイダーを抱える顧客がいる。SaaS プロバイダーの将来はどうなるか。「SaaS は不要で、AI で自前の SaaS 層を作ればよい」という説もある。顧客は SaaS に投資すべきか、それとも破壊的に変えたい人はフロンティア層に投資し直すべきか。

> 補足：トランスクリプトには話者ラベルがありません。以下の回答者は、「Dive in any time」という呼びかけや、「Matt and I both had the opportunity…」といった発言の流れから判断したものです。

**Stephen 氏の回答**:

- 前日に急ぎでまとまった、**Salesforce との統合**のデモを例に挙げています。「ヘッドレス CRM」の考え方で、AI が仕事の流れの中に現れる形です。顧客に今も好まれているレガシー SaaS では、コアのソリューションを維持したままエージェント型のフロントエンドを作れることを示しました。Accenture がデモを行い、Customer Zero の一社になる予定です。Salesforce 環境に詳しいパートナーが、業界やペルソナ（営業、マーケティング、サポートなど）ごとに作り込む機会があるとしています。すでに 2〜3 のパートナーと話をしたとも述べていますが、何についての話かは語られていません。
- SAP とのより広い統合も発表済みです。両社に顧客のために AI 戦略を組み合わせさせることで、顧客に選択肢があり、プラットフォーム同士がより継ぎ目なく動くよう Microsoft が裏の作業をし、パートナーが石油・ガス、小売、製造などの最後の仕上げを加えられるとしています。
- Satya 氏の SaaS 製品に関する話に触れ、**システム・オブ・レコードと中核アプリケーションは今後も残る**と述べています。違いを生むのは、ユーザー向けのフロントエンドをいかに高度に個別化するかだと見ています。

**Matt 氏の回答**:

- AI が経験豊富な人と、仕事に不慣れな人とでどう違う形で作用するかを探っていきたい、という話から始めています。経験のある人は「良いものとは何か」を知っており、良い判断ができます。AI が多様な解決策を素早く作れても、それが常に良い考えとは限りません。
- 規模の経済は AI でも脅かされない、という原則を挙げています。企業の総勘定元帳、電子カルテ、大規模 EC のコマースエンジン、株式市場の金融基盤のようなミッションクリティカルなシステムを vibe code で作るのは「愚かな試み」だとしています。慎重に設計され、実戦で鍛えられ、適切な統制と統合を備えたシステムの規模の経済は、非常に大きな利点です。
- vibe coding で作った類似物が多数あると、新しいセキュリティ脆弱性やコンプライアンス要件が出るたびに、すべてに個別に対応しなければなりません。**企業内にインテリジェントな階層（layering）があれば、下層で直した内容が上層すべてに引き継がれる。**
- 経験と判断のある人が、顧客に対して、どこは vibe code で素早く作って事業を成長させ、どこは慎重に進めるか、確立されたソフトウェアに賭けるかを理解させる必要があります。「SaaS は死んでいない」が、SaaS が適切なときに適切な役割を果たすよう、階層化の原則を明文化する必要があるという考えです。
- 数か月前に顧客から聞いた話として、購入先のすべてのベンダーが SaaS 内のデータから洞察を得る新しい AI 機能を持ち込み、どれを購入し、どれを自作し、どれを OneLake などに低レベルで統合して Microsoft IQ から見えるようにするか、判断に悩んでいると紹介しています。パートナーの資産は、OneLake と Fabric IQ 経由でも、Copilot のプラグインとしても接続でき、どちらの経路でも顧客の質問に答えられ、それぞれトレードオフがあります。最終的に主流になって実績が証明されるパターンは、まだ分からないとも述べています。
- SaaS プロバイダーにとって極めて重要な問いは「リスクを適切に管理する、安全なサービスを運営しているか」だとして、Microsoft 自身の経験を話しています。約 3 年前（「I want to say three years ago」）に攻撃者が政府系顧客のメールテナントを侵害し、US Cyber Security Review Board が報告書を出しました。その後、別の攻撃者による Microsoft 自身のテナントの侵害もありました（顧客データではなく Microsoft のテナントの侵害）。以降、**Secure Future Initiative** に大きく投資しており、当時プロダクトグループにいた Matt 氏の経験では、すべてのエンジニアをすべての機能から外し、6 か月間セキュリティ強化だけを行ったそうです。取り組みは続いており、6 か月ごとに更新を公開していて、直近の更新は 7 月に公開されました。完璧という意味ではなく、企業全体の視点で継続的に強化している例として、ポスト量子暗号やエージェントの保護など、当初なかった新しい領域も含めて、報告書を読むよう勧めています。

**Stephen 氏の補足**: Microsoft for Startups の base camp（月曜の夜と話しています）で、Matt 氏とともに新しい人材と機会を見たと述べています。スタートアップが Microsoft プラットフォームを好む理由の多くは、エンタープライズ対応のポジショニングだと言います。エンタープライズでは CFO が四半期ごとに署名するため、堅牢で、ミッションクリティカルで、エンタープライズ対応でなければなりません。エンタープライズの顧客には敬意と信頼を示し、安全で信頼できる形でエージェント型の未来を展開できると示す必要があり、エンタープライズの知識をスタートアップにも移していけると話しています。

## 6. デモ・手順

このセッションでは、画面を使ったライブのデモは行われていません。ただし、パートナー事例のうち 2 つは録画ビデオで示され、Matt 氏が説明（一部は一時停止しながら）しています。録音は音声だけなので、画面の細部は確認できません。以下は語られた内容に限ります。

### 6.1 Adobe CX Enterprise と Work IQ（ビデオ）

1. ビデオは、管理者が設定する場面から始まる（短時間で完了）。Matt 氏は途中で巻き戻して見せ直しています。
2. CX Enterprise Connector の customizations の中の、プラグインのギャラリーに「Microsoft Work IQ」が表示される。
3. ユーザーが認証して接続を確立し、チャットを開始する。
4. マーケティングキャンペーンについて質問する。回答には brief（概要書）が含まれ、これは Work IQ が M365 のコンテキストから取得したもの。メールも表示される。
5. リンクをクリックすると、元のドキュメントが M365 のネイティブな画面で開く。ここでユーザーが認証するため、同じセキュリティ制御がそのまま適用される。M365 の閲覧・編集の全機能が使える。
6. 続いてユーザーがマーケティング固有の質問をし、同じデータを使って、Adobe がマーケティングプランを作り、M365 のコンテキストで強化した回答を出す。

### 6.2 OneStream と Copilot Cowork（ビデオ）

ビデオは一人称のナレーションで進みます（以下は音声からの内容で、数値や名称には音声認識の誤りの可能性があります）。

1. 予測レビューの午後、Copilot Cowork で、OneStream の FY26 の 6+6 の P&L と Budget Final の比較を依頼する（「FY266 plus 6」と聞こえるため、表記は確定できません）。
2. プラグインは Cowork を Microsoft 365 の外に拡張する。OneStream MCP を通じて、Cowork が連結財務データを直接クエリする。OneStream は、財務のための統制された financial intelligence layer と説明されている。
3. 結果として、サマリー行、コスト超過の上位 3 件、OneStream と結びついたライブの数式を含むワークブックが出力される。
4. 次に Excel に移る。新しい統合プラグイン体験で、同じプラグインが Excel の Copilot でも使え、Copilot が OneStream に問い合わせられる。
5. マーケティング・広告の差異が大きいため、勘定科目の内訳を依頼する。OneStream が詳細をシートにライブで返す。4 つの勘定科目で、予算を 3.33 million 超過している（通貨単位は語られていません）。

8. 最後に、Priya に Apex の数字の確認を求めるメールの返信を、この分析から Copilot に下書きさせ、Outlook に保存する。送信はせず、ユーザー自身が送る。

## 7. 注意点・発表者の気付き

- Frontier transformation engineer のバッジは意図的に高いハードルで、会社レベルの Frontier specialization は、FPT と AdCore が最初の達成企業です。
- ミッションクリティカルなシステム（総勘定元帳、電子カルテ、コマースエンジン、金融基盤）を vibe code で作るのは勧められないというのが Matt 氏の見解です。理由は、脆弱性やコンプライアンス要件への対応を各システムに個別に行う必要が出るためで、「SaaS は死んでいない」と述べています。
- 購入・自作・低レベル統合のどれを選ぶかについて、最終的に主流になるパターンは「まだ分かっていない」と明言されています。OneLake と Fabric IQ 経由か Copilot のプラグインかという 2 つの接続経路には、それぞれトレードオフがあります。
- SaaS プロバイダーには、攻撃者が以前より速く、強力になっているため、積極的なセキュリティ姿勢が必要だと述べています。

## 8. 利用者にとっての利点

発表で語られた顧客・パートナー事例の成果は次のとおりです。

- **OneStream の例**: 財務データと業務コンテキスト（Teams、メール、会議の文字起こし、ファイル）を 1 つのワークブックにまとめ、数字、理由、承認を 1 か所で確認できます。
- **Adobe の例**: ユーザーは Adobe の体験の中にいたまま、M365 のコンテキストを、同じセキュリティ制御の下で利用できます。
- **TCS の例**: 領域固有のコントロールを再利用可能な IP とサービスで導入でき、顧客は成果をより早く得られると述べています。
- **Maven AGI の例**: 自律的なチャット解決 80%、ライブサポート 4 倍高速、自律的な回答 93%、1 時間あたりの解決件数 25% 増加などが報告されています。
- **Salesforce 統合**: 既存の中核 SaaS を維持したまま、エージェント型のフロントエンドを追加できます。

## 9. まとめ

AI の波が過去の変化より速く大きいことを前提に、Microsoft は Copilot、Agent 365、Microsoft IQ、セキュリティ、Azure のプラットフォームを整えています。ただし、それが各業界・地域・顧客固有の事情に届くのはパートナーを通してであり、Matt 氏は Copilot プラグイン、Cowork とコード、GitHub Copilot、Microsoft IQ と Fabric、Azure Catalyst、エージェント型 SOC、AI のリスク管理と FinOps を機会として挙げています。Adobe、OneStream、TCS、Maven AGI の事例は、Microsoft とパートナーのどちらが前面に立っても、ユーザーが複数システムをまたいで継ぎ目なく成果を得る形でした。パートナーには、Customer Zero として自社で実践し、スキリング、インセンティブ、GTM リソースを活用することが呼びかけられています。Q&A では、システム・オブ・レコードと中核アプリケーションは残り、階層化と、経験に基づく判断の価値が語られました。
