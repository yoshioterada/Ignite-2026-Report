## 5. 発表内容の詳細

### 5.1 Windows 365 Flex の位置づけとライセンス

Tania 氏は、今年の初めにリブランドがあり、**Windows 365 Flex** はもともと Frontline と呼ばれていたと説明しています。製品の中身、使い方、購入方法、ライセンスモデルは変わっておらず、名前だけが変わったという説明です。より多くのワーカータイプに対応するという方向性を、名前に反映したとのことです。

ライセンスの種類は次の 3 つです。

| ライセンス | 内容 |
| ---- | ---- |
| Windows 365 Enterprise | 1 ライセンスで 1 台の Cloud PC を 1 ユーザーに割り当てる。24 時間 365 日、常に使える |
| Windows 365 Flex Dedicated | 1 ライセンスで 3 台の専用 Cloud PC が得られ、最大 3 ユーザーに割り当てられる。同時にアクセスできるのは 1 ユーザーだけ。「fall of the sun」のユースケースに向くという発言がありますが、follow-the-sun のことかどうかは音声認識の都合で確定できません |
| Windows 365 FlexShare | 共有 Cloud PC と Cloud Apps を含む。1 ライセンスで 1 台の Cloud PC が得られ、ユーザーのグループに割り当てて、**同時ではなく順番に** 共有する |

FlexShare の例として、2 ライセンスで 2 台の Cloud PC を 6 ユーザーに割り当てる図が示されました。時間帯をずらして使う臨時・タスクベースの利用者に適しているという説明です。

Flex に向くユースケースとして挙げられたのは、次のものです。

- 同じ責務で同じ作業台を共有する役割（シフトで人が出入りするコールセンターなど）
- 特定のアプリだけ使う専門のタスクワーカー
- 在庫管理や基幹業務アプリを日中に使う小売の従業員
- 時々デバイスにアクセスするサードパーティのベンダーやパートナー

これらは柔軟性が最も求められる一方で、IT 管理者にとっては安全性と管理のしやすさを保ちたい領域だとされています。

### 5.2 VDI 管理の負担を減らす

Tania 氏は、VDI（音声では BDI と聞こえますが、文脈から VDI のことです）の展開には多くの手順がかかると述べています。IT 管理者は、ロードバランシング、ストレージ、CPU、ユーザープロファイルとデータなどのインフラを気にしなければなりません。Windows 365 Flex では、考えることが次の 3 つの問いに減ります。

1. Cloud PC のサイズはどうするか
2. 組織に必要な同時実行数（concurrency）はどれくらいか
3. Cloud PC を何台プロビジョニングするか

その結果、問いは「組織の利用者の需要に応えるだけの Cloud PC があるか」に絞られ、インフラは Microsoft が担当します。

### 5.3 FlexShare は non-persistent ready

FlexShare は、永続的なデスクトップが不要なタスクワーカー・臨時利用者向けに作られています。利用の流れは次のとおりです。

1. 利用者が任意の端末に行き、Windows app またはリンクされたデバイスで Cloud PC や Cloud Apps に接続する。
2. 必要なアプリで作業して、サインアウトする。
3. その Cloud PC はプールに戻り、次のユーザーが使える。
4. これが全ユーザーで繰り返される。

前のユーザーの痕跡が残らないかという疑問に対して、答えは「残らない」で、Windows 365 は non-persistent ready だと説明しています。non-persistent には、セキュリティ、管理の簡素化、セッション間で一貫した体験、必要に応じたスケールという価値があります。過去 12 か月に顧客から聞いたフィードバックは、次の 3 点でした。

- ユーザーがサインアウトするたびに、自分が定義した良好な状態に Cloud PC を戻したい
- ユーザー間で痕跡を残したくない
- Cloud PC を簡単に更新したい

これに応えて、各ユーザーは、管理者が Intune で定義した desired state の、クリーンな Cloud PC を使えます。アプリの設定は、セッションをまたいでユーザーに付いてきます。また、Cloud PC をスナップショットの状態に素早くリセットすることもできます。

### 5.4 User Experience Sync

**User Experience Sync** は、共有 Cloud PC と Cloud Apps で、永続的で一貫した体験をユーザーに提供するための機能です。重要なアプリケーションデータ、構成設定、アクセシビリティの設定を保持するので、ユーザーはいつ接続しても自分の環境に戻った感覚になります。

「昨夜から GA になった」と説明されています。Flex のライセンスに含まれており、追加費用はかかりません。管理はすべて Intune で行います。

### 5.5 Snapshot-based reset

**snapshot-based reset** は、**12 月から public preview** になります。Tania 氏は、Ignite での Windows 365 FlexShare に関する最大の発表の 1 つだと述べています。共有プールの各 Cloud PC に「クリーンなベースライン」を持たせ、ユーザーがサインアウトすると、その Cloud PC がスナップショットの状態に戻る仕組みです。あるユーザーの変更が次のユーザーに持ち越されることはありません。

仕組みは、次の順に説明されました。

1. 共有プール内の各 Cloud PC を、参加・登録（join / enroll）し、管理者が Autopilot device preparation policy で定義した Intune の desired state（アプリ、スクリプト、コンプライアンスとエンドポイントセキュリティのポリシーを含む）にする。
2. Autopilot device preparation policy が ready の信号を出すと、各 Cloud PC が自分のスナップショットを取得する。
3. Cloud PC の準備ができて、次のユーザーが使えるようになる。
4. ユーザーがサインインする。User Experience Sync を有効にしていれば、ユーザーデータとアプリケーションデータが付いてくる。
5. 作業後にユーザーがサインアウトしてセッションを終えると、Cloud PC はスナップショットの状態に戻る。リセット中は、短時間だけ利用できなくなる。
6. 戻りが終わると、プールに戻って次のユーザーが使える。

さらに、**24 時間ごと** に、Cloud PC がアイドル中に Intune と同期し、最新のポリシーとアプリの変更を反映してから、新しいスナップショットを取ります。そのため、ベースラインは 24 時間ごとに最新になり、すべてのユーザーがクリーンな Cloud PC にサインインできます。

### 5.6 Windows 365 Cloud Apps

Cloud Apps は、FlexShare と同じライセンスの一部です。Cloud PC をプロビジョニングする代わりに、特定のアプリだけが必要な社員向けに Cloud Apps をプロビジョニングします。既存の Windows 365 ポリシーと並べて、Intune で管理・公開します。VDI やオンプレミスからの移行もサポートされると説明しています。

### 5.8 事例：Telefonica Germany

Telefonica Germany で Workplace と Transformation を担当する登壇者が、事例を紹介しました。

**課題**

- 販売チャネルはフランチャイズパートナーと間接販売の店舗で、約 13,000 のパートナーがいる。
- パートナーは、自前のハードウェアと IT を使って、Telefonica の顧客データを扱う。これらのデバイスを通じて、850 万件を超える顧客とのやり取りがあり、最も重要なデータが扱われる。
- ドイツには厳しい政府規制とデータ保護があり、データをハードウェア上に残せない。セッションでは顧客の個人情報、銀行口座、クレジットカード番号を扱う。

**選んだ解決策と構成**

Windows 365 を選んだ理由は、インフラが少なく、導入が簡単で、Tania 氏のデモのように Cloud Apps を簡単にプロビジョニングできることでした。

- Windows Store からアプリをインストールするだけで、管理者権限は要らない。
- どのクライアントでも使える。タブレット、Mac、Windows を問わない（「ゲームチェンジャー」と表現）。
- セッションはクラウドに残り、ストリーミングされるだけなので、デバイスには何も残らない。
- ID は Entra で、MFA や条件付きアクセスなどの標準機能を使う。
- 提供は Windows 365 の Cloud Apps で、必要なアプリケーション付きの Edge ブラウザーをストリーミングしている。
- データ保護の目的で、Microsoft の DLP アドオンを追加し、許可されないデータの持ち出しをブロックしている。

**進め方と成果**

要件の期限は 90 日しかなく、自前でインフラを作る時間がないことも、Windows 365 を選んだ理由でした。2 か月で設計を行い、ビジネス、セキュリティを含む 5 つのチームが関わりました。10 月に本番稼働し、最初の 2 週間で 3,000 ユーザーが稼働しました。念のため、旧ソリューションを 1 月まで並行稼働させ、店舗には利用者向けのトレーニングと配布資料を送りました。実際には、使いやすかったため、旧システムを予定より早く止められたと述べています。

| 指標 | 成果 |
| ---- | ---- |
| 運用コスト | 90% 削減 |
| プロビジョニング | 80% 高速化 |
| サポートチケット | 30〜40% 減（標準化されて問題が減ったため） |
| 稼働ユーザー | 13,000 ユーザー（最初の 2 週間で 3,000） |

年間で数十億（billions）の売上を上げているパートナーを、90 日で保護できたと述べています。

**次の取り組み**

Citrix に残っている開発者・運用チームなどの複雑なユースケースを、プロファイルに対応付けます。公開アプリだけが必要な人にはフル PC ではなくアプリを、Cloud PC が必要な人には Cloud PC を提供する方針です。開発者向けには Windows 365 の developer image を使い、必要なアプリの 90% 以上が入っているため、すぐに生産的になれるとのことです。

### 5.9 Cloud PC devices

もう 1 人の登壇者は、Cloud PC と体験の間にある「ユーザーが目の前にするデバイス」の話をしました。ホットデスクや拠点、シフトごとにフル PC を購入し、トラブルシューティングし、パッチを当てているなら、せっかく削減したコストを手放しているという問題提起です。**Cloud PC devices** は、Windows 365 に安全に接続するために作られたデバイスで、secure by design、管理に慣れた方法で扱える、クラウドの力を使うという特徴があります。

| デバイス | 発表された内容 |
| ---- | ---- |
| Windows 365 Link | 2024 年に Ignite のステージで発表された、最初の Cloud PC デバイス。20 か国以上で利用可能。小型でファンレスのため静か。最大 2 台の 4K ディスプレイ対応。希望小売価格 349 USD。ホットデスクや共有スペース向け |
| ASUS NUC 16 for Windows 365 | Commercial PC の OEM との提携の第 1 弾。最大 3 台の 4K ディスプレイ対応。2.5 ギガビットのイーサネットなど、ポートが豊富。小型。希望小売価格は 6.99 USD と聞こえますが、音声認識の都合で金額は確定できません（登壇者は「ASUS 側の QR で詳細を確認できる」と案内） |
| Logitech とのバンドル | 「desk in a box」。Windows 365 Link、キーボード・マウスのコンボ MK370（USB レシーバーの Logibolt または Bluetooth）、ヘッドセット（Sone 305 と聞こえます。表記は確定できません）、Brio 305 の Webcam が入る。モニターは含まず。希望小売価格 549.96 USD |

2 つのデバイスは、どちらも同じロックダウンされた OS を使い、起動後すぐに Windows 365 に接続します。

**secure by design**

これらのデバイスには、企業データが保存されません。盗難や故障が起きても、企業データがリスクにさらされることはありません。ローカルで動くアプリも、使える管理者アカウントもありません。スタック全体での対策は次のように紹介されています。

| レイヤー | 対策 |
| ---- | ---- |
| ハードウェア | TPM 2.0 と Secure Boot で強いルート オブ トラストを確立 |
| OS | hypervisor protected code integrity、virtualization based security。セットアップ時に BitLocker を有効化 |
| アプリケーション | 厳格な app control ポリシー。Windows 365 に安全に接続するための主要サービス以外は実行を禁止 |
| ID | Entra ID join。ローカルアカウントはなく、サインインはパスワードレス。Microsoft Authenticator などのアプリか FIDO2 キーを使う。Windows Hello は今後数か月で対応予定 |
| 管理 | Intune で管理。条件付きアクセスとコンプライアンスポリシーで、準拠したデバイスだけが Cloud PC に接続できるようにする |

これらはすべて既定で有効で、無効にはできないと説明しています。

**管理のしやすさ**

デバイスは、ほかの PC と一緒に Intune で管理します。ユーザーの設定手順は 3 ステップで、(1) ネットワークに接続する、(2) 利用条件に同意する、(3) サインインする、だけです。サインイン時にデバイスがテナントに参加し、Intune に登録されます。その後は、再起動、ワイプなど Intune の通常の操作が使えます。更新はバックグラウンドでダウンロードされ、使われていない夜間にインストールされます。

**ユーザーの生産性**

数秒で起動し、即座にスリープから復帰します。ログイン UI からクラウドに直接接続でき、サインイン後はデバイスの存在が意識されず、慣れた Windows の環境になります。Microsoft Teams は、ビデオのローカルレンダリングで最適化されています。キーボード、マウス、Webcam、ヘッドセットなどの標準的な周辺機器は、デバイス内のクラスドライバーにより、追加ドライバー無しで動きます。このデバイスはユーザーに紐づかないため、1 台を複数ユーザーで使えます。ホットデスク、ホテリング、コールセンターに向き、1 人に割り当てた専用端末としても、Windows 365 Enterprise や Flex など、どの形態でも使えると述べています。

**すでに提供されたもの**

- テナントのブランディング（自社のロゴや社名の表示）
- セットアップ中の Bluetooth ペアリング（以前は有線のキーボードかマウスが必要だった）
- ローカルでのデバイスリセット（IT 管理者だけでなく、必要ならエンドユーザーにも許可できる）
- ASUS NUC 16 for Windows 365 の追加
- Windows 365 Link の提供地域に、サウジアラビアとアラブ首長国連邦を追加

**今後数か月で提供予定のもの**

- Zoom、Webex by Cisco を含む UC ソリューションのサポート（通話最適化）
- low-level USB redirection（チェックアウトや受付などの場所で追加のハードウェアが必要になるシナリオ向け）
- USB とローカルネットワークの印刷（近日提供）
- Windows Hello でのサインイン

> 補足：スライドには、すでに提供されたものの確認用にビルド番号も載っていたそうですが、番号そのものは音声では読み上げられていません。

### 5.10 そのほかの接続手段

Cloud PC devices のほかに、Windows 365 に接続する選択肢が 3 つ紹介されました。

- **Windows 365 Boot**：既存のデバイスを再利用して、直接 Windows 365 に起動させる
- **365 Switch**（音声のまま。正式名称は確定できません）：個人のデバイスを持ち込む（BYOD）ユーザー向けに適している
- **Windows app**：複数のプラットフォームから Windows 365 やアプリに接続できる

### 6.1 デモ 1：Intune での Cloud Apps のプロビジョニングと User Experience Sync（Tania 氏）

Tania 氏は「ライブデモは勇気が要る」と話し、Intune でプロビジョニングポリシーを作成しました。なお、セッション序盤にスクリーンの不具合があり、Tania 氏が修正を待つ場面がありました。

1. Intune で devices から Windows 365 に進み、Cloud PC のプロビジョニングで、Cloud Apps 向けのプロビジョニングポリシーを作成する。ステップは 6 つ。
2. ポリシーに名前を付ける。
3. フル Cloud PC かアプリケーションかを選ぶ。今回は applications を選んだ（共有 Cloud PC をプロビジョニングする場合も手順は同じ）。ライセンスの種類は Flex に自動選択され、Flex mode は shared になる。
4. join details の種類は初期値のまま。geography と region を選び、Microsoft Entra のシングルサインオンを有効にする。
5. イメージは、custom image か gallery image から選べる。今回は gallery image を使い、イメージ上のアプリケーション（Cloud Apps として公開できるもの）が一覧で見える。
6. configuration では、事前に作成した Autopilot device preparation policy を紐づける。**User Experience Sync は、チェックボックスを 1 つオンにするだけで有効になる**。
7. scope tags は省略する。
8. Cloud PC と Cloud Apps にアクセスさせるグループを追加し、Cloud PC のサイズ（2 番目の選択肢）、assignment name（ユーザーが Windows app で見る名前）、台数（このデモでは 2 台）を指定する。
9. 最後に構成内容を確認して、ポリシーを追加する。

その後、時間の都合で、事前に作成した別のプロビジョニングポリシーに切り替えて、次の内容を示しました。

1. プロビジョニングされたデバイス（Cloud Apps を動かす Cloud PC）の一覧と、編集できるプロパティ。
2. cloud apps ブレード：公開できるアプリの一覧。アプリを選んで publish をクリックすると、数秒でエンドユーザーに配信される。事前に数個を公開済み。
3. user storage：このポリシーでは Cloud PC を 3 台、あるサイズでプロビジョニングしたので、その合計ストレージが表示される。ライセンスに含まれる。ユーザーが Cloud App や Cloud PC に接続した時点で、ユーザーのストレージが作成される（音声では「user search」と聞こえる箇所があり、表記が確定できません。ここでは user storage の話として書いています）。
4. user storage の種類は 2 つ。fixed size（サイズを指定）と auto expanding（最大のユーザーストレージサイズまで、必要に応じて拡張）。
5. maintenance を有効にすると、最後にアタッチされてから何日後にユーザーストレージを削除するかを設定できる。
6. restore points：自動の restore point の頻度を、日数で設定できる。

これらは User Experience Sync の新機能で、public preview が当日から始まったと説明されています（「GA は昨夜から」という前出の発言との関係は、発表では説明されていません）。

最後に、エンドユーザーの視点を示しました。

1. Windows app で「Contoso Hotel」アプリに接続する。
2. 同じアプリの中に共有 Cloud PC も表示されており、同じ操作で接続できると説明した（実際に接続する場面は語られていません）。
3. アプリが起動する。ダークモードになっており、以前に設定を変更していたので、User Experience Sync が有効なため再設定は不要だった。

### 6.2 デモ 2：Windows 365 Link と USB リダイレクト（もう 1 人の登壇者）

「2 つあるライブデモの 2 つ目」として、机の上の Windows 365 Link を使って行われました。

1. カスタマイズ済みのログイン画面を示した。会社名、ロゴ、背景画像が表示されている。
2. メールとパスワードでもサインインできるが、FIDO2 のセキュリティキーでサインインした。
3. サインイン後、自分に割り当てられた Cloud PC が一覧で表示された。フルの Enterprise が 1 つと、Flex がいくつかあり、Flex のものを起動した。
4. 机上に、Topaz 製の USB 接続のサインパッドがある（医師の診察室や、クレジットカードの伝票・契約書のサインで見かけるものと説明）。起動した Cloud PC で、Topaz の demo アプリを開いた。
5. Link に USB で接続したスタイラスで「hello, Ignite 26」と書き、画面にスムーズに表示された。
6. 仕組みの説明：サインパッドには、標準では Windows に入っていない専用ドライバーが必要。Link のセキュリティ姿勢を変えたくないため、**Link から Cloud PC に USB 信号をリダイレクトし、ドライバーを事前にインストールした Cloud PC 側で処理している**。low-level USB redirection として取り組んでいる機能で、多くのシナリオが可能になることを期待している。
7. Intune に切り替えて、devices の Windows を開く。Cloud PC の一覧のうち、名前が WCPCD で始まるものが Cloud PC devices。手元の Link に対応するデバイスを開くと、ほかの Windows デバイスと同じように、モデル、シリアル番号が見え、再起動やワイプなどの操作ができる。

## 7. 注意点・発表者の気付き

- セッション序盤に、会場のスクリーンに不具合がありました。登壇者は、すぐ直ると見込む旨を述べています。
- snapshot-based reset は、**public preview の開始は 12 月** です。リセット中、その Cloud PC は短時間利用できなくなります。
- ベースラインのスナップショットは、アイドル中に 24 時間ごとに更新されます。
- Cloud PC devices のセキュリティ設定（TPM、Secure Boot、app control など）は、既定で有効であり、無効にできません。
- Cloud PC devices には企業データが無いため、問題が起きたときの最初の対応として、エンドユーザーにデバイスのリセットを案内できるという考えが語られました（音声では「dispreading」と聞こえ、正確な表現は確定できません）。データを失えない端末ではチケット作成や調査に時間がかかりがちですが、そのコストを減らせるという説明です。
- Telefonica の事例では、並行稼働させた旧システムは、使いやすかったため、予定より早く不要になりました。
- 次の機能はまだ提供されていません。UC ソリューション（Zoom、Webex）の対応、low-level USB redirection、USB・ネットワーク印刷、Windows Hello サインイン。時期は「今後数か月」「近日」とされ、具体的な日付はありません。

## 8. 利用者にとっての利点

- **コスト**：Telefonica では運用コスト 90% 減、プロビジョニング 80% 高速化、サポートチケット 30〜40% 減。デバイス側でも、PC を 1 台ずつ購入・保守する負担を避けられると説明されている。
- **運用の簡素化**：VDI の複雑な設計から、サイズ・同時実行数・台数の 3 つを決めるだけの運用に変わる。インフラは Microsoft が担当する。
- **セキュリティ**：snapshot-based reset により、ユーザー間の痕跡が残らない。Cloud PC devices には企業データが保存されない。Telefonica の事例では、データがデバイスに残らず、DLP アドオンで持ち出しをブロックしている。
- **ユーザー体験**：User Experience Sync により、アプリの設定がセッション間で引き継がれる。デバイスは数秒で起動し、設定も 3 ステップ。
- **導入の速さ**：Telefonica は 90 日の期限内に、13,000 ユーザーへ展開した。
- **管理の一貫性**：Cloud PC devices も、ほかの Windows デバイスと同様に Intune で管理できる。User Experience Sync は Flex のライセンスに含まれ、追加費用は不要。

## 9. まとめ

Windows 365 Flex は、共有・臨時利用の社員のための Windows 365 のライセンスです。FlexShare は、User Experience Sync（GA）と、12 月に public preview となる snapshot-based reset により、non-persistent の要件に応える形になりました。

Telefonica Germany は、90 日という期限のなかで 13,000 ユーザーに展開し、運用コストを 90% 削減したと報告しています。Windows 365 Link や ASUS NUC 16 などの Cloud PC devices は、企業データを持たない secure by design のデバイスとして、ほかの PC と同じ Intune で管理できます。USB リダイレクトや Windows Hello など、今後数か月で提供される機能も予告されました。
