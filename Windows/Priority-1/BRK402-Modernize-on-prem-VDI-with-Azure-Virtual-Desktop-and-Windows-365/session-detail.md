# BRK402 Modernize on-prem VDI with Azure Virtual Desktop and Windows 365

## 1. はじめに

このセッションは、オンプレミスの VDI（仮想デスクトップ基盤）をクラウドに移行したいが、どこから手を付ければよいか分からない、という方に向けた内容です。Azure Virtual Desktop（AVD）と Windows 365 を使い、**一括移行ではなく、自分のペースで段階的に移行する道筋**を示すのがテーマです。

構成は次の流れです。最初に Microsoft の Bev 氏が、移行を後押しする要因（ライセンス、ハードウェア費用、障害の影響）と、お客様から聞く不安を整理します。続いて Willis Towers Watson（WTW）と Chevron のお客様 2 名が、実際の移行経験を語ります。後半では Roop 氏が、不安への答えとなる製品機能を、3 つのデモを交えて紹介します。最後に Bev 氏が、持ち帰るための実践的な推奨事項で締めます。

発表の流れは次のとおりです。

## 5. 発表内容の詳細

### 5.1 移行を押し出す要因（push factors）

Bev 氏は、今の組織にかかっている圧力を 3 つ挙げています。

| 圧力 | 語られた内容 |
| ---- | ---- |
| ライセンス | 10 社中 9 社のお客様が、ライセンス費用の上昇から代替手段を検討していると回答。更新期限もあり、現状維持か前進かの判断を迫られる |
| ハードウェア | エンドポイント端末だけでなく、サーバー価格も 50% あるいはそれ以上上がった。更新用に確保した予算が以前ほど届かず、使い続けるか、別の投資に回すかの判断が必要 |
| 中断のリスク | インフラに投資しないと、障害時の調査・対応にかかる時間、想定外の短期的なハードウェア投資、エンドユーザーの生産性低下がコストとして積み上がる |

そこで、現状維持（資産を使い切る）か、一括移行（大規模で怖い）かという選択肢が残り、発表はその「第三の道」を提案します。

### 5.2 クラウド（Microsoft Cloud）を選ぶ理由

Bev 氏が挙げた利点は次のとおりです。

- **継続的な投資**：Gartner の desktop as a service の Magic Quadrant で、4 年連続でリーダーに位置付けられている。クラウドに移れば、継続的な機能追加が提供される。
- **エージェントにも対応**：Gartner は、2030 年までに DaaS ワークスペースの 20% が AI エージェントに使われると見ていると紹介。Windows 365 は、ユーザーとエージェントの両方を単一のワークスペースから管理できる設計になったと述べています（「今日の発表をすでにご覧になった方もいるでしょう」と前置きしています）。
- **セキュリティ**：zero trust が組み込まれており、データはエンドユーザーの手元ではなく、決めた場所に置ける。
- **運用**：Intune コンソールから、クラウドデバイスと物理デバイスを 1 か所で管理でき、共通ポリシーを使える。
- **使い心地**：ローカルに近い体験と、場所・デバイスをまたいだデスクトップの継続性。
- **俊敏性とコスト**：オンデマンドで拡張・縮小でき、拡張のたびにインフラ案件を計画する必要がない。

### 5.3 お客様が抱える 4 つの不安

Bev 氏は、よく聞かれる不安を次の 4 つにまとめています。以降のセクションは、この 4 つに沿って構成されています。

1. **コストと既存投資**：ハードウェアは安くなく、まだ新しいものもある。いつ移行するのが適切か。
2. **セキュリティ**：クラウドは安全でないのではないか、データはオンプレミスに置くよう事業側から言われている。
3. **ユーザー体験とパフォーマンス**：Cloud PC は遅い（laggy）という予想が多い。現状と同等以上である必要がある。
4. **移行の複雑さ**：環境、アプリ、社内スキルがそれぞれ違うため一律の道筋は引けず、「全部か無か」の大規模で苦しい作業になるという思い込みがある。

### 5.4 お客様対談

#### 5.4.1 自己紹介と規模

- **Colin 氏（WTW）**：55,000 人の従業員が約 50 か国にいる。AVD の月間アクティブユーザーは 15,000 人、Windows 365 は 1,700 人。
- **Shyam 氏（Chevron）**：principal architect で、product line manager でもあると自己紹介。workforce enablement に所属し、チームはエンドポイントへの接続、エージェント型ワークフロー、Copilot、M365 プラットフォームを管理しているとのことです。

#### 5.4.2 移行のきっかけ

Colin 氏は、ライセンス費用、そしてレガシー VDI 環境の複雑さと管理負担を挙げています。Citrix の 1 年間のライセンス契約があったため、その 1 年を使ってすべてのワークロードを AVD に移すと決めました。一括移行は難しいので、自分たちはアプリの専門家だという立場から、AVD 上でアプリを作り直すアプローチをとり、必要なスキルを集め、インフラ構築では Microsoft と協力したそうです。

Shyam 氏は、Citrix を使いながらクラウドのリソースにも支払っており、二重払い（double dipping）だったと述べています。その後 VDI を進めたものの、性能や安定性の問題（セッション切断など）が出て、さらにツールを追加し、環境の複雑さが増しました。AVD に移して改善しましたが、裏側のインフラを維持するのに多くのアーキテクトやエンジニア、運用チームが必要でした。そこに Windows 365 が登場しました。

#### 5.4.3 Windows 365 への自発的な移行

Shyam 氏によると、Windows 365 をテストしたところ、サポート対応も不要でユーザーがそのままログインでき、ファーストラインやエンタープライズのキューから良いフィードバックが集まりました。そこで Windows 365 もユーザーに提供し始めたところ、誰かを強制したわけではないのに、**約 80% のユーザーが AVD から自発的に Windows 365 へ移った**とのことです。

ただし AVD も併用しています。GPU を使うワークロード、ドメイン参加が必要で SaaS 化できないもの、subsurface（地下）関連のワークロード、追加のストレージや Azure の容量が必要なもの、オンプレミスと通信するものなどの特殊なケースです。リモートアプリにも AVD を使っています。以前は AVD/VDI のためだけにパッケージの別リポジトリを維持していましたが、Windows 365 の Cloud PC では端末側と同様にシームレスだったと述べています。

Bev 氏は、これを受けて「Intune でパッケージを 1 回作り、VDI にも物理端末にも配る。同じ方法で全デバイスを管理できれば大きな成果」とコメントしています。

#### 5.4.4 Windows 365 の利点

Colin 氏は、AVD を「アラカルトのメニュー」にたとえています。ハイブリッド参加、Active Directory への依存など必要なことは AVD のレシピで実現できます。一方で Windows 365 にユーザーを移すと、ユーザーの受け入れ度が非常に高く、接続が安定しており、従来の VDI の妥協点がほとんどない、「これまでで最もクラウド上のノート PC に近い」と述べています。Teams の音声・ビデオ品質は、1 年前の Teams SlimCore の最適化で大きく向上したそうです。また、Link のような Windows デバイスが登場し、今日 ASUS からも新しいものが発表されたと触れています。

コスト面では、「すでにノート PC を渡しているのに、これは上乗せではないか」と上司から言われると述べ、いずれ低コストのデバイスで費用を取り戻す方向になる、と話しています。

#### 5.4.5 Chevron の運用成果

Shyam 氏の説明（Chevron は石油・ガス企業で、IT は事業を支える立場だと前置きしています）は次のとおりです。

- チームは、機能面や事業を支えるワークフローに集中できるようになった。
- Nextink（音声認識の都合で表記が確定できません）でデジタル体験スコアを計測しており、ノート PC 上より Cloud PC 上のほうが、おそらく 5〜10% 高い（"probably 5 or 10%" と述べています）。
- 以前は ServiceNow でチケットを作り、どのホストプールにどこでプロビジョニングするかを決めていた。今は Intune と直接統合し、ユーザーが操作して約 30 分で Cloud PC が割り当てられる。
- 45 日以上使われていない Cloud PC は廃止する。
- 契約社員が入るときなどに、セルフプロビジョニングで自動化された手順を進められる。

Bev 氏は、プロビジョニングポリシー、ネットワーク接続、カスタムイメージを組み合わせ、グループにユーザーを入れる操作に落とし込めばセルフサービスで展開できると補足しています。ライセンスの回収については、別の登壇者が「60 日を与えている」と述べ、ライセンスがプールに戻ると説明しました。さらに、デジタル体験スコア（例として 80 から下がる）や CPU 使用が多いユーザーを、自動でより上位の SKU に切り替える運用の話も出ています（誰の発言かは文面から確定できません）。

**WTW（Colin 氏）**
- 金融機関として、VDI の中心的な用途は、オフショアのデータ処理チームやサービスセンター（Mumbai、Manila など）。扱うクライアントデータは EU や米国内に留める必要がある。
- 今年は、Windows 365 や新しい AVD ホストプールが多くの用途で事業側の第一選択になった。
- 今年も買収で成長する予定で、M&A では、Windows 365 または基本的な社内アプリだけを入れた共有ホストプールにより、最初の段階から社内デスクトップに入れるようにする。
- 開発者コミュニティにも Windows 365 を押し進める。ノート PC 更新の巨額な費用に直面した人たちから、Windows 365 のほうが合うという声が来ている。
- 助言：「思うほど遅れてはいない」。Citrix にいる、AVD を少し導入した、AVD のシングルセッションと Windows 365 Enterprise を比べている、いずれの段階でも、大きな節約とユーザー体験向上の余地がある。大胆に進め、成果から逆算する。

**Chevron（Shyam 氏）**
- GPU ワークロード（特に subsurface 関連）を検討している。
- 間もなく cloud apps を開始する予定で、特にフロントライン向けに期待している。セキュリティ脆弱性への対応でパッケージ更新が必要なため、Visual Studio Code や SQL Management Studio などを cloud apps で提供することを考えている。
- 製油所に共有デバイスを置く必要があるため、Link デバイスと boot PC（聞こえた表記のまま）を検討中。ユーザープロファイルの後始末を気にせず、「UbiKey」（聞こえた表記のまま）でログインして使い始められるようにしたい。
- 将来的には、Chevron の知識労働者の 50〜60% が Windows 365 に移ることを見込んでいる。
- 実績：約 3 か月で Windows 365 が 50 台から 6,000 台に増えた。現在のエンドポイントは 10,000 台前後。Microsoft から報酬をもらってこう言っているわけではない、と断っています。

### 5.5 コストと既存投資：AVD hybrid

ここから Roop 氏の担当です。移行先は、AVD と Windows 365 の 2 つ。会場に挙手を求めたところ、AVD は「かなりの数」、Windows 365 は「2 人」でした。オンプレミスの人数については、発表では具体的に語られていません。お客様からは、すべてのワークロードをすぐにクラウドへ移せるわけではなく、自分のペースで進める道が必要だと聞くそうです。

**運用コストの違い**：スライドでは、右端にオンプレミス VDI、中央に AVD、左端に Windows 365 が並んでいます。

| 形態 | 管理の範囲 |
| ---- | ---- |
| オンプレミス VDI | 物理データセンターからコネクティビティまで、IT 部門が全スタックを管理 |
| AVD | コネクティビティ基盤はクラウドへ移り（PaaS のように管理）、VM は IaaS のように管理 |
| Windows 365 | Microsoft が管理の大部分を担う |

オンプレミスからクラウドへの橋は高すぎないか、という問いに答えるのが **AVD hybrid** です。コネクティビティ基盤をクラウドに移し、VM はオンプレミスのデータセンターに残します。

**アーキテクチャ**：リモートデスクトップサービス（RDS）などで従来オンプレミスにあったブローカリングとゲートウェイ（接続の調整）が Azure に移り、Microsoft が管理します。デスクトップ、アプリ、プロファイルはオンプレミスに残ります。これらをつなぐのは次の 3 つです。

1. **Entra**：クラウド認証。AVD や Windows 365 と同じセキュリティ制御が AVD hybrid でも使える。
2. **Azure Arc**：オンプレミスのサーバーを環境に参加させる。インバウンドポートをインターネットに開けず、リバース接続でセキュリティを確保できる。
3. **Windows app**：あらゆる接続先への「単一の入口」。

移行の流れは、左のオンプレミス VDI から AVD hybrid へ進み、そこから、VDI の専門知識が社内にあり VM を IaaS として管理できるなら AVD、管理を簡素化したいなら Windows 365 へ、と選べます。

AVD hybrid が向く場面は、移行の途中、一部のワークロードを先に AVD hybrid に移して後から AVD や Windows 365 へ移す段階移行、そして**データをオンプレミスに置く規制要件**がある場合です。

### 5.6 Windows 365 Reserve

Windows app が単一の入口であることを受けて、Roop 氏は「Windows 365 Reserve」を紹介します。昨年後半に発表された提供形態で、**一時的な Cloud PC を 10 日間**使えるものです。

- 想定する場面：個人のデスクトップが故障して使えないとき、主端末が戻るまでの一時的な Cloud PC。デスクトップは物理でも VDI 由来でもよい。
- 使い方：ライセンスをユーザーに割り当てておき、障害が起きたら、ユーザーが Windows app から自分で Cloud PC をプロビジョニングする。元の端末が戻ったら返却する。
- 例え：物理端末が壊れたときに IT から代替機を借り、元の端末が戻ったら返す運用と同じ構図。

Bev 氏は後半で、インフラに問題が起きても M365 のツールには届き、基本的な業務を続けられる点を Reserve の回復力として挙げています。また、Reserve は障害時の継続性だけでなく、短期のプロジェクトやハッカソンで Cloud PC の使い心地を試す用途にも向くと述べています。

### 5.7 データ主権とセキュリティ

**データの置き場所**
- オンプレミスに置く：AVD hybrid、または AVD local（Azure Local）。
- パブリッククラウド：AVD と Windows 365 の両方で、多くの Azure リージョンから選び、データを近くに置ける。サービスのメタデータは M365 と同じコンプライアンス基準に従い、UDB コンプライアンス（聞こえた表記のまま。音声認識の都合で確定できません）を含む。
- より厳しい規制要件向けに、AVD と Windows 365 の government cloud がある。

データ主権は、データがどこにあるかだけでなく、**誰がどのようにアクセスするか**でもあります。今週の発表として、BYOD（私物端末）の利用を楽にする 3 つの新機能が紹介されました。

| 機能 | 説明 |
| ---- | ---- |
| Intune app protection policies（MAM） | デスクトップにアクセスする前に、端末の状態（posture）を確認できる |
| context-based redirection | ユーザーがどこから接続しているかに基づいて、リダイレクトを制御する |
| input and output protection（display protection とも） | キーロガーや、画面キャプチャを行うマルウェアから保護する |

### 5.8 ユーザー体験：Direct stream

Roop 氏は、目標は「従来の VDI ではなく、ローカル PC に近い」体験だと述べます。接続速度は約 10 秒で、物理 PC にログオンするのに近いとのことです。**Direct stream** は今週発表された新しいクラウドストリーミング技術で、次の 4 点を改善したと説明されています。

1. 接続・セッションをより速くする。
2. セッション中に最高の性能を出す。
3. 背後のネットワークが変化しても、接続が適応する。
4. エンドツーエンドで安全にする。

デモで示されたのは、3 番目の「ネットワーク変化への適応」を担う **multipath** です（6 章参照）。Bev 氏は、まとめで Direct stream に触れ、グラフィックを多用するワークロードにも使えるようになること、ネットワークが変わったり、蓋を閉じて戻ったりしても接続が続くことが、Cloud ホスト PC の捉え方を変えると述べています。

### 5.9 移行の複雑さ：アプリへの向き合い方

Roop 氏は、移行は一度に全部ではなく、多段階でよいとしたうえで、お客様の最大の懸念は「アプリをどうするか」で、これが「long pole」だと述べます。そのため、次を勧めています。

1. **まずアプリの棚卸し**：20 年、30 年前のアプリはもう不要かもしれず、代わりの SaaS があれば乗り換えて古いものは捨てる。
2. **可能なら Intune で展開**する。主要アプリはベースイメージに入れる。
3. モダナイズできるものは **MSIX** などの新しい技術を使う。AVD では、アプリを動的に追加する Gap Attach（音声認識の都合で表記が確定できません）も使える。
4. モダナイズが難しく、クラウドに置くと遅延が増えるアプリは、**AVD hybrid** でデータベースやアプリケーションサーバーの近くに残せる。
5. **App-V server** のサポートが、さらに 3 年延長されると発表された。既存の App-V パッケージを使い続ける余裕ができる。
6. 移行する段階では、昨年発表した **Migration API** が使える。Graph を使って、オンプレミスや Azure から VM のスナップショットを取り、そこから Cloud PC をプロビジョニングする。お客様やパートナーが移行を楽にするための基礎になるとのことです。

また Roop 氏は、SaaS 版（Windows 365）と PaaS 版（AVD）の機能差を埋める取り組みを続けていると述べます。昨年発表した cloud apps と、共有モードの Flex により、以前は AVD だけだった**プール型（pooled）のシナリオ**も Windows 365 で扱えるようになりました。

## 6. デモ・手順

Roop 氏による画面デモが 3 つあります。画面上の細かい操作は音声からは確認できないため、語られた範囲だけを順に書きます。

### 6.1 AVD hybrid のホストプール作成

1. 馴染みのある Azure ポータルで、ホストプールを作成する画面を開く。
2. 場所（サービスのメタデータを置く場所）を選び、ホストプールの種類（pool）を選ぶ。ここまでは、AVD でも AVD hybrid でも同じ。
3. 違いが出るのはセッションホストの選択。選択肢は **Azure、Azure Virtual Desktop Hybrid、Azure Local** の 3 つ。
4. AVD Hybrid を選ぶと、Azure Arc に登録されている VM が自動的に表示される（音声認識が乱れており、「VM が Azure Arc から自動入力される」という趣旨の発話です）。

### 6.2 MAM（Intune app protection policies）の体験

想定シナリオは、6 か月のプロジェクトで契約社員を受け入れる場合です。端末を登録（enroll）して管理し続けたくないが、アプリとデータにはアクセスさせたい、という場面です。

1. 新しい契約社員が、ユーザー名とパスワードでサインインする（パスワードレスも可能と補足）。
2. MAM が有効だと、まず端末の**登録（registration）**が求められる。登録は enrollment（管理への登録）とは別物で、Entra にレコードを作るだけ。
3. 登録すると、デバイス上にアカウントが追加される。
4. ユーザーがログインすると、デバイスのセットアップが完了する。
5. Windows app が最新バージョンでないことが自動的に検出され、更新するまでアクセスがブロックされる。

OS バージョンや Windows app のバージョンなど、複数のポリシーを設定できると補足されています。

### 6.3 Direct stream の multipath

想定シナリオは、先ほどの契約社員が、オフィスの問題によりカフェで作業している場面です。

1. アプリで作業している状態で、Wi-Fi を無効にする操作を模擬（シミュレート）する。
2. 接続がただちにモバイルホットスポットに切り替わる。左側のグラフィックを見ると、まったく途切れがない。

これは Direct stream の **multipath** によるもので、最初に最適なネットワークを選び、接続が悪くなると、ユーザー体験に支障なく自動で経路を切り替えると説明されています。

## 7. 注意点・発表者の気付き

- **アプリが最大の難所**：移行で最も時間がかかるのはアプリ（long pole）。棚卸しから始める。
- **パッケージの二重管理**：Chevron では、VDI 用に別のパッケージリポジトリを維持していた。Intune で 1 回作って全デバイスに配れれば大きな成果になる、と Bev 氏がコメントしている。
- **ツールの追加は複雑さを増す**：Chevron では、性能・安定性の問題に対してツールを足し続け、環境が複雑になった。
- **コスト面の声**：「すでにノート PC を渡している」という社内の反応があり、低コストデバイスで回収する必要がある（WTW の登壇者）。
- **AVD が残るケース**：GPU、ドメイン参加が必要で SaaS 化できないもの、追加ストレージや Azure 容量、オンプレミスとの通信が必要なものは、Chevron でも AVD を使っている。
- **登録と enrollment は違う**：MAM のデモで、登録は Entra にレコードを作るだけで、管理への登録ではないと強調されました。
- **Direct stream の制約**：機能の提供状況・地域などの詳細は、発表では触れられていません。

## 8. 利用者にとっての利点

| 事例・テーマ | 語られた成果 |
| ---- | ---- |
| Chevron | Windows 365 の台数が約 3 か月で 50 台から 6,000 台に増加（現在のエンドポイントは 10,000 台前後）。約 80% のユーザーが AVD から自発的に移行。デジタル体験スコアが、おそらく 5〜10% 高い（ノート PC 上との比較）。セルフサービスのプロビジョニングで約 30 分。未使用 45 日で廃止 |
| Willis Towers Watson | 1 年間の Citrix ライセンス期間内に、AVD への移行を完了させる方針。AVD 月間アクティブ 15,000 人と Windows 365 の 1,700 人。M&A、開発者向けにも Windows 365 を拡大予定 |
| AVD hybrid | コネクティビティ基盤をクラウドに移し、VM やアプリ、プロファイルはオンプレミスのまま、最小限の変更でクラウド活用を開始できる |
| Windows 365 Reserve | 障害時の一時的な Cloud PC を 10 日間提供し、継続性を確保。短期プロジェクトやハッカソンでの試用にも |
| Direct stream | 接続約 10 秒、ネットワーク切り替え時にも途切れない |

> 注意：WTW の「移行」は、発表では「1 年間のライセンスを使って AVD へ移す」と述べられた方針で、移行の完了や結果の数値は語られていません。

## 9. まとめ

- ライセンス、ハードウェア価格、障害のリスクという圧力に対して、「現状維持」と「一括移行」の間に、準備できたワークロードから移す第三の道があります。
- 4 つの不安に対する答えとして、コストと既存投資には AVD hybrid と Windows 365 Reserve、データ主権とセキュリティにはリージョン・government cloud・BYOD 向けの新機能（MAM、context-based redirection、input and output protection）、体験には Direct stream、移行の複雑さにはアプリの棚卸しと Migration API などが紹介されました。
- 1 つのコントロールプレーンと 1 つのアプリ（Windows app）で、複数の形態を一貫して管理・利用できるため、段階的な移行がしやすくなります。
- 最後に Bev 氏は、(1) 今あるものを評価しアプリと依存関係を棚卸しする、(2) AVD hybrid や Windows 365 Reserve で試験導入する、(3) 試した後に拡大する（ハードウェア更新やライセンス要件に合わせる）、(4) オンプレミス VDI を縮小して最適化する、(5) 社内にスキルがなければパートナーを検討する、という流れを勧めています。
