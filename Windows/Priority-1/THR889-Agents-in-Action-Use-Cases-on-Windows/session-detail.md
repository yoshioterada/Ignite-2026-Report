# THR889 Agents in Action: Use Cases on Windows

## 1. はじめに

このセッションは、Windows 上でエージェントを安全に動かすための考え方と、それを実際のエージェントで確かめるデモを、25 分で紹介するシアターセッションです。

登壇者は Windows のエージェント向けプラットフォームを担当する PM で、Windows の方針を **hybrid intelligence（ローカルとクラウドの併用）** と **agent governance（エージェントのガバナンス）** の 2 本柱で説明します。governance はさらに identity（識別）、containment（隔離）、management（管理）に分けられます。後半のデモでは、GitHub Copilot、Perplexity、Hermes、OpenClaw といったエージェントが、ローカルモデルの利用や MXC（Microsoft Execution Containers）によるアクセス制限を実際にどう扱うかが示されます。

## 3. 何に関する発表か

AI に天気を尋ねる使い方から、コードの作成、アプリの作成、ファイルの操作といった**実際の仕事を任せる使い方**へ移ってきました。エージェントは自分で判断し、使うツールを選び、デバイスとやり取りします。そのため、OS に求められるものが変わるというのが出発点です。発表者は、Windows プラットフォームとして次の 3 つの問いを考えていると説明しています。

1. 毎回高額なクラウド処理にしなくても、エージェントに計算資源を与えるにはどうするか。
2. すべてにアクセスさせることなく、役に立つ範囲のリソースを与えるにはどうするか。
3. 数百、数千台のデバイスにまたがるエージェントの活動を、組織としてどう統制するか。

発表は次の流れで進みます。

1. Windows の 2 本柱（hybrid intelligence と agent governance）の説明
2. governance の 3 要素（identity、containment、management）
3. なぜ Windows なのか
4. デモ（GitHub Copilot app、Perplexity、Hermes、OpenClaw）
5. まとめと関連セッションの案内

## 4. 発表者が伝えたいメッセージ

発表者が示す目標は、**「適切な identity の境界と管理の仕組みのもとで、エージェントが有用な仕事をするための計算資源を与える」**ことです。能力の高いエージェントと、ユーザーや組織が持つべき統制の両方を、同時に実現したいという考えです。

また、エージェントはクラウドかローカルかの二者択一ではなく、**両方を組み合わせて使う**ものだと位置づけています。そしてエージェントの制限は、エージェントへの指示（プロンプト）に頼るのではなく、**OS（Windows）の層で強制する**という点を、デモで繰り返し示しています。

## 5. 発表内容の詳細

### 5.1 背景：エージェントはアプリケーションと違う

従来のアプリケーションは、ボタンを押せば決まった結果が得られます。一方、エージェントは同じゴールを 2 回与えても、異なる経路をたどり、異なるツールやファイルを使い、異なる判断をする可能性があります。この柔軟さがエージェントの価値であり、手順を 1 つずつ指示せずにゴールだけ与えられるのが利点です。しかし、すべての行動を予測できないため、**エージェントに許される範囲をプラットフォーム側の境界で定める必要がある**と説明しています。

### 5.2 Hybrid intelligence

クラウドモデルは非常に高機能ですが、すべてのタスクにクラウドの AI が必要なわけではない、というのが出発点です。発表では、NVIDIA RTX Spark を搭載した Surface Ultra というマシンを使いながら（機種名は音声認識の都合で表記が確定できません）、ローカルで処理する利点を 2 つ挙げています。

| 利点 | 説明 |
| --- | --- |
| コスト | コーディングやコンテンツ生成でエージェントを一日中使うと、クラウドのトークン使用量が急速に増える。一部の処理をローカルで動かせば、すでに持っている計算資源を使え、毎回クラウド推論に支払わなくて済む。 |
| プライバシー | ローカルモデルなら、推論をデバイス内で完結できる。プロンプト、データ、出力が必ずしもクラウドに送られないので、機密情報を含むプロジェクトに向く。 |

ただし、すべてをクラウドからローカルに移す話ではないと強調しています。hybrid intelligence は、開発者がローカルとクラウドの計算資源を**併用**できる考え方です。Windows が、ハードウェア、ローカルの AI ランタイム、開発者向けプラットフォームを組み合わせて、ローカルのインテリジェンスをエージェント体験の実用的な一部にするとしています。

### 5.3 Agent governance：3 つの領域

#### Identity（識別）

ユーザーの代わりにエージェントが作業するとき、その活動を自分の活動と区別したい、という要望から始まります。Windows は、シナリオに応じて複数のエージェント identity の方式をサポートします。

* ユーザーの代理で動くエージェントは、その活動が「エージェントによるもの」として識別できる。
* より自律的なエージェントは、**別の Windows のエージェント identity** のもとで動ける。独自の実行環境を持ち、そのアクセスを人間のユーザーとは独立して統制できる。

#### Containment（隔離）：MXC

**MXC（Microsoft Execution Containers）** は、予測できないエージェントの挙動を、プラットフォームが定めた境界の内側に閉じ込めるものです。例として、ウェブサイトを作らせるコーディングエージェントに、個人情報や機密データへのアクセスは不要です。MXC なら必要なリソースだけ与え、残りは制限できます。

重要なのは、この制限が Windows の層で強制されることです。「エージェントに何をすべきか、すべきでないかを伝える指示」だけではありません。また、コーディングアシスタントと、ツールやアプリをまたいで独立して動く自律エージェントとでは、必要な隔離レベルが違います。そのため Windows は、1 つの隔離モデルを押し付けるのではなく、**ワークロードに応じた複数の隔離レベル**を用意しています。

#### Management（管理）

組織は、どのエージェントが動いていて、何にアクセスでき、どうポリシーを強制するかを把握する必要があります。Windows は、これを Microsoft のセキュリティ・管理のエコシステムにつなげます。

| 製品 | 発表で説明された役割 |
| --- | --- |
| Intune | IT がエージェントのポリシーを定義・管理する |
| Microsoft Entra | エージェントの identity、認証、アクセス制御をつなぐ |
| Agent 365、Defender、Purview | エージェントの活動を、管理・セキュリティ・データガバナンスのワークフローに取り込む |

（トランスクリプト上は「PureView」と書かれていますが、製品名としては Purview の意味と判断しました。）

発表者は、**identity がこの 3 つをつなぐ**と述べています。identity によって「どのエージェントが動いているか」が分かるため、隔離やポリシーを適用でき、他のアプリやサービスとのやり取りにもその文脈を引き継げます。デバイス上とクラウドで、バラバラの制御ではなく、一貫したガバナンスを目指すとしています。

> ご参考：MXC のアーキテクチャについて、翌日のブレイクアウトセッション 390（11:30）が案内されています。

### 5.4 なぜ Windows なのか

MXC はクロスプラットフォームであるのに、なぜ Windows なのか、という問いに対し、発表者は「単にサンドボックスがあることではない」と答えています。違いは、次の要素が**まとまって**あることです。

* 複数の隔離レベル
* エージェントの identity
* 組織がすでに使っている管理・セキュリティツール
* エージェントやアプリケーション任せにせず、OS が強制する境界

コーディングエージェントでも、OpenClaw のようにより自律的なエージェントでも、Windows は組織の既存のガバナンスポリシーにつながる、適切な identity と隔離のモデルを提供できるとしています。MXC を使って構築しているパートナーも多く、発表者はすべてを紹介する代わりに数例をデモすると述べています。

## 6. デモ・手順

このセッションにはライブデモがあります。画面は音声から見えないため、以下は発話で語られた範囲に限ります。デモは NVIDIA RTX Spark の Surface Ultra 上で行われました（機種名は音声認識の都合で表記が確定できません）。

### 6.1 デモ 1：GitHub Copilot app で hybrid intelligence（ローカルモデル）

1. Task Manager を開き、GPU に **42 GB のメモリを割り当てている**ことを示します。
2. GitHub Copilot app の model providers を見せます。Windows ML がインストールされており、ローカルモデルが動いている状態です（モデル名は「see Flint NVFP4」と聞こえますが、音声認識の都合で表記が確定できません）。モデルを止めれば Task Manager の使用量が下がると説明します。
3. まず、GitHub Copilot の **Fusion** 機能を紹介します。クラウド規模の推論と、デバイス上で直接動くモデルの長所を組み合わせ、タスクに最適なモデルをエージェントが使えるようにする機能です。
4. 題材は、発表者が作った、シアトルの Capitol Hill 地区のレストランをランダムに推薦するウェブサイトです。「日本料理をこのリストに追加して」といったタスクを与えると、Fusion が推論を担当するという説明です。このタスクは、説明のみで実行結果は示されていません。
5. 次に、ローカルモデルだけを使う例です。読み込み済みの「レシピサイト」プロジェクトで、現在はラザニアのレシピしかありません。ここにチョコチップのレシピを追加する、ローカルモデル向けのプロンプトを実行します。
6. 推論中に GPU 使用率が急上昇することを見せ、GPU へのオフロードの証拠だと説明します。時間がかかるため、先に別のデモに移ります。
7. しばらくしてチョコチップのレシピが追加されました。発表者は「local intelligence」と述べています。

発表者は、これは GitHub Copilot が hybrid intelligence と MXC の両方を使っている例だと説明しています。

### 6.2 デモ 2：Perplexity のローカルモデルと MXC

1. model providers でさきほどのローカルモデルを停止し、Perplexity のアプリを開いて、そのローカルモデルを起動します。専用 GPU メモリが、モデルを止めたときに下がり、Perplexity のモデルを起動すると上がることを確認できると説明します。
2. Perplexity をコンピューターモード（computer mode）で使い、「デスクトップフォルダにアクセスできるか」と尋ねます。モデルの起動に時間がかかりました。
3. 答えは「**デフォルトではデスクトップフォルダにアクセスできないはず**」です。実際に、アクセスの要求は拒否されました（「denied by you or the sandbox policy」という趣旨の表示と発言）。
4. Perplexity の設定でフォルダを追加すると、**サンドボックスの形を変えて、エージェントに特定の対象へのアクセスを与える**ことになります。そのうえで、デスクトップフォルダへのアクセスを再度試みます。
5. デスクトップへのアクセスを与え、サンドボックスの形を変えたあとは、エージェントがデスクトップフォルダにアクセスでき、中身をすべて答えられる状態になった、と説明します。発表者はこれを「Perplexity での MXC のデモ」としています。

### 6.3 デモ 3：Hermes と MXC

1. Hermes も MXC を使っていると紹介し、「このフォルダ（パスを指定）のファイルを使って、その内容に基づく詩を書いて」と指示します。
2. このときサンドボックスはオフで、「隔離されていない状態で動いており、何にでもアクセスできるはず」と説明します。
3. Hermes が詩を書き始めます。発表者がデスクトップの内容を確認すると、public フォルダにレシピ、ボートの絵、木々と睡蓮の絵がありました。Hermes はキッチンと水辺に関する短い詩を書き、ファイルを正確に読み取っていたと述べています。
4. 次に、Hermes に自分のプロジェクトのリポジトリ以外へアクセスさせたくない、あるいは非公開のファイルを読ませたくない場合として、サンドボックス設定を開き、**サンドボックスをオンにします**。
5. 「ダウンロードフォルダを読めますか」と尋ねます。ダウンロードフォルダへのアクセスは与えていないため、ブロックされるはずだと説明します。
6. エージェントは、サンドボックスのファイルアクセスツールが失敗した、と答えました。代わりに、**ファイルを添付する**方法があるとも示します。直接ディレクトリを読む能力はありません。

発表者は、Perplexity、Hermes、GitHub Copilot はいずれも MXC を使う信頼できるエージェント体験であり、エージェントをまたいで予測可能な体験になるため、ユーザーはファイルが安全だと安心できる、と述べています。

### 6.4 デモ 4：OpenClaw と MXC セッション

OpenClaw は、別の種類の MXC サンドボックスを使うと説明されています。

1. 発表者の OpenClaw は、エージェントを**分離された Windows セッション内で、別のエージェントユーザーとして**実行しています。そのため、デスクトップ、プロセス、ユーザーコンテキストを共有しません。
2. Task Manager の Users タブを開き、発表者のユーザーと、OpenClaw のエージェントユーザーが、それぞれ別のプロセスを持っていることを示します。人間のユーザーとセッションからは完全に分離されています。
3. 何の権限も与えていない状態で「これにアクセスできますか」と尋ねます。結果は「できない」となるはずだと説明します。
4. 発表者は、OpenClaw が長時間動き、コードを自己修正する自律的なエージェントである点を挙げ、「自分のセッションで動き、デバイスから完全に分離されているので、仕事を任せても安心できる」と述べます。特定のファイルやネットワークへのアクセスを与えたい場合は、与えることもできます。
5. エージェントユーザーは人間とは別のユーザーなので、人間のユーザーはエージェントユーザーを制御できます。「claw cuddle」と聞こえるツール（音声認識の都合で表記が確定できません）で、gateway の状態が見え、動作中であると確認できます。共有ドライブも見られます。エージェントの活動はすべて見られますが、エージェントから人間の活動すべては見えません。
6. 最後に、エージェントはファイルの読み取りを試みましたが、エージェントのセッションは別の隔離されたユーザーアカウントで動いているため、デスクトップのファイルにはアクセスできませんでした。

なお、OpenClaw のアプリは最近ストアに新しいバージョンが公開され、UI が少し更新されたと案内されています。

## 7. 注意点・発表者の気付き

* エージェントは同じゴールでも毎回違う動きをするため、挙動を予測しきれない前提で、プラットフォーム側に境界を設ける必要があります。
* 制限は、エージェントへの「指示」ではなく、Windows の層で強制されるものとして説明されています。
* 隔離のレベルは 1 つではなく、ワークロード（コーディングアシスタントか、自律エージェントか）に応じて選ぶものです。
* サンドボックスをオフにすると「隔離されていない」状態になり、エージェントは何にでもアクセスできます（Hermes のデモで説明）。
* ローカルモデルはクラウドの置き換えではありません。クラウドモデルが提供する重要な能力は残るため、併用する考え方です。
* デモでは、ローカルモデルの起動と応答に時間がかかる場面がありました（Perplexity の起動、GitHub Copilot のレシピ追加）。
* MXC の詳細なアーキテクチャ、hybrid inference の詳細は、このセッションでは扱われていません。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

* **コスト**：一日中エージェントを使う場合、ローカルの計算資源を使うことでクラウド推論の費用を抑えられる。
* **プライバシー**：ローカル推論なら、プロンプトやデータ、出力が必ずしもクラウドに送られない。機密情報を含むプロジェクトに向く。
* **安心感**：MXC を使うエージェント（Perplexity、Hermes、GitHub Copilot）では、ユーザーはファイルが安全だと考えられる。OpenClaw のように長時間動く自律エージェントでも、別セッションで動くため、仕事を任せやすい。
* **組織の統制**：Intune、Entra、Agent 365、Defender、Purview と連携し、数百、数千台のデバイスで一貫したガバナンスを目指せる。

なお、特定の顧客名や数値の導入効果は、発表では紹介されていません。

## 9. まとめ

Windows は、エージェントの時代に向けて、**hybrid intelligence** と **agent governance** の 2 つを進めています。ローカルとクラウドの計算資源を併用してコストとプライバシーの課題に応え、identity、containment（MXC）、management で、エージェントの活動を OS の層で統制します。

デモでは、ローカルモデルによる GitHub Copilot のレシピ追加、Perplexity と Hermes でのフォルダアクセスの制御、OpenClaw の別ユーザーセッションでの分離が示されました。登壇者はこれを「trustworthy agentic computing（信頼できるエージェントコンピューティング）に向けた進展」と位置づけています。

関連セッションとして、hybrid inferencing は翌日 9:00 のブレイクアウトセッション 389、MXC は翌日 11:30 のブレイクアウトセッション 390 が案内されています。最後に、アンケートのスライドが示されました。
