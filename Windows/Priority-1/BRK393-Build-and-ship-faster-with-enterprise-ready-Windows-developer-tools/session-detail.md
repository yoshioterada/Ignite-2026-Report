# BRK393 Build and ship faster with enterprise-ready Windows developer tools

## 1. はじめに

このセッションは、Windows 開発チームの 2 人が、開発者のライフサイクル（オンボーディング、インナーループ、アウターループ）に沿って、Windows 上の開発ツールの改善点を紹介するものです。内容の大半は**ライブデモ**で、新しいデバイスのセットアップを 1 行のコマンドで行う developer configuration、Dev Drive、各種コンテナー（Windows Sandbox、MXC、WSLC）、Core Utils、Intelligent Terminal、PowerToys、そして Windows のシェルのカスタマイズが順に見せられます。

「新しい PC を開発できる状態にするのに数時間から数日かかる」「Windows でも Linux と同じコマンドを使いたい」「エージェントを安全に動かしたい」といった悩みを持つ開発者や、開発者向けの端末を用意する IT 管理者に向いた内容です。紹介された機能の多くは、すでに retail / GA チャネルで使えると説明されています。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/BRK393](https://ignite.microsoft.com/en-US/sessions/BRK393)

もう一つの軸は、「Windows が開発者にとって opinionated な（開発者向けの既定値を持った）OS であること」です。ダークモード、長いファイルパス、隠しファイルや拡張子の表示など、開発者が新しい PC で最初に行う設定を、最初から用意するという考え方です。また、全体を通して「muscle memory（体が覚えている操作）」を大切にするという話が繰り返されます（Core Utils や PowerToys、シェルのカスタマイズ）。

最後に、「Windows を自分のものにして、自分に合うようにしてほしい」という呼びかけで締められました。

## 5. 発表内容の詳細

### 5.1 Project Zenith と developer configuration

**Project Zenith** は、パワフルなハードウェア（OEM と協力して用意）と、開発者向けに opinionated な OS を最初から組み合わせたものだと説明されています。ステージには Zenith クラスのデバイスがいくつか置かれていました。

- AMD の dev box
- Surface RTX Spark dev box
- HP ZBook Ultra G3A（デモの大半で使うデバイス。デバイス名は聞こえたとおりで、音声認識の都合で表記が確定できません）。メモリは 192 GB と語られました。

これらは Project Zenith をプリロードした状態で出荷される予定で、Acer、AMD、Asus、HP、Lenovo、Surface などのパートナーからこのプリロードが既定で入る、と説明されています。

#### Developer configuration スクリプト

Zenith 対応デバイスを持っていない、通常の古い Windows ノート PC でも、同じ構成にできるように、**developer configuration スクリプト**が用意されています。2 つのバージョンがあります。

| バージョン | 内容 |
| ---- | ---- |
| standard（推奨） | 開発ツールチェーンの良い基本セット。Python、PowerShell 7、Git、GitHub CLI、VS Code に加え、ターミナルを見やすくする oh my Posh の設定、WSL と Ubuntu。 |
| full | standard のスーパーセット（すべてに、もう少し追加したもの）。 |

あわせて、Windows の設定も調整されます。ダークモード、長いファイルパス、隠しファイルの表示、ファイル拡張子の表示など、開発者が普段行う設定が自動で行われます。何度でも実行でき、何かが変わってしまった場合は元に戻せます。スクリプトが何をしているかは隠されていません。

これはオープンソースのプロジェクトで、aka.ms/developerconfig（トランスクリプト上は "devconfig" とも言い換えられています）からスクリプトを入手できます。モジュール化されているため、WSL や Linux の開発者が WSL の構成だけを素早く行いたい場合は、その部分だけを取ることもできます。デモは 6.1 に記載します。

### 5.2 ローカルモデルで重い処理を動かす「touch grass」

Hamza 氏が、Zenith クラスのパワフルなデバイスの限界を試すために、ローカルモデルで少し重い処理をさせると紹介しました。Clint 氏の説明によると、デスクトップに手続き的に草を生成する小さなタスクバーアプリを用意しており、「touch grass」と呼ばれるお気に入りのデモです。使うローカルモデルは「MAI code 11 flash」と聞こえます（音声認識の都合で表記が確定できません）。すでにメモリに読み込まれており、一般的な雑務（toil）タスクをこなせる、と説明されました。

ローカルモデルの利点として、Clint 氏は次を挙げています。

- Frontier モデルは Frontier な仕事に向いているが、ローカルモデルならデータは安全なまま。
- クラウドにトークンを使わない。
- すでにあるハードウェアを活用できる。データはコンピューターの外へ出ない。

デモは 6.2 に記載します。以降、このデバイスをほぼすべてのデモに使い、タスクが終わるとデスクトップに草が現れる、という仕掛けです。

### 5.3 Dev Drive

**Dev Drive** は、ReFS をベースにした新しいファイルシステムです。多くのファイルフィルタードライバーを取り除き、開発者のシナリオ向けに設計された Defender の performance mode を備えています。作成は、設定の「system」の「advanced」にある「create dev drive」ボタンから簡単に行えると説明されました。

ベンチマークアプリのデモ（6.3）では、C ドライブと D ドライブ（Dev Drive）を比較しました。結果は約 2.4 倍で、登壇者は、IO が多いシナリオで平均 2〜3 倍速くなると述べています。使っていないなら、速度を取りこぼしている、と Dev Drive の利用を勧めています。

### 5.4 コンテナー：Windows Sandbox、MXC、WSLC

Windows には、現在いくつかのコンテナーの選択肢があります。

| 技術 | 説明 |
| ---- | ---- |
| Windows Sandbox | 使い捨て（ephemeral）のコンテナー。素早く起動し、閉じればきれいに片付いて消える。Hyper-V VM を手作業で作るよりずっと速い。他の環境に触れない、隔離されたクリーンな環境が必要なときに向く。CLI から起動できる。 |
| MXC（Microsoft Execution Containers） | エージェントの作業用に隔離された環境。エージェントが何にアクセスできるかをコンテナーに指示でき（例：ファイルにはアクセスできるが Windows の設定にはアクセスできない、IO アクセスは許可する、など）、作業が終わるとコンテナーは閉じ、きれいに片付く。監査も可能。MDM と GPO に対応している。 |
| WSLC（WSL containers） | WSL に組み込まれた Linux カーネルを共有する Linux コンテナー。Linux でコンテナーを使うときと同じ感覚で、コマンドライン引数もおなじみのもの。enterprise ready で、（聞き取り不明瞭な）統合機能が最初から備わっている。 |

MXC については、エージェントの利用が増えるなかで「ガードレール」と「blast radius（影響範囲）」の話をよく聞く、という背景が語られました。エージェントがマシン中のファイルを触ったり、変更したり、新しいファイルを作ったりしてほしくない場合のために作られたもので、「エージェントがいるときは実行コンテナーで実行する」というポリシーを、SDK 付きで展開できます。MXC は「昨日」に多くの人が耳にしたはずだとも語られています。

デモは、WSLC（6.4）と Windows Sandbox（6.5）です。

### 5.5 Core Utils

Linux で使っている grep、find、cat などのユーティリティが、Windows に戻ったときに使えない不便さに応える機能です。事前に `WinGet install Microsoft.core utils`（発話どおり）を実行すると、同じユーティリティが PowerShell でそのまま使えるようになります。設定も追加のセットアップも不要で、WinGet のコマンド 1 つだけだと説明されました。チームの大きな主張は、どのエコシステムから来ても muscle memory が期待どおりに動くことです。デモは 6.6 に記載します。

### 5.6 Intelligent Terminal

Hamza 氏が使っているのは、クラシックな Windows Terminal ではなく、実験的な fork である **Intelligent Terminal** です。ターミナル体験の最先端として試している、と紹介されました。2 つの柱があります。

1. **エージェントの管理**：GitHub Copilot、Claude（音声上は "Cloud" とも聞こえます）、Codex のようなエージェント CLI をターミナルで使っている人が、エージェントが何をしているか、注意が必要か、何を待っているかを簡単に見られるようにする。
2. **Clippy のような支援**：Office の Clippy のように、間違った操作に気づいて助けてくれる。誰もが PowerShell や WSL、ターミナルの専門家ではないため。

#### サイドバー

縦並びのタブ表示（サイドバー）では、各タブの状況と作業ディレクトリを表示するなど、構成を変えられます。Git の情報を載せることも、エージェントだけを表示するフィルターも可能です。タブを分割すると、ペイン単位で状況が見えます。折りたたむこともできます。

また、**グローバル検索**があり、タブと、最近のエージェントセッション（Copilot でも Claude でも）を横断して検索できます。最近のエージェントセッションを常に表示させることもでき、検索から過去のセッション（例：リリースビルドのセッション）を開き直せます。

#### エージェントペイン

テストが失敗したときに、ターミナル下部に「何か問題が起きたと検知しました。ここをクリックすると、エラーを分析して修正します」という Clippy のような案内が出て、エージェントペインで修正まで進められます。エージェントペインはターミナルの中にあり、シェルで起きていることのコンテキストを常に持っています。デモは 6.7 に記載します。

エージェントやモデルは設定で選べます。デモでは「Opus 55」（聞こえたとおり）を使っていますが、設定の agent から、好きなエージェントやモデルにつなげられ、MAI Flash や Ollama のようなローカルモデルも使えると説明されました。Clint 氏は、**ACP（Agent Client Protocol）**、つまりオープン標準に対応する harness なら何でもペインに組み込める、と補足しています。Intelligence 用の slash コマンドもあり、エージェントペインを常に右に置くこともでき、WSL でも期待どおり動きます。テーマも変えられます。

Intelligent Terminal は、オープンソースの実験的な Windows Terminal で、コミュニティのフィードバックを聞きながら、ほぼ 2 週間ごとに頻繁にリリースしていると説明されました。

### 5.7 PowerShell 7 の Windows への組み込み計画

Clint 氏が「発表できて嬉しい」こととして述べた内容です。

- PowerShell 7 は、Windows の branches の中に入った（now in Windows inside of branches）。Windows retail には **2027 年**から入り始める。
- **最初の段階**：Windows PowerShell が optional feature として、既定で有効のまま（発話では「この phase」と話され、番号は付けられていません）。
- **Phase 2**：新規インストール向け。PowerShell 7 が optional になり、既定で無効になる（発話は "PowerShell 7 will be optional, and it will become disabled by default" と聞こえます。どちらの PowerShell が既定で無効になるかは音声の都合で確定できません）。
- **Phase 3**：新規インストールの Windows で、Windows PowerShell 5.1 が削除される。

いずれの段階もデータに基づいて判断し、誰の運用も妨げないよう、コミュニティと一緒に安全にスムーズに進めると説明されています。

### 5.8 PowerToys

PowerToys は、Windows にあってほしいと思う機能を足し、生産性を上げるオープンソースのユーティリティ集で、30 ほどあると紹介されました。デモ（6.8）では次が紹介されました。

| ツール | 説明（語られた内容） |
| ---- | ---- |
| Command Palette | キーボード中心の人向けのランチャー。拡張機能ベースで、dock を作り、リソース管理などを出せる。 |
| Window Hopper | フォーカスされているアプリのウィンドウだけを、同じキーストロークで巡回する。alt+tilde（Tab の真上のキー）を使う。 |
| Grab and Move | alt を押しながら、タイトルバー以外の任意の場所でウィンドウを掴んで動かせる。タブの多いアプリなどでタイトルバーを掴みにくいときに便利。 |
| FancyZones | 最初期からある PowerToys の一つ。shift を押しながらウィンドウを掴み、ゾーンにスナップする。shift と control を押して複数のゾーンにまたがせることもでき、ゾーンは自由に作れる。 |
| Advanced Paste | Windows の貼り付けを強化する。モデルプロバイダーやエージェントをつなげられるが、モデル無しの組み込み機能もある（CSV を JSON として貼り付け、画像の OCR など）。カスタム貼り付けのオプションも作れる。 |

### 5.9 Windows K2：OS 自体の改善

開発者から「Windows をより速く、信頼でき、高性能で、カスタマイズしやすくしてほしい」という声があり、ここ数か月、**Windows K2** という取り組み（"initiative called Windows K2"）を進めてきたと説明されました。柱は 3 つです。

1. **Performance（パフォーマンス）**：多くの場合で、最大 20% 応答性が向上。検索、スタート、ファイルエクスプローラーなど日常使うシェルが、更新の適用とともに速くなる。
2. **Reliability（信頼性）**：更新などによる中断が減る。
3. **Control and customization（制御とカスタマイズ）**：スタート、検索、コンテキストメニュー、ファイルエクスプローラーなどをカスタマイズでき、新しい更新でその設定が登場していく。

デモは 6.9 に記載します。

## 6. デモ・手順

デモはライブで行われたと語られています（"we're going to do it live"）。画面の細部は音声から分からないため、語られた範囲だけを書きます。

### 6.1 developer configuration スクリプトの実行（ライブ）

1. デモ用に、**仮想マシン**を使う（ハードウェアのリセットは時間がかかり、VM ならチェックポイントを取れて、何度も試せるため、とのこと）。
2. PowerShell を起動し、コマンドを 1 つ実行（Enter を押す）。これでスクリプトがダウンロードされ、実行が始まる。
3. 最初から最後まで約 15 分、UAC プロンプトが 1 回、再起動が 1 回ある、と事前に説明。
4. セッションの途中で、この VM の進行状況を確認する。中盤（デモ 2 に戻ったとき）には、WSL をインストール中で、再起動を終え、完了まで数秒の状態。
5. 終盤、このマシンは完全に構成済みの状態になっている。UAC と再起動を 1 回ずつ経た。Ubuntu、PowerShell、GitHub Copilot がすぐ起動できる状態で入っており、コマンドラインから GitHub Copilot を起動できる。ダークモード、ファイルパスの有効化、カスタムのコンテキストメニューなども反映されている。

登壇者は「1 行のコードで、ほぼ空の VM が、構成済みですぐ使えるデスクトップになった」と述べています。

### 6.2 ローカルモデルのタスク（touch grass）

1. Clint 氏が、ローカルの MAI code 11 flash モデル（メモリに読み込み済み）に、次のようなタスクを与える。未使用のコードの検出、import されているパッケージの確認、（聞き取り不明瞭な）フラグ、結果の要約、そして「実行して」、最後にアプリを実行する。
2. Hamza 氏は、未使用の import や脆弱性の監査も依頼していると補足する。
3. セッションの途中で、デスクトップに草が現れる。デモ中盤の確認では、デスクトップの草アプリが正常にビルド・実行され、未使用のフラグがいくつか見つかっていた。8 分ほどの間に、ビルドと実行まで行ったと語られる。

この処理は、このコンピューター上で 100% ローカルで動いていると説明されています。

### 6.3 Dev Drive のベンチマーク

1. 画面には C ドライブと D ドライブがあり、専用に作られたベンチマークアプリを実行する。
2. 比較は、C ドライブと D ドライブ（Dev Drive）で行う。テスト内容：
   1. git clone（15,000 ファイル）
   2. Node（VS Code の ESLint、npm CLI）
   3. .NET（.NET 10 の eShop）
   4. Rust（Microsoft Edit プロジェクト）
3. これらは、他のワークロードも同時に動いている状態でこのコンピューター上でコンパイルされている。Clint 氏は、IO の重いシナリオで約 2.6 倍の改善を予想すると述べる。
4. このコンピューターは Clint 氏の社用マシンで、Microsoft のポリシー下にある。つまり実際の企業環境のシナリオだと説明。
5. 結果は約 2.4 倍で（発話は "2.4% X faster" と聞こえます）、登壇者は「2.4 は素晴らしい」と述べる。もう一人の登壇者が、Terminal のビルドに Dev Drive を使っており、平均 2〜3 倍速いと補足した。

### 6.4 WSLC のデモ

1. ウェブブラウザー、GPU のタスクマネージャー、WSLC のコマンドラインを並べて表示する。
2. WSLC のコマンドを実行する。コンテナーが起動し、Web サーバーが立ち上がる。
3. パーティクルのシミュレーションが 20,000 個で動き、GPU の使用率が上がる。数を 50,000 に増やす。
4. シミュレーションをキャンセルし、コンテナーを停止する。メモリが下がり、シミュレーションが止まる。

起動は約 5 秒、停止は数秒。コマンドラインだけで操作でき、GPU も使えると説明されています。Linux のネイティブなコンテナーが、Windows 上でそのまま動くという点が強調されました。

### 6.5 Windows Sandbox のデモ

1. ターミナルから `WSB start` で Sandbox を起動する（スタートメニューからも起動できるが、コマンドラインを使う）。
2. 起動時の ID を変数に入れておく。
3. その ID で接続すると、PC 上で他の処理が動いていても約 5 秒で、閉じ込められた Windows 環境が使える。中で行うことは外の PC に影響しない。
4. `WSB stop` で停止する。

全体で約 20 秒で、隔離環境を起動して停止できたとのことです。Hamza 氏は、Clint 氏から実行ファイルを渡されてテストを頼まれたとき、ローカルでは実行せず Sandbox（Linux なら WSL コンテナー）に入れて試す、という使い方を紹介しました。

### 6.6 Core Utils のデモ

1. Linux（WSL）で grep や find などの通常のユーティリティを使う。
2. 次に PowerShell で、デモの直前に `WinGet install Microsoft.core utils` を実行済みであることを示す。
3. PowerShell で grep、find、ファイルに対する cat を実行し、そのまま動くことを示す。

### 6.7 Intelligent Terminal のデモ

1. デモ用のリポジトリで、サイドバー（縦のタブ表示）を見せる。ステータスと作業ディレクトリを表示している。
2. タブを分割し、ペイン単位の状況が見えることを示す。サイドバーの折りたたみも見せる。
3. グローバル検索で、タブと最近のエージェントセッション（Copilot や Claude など）を検索し、過去の「リリースビルド」のセッションを開く。
4. 別のペインで、NPX コマンドを使って、記事サービス（article service）のテストを実行する。5 件成功、1 件失敗。
5. 下部の Clippy のような案内（エラーを検知したので、ここをクリックすると分析して修正する）をクリックする。
6. エージェントが TypeScript ファイルを調べ、何が問題かを特定し、ファイルを編集してバグを直す。権限モードは「シェルで何かを実行する前に必ず確認する」に設定してあるが、auto モードにもできる。
7. エージェントは同じテストを再度実行し、すべて合格した。
8. 設定の agent から、エージェントやモデルを差し替えられることを口頭で説明する（5.6 参照。実際に切り替える操作は語られていません）。

### 6.8 PowerToys のデモ

1. **Command Palette**：「code」と入力して Enter を押すと VS Code が起動する。dock を作ってリソース情報を出す操作を試すが、取得に数秒かかる。「2 plus 2」と入力して Enter を押すと、結果がクリップボードに入る。
2. **Window Hopper**：ファイルエクスプローラーのウィンドウだけを巡回する（alt+tilde。shift を押しながらで逆順）。
3. **Grab and Move**：alt を押して、アプリのウィンドウを任意の場所で掴んで動かす。
4. **FancyZones**：shift を押しながらタイトルバーを掴み、ウィンドウ（Notepad など）をゾーンにスナップする。shift と control で複数のゾーンにまたがらせる。
5. **Advanced Paste**：クリップボードの CSV を、組み込み機能で JSON として貼り付ける（モデルは使わない）。画像のクリップボードがあれば OCR で画像からテキストへ変換できる（デモ時にはクリップボードに画像が無く、実演していない）。カスタム操作として登壇者が作った「TLDR」（クリップボードの内容を、接続したモデルで 1 行に要約する）を、Notepad で Control Alt V から実行する。

### 6.9 シェルのカスタマイズ（Windows K2 の改善）

1. **タスクバー**：設定の taskbar behavior で、位置を top や left に変更し、その後、元に戻す。
2. **スタートメニュー**：設定で、Web 検索とストア検索をオフにできる。enhanced mode をオンにすると、特定のファイルやフォルダーにインデックスを絞り、検索が速くなる（登壇者は、自分はストア検索をあまり使わないと説明）。
3. **コンテキストメニュー**（新機能。coming と語られる）：ファイルエクスプローラーでダウンロードフォルダーを右クリックし、メニューを編集する。コピー系の操作を上にインライン表示する、cloud search を独立したセクションにしない、「show customize」（聞こえたとおり）を削除する、プロパティ（聞こえた表記は "backend properties"）を下に追加する、拡張機能の項目として Intelligent Terminal と terminal dev を追加する、といった変更を行い、デスクトップでも変更が反映されたことを確認する。なお、シェルのカスタマイズの説明の冒頭では「新しい run dialog」が最初の例として挙げられましたが、そこから話がタスクバーに移り、run dialog の詳細は語られていません。

> 補足：デモの途中で、登壇者がメニューや設定の場所を探して手間取る場面があり、「ライブではこれが一番やってはいけないことだ」と冗談交じりに話しています。

## 7. 注意点・発表者の気付き

- **VM でのデモ**：developer configuration のデモは、ハードウェアのリセットに時間がかかるため、VM を使った、と登壇者が正直に説明しています。
- **スクリプトの特性**：複数回実行でき、設定が変わっても元に戻せ、何をしているかが隠されていない（オープンソース）。モジュール化されている。
- **PowerShell の移行**：各 phase は、データに基づいて判断し、誰の運用も妨げないように進めるとされています。Windows PowerShell 5.1 は、新規インストールの Windows で削除する予定（Phase 3）。
- **提供チャネル**：多くは retail と GA で使えますが、シェルのカスタマイズなど一部は Insider で、順次展開中です。
- **Intelligent Terminal の位置づけ**：実験的な（experimental）fork であり、オープンソースです。
- **MXC**：エージェントが影響を与えられる範囲を、ポリシーで制限する目的のものです。
- 発表では、ローカルモデルの性能や、各ツールの詳細な設定手順までは触れられていません。

## 8. 利用者にとっての利点

発表で語られた効果をまとめます。

| 項目 | 語られた内容 |
| ---- | ---- |
| セットアップ時間 | 数時間から数日かかっていた開発環境の構成を、数分、繰り返し実行できる形に（デモでは約 15 分、UAC 1 回、再起動 1 回）。 |
| ローカルモデル | データがコンピューターの外に出ず、クラウドにトークンを使わず、既存のハードウェアを活用できる。 |
| Dev Drive | IO が重いシナリオで、約 2.4 倍（登壇者の説明では平均 2〜3 倍）の高速化。 |
| コンテナー | Sandbox は約 20 秒で隔離環境を起動・停止。WSLC は約 5 秒で起動。MXC はエージェントの影響範囲を制限し、MDM と GPO に対応。 |
| Core Utils | WinGet のコマンド 1 つで、Linux のユーティリティが PowerShell で動く。 |
| Windows K2 | 多くの場合で最大 20% の応答性向上、更新による中断の減少、シェルのカスタマイズ。 |

## 9. まとめ

このセッションは、Windows を開発者にとって「自分のものにできる」場所にするための、一連のツールとデモでした。1 行のスクリプトで開発環境を整える developer configuration、Dev Drive による高速化、Sandbox、WSLC、MXC という 3 種類のコンテナー、Linux のユーティリティを PowerShell で使える Core Utils、エージェント管理と修正支援を備えた Intelligent Terminal、PowerToys、そして Windows K2 による OS の高速化とカスタマイズが紹介されました。PowerShell 7 の Windows への組み込み計画（2027 年から retail に入り始める）も発表されています。

登壇者は、各機能の多くが今日すでに使えるとして、`WinGet install Microsoft.core utils`、Intelligent Terminal、WSLC、Dev Drive、タスクバーやスタートメニューのカスタマイズを試すよう呼びかけました。
