# BRKSP622 Build the agentic workplace with Dell and Microsoft

## 1. はじめに

このセッションは、Dell と Microsoft が共同で、AI エージェントが働く職場（agentic workplace）で「PC がなぜ重要か」「AI のコストがどう変わるか」「セキュリティをどう確保するか」を説明する 45 分の発表です。聞き手は、次の PC のリフレッシュや AI インフラの計画を担当する IT 部門の意思決定者や、IT 戦略を考える人です。

発表者が最初に挙げた持ち帰りは 3 つです。

1. PC は、これまで以上に重要になる（人とエージェントが同時に働く前提で設計されている必要がある）。
2. ハイブリッドインテリジェンスで AI の処理がクラウドから PC に移るため、経済性が変わる。PC の更新は、AI インフラ全体の判断でもある。
3. 実際に始めるための現実的な道筋がある。

構成は、「Fact or Fiction（本当か嘘か）」の 3 つの問いを軸に、動画を使ったデモ（PC 上の Copilot、Dell の Auto Diagnose、GB300 搭載ワークステーション）と、Agent 365 などのガバナンスの紹介が続く形です。Q&A の時間は設けられましたが、トランスクリプトには質問が出ていません。

## 5. 発表内容の詳細

### 5.1 Fact or Fiction 1：クラウドで AI が動くなら、高性能な PC は要らない？

Jon 氏は、会場に挙手を求めたうえで、「AI がクラウドで動くなら、高性能な PC は不要」という主張は**フィクション**だと答えています。根拠は、**Signal 65** による独立した調査（"Signal 65" は聞き取りの綴りで、音声認識の都合で表記が確定できません）で、クラウド上のエージェント型 AI が、ローカル PC の性能に**最大 24%** の影響を与えうるという結果でした。この結果は直感に反するので、「PC のリフレッシュ周期を延ばそう」「そこそこの PC でよい」という判断が広まりやすい点に注意してほしい、と述べています。

調査では、PC 上で同時に起きている作業を 3 つの層に分けています。

| 層 | 内容 |
| ---- | ---- |
| 第 1 層：目に見える層 | 通常のオフィス業務。ライブ会議、複数の PowerPoint、多数のブラウザータブなど |
| 第 2 層：エージェントが動かす作業 | Claude や Copilot など。AI はクラウドで動くが、「ハーネス」は PC 上で動く。ブラウザーを開いてページを移動し、ファイルを読み書きし、スプレッドシートに対してコードを動かすなど、データ処理とオーケストレーションを行う |
| 第 3 層：誰も気付かない裏方 | バックグラウンドのセキュリティ、エンドポイント保護、企業のイメージ |

この 3 つの層が同じリソースを取り合い、第 2 層と第 3 層が第 1 層の性能に影響を与えます。つまり、オフィス業務の応答性が下がります。これは、2020 年には想定されていなかった負荷であり、しかも「クラウドで動くエージェント型 AI だけ」の場合の話です。今週 Microsoft が発表したように、エージェントやモデルを PC 上で動かすなら、必要な水準はさらに上がります。

Jon 氏は、新しい **Dell Pro** のラインナップが、この 3 層の負荷に対応するよう設計されており、PC 上でエージェントやモデルを動かす余裕もあると説明しています。

| モデル | 想定する利用者 |
| ---- | ---- |
| Dell Pro 3 | 基本的なフロントラインのユーザー |
| Dell Pro 5 | パワーユーザー |
| Dell Pro 7、Dell Pro Premium | モバイルのユーザー（プロフェッショナルや経営層） |

これらはすべて、ハイブリッドインテリジェンスの基盤として設計されているとのことです。

### 5.2 Windows とハイブリッドインテリジェンス（Stefan 氏）

Stefan 氏は、多くのお客様が「frontier transformation」（AI とエージェントが人と一緒に働き、エージェントが作業の機械的な部分を引き受けて、人は重要な部分に時間を使う状態）の途中にあると説明し、3 つの柱で整理しています。

1. **AI in the flow of human ambition**：AI やエージェントを見つけやすくする。例として、今週発表された、Windows のタスクバーの検索の改善があります。単に検索するのではなく、意図を表現すると、Copilot がそれを受けて Windows 上で直接アクションを取ります。
2. **Built on a platform of intelligence**：これまで知能の大半は、クラウドで動くフロンティアモデルから来ていました。Copilot+ PC や、新しいビルダー・クリエイター向けの PC、ワークステーションの登場で、推論をローカルで実行できる範囲が広がっています。利点は、**コスト管理、セキュリティ、プライバシー**です。今後数年で、PC、ワークステーション、オンプレミスのサーバー、クラウドの全域で知能が動くようになる、という見通しです。
3. **A platform of trust**：AI とエージェントも、信頼のプラットフォームで統制する必要があります。そのため、デバイスと人のための既存の IT ツール（Entra ID、Intune、Defender、Purview）を、AI とエージェントにも広げます。IT 部門は、使い慣れたツールで AI とエージェントを保護・統制できます。

Stefan 氏は、Windows は多くの人にとっての「window to work」であり、すべてのエージェント、AI タスク、モデルにアクセスできるように作っていると述べています。すべてをローカルで動かすという意味ではなく、ローカルとクラウドを組み合わせる形になる、という説明です。具体的には次の 3 点です。

* **エージェントのための最も安全なプラットフォーム**：**Microsoft Execution Containers** を導入しました。エージェントがその中で動き、IT 部門が管理・統制できます。新しい製品である Agent 365 にも現れます（トランスクリプトでは "Microsoft 365, Microsoft Agent 365" と書き起こされています）。エージェントを素早く展開しつつ、統制を保てます。
* **ローカルのコンテキストとファイルの活用**：エージェントや AI が、クラウドだけでなく、PC 上のローカルのコンテキストやファイルを利用できます。ユーザーの許可があれば、PC 上でアクションを取ることもできます。
* **インテリジェントなルーティング**：ユーザーが選ぶのではなく、Windows とアプリケーションが、知能をどこから得るかを判断します。PC で動く場合も、オンプレミスで動く場合も、必要なときはクラウドのデータセンターのフロンティアモデルで動く場合もあります。これが「ハイブリッドインテリジェンス」であり、Windows をその拠点にするというビジョンです。判断は、ローカルのハードウェアの能力と、具体的なワークロードの要件に応じて行われます。

Stefan 氏は、PC の戦略を今後 12〜18 か月で計画している企業は、PC を AI インフラの一部と考え、知能をどこで動かせるかを考慮に入れるべきだと述べています。

### 5.3 Dell と Microsoft のハードウェアと、利用状況の数値（Stefan 氏）

* ナレッジワーク向けには、**Dell Pro Copilot PC** が、応答性が高く安全な AI 体験を日常業務に届けます。
* Windows では、出荷されるコマーシャル PC の約 **40%** が Copilot+ PC です。これらの PC では、毎月 **2 兆回**の推論がローカルで行われていると述べています。今後、ローカル推論を使うワークロードが増え、PC とその上のモデルの能力が上がるにつれて、さらに増えるとのことです。
* ビルダーやパワーユーザー向けには、要求の厳しいローカルモデルが必要とする性能とメモリを備えた Dell のシステムがあります。以前はすべての AI・エージェント関連の処理をクラウドに回していた開発者が、ローカルで処理できる範囲を増やせます。
* **GitHub Copilot** には、ローカルとクラウドの間のインテリジェントなルーティングが発表されました（機能名は聞き取りでは "HydraFusion"。音声認識の都合で表記が確定できません）。開発者のプロンプトはまずクラウドに送られ、クラウドが分析して、サブタスクに分解し、どれをクラウドの知能で、どれをデバイス上のローカルな知能で処理するかを判断します。コスト管理に加えて、**開発者のパターンが変わる**点も挙げられています。開発者は、トークンのクォータに当たることを恐れず、より積極的に試すようになるとのことです。
* すでに複数の **Fortune 500** の顧客が、このクラスのハードウェアと GitHub Copilot CLI で動き始めています。
* より高度なフロンティア型のモデルをオンプレミスで動かすための、新しいクラスのワークステーションでも、Dell と提携しています。

### 5.4 Fact or Fiction 2：デバイスを修理するために、データを全部パブリッククラウドに送るか

Sahil 氏は、バッテリー、マイク、カメラなどの問題を直すために、エージェントがデバイスのデータをすべてパブリッククラウドに集めるか、と会場に尋ね、答えは**フィクション**だと述べています。理由を言葉で説明する代わりに、Dell の新機能 **SupportAssist Agentic Auto Diagnose**（トランスクリプトでは "Support Assist Agentic Auto Diagnose"）の動画を見せました。内容は 6 章に書きます。

Auto Diagnose は、ユーザーが気付く前に問題を検出・診断し、多くの場合は修復する Dell のエージェントです。

### 5.5 AI のコスト：トークンと「token per dollar per watt」

Sahil 氏は、CIO や CFO が来年度の予算を考えるうえで、最も気にしているのがコストだと述べ、AI ワークロードの変化を説明しています。

* 2 年前は、チャットボットが中心でした。プロンプトがトークン化され、トークンがデータ群を対象に推論して出力を返します。
* 現在はエージェント型です。自律的なエージェント、トリガーされるエージェント、大量のデータを複数ループで調べるエージェント、サブエージェント、関数呼び出しやツール呼び出しを行うエージェントがいます。ワークフローが予測可能ではないため、**トークンのコストが指数関数的に上がります**。

AI の性能を測る指標として、**token per dollar per watt** を挙げています。適切なワークロードをデバイス上に回せば、デバイスは先行投資があるものの、稼働コストはほぼゼロで、「dollar」の項がゼロになります。「watt」も、巨大なデータセンターに比べれば無視できる水準です。そのため、特定のワークロードでは、Dell のデバイスに回すと AI の性能（この指標）が大きく向上するという説明です。

Mark 氏は、これを受けて、エージェントが増えればトークンも増え、すべてのトークンをクラウドに送ればクラウドのコストも増えると補足しています。そこでローカル AI の機会が生まれますが、フロンティアレベルの知能が必要なときはクラウドを使えばよい、という立場です。

Mark 氏は、利用者のペルソナ別に次のように説明しています。

* **日常のナレッジワーカー**：Dell Pro の PC のローカル計算で、エージェントのハーネスが行う作業（ドキュメントの確認、テキストの確認、コードスニペットの実行など）をオフロードできます。これらは日常の作業と同時に起きるため、負荷が上がる原因でもあります。
* **スーパーユーザー化するナレッジワーカー**：AI の使い方を学ぶほど、クラウドのトークン消費が増えます。それをデバイス上に下ろしたい、という考えです。

### 5.7 Fact or Fiction 3：デバイスが侵害されたら、ゲームオーバーか

会場の多くは「本当」には挙手せず、答えは**フィクション**でした。セキュリティは、単一の防御ラインには頼れず、多層で構築する必要があるという説明です。

**Dell の取り組み**（Mark 氏の説明）

* セキュリティは、PC が作られる前から始まります。調達から製造、配送までの、セキュアな設計原則とサプライチェーンの管理があります。
* コマーシャル PC には、将来の暗号の脅威に備える基盤となる、量子への保護（"quantum protections"）が備わっています（トランスクリプトの文言は不完全で、詳細は語られていません）。
* 日常の利用では、ハードウェアベースのセキュリティと、ファームウェアの改ざんを検知する **Dell Safe BIOS**、認証情報をハードウェアで隔離する **Safe ID と Control Vault**（聞き取りの綴りで、音声認識の都合で表記が確定できません）があります。
* Mark 氏は、こうした取り組みが「Dell の PC が世界で最も安全で管理しやすい」ことの一部だと述べています（Dell 側の主張です）。
* エージェント型のセキュリティには、シリコンの調達からアプリ、データまで、多くの層が必要です。
* まとめとして、サプライチェーン、Dell のハードウェア root of trust、Intel のシリコンレベルのセキュリティ、Windows と Microsoft のアイデンティティ、Dell のフリート全体での脅威検知が、すべての層に信頼を組み込みます。

**Agent 365**（Sahil 氏の説明）

Agent 365 は、エージェントの observability（可観測性）のレイヤーで、次の 4 つの点で役立つと説明されています。

| 観点 | 内容 |
| ---- | ---- |
| エンドツーエンドの管理 | 企業内で動かしているすべてのエージェントについて、健全性、管理しているワークフロー、アクセスできるツールを把握する |
| ガバナンス | エージェントのポリシー、アクセスできるツールとデータソースを定め、必要なら制限する |
| 脆弱性 | エージェントのアーキテクチャは、やり取りの接点が多いほど脆弱性も多い。Agent 365 は、脆弱性がどこにあり、どう是正できるかをライブダッシュボードで示す |
| ビジネス価値 | エージェントを作ること自体を目的にしない。エージェントがビジネス価値につながるようにし、その価値を測る。ユーザーが、業務でどう使い、どんな価値を得て、さらにどんな改善が要るかを見る |

### 5.8 Dell Professional Services による展開（Mark 氏）

従業員が 20,000 人の企業にどう展開するか、という実務的な問いに対して、Mark 氏は Dell Professional Services を挙げています。

1. 知識労働者、開発者、クリエイターなど、**ワークロードに合った PC を選ぶ**。最新の Dell Pro PC で次の更新サイクルを最適化し、エージェント型 AI を検討に含める。
2. 環境とアプリケーションを見て、どのワークロードが Dell Pro PC で動くべきか、デスクサイドの知能で動かすべきか、クラウドに置くべきかを整理する。
3. そのリファレンスアーキテクチャを、**Microsoft Intune のポリシー**による構成と、ゼロタッチのプロビジョニングと展開のための **Windows Autopilot**（「maybe」と述べています）で実践する。
4. それにより、従業員 500 人でも 50,000 人以上でも、agentic workplace 全体に持ち運べるブループリントができる。

Mark 氏は、Dell と Microsoft の関係の価値は、この統合作業の最適化にあり、IT 部門が生産性の成果に集中できる点だと述べています。

### 6.2 Dell SupportAssist の Auto Diagnose（Sahil 氏が導入）

Sahil 氏が動画を紹介し、前半の説明（Tyler の例）は同氏の発話です。後半（LoRA や MXC の説明）は、話者を文面から特定できません。語られた順に整理します。

### 6.3 GB300 でのエージェント型ワークロード（Mark 氏）

Mark 氏は、GB300 上で Microsoft Windows を使い、常時稼働のエージェント群にジョブを渡す「agentic workplace」の動画を紹介しています（IT 部門が既に管理できる環境で動いているとのこと）。

1. 1 つのプロンプト「on-prem AI 推論について調べて、HTML のブリーフィングを作って」から始まる。
2. 背後で planner が、ジョブを複数のサブエージェントに分け、検索、読み取り、分析、構築を**並列**で行う。
3. すべてのページ、ツール呼び出し、推論ステップでトークンが消費され、それが GB300 のリソースになる。GB300 は 72 コアの Grace CPU と Blackwell GPU、748 GB のコヒーレントメモリを組み合わせた、「デスクサイドの箱に入ったデータセンター級のシリコン」と説明されています。
4. トークンのバッチが埋まり、プリフィルとデコードのステップが行われ、重みが HBM メモリから GPU にストリームされ、KV キャッシュが埋まる（動画の説明の言葉）。
5. 出てきたトークンがテキストになり、テキストがコードになり、builder エージェントが**単一ページのアプリ**を書く。
6. 結果は「1 つのプロンプト、5 つのエージェント、数百万のトークン、1 つのシングルページアプリケーション」。全体で約 **1,150 万トークン**を使い、最後の約 18 万 7 千トークン（聞き取りでは "170, 187,000 or so"。数字は音声認識の都合で確定できません）が最終の層だった、と述べています。

Mark 氏は、これを「デスクサイドのエージェント型 AI であり、トークン工場を、従業員とデータのすぐそばに持ってこられる」ものとし、クラウドを置き換えるのではなく、トークンをどこで動かすかを意図的に決めることで、性能、データ、AI の経済性を制御できると説明しています。

## 7. 注意点・発表者の気付き

* **PC の更新は AI インフラの判断**：クラウドで AI が動くからといって、PC のリフレッシュを延ばしたり「そこそこの PC」にしたりすると、性能に影響する（最大 24%）可能性があります。
* **エージェント型のワークロードは予測しにくい**：自律型、マルチループ、サブエージェント、ツール呼び出しにより、トークンのコストが指数関数的に上がります。
* **フロンティアレベルの知能はクラウドが必要**：ローカルですべてを置き換えるのではなく、使い分けます。
* **単一の防御ラインに頼らない**：セキュリティは、シリコンの調達からアプリ、データまでの多層で考える必要があります。
* **エージェントは目的なく作らない**：Agent 365 で、ビジネス価値を測定して改善につなげる必要があります。
* **ユーザーの承認**：PC 上の Copilot の例では、ユーザーの明示的な承認なしに何も送信されません。Auto Diagnose も、ユーザー体験に影響する変更は、確認のうえ提案する形です。
* **発表で触れられていない点**：ハイブリッドインテリジェンス機能の提供時期や価格、各 Dell 製品の価格などは、発表では語られていません。

## 8. 利用者にとっての利点

* **コスト**：適切なワークロードをデバイスに回すと、稼働コストがほぼゼロになり、token per dollar per watt の指標が大きく向上する、という説明です。Mark 氏のラボでは、GB300 のマシンで 1 日に平均約 10 億トークンを処理しているとのことです。
* **開発者の行動の変化**：ローカルとクラウドのルーティングにより、トークンのクォータを恐れず、積極的に試すようになるとのことです。複数の Fortune 500 の顧客が、GitHub Copilot CLI で既に動き始めています。
* **セキュリティとプライバシー**：ローカルでの推論は、コスト管理、セキュリティ、プライバシーの利点があります。Intune、Entra ID、Defender、Purview、Agent 365 など、既存の IT ツールで統制できます。
* **ユーザー体験**：Auto Diagnose が、ユーザーに気付かれる前に問題に対処し、体験に影響する変更は提案にとどめます。
