## 5. 発表内容の詳細

### 5.1 ローカル AI を使う理由

登壇者は、PC に搭載されたチップを使い分ける考え方を説明しています。

| チップ | 発表での位置づけ |
|---|---|
| GPU | 性能を最大限に引き出す |
| NPU | AI ワークロード専用で、バッテリーと電力の効率が高い |
| CPU | できるだけ多くのデバイスをカバーする |

ローカル AI の利点として、次の 4 点が挙げられました。

1. **プライバシー・セキュリティ・コンプライアンス**：データがデバイスの外に出ないため、これらの要件を満たしやすくなります。
2. **遅延と性能**：オーディオやビデオの処理をハードウェアの近くで行うため、クラウドとの往復による遅延がありません。
3. **ネットワーク不要**：ネットワークが使えない場面やエアギャップ環境でも、クラウド接続なしで動作します。
4. **コスト**：API は Windows に同梱されています。ハードウェアと計算資源は利用者のものなので、実行に費用がかかりません。登壇者はこれを「オフラインで低遅延に使える無料の API」と表現しています。

### 5.2 Windows AI APIs のカタログ

Windows AI APIs は **Windows App SDK に含まれて提供**され、数行のコードで使い始められます。スライドで紹介された主な API は次のとおりです。

| 分野 | API |
|---|---|
| テキスト | text summarization（要約）、text rewrite（書き換え） |
| 画像 | 背景除去、画質向上、AI による画像生成 |
| 音声 | speech recognition（音声認識） |
| 動画 | video super resolution |

全 API の一覧はスライド上のリンクで確認できると案内されました（リンク先の URL は音声からは分かりません）。

### 5.3 Aion Instruct の概要

Aion Instruct は、Windows 上で動作する最先端（state-of-the-art）の小規模言語モデルで、パラメーター数は 23 億（2.3 billion）です。従来の Windows SLM である **Phi Silica** と比べて、次の違いがあると説明されています。

| 項目 | Phi Silica との比較 |
|---|---|
| メモリ使用量 | 3.4 倍小さい |
| コンテキスト長 | 9 倍。最大 32K トークン |
| 応答速度 | 最大 2 倍高速 |

**Aion Instruct は 12 月上旬から、NPU と GPU の両方のプラットフォームでパブリックプレビューとして提供される予定**です。詳細はスライドのリンク先で確認できます。

通常の言語モデルとして応答を生成する使い方に加えて、よく使われるテキスト処理向けに、すぐ使える API が用意されています。発表では、text rewrite、text summarization、structured output、LoRA fine-tuning が挙げられました。

### 5.4 パートナー事例: Flux Inc.

Aion Instruct を組み込んでいるパートナーとして、AI を使ったノートアプリの Flux Inc. が動画で紹介されました（社名は音声認識の都合で表記が確定できません）。この動画では 2 つのモデルが使われています。

- 手書き風の文字を生成する handwriting AI モデル。Windows ML で動作し、入力したテキストを、利用者自身の筆跡に似た手書きに変換します。
- Aion Instruct による、文の次の単語の予測。

すべてがデバイス上で動くため、良好なインターネット接続がなくても利用者は作業の流れを止めずに済み、次の単語の予測が数ミリ秒で返ってくると説明されています。

### 5.5 Structured output

多くのアプリは、自由形式のテキスト入力を、後続のアプリが取り込める構造化テキストに変換する必要があります。登壇者が挙げた例は、クォータの申請（「quotas」と聞こえます。音声認識の都合で確定できません）やカスタマーサポートです。ところが SLM でも LLM でも、スキーマに従って出力するよう指示しても、常にそのとおりになるとは限りません。

そこで用意されたのが **structured output** です。**constraint sampling** という手法を使い、入力で定義した JSON スキーマに沿った出力になることを保証します。生成ミスによって後続のアプリが壊れることを防げる、という位置づけです。登壇者は、必須フィールドを指定でき、各フィールドの取り得る値も指定できるため、自社のシナリオに合わせて JSON スキーマをカスタマイズできると補足しています。

### 5.6 LoRA fine-tuning

モデルをカスタマイズする一般的な方法は full fine-tuning ですが、モデルのすべての重みを再学習するため、時間もコストもかかります。これに対して **LoRA fine-tuning** は、軽量な **LoRA adapter** だけを学習し、ベースモデル（ここでは Aion Instruct）と組み合わせて使います。

登壇者によると、アダプターはいくつでも作れます。企業内に 2 つ、3 つ、5 つとシナリオがある場合は、それぞれにアダプターを作り、必要に応じて差し替えて使えます。

#### Microsoft Education の事例

事例は、Microsoft Education 側のナレーション付き動画で紹介されました。内容は次のとおりです。

- Microsoft Education は、ハイブリッド AI を使って、授業のアイデアから教室で使える対話型レッスンを作っています。教師と生徒が世界中で使っており、複数の言語で高い教育品質が求められます。
- 演習問題はオンデバイスのモデルでローカルに生成しています。ベースモデルで作ったところ、品質が十分ではありませんでした。形式・言語・教育上の要件を安定して満たせなかったためです。
- 解決策が LoRA adapter です。1 言語あたり約 50 MB の小さな追加モジュールで、オンデバイスモデルにタスクを教えます。
- **Foundry Toolkit** を使ったパイプラインを構築しました。タスクのプロンプトと品質基準を入力すると、学習・評価済みの LoRA adapter が出力されます。
- ブラインドテストセットで、アダプターの有無による結果を同じリクエストで比較しました。アダプターを使うと、テストした**すべての言語で教師の使いやすさのスコアが上がり、壊れた演習は 3 分の 2 減りました**。
- 再利用できるパイプラインがない場合、新しいベースモデルが出るたびに、データ準備・学習・評価からやり直す必要があります。パイプラインがあったため、Aion Instruct と 7 言語でパイプライン全体を最初から実行し、評価済みアダプターを得るまでに **6 日**で済みました。

### 5.7 Video Super Resolution

Video Super Resolution（VSR）は、デバイス上で動画をアップスケールする、プラットフォームに最近追加された API です。解像度の低い入力ビデオストリームを渡すと、ローカルの AI 処理で高解像度のビデオストリームが出力されます。**最大 4K まで**対応します。

比較映像では、左に元の動画、スライダーの右に VSR 適用後の動画が表示されました。2 人が話している映像で、VSR を適用すると人物がより鮮明になり、背景にある文字も読みやすくなったと説明されています。

#### パートナー事例: WhatsApp

WhatsApp はデスクトップアプリで、ビデオ通話の鮮明さを高めるために VSR を使っています。紹介動画では、ネットワークが悪く映像がぼやける状況で HD を有効にすると、VSR が受信映像をリアルタイムでシャープにする様子が映されました。HD をオフにすると品質が下がり、スプリットビューでは VSR なし（左）とあり（右）の同じライブストリームを比べられます。

#### 新しく対応したシナリオ

従来は、ビデオ通話のようなトーキングヘッド（人物の顔が映る）シナリオ向けでした。今回、次のシナリオへの対応が発表されています。

| シナリオ | 内容 |
|---|---|
| テキスト品質の向上 | 映像ストリーム内に写った文字を読みやすくする |
| 手ブレ補正 | 揺れるカメラで撮影した映像のカメラシェイクを低減する（stabilization API） |
| ゲーム配信 | ゲームのライブ配信で、ゲーム内のディテールを強調する |

対応ハードウェアは、**NPU と CPU がサポート対象で、GPU は現時点では experimental（実験的）段階**です。詳細はスライドのリンクで案内されました。

手ブレ補正のデモ映像では、左が元の動画、右が VSR 適用後で、右側は揺れが少なくなっていました。登壇者は、企業で映像を安定させたい場合に便利な API であり、数行のコードで同様の効果が得られると述べています。

#### パートナー事例: TeamViewer

TeamViewer は、技術サポートを提供・受ける際のプラットフォームです。紹介動画では、Microsoft Foundry on Windows により、**今年 12 月に TeamViewer の AssistAR（綴りは音声認識の都合で確定できません）へ VSR API を導入する**と語られています。サポート通話の映像を鮮明にし、文字を読みやすくするのが目的です。さらに来年以降、テキスト認識の強化やカメラの手ブレ補正などの機能を、AssistAR や他の TeamViewer 製品に追加していく予定だとされています。動画の中では、ローカル AI が高速で安全、高品質なリモートサポートの鍵になると述べられています。

## 6. デモ・手順

デモは**あります**。Aion Instruct を使うサンプルアプリの実演（6.1〜6.3）と、VSR の比較映像・AI Dev Gallery の画面紹介が行われました。録音は音声のみのため、画面の細部は語られた範囲でしか分かりません。

### 6.1 デモ環境

画面の左に、Windows App SDK ベースのデモアプリ（Aion Instruct と対話するインターフェース）、右にタスクマネージャーの NPU タブを開き、NPU の動きを見ながらデモを進めました。最初にアプリ上で Aion Instruct がオンラインになっていることを確認しています。

### 6.2 文章生成、Rewrite、要約

1. 「火曜の会議を水曜に変更したいという短いメールの下書きを書いて」と依頼して送信します。トークンがストリーミングで出力され、その間の NPU の動きが連動して見えます。きちんとした、プロらしい構成のメールが生成されました。
2. 同僚宛てには少し堅いので、よりカジュアルにしたい場面です。モデルに言い換えを指示することもできますが、このシナリオ向けに最適化された **Rewrite API**（Aion Instruct を基盤とする）を使うと説明されています。現在のスタイルは general、casual、concise、formal の 4 種類です。
3. メールの下書きをコピーし、casual を選んで rewrite を実行すると、すぐにカジュアルな文面が返ってきました（読み上げられた冒頭は「Hope you're doing great. Could we swap out our Thursday, ...」）。
4. 次は要約です。同僚からの 4 段落の週次レポートがあり、急いで読みたいという想定です。Summarize API を選んで実行すると、すぐに段落形式の要約が出ました。4 段落のテキストが、やや長めの 1 段落にまとまったと説明されています。

### 6.3 Structured output

注文の受付（order intake）を例にしたデモです。

1. 顧客のメッセージは、「USB-C アダプターを 4 個注文したい。ケーブルは不要で、通常配送でよい」という内容です。
2. 後続のアプリが必要とするフィールドを定義します。`item`（文字列）、`quantity`（処理する個数）、`shipping`（`standard` と `express` の 2 種類から選ぶ）の 3 つです。この 3 つは必須で、他のフィールドは不要であるとスキーマで指定しています。
3. 送信すると、NPU 上で Aion Instruct が動き、スキーマどおりの JSON が生成されました。item は「USB-C adapters」、quantity は 4、shipping は standard でした。
4. 言葉で書かれた「four」が数値の 4 に変換されている点が、登壇者から指摘されています。

## 7. 注意点・発表者の気付き

- Aion Instruct は**パブリックプレビューの開始が 12 月上旬**とされています。発表時点では提供前です。
- VSR の GPU 対応は experimental 段階で、サポート対象は NPU と CPU です。
- SLM・LLM は、スキーマどおりに出力するよう指示しても必ずしも守らないことが、structured output の必要性として説明されました。
- full fine-tuning は重みをすべて再学習するため時間とコストがかかります。軽量な LoRA adapter はその代替として紹介されています。
- 製品としての制約や価格、対応 OS の詳細などは、発表では特に触れられていません。

## 9. まとめ

Windows AI APIs は、Microsoft Foundry on Windows の一部として Windows App SDK に同梱され、テキスト・画像・音声・動画のシナリオをローカルで処理できます。

テキスト分野の中心は、23 億パラメーターの SLM である Aion Instruct です。Rewrite や要約の API、JSON スキーマに沿った出力を保証する structured output、LoRA adapter によるカスタマイズが用意されています。動画分野では、最大 4K までの高画質化を行う VSR に、テキスト品質の向上・手ブレ補正・ゲーム配信が新しく加わりました。

試すには、無料でオープンソースの AI Dev Gallery が出発点になります。登壇者は、同チームのセッションが当日の後ほどと木曜日にも開かれること、Windows セクションのブースで相談を受け付けていることも案内しています。
