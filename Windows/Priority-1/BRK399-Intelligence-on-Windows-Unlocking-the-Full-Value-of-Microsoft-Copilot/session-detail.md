# BRK399 Intelligence on Windows: Unlocking the Full Value of Microsoft Copilot

## 1. はじめに

このセッションは、すでに Microsoft Copilot を導入した組織が、Windows と組み合わせることでその投資からさらに価値を引き出す方法を紹介するものです。発表は「Faster（速く）」「Smarter（賢く）」「組織で使える状態に（ready for your organization）」という 3 つの章立てを予告して始まり、前半は File Explorer・Start メニュー・タスクバー・検索といった Windows 本体の改善を、後半は Copilot が PC の状態を調べたりファイルを整理したりする **Windows Hybrid Intelligence** を扱います。

最後には、金融機関 Flagstar の Chief Technology and Data Officer が、Windows 11 と Copilot の活用状況と今後の構想を語ります。Windows の展開や Copilot app の展開を担当している IT 管理者、そして「Windows でどこまで AI を使えるのか」を知りたい開発者に向いた内容です。

## 3. 何に関する発表か

テーマは「PC は AI 戦略の中核であり、Windows 上の Copilot は、他の環境よりも多くの価値を出せる」という考えです。発表者は、Windows と Microsoft 365 Copilot は「1 つの大きなチーム」であり、設計・セキュリティ・サポートまで一体で作られていると説明しています。Start メニューや Copilot キー、File Explorer から Copilot app にファイルを送る操作など、OS と統合された体験がその例です。

発表の冒頭では、Copilot app が Windows で使われている度合いについても触れています。**20% を超える、週 3 回以上のリピート利用**が、他のどのプラットフォームよりも Windows の Copilot app で多い、というデータです（正確な比較の対象は音声から断定できません）。アプリ自体はどのプラットフォームでもほぼ同じなので、OS との統合がこの差を生んでいる、というのが発表者の見立てです。

## 4. 発表者が伝えたいメッセージ

1 つ目は、**基本性能の改善を地道に続けている**ということです。発表者によれば、PC は時間とともに遅くなり、「新しいハードウェアを買うことがデフォルトの対処になってはいけない」という考えです。クラッシュやドライバーの問題はヘルプデスクの負担になり、サインインは 1 回で成功すべきで、更新が誰かの 1 日を台無しにしてはいけない、というフィードバックを受けて、この 1 年ほどの開発をパフォーマンス・信頼性・craft の 3 領域に集中させたと述べています。

2 つ目は、**Copilot をより手軽に使えるようにする**ことです。検索ボックスから Copilot に指示を出したり、右クリックメニューで Copilot にファイルを尋ねたりできるようにすることで、組織の全員が、アプリを起動するのと同じ感覚で Copilot を使えるようにする、という方針です。

3 つ目は、**Windows Hybrid Intelligence** によって、Copilot が「世の中一般の知識」だけでなく「その PC の状態」を踏まえて答え、行動できるようにすることです。ただし、制御は利用者と IT の両方が持つ設計になっています。

## 5. 発表内容の詳細

### 5.1 会場への質問

冒頭で、登壇者は会場に質問しています。26H2 の展開に関わっている人は何人か、Copilot app を組織に広く展開している人は何人か、Windows Insider のベータビルドを試している人はいるか、Frontier program に参加している人はいるか、という内容です。発表者の言葉では、Copilot app を広く展開している参加者は「たくさん」手を挙げ、Windows Insider は「数人」、Frontier program は挙手が無かったようです。

### 5.2 Faster：パフォーマンス・信頼性・craft

3 つの領域は、次のように説明されています。

| 領域 | 説明 |
| --- | --- |
| Performance | メモリ効率、アプリの読み込み時間、応答性など、PC の使い心地の土台 |
| Reliability | クラッシュやドライバーの問題を減らし、OS 全体をなめらかにする |
| Craft | 使いやすさを意識した UX。「人間側」の面で、操作を直感的にし、必要な機能にたどり着きやすくする |

これを示すために、同じ 16 GB の PC で 1 日の業務を再現した比較ビデオが流されました。左は 1 月のビルド（Office、Microsoft 365、Teams を含め、すべて 1 月時点のもの）、右は 10 月のビルドです。ある 1 つのワークフローは、1 月のビルドで約 40 秒、10 月のビルドで約 30 秒でした。発表者によれば、ここで見せた内容はすべて一般提供（retail release）で入手できます。

Windows の外側の改善として、次の数値が挙げられました。

| 対象 | 改善 |
| --- | --- |
| Word、PowerPoint、Excel、Outlook | コミットメモリが最大 360 MB 減 |
| Defender、Purview、OneDrive（バックグラウンドのもの） | メモリ使用量が最大 550 MB 減 |
| Teams | 起動が 20% 高速化 |
| Edge | 起動が 33% 高速化 |
| 新しい Copilot app | 今年 1 月以降と比べて 77% 高速化（比較の基準は音声からは断定できません） |

共通するテーマは、システムリソースを、利用者がやりたいことに使えるようにし、アプリが「税金」のようにリソースを消費しないようにする、ということです。

### 5.3 File Explorer

Paul 氏は、File Explorer が最も多く使われるアプリの 1 つであることを踏まえ、速度・信頼性・パフォーマンスという基本と、日常作業の摩擦の除去に集中したと説明しています。人が使う場合だけでなく、エージェントと協調して作業する場面（同僚やエージェントが更新・共有したファイルがすぐ見える）でも重要だという位置づけです。

高速化のために行ったこととして、次の 4 点が挙げられています。

1. UI の再設計（re-architect）
2. カーネルの機能を活用した起動速度の向上
3. クラウドとディスクからのデータ読み込み・キャッシュに関するコードパスの最適化
4. Windows が事前にロード（プリロード）するプロセスの見直し。File Explorer もその対象に加えた

使い勝手の改善として、アドレスバーに `~` を入力するとユーザープロファイルに、`~/` に相対パス（発話の例では downloads）を続けるとそのフォルダーに移動できます。また、UI スレッドを止める可能性のある箇所を、数百か所特定して取り除いたと述べています。例として、誤った SMB パスをアドレスバーに入力したとき、以前は待たされ続けていたものが、今はすぐに「そのパスは正しくない」と示されます。名前の変更、移動、コピー、一括削除など、多くのシナリオで摩擦を取り除いており、今後数か月でさらに追加される予定です。

**右クリックのコンテキストメニュー**も、高速化と簡素化が行われています。エンドユーザーと IT 管理者の両方が内容を調整でき、例えば印刷をほとんどしない人は「Print」を外し、印刷が重要な人は残す、といった設定が可能です。Copilot や Terminal などアプリの拡張にも同じ考え方が及んでいます。Terminal を有効にすると、フォルダーの背景を右クリックしたときに、そのフォルダーで Terminal を開けます（Paul 氏は Copilot CLI でのコーディングをする人に便利だと述べています）。Copilot を有効にすると、ファイルの右クリックから、そのファイルの分析や要約を Copilot に頼めます。従来は巨大なメニューに複数の Copilot が並び、目的の項目が見つけにくく、表示も遅いことがあったが、それを整理した、という説明です。

### 5.4 Start メニュー

Start メニューは「Windows であらゆることを始める場所」であり、ここでも個人設定の自由度を高めています。Pinned、Recent、All の各セクションを、エンドユーザーがオン・オフでき、IT 管理者も制御できます。

- 最近使ったファイル（Recent）は便利な人もいれば、機微な情報に配慮したい人や、1 台を複数人で共用する構成では表示したくない場合があり、オフにできる。
- フロントラインワーカーなど、Pin したアプリだけに集中させたいグループには、グループごとに既定の Pin を設定できる。例えば、Copilot を含めた構成にできる。
- メニューのサイズを小さくも大きくもできる。

### 5.5 タスクバー

エージェント的なコンピューティングで同時に進める作業が増えているため、タスクバーが利用者のニーズに合うことはより重要になっている、という文脈です。Windows 11 の新しいタスクバーには、左・右・上への配置といったパーソナライズが無いという声があり、それを**復活させました（一般提供中）**。通知やクイック設定（音量など）も、各配置で適切に動作します。

そのほか、ウィンドウごとのラベルの表示（タスクバーを To Do リストのように使う人がいるという説明）や、アイコンを小さくしてより多くのアプリを並べる設定にも対応しています。Paul 氏は、同僚が Copilot のコーディング機能でたくさんのアプリを作っており、そのための余白が必要だと話しています。信頼性については、社内で追跡しているすべての指標で「スリーナイン（three nines）」の信頼性を目指して引き上げている、という説明です。

### 5.6 新しい Windows 検索

Windows キーを押して入力する操作は、多くの人にとって当たり前の動作になっています。この検索を、最新の WinUI のスタックを使い、ゼロから作り直した、と説明されています。目的は、より速く、より信頼でき、より見やすくすることです。アプリの起動は非常に速く（Teams を検索して起動する様子の録画が流されました）、ファイル検索ではサムネイルとパスも表示されるので、ファイルを開く前に目的のものか確信できます。

さらに、検索は「探して終わり」ではなく、その後に何かをしたいことが多いという気付きから、**アクション（actions）** が加わりました。Paul 氏は次のものを画面上で見せています（デモの内容は 6 章に記載）。

- ウィンドウの整列（arrange my windows）
- Do not disturb のオン
- VPN への接続と切断
- 仮想デスクトップの作成

Paul 氏はこれらのほか、デモはしないと断ったうえで、検索に計算機能もあり、「37 の平方根」のような質問にも答えられると述べています。アクションの多くは元に戻せるとも説明しています（VPN の切断が例）。

企業環境では、検索に SharePoint のファイルや人（組織内の人物）なども含まれます。デモでは同僚の名前で検索し、連絡先を表示しました。そこから、たとえばメールを送ることもできる、という説明でした。

### 5.7 Copilot と Windows の統合：2 つの流れ

Guneet 氏は、Copilot on Windows の取り組みを 2 つに分けて説明しています。

1. **フローの中にとどまること**：タスクバー、より関連性の高い検索、Copilot の情報（OneDrive や SharePoint のデータを含む）を検索に取り込むなど。他の場所に移動せずに、Copilot のデータや洞察にアクセスできるようにする。
2. **Windows Hybrid Intelligence**：次の 3 つで構成される。

| 要素 | 内容 |
| --- | --- |
| Local context | デバイスの状態、場所、設定を理解する |
| Local action | デバイス上で起きていることに対して、利用者に代わって行動する |
| Local models | ローカルで動くモデル |

発表者は、すべてのデバイスがローカル AI モデルを実行できるわけではないが、デバイスに関する知能の恩恵はどのデバイスでも受けられる、と述べています。全体として、エンドツーエンドで一貫した体験を提供するという位置づけです。

### 5.8 検索から Copilot を使う

Copilot app（ネイティブの Windows 版）を組織に展開していれば、Windows 検索と統合され、組み込みアクションだけでなく、**Copilot にできるあらゆること**を検索ボックスから実行できます。例として「when's my next meeting?」のような質問が挙がっています。Paul 氏は、Windows 検索を OS における「意図（intent）の入口」にしたい、と説明しています。

あわせて次の機能が紹介されました。

- 検索の入口からファイルを添付して Copilot に渡せる（File Explorer で右クリックして「Ask Copilot」とする方法とは別の入口）。画面などから Windows のコンテキストを持ち込む方法も、さらに検討中。
- 検索を開いた最初の状態（zero state）に、Copilot の提案や最近のチャット履歴を表示する。例えば、書きかけのメールがあればその続きを提案する。ダウンロードに関する処理を依頼していた場合は、同じクエリを打ち直さずに、最近のチャットからそのまま再開できる。

### 5.9 Windows Hybrid Intelligence のシナリオ

Paul 氏は、Copilot ができることが Windows 上でどう強化されるかを、3 つのシナリオで説明しています。いずれも画面録画のビデオで、再生に問題があった場面もありました（6 章参照）。

**(1) インターネットが遅い理由を調べる**

通常のチャットエージェントに「なぜインターネットが遅いのか」と聞くと、考えられる理由を並べた短い文章（essay）を返す。Windows Hybrid Intelligence では、「システムを調べれば答えられる質問だ」と判断し、利用者に許可を求めます。許可の選択肢は「常に許可」と「このセッションのみ許可」です。許可すると、サンドボックス環境で PowerShell のコマンドレットを実行し、アダプターの状態、接続性、パケットエラー、破棄されたトラフィックなどを調べて、**その PC に合わせた答え**を返します。コマンドは読み取り専用で、システムの状態を変更しません。Paul 氏は、Copilot における Work IQ や Web IQ によるグラウンディングと似ているが、問い合わせ先がローカルのシステムになる、と例えています。

**(2) Bluetooth デバイスが検出されない**

2 つ目の例は、PC が Bluetooth デバイスを検出しないという問題の切り分けです。許可の選択肢は「このデバイスで許可」と「常に許可」です。Copilot は同様に、サンドボックス内で PowerShell コマンドを呼び出して調べます。Paul 氏は、利用者が自分で問題を解決できるだけでなく、**サポート費用の削減**にもつながる可能性があると述べています。ヘルプデスクとやり取りするときも、Copilot を使って一緒に原因を調べられます。企業は、そもそもこの機能を使わせるかどうかを制御できます。

**(3) 経費精算用の領収書を整理する**

3 つ目は、システムを調べるだけでなく、ファイルを変更する例です。詳細は 6 章に書きます。

### 5.10 ガードレール：同意、可視性、元に戻す

Paul 氏は、このファイル整理は、制約のないコーディングエージェント（どのファイルでも編集できるもの）とは異なると説明しています。多くの組織は、全ユーザーに制約のないコーディングエージェントを必ずしも許可しません。そのため、チャットに組み込んだこの機能は、**限定された範囲で、組織全体に自信を持って展開できる**ものです。

- 検索対象は、デバイス上の既知のフォルダー（known folders）など、決まった範囲です。
- 実行できる操作も限られています。ファイルは削除せず、名前の変更や移動までです（Paul 氏の発話は「rename or remove」と聞こえますが、音声認識の都合で表記が確定できません）。

Guneet 氏は、顧客がどのように Windows Hybrid Intelligence を導入するかを完全に制御できるとして、次の 4 点を挙げています。

1. **初回の同意**：Copilot が初めてローカル PC にアクセスする必要があるときに、同意画面が出る。この同意は、ローカルのファイル検索と、読み取り・アップロードを対象とします。
2. **クラウドへのアップロードの可視化**：PDF や経費精算書を分析する、OneDrive に保存する、といった操作は、Copilot が支援しつつ、Copilot 内で明確に記録され確認できる。読み取りだけの処理ではその重要度は低いが、共有場所が多く、文書の意味も重いため、可視性を確保する。
3. **書き込みは毎回、明示的な同意**：ファイルの移動や編集など。
4. **ファイル変更は元に戻せる**：タスクの完了後に矢印が表示され、それを押すと、何も起きなかった状態に戻る。

エンドユーザーと IT の両方が制御でき、IT はポリシーを設定したうえで、従業員が必要なものを使えるようにできる、という説明です。

### 5.11 ローカルモデル

Guneet 氏は、Copilot が今後、PC 上のローカルモデルをより多く使い、タスクが本当に必要とするときにクラウドに到達する形になると述べています。これはすでに公に話してきたことで、現在も開発中です。計画としては、まず Code タブ、その後 autopilots（音声認識の都合で表記が確定できません）に広げるとのことです。

理由として、次の 3 点が示されました。

- **タスクに合わせたモデルのサイズ選び（right-size）**ができる。
- **AI を動かす場所を、より制御**できる。規制の厳しい業界、特に銀行ではデータ主権が重要であり、一部のワークロードを手元のハードウェアで動かせることに価値がある。
- **支出の効率化**。トークンの予算を、フロンティアモデルを使うべき大きなタスクに使い、ローカルでこなせる小さなタスクには使わずに済む。

詳細は、今後数か月で共有される予定で、現時点では「ローカルモデルの考え方の青写真」という位置づけです。

### 5.12 Flagstar Bank：Jason Pope 氏との対話

**会社の背景**

Flagstar は「super regional bank」と呼ばれる規模で、資産規模は、発話で "about 100 billion in assets" と語られています（通貨の単位は発話にありません）。2024 年ごろに 3 つの銀行（Legacy New York Community Bank、Michigan の Legacy Flagstar、Legacy Signature Bank）が合併してできました。Jason 氏が 2025 年初めに着任したときは、Windows 10 も含め、あらゆるバージョンの Windows が存在していたそうです。そこで Microsoft のエコシステムに全面的に取り組むことにしました。Surface の Copilot PC から Intune の管理プレーンまで、そして Microsoft 365 E7 SKU の登場で、Agent 365 を含む全体像がそろった、と語っています。

規制業界については、銀行は、利用者の「すべてのクリック」や「アクセスできるすべてのもの」を、定量的・定性的に説明できなければならない、と述べています。AI によって運用の幅が広がる中で、Windows 11 が、細かな制御、可視性、監査可能性（auditability）を実現した、という説明です。

**優先事項**

1. エンドユーザーコンピューティングの基盤を、Microsoft のエコシステムの中で近代化する（Intune、Defender for Endpoint、コア基盤の簡素化）。AI の基盤要素と、それをどこで動かすかを重視する。ローカルで動かすこと（localization）が重要。
2. Windows と Copilot PC を通じて、ハイブリッドインテリジェンスを利用者の手元に届ける。さらに、Surface ノート PC 上で動かす小規模言語モデル **BranchIQ** を提供している。行員やフロントオフィスの担当者が、規制対応のために守るべき標準的な方針・手順に、数秒でアクセスできる。
3. これらをすべて、完全なトレーサビリティと監査可能性を備えて、安全に実現する。Jason 氏は「どう実現するかを、安全に行い、シグナルとテレメトリーをどう記録しているかを、端から端まで証明しなければならない」と強調しています。

**質問 1：Windows は従業員の働き方をどう変えたか**

Jason 氏は、エコシステム全体の話だとしたうえで、Windows 11 の機能は 10 年前に夢見ていたものだと述べています。顧客の口座を開く場面や、ノート PC のふたを開く場面での速さが優位性を生む、という考えです。以前は起動が遅くて、画面と本体の間に親指を挟んだままノート PC を持ち歩く人がいたが、新しい Windows 11 ではハイバネートから数秒で復帰する、と話しています。顧客の前に立っているときは、その数秒が重要です。

Copilot については、毎朝最初にすることとして、Copilot に「tell me about my day（今日の予定を教えて）」と頼むと語っています。カレンダーが混乱しているので、今どこにいて、どこへ行くべきかを把握し、準備まで Windows 上でできるのは、10 年前にあればよかった能力だという話です。

**質問 2：最も可能性を感じる点**

タスクバーからの検索の統合が、想像を超える可能性を開くだろうと述べています。外出が多く、検索をよく使うからです。Windows 11 で最も楽しみにしているのは **Microsoft execution containers**（発話の表記。MXC）で、BranchIQ のような小規模言語モデルがある環境で、他のシステムに接続できるサブエージェントを MXC 上に置くことを構想しているそうです。現時点では本番稼働しておらず、試行中（tinkering）で、「可能性の技術（art of the possible）」の段階だと語っています。

**質問 3：BranchIQ の影響と Copilot との接続**

現在、金融サービス向けに設計された小規模言語モデル BranchIQ を Copilot に統合する取り組みを、インキュベート中です。Copilot app を「仕事の入口（front door）」と位置づけ、そこから BranchIQ を呼び出し、ローカルで動く BranchIQ に答えが無い場合は、単一の入口の中でルーティングして、必要な場所に行ける形にしたい、という考えです。

例として口座開設を挙げています。BranchIQ が KYC のプロセスを支援したあとにも、手作業の工程が多く残っています。Copilot と BranchIQ の統合により、オンボーディング全体の入力まで到達できる可能性があるとのことです。銀行のオンライン口座開設は 7〜12 クリックが必要でうんざりするもので、これを BranchIQ のエージェントと Copilot の統合で自動化できれば、**リージョナルバンクにとって体験レイヤーを変える**ものになる、という見方です。Jason 氏は、まだ取り組み中なので多くは言えない、と断っています。

### 6.3 Windows Hybrid Intelligence のビデオ 3 本

Paul 氏は、PowerPoint の再生に問題があったと語っています（「PowerPoint demons」と冗談を交えています）。

**(1) Slow Wi-Fi のデモ**

1. 利用者が Copilot に「why is my internet connection so slow?」と尋ねる。
2. Copilot が、システムを調べるための許可を求める。Paul 氏は「このセッションのみ許可」を選んだ。
3. Copilot が、サンドボックスで読み取り専用の PowerShell コマンドレットを実行し、アダプター、接続性、パケットエラーなどを確認する。
4. その PC に即した回答が表示される。ただし、このビデオは最後まで再生できず、回答の内容は画面では見られませんでした。

**(2) Bluetooth のデモ**

1. ノート PC が Bluetooth デバイスを検出しない、と Copilot に伝える。
2. 許可の確認が表示される（選択肢は「このデバイスで許可」「常に許可」）。
3. Copilot が、サンドボックスで PowerShell のコマンドを呼び出して調査し、答えを返す。このビデオも、途中で再生されませんでした。

**(3) 経費精算の領収書整理（別のデッキに切り替えて再生）**

前提として、Paul 氏は、カンファレンスの領収書を、メールやメッセージからダウンロードフォルダーに保存してあります。ダウンロードフォルダーは「PC のガラクタ入れ」と呼ばれる状態です。

1. 参加したカンファレンスの領収書を見つけ、読み、種類（食事、宿泊、ライドシェアなど）を判断し、会社の経費ポリシーに沿って整理するよう、Copilot に依頼する（依頼文の正確な文言は語られていません）。
2. 最初に、許可を求められる。以前に「このセッションのみ許可」を選んでいたため、再び許可を求められた。「常に許可」を選んでいれば、この確認は出なくなる。設定でリセットもできる。
3. Copilot は、PowerShell コマンドレットではなく、ダウンロードフォルダー、OneDrive、Windows 検索の機能を使って、カンファレンスに関係しそうなファイルを探す。Copilot+ PC では、そこでセマンティック検索が使われる。
4. 領収書の関連づけと分類が終わると、「整理してよいか」という **2 回目の確認**が出る。1 回目は、読み取りと検索の許可を得るためのもの。今回は名前変更と移動を行うので、「常に許可」の選択肢はありません。
5. 実行すると、右側の File Explorer に「2026 conference expenses」というフォルダーが作成され、ファイルがそこへ移動され、種類（食事、ライドシェア、宿泊など）に応じた名前に変更されていく。この操作は、チャットのタブから行われた。

## 7. 注意点・発表者の気付き

- **書き込み系の操作には「常に許可」を用意していません。** 発表者は、現時点で AI を大規模に展開するうえで安全で適切と考える水準として、ファイルの名前変更や移動は、毎回の明示的な確認の背後に置くべきだと判断した、と説明しています。
- 読み取り系のシステム調査の許可は、「常に許可」を選ぶと以降の確認が出なくなりますが、設定からリセットできます。
- Windows Hybrid Intelligence の機能を、企業がそもそも許可するかどうかも制御できます（Paul 氏の発話）。
- ローカルモデルは、すべてのデバイスで動くわけではありません。また、ローカルモデルの Copilot への導入は「現在も取り組み中」で、詳細は今後数か月で共有される予定です。
- Jason 氏は、BranchIQ と Copilot の統合や MXC 上のサブエージェントは、**まだ本番稼働しておらず、試行中**だと明言しています。
- Copilot の効果を出すには「Windows と Copilot を一緒に使う」ことが前提で、数台のデバイスで試すよう勧められています。
- 発表では、Windows Hybrid Intelligence や新しい検索・Start メニューなどの提供時期、対象 SKU、必要なライセンス、ポリシー名や設定方法は説明されていません。

## 9. まとめ

このセッションは、Windows 11 の基本性能の改善（File Explorer、Start メニュー、タスクバー、検索）と、Copilot を組み込んだ新しい体験の両方を扱いました。前半は、メモリ使用量や起動時間の具体的な数値と、IT 管理者が調整できるメニュー、復活したタスクバーの配置設定、アクション付きの新しい検索を紹介しています。

後半の中心は **Windows Hybrid Intelligence** です。Copilot が local context、local action、local models を使い、PC の状態を調べたり、領収書ファイルを整理したりします。調査には許可、ファイルの変更には毎回の明示的な確認、変更後には元に戻す操作が用意されています。

Flagstar の Jason Pope 氏は、規制の厳しい銀行の立場から、監査可能性とローカルでの AI 実行の重要性を語り、BranchIQ を Copilot に統合する構想を、現在は試行中の取り組みとして紹介しました。参加を希望する場合は、Windows Insider Program for Business と Microsoft Frontier Program が案内されています。
