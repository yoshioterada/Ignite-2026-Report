# THRSP1121 Power to the practitioner: Connect Microsoft endpoint operations

## 1. はじめに

このセッションは、Ninja One（クラウド型の統合 IT 運用プラットフォーム）が、Entra、Intune、Windows 365、Azure、Microsoft 365 といった Microsoft 環境とどう連携するかを紹介する短い登壇です。ゴールは、Microsoft 環境を置き換えることではなく、**その上に重ねる単一の運用レイヤー**として使い、複数のツールを行き来せずに資産を管理できるようにすることだと説明されています。

前半は Ninja One の製品概要と Microsoft 連携の要約で、後半の大部分は、Entra でユーザーを作るところから、バックアップ、デバイス探索、ポリシー、パッチ、脆弱性、チケット管理までをつなぐ**ライブデモ**です。

このセッションを読むと、次のことが分かります。

- Ninja One が何を管理・保護・サポートするプラットフォームなのか
- Entra、Intune、Windows 365、Azure、Entra backup との連携で何ができるのか
- デモで、ユーザー・デバイス・脆弱性・チケットがどうつながって見えるのか

## 5. 発表内容の詳細

### 5.1 Ninja One とは

Ninja One は、クラウドベースの統合 IT 運用プラットフォームです。タグラインは "unify IT and simplify work"。**manage（管理）、protect（保護）、support（サポート）**の 3 つの柱で作られています。

| 柱 | 内容 |
| --- | --- |
| manage | Windows、Mac、Linux のノート PC・デスクトップ・サーバー、Android と iOS のモバイル端末、ネットワーク機器を、単一の画面（single pane of glass）から管理。IT 資産管理モジュールで資産の検出とインベントリも行い、構成の自動化・管理にも対応 |
| protect | 自律的なパッチ適用（Windows、Mac、Linux の OS とサードパーティ製品の両方）。最近リリースした脆弱性管理モジュールが、パッチと連動する。Ninja で脆弱性を検出し、対応が必要な CVE と CVSS を把握したうえで、Ninja で脆弱性に対処するため、閉じたループ（closed loop）になる（対処の部分は "pass those vulnerabilities" と聞こえ、音声認識の都合で表記が確定できません） |
| support | チケット管理プラットフォームを内蔵し、チケットの管理と是正に使える。独自のリモートアクセスツールもある |

バックアップは、エンドポイントとクラウドの両方に対応します。エンドポイント側では Windows、Mac、Linux のファイル／フォルダーのバックアップとイメージベースのバックアップ、クラウド側では Google と Microsoft のワークスペースのバックアップが挙げられました。

これらすべては **ポリシーベースの自動化**の上に構築されています。ポリシーは Ninja の「頭脳」で、オンボードされたデバイスがどう動作するかを決めます。8 つか 9 つの製品にまたがる統合レポートも提供されています。

### 5.2 マルチテナンシー、API、連携、AI

- **マルチテナンシー**：2014 年に創業し、当初は MSP（マネージドサービスプロバイダー）向けから始めました。そのため、マルチテナンシーが最初から作られています。その後、社内 IT と MSP のニーズに共通点が多いと分かり、両方に対応する機能を作っています。MSP では顧客の管理に、社内 IT では組織、拠点、部門の分け方に使えます。
- **API**：非常に充実した API があり、Ninja One にログインせず API だけを使う人も多い、と述べています。
- **連携**：創業時からエコシステムのベンダーであろうとしました。
- **Katana AI**：「人間中心の AI」と説明されています。最近リリースされ、エージェント型 AI モジュールを通じて Ninja One を完全に操作できます。
- **MCP サーバー**：ChatGPT、Claude、Copilot から Ninja One を操作することもできます。

### 5.3 Microsoft 連携の要約

Ajay 氏は、詳細は Josh 氏のデモに任せるとして、連携を次のように要約しています。

| 連携先 | できること |
| --- | --- |
| Entra ID | 技術者とユーザーを Ninja One に自動でオンボードする |
| Intune | デバイスを検出し、Ninja One エージェントを展開して完全に管理する |
| Windows 365 | Ninja One エージェントを展開して完全に管理する |
| Azure | 会期中にリリースしたばかりの新しい連携。Azure のワークロードを管理する |
| Entra backup | ID をバックアップする |

これらはすべて Ninja One Endpoint Management の上に載る、という構成です。

## 6. デモ・手順

Josh 氏によるライブデモがあります。録音は音声のみのため、画面の細部は音声から確認できず、以下は語られた範囲に限ります。

1. **ダッシュボード**：Ninja One のダッシュボードを見せ、「緑が良好、赤が悪い」と説明する。
2. **Entra とのユーザー連携**：administration の accounts にある identity providers を開く。Entra を使う場合は、フルの SCIM サポート（トランスクリプトでは "skim"）があり、Entra でユーザーとグループを作ると Ninja One に同期される。その後、技術者ロールとエンドユーザーロールで、きめ細かいロールベースアクセス制御を定義できる。ユーザーの作成・無効化などは自動で行われる。
3. **Entra のバックアップ**：ダッシュボードから backup を開く。Ninja One の SaaS バックアップは、メールと OneDrive のデータを取り込んで保護する。Entra には設定が多く、変更がいつ起きたかを追跡して再設定したくないため、**既知の良好な時点に戻す**ことができる。ドロップダウンからグループやロールを取り込める。高度なアプリ登録（API クライアントなど）があればそれも追跡して元に戻せる。Josh 氏は、Entra のバックアップを「バックアップの縁の下の力持ち」と表現している。
4. **デバイスの検出**：複数の方法がある。
   - **ネットワーク監視サービス**：ローカルネットワークを、リージョンや場所をまたいで ping／スキャンし、ローカルのマシンを見つける。Wi-Fi に勝手に接続された、いわゆるシャドー IT も検出できる。
   - **Microsoft Intune コネクタ**：最も人気のコネクタで、数千人の利用者がいる。Entra にあるデバイスを取り込んで管理できる。Josh 氏は、Entra を使うなら条件付きアクセスを使ってほしいと述べている。
   - **Intune のパートナーコンプライアンス**：iOS、Android、Mac のマシンを Ninja One で管理している場合に、コンプライアンスの状態を Intune に書き戻せる。
5. **検出結果の確認**：ダッシュボードの devices、discovered に、検出されたマシンの一覧が表示される。既存のマシン、または Ninja One エージェントを展開したマシンは「linked」と表示される。個別のデバイスを開くとデータが見られる。エージェントを導入した実機では、CPU 使用率が高いか、特定のアラートがあるかなど、リアルタイムのデータが分かる。画面の例では、あるマシンが unhealthy で、下にスクロールすると condition alerts で原因を確認できる。
6. **Azure 連携（早期アクセス）**：専用のタブで、Azure と AWS の連携（発話は "Azure AWS integration"。Azure と AWS の両方を指すのか音声からは確定できません）を追加したと説明。仮想マシンなどを取り込める。さらに "your functions" の追加にも取り組んでいると述べ（音声認識の都合で内容が確定できません）、すべてを 1 つのポータルに置けるようにする、と説明している。認証は、独自の API キーを持ち込んでセキュリティを自分で制御する方法のほか、大企業向けにフェデレーテッドな認証にも対応する。対象のスコープは Azure のタグで決める。Josh 氏は、最小権限とスコープを組み合わせる考え方を支持すると述べている。
7. **ポリシーによる管理**：administration の policies を開く。Ninja One では、すべてがポリシーで管理され、複数のマシンに適用できる。主な方法は、いわば「トリップワイヤー」としての**条件（conditions）**によるアラートで、例えばディスク容量が一杯になっていないか、といったものを定義する。Josh 氏は途中で別のポリシーを開いてしまい、どれか思い出せないと述べている。条件には、何がトリガーになるかを定義し、さらに自動化（automation）を追加できる。ソフトウェアのインストール、PowerShell スクリプトや bash スクリプトの実行などで、監視している状態を自己修復できる。そこからチケットを作ることもできる。
8. **OS パッチ**：マシンにパッチを事前に取得（preload）して、帯域の低い拠点でも後でダウンロード・インストールできる。プロキシも可能。保証（warranty）の追跡も、Josh 氏のお気に入りの機能として挙がった。
9. **脆弱性**：Rapid7、Qualys（トランスクリプトでは "Qualis"）、Tenable、Microsoft など、主要な脆弱性ベンダーと連携している。デモのマシンには、CrowdStrike や Rapid7 などを関連付けてある。ダッシュボードの overview で、サードパーティから取り込んだ CVE（または Ninja の脆弱性スキャナーを使う場合はそれ）を拾える。特定の CVE を開いて見ることもできる。
10. **変更管理（CAB）と連動したパッチ**：変更諮問委員会（change advisory board）を重視する場合、CVE から対応するパッチを Ninja のパッチ管理で取得し、CVE に対してパッチを当てる。この例では 6 台の管理デバイスに割り当てられ、チケットを作成して、チケットサイクル全体を進められる。Ninja のチケット管理でも、外部のチケットツールでも可能。
11. **チケット管理**：add app で、連携できるアプリの例が見える。ServiceNow、Zendesk、Freshservice などで、Ninja のネイティブ機能をこれらサードパーティにも広げる、という説明。open tickets で、チケットのライフサイクルを好みの形で見られ、どのユーザーのチケットか、デバイスのチケット履歴も見られる。ナレッジベースとも結びつき、Katana や Copilot が MCP と API を通してナレッジベースを使い、アクションを実行できる。SLA の設定、自動化のトリガー、サービスデスクでのラウンドロビン（担当の持ち回り）などの機能もある、とまとめている。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **ツールを行き来せずに済む**：Entra、Intune、Windows 365、Azure の情報を、Ninja One の単一の運用レイヤー（single pane of glass）から扱える。
- **ユーザーとデバイスの自動化**：Entra からのユーザー作成・無効化の同期、Intune からのデバイス検出とエージェント展開が自動で行える。
- **Entra の構成を元に戻せる**：グループ、ロール、アプリ登録を、既知の良好な時点に戻せる。
- **シャドー IT の発見**：ネットワーク監視サービスで、勝手に接続されたマシンを見つけられる。
- **脆弱性から修復までのループ**：CVE の把握、パッチ、チケット、変更管理までが 1 つの流れになる。
- **既存ツールの活用**：ServiceNow、Zendesk、Freshservice など既存のチケットツールともつながる。MCP サーバーにより、ChatGPT、Claude、Copilot から Ninja One を操作できる。
- **実績**：顧客 4 万、管理エンドポイント 1,500 万、140 以上の国、顧客満足度に当たる指標 98%（聞こえた数字のまま）。

> 補足：個別の顧客事例や、導入による削減時間・金額は紹介されていません。

## 9. まとめ

Ninja One は、Windows、Mac、Linux、モバイル、ネットワーク機器の管理、パッチと脆弱性管理、バックアップ、チケット管理を 1 つのプラットフォームにまとめ、Entra ID、Intune、Windows 365、Azure、Entra backup と連携することで、Microsoft 環境を置き換えずに運用の入口を 1 つにします。ライブデモでは、Entra でのユーザー同期から、デバイス検出、ポリシー、パッチ、脆弱性、チケットまでが 1 つの流れになることが示されました。詳しく知りたい場合は、ブース 5368 で個別のデモを受けられます。
