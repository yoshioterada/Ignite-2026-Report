# BRK400 Windows 365: Your flexible, trusted workspace for the age of AI

## 1. はじめに

このセッションは、Windows 365（Microsoft のクラウド上で動く Windows、つまり Cloud PC）を「人」と「AI エージェント」の両方のための、柔軟で信頼できる作業環境として紹介する発表です。発表者は、Windows 365 の提供開始から 5 年間の歩みを振り返ったうえで、Ignite で発表された新機能を、人向け、エージェント向け、IT 管理者向けの 3 つの方向に分けて説明します。後半は、Chevron と Lululemon の担当者を迎えたパネルディスカッションです。

デモは動画で流す形が中心で、Direct Stream による接続の速さ、周辺機器のリダイレクト、GPU を使った Cloud PC、開発者向けのセットアップ、ローカルモデルとクラウドモデルの使い分け、永続的な Cloud PC をエージェントに渡す例が紹介されます。

## 5. 発表内容の詳細

### 5.1 背景：5 年間の使われ方と 3 つの課題

Windows 365 は提供開始から 5 年（Azure Virtual Desktop は 7 年）です。顧客の使い方は、契約社員を安全に受け入れる、個人所有端末を使う（BYOD）といった単純な用途から始まり、海外拠点への事業拡大、開発者向け、小売などの共有端末で働くフロントラインワーカーへと広がってきたと説明されています。

AI とエージェントについては、IDC の予測として 2028 年までに 13 億のエージェントが従業員と一緒に働くという数字が示されました。エージェントがアプリを開く、フォームに入力する、API を持たない基幹業務システムにアクセスする、といった作業が想定され、そのための安全な作業場所を、従業員にしてきたのと同じように用意する必要がある、という主張です。

顧客から聞く 3 つの圧力として、次が挙げられました。

| 課題 | 内容 |
|---|---|
| 端末性能と AI 対応 | 従業員の 80% が、自分の AI 対応度を端末の性能で捉えている |
| ハードウェア価格 | 第 3 四半期末の最新値で 40% 超の上昇。上昇傾向は続いている。買い替えれば済む状況ではない |
| 将来への備え | CIO は、イノベーションを損なわず、コストを保ちながら、インフラの将来対応をしなければならない |

これに対する答えが「人とエージェントの両方のための、柔軟で信頼できる作業環境」としての Windows 365 です。人については、仕事に合わせて計算資源を合わせられ、PC の寿命（ライフサイクル）を延ばす助けになると説明しています。前日の Pavan 氏のイノベーションセッションで話題に出ており、ブログにも情報を公開しているとのことです。エージェントについては、IT の管理下に置いたまま安全な計算基盤を提供する、という位置づけです。

### 5.2 構成の幅

Cloud PC は弾力的なので、日常的なメール作業から、GPU が必要なグラフィックス集約型の作業まで対応できます。構成は 2 から 32 vCPU、最大 128 GB の RAM（「2 から 32 VCPU、128 GB の RAM まで」と発話）、GPU ではビデオメモリ 4〜16 GB の選択肢があります。数値の詳細はスライドに表示されていました。

### 5.3 5 年間の取り組みの振り返り（Bhavya Chopra 氏）

発表者は、「5 年前、Cloud PC は永続的な仮想デスクトップ 1 種類を意味していた」と述べ、その後の拡張を次のように挙げています。

- 新しい提供形態：Windows 365 Enterprise Flex や Reserve（音声認識の都合で正式名称の表記が確定できません）。デスクトップとクラウドアプリの両方
- 新しい計算構成：32 vCPU まで、GPU の SKU
- AVD hybrid：オンプレミスのインフラ向けのクラウドネイティブな VDI。9 月に一般提供（GA）。オンプレミスに残りたい顧客も、クラウド接続を持ちながら移行を始められる
- 専用デバイス：Windows 365 Link（小型のパック型デバイス）と、Asus が最近発売した NUC 16（Windows 365 専用デバイス）

### 5.4 Ignite の新機能：概要

発表者は、まず Ignite での新発表を一覧にしています。

- **Direct Stream**：Cloud PC をローカルのように感じさせるための技術
- **Nvidia との新 GPU**：グラフィックスと AI の両方のワークロード向けに作られた GPU（発話では「RTX Pro 6000 Black Belt Server Edition」と聞こえ、音声認識の都合で表記が確定できません）
- **Windows 365 Link と Logitech 周辺機器のバンドル**：机上の環境がローカルのように感じられる
- **開発者向け**：Dev Box の廃止（提供終了）の発表と、全開発者に Cloud PC を使ってもらうための機能群
- **ローカル AI モデルの実行サポート**：ハイブリッドインテリジェンスのテーマ

「Cloud PC はローカルのように感じるべきで、別物に見えてはならない。仮想化は実装の詳細になるべきで、それを気にするのは自分たちの仕事」と述べています。

### 5.5 Direct Stream：速さ・性能・信頼性・GPU

この 5 年間、ストリーミングのスタック（トランスポート、ネットワーク、プロトコル）を作り込み、機能を少しずつリリースしてきたとのことです。投資は 4 つのカテゴリーです。

| カテゴリー | 説明 |
|---|---|
| 速さ | 適切な条件では数秒で接続。デモでは Windows アプリで接続ボタンを押してから 10 秒以内にデスクトップに入る |
| 信頼性 | 接続の信頼性が 300% 向上したと述べている |
| 性能 | セッション中の応答性を高める。過去の VDI の体験は改善する、と発表者は述べている |
| セキュリティ | クライアントからクラウドまでのトランスポート全体で安全 |
| GPU | GPU を持つ Cloud PC で、ローカルに近い体験を得られるだけの能力を引き出す |

> 補足：4 つのカテゴリーとして挙げられたのは、速さ、性能、セキュリティ（トランスポート）、GPU です。信頼性は別に「3 つ目の観点」として説明されており、上の表では並べて示しました。発話の数え方が一貫していない点にご注意ください。

**周辺機器（HID リダイレクト）**：デザイナーや開発者にとって、マウスやキーボードは「仕事の道具」で、5 ボタンのマウスの各ボタンを細かく設定している人もいる、という前提で説明されました。画面では Logitech MX Master 4 が Cloud PC の中で動作し、Logitech Options Plus アプリで、各ボタンの動作をローカルと同じようにカスタマイズできます。これは HID（ヒューマンインターフェースデバイス）のリダイレクトで、デバイスがセッション内で列挙・管理されるため、クライアント端末側に戻って設定する必要がなくなる、と説明しています。

**GPU Cloud PC**：Nvidia のチップを搭載した GPU Cloud PC で、4K のフルスクリーンアニメーションを 60 FPS で再生する様子が示されました。

**マルチパス（信頼性）**：ネットワーク経路が 2 本ある状態で、主経路を無効にしても、動画が止まらないことが示されました。従来は、ネットワークを切ると黒い画面で再接続のダイアログ（5 回中 1 回目…といった表示）が出ていました。マルチパスでは、二次経路が使えるときにセッションを切らずに切り替わります。セッションが切断される場合でも、画面がぼかしになり、自動的に再接続していることが分かる、より現代的な表示になります。

### 5.6 開発者向け Cloud PC

昨年の Build で、Git、GitHub、Node.js、WSL などを構成済みにした開発者向けイメージ（Windows 11 の開発者構成イメージ）が発表されました。今回は、Dev Box サービスの廃止（提供終了）を発表したうえで、顧客から「IT 部門は自分の日々のプロジェクトを知らない。環境のカスタマイズを IT に頼みたくない」という声があったことが紹介されています。必要なツールやリポジトリを知っているのは、チームリーダーやシニアエンジニアだという前提です。

そこで、次の仕組みを作っているとのことです（デモの内容は 6.2 に記載）。IT は Intune で GitHub リポジトリを指定し、チームリーダーが GitHub 上でアプリを導入して、Cloud PC で実行したいスクリプトを用意します。

### 5.8 Windows 365 for Agents

昨年発表された Windows 365 for Agents について、発表者は、Windows は 40 年間仕事が行われてきた場所であり、働く人の数が今後 3 年で倍増するくらい拡大してもそれは変わらない、と述べています。すでにあるものは次のとおりです。

- Microsoft Copilot Studio と Agent 365 のコンピューター利用ツール（Computer Use Tool）
- 2 つのモデル：オンデマンドの PC と、常時利用できる PC。どちらも従量課金

コンピューター利用ツールは、エージェントが人と同じようにコンピューターを使う仕組みです。画面を理解し、クリックし、入力し、アプリ間でデータを移します。API が無く、業務ロジックがアプリ内に閉じているアプリ（Microsoft 社内にもあると述べている）が対象で、MCP サーバーにもつながっていないアプリに有効です。

Ignite の新機能は次のとおりです。

| 新機能 | 内容 |
|---|---|
| Microsoft Copilot harness | Copilot Studio が公開した新しいハーネス（エージェントの実行基盤）。コンピューター利用ツールをこのハーネスでもサポートする |
| Microsoft Foundry | コンピューター利用ツールを Foundry のツールキットで利用可能にする |
| オンプレミスアプリへの安全なアクセス | 「Windows 365 for Agents はオンプレミスアプリに届かない」という声を受けて作った。プレビュー |
| 永続的な Cloud PC | 自律エージェント向け。固有の ID を持ち、前回のセッションの文脈を次回に引き継ぐ。OpenClaw のような常時動作するアシスタントを想定（表記は音声認識の都合で確定できません） |

これらはすべて Copilot クレジットで課金されると述べています。永続的な Cloud PC は、このセッションの時点では「今月末に Frontier のプレビューで利用可能」と説明されています。

IT 管理者の設定は、人の Cloud PC と同様です。Intune で「Persistent Cloud PC」（永続的な Cloud PC）を選び、イメージを選択し、より高い耐障害性のために地域を選び、サポートするエージェントランタイムを選びます。現在サポートしているのは、デモで見せた OpenClaw です。作成すると、エージェントが使えるようになります。Agent 365 と統合されており、人間のユーザーに使っているのと同じセキュリティスタックが、エージェントのユーザー向けに更新されていくとのことです。

### 5.9 Microsoft 社内事例（動画）

Microsoft Business Operations チームが Windows 365 for Agents を使っている事例の動画が流れました。発話で確認できる内容は次のとおりです。

- 対象は、受注から入金までの業務のように、複数のシステムとツールをまたぎ、引き継ぎが多い業務。古いシステムが多く API でつながらないため、熟練した担当者が「システム間の糊」になっていた
- デジタルワーカーには、企業が管理するデバイスが必要。API やアプリのコネクタがあればそれが出発点になるが、すべての業務プロセスにあるわけではない
- 画面のスクリーンショットを撮り、UI を操作する方法で、初めて見るアプリでも動作する
- デジタルワーカーには、人間と同じ権限を既定で与えるべきではなく、ID で追跡・観測・制御する
- 「判断と説明責任は人間が持ち、反復はエージェントが持つ」という考え方
- デジタルワーカーの活用で、プロセス全体で人手が関わる量が少なくとも 75% 削減された。Windows 365 for Agents を導入するとさらに 20% の改善が得られた

### 5.10 IT 管理者向けの新機能

発表者は、Cloud PC を物理 PC と同じように簡単に保護・管理でき、クラウドならではの価値は上乗せして提供する、と説明しています。Ignite の内容は次のとおりです。

- **アプリ保護ポリシー**：Windows アプリ向けにサポートを開始（iOS と Android は以前から対応済み）
- **コンテキストベースのリダイレクト**：接続の信頼度に応じて、Cloud PC に出入りするデータを制御する。管理外の端末、安全でないネットワーク、安全なネットワークなどの条件ごとに、コピー＆ペースト、ドライブ、プリンターなど、DLP 上の主な項目を許可するか決められる（発話では 4 つの大きな項目と述べているが、挙げられたのは 3 つ）
- **Windows 365 Reserve**（共有 Cloud PC）：自動ストレージ管理、ユーザー主導のプロビジョニング解除、自動のプロビジョニング解除
- **監視とレポート**：接続と Cloud PC の性能の詳細を見られるレポートとダッシュボード
- **Windows 365 Admin Assistant（プレビュー）**：Intune の中で、Windows 365 を管理しながら（監視ダッシュボードからも）エージェントを呼び出し、問題を問い合わせられる

Admin Assistant の例として、発表者は前日の出来事を話しています。Microsoft の経営層の 1 人から「しばらくログインしていない Cloud PC が動くか確認してほしい」と頼まれ、Admin Assistant に「Cloud PC は正常か」と尋ねたところ、前回は 10 秒の接続失敗があったが現在は問題ない、という答えが返り、その旨を伝えられたそうです。紹介する予定だったデモ動画は、時間の都合で省略されました。

### 5.11 顧客パネル

Mayank Verma 氏が司会で、Chevron の Shyam Pachamathu 氏と Lululemon の Ed Collins 氏が登壇しました。

**各社の状況**

- **Chevron**：約 4〜5 年前に VDI を始め、統合面で多くの課題があった。AVD に移ったが統合の複雑さは残り、そこへ Windows 365 が来て、以降その道を進んでいる。展開済みの Cloud PC は 10,000 に近く、今も増加中。
- **Lululemon**：1998 年に創業し、1 店舗から 30 市場で 800 店舗超に成長した。小売店、オフィス、倉庫を含む世界中のデバイスを管理している。短期間に 1,000 台超の Cloud PC を展開する必要があり、Microsoft チームの支援で上層部の承認を得て、約 1,100 台を 3 日足らずで展開した。

**予算圧力（AI 投資、インフラコスト、ハードウェア価格上昇）への対応**

- Chevron の考え方は、コストより、最終的な成果（利用者の体験）を見ること。以前は MSP パートナーなどが関わり、仮想デスクトップに入るまでに多くの統合ポイントがあった。Windows 365 ではそれが切り離され、利用者はいつもの自分のデスクトップに入る。ノート PC など物理デバイスの保守に関する価値も大きいと述べている。また共有 PC の多い製油所で、Cloud PC や（発話では）小型デバイスを使い、資産を使い切る（原文は「sweat the asset」）ことができる。
- Lululemon は、セキュリティとユーザー体験のバランスを重視している。セキュアにしすぎると、利用者は使わなくなるか別の方法を探す、という考えです。ゼロトラストを徹底し、Lululemon が管理・所有する信頼済みデバイスからのみデータ、アプリ、リソースに入れるようにしたい。ただ急成長しているため、インドのテックハブで翌日から働き始める人に、端末を購入して発送し、Autopilot と Intune で設定する場合は数週間かかる。Cloud PC なら数時間で用意でき、ライセンスを付与してプロファイルを割り当てれば、すぐに始められる。
- コスト比較では、物理端末の更新サイクル（Evergreen）を 5 年に延ばすと、5 年で割れば物理端末のほうが安いこともあり得る。しかし Cloud PC は更新が不要で、2 時間でアップグレードできる。Mayank 氏は、生産性の向上は企業ごとに意味が違い、インフラ側の計算式も企業ごとに異なる、とまとめている。

**AI への取り組み**

- Lululemon：動きは速い。インドで展開した Cloud PC（発話では 1,200 台）の多くは AI 開発者向け。長い旅になるが、できるだけ速く追いつこうとしている。
- Chevron：AI はあらゆる場所にある。全従業員に Copilot、ローカル LLM など、必要なツールと余力を用意し、取り組みを始められるようにしたい。「トークン経済」は現実で、今取り組まないと負ける、と述べている。ローカル LLM をエッジに置いて作業の大部分をこなし、必要なときだけ OpenAI などに出る形を目指している。

**会場へのアドバイス**

- Chevron：成果を見て、従来の「ユーティリティー IT」から、利用者を支える方向へ。Cloud PC は急速に広がった。AVD を回収しなかったのに、AVD を持つ利用者が Windows 365 を渡されると自然にそちらへ移り、ライセンスを買い足すことになった。

## 7. 注意点・発表者の気付き

- **現時点で提供されているものと、これからのものの区別。** 永続的な Cloud PC は今月末の Frontier プレビュー、オンプレミスアプリへの安全なアクセスはプレビュー、Windows 365 Admin Assistant もプレビューです。AVD hybrid は 9 月に GA 済みです。
- **発話が一貫していない数字。** Direct Stream の 4 カテゴリーの数え方、Lululemon がインドに展開した台数（約 1,100 台と 1,200 台）は、発話の中でも揺れています。
- **ハードウェア価格。** 40% 超の上昇は「第 3 四半期末の最新値」とされ、買い替えで対応できる状況ではないと発表者は述べています。
- **エージェントの権限。** Microsoft 社内事例の動画では、デジタルワーカーに人と同じ権限を既定で与えるべきではなく、ID で追跡・制御すると説明されています。
- **コストの考え方は企業ごとに異なる。** 物理 PC を 5 年使う場合は安くなり得るが、Cloud PC は更新が要らない、という Lululemon の整理が紹介されました。生産性の測り方は企業ごとに違うとのことです。
- **デモの不具合。** 動画の再生に失敗した場面があり、発表者は「デモが 1 つは動かないものだ」と話しています。デモ自体の内容は上記のとおりです。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **ローカルに近い体験**：接続は適切な条件で 10 秒以内。接続の信頼性は 300% 向上。マルチパスで経路が切れても動画が途切れない。HID リダイレクトで周辺機器がローカルと同様に動く。GPU Cloud PC で 4K、60 FPS を実現。
- **開発者の立ち上げ**：IT でなくチームリーダーが環境（ツール、リポジトリ、スクリプト）を用意し、ログインした日から使える。
- **トークンの節約**：簡単な作業をローカルモデルに回すことで、クラウドのトークン消費を抑える。
- **エージェントの安全な作業場所**：API の無いアプリでも、画面操作で業務を自動化できる。Microsoft 社内では、人手が関わる量が少なくとも 75% 減り、Windows 365 for Agents でさらに 20% 改善した。
- **IT 管理**：アプリ保護ポリシー、コンテキストベースのリダイレクト、Reserve の自動管理、監視レポート、Admin Assistant による問い合わせ。
- **顧客の成果**：Chevron は約 10,000 台の Cloud PC を展開。AVD 利用者が自発的に Windows 365 へ移った。Lululemon は約 1,100 台を 3 日足らずで展開し、新規入社者の環境を数時間で用意できる。
