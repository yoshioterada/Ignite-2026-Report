# THRSP1052 Connect people, spaces, and AI for better workplace experiences

## 1. はじめに

会議室にカメラやマイクを設置しても、予約、照明、空調、利用状況の把握が別々の仕組みでは、利用者も管理者もその間を埋めなければなりません。このセッションは、職場に足りないのは機器の数ではなく、仕組み同士のつながりだという問題提起から始まります。

Q-SYS がスポンサーを務める発表で、Microsoft Teams、Copilot、Places といった仕事のためのソフトウェアと、会議室の AV、センサー、建物設備をどう結び付けるかを説明しています。後半では、Redmond の Microsoft Experience Center One（EC1）を、建物全体を一つのプラットフォームで扱う事例として紹介しました。

**機器単位で選ぶのではなく、人が仕事をする流れと、建物全体の運用を支える基盤として考える**、というのが中心のメッセージです。

## 3. 何に関する発表か

対象は、会議室や建物の AV・IT を、AI を含む職場のサービスにつなぐ仕組みです。AV はここでは、音声、映像、それらの制御を含む領域として扱われています。

登壇者は、AI を使うデジタルな体験が、部屋、機器、センサー、建物設備と交差する点に注目しました。ソフトウェアだけでなく、物理空間が生み出す情報もつながって初めて、職場全体の改善に利用できます。

JLL がその年に実施した調査として、企業・不動産分野のリーダーの 78% が、AI は不動産戦略に影響すると考えている、という数字を紹介しました。一方、コラボレーションの観点では 31% という数字を対置しています。後者の設問や評価基準は詳しく説明されていませんが、AI への期待に対し、物理的な職場が追い付いているかを問い掛ける導入です。

発表は、職場を構成する 4 つの層、Q-SYS のプラットフォーム、接続による価値、EC1 の事例という順番で進みます。

## 4. 発表者が伝えたいメッセージ

登壇者は、職場の問題を「技術がない」「機能が足りない」とは捉えていません。個別の製品として導入された仕組みがつながっていないことを課題にしています。そこで、AI、ソフトウェア、AV 機器、物理空間を一つのエコシステムとして設計するよう提案しました。

利用者が欲しいのは、AV や建物管理の仕組みそのものではありません。適切な場所を見つけられること、会議をすぐ始められること、機器のトラブル対応ではなく仕事に集中できることです。技術が背景に退き、自然に使える状態を目指します。

また、すべてを一社で作るわけではありません。Q-SYS が基盤を提供し、パートナーが機器、ソフトウェア、サービスを拡張します。**接続できるプラットフォームを選ぶことが、後から変化を取り込む余地につながる**という考えです。

## 5. 発表内容の詳細

### 5.1 職場を 4 つの層で捉える

最初に、人を起点とする構成を示しました。

| 層 | 役割 | 発表中の例 |
| --- | --- | --- |
| People（人） | 利用者が得たい成果を定める | 協働しやすい、場所を探しやすい、情報にすぐアクセスできる |
| Productivity（生産性） | 仕事の情報と協働を支える | Microsoft Teams、Copilot、Places |
| Products（製品） | 物理的な職場との接点になる | マイク、カメラ、センサー、表示装置、照明、空調など |
| Connectivity（接続） | 各領域の仕組みとデータを結び付ける | AV・IT、建物設備、監視・管理、利用分析、AI サービスの接続 |

「人」の層では、自宅や自分の執務空間のように、表示装置、照明、日よけなどを無理なく扱える状態を例にしました。会議室でも同じように、利用者が設備を意識せず仕事を始められることを目指します。

「生産性」の層では、役員向けの説明会を準備する場面を想定しています。Copilot が過去の会議を要約し、アクション項目を特定し、資料を作ります。Teams は会議室と遠隔の参加者をつなぎ、Places は予定の調整、出席傾向の把握、適切な場所の選択を支えます。

「製品」の層には、音声、映像、制御、センサー、ディスプレイ、プロジェクター、入退室、予約、サイネージ、照明、空調が含まれます。製品はそれぞれ、利用者と物理空間の接点になります。

### 5.2 会議の前後まで、情報をつなぐ

「接続」の層の説明では、翌日の役員向け説明会を例にしました。Microsoft 側が会議の文脈と参加者情報を提供し、Q-SYS が音声、映像、制御の環境を準備します。建物設備のパートナーとして、姉妹会社の Distech Controls を挙げ、照明や室内環境を整える流れを説明しました。

利用場面の説明では、入室すると会議が自動で始まり、カメラが参加者を適切に捉え、室内と遠隔の両方に向けて音声を最適化する姿を挙げました。照明・空調・表示装置の操作や、センサーによる在室状況の把握も関係します。会議後には、集めたデータを職場の運営担当者が確認し、空間の使われ方、協働、設備の動作、環境条件、従業員体験を把握する考えです。

> 補足：ここは、接続された職場での利用場面を説明した部分です。紹介した一連の動作を、会場で実際に実行したデモではありません。また、すべての動作を EC1 で実装済みと説明したわけでもありません。

### 5.3 Q-SYS のフルスタック AV プラットフォーム

Q-SYS は、クラウドを前提とする構成でデータと機器を統合する、ソフトウェアベースのフルスタック AV プラットフォームとして紹介されました。音声、映像、制御、データ、クラウドの機能を同じ基盤で扱い、リアルタイムの動作と、データから状況を把握することにつなげます。

構成の説明では、次の 3 つを挙げています。

1. **部屋の「目と耳」に相当する入出力**  
   マイク、スピーカー、センサーなどから情報を得ます。紹介映像では「マルチモーダルな入出力（multimodal I/O）」という表現も使われています。
2. **Intelligent Platform OS（インテリジェントなプラットフォーム OS）**  
   中央で情報をまとめ、連動させるオーケストレーションの層です。
3. **Cognitive cloud（認知クラウド）**  
   情報をクラウド側で学習や適応に利用し、現在と将来の機能につなげる層です。

発表の要点は、入力機器を単独で増やすのではなく、得られる情報と制御を同じ基盤につなぐことです。個別の API の呼び出し方法や、クラウドへのデータ転送設定までは扱っていません。

### 5.4 Q-SYS Open とパートナーによる拡張

プラットフォームの周囲には、次の要素を置いています（Q-SYS Open と Q-SYS Partner は名称のまま記載）。

| 要素 | 発表での位置付け |
| --- | --- |
| Q-SYS の製品 | 自社で設計・開発するハードウェア、ソフトウェア、サービス |
| Q-SYS Open | 業界標準のプロトコル、公開 API、開発者向けツールによる拡張 |
| Q-SYS Partner | Q-SYS が認めた連携を含むパートナーのエコシステム（パートナープログラム） |

パートナーは、機器やソフトウェア、サービスをプラットフォームへ接続します。Q-SYS verified assets（Q-SYS が検証済みの連携資産）にも触れ、別々に動いていた技術を、同じ環境のデータの流れに取り込むと説明しました。

これにより、システムの監視、利用場面の自動化、物理空間で起きたことと職場の IT ワークフローとの接続を進めます。拡張の方向性を述べたもので、セッション内でプラグインを実装したり、特定の API を実行したりしたわけではありません。

### 5.5 接続された職場で得たい価値

登壇者は、成果を機器の設置数ではなく、利用と運用の両面から整理しました。

- **データに基づく把握**：人が空間、設備、職場の資源をどう使っているかを理解します。
- **従業員体験の改善**：利用時の手間を減らし、協働しやすくします。
- **公平な会議体験**：遠隔参加者だけでなく、同じ部屋にいる参加者の体験にも目を向けます。
- **運用の複雑さの削減**：分断されたツールではなく、接続された基盤から複数の仕組みを扱います。
- **展開と管理の迅速化**：一つの部屋だけでなく、建物やキャンパスへ広げます。
- **AI 活用の準備**：将来の職場向けエージェント、自動化、知的な体験の基礎を作ります。

特に会議体験の話では、遠隔側だけを改善して終わるのではなく、部屋の中の人にも同じように配慮する点を強調しました。

### 5.6 Microsoft Experience Center One の事例

EC1 は、Redmond にある Microsoft の旗艦施設です。役員向けの説明会だけでなく、来訪者が建物全体で Microsoft の技術やビジョンを体験する場として紹介されました。

事例映像では、従来の音声・映像中心の設備から、建物のどこでも体験を提供する構成への変化を説明しています。Q-SYS のソフトウェアとクラウドを中心とする性質が、将来の変化を取り込める建物を作る考え方に合っていたとのことです。

設備の配置先は、特別な体験を提供する空間から共用エリアまで広がります。役員会議室の例では、カメラを 1 台置くだけでなく、複数のカメラを同じプラットフォームへ接続し、そのデータを利用する構成に触れました。

建物の全フロアにまたがるフラットなネットワークを構築し、1,200 超のエンドポイントを一つの仕組みへ接続したと説明しています。映像の後、登壇者は次の数字を整理しました。

| 項目 | 発表で紹介された規模・変化 |
| --- | --- |
| 対応する空間 | 70 超 |
| 接続するエンドポイント | 1,200 超 |
| 設計・構築時に除去した障害発生点 | 1,500 |
| 統合したサブシステム | 7 |
| 全体を支える基盤 | 1 つのフルスタック AV プラットフォーム |

1,500 という数字については、故障し得る連携箇所を減らしたことを意味すると補足しました。7 つのサブシステムの統合も、問題が起きた際に別々の窓口へ連絡する状態から、相談先をまとめることとして説明しています。

### 5.7 最後の呼び掛け

AI エージェントが使われる時代の目標は、技術をさらに設置すること自体ではありません。人、空間、AI をつなぎ、そこから得る情報で働き方を改善し続けることだと結びました。

最後の提案は、エコシステムを先に考えること、柔軟なプラットフォームで構築すること、継続的な改善を前提に設計することの 3 点です。質疑を受け付ける案内はありますが、提供されたトランスクリプトに実際の質問・回答は収録されていません。

## 6. デモ・手順

このセッションでは画面を使ったデモは行われていません。スライドによる説明と、EC1 の導入事例映像の上映が中心です。製品の操作画面、管理画面の設定、コードの実行などの手順は紹介されていません。

代わりに、説明された会議体験の流れを整理すると、次のようになります。

1. Microsoft 側の情報から、会議の文脈と参加者を把握します。
2. Q-SYS が音声、映像、制御を含む会議環境を準備します。
3. 建物設備のパートナーが照明などの環境条件を整えます。
4. 会議中に、利用状況や設備、環境に関する情報を集めます。
5. 職場の運営担当者が情報を確認し、次の改善に利用します。

これは発表で示した利用の流れであり、再現可能な設定手順ではありません。EC1 の映像も、導入の考え方と構成を紹介するもので、個別の設定値は読み取れません。

## 7. 注意点・発表者の気付き

**接続の複雑さも、設備の設計時に扱う必要があります。** EC1 の事例では、機器をつなげた数だけでなく、故障し得る連携箇所を減らしたことに注目しました。連携を増やすだけではなく、運用の分断を減らす考えです。

また、一社ですべての技術を作ることはできないと明言しています。API、標準プロトコル、開発ツールとパートナーの組み合わせを前提にします。ただし、具体的な互換性一覧、認証手順、データ保持、ネットワーク設計の条件までは説明されていません。

個別の部屋だけでなく、建物やキャンパスへ展開できるかも検討点です。EC1 では、特別な会議室と共用エリアの両方を同じ基盤で扱う柔軟性が評価されています。

## 8. 利用者にとっての利点

従業員にとっては、会議の開始や部屋の操作でつまずく時間を減らし、仕事へ集中できることが狙いです。遠隔参加者に加え、室内の参加者も含めた会議体験を扱っています。

設備や IT の運営側には、空間と機器の利用状況を結び付けて把握し、分断された管理を減らす利点があります。EC1 では、70 超の空間と 1,200 超のエンドポイントを一つの基盤に接続し、7 つのサブシステムを統合したと紹介されました。

将来の AI 活用に対しても、物理空間の情報と IT の処理をつなぐ土台になります。ただし、労働時間や費用の削減率、投資回収期間、障害件数の減少は提示されていません。紹介された構成や設計上の変化と、未提示の事業成果は分けて理解する必要があります。

## 9. まとめ

職場を、個々の会議機器ではなく、人、仕事のためのソフトウェア、物理設備、接続の 4 層で捉えた発表です。Q-SYS の基盤とパートナーの拡張を使い、Microsoft の会議・業務情報を、部屋の音声、映像、センサー、建物設備へつなぐ考え方を示しました。

EC1 の事例は、その対象が会議室一つではなく、建物全体であることを具体的にしています。導入時には、機器の機能だけでなく、情報の流れ、管理の窓口、将来の変更を受け入れる余地まで含めて考えることが、発表から受け取れる要点です。
