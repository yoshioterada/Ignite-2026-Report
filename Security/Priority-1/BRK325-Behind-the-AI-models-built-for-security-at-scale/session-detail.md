このセッションは、Microsoft がセキュリティ向けに作った専用モデル「MAI Cyber」ファミリーについて、**なぜ専用モデルが必要だったのか、どう訓練したのか、どう安全に扱っているのか、そしてコストをどう抑えているのか**を、開発側が説明するものです。

発表者の主張は次の 3 点です。

1. **攻撃者は休まない。防御側も常時稼働の AI が必要。** AI エージェントによって、攻撃は 24 時間休みなく、機密リソースを容赦なく攻撃し続けられ、数日〜数週間かかっていた侵害が数時間で起きる、と述べています。そのため防御側も、常時稼働できる AI を、手の届くコストで使えることが重要です。

## 5. 発表内容の詳細

### 5.1 脅威の状況：AI は攻撃にも防御にも有利

Nazmus 氏は、AI が複雑な攻撃をより多くの攻撃者に使いやすくしたこと、エージェントが連携する攻撃が 24 時間動き続け、機密リソースを繰り返し攻撃し、数時間でシステムを侵害し得ることを挙げました。一方、防御側については、セキュリティ上の問題を見つけて直す課題は業界全体にとって難しいものだったが、数字を見れば AI は防御にも有効であり、適切なエージェントと適切なモデルを使えばソフトウェアをより安全にできる、と述べています（具体的な数字は、このセッションでは示されていません）。

今年の初めに Microsoft Security と Microsoft AI が協力を始めた際、「機械の速度で動く攻撃者に対して、防御側に決定的な優位をどう与えるか」を問いにしました。当時のモデルの状況は、大きく、計算資源を多く使い、ベンチマークのリーダーボードでの性能を目指して最適化されたものが中心でした。数か月前の主な用途は、ソフトウェアの脆弱性の発見で、ワークフローは静的、つまりコードのバッチをスキャナに通すようなものでした。

### 5.2 AI・言語モデルに必要な 4 つの柱

Microsoft には、セキュリティの数十年の経験があり、機械学習を防御に使ってきた経験があります。その経験から、どの AI ソリューションでも満たすべき 4 つの柱を挙げています。

| 柱 | 説明 |
| ---- | ---- |
| Accuracy（正確さ） | 結果が良いこと。セキュリティは「干し草の山の中の針」を探す作業で、再現率（recall）と適合率（precision）の両方を最適化するのは非常に難しい。これを誤ると、セキュリティエンジニアのチームにノイズと負担を与える |
| Diversity（多様さ） | 企業を守るのはコードのスキャンだけではない。アラートの調査、検出ルールの作成など、多様な仕事に対応できること |
| Cost（コスト） | 常時稼働の防御は、チームが導入できる程度に安価である必要がある |
| Trust（信頼） | 訓練時にインフラのガードレールがあり、推論時に安全にデプロイされ、システムの挙動が透明で、AI が何をしているかを見て、検証し、制御できること |

この 4 つの成果を目指して、**目的特化のセキュリティモデル**にたどり着いた、という流れです。MAI Cyber ファミリーは、まずセキュリティチームが必要とするタスクに時間をかけて特化させ、その特化が性能とコストの最適化につながり、スケーラブルなエージェント型ワークフローを可能にする、という構想です。その土台として、Microsoft のベストプラクティスと、重要インフラを何十年も運用してきた教訓に基づく「信頼」を置きます。

戦略は、**セキュリティデータ、セキュリティの専門知識、強化学習**の 3 つに支えられています。Microsoft には、脅威インテリジェンスや、スキャンしている数万規模の自社リポジトリなどのデータがあります。ペネトレーションテスト、アプリのセキュリティ、インフラのセキュリティの専門家が、「良い」ソリューションがどんなものかを形づくり、その専門知識は、AI モデルの訓練方法、強化学習環境（gym）の設計、訓練中にモデルが得る報酬に反映されます。

### 5.3 MAI のモデル戦略と、MAI Cyber モデルの作り方

Ramya 氏が、MAI のモデル戦略を説明しました。

- MAI のモデル戦略は**コード**から始まる。コーディングモデルは一般にとても優れている。
- まず MAI の基盤モデルから、**MAI Code Flash** を作った。このモデルは推論が強く、セキュリティの前提条件の 1 つである。
- 親モデル（MAI Code Flash）の上に、Microsoft Security の専門知識、データを重ね、**強化学習**で **MAI Cyber 1 Flash** を作った。このモデルは **7 月に M-dash 内で出荷**された。
- **MAI Cyber 2 Flash** は、このセッションの前日に Ignite で発表された。同じ系譜で、より多くの脆弱性を発見できる。ベースには MAI Code の Flash モデルがあり、その上にさらに知能を積み上げた（トランスクリプトでは「MAI code to Flash model」と聞こえ、モデル名の表記は確定できません）。検出ルールの作成（detection authoring）、トリアージ、調査にも役立つ。

目標は、**フロンティア級のセキュリティ能力を、競合モデルよりずっと低いタスクあたりコストで提供すること**です。

- データの選定は、エンタープライズでの利用を前提に計画している。モデルに入るデータは、厳選され、徹底的に審査され、再現可能なものである。
- 「何としてもフロンティアに追いつく」ことを急いでいるわけではない。
- **モデルは顧客データで訓練されていない。** M-dash では、顧客データから完全に距離を置いている（訓練に使わない、中を見ることもできない）。「あなたの環境で悪用可能なもの」は、あなたのデータだ、という説明です。
- このモデルはサイバーセキュリティのモデルなので、**誰が使えるかのアクセス制御**が重要で、Microsoft Security 製品の内部に出荷されていても、ログとポリシーによって、アクセスできるユーザー・顧客を限定している。

### 5.4 訓練データ、強化学習、評価

Anthony 氏は、実世界のセキュリティデータについて次のように説明しました。

- Microsoft のリポジトリと、Microsoft が依存するオープンソースのリポジトリを、数千規模でスキャンする。膨大な量の発見（findings）が生まれ、データ開発のプロセス全体で **1,000 億トークン以上**を利用した。
- データを集めるだけではなく、**数千人の Microsoft のエンジニア**がその発見結果を精査して、Microsoft 製品の脆弱性を修正し、オープンソースの修正にも貢献している。その作業は、モデルへの重要な訓練データにもなる。誤った発見、重複した発見、ユーザーの時間を無駄にするノイズを見つけ、それをモデル側で直す。

そのうえで、**検証可能な報酬による強化学習（reinforcement learning with verified rewards）** を使います。

1. 目標が分かっている課題に対し、モデルにさまざまなツールの使い方、手法、ポリシー、戦略を試させる。
2. 目標に達するまで、そのタスクを繰り返す。
3. さらに繰り返して、より効率的な経路を探し、進捗に応じてモデルに報酬を与える。

このプロセスは大部分が自動化されていますが、完全には自動ではありません。**人間の研究者が中心にいて**、進捗を観察し、訓練が局所最適に陥った場合に抜け出す手助けをします。自動化が出せる解だけでなく、最善の解を追求するためです。

また、モデルだけでなく、**エンドツーエンドのシステムを評価**します。実際の Microsoft のサービス（社内でも脆弱性の発見と修正に使っているもの）に対して評価し、エージェントモデルとサービス全体が協調して動く組み合わせを見る必要があると述べています。これにより、MAI Cyber 2 Flash を使う M-dash の、実行ごとの一貫性（run-to-run consistency）が大きく改善しました。

### 5.5 学んだ教訓

3 回のモデルリリースを通して、次の教訓が語られました。

- **モデルは近道（ショートカット）を探す。** 能力が上がるほど、実際のデプロイで期待するガードレールの内側にモデルを留めておくことは、エンジニアリング上の課題になる。例えば、脆弱性の答えをインターネットで調べる「不正」をしないようにするのは難しく、重要な問題である。評価データが得られるたびに、**報酬ハッキング**（reward hacking）がなかったか、結果が本当に良いかを確認し直すのに多くの時間を使っている（Nazmus 氏）。
- **公開ベンチマークの改善が、顧客の環境での性能向上に直結するとは限らない。** 最初は公開ベンチマークのヒルクライミング（点数を上げていく取り組み）が中心だったが、同じ性能が Microsoft Security の製品内の顧客には再現されなかった。最初のリリースではうまくいかなかったが、今は公開ベンチマークだけでなく、社内の製品利用状況も見て、顧客向けの解決策に合わせている（Ramya 氏）。
- 「**エンタープライズはベンチマークではない**」。

### 5.6 封じ込め（ゼロトラストの考え方）

Anthony 氏は、能力の高いサイバーセキュリティモデルを、「**内部脅威になり得るもの**」として扱う必要があると説明しました（Satya Nadella 氏のブログ記事で、この考えが述べられていたとのことです）。盲目的に信頼できるツールではなく、潜在的なリスクから守るための一連のセーフガードが必要だという考えです。MAI Cyber 2 Flash の訓練と評価で取った、ゼロトラストのアプローチは次のとおりです。

1. **封じ込め：** 強制できるルールとして、モデルにインターネットへのアクセスを与えない。ベンチマークの答えを調べないためと、インターネット上の何かと接触させないため。訓練中のサービスには、インターネットへの経路がない。
2. **構成の確認：** 設定したら終わり、ではない。大規模なマルチユーザーの訓練環境であるため、インフラに自分の状態を**証明（attest）させ**、その状態を**検証**する。構成が不正確、データが古い、条件がそろっていない場合は、訓練ジョブを実行しない。
3. **積極的な監視：** 挙動とログだけでなく、モデルの**思考の連鎖（chain of thought）** も見て、許可された挙動と、意図した進め方に従っているかを確認する。外れていれば、ジョブを**即時に終了**し、人間が完全にレビューして問題を修正するまで再開できない。

### 5.7 結果

Nazmus 氏が、リリースごとの結果を、特定のベンチマークの「ヒルクライム」の図で説明しました。この図は、「Cyber Jam E2E」（エンドツーエンド）と聞こえる、約 900 のタスクで脆弱性発見能力を測るベンチマークです（ベンチマーク名の綴りは、音声認識の都合で確定できません。後半では「CyberGym end-to-end」とも聞こえます）。

| リリース | 内容 |
| ---- | ---- |
| MAI Cyber 1 Flash（7 月） | 最初のリリース。M-dash 内で、より大きな他のモデルと組み合わせて使い、プレビュー顧客で十分な成果を出した。性能とコスト効率の組み合わせにより、**週のスキャンの 40% 超が MAI のモデルの組み合わせを使っている** |
| 1.1（10 月） | 同じ**アクティブパラメータ 50 億**のモデルサイズ。ソリューションの効率に注力し、性能をほぼ維持しながらトークン効率を高めた。M-dash の評価で **18% の改善**、性能もわずかに向上 |
| MAI Cyber 2 Flash（最新） | **アクティブパラメータ 120 億**の、より大きなモデル。**100 万トークンのコンテキストウィンドウ**（以前は 256K）。RL 環境のデータと訓練時間を増やした。CyberGym のエンドツーエンドで GPT-6 Astra（音声認識の都合で表記が確定できません）の性能に並び、上回りながら、**タスクあたりコストは 2% 未満** |

ほかに、次の結果が紹介されました。

- **実世界のコードでの成果：** 発表の前日に共有された、M-dash のフロンティア版のハーネスを作る **Forge** セキュリティ研究チームと、**GitHub Security Lab** の協力。M-dash と MAI Cyber 1.1 を使い、**6 つのオープンソースプロジェクトの 99 件の脆弱性**について、共有の修正を見つけた。そのプロジェクトの累計ダウンロードは月間 25 億回。モデル開発へのシグナルとしてだけでなく、業界のチームが使うソフトウェアそのものを改善することにもつなげている、という説明です。
- **脆弱性発見以外のタスク：** タスクの多様性を重視し、Cyber 2 の訓練では、「perception agents」（綴りは音声認識の都合で確定できません）にも注力した。ペンテストなどのレッドチーム的なタスクの能力を測るウェブエクスプロイトのベンチマークでも、「GPT-56 cyber」と聞こえるモデルと競合できる結果が出ている（モデル名は音声認識の都合で確定できません）。

### 5.8 コストと予算：セキュリティチームの現状

Nazmus 氏は、この 1 年のセキュリティチームからの声を、予算の締め付けを感じている状況だと紹介しました。AI による新しいリスクと、厳しい予算の上限があり、毎日のように警戒すべき脅威インテリジェンスのレポートが出て、新しいモデルが出て、取締役会や関係者も不安を持つ、という状況です。チームはエージェント型のソリューションを導入し、環境に合わせて素早く改善していますが、**エージェントのコストをどう予測し、財務部門とどう予算を組むか**が課題です。そこで、セキュリティモデルの設計目標は、高いベンチマークの点数ではなく、**費用対効果の高い保護**だと述べています。

業界の変化として、次の 3 点が挙げられました。

1. **モデルのアンサンブル：** 数か月前は 1 つの大きなモデルをすべてのタスクに使うこともあったが、現在はタスクに合った大きさのモデルを組み合わせる。MAI Cyber 1 を M-dash に入れた際も、小さいモデルと大きいモデルの混合だった。
2. **量より信号：** エージェント型のソリューションは、量よりも**シグナル**に焦点を移し、手動のトリアージを楽にし、取るべきアクションに近づく。
3. **コンポーザブルなエージェント：** 数か月前のエージェントは、1 つの大きなモノリシックなもので、長時間の実行では制御が難しかった。今後は、専用の評価を持つ小さなエージェントやサブエージェントを組み合わせ、マルチエージェントのワークフローにする形になる。「perception」のプレイブックはこのパターンの例で、性能とコストのバランスを取る方法として Microsoft 内外で見られる、とされています。

Nazmus 氏が示した単純な式は、「**セキュリティのカバレッジは、AI セキュリティのコストに反比例する**」というものです。タスクあたりのコストが下がれば、同じ予算でより多くのセキュリティタスクに AI を使えます。MAI Cyber のリリースごとに、タスクあたりのコストを最適化してきたとのことです。

### 5.9 Q&A

**Q1：利用が広がるにつれ、蒸留や悪意のある者によるアクセス・悪用を、どう防ぐか。**

回答の要点は次のとおりです（話者は特定できません）。

- 責任ある AI の取り組みの一環として、重大な課題として扱っている。M-dash を広く提供していない理由の 1 つも、正当な防御側だけにアクセスを限定するため。
- M-dash はサービスとして設計されており、**MAI Cyber のモデルへの直接アクセスは提供していない**。サービス側にもセーフガードを追加するため。
- 脆弱性を証明して正確なレポートを顧客に届ける作業は、エクスプロイトの構築と大きくは違わない。そのため、厳格な審査で正当な防御側だと確認した後でも、念のため、その環境へのアクセスは許可しない。
- M-dash は「箱の中の箱」のように、複数のコンテナで構成される。概念実証（PoC）は、1 つの箱の中で作られる。エクスプロイトの確かさや検証結果に関する情報は外に出るが、**実際のバイナリは箱から出ない**。権限のない者がサービスにアクセスしても、攻撃を進めるために使えない。

**Q2：将来の拡張性について。Sentinel を使っている既存の顧客に Perception の外へ広げることや、MSSP が独自のエージェントを開発できるようにすることは考えているか。**

回答の要点は次のとおりです。

- 意図的に一歩ずつ、短いサイクルと焦点を絞った目標で素早く反復する進め方をしている。Cyber 2 で M-dash の枠を超えて広げられるようになったことに期待していると述べ、次のように続けた。
- Cyber 2 の訓練は、perception のエージェントのうち 3〜4 つに絞った。エージェントごとに専用の RL gym を作るのに多くの時間を使い、より大きなモデルを使わなくても性能を上げられ、それがコストの低さにつながる。このアプローチを続ける。
- 現時点では、**Cyber のモデル系譜は M-dash と perception に集中し、それ以外には広げない**という考え。これはモデルについての話。
- カスタムのエージェントやプレイブックについては、ブースで同様のフィードバックを聞いている。特にプレイブックは、カスタムプレイブックに意味があるかもしれないと考え始めている段階。「どんなエージェントやプレイブックを作りたいか」を、ブースで知りたい。**現時点で製品にはないが、プレイブックは詳しく検討しており、カスタムエージェントは将来的な可能性として考えている。**

## 7. 注意点・発表者の気付き

- モデルは近道（不正）を探すため、能力が上がるほどガードレールの維持がエンジニアリング上の課題になります。評価のたびに、報酬ハッキングがなかったかを確認する必要があります。
- 公開ベンチマークの点数は、製品内の顧客環境での性能を保証しません。最初のリリースではこの点でうまくいかなかったと、率直に述べられました。
- サイバーセキュリティモデルは「内部脅威になり得るもの」として扱います。訓練環境はインターネットから遮断し、構成を証明・検証し、思考の連鎖まで監視します。
- 脆弱性の証明は、エクスプロイトの構築と変わらないため、M-dash はアクセスの審査を行い、モデルへの直接アクセスを提供せず、バイナリを箱の外に出さない設計になっています。
- M-dash は広く提供されておらず、プレビューへの申し込みが案内されています。
- カスタムエージェントやプレイブックは、現時点では製品にありません。

## 9. まとめ

MAI Cyber モデルは、セキュリティのために作られた専用モデルで、Microsoft の専門知識を反映し、安全性とセキュリティを後付けではなく最初から組み込んでいます。MAI Code Flash を親にして、セキュリティのデータと専門知識、強化学習で訓練し、7 月の Cyber 1 Flash、10 月の 1.1、そして発表前日の Cyber 2 Flash へと進化しました。最新モデルは 120 億のアクティブパラメータで、CyberGym のエンドツーエンドで GPT-6 Astra に並び上回りながら、タスクあたりのコストを 2% 未満に抑えたと説明されています。

訓練では、インターネット遮断、構成の証明と検証、思考の連鎖の監視という封じ込めを行い、モデルへのアクセスも制御しています。発表者は、ソリューションを使うチームにとって費用面の収支が合うようにすることを目指すと述べ、詳細は今週公開されたブログ記事と、M-dash のプレビューへの申し込みで確認できるとして、発表を締めくくりました。
