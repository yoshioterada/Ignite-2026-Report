# THR994 Trusting Your AI Workforce: Securing and Governing Enterprise Agents

## 1. はじめに

社内に 1 つでも、1,000 でも、10,000 でも、エージェントが増えたとき、私たちはそれらを把握し、安全に動かせているでしょうか。このセッションは約 25 分で、デモを中心に、Microsoft の 4 つの管理画面を順に見せながら、エージェントを「信頼できるエージェント」にするための考え方を示します。

発表者は、確認すべき疑問を 4 つ挙げています。エージェントは何を見て、何をできるのか（可視性）、どんな権限を持っているのか（権限）、過剰共有（オーバーシェアリング）は起きていないか、そしてエージェントは安全に動いているのか（安全性）です。デモでは、架空の会社 Bontoso（音声認識の都合で表記が確定できません）の人事エージェントを題材に、これらに答えていきます。

発表者は、ドアの例えも使っています。防犯用のドアやセキュリティドア（音声認識の都合で正確な語が確定できません）は、メーカーが鍵をかけるものではなく、自分のドアなので自分で鍵をかける、という趣旨です。

## 5. 発表内容の詳細

### 5.1 4 つの疑問

- **可視性**：エージェントは何を見て、何をできるのか。何個あるのか。
- **権限**：エージェントにはどんな権限があるか。権限は過剰か、不足か、適切か。責任者はいるか。最小権限の原則で展開されたか。
- **オーバーシェアリング**：多くの会社にあります。発表者は、技術的負債だと位置づけています。
- **安全性**：エージェントは安全か。何をしているか。

### 5.2 デモの前提：ユーザーとエージェントの ID は別

デモ環境の人事エージェントは、Teams で動き、ユーザーの代わりに操作もします。操作をする際、エージェントはまずユーザーに許可を確認します。ユーザーが同意すると、リストや SharePoint ライブラリのファイルに書き込みます。

ユーザーの Mickey は、SharePoint サイトと Bontoso HR ハブ（社内文書のリポジトリ）にアクセスできます。その中には機密性の高い文書があり、給与レンジと役職の一覧も含まれます。Mickey はこれらを直接開いて見られます。そして Mickey がエージェントに自分の給与レンジを尋ねると、エージェントは 2027 年の給与レンジ案を返します。

ユーザー視点では、Mickey は元々そのファイルにアクセスできるので、問題には見えません。しかし発表者は、エージェントとユーザーはそれぞれ別の ID を持ち、互いにあまり関係がないため、セキュリティ上は問題だと述べています。このエージェントを使える全員が給与レンジを見られてしまうからです。そこで IT 部門が対処し、翌日に Mickey が同じことを尋ねると、答えが変わりました。

### 5.3 視点 1：Entra（ID とアクセス）

Copilot Studio でエージェントを作ると、エージェント専用の Entra エージェント ID が付きます。メタデータでそれを確認できます。認証の設定は、Microsoft による認証（Entra ID 認証）で、Microsoft Teams、SharePoint、Power Apps、Microsoft 365 Copilot が対象です。エージェントの詳細には、実行するモデル、指示、ナレッジ（長年ある SharePoint ライブラリ。外部ユーザー以外の全員に共有されている）、ツールが示されます。発表者は、この過剰共有されたライブラリを技術的負債の例として挙げています。

Entra 管理センターでは、エージェント全体の概要、エージェント ID の一覧、統計とグラフが見られます。Bontoso の人事ヘルパーを開くと、次の情報が見られます。

- **ステータス**：有効（アクティブ）
- **スポンサー**：エージェントのライフサイクルに責任を持つ人です。ユーザーが退職してスポンサー ID が無くなった場合に何が起きるかも、ここで確認できると説明しています。
- オブジェクト ID、エージェント ID のアクセス許可
- 条件付きアクセスポリシーと、アクセスパッケージ（資格管理の一部）へのショートカット
- **サインインログ**：エージェント自身のサインインです。デモでは、画面を更新（F5）してから、過去 24 時間ではなく過去 7 日間のログを表示しています。

### 5.4 視点 2：Purview（データとコンプライアンス）

Mickey の回答が変わった理由は、IT 部門が「機密性の高い Copilot ポリシー」を作ったためでした。このポリシーの内容は次のとおりです。

- 適用先は、すでに適用済みで、Copilot Chat と Copilot Cowork です。
- SharePoint ライブラリ内の、機密・高機密などの文書が対象です。
- 条件は、Copilot がそれらのリソースにアクセスするなら、ブロックするというものです。

> 注意：Mickey は、SharePoint ライブラリへの権限を持っているため、直接文書を開くことはできます。ポリシーがブロックしたのは、Copilot とオーバーシェアリングによって、本来見るべきでない人にデータが表示されることです。

Purview で確認できる画面は次のとおりです。

1. **データ損失防止（DLP）のアラート**：ポリシーが働くとアラートが作られ、一致したポリシー、日付、ユーザー、場所、影響を受けた ID とエンティティ、ポリシーの詳細を確認できます。
2. **DSPM**：発表者は、従来の DSPM の 2 つの部分は廃止予定だと述べ、新しく「アプリとエージェント」が加わったと紹介しています。ここには、すべてのアプリとエージェントが並び、最近よく使われたエージェントの上位 20 件が出ます。発表者は Bontoso で絞り込み、リスク、ポリシー、配布、エージェントのアクセス先、ステータスと挙動を確認しています。
3. **アクティビティエクスプローラー**：エージェントの AI アクティビティを直接表示します。DLP ルールの一致、AI とのやり取り、機密情報の種類、カテゴリ、誰の代理で動いたか、ユーザー参加者、アプリケーション、エージェント、AI アプリがアクセスしたリソースが見られます。青い URL はクリックでき、アクセスされたリソースを確認できます。
4. **監査ログ**：最近実行した検索クエリの結果で、合計件数は 638 件でした。詳細には、アクセス元の IP アドレス、Copilot とエージェントのやり取り、使われたエージェントのブループリント ID、名前、ID、ワークロード、ユーザー ID、クライアント IP、メタデータ、アプリホスト、プラットフォーム ID があります。

### 5.5 視点 3：Defender（脅威対策）

発表者は、何かが起きないようにするだけでなく、起きたときに何が起きたかを見られる点が大切だと説明しています。使い始めるには、まず「エージェント保護」を有効にします。その後、Microsoft Defender はすべての AI エージェントのやり取りを表示し、エージェントの洞察を出します。

Bontoso HR ヘルパーのページを開くと、リスクと、防御の観点の詳細が見られます。バージョン、攻撃対象領域、起きたこと、あれば推奨事項、MCP サーバー、グラフなどです。

さらに高度な使い方として、ログは消えずに残り、クエリできます。

- **エージェント情報テーブル**：すべてのエージェントのインベントリと構成情報を持ちます。ID、プラットフォーム、所有者、メタデータを含みます。クエリのコメントでは、エージェントの姿勢の確認、リスクのあるエージェントや誤構成のエージェントの特定、エージェント ID とアラートやアクティビティとの突き合わせに使う、と説明されています。
- **高度なハンティング**：エージェントの実行結果や挙動を調べるための列とテーブルがあり、調査に使えます。

### 5.6 視点 4：Agent 365（Microsoft 365 管理センター）

Microsoft 365 管理センターの Agent 365 では、環境内のすべてのエージェントの一覧が見られます。Bontoso HR ヘルパーを開くと、可視性と保護、エージェントの詳細と概要、接続されているチャネル、アクセスできるもの、所有者、作成日、指示、ID の詳細、環境とプロパティが表示されます。さらに、ユーザーの一覧、データやツールに触れてよい人、読み取れる内容も見られます。

発表者は、IT 部門には、エージェントがどこにいて、何に触れ、何を見られ、誰が所有者かを把握する必要があると述べています。

### 5.7 条件付きアクセスと資格管理

Entra の条件付きアクセスは、現時点でエージェントを ID として対象にできます。ユーザーとグループの代わりに「エージェント ID を選択」し、個別のエージェント（デモでは Bontoso HR ヘルパー）をポリシーに指定できます。

また、資格管理を使っている場合は、エージェントをアクセスパッケージに含められます。これにより、エージェントがアクセスできる内容を期間で区切れます。発表者は、これらは今後さらに重要になると述べています。

### 5.8 まとめの視点とパラシュートの例え

4 つの視点は、Entra（ID とアクセス。エージェント ID、スポンサー、条件付きアクセス）、Purview（データとコンプライアンス）、Defender（脅威対策）、Copilot Studio（ガードレール）です。

お客様から「本当にこれが全部必要か」と聞かれることがあるそうです。発表者はパラシュートで答えます。飛行機から飛び降りるだけならパラシュートは要りません。ただし、もう一度飛びたいならパラシュートが必要です。ツールも同じで、必要かどうか迷うなら、使うほうが以前よりずっと安全になる、という考えです。

## 6. デモ・手順

このセッションにはデモがあります。ただし、画面の細部は音声からは確認できません。以下は、語られた順です。

1. Teams 上の人事エージェントを見せます。給与レンジや育児休暇の日数、事前申請の要否といった質問に答えます。申請の操作では、エージェントが許可を確認し、ユーザーが同意すると、リストや SharePoint のファイルに書き込みます。
2. ユーザー Mickey の視点で、SharePoint サイトと Bontoso HR ハブを開き、機密性の高い文書（給与レンジと役職）を直接開きます。
3. Mickey がエージェントに給与レンジを尋ねると、2027 年の給与レンジ案が返ります。
4. 翌日に Mickey が同じことを尋ねると、答えが変わっています。理由を探るため、Copilot Studio のエージェントを開きます。
5. Copilot Studio で、Entra エージェント ID、認証設定（Microsoft による認証）、モデル、指示、ナレッジ（SharePoint ライブラリ）、ツールを確認します。
6. Entra 管理センターで、エージェントの概要と ID の一覧を見て、Bontoso HR ヘルパーのステータス、スポンサー、オブジェクト ID、ショートカットを確認します。サインインログを、過去 24 時間から過去 7 日間に変えて表示します。
7. Purview で、機密性の高い Copilot ポリシーを開き、適用先（Copilot Chat と Copilot Cowork）と、アクセスがあればブロックする条件を確認します。
8. Purview の DLP アラート、DSPM の「アプリとエージェント」、アクティビティエクスプローラー、監査ログ（638 件）を順に確認します。
9. Defender で、エージェント保護を有効にしたうえで、Bontoso HR ヘルパーのページと、エージェント情報テーブルのクエリ結果を確認します。
10. Agent 365 で、エージェントの一覧と、Bontoso HR ヘルパーの詳細を確認します。
11. 最後に Entra の条件付きアクセスで、エージェント ID を指定する設定を示します。

## 7. 注意点・発表者の気付き

- **ユーザーの権限とエージェントの権限は別。** ユーザーが見られる文書を、そのエージェントを使うすべての人に見せてよいとは限りません。
- **過剰共有は技術的負債。** エージェントが生んだものではなく、以前からの慣行がエージェントによって表に出ただけです。
- **ポリシーの限界。** ブロックされるのは、Copilot とエージェント経由でのアクセスです。ユーザーが元の権限で直接文書を開けることは変わりません。
- **Defender はエージェント保護を有効にしてから。** 使い始めるときの前提として挙げられています。
- **DSPM の旧来の 2 つの部分は廃止予定。** 発表者はそう述べています。時期は発話では確認できません。
- **道具はあるが、使うのは自分たち。** 「ドアに鍵をかけるのは自分」という点を強調しています。

## 8. 利用者にとっての利点

発表者が挙げた利点は、次のとおりです。顧客事例と数値による成果は語られていません。

- エージェントの数が多くても、誰が責任者で、何にアクセスし、何をしたかを、Entra、Purview、Defender、Agent 365 で追える。
- 機密文書へのエージェント経由のアクセスを、ポリシーでブロックし、過剰共有によるデータ露出を抑えられる。
- 条件付きアクセスと資格管理で、エージェントの ID を個別に制御し、アクセスできる期間も区切れる。
- 発表者は総括として、可視性、ガバナンス、セキュリティの 3 つを挙げています。

## 9. まとめ

- 4 つの疑問（可視性、権限、オーバーシェアリング、安全性）に、4 つの視点（Entra、Purview、Defender、Copilot Studio）で答える内容でした。
- エージェントには専用の ID と責任者（スポンサー）があり、ユーザーの ID とは別に管理される。
- Purview のポリシーで、Copilot とエージェント経由の機密データ露出をブロックし、DLP アラート、DSPM、アクティビティエクスプローラー、監査ログで追跡できる。
- Defender と Agent 365 で、リスクの確認と、エージェントの一覧・詳細の確認ができる。
- 道具はすでにあり、使うかどうかが問われている。
