# THR992 Every agent is a principal now. Do you know what yours can reach?

## 1. はじめに

Copilot Studio でエージェントを公開すると、裏側の Microsoft Entra では何が起きているのでしょうか。このセッションは約 25 分の短い枠で、この疑問に答えます。発表者は、Copilot Studio でエージェントを 2 つ作り、Entra 管理センターと Agent 365 の管理画面で何が見えるかを、事前に録画したデモで順に見せています。

結論を先に書くと、エージェントの種類によって、エージェント ID が作られる時期と、「付与済みのアクセス許可」に表示される内容が異なります。さらに、エージェント ID が導入される前に作った古いエージェントには ID がなく、移行の方針を決める必要があります。セッションの最後には、会社に戻ってから確認すべきことが 4 点にまとめられています。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/THR992](https://ignite.microsoft.com/en-US/sessions/THR992)

## 3. 何に関する発表か

テーマは、Copilot Studio で作ったエージェントに付く ID と、その管理です。冒頭の問いかけは「エージェントを公開したとき、あなたは誰を雇ったのか」というものです。発表の流れは次のとおりです。

1. 導入とデモの予告
2. デモ：Copilot Studio で 2 種類のエージェントを作成し、Entra と Agent 365 で確認する
3. 覚えておきたい 3 つの用語（ブループリント、コネクタースコープ、条件付きアクセス）
4. 2 種類のエージェントの違いのまとめ
5. 誰がどの部分を担当するか（メーカー、Power Platform 管理者、ID・セキュリティチーム、グローバル管理者）
6. これまでに作ったエージェント（ID を持たない古いエージェント）の扱い
7. 前日のセッションで紹介されたエージェントアカウントへの言及
8. 職場に戻ってからの 4 つの行動

## 4. 発表者が伝えたいメッセージ

発表者の主張は、「エージェントを作る人（メーカー）だけでなく、ID・セキュリティ・管理を担う人たちが連携して初めて、エージェントを安全に運用できる」ということです。エージェントが人のようにテナントで動くなら、人と同じように ID が必要になる、という考えがその前提にあります。

また、どの権限が付与されているかを「知っている」ことが第一歩だと繰り返しています。メーカーが付与した権限をメーカー自身が把握し、問題があれば管理者に相談できる状態を作ることが大切だという立場です。

## 5. 発表内容の詳細

### 5.1 デモの全体像

発表者は、デモが 3 段階で進むと説明しています。

- Copilot Studio で 2 つのエージェントを作る。1 つは Copilot ハーネス（以前は GitHub Copilot ハーネスと呼ばれていたもの）で作るオンボーディングバディ、もう 1 つは標準ハーネスで作る経費デスクエージェントです。
- Entra に切り替え、ID、ブループリント、スポンサー、所有者、付与されたアクセス許可を確認する。Azure ポータルの Entra でも Entra 管理センターでも、同じ機能が使えると説明しています。
- グローバル管理センター（発話では global admin center）に切り替え、Agent 365 のエージェントインベントリ（一覧）を確認する。

発表者は、25 分では短いので、すべてのデモを事前に録画してあると述べています。待ち時間が長い場面があるのは、録画のためです。

### 5.2 Entra で見られるものと 3 つの用語

Entra には「エージェント」のメニューがあり、ブループリントとエージェント ID が一覧で見られます。ID の詳細ページでは、スポンサー、ブループリント、所有者、付与されたアクセス許可、アクティビティを確認できます。

- **ブループリント**：エージェント ID を作るためのテンプレートです。Copilot Studio で作ったエージェントは、すべて同じブループリントを使います。Copilot Studio 製のエージェント全体に適用したいポリシーなどは、ブループリントに設定するとよいと説明しています。すべてのエージェントがその設定を継承するためです。
- **コネクタースコープ**：「付与されたアクセス許可」に表示される、エージェントが実行したい操作の権限です。
- **条件付きアクセス**：Entra のルールエンジンです。リスクのある操作をブロックするために使います。従業員向けの条件付きアクセスポリシーと同じように、エージェントにも設定できると述べています。Azure ポータル側でも Entra 管理センター側でも可能です。

### 5.3 2 種類のエージェントの違い

デモの結果から、発表者は次の違いをまとめています。

| 項目 | Copilot ハーネスのエージェント | 標準ハーネスのエージェント |
|---|---|---|
| エージェント ID が作られる時期 | エージェントの公開時 | エージェントの作成時（下書きの時点） |
| 付与されたアクセス許可の表示 | 現時点では何も表示されない | 表示される。ただし全部ではない |
| Agent 365 の一覧でのアイコン | 設定したアイコンが表示された | 設定したアイコンが表示されなかった |

付与されたアクセス許可については、カスタムコネクタや MCP サービスのツールをエージェントに登録しても、現時点では表示されないと説明しています。これが変わることを望んでいるが、将来どうなるかは分からないとも述べています。この制約はドキュメントにも書かれているものの、ドキュメントと実際の挙動が異なることもあるため注意が必要だという趣旨です。

### 5.4 誰が何を担当するか

発表者は「どの扉を誰が持っているか」という言い方で、役割を整理しています。

- **メーカー**（エージェントを作る人）：Copilot Studio を使い、管理の細部を知らないことがあります。データポリシーについては Power Platform 管理者と、特別な権限が必要な場合は ID・セキュリティチームと話す必要があります。
- **Microsoft 365 のグローバル管理者**：Agent 365 の担当です。エージェントマップを使うこともあります。エージェントマップは、エージェントとそのツールの動きや、リスクのある操作をグラフィカルに見せる画面です。

これらの人たちが協力して初めて、社内でエージェントを作り、安全に運用できると述べています。

### 5.5 これまでに作ったエージェントの扱い

エージェント ID の導入前に作った古いエージェントを、発表者は「オンボーディングボット」を例に説明しています。このエージェントにはエージェント ID がありませんが、エンタープライズアプリケーションとして見つかります。ただし次の問題があります。

- ブループリントがない
- スポンサーがない
- コネクタースコープがない
- 条件付きアクセスを設定できない

そのため、ガバナンスの面では扱いにくくなります。対応は次の 3 つの選択肢です。

1. **作り直す**：非常に複雑なエージェントで、今なら同じ作り方をしない場合に向いています。ただし作業量は多くなります。
2. **移行する**：現時点ではプレビューで、その場で移行（インプレース移行）する形です。うまくいかなければ、結局作り直しになる可能性があります。
3. **待つ**：いずれ Microsoft が移行してくれるものの、時期は分かりません。問題が起きたときに、ユーザーがエージェントを使えなくなったり、セキュリティ上の不具合が出たりすれば、すぐに対応しなければなりません。

発表者は、すべてに通用する答えはなく、利用者数、作り方、複雑さによって決まると述べています。

### 5.6 前日のセッションとエージェントアカウント

発表者は、前日に行われた別のセッションで紹介された内容として、エージェントアカウントに触れています。エージェントは操作の実行だけでなく、自分のメールボックスを持ち、Teams のプレゼンスも持てて、人のように働けるとのことです。エージェントが人のようにテナントで動くなら、エージェント ID が重要になると説明しています。このセッションは Ignite のオンデマンドで視聴できます。条件付きアクセスの手段が増え、Agent 365 の機能も増えるので確認すべきで、将来は Entra 自体にも機能が増えてほしいと述べています。

### 5.7 職場に戻ってからの 4 つの行動

発表者は「月曜日に職場に戻ったら」として、次を勧めています。

1. Entra の「エージェント」と「エージェント ID」を確認し、付与されたアクセス許可（API のアクセス許可）を見る。
2. データポリシーを確認し、エージェントとどう関係しているかを見る。必要なら、セキュリティ上の観点で変更する。
3. エンタープライズアプリケーションの中から、「agent created by Copilot Studio」（Copilot Studio で作成されたエージェント、の意）というタグのものを探し、まず何件あるかを数える（タグの綴りは、音声認識の都合で表記が確定できません）。
4. 見つかったエージェントごとに、作り直す・移行する・待つのどれにするかを決める。

## 6. デモ・手順

このセッションにはデモがあります。ただし、発表者は事前に録画した映像で見せており、画面の細部は音声からは確認できません。以下は、語られた順に整理したものです。

### 6.1 オンボーディングバディ（Copilot ハーネス）の作成

1. Copilot Studio で、過去に作ったエージェントの一覧が表示された状態から、Copilot ハーネスを使う新規エージェントを作成します。
2. 名前は「オンボーディングバディ」です。質問に答えるだけでなく、操作も実行させたいため、ボットやエージェントではなく「バディ」と呼んでいます。
3. 指示は、ナレッジとツールを使うという、もう 1 つのエージェントとほぼ同じ内容です。
4. ビジネス上の ID として、名前、説明、アイコンを設定します。
5. 右側のペインでチャネルを設定します。Copilot と Teams で使う設定です。
6. ナレッジとして、事前に用意した Word 文書を追加します。SharePoint の文書や公開 Web サイトなど、他のソースも追加できると補足しています。
7. ツールとして、`get my profile`アクションと`get calendar view of events`アクションを追加します。後者は、オンボーディング用の会議が予定に入っているかを確認するためのものです。
8. 保存後、Azure ポータルの Entra の「エージェント」メニューでエージェント ID を確認します。新しい順に並べて更新しましたが、この時点ではエージェント ID は存在しませんでした。

### 6.2 経費デスクエージェント（標準ハーネス）の作成

1. Copilot Studio のホームページで、3 つ目の選択肢（少し見つけにくい場所にあると説明）から作成します。
2. 先に名前を付けてエージェントを作成すると、その後で設定を進める形です。作成には時間がかかります。
3. UI は Copilot ハーネスの場合と異なり、右側に設定用のペインはありません。設定はタブで行い、右側にはテストペインがあります。
4. 名前、説明、アイコンを設定します。2 つのエージェントが関連して見えるように、似たアイコンを用意しています。この画面ではドラッグ＆ドロップができず、エクスプローラーからアイコンを選んでいます。
5. 指示は、経費を扱うエージェントという点で内容は異なりますが、形式は同様です。
6. ナレッジとして、別の Word 文書を追加します。この UI では、文書が処理中であることを示すステータスが表示されると説明しています。Copilot ハーネスの画面では、この表示はありませんでした。
7. 比較のため、同じ 2 つのツールを追加します。`get my profile`を検索して選ぶと、選択を確認する画面になり、確認後に設定画面に移ります。ツールの名前と説明を、ビジネスの観点でよく考えるよう促す画面だと述べています。ツールが複数あるとき、名前と説明が適切なら、エージェントが使い分けやすくなり、指示に多くを書かなくて済むためです。
8. 2 つ目のツールとして、Outlook 365 コネクタの`get calendar view of events`を追加します。
9. 設定の途中でタブが切り替わるため、全体を見るには概要タブに戻ります。チャネルの設定を忘れていたことにも気づきますが、別のタブにあります。
10. Entra に切り替えると、並び順を変えて確認した結果、標準ハーネスのエージェントには、下書きの時点ですでにエージェント ID が作られていました。オンボーディングバディには ID がありません。

### 6.3 エージェント ID の詳細確認と公開

1. 標準ハーネスのエージェント ID を開き、詳細ページを確認します。自分がスポンサーとして表示されています。エージェントを作った人であり、ライフサイクルに責任を持つ立場だからです。
2. ブループリントの表示があります。Copilot Studio で作ったエージェントは、すべて同じブループリントを使います。
3. 「所有者とスポンサー」では、他のスポンサーを所有者として設定できます。ガバナンスの観点で興味深く、社内ルール次第で使えると述べています。
4. 「付与されたアクセス許可」はこの時点では空で、アクティビティもほぼ空です。エージェントが展開され、従業員に使われるようになると、情報が増えると説明しています。
5. 両方のエージェントを公開します。先に経費デスクエージェントを公開しましたが、順序に意味はないと述べています。公開はバックグラウンドで処理され、確認のダイアログが表示されます。オンボーディングバディのほうは、公開ボタンが押せる状態になるまで待つ必要があり、クラウドの状況しだいで時間がかかると説明しています。確認のダイアログには、選択されたチャネルと、公開が処理中であることが示されます。
6. 概要画面で、両方のステータスが「公開済み」になったことを確認します。
7. Entra を更新すると、エージェント ID が 2 つになっています。オンボーディングバディの ID は公開後に作られたものです。概要ページは同じで、付与されたアクセス許可は空でした。発表者はツールが 2 つ表示されると予想していたと述べています。
8. 経費デスクエージェントでは、公開前はアクセス許可が 0 件でしたが、公開後に 1 件表示されました。ツールが 2 つなのに 1 件だけなのは、どちらも Microsoft 365 の中核アクションに属するためです。サードパーティのコネクタを使うと、複数の項目が表示されます。
9. 発表者は、これらをブロックするか、ポリシーを作るかは管理者の判断だと述べています。大切なのは、メーカーを通じてどの権限が付与されているかを把握することです。

### 6.4 Entra 管理センターでの確認

1. Azure ポータルから Entra 管理センターに切り替えます。左のナビゲーションを開いたため表示領域は少し狭くなりますが、画面はほぼ同じです。
2. 「エージェント」メニューにブループリントとエージェント ID があり、ID を開くと同じ情報と同じ操作が使えます。
3. 条件付きアクセスポリシーを、従業員向けと同様にエージェントにも設定できます。

### 6.5 Agent 365 での確認

1. グローバル管理センターから Agent 365 を開き、エージェントの概要の「すべてのエージェント」を表示します。
2. オンボーディングバディと経費デスクエージェントが表示されます。Copilot ハーネスのエージェントにはアイコンがあり、標準ハーネスのエージェントには設定したアイコンがありません。この違いを、発表者は「面白い」と述べています。
3. どちらのエージェントでも、クリックすると詳細ペインが開き、エージェント ID を含む情報が見られます。管理者は Copilot Studio に入らなくても、ナレッジ、指示、ツールを確認できます。ツールについては、API の呼び出しが見られる点が気に入っていると述べています。
4. セキュリティタブでは、機密性の高いやり取りに関するエージェントのアクティビティを見られます。これは Purview の部分です。必要なら Entra に戻って詳細を確認することもできます。

## 7. 注意点・発表者の気付き

- **付与されたアクセス許可の表示には限界があります。** Copilot ハーネスのエージェントは何も表示されません。標準ハーネスのエージェントも、カスタムコネクタや、MCP サービスで登録したツールは表示されません。ドキュメントには書かれていますが、知識が食い違っていることもあるため注意が必要だと述べています。
- **Microsoft 365 のコネクタは 1 項目にまとまります。** 中核アクションのコネクタをいくつ使っても、1 件しか表示されません。そのため、何をブロックして何をブロックしないかを考える必要があります。サードパーティのコネクタは、複数の項目が表示されます。
- **エージェント ID の作成時期が異なります。** 標準ハーネスは作成時、Copilot ハーネスは公開時です。
- **古いエージェントのガバナンスは弱くなります。** ブループリント、スポンサー、コネクタースコープがなく、条件付きアクセスも設定できません。
- **発表者の希望：** 付与されたアクセス許可の表示が改善されること、Entra に機能が増えることを望むと述べています。これらは希望であり、予定として語られたものではありません。
- **現在の提供状況：** 古いエージェントの移行機能はプレビューです。「待つ」場合に Microsoft が移行する時期は示されていません。

## 8. 利用者にとっての利点

このセッションでは、顧客事例や、効果を示す数値は語られていません。発表で語られた利点は次のとおりです。

- Entra で、エージェントのスポンサー、ブループリント、付与されたアクセス許可、アクティビティを確認できる。
- 従業員と同様に、条件付きアクセスでエージェントのリスクのある操作をブロックできる。
- Agent 365 から、管理者が Copilot Studio に入らなくても、エージェントのナレッジ、指示、ツール、API 呼び出しを確認できる。
- ブループリントにポリシーを設定すれば、Copilot Studio 製のすべてのエージェントに適用できる。

## 9. まとめ

- Copilot Studio のエージェントには、Entra でエージェント ID が作られる。作成時期は、標準ハーネスが作成時、Copilot ハーネスが公開時である。
- 押さえるべき用語は、ブループリント、コネクタースコープ、条件付きアクセスの 3 つである。
- 付与されたアクセス許可の表示は現時点で不完全であり、メーカー、Power Platform 管理者、ID・セキュリティチーム、グローバル管理者が連携する必要がある。
- ID を持たない古いエージェントは、作り直す、移行する（プレビュー）、待つのいずれかを、エージェントごとに決める。
- 職場に戻ったら、Entra のエージェント ID とアクセス許可、データポリシー、エンタープライズアプリケーションのタグ付きエージェントの件数と対応方針を確認する。
