# BRK493 Expanding the partner opportunity with Microsoft Agent 365​

## 1. はじめに

このセッションは、Microsoft のパートナー企業（セキュリティ、コンサルティング、マネージドサービスを提供する会社）に向けて、Agent 365 を軸にした新しいサービス機会を解説する約 45 分のブレークアウトです。前半は Microsoft の担当者が、顧客が直面している課題、Agent 365 の 4 つの柱、パートナーの収益構造の変化を説明します。中盤では Capgemini と Protiviti の 2 人がパネル形式で実践経験を語り、後半では Microsoft がパートナー向けに用意した学習・販売支援の資料を紹介します。

結論を先に言うと、発表の中心は「エージェントを作れるか」ではなく「エージェントを自信を持って運用できるか」への問いの変化です。そしてその運用を、助言から実装、ライフサイクル管理、検証、マネージドサービスまで続く継続的な事業としてパートナーが担える、という主張です。

テーマは、エージェントが業務を実行する時代に、顧客が自分の環境で動くエージェントを把握・統制できるようにする仕組み（Agent 365）と、それを支援するパートナーの事業機会です。

発表の流れは次のとおりです。

1. 顧客の状況の変化：AI の利用から、エージェントの管理へ
2. Agent 365 の位置づけ：エージェントのためのコントロールプレーンから、AI 全体の可観測性プラットフォームへ
3. パートナー収益の変化とサービス領域（Microsoft 365 E7 を含む）
4. パートナー 2 社（Capgemini、Protiviti）によるパネルディスカッション

1. **顧客の問いが変わった。** エージェントを作れるかではなく、大規模に自信を持って運用できるかが問われています。

3. **信頼の土台は共有された可観測性です。** CIO、CISO、事業責任者が同じ信号を、それぞれの視点で見られることが重要だとしています。

## 5. 発表内容の詳細

### 5.1 導入：顧客はエージェントの実態を答えられるか

冒頭で司会が会場に挙手を求めました。まず、すでにエージェントを動かしている顧客がいる人。次に、その顧客が次の 3 点に答えられる人です。

- エージェントが何体あるか
- そのエージェントが何にアクセスできるか
- エージェントが誤った場合に誰が責任を負うか

手が挙がったのは最後に 1 人程度でした。司会は、多くの顧客では誰も完全には答えられないと述べています。新入社員にはバッジ、計画、上長が定めたアクセス権、業績評価がありますが、エージェントにはそれらがほとんど与えられていないという対比も示されました。

### 5.2 顧客の会話の変化：AI を使う段階から、管理する段階へ

ここ数年、顧客は「1 人が 1 つのプロンプトを入力し、1 つの答えを得て、成果がその人の中に留まる」形で AI を使ってきました。現在は、エージェントが複数手順の作業を実行し、ツールを呼び出し、他のエージェントに引き継ぎ、事業の代理として行動する段階にあります。

AI が質問に答えるだけでなく行動するようになった時点で、その行動の責任者が必要になります。司会はこれを「新機能ではなく新しい運用モデル」と表現しました。なお、司会は今回の資料作成に自分でもエージェントを使い、結果は確認したと述べています。

顧客がまだ答えられない問いとして、次が挙げられました。

- 自分の環境で何が動いているか
- それは何にアクセスしようとしているか
- 各アクションに実際いくらかかっているか

Microsoft の営業現場からの助言として、顧客の前でここで立ち止まり、「このうち今日答えられるものはどれか、その答えは誰が持っているか」と尋ねることが紹介されました。多くの場合、会場は静まるとのことで、その沈黙がパートナーの出番だと説明されています。答えがないままでは、エージェントの導入はスプロール（無秩序な増加）、管理されていないアクセス、運用リスクになり、生産性の向上も消えてしまうという主張です。

### 5.3 エージェントは複数の層でできている

エージェントは単独の存在ではなく、アプリ上で動き、モデルを呼び出し、データに接地され、MCP サーバー、プラグイン、コネクタなどのツールを使います。リスクとコストはどの層にも現れ、積み重なります。例として次が挙げられました。

- 従業員がノート PC にインストールしたエージェントは、ローカルのファイルに到達できる
- クラウド上のエージェントは、SaaS のデータに触れるツールを呼び出せる

そのため、エージェントが存在することを見るだけでは足りず、顧客はすべての層を見る必要があると説明されています。

### 5.4 基調講演との接続：信頼の柱

司会は同日の基調講演に触れました。Satya Nadella 氏は「人間の意欲」「インテリジェンス」「信頼」の 3 本柱を語ったとされ、司会は「業務の流れの中の AI は、背後のインテリジェンスの質で決まり、信頼なしにはどちらも拡大しない」という趣旨の言葉を強調しました。基調講演で Nadella 氏は、この新しい技術をどう信頼するかと問い、「信頼できない。だからインテリジェンスの供給と、その権限を切り離す必要がある」と答えたとのことです。このセッションは、その信頼の柱に位置づけられます。信頼は、実際に何が起きているかを見ることから始まるという流れです。

### 5.5 3 人の購買担当者と共有可観測性

1 つの AI 環境に対して、立場ごとに必要な情報は異なります。

| 立場 | 知りたいこと |
|---|---|
| CIO | どのエージェントが動いていて、誰が所有しているか |
| CISO | 侵害されたもの、またはデータを過剰共有しているものがないか |
| 事業責任者 | どのような価値を届けているか |

つまり 3 種類の購買担当者、3 つの予算、アカウントへの 3 つの入り口があるということです。3 者が同じ信号を、それぞれの視点で使うと、互いを遅らせずに一緒に前進できます。この理由で、共有された可観測性が信頼の基盤だと述べられました。

### 5.6 Agent 365 の位置づけと 4 つの柱

Agent 365 は昨年、エージェントのコントロールプレーンとして紹介されました。今年はそれを広げ、AI のための可観測性プラットフォームとして、各責任者が普段使っているツールの中で同じ視点を共有できる形になったと説明されています。原則は「エージェントを、ユーザー、アプリ、デバイスと同じ厳密さで管理する」ことです。

4 つの柱は次のとおりです。

1. **管理（Management）**：AI 環境全体を 1 つの視点で見る
2. **ガバナンス（Governance）**：明確な所有者、権限、説明責任
3. **セキュリティ（Security）**：リスクを把握し、統制を適用し、エージェントを守る
4. **ビジネス価値（Business value）**：支出を最適化し、投資対効果を高める。今週何度も触れられている新しい柱で、新たに発表された Agent 365 のビジネス分析アプリ（business analytics app）で扱われる

各柱は積み上がる関係にあります。見えないものは統制できず、統制できないものの価値は証明できない、という説明です。

### 5.7 数値：すでに始まっている現実

- IDC は 2028 年までに 13 億のエージェントが稼働すると予測している（パートナーには既によく知られた数字と紹介）
- Agent 365 は 5 月に一般提供（GA）された
- 顧客はすでに 5,000 万を超えるエージェントを登録した
- 顧客は Purview で 76 億を超えるエージェントのアクティビティを監査した

ただし、エージェントが増えても価値が自動的に増えるわけではありません。多くの顧客ではツールの断片化、データの分断、セキュリティアプリの乱立、あちこちでのパイロットとなります。勝つのは最多のエージェントを持つ顧客ではなく、持っているエージェントを見て、統制し、信頼できる顧客だと述べられました。そして、顧客は自力ではそこに到達できず、準備状況の評価、統制の実装、導入の推進、継続サービスとしてのガバナンス運用を誰かが担う必要があり、それは製品ではなくパートナーだという主張です。

### 5.8 パートナー収益の変化と 5 つのフロンティア サービス領域

パートナーの収益構造について、次の数値が示されました。

- アドバイザリー（助言）は最も急成長しているパートナー サービスで、35% 増。顧客は購入を決める前に何をすべきかの支援を求めている
- 2028 年までに、継続的収益はパートナーの平均的な収益の半分近くになる見込み
- SME&C の顧客では、マネージドサービスが 60〜80% のケースで発生している

価値は、先に助言、後に継続サービスへ移っているという整理です。Agent 365 はその変化の真ん中にあります。

直前のセッション（497）で紹介された 5 つのフロンティア サービス領域は、顧客の引きが強く、パートナーが投資している分野に基づきます。

1. AI アドバイザリー
2. セキュア / ガバナンス / デプロイ
3. エージェント型トランスフォーメーション
4. AI のための FinOps
5. 導入定着の推進（使われなければ何も報われないため）

これらすべての土台として、AI Center of Excellence（卓越した拠点）を継続的なマネージドサービスとして置きます。Agent 365 はこの図のすべての枠に関わるとされました。

詳細スライドでは 2 点が指摘されました。

- 右上の赤枠は、エージェントのセキュリティとガバナンスの新しい機会。レジストリとアクセス、脅威対策とランタイム、エージェントのデータセキュリティとコンプライアンス、相互運用性が含まれ、セキュリティ パートナーの得意分野だと説明
- その下は、エージェントの構築と管理。再利用できるエージェントの知的資産、エージェント ファクトリーと COE、エージェントのマネージドサービスが拡大している

Microsoft 365 E7 は、これらを束ねる商用の手段と位置づけられました。

パートナーの動きとして、Forrester の最新調査から 2 つの声が紹介されました。

- あるシステムインテグレーターは、E7 を近年で最も魅力的な Microsoft のライセンス パッケージの 1 つと呼んでいる。大規模なエージェント展開に必要なガバナンスと ID の作業に、顧客がすぐ着手できるため
- あるセキュリティ サービス プロバイダーは段階的に進めている。デプロイ サービスは今すぐ提供を開始し、マネージドサービスは今後構築する

また、Gartner が Microsoft を、AI エージェント管理プラットフォームに関する初の Magic Quadrant でリーダーに選んだことも紹介されました。

4 つの柱をサービスラインとして見ると、管理は「発見と評価」「デプロイと統合」「マネージドサービスまたはエージェント オペレーション」と続きます。ガバナンスなど他の柱にも同じパターンがあり、すべてが評価で始まり、継続またはマネージドサービスで終わる、つまりライフサイクル型の事業だと説明されています。

### 5.9 パネルディスカッション

司会は、セキュリティは作り直すものではなく、新しい人口（デジタルワーカー）に拡張するものだと述べ、2 つの視点を持つ登壇者を紹介しました。Mona Gadiri 氏は Capgemini で、エージェント型 SOC サービスとマネージド オペレーションを世界規模で構築しています。Antonio Maio 氏は Protiviti で技術コンサルティングを率い、リスク、ガバナンス、運用モデルから会話を始めます。

**自己紹介**

- Mona 氏：約 2 年前に、SOC と製品ポートフォリオを、次の波の Microsoft セキュリティ技術に対応させるために採用された
- Antonio 氏：Protiviti は 25 か国に 90 のオフィスを持つグローバルなコンサルティング会社で、Microsoft の実践部門が世界規模で大きい

**質問 1：パートナーにとって最大の機会はどこか**

Mona 氏は、セキュリティの実践部門をすでに始めている、あるいは始めるなら今ほど良い時期はないと述べました。サイバーセキュリティに取り組む人が足りていないこと、Microsoft の実践部門があればゼロからの出発ではないことが理由です。機会は 1 つのセキュリティ運用やマネージドサービスにとどまらず、ライフサイクル全体にあります。ガバナンスされた信頼できる企業は初日だけでは成立せず、ライフサイクル全体を通じて実現するという考えです。

Antonio 氏は、機会はセキュリティを大きく超えると述べました。最大の機会は、顧客をエージェントの実験やパイロットから、信頼できる企業規模の導入へ移すことで、強調点は「信頼できる」です。Agent 365 は可観測性とコントロールの基盤を与えますが、顧客にはエージェントの運用モデル、つまり組織全体でエージェントを継続的にどう使うかの確立が必要です。それにはガバナンス、ID、セキュリティ、データ保護、事業のレジリエンス、変更管理などが含まれます。

**質問 2：セキュリティ、AI ワークフォース、データの実践部門をどう進化させているか**

Antonio 氏は、エージェントは従来の実践部門の壁を取り払うと述べました。エージェントは ID を持ち、データにアクセスし、モダンワークプレースの中で動き、保護すべき機密データを扱うためです。Agent 365 を軸にした実践部門を作るとき、新しい独立部門を作るより、既存の部門が持つ能力を集めることが重要だとし、特定の取り組みのために固有のスキルを持つ人を集める「ポッド」という編成を紹介しました。技術をデプロイするだけでなく、顧客がエージェント エコシステムを運用・統制できるよう支援する視点に切り替える必要があり、この多分野の編成が最も良いと述べています。

Mona 氏は、Capgemini では同様の編成を「タイガーチーム」と呼ぶと述べました。バスケットボールのチームにポイントガードが 6 人いても成り立たないのと同じで、同じ考え方の人だけを集めても違う結果は出ません。多様な考え方の人を選ぶ必要があり、Capgemini 全体としては「ワン Capgemini」の考えで、自分の得意分野を認識し、足りない部分を補う仲間をチームに置く、という説明でした。

**質問 3：チームや専門性を結びつける際の課題と教訓**

司会は、Microsoft 自身もソリューション領域の境界をまたぐ場面で、階層や縦割りに苦労していると述べて質問しました。

Mona 氏は、ロゼッタストーンのたとえで、共通言語の重要性を説明しました。例えば「ワークロード ID」と言っても、SOC の担当者にはそれが何か伝わりません。SOC の担当者は攻撃の深刻度、他者が何をしたか、その ID が誰に関連づくかを気にするためです。新しい辞書を作り、実務者と話すときの言葉を変える勇気を持つことを勧めています。共有された言葉と定義がなければ、互いに話が通じず、新しいコミュニティ、文化、価値観も作れないという考えです。

Antonio 氏は、多分野の人々の間で簡潔かつ一貫して伝え、同じ方向に進むことが 1 つ目の鍵だとしました。もう 1 つは、エージェントのライフサイクル管理です。顧客の案件でこれを扱うと顧客とのライフサイクルでの関係が生まれ、技術のデプロイから、エージェントの長期的な運用と統制へ実践部門が進化します。自然にアプリケーション ライフサイクル型のモデルとマネージドサービスにつながります。課題は、多分野のチームで顧客要件に応えたうえで、それを顧客への継続的なマネージドサービスに発展させる点で、これは一種の転換だと述べました。

**質問 4：営業組織をどう支援しているか**

Mona 氏の助言は 2 つです。

1. 人を減らす話をしないこと。エージェントが何かをしても人がいなくなるわけではありません。人は不安を感じているため、共感から入ります。「仕事の嫌な部分をしなくてよいなら、何に創造性を使いたいか」「時間の 3 分の 1 が空いたら何をするか」と問うのが良い出発点です。
2. 成果に錨を置くこと。成果とは、フロー、信頼性、品質などで、AI エージェントを使うかどうかに関係なく賛同できるものです。そこから「どうやるか」を少しずつ剥がしていき、その中にエージェントが含まれるようにすると受け入れやすくなります。人は安心すると創造的になり、創造的になると新しいイノベーションが生まれます。「労務費を 40% 削減しに来た」という話は人を動かさない、とも述べています。

Antonio 氏は、イノベーションに対して開かれていること、技術が急速に変わるので方向転換できることを挙げました。顧客へのデモの最中に、Microsoft の技術が変わることもあるとの経験談もありました。

続けて、パネリストの一人が、エージェントやコードに愛着を持たないことを勧めました。コードは明日消え、週末に作り直したものの方が良くなる。「これが唯一の方法だ」と思い込むと手放せなくなる。イノベーションの時代には、エージェントを含めて捨てる覚悟が必要で、作り直しにもう 9 か月はかからないという説明です。

**エージェントのライフサイクルとゲート**

司会は、冒頭の「従業員を採用する」比喩に戻り、エージェントにも退職（オフボーディング）や変更管理のプロセスが必要になるのかと問いました。パネリストの一人は、エージェントに成人儀礼のような節目を設けたいと冗談を交え、7 歳の子どもを一人で道路を渡らせないが、背が足り、左右を確認でき、自分で歯を磨き着替えられるなら考える、という例で「ゲート」が必要だと説明しました。司会は、これがデプロイ、監視、保証、最適化、最終的な廃止までを通過するゲートというライフサイクルの話だと整理しています。

その後のやり取りの要点は次のとおりです。

- 廃止を恐れない。ソフトウェアにバージョンがあるように、エージェントにもバージョンを持たせ、名前を付けられる
- エージェントのライフサイクルはまだ発展途上で、近く多くが出てほしいと述べられた（発表の場では、具体的な製品計画は示されていません）
- 隔離リスト、全社員に公開、財務部門だけに公開、といったゲートは同じ考え方で、1 人にうまくいっても全部門にうまくいくとは限らない
- パネリストの一人の意見として、ロードマップはもう作らず、仮説を立てて検証することが仕事になる。6 か月後を想定するロードマップは人工物で、次の週すら予想できないが、仮説なら検証でき、失敗しても学びがあれば次はより良いものが作れる、という「ホットテイク」が語られた

**質問 5：アドバイザリーや実装から、継続的なマネージドサービスへの進化**

Mona 氏は、次の考えを述べました。

- 自律的であることよりも、「自律的であることを、そうでなくなるまで許す」ことが好ましい。出発点は、可能なものではなく、してはいけないものにするのが最も安全で効果的
- 「してはいけない」条件をすべて洗い出して外すと、それ以外は速く進められる。自律型を拒む理由は、すべてのユースケースをカバーできるかが分からない点にある
- その「してはいけない条件」をゲートとして、マネージドサービスにできるものとできないものを決めれば、大きな機会が残る。顧客が自律化の準備ができていないと言っても、将来できないとは限らず、証明すべきことがあるだけ
- デプロイの先にある「第 2 日」（導入後に起きること）では、何をマネージドサービスにするかが重要になる。マネージドサービスの定義そのものを見直す機会で、セキュリティ、ライフサイクル、ドリフト分析のための突き合わせ、ロジックの再点検、エージェントが下した直近 50 件の判断を人が精査するレビューなどが例として挙げられた
- SOC が単にアラートを見るだけだった世界から、AI がアラートを見るなら、その運用を信頼できるかを裏付けるレビューサービスを売れる。AI と検知の背後に置くマネージドサービスは「検証をサービスとして」売ることになり、顧客はそれを切望している。今日のエージェントの発言が明日も同じとは限らず、今日のリスクも明日とは違うため、起きたことが起きたとおりだと検証する機会が必要になる
- 構築や最適化だけでなく検証に注力する。適切に動いていると検証できるパートナーが、誰もが求める「緑のダッシュボード」を提供できる。何か見つけたとしても仕事をしただけで、それが価値になる

司会は、これを基調講演の、エージェントを信頼できるかという話、信頼に向けて権限を切り離すという点に結びつけました。

Antonio 氏は、サービス ポートフォリオが確かに変化していると述べました。助言の仕事は増えているが、実装へ、さらに実装からライフサイクル管理、保証、検証、その後のマネージドサービスへと移っています。マネージドサービスの内容は多様です。提供メニューを、セキュリティだけでなく、モダンワーク、CRM と Dynamics、AI 全般など、すべてのサービスでエージェントを扱えるよう調整し、ガバナンス、データ、データセキュリティ、セキュリティなど複数の視点を持つ多分野のチームを入れたことで、サービス自体が進化したと述べました。例えば、顧客が統制の合理化のためのエージェントを作りたいと来たとき、それが顧客のための「エージェント開発ファクトリー」の立ち上げにつながります。長期にわたってエージェントを構築、デプロイし、アプリケーション ライフサイクル管理を通し、検証と最適化を行い、全体としてのエージェント ガバナンス フレームワークを確立する流れです。多くはまだ進化中で、技術が進むにつれて機会も現れるため、サービス ポートフォリオの変化に開かれている必要があるとのことです。

**締めの発言**

- パネリストの一人：変革の入り口にいて、自分たちは炭鉱のカナリアのようなものだ、と述べました。製品・ポートフォリオ担当者への格言として「はさみが必要か、それとも切るためのものが必要か」を紹介しています。パンを切るのにはさみを選ぶと、つぶれたパンとくずが残ります。顧客がエージェントを作ってほしいと言うたびにこの問いを投げれば、当初と違う答えが得られるはずだ、という主張です。

## 7. 注意点・発表者の気付き

- エージェントの数、アクセス範囲、責任者の 3 点を顧客が答えられないことが、出発点の課題として語られました。
- 見えるのはエージェントだけでは足りず、アプリ、モデル、データ、ツール（MCP サーバー、プラグイン、コネクタ）の全層を見る必要があります。
- エージェントの数が多いこと自体は価値ではなく、断片化を招く恐れがあります。
- 人を減らす話をしない。共感から入り、成果（フロー、信頼性、品質）に錨を置く。
- 共通言語を作る。同じ用語（例：ワークロード ID）でも、職種によって意味が伝わらない。
- 技術が急速に変わるため、デモの最中に製品が変わることもあり、方向転換を前提にする。
- エージェントやコードに愛着を持たず、作り直す覚悟を持つ。
- Agent 365 は進化中で、できること・できないことの両方を深く理解したうえで、サービスの変化を考える。
- エージェントのライフサイクル管理は、パネリストによれば、まだ発展途上です。

## 9. まとめ

顧客の問いは「エージェントを作れるか」から「大規模に運用できるか」に変わり、エージェントが行動する以上、誰かが責任を持つ運用モデルが必要です。Agent 365 は、管理、ガバナンス、セキュリティ、ビジネス価値の 4 つの柱で、その共有可観測性を担います。5 月の GA 以降、5,000 万を超えるエージェントが登録され、76 億を超えるアクティビティが Purview で監査されたと紹介されました。

パートナーにとっては、助言から始まり、実装、ライフサイクル管理、検証、マネージドサービスへと続く継続的な事業が機会になります。Capgemini と Protiviti は、多分野のチーム編成、共通言語、共感を持った営業支援、「してはいけない」条件から始める自律化、そして検証をサービスとして提供する考えを共有しました。Microsoft は、顧客ゼロ番としての実践、ロール別学習、Envisioning Workshop and POC、今週公開予定の 2 つのガイドで、その立ち上げを支援すると説明しています。
