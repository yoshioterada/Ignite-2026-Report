# THR876 Get ready for AI with the E5 you already own

## 1. はじめに

このセッションは、Microsoft 365 E5 をすでに契約している組織に向けて、「持っているのに使い切れていない」セキュリティ機能を一通り見直し、さらに E5 に加わった新しい価値である **ISOC（integrated security operations center、統合セキュリティオペレーションセンター）** を紹介する短いセッションです。登壇者の Matt Egan 氏は、E5 で手に入る機能を「攻撃の遮断」「アクセスの制御」「データの保護」「エクスポージャー（露出）の削減」の 4 つに整理し、Sentinel の機能を Defender ポータルに取り込む ISOC を、ライブデモを交えて説明しました。

押さえたい点は 3 つあります。E5 のセキュリティ製品は「1 つのデータ基盤を 4 つの視点で見ている」ものであること、ISOC により Defender の Advanced Hunting の既定の保持期間が 30 日から 90 日に延びたこと、そして最後に示された「E5 を使い切る 3 ステップ」です。後半の Q&A では、Defender の passive mode、E7 と E5 の違い、Sentinel と ISOC の選び方などが話題になりました。

## 5. 発表内容の詳細

### 5.1 E5 でできる 4 つのこと

Egan 氏は、スライド上の 4 項目を会場に問いかけながら説明しました。

| 項目 | 発表で語られた内容 |
| --- | --- |
| 攻撃の遮断（disrupt attacks） | 自動攻撃遮断（automatic attack disruption）が、攻撃者を検知するとマシンの隔離やユーザーの隔離（quarantine）などを自動で行う。メール、デバイス、ID にまたがって機能する |
| アクセスの制御（control access） | Entra で、誰が・いつ・どこから・何にアクセスできるかを制御する |
| データの保護（protect data） | Purview。会場でデータをすべてラベル付けした人は 1 人だけで、Egan 氏自身もまだ終わっていないと述べた |
| エクスポージャーの削減（reduce exposure） | Exposure management が脆弱性を見つけ、攻撃パス（attack path）として描く。例として、脆弱性のあるワークステーションが別のユーザーからアクセス可能で、そのユーザーの認証情報とトークンがそこにあり、クラウドリソースへのアクセスも悪用され得る、という連鎖を示せる |

これらを E5 で得られるのに、なぜ他のツールも使っているのか、と Egan 氏は問いかけています。

なお、スライドにはこの 4 項目の横に中身の無い枠があり、Egan 氏は「あとで埋める」と冗談めかして話しています。その枠には、のちに ISOC が入ることが示されます（5.5）。

### 5.2 「1 つのデータ基盤、4 つの視点」とポータルの住み分け

Egan 氏は E5 を、「1 つのセキュリティデータの源泉に、4 つの異なる視点（レンズ）がある」ものと説明しました。Defender for Endpoint が集める情報は、セキュリティ対応担当者に見えます（エンドポイント、データへのアクセス、ID の情報、攻撃がどのように遮断されたかなど）。ID セキュリティ担当者は、ログイン失敗、ログインの問題、条件付きアクセスポリシーなどを見ます。さらに脆弱性管理とデータセキュリティの視点があります。裏側では相互に情報が相関されます。

例えば、データセキュリティの問題から始まったものは Purview でアラートになり、セキュリティの問題でもあるので Defender でもアラートになります。ユーザーの ID に関することは Entra でアラートになり、複数のソースやソリューションにまたがるものは Defender に切り替えて見ます。

過去数年の取り組みとして、製品をペルソナ（セキュリティ、データ、ID など）に合わせて再編してきたと述べています。ポータルは次のように分かれています。

| ポータル | 対象 |
| --- | --- |
| security.microsoft.com | セキュリティ全般 |
| Entra | ID |
| Purview | データセキュリティ |

Exposure management は、これら 3 つすべてを参照するため、Security、Entra、Purview の 3 か所に分散して見つかります。いずれも E5 に既定で含まれると説明しています。

### 5.3 Intune のコンプライアンス信号と条件付きアクセス

E5 には Intune によるデバイス管理も含まれます。Egan 氏は、Intune のコンプライアンス信号を条件付きアクセス（CA）ポリシーに使えること、さらにそのコンプライアンス信号は Defender に基づけることを紹介しました。

Defender でセキュリティインシデントが発生すると、その信号を Intune が受け取り、デバイスのコンプライアンス状態を変えます。その結果、CA ポリシーが当該ユーザーをネットワークから締め出せます。ほぼ既定で有効になっており、必要なのは CA ポリシーとコンプライアンスポリシーの設定だけだと述べています。Defender の信号を Intune で使えると知っていた人は、会場で数人でした。

### 5.4 ISOC（integrated security operations center）

Egan 氏は、ISOC を、Sentinel の機能の多くを Defender ポータルに取り込むものだと説明しました。Sentinel で行っていたこと（自動化や組み込みの保持など）が Defender で行えるようになります。会場には、基調講演で聞いた人もいるでしょうと言及しています。

**保持期間：30 日から 90 日へ**

Defender の Advanced Hunting の既定の保持期間は 30 日でした（競合には 7 日程度のものもあると発言）。ISOC では、Advanced Hunting のデータやエンドポイントのデバイスデータなどが、既定で最大 90 日間保持されます。さらに延ばすこともでき、データレイクを有効にして 12 年間保持する、といった設定の例が挙げられました。

**自動化**

かつて Sentinel の役割だった自動化機能が ISOC に統合されます。自動化の playbook、Logic Apps の起動、自動化を作るための code builder を使えます。Egan 氏は、会場に「client agent を使った自動化の構築を試したか、気に入ったか」と尋ね（音声認識の都合で、client agent の表記が確定できません）、反応が良かったことに触れています。

**4 つの柱**

Egan 氏は、ISOC で活用できる 4 つの柱として次を挙げました。

1. より遠くまで遡った調査：90 日前のイベントを見たり、保持期間を延ばして深い調査や持続的な脅威ハンティングを行う。顧客から、イベントの 2 か月後に何かが起き、遡って詳しく見る必要が出た、という声があったと説明している。
2. SIEM 機能：cases と workbooks を含む。cases は、インシデントの上位にある抽象レイヤーのようなもので、複数のインシデントを含められ、ワークフローも持てる。SLA を管理でき、あるインシデントを担当するチームが SLA を超過した場合にエスカレーションを行う、といった使い方ができる。
3. 可視性とコンテキストの拡大：Microsoft と Microsoft 以外の信号を、Sentinel のときと同様に 1 つのポータルにまとめる。2 つの別環境を管理する必要がなくなる。
4. コスト効率の高いデータ保持：Sentinel に導入された Data Lake を ISOC のインターフェイスにも取り込む。

**ログの扱いの考え方**

Egan 氏は、ログ管理の「こんまりメソッド」を紹介しました。ログを手に取り、「これは分析上の喜びをもたらすか」と問う考え方です。単独で、または他のログと組み合わせて「悪いことが起きた」と言えるログは、良いセキュリティログであり、ホットなログ（すぐ参照できる層）に置いてすべてのものから利用できるようにします。一方、分析的な価値は無いが調査には役立つログは、データレイクに置くべきだとしています。例として、大量のトラフィックデータを吐き出し続けるファイアウォールのログを挙げ、それ自体で分析ルールを作ることはしない代わりに、サマリールールを作ったり、調査や分析ルールとの相関に使ったりする、と述べています。分析層に置くのはコスト効率が悪く、データレイクが有効なのはこのデータだという説明です。

### 5.5 E5 に加わる新しい価値

Egan 氏は、デモの後で冒頭の枠を埋めました。ISOC を動かせること、つまり SIEM 機能が E5 に含まれることです。E5 の製品から得たデータはすべてその中に入り、追加の価値が得られます。Egan 氏は「すでに有効化した。まもなく展開されるはず」と述べています。

- Sentinel を使っていない場合：「Connect to Workspace」というボタンが表示される。
- Sentinel を使っている場合：移行が始まる。実行前に通知があるはずだと思う、と述べている（確定した案内ではなく、本人の見通しとして語られた）。

### 5.6 E5 を使い切る 3 ステップ

1. **現状を確認する**：環境にあるロールを見て、チームをそれに対応づける。データセキュリティ担当は Purview を使っているか、エンドポイント、ID などの担当も同様に、機能を確認して有効にする。
2. **サードパーティ製品と比較する**：Egan 氏は「Microsoft のバッジを付けた偏りはある」と断ったうえで、自分が比較した限り、Microsoft の製品は十分に見劣りしないと述べています。また、エンドツーエンドで完全に統合された機能群を持つ他社製品は無いとし、他のツールを組み合わせたり SIEM で相関を取ったりする必要があるのに対し、ISOC ではそれが要件ではなくなると説明しています。
3. **ワークスペースを設定する**：E5 の特典を使い始める。

さらに、サードパーティ製品を使っている場合でも、E5 の製品の多くはそれらと並行して動作できると述べています。エンドポイント製品については、Defender が **passive mode** に入り、EDR の信号は提供するが、サードパーティ製品の能動的なブロックは行いません。さらに **EDR in block mode** を使うと、他製品が見逃したときに Defender が介入して修復し、自動攻撃遮断を起動できます。

### 5.7 Q&A

**Q1. この機能は政府向け環境（GCC）でも使えるか（質問そのものは音声に入っておらず、Egan 氏の「E5? G5?」という聞き返しと回答から読み取れる内容）**

Egan 氏は、正直なところ分からないと答えています。おそらくロードマップ上にあり取り組んでいると思うが、現時点で詳細は持っていない、とのことです。同僚に GovCloud 担当がおり、新機能が出るたびに「GCC にあるのか」と最初に聞かれるという話をし、現時点ではまだ無いと思うと述べました。メールで連絡してくれれば調べて返答する、と案内しています（本人は、Microsoft.com で Matt Egan という名前は自分だけだと述べ、綴りを M-A-T-E-G-E-N と読み上げています）。

**Q2. Defender が passive mode に入るのはポリシーで行うのか**

passive mode 自体は自動です。Defender AV（アンチマルウェア）はすべての Windows に組み込まれ、既定で有効です。サードパーティ製品を入れて正しく登録されると、Defender AV は自分を無効にします。ただし、デバイスが Defender XDR に登録されている場合は、Defender は passive mode に入ります。その場合、ブロックのアクションは行いませんが（できること・できないことに制限がある）、EDR データは収集します。一方、EDR in block mode（自動の修復アクションを行う）は、**デバイスグループ単位でスコープを設定でき**、完全自動、半自動、なしを選べると説明しています。

**Q3. E5 と E7 の違いの概要**

Egan 氏は、E7 は「E5 のセキュリティツールをエージェントに拡張するもの」だと説明しました。例として Copilot や Copilot Studio のエージェントを挙げています。E5 が組織内のユーザー向けのライセンスなのに対し、E7 はユーザーが使うエージェント向けのライセンスで、課金は引き続き「ユーザー単位」です。ユーザー 1 人あたりエージェントが 100 個あっても、必要な E7 ライセンスはそのユーザーの 1 つで、エージェントごとの課金ではありません。これにより Purview、Defender、Entra がエージェント ID（agentic identities）にも拡張されます。

E7 には **Entra Suite** も含まれます。その中の GSA（Global Secure Access）では、TLS 検査とネットワーク制御を使ったエンドポイント上のエージェントの検出（agentic discovery）ができ、さらに GSA の一部として **MCP ファイアウォール**があり、MCP リソースへのアクセスをブロックできると説明しています。

**Q4. E5 または E7 の顧客が、ISOC ではなく Sentinel を導入する理由は何か**

Egan 氏は、現時点では ISOC を使うほうがおそらく良い道だと答えました。一方で、Sentinel を Defender XDR から完全に独立させて分離したいユースケースもあると述べています。聞いたことのある例として、ある国に拠点があり、データ主権の観点で現地のデータアクセスが求められる場合に、Defender のインスタンスが別の国にあるため、両者を分けて運用する必要がある、という要件を挙げました。

## 6. デモ・手順

このセッションにはライブデモがあります。Egan 氏は「ISOC をセットアップするところから、UX、全体のつながり方まで見る」と予告して始めました。画面の細部は音声からは確認できず、語られた範囲は次のとおりです。

1. Defender ポータルの中の ISOC を表示した。大きな見た目の差は無く、追加の機能が有効化されただけだと説明した。左側に cases、統合された脅威インテリジェンス、ダッシュボードやレポートなどが並ぶ。
2. 始めるには、新しいワークスペースを設定する。ボタンをクリックして、配置するサブスクリプションを選ぶ。
3. ワークスペースができたら、次の 3 つのうちのどれかを行える。
   - カバレッジの拡大（すでにある Defender 以上の信号の追加）
   - 行動分析（UEBA）の有効化（UEBA が Sentinel と Defender の一部として付いてくることを知っていた人は少なかった）
   - 脅威インテリジェンスの指標の取り込み（脅威インテリジェンスが Defender にも含まれることを知っていた人も少数）
4. カバレッジの拡大のために content hub に移動する。ここでは、さまざまなプロバイダーやデータソースの 400 以上のコネクターにアクセスでき、新しいサービスを有効化できる。
5. 例として AWS を有効化した。AWS の信号の取り込みが始まる。実際には AWS の role ARN などの権限情報を入力する必要があるが、デモでは一部を省略していると説明した。その後、管理画面で AWS インスタンスの詳細を確認できる。
6. 脅威インテリジェンスを見た。Defender のデータだけでなくサードパーティのデータにも使える情報があり、例として VM 拡張機能の悪用に関するものが表示された。最新の脅威を確認でき、データはシステムの統合により自動でマッピングされる。
7. ここでクリックが効かなくなり、バックアップ計画として別の環境に切り替えた。
8. 別環境で、脅威インテリジェンスフィードとの統合、およびデータソースへのマッピングを見せた。画面に「threat intelligence briefing agent」があるが、それは「perception」（音声認識の都合で表記が確定できません）の一部で、今日は扱わないが、ポータルに完全に統合されていると述べた。
9. 「high impact threats」を見ると、環境に対する脅威の内容と、関連する影響を受けた資産（アラートや特定のエクスポージャーがあるもの）を確認できる。サードパーティのデータを取り込むことで、この情報はリソースに自動的にマッピングされる。
10. cases を開いた。インシデントの担当者を割り当てたり、調査を完了したりできると説明した。インシデントの一覧と概要、関連する脅威アクターや資産の詳細を確認できる。
11. あるインシデントを見て、関連するユーザーを確認し、そこから Entra の ID データへクロス参照した。Egan 氏はこれを、「1 つのデータ基盤を、異なるツールの視点で見ている」という冒頭の話につなげた。

デモは、時間が押していることから切り上げられました。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- 既存の E5 に、攻撃遮断、アクセス制御、データ保護、エクスポージャー管理が含まれている。
- ISOC により、Advanced Hunting の既定の保持期間が 30 日から 90 日になる。データレイクを併用すれば、さらに長期（例として 12 年）の保持もできる。
- SIEM 機能（cases、workbooks、自動化、Microsoft と非 Microsoft の信号の統合）が、1 つのポータルで使える。2 つの環境を管理する必要が減る。
- 分析的価値の低い大量ログは、データレイクで低コストに保持できる。
- サードパーティの EDR と並行して Defender を動かし、EDR in block mode で他製品の見逃しを補える。
- E7 では、ユーザー単位の課金のまま、Purview、Defender、Entra をエージェント ID に拡張できる。

## 9. まとめ

E5 には、攻撃遮断、アクセス制御、データ保護、エクスポージャー削減という 4 つの機能群が含まれており、それらは 1 つのデータ基盤を異なる視点で見るものです。そこに、Sentinel の機能を Defender ポータルに取り込む ISOC が加わり、90 日の既定保持、自動化、cases、Microsoft と非 Microsoft の信号の統合、データレイクが使えるようになります。Egan 氏は、現状の確認、サードパーティ製品との比較、ワークスペースの設定という 3 ステップで、手元の E5 を使い切るよう呼びかけました。
