# THRSP1086 Trust that travels starts on the endpoint

## 1. はじめに

このセッションは、AI エージェントを PC 上で動かす時代に、エンドポイント（PC）の「信頼」をどう守るかを扱う約 25 分の発表です。ASUS と Intel の 2 人が、クラウド側の ID・ポリシー・デバイス管理から、CPU（シリコン）、BIOS などのファームウェアまで、上のレイヤーから順に、1 本の信頼の連鎖として説明します。

発表の中心にある考え方は、タイトルにもなっている **「trust that travels（持ち運ばれる信頼）」** です。これまでデータセンターの中に置けた ID、ポリシー、コンプライアンスの信号が、いまはデバイスと一緒に移動します。そのため、デバイス自身が「自分はまだ信頼に値する」と繰り返し証明し続ける必要がある、という主張です。

後半では、ランサムウェア、物理的な改ざん、持ち主が変わる場面という 3 つの具体的なシナリオで、各層がどう働くかが説明されます。最後に、ポスト量子暗号（PQC）を「購入判断の問題」として捉える議論が紹介されます。このセッションでは画面を使ったデモは行われていません（スライドと口頭の説明が中心です）。

## 3. 何に関する発表か

テーマは、AI エージェントがユーザーの代わりにメールを読み、ファイルを開き、API を呼び出す環境で、PC というエンドポイントの信頼をどう担保するかです。ASUS の登壇者は、聴衆の多くが「今年は AI エージェントを展開しろと言われているが、10 年かけて作ってきたセキュリティモデルにどう影響するのか」と考えているはずだ、と冒頭で語りかけています。

発表の流れは次のとおりです。

1. 何が変わったのか：ユーザー、デバイスに加えて「エージェント」という 3 つ目の ID が登場した
2. 上のレイヤー：ID・ポリシー・クラウド管理（健全なデバイスにだけ短期のパスを出す考え方）
3. シリコンのレイヤー：Intel vPro と Intel Threat Detection Technology、vPro Fleet Services
4. ファームウェアのレイヤー：ASUS Expert Guardian（NIST SP 800-193 準拠）と、Intune 向けの ASUS Config Manager
5. 信頼が試される 3 つのシナリオ（侵害された場合、物理的に触られた場合、持ち主が変わる場合）
6. ポスト量子暗号のロードマップ

## 4. 発表者が伝えたいメッセージ

Intel の Jeremy 氏は、変わったのは「PC との関わり方」だと説明します。以前は、人がノート PC やデスクトップの画面を操作するだけで、最悪の事態でも不正なリンクをクリックしてウイルスが入る程度でした。いまは同じノート PC 上のエージェントが、メールを読み、ファイルを開き、API を呼び、予約や承認、データの移動を実行します。その際に使うのは、「デバイスが安全だと言ったから」発行されたセキュリティトークンです。

そのためエンドポイントには、ユーザー、デバイス、エージェントという 3 つの ID が存在します。最初の 2 つにはポリシーが何年も前からありますが、3 つ目のエージェントは「最も強い権限を持ち、最も監督が少ない」存在だと表現されています。しかも、エージェントのために書いたポリシーはすべて、「空港で誰かのカバンに入っているシリコン」の上に載ります。

ここから 2 人は、次の主張を組み立てます。

- ポリシーは、その下にある証拠（エビデンス）の質を超えられません。デバイスが「健全です」と嘘をつけば、アクセスルールは悪いデータに基づいて自信満々に判断してしまいます。
- だからシリコンとファームウェアが、攻撃者が偽造できないレベルで証拠を作る必要があります。
- ゼロトラストは「決して信頼せず、常に検証する」ですが、検証する何かが最初に必要で、それは攻撃者の手が届かない場所にいなければなりません。
- 結論は、**「Silicon verifies, the TPM signs, the cloud checks（シリコンが検証し、TPM が署名し、クラウドが確認する）」** という連鎖です。

## 5. 発表内容の詳細

### 5.1 一番上のレイヤー：ID・ポリシー・クラウド管理

最初に取り上げられたのは、聴衆の多くがすでに運用している層です。発表者は、すべてのログインを「短時間で失効するパス」にたとえています。健全なデバイス上の、この場所にいる、この人に、このアプリ用のパスを渡し、次回はまた取り直さなければなりません。

ここでの「健全」はポリシーで定義されます。例として、ディスクが暗号化されている、Secure Boot が有効、エンドポイント保護が動作している、ファームウェアが最新、といった条件が挙げられました。デバイスが健全でなくなれば、次のパスは拒否されます。発表者は、会場のほぼ全員がこの仕組みを何らかの段階で運用しているはずだ、と述べたうえで、弱点は「ポリシーの根拠となる証拠」にあると続けます。デバイス自身がコンソールに対して嘘をつく可能性があるからです。

### 5.2 シリコンのレイヤー：Intel vPro

ここからは Intel の Jeremy 氏が中心です。Intel vPro ブランドのシステムでは、ハードウェアのレベル、つまりソフトウェア層より下で情報が作られるため、攻撃者が偽造できないと説明されています。

**Intel Threat Detection Technology（TDT）**
CPU 内部の振る舞い（パフォーマンスカウンターやメモリアクセスのパターン）を監視し、その情報をエンドポイント保護に渡します。発表者は、聴衆にはウイルス検出だけでなく、エンドポイント保護を導入していてほしいと述べています。主な数値は次のとおりです。

- SE Labs の独立した調査で、シリコンのセンサーだけで **上位のランサムウェアの 93%** を検出
- エンドポイント検出・対応（EDR）の有効性を **24%** 引き上げ
- Core Ultra Series 3 では AI モデルが GPU と NPU 上で動くため、ユーザーは負荷を感じにくい
- シグネチャではなくハードウェアの活動を読むため、シグネチャ型ツールがまだ見たことのない、AI 生成の変異型マルウェアも捕捉できる

**vPro の管理機能と vPro Fleet Services**
vPro には、OS より下でシステムを制御できる管理機能があります。vPro Fleet Services を使うと、Intune のポータルからこれを利用できます。Intune を使っている顧客は、そのポータルから「アウトオブバンド管理」をサービスとして有効化でき、追加のサービスは不要でクラウドだけで完結します。管理者は、起動しないデバイスでも、電源オフの状態でも、デバイスに触れて修復できます。LAN などのネットワークに接続したことがあれば、Wake on LAN も使えます。すでに数千の商用顧客が導入済みとのことです。

信頼モデルについては、**Intel は鍵の一部だけを持ち、残りを IT が持つ**と説明されました。Intel がデバイスに入り込むことはできず、IT が入れるようにするだけです。

また、Core Ultra Series 3 では、マイクロコードのファームウェアとドライバーのセキュリティ更新が **10 年間** 提供され、業界で最長だと述べています。

### 5.3 ファームウェアのレイヤー：ASUS Expert Guardian

ASUS の登壇者は、ASUS Expert Guardian が **NIST SP 800-193** のガイドラインに沿って設計されていると説明します。この規格は、プラットフォームのファームウェアを保護し、改ざんを検出し、自力で復旧できることを求めるものです。Jeremy 氏が説明したシリコン機能の下に位置する土台、という位置づけです。

構成要素と動きは次のとおりです。

1. Expert Guardian の中には別のチップ、**ASUS Security Processor Unit（SPU）** があります。Intel Boot Guard と並んで動き、物理的に分離されています。役割は BIOS とファームウェアの保護のみです。
2. 電源投入時、CPU が Windows のコードを 1 行も実行する前に、SPU がファームウェアイメージを検査します。
3. 検査に失敗するとその場で起動を止めます。そして、変更できないバックアップ（immutable backup）、またはセキュアな 2 つ目の BIOS から、最後に正常だったイメージ（last known good）を戻します。これらのイベントはすべてログに記録されます。
4. その後、Intel Boot Guard が CPU 内で最初の計測を固定（アンカー）します。Measured Boot が UEFI の各ステージを TPM に記録し、そのあと Secure Boot が署名されたブートローダーに制御を渡します。
5. プラットフォーム全体が、第三者機関のラボにより NIST SP 800-193 に対して認証されています。言葉だけを信じてほしいわけではない、と補足しています。

この仕組みがクラウド側でどう効くかについても説明がありました。コンプライアンスレポートの大半は、デバイスが自分自身について述べたものにすぎません。しかし、Secure Boot、ディスク暗号化、コード整合性（code integrity）といった重要なチェックについては、コンソールは **アテステーション（attestation）** を受け取ります。これは、ディスクリート TPM の内部で生まれ、一度もそこから出たことのない鍵で署名された計測値です。その下のファームウェアは、別の保証としてデバイス上で強制されます。Intel Boot Guard が最初に動くコードを検証し、SPU が検証に合格しないものを拒否・復旧します。したがってファームウェアは、簡単にも密かにも差し替えられません。コンソールはデバイスの言葉を信じるのではなく、署名を検証している、というのが要点です。

この土台で連携する Intel の 3 つの機能は次のとおりです。

| 機能 | 役割 |
| --- | --- |
| Boot Guard | 鍵が CPU にヒューズ（fuse）として焼かれており、最初の BIOS コードを検証する |
| BIOS Guard | 認可された更新を除き、実行時に BIOS フラッシュへ書き込めないようにする |
| Runtime BIOS Resilience | Windows が起動したあとも、この保護を維持する |

### 5.4 ASUS が担う範囲と ASUS Config Manager for Intune

ASUS の登壇者は、Expert Guardian の担当範囲を明確に区切っています。**ファームウェア層とプラットフォームのセキュリティは ASUS の担当**であり、その上のウイルス対策、エンドポイント管理、エージェント向けのソフトウェアセキュリティ層は、顧客が選ぶものです。ASUS はそれらを置き換えるのではなく、連携することを目指しています。

その例が **ASUS Config Manager for Intune** です。BIOS とドライバーを管理する Intune 向けのプラグインで、普段使っている Intune コンソールから、次のことができると説明されています。

- フリート全体への BIOS 構成のプッシュ
- BIOS 管理者パスワードの一元管理
- BIOS やドライバーの更新の展開

このプラグインは**無償**で提供され、他の OEM などのサードパーティ製ツールを別に用意する必要がありません。管理対象のエンドポイントを増やさず、ファームウェア層も他のすべてと同じポリシーエンジンで統治できる、という説明です。なお、このくだりで「Let's show it」という発言がありますが、操作を実演するナレーションはなく、説明は口頭で続きます。

### 5.5 シナリオ 1：侵害されたデバイス（ランサムウェア）

顧客に実際に起きたこととして、営業ディレクターの個人のノート PC の例が紹介されました。彼女は出張中で、メールボックスと CRM システムにアクセスできるエージェントがマシン上で動いており、そこにランサムウェアが入り込みます。

流れは次のとおりです。

1. ワークロードが、大量暗号化やメモリ上への認証情報の準備といった、ランサムウェアらしい動きを始める。
2. OS より下で動く Intel Threat Detection Technology が、ファイルベースの検出が追いつく前に CPU の挙動パターンを捉える。
3. エンドポイント保護に高精度のシグナルが渡り（ここでは ASUS のエンドポイントソフトウェアに引き渡す、と説明されています）、デバイスのリスクレベルが上がる。
4. デバイス管理がデバイスを「非準拠」にし、アクセスルールが、エージェントのものを含めてパスの更新をやめる。
5. エージェントは事実上「接地（grounded）」される。

発表者の言葉では、**エージェントの権限は、デバイスの健全性から借りているもの**です。健全性が下がれば権限も下がり、誰もエージェントを探して止める必要がありません。被害は、CRM 全体ではなくノート PC 1 台分のファイルに限定されます。

次に「BIOS はファイルを救えるか」という顧客の定番の質問に、ASUS の登壇者は **「できない」** と明確に答えました。ここはベンダーが過大に宣伝しがちな点だとしています。OS 内でドキュメントがすでに暗号化されてしまったら、ファームウェアでは戻せません。それはバックアップと、上記の検出の役割です。

ファームウェアが実際にできることは 2 つです。

- **攻撃の前**：DMA 保護をデフォルトで有効にする、USB アクセスのロックダウン、Secure Boot、ロールバック防止（脆弱な BIOS に黙ってダウングレードされない）などで入口を閉じる。
- **再構築のとき**：信頼できるハードウェアの上で再構築していることを保証する。攻撃者は、OS より下に潜み、IT が行う再イメージ化を生き延び、1 か月後に戻ってきてさらにデータを盗もうとするからです。NIST 800-193 は、まさにこのシナリオ向けの検出を想定しています。

次の起動時に、SPU が BIOS イメージを検査し、署名が検証できなければ **起動はそこで停止** します。交渉の余地はありません。最後に正常だった BIOS バックアップに戻し、改ざんイベントを記録して、クリーンなプラットフォームを起動します。これにより、IT チームが行った再イメージ化が意味を持ちます。

さらに、マシンが電源オフ、再起動ループ、メモリチェックを通過できないなど、まったく起動しない状態でも、vPro のアウトオブバンド機能が「経済性を変える」と述べています。トラックを出したり、別のシステムを翌日配送したりする必要がありません。管理者は Fleet Services のコンソールから、電源状態にかかわらず OS より下でマシンに到達して遠隔修復できます。登壇者は、「our GM」と呼ぶ Jen Larson 氏（綴りは音声認識の都合で未確定。どちらの会社の GM かは発話からは確定できません）がこれを「PC のディザスタリカバリー」と率直に表現した、と紹介しています。

このシナリオのまとめは、「シリコンが気づき、ファームウェアが Windows の読み込み前に入口で止める。BIOS が壊されても、デュアル ROM がクリーンなコピーを用意している」です。そして、BIOS がファイルを救うふりはしない、システムを守るのは「戻ってこられるシステム」を残すためだ、と強調されています。

### 5.6 シナリオ 2：物理的な接触（ケース開封）

2 つ目は、見知らぬ人ではなく、どのノート PC を狙うかを知っている人物のシナリオです。例として、展示会の競合他社、共有オフィスの業者、夕食に出ている間のホテルの部屋が挙げられました。裏蓋を開け、SSD を抜いたり何かを仕込んだりして、気づかれる前に閉じます。攻撃者の最大の強みは「静かであること」で、ノート PC は何事もなかったように組織に戻ってきます。

これに対し、ASUS の商用デバイスすべてに搭載されている **chassis intrusion（ケース開封検知）** がその強みを奪います。

- 専用のハードウェアセンサーが、カバーが外されたことを検知する。
- システムの電源が切れた状態でも検知でき、電源は落ちたまま、AC 電源が再接続されるまで動作しない状態を保つ。
- 次の電源投入時、BIOS が最初の起動で画面に侵入警告を表示する。IT チームにとっての物理的な証拠になる。
- デバイスは何もなかったように業務に戻らず、その場で保持される。IT はその 1 台を回収して確認できる。

これとは別に、センサーと無関係に 2 つのことが毎回の起動、すべてのマシンで行われます。

- SPU が、何かを実行する前にファームウェアイメージを検査する。BIOS の中に仕込まれたものは、カバーの開封に誰も気づかなくても捕まる。
- BitLocker が有効なら、鍵はマザーボード上の TPM に封印されている。SSD 単体では暗号化されたデータにすぎない。

3 つの独立した層（改ざんを示すケース、検証されたファームウェア、自分のボードでしか開かないドライブ）があるので、「ケースが開けられたデバイスは、侵害されたデバイスではなく、フラグが立ったデバイスになる」という説明です。

コンソール側が求める信号は、侵入イベントとファームウェア検証結果の組み合わせです。それが得られるとデバイスは隔離され、そのデバイス上のエージェントはユーザーと一緒にトークンを失います。さらに vPro があれば、誰かがログインする前に、IT がアウトオブバンドでマシンを調べられます。攻撃者が最も必要とする「気づかれないこと」を、ハードウェアが渡さない、という整理です。

### 5.7 シナリオ 3：持ち主が変わるとき

どの組織でも毎週起きる場面として、エンジニアの退職、アナリストの異動、ノート PC の再割り当てが挙げられました。防衛、製薬、半導体の顧客のように、デバイスに多くの知的財産があるケースで特に心配される瞬間です。紛失や盗難で、本人の意思と関係なく持ち主が変わる場合もあります。

**計画されたケース（オフボーディング）**
機密性の高い組織では、データが外に出ていくのは、ドライブが適切に消去されないまま次の人に渡されたときです。そのため ASUS のメディアサニタイズ（media sanitization）は **UEFI レベル** で動き、OS が読み込まれる前に実行されます。IT は「clear」か「purge」を選びます。発表では **NIST 888** に沿うと聞こえます（音声認識の都合で表記が確定できません）。サードパーティのブートツールは不要で、ドライブをシュレッダーに送る必要もなく、消去されたことを証明できます。その後に再イメージ化して次の人に渡す、というライフサイクル管理です。

**計画外のケース（紛失）**
顧客はよく「何か変だと思ったらすぐドライブを消去すればいい」と考えます。ASUS の登壇者は「消去を最優先にする」ことに異を唱えました。chassis intrusion を検出したときに自動で消去するよう設定することも可能ですが（発表の聞き取りは「assets intrusion」で、chassis intrusion のことと読めます）、それはユーザーのデータがバックアップされている場合に限る、という考えです。消去するとそのデータが失われるためです。

発表の順序は「**Lock first, wipe second（先にロック、消去は後）**」です。

1. 最初の対応は、顧客が使っているエンドポイントセキュリティ製品の役割。デバイスの位置特定、凍結（freeze）、画面へのメッセージ表示、アクセス失効などを行う。
2. 消去は、デバイスが戻ってこないと明らかになってから。
3. ASUS の部分はその下に静かに存在する。データはすでに TPM の背後で暗号化されており、UEFI レベルの消去はいつでも実行できる状態で待機している。決める時間がある。

並行してクラウド側も動きます。管理コンソールでデバイスが「紛失」とマークされた瞬間に、ID プラットフォームがセッションを失効し、そのデバイスに紐づくエージェントの委任（delegation）も一緒に失効するため、エージェントは停止します。vPro では、有効にしていれば、デバイスが再びネットワークに接触した際に、Windows の状態にかかわらず、コンソールからアウトオブバンドで IT が到達できます。

3 つの場面に共通するパターンは、「デバイスは信頼に値することを証明し続け、それができなくなった瞬間に信頼が外れる」というものです（原文は「the trust leaves with you, not with the hardware」で、後半の含意は発話からは確定できません）。

### 5.8 ポスト量子暗号（PQC）

最後に、CIO からよく聞く反応への「正直な答え」として、PQC が取り上げられました。反応とは、「ポスト量子の見出しは読んだが、自社の PC の更新は 2027〜2028 年なので、まだ自分の問題ではない」というものです。ASUS の登壇者は、時間の隔たりが 2 つあると答えています。

1. **データそのもの**：「Harvest now, decrypt later（今集めて、後で復号する）」。攻撃者は今日、量子コンピューターを必要とせず、データだけがあればよい。データを 10 年機密に保つ必要があるなら、時計はすでに動いている。
2. **ハードウェアに特有の問題**：Secure Boot、Measured Boot、ファームウェア署名はすべて RSA と ECC の署名に依存している。それを検証するルート（ブート ROM、ワンタイムプログラマブルのヒューズ、シリコン自体）は後からパッチを当てられない。2027〜2028 年に買った PC は 2030 年、2033 年も稼働しているので、ルートオブトラストが出荷時に持つアルゴリズムは、その寿命の間ずっと同じになる。

**Intel 側の状況**（Jeremy 氏）
- NIST のポスト量子の取り組みに 2016 年から参加し、確定した 3 つの標準のうち、SLH-DSA の標準に貢献した。
- 2023 年以降、商用プラットフォームには、量子耐性のあるマイクロコード認証とメモリ暗号化、および CPU と SoC ファームウェアを認証する CNSA 2.0 準拠のポスト量子アルゴリズムが搭載されている。
- CNSA 2.0 はファームウェア署名の量子耐性化を 2030 年までに求めている。Intel は、すべての新プラットフォームで 2030 年までに PQC に完全準拠することを約束している。

**ASUS 側の状況**
- NIST は 2024 年 8 月に FIPS 203、204、205 を確定し、業界にとって具体的な目標ができた。
- ASUS はすでに、PQC にネイティブ対応した SPU を出荷しており、発表では Xpertbook Ultra と「A7」と聞こえるモデルが挙げられました（製品名は音声認識の都合で確定できません）。
- 現在、この SPU は自身のファームウェアイメージを **MLDSA** で検証している（発表での綴りのとおり）。これは出荷後に変更できない層であり、そこを最初に対応したと説明しています。
- 2027 年にかけて、PQC で検証されたファームウェアを商用ラインアップ全体に広げる計画で、これを最初に行うプレーヤーになると述べている。
- プラットフォーム全体の PQC 対応は 2029 年の世代を目標としているが、発表の該当部分は音声認識が崩れており（「2029 series AB and ultra lineups」）、対象のラインアップは確定できません。Intel のロードマップにも依存すると述べています。

ロードマップの詳細については、Jeremy 氏が、セッション後に声をかけてほしいと案内して時間切れとなりました。

## 7. 注意点・発表者の気付き

- **BIOS はランサムウェアで暗号化されたファイルを救えません。** ベンダーが過大に主張しがちな点だと、ASUS の登壇者が明確に否定しています。ファイルを戻すのはバックアップの役割です。
- ファームウェアが守るのは、攻撃前の「入口を閉じること」と、再構築時に「信頼できるハードウェアを確保すること」です。
- **紛失時は「消去を先にしない」。** まずロック、位置特定、アクセス失効を行い、消去は戻ってこないと分かってから。自動消去を設定する場合も、バックアップが正しく動いていることが前提です。
- ASUS が担当するのはファームウェア層とプラットフォームのセキュリティまでです。その上のウイルス対策、エンドポイント管理、エージェントのセキュリティ層は顧客が選ぶもので、置き換えは意図していません。
- vPro のアウトオブバンドの経路は、有効にしている場合に使えます。また、ネットワークに接続したことがあることが Wake on LAN の前提として述べられています。
- ルートオブトラストのアルゴリズムは出荷後に変えられません。2027〜2028 年に買う PC も 2030 年、2033 年まで使われる、と指摘されています。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- 偽造できないハードウェアレベルの証拠により、デバイスの健全性判断の質が上がる。
- 数値として、シリコンセンサーのみで上位ランサムウェアの 93% を検出し、EDR の有効性が 24% 向上（SE Labs の独立調査）。
- ランサムウェア発生時に、デバイスが非準拠になり、エージェントを含むアクセスが止まるため、被害を 1 台分に限定できる。
- 起動しないデバイスでも、vPro のアウトオブバンドで遠隔修復でき、現地への派遣や機器の発送が不要になる。
- Core Ultra Series 3 では、マイクロコード、ファームウェア、ドライバーのセキュリティ更新が 10 年間提供される。
- ASUS Config Manager for Intune が無償で提供され、別のツールなしに Intune から BIOS とドライバーを管理できる。
- 再イメージ化が意味を持つこと（BIOS が改ざんされていれば起動時に検出され、復旧される）。
- UEFI レベルのメディアサニタイズで、オフボーディング時にデータが残らないことを証明できる。

## 9. まとめ

AI エージェントがユーザーとデバイスに続く 3 つ目の ID として加わり、エージェントの権限はデバイスの健全性に依存する、というのがこのセッションの出発点です。ポリシーは証拠の質で決まるため、ASUS と Intel は、Intel のシリコン（Boot Guard、BIOS Guard、Runtime BIOS Resilience、Threat Detection Technology、vPro）、ASUS の SPU と Expert Guardian、TPM によるアテステーション、Intune などのクラウド管理を、ひと続きの信頼の連鎖として説明しました。

ランサムウェア、物理的な改ざん、デバイスの持ち主の変更という 3 つの場面では、いずれも「デバイスが信頼を証明できなくなった瞬間に、エージェントの権限も止まる」というパターンが示されました。同時に、BIOS はファイルを救えない、消去よりロックが先、といった限界も明示されています。最後に、ルートオブトラストは出荷後に変えられないため、PQC は先の話ではなく、冒頭で「購入の問題」と位置づけられたとおり、いま買う PC の寿命に関わる話だ、という議論で締めくくられました。
