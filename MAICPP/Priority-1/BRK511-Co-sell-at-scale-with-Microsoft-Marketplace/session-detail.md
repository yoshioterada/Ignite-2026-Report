# BRK511 Co-sell at scale with Microsoft Marketplace

## 1. はじめに

このセッションは、Microsoft Marketplace を使って Microsoft と一緒に（co-sell）ビジネスを伸ばしたい ISV（ソフトウェア会社）とチャネルパートナー向けの 45 分のブレークアウトです。技術的な実装やデモの話ではなく、Marketplace の成長データ、今年の進捗、新しい機能の発表、Microsoft の営業組織のインセンティブ、パートナー企業の事例が中心です。

発表者が一貫して伝えているのは、**「Microsoft と co-sell したいなら Marketplace で取引する」** というメッセージです。Marketplace は単なる取引の仕組みではなく、go-to-market（市場への届け方）の戦略に組み込むものだ、という点も繰り返し語られています。

## 5. 発表内容の詳細

### 5.1 Marketplace の成長データ

登壇者（Mira）は、ビジネスが急成長していることを示しました。

- Microsoft Marketplace のビジネスは **3 年連続で倍増** しており、今年も倍増に向かっている。
- 会場の参加者全体で、Marketplace を通じて数十億ドル規模の取引が行われた。

さらに、成長がどこから来たかについて、2 つのデータが紹介されました。

| データ | 内容 |
| ---- | ---- |
| 新規顧客の地域 | Marketplace の net new customer（純新規顧客）の **60% が米国外** から来ている。Marketplace がもはや米国向けのローカルな仕組みではなく、グローバル投資が正しい方向だという信号とされている |
| チャネル案件の規模 | チャネルパートナーが関わる案件は、Marketplace の平均的な案件より大きい。チャネル主導の private offer は、平均で Marketplace の平均案件より **80% 大きい** |

発表者は、これはチャネルパートナーが単なるリーチの拡大役ではなく、市場をリードして、より大きく、より速く、より戦略的な案件を作っている証拠だと述べています。

また、Azure のコミットメントを持つ顧客については、**100% が Marketplace でも取引している** と発表されました。

### 5.2 3 つの重点領域と今年の進捗

7 月の MCAP Start（音声認識の都合で表記が確定できません）で共有した 3 つの投資領域は、**global expansion（グローバル展開）、channel activation（チャネルの活性化）、co-sell at scale（co-sell の大規模化）** です。それぞれの進捗が報告されました。

#### Global expansion

- 6 か月未満で、**40 を超える市場** で提供を開始した。
- この 40 市場すべてで MPO（multi-party private offer）を拡大している。MPO は、チャネルパートナーに頼ってオファーを市場に届ける仕組みで、チャネルパートナーへの信頼の表れでもあると説明されている。
- この日、**マレーシアとサウジアラビア** での提供開始が発表され、今後さらに国が追加される予定。
- **通貨の柔軟性（currency flexibility）**：パートナーは private offer の作成時に、自分または顧客に合う **16 の通貨** から選べる。案件が大きくなってカスタマイズしたいときに特に役立つとされている。

発表者は、プログラムはグローバルだが実行は非常にローカルであり、パートナーが顧客の言葉で独自の提案をできるようにしたかった、と説明しています。

#### Channel activation

顧客は 1 つのソフトウェアを買いたくて来るのではなく、実際のビジネス課題を解決したくて来る、というのが出発点です。チャネルパートナーは製品を再販するだけでなく、導入、トレーニング、マネージドサービス、更新までのプロフェッショナルサービスを付加しています。

そこで、**近日中に発表予定** として、チャネルパートナーが 1 つの private offer の中で、複数のソフトウェアをバンドルするだけでなく、**自社のソフトウェアサービスやプロフェッショナルサービスもバンドルして、1 つの完結したソリューションとして提供できる機能** が紹介されました。提供は **2027 年初頭** で、登壇者自身が「プレアナウンスメント」と位置づけています。

- ISV にとっては、チャネルパートナーが販売を広げるだけでなく、プロフェッショナルサービスを組み合わせて顧客成果を軸に提案することで、より多くの顧客につながる。
- チャネルパートナーにとっては、サービスを売る場面で Marketplace を会話に持ち込み、ポートフォリオを広げ、プロフェッショナルサービスで収益化し、顧客のビジネス成果に基づく 1 つのソリューションを提供できる。

#### 販売プロセスの簡素化

「プロセスを減らす、または楽にしてほしい」という声に応えて、この日、3 つの機能強化が発表されました。

| 機能 | 内容 |
| ---- | ---- |
| Request a private offer | 顧客が、リスティング上から直接 ISV に private offer を依頼できる |
| One step purchasing | private offer の購入体験を簡素化し、案件をより速く成立させる |
| Future dated agreement | パートナーが、より大きな顧客に対応できるよう、private offer の将来日付を柔軟に設定できる。更新の計画も簡単になり、サービスの空白（service gap）を避けられる |

発表者は、個別には機能強化に見えても、3 つが合わさることで、顧客の関心から会話、取引、更新までを簡単につなげる強いシグナルになる、と説明しています。

### 5.3 Microsoft にとっての Marketplace と co-sell

ここから、Sandy が登壇しました。Sandy は global ISV ecosystem を率いており、ISV から最も多く聞かれる質問は **「Microsoft の 60,000 人の営業担当や、チャネルパートナーとどう co-sell するか」** だと述べています。相手が最大級のパートナー（Anthropic、SAP などの名前が挙がりました）でも、最小のスタートアップでも、同じ質問になるそうです。

発表者は、すべての道は Marketplace に通じるとして、その背景を説明しました。

- **顧客側の需要が大きい。** 特に Azure のコミットメント（消費コミット）を持つ顧客が、Marketplace で購入してそれを消化できる。エンタープライズでは、上位 1,000 社の顧客のうち **約 90%**（発表者の見立て）が Azure のコミットを持っているとされている。
- コミットの有無にかかわらず、請求や請求書など、Microsoft とのやりとりを 1 か所にまとめたい顧客にも役立つ。
- **エージェントの時代への備え。** 前日のラウンドテーブルでは、数百万のエージェントが登場し、調達が人だけでなくエージェントを通じても行われる、という話が出た。エージェントが発見・試用・購入・展開するときに Marketplace にいる必要がある。製品体験の中のフロントストアなどが作られるが、バックエンドは Marketplace にある、という説明。

発表者は、これが「あると良いもの」ではなく、go-to-market と co-sell 戦略の中核だと述べています。そのため Microsoft は、営業の整合（seller alignment）、インセンティブ、チャネルパートナーの巻き込みを進めています。今年は **Marketplace への投資を 200% 増やした** と発表されました。投資は案件への支援（Azure sponsorship など）だけでなく、営業のキャパシティと営業の準備（readiness）にも向けられています。

#### 営業担当者に求めていること

営業担当者には、案件の支援だけでなく、最初の go-to-market 計画から取り組むよう求めています。

1. go-to-market の計画と、一緒に行う co-innovation を決める。
2. ソリューションを Marketplace で取引可能にし、適切な位置づけで見つけてもらえるようにする。
3. チャネルパートナーや顧客と協力し、パイプラインと案件の速度（deal velocity）を確認する。
4. 共同の顧客コール、共同のパートナーコールを行う。
5. ビジネスとパイプラインを追跡し、案件を成立させるための適切なインセンティブを整える（Microsoft 側が支援する）。

チャネルパートナーは、Microsoft の営業チームの拡張であり、これまでもそうだった、という位置づけです。

#### 営業担当者のインセンティブ

- 商用（commercial）の営業担当者に、**Marketplace の取引に対する非常に大きなクォータ** を設定した。過去数年は「Microsoft の営業担当者から関心が得られない」という声があったが、**今年は多くの関心がある**。営業担当者は Azure クォータを消化するために、パートナーの協力を必要としており、その最大の方法が co-sell だと説明されている。
- ヘルスケアなど特定分野向けに、期間限定の spiff（短期の特別インセンティブ）を設けて、重点的に加速したいソリューションに焦点を当てる。
- チャネルパートナーに向けたインセンティブも増やしている。

#### パートナー向けの投資（案件のライフサイクルに沿って）

| 段階 | 投資 |
| ---- | ---- |
| 構築 | **Build and publish incentive**：小さなパートナーやソフトウェア会社が、市場に出すソリューションを構築・共同イノベーションするための投資（大手には不要な場合もある） |
| 案件の加速 | **Marketplace rewards**：Marketplace で売るほど獲得でき、案件のスポンサーシップ資金として戻せる |
| 展開後 | **Deployment funds**：移行やモダナイゼーションなど、案件後の展開を加速する資金 |

Marketplace rewards の仕組みについては、次のとおり説明されています。

- Marketplace で販売すると、契約金額の **10%** がウォレットに入り、次の案件の rewards として使える。
- ウォレットの上限は、今年 **200 万（2 million）に倍増** した。200 万を超えて使っているパートナーもいる。
- 使い道や、どの案件に使うかはパートナーの裁量。クレジットの形で案件に適用でき、**その節約分を顧客に還元** できる。

発表者は、今年の取引の速度（velocity）の数字が、この施策が的を射ていることを示していると述べています。

#### co-sell の位置づけ

Sandy は、チームやエンティティがない国（例としてチェコ共和国が挙がっています）のパートナーとも、Marketplace とチャネルパートナーを使って大規模に co-sell を進めていると話しました。地域展開、案件規模を広げるチャネルパートナーの巻き込み、他のパートナーをつなぐことなど、広く成長の機会があるとしています。

そして、次の言葉で位置づけを示しています。**「Microsoft と co-sell したいなら、Marketplace で取引する必要がある。それが North Star（北極星）だ」**。Marketplace 以外で成立する案件も歓迎するが、Microsoft の営業の動機づけとすべての投資を引き出すうえでは、Marketplace で取引するのが正しい道だ、という説明です。

### 5.4 Veeam との対談

Sandy が、Veeam を「エージェント時代のレジリエンス（復元力）を再構想している会社」と紹介し、Jeannie Kroll 氏を壇上に迎えました。Jeannie 氏は、Veeam の public cloud ビジネスをグローバルに率い、hyperscale パートナーシップも担当しています。Veeam に 10 年、その前の 13 年は Microsoft にいたため、Marketplace の構想の初期から関わってきたと話しています。

対談の内容は次のとおりです。

**Marketplace はどう成長に役立っているか**

- Veeam は **100% チャネル組織** で、パートナーを通じて拡大している。Marketplace はその道のりに寄り添ってきた。
- Veeam の Marketplace ビジネスは **前年比で倍増**。目標は「顧客がお金を払いたい方法で受け取ること」であり、その方法がますます Marketplace になっている。
- 顧客は Marketplace でソリューションを探しに来る。Marketplace は、ソリューションを市場に速く届けるのにも役立つ。
- Veeam は 150 か国超で販売しており、Fortune 500 から小規模な SMB まで顧客がいる。
- エピソードとして、Jeannie 氏が休暇で訪れたカリブ海のボネール島のダイビングショップの話が紹介された。隣のリセラーの窓に Microsoft と Veeam のロゴがあり、ショップのオーナーが「あなたたちのソフトを使っている」と言ったという。チャネルが、小さな事業者が本業に集中できるようにしている例として語られた。

**適切なチャネルパートナーの見極め方**

- チャネルパートナーは、**顧客が決める**。Veeam は規模を出すことに注力する。
- 顧客セグメントによって Marketplace の使い方が変わる。Microsoft を通じて支出を集約したい顧客もいれば、顧客のニーズに合わせて拡大したいチャネルパートナーもいる。Veeam はエンタープライズ、ミッドマーケット、SMB のすべてにいて、全セグメントでそのギャップを埋めようとしている。
- 大規模顧客環境で Microsoft と co-sell する場合から、チャネルパートナーを介して大規模に展開する場合、直接の営業から案件を見つけて Marketplace に乗せる場合まで、戦略は異なる。**Marketplace を trial（試用）の手段としても使っている**。

**他のパートナーへのアドバイス**

- Jeannie 氏は、Marketplace を「プラットフォーム、一連のツール」と表現した。その戦略を自社で持ち、プラットフォームの提供価値を理解する必要がある。
- Sandy は、多くの人が Marketplace を取引エンジンと見ているが、実際には自社の販売戦略の一部であり、「Marketplace に載せただけでは売れない」と補足した。
- 対談では「ショッピングモールそのものは売れない」という表現も出た（Marketplace はショッピングモールのようなもの、という趣旨。発言者は音声からは特定できません）。
- まず、自社のチャネル戦略（直接営業か、チャネルパートナーを受け入れるか、各手段で事業の何％を扱うか）を決め、そのうえで Microsoft のプラットフォームを理解する。

**Veeam の今後**

- 前年に大きな買収があり、製品と市場投入の速度、提供価値が高まっている。新しい市場への展開も進める。
- マレーシアとサウジアラビアの発表について、チャネルと MPO の動きが多くの国への拡大に役立つため、現地の営業担当者も強く関心を持っている。ハイパーローカルな販売に注力しつつ、Marketplace がグローバルなスケールを提供する。
- Sandy は、Veeam がサウジアラビア（KSA）のローンチパートナーであることに感謝した。サウジでの提供開始は前日だったと述べている。

### 5.6 エージェントと Marketplace

全体を俯瞰すると、Microsoft と ISV が一緒に行うことは **co-innovation、co-build（製品を共同で作る）、go-to-market（co-sell）** の 3 つで、その全体で Marketplace が大きな役割を担っている、と説明されました。

さらに、Copilot や Cowork 向けのエージェントを作っている場合、そのバックエンドは Marketplace を通ると述べられています。単独の SaaS サービスを Azure で提供する場合も、Copilot に組み込まれるエージェントの場合も、取引やプラグインは Marketplace の e-commerce を通り、顧客はそこでエージェントなどを見つけることになる、という見方です。

### 5.7 SMB という新しい機会

最後に Mira が戻り、Marketplace は従来エンタープライズ中心で、コミットメントを持つ顧客に焦点を当ててきたが、今は **Azure のコミットメントなしで購入しに来る顧客が増えている** ことを指摘しました。これが SMB への新しい機会につながります。

- IDC の見積もりとして、SMB のクラウド支出が **1 兆ドル** に達するという数字が示された（年は「2023」と聞こえますが、音声認識の都合で確定できません）。
- 発表者は SMB の顧客を 2 つのコホートに分けて説明した。

| コホート | 特徴 | Microsoft の投資 |
| ---- | ---- | ---- |
| デジタル主導の SMB | Marketplace で探し、試し、購入したい。簡単に見つけて取引でき、面倒がないことを求める | プラットフォーム、ターゲットを絞ったマーケティングキャンペーンへの投資。今後さらに投資が増える |
| 信頼できるアドバイザー経由の SMB | 信頼するチャネルパートナーと、ソフトウェアの購入だけでなく完結したビジネスソリューションを作りたい | MPO の拡大と、RUM の拡大（音声認識の都合で表記が確定できません） |

MPO は、ISV がチャネルパートナーを通じて、割引付きで顧客にオファーを出せる multi-party private offer です。加えて、従来 Microsoft ソフトウェアを販売してきたチャネルパートナー向けに設計された **CSP private offers** もあります。これは、パートナーが Microsoft ソフトウェアだけでなく ISV のソフトウェアも売り、自社のプロフェッショナルサービスを組み合わせ、1 つの完結したソリューションを Marketplace で取引できる大きな機会だと説明されています。

## 7. 注意点・発表者の気付き

- **Marketplace に載せただけでは売れません。** ISV もチャネルパートナーも、販売戦略の一部として Marketplace を位置づけるべきだと、Sandy と Jeannie 氏の両方が述べています。
- **Marketplace を商談の終盤（11th hour）に持ち込むと「複雑」と言われがちです。** Mira は、Marketplace は数十億〜数兆ドル規模の取引を扱うために洗練された設計になっていると述べ、会話の早い段階から取り入れるよう強く勧めています。
- **Marketplace 以外で成立する案件も歓迎されます** が、Microsoft の営業担当者の動機づけとすべての投資を引き出すには、Marketplace で取引することが前提になります。
- ソフトウェアとサービスのバンドル機能は **2027 年初頭の提供予定のプレアナウンス** であり、現時点で利用できるものではありません。
- Marketplace rewards は、契約金額の 10% がウォレットに入り、上限は 200 万です。使い道は、パートナーの裁量で決められます。
- Veeam の事例では、適切なチャネルパートナーは「顧客が決める」ものと語られています。

## 8. 利用者にとっての利点

このセッションでの「お客様」は、主に ISV とチャネルパートナーです。発表で語られた利点は次のとおりです。

**ISV（ソフトウェア会社）にとって**

- Microsoft の営業担当者の動機づけ（Marketplace に対する大きなクォータ）と、Marketplace rewards、build and publish incentive、deployment funds などの投資を活用できる。
- チャネルパートナー経由で、案件規模を広げ、新しい国や地域に届けられる（Veeam は 150 か国超で販売、チームがない国でも Marketplace とチャネルで進められる例が語られた）。
- 顧客は Marketplace で購入することで、Azure のコミットメントを消化できる。

**チャネルパートナーにとって**

- ソフトウェアだけでなく、プロフェッショナルサービスを含めた完結したソリューションを提供できるようになる（2027 年初頭の予定）。
- 通貨の柔軟性（16 通貨）、private offer の依頼、one step purchasing、future dated agreement で、案件の作成から更新までが楽になる。

**成果の例**

- Cisco：過去 12 か月で Marketplace での成長が 8 倍、20 社超のチャネルパートナーを追加。
- Veeam：Marketplace ビジネスが前年比で倍増。
- Siemens と Dapple（表記未確定）：取引のすべてを Marketplace で行っている。

## 9. まとめ

Microsoft Marketplace は 3 年連続で倍増し、今年も倍増に向かっています。成長の背景には、新規顧客の 60% が米国外から来ていることと、チャネルが関わる案件が平均より大きいことがあります。Microsoft は、グローバル展開（40 超の市場、マレーシアとサウジアラビアの追加、16 通貨）、チャネルの活性化（ソフトウェアとサービスのバンドル、3 つの販売プロセス改善）、co-sell の大規模化（営業のクォータとインセンティブ、Marketplace rewards の拡大）に投資しています。

最後に、聴衆に向けて次の行動が呼びかけられました。

1. **自社の Marketplace 戦略を見直す。** go-to-market の戦略を確認し、Marketplace を会話の早い段階に持ち込み、顧客の認識を高める。
2. **チャネル戦略を持つ。** すでにあれば、チャネルを巻き込む。なければ Microsoft が一緒に、理想のパートナーや役割を考える。チャネルパートナーは、差別化と付加価値を作り、ISV の製品を補完して、SMB 顧客のワンストップの窓口になる。
3. **Frontier Accelerate for Marketplace（FAM）プログラムに参加する。** パートナーが Marketplace を理解し、リスティングし、事業を伸ばすためのプログラムで、まだ参加していなければ登録を勧められた。
4. **エコシステム（パートナーシップ）で成長する。** 周りのパートナーが何をしているかを知り、互いの提供価値を補完して、顧客の課題を一緒に解決する。
