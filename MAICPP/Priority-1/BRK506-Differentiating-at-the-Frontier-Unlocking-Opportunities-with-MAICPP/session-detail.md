## 5. 発表内容の詳細

### 5.1 プログラムの全体像と数値

Heather 氏は、自身のチームが Microsoft と取引のある約 500,000 社のパートナーエコシステム全体を支援していること、MAICPP のエグゼクティブスポンサーであることを自己紹介で述べています。

インセンティブについては、前年比でおよそ 20% 増（別の箇所では「19% 超」）と説明しています。ただし、全体に薄く配分するのではなく、顧客の消費や利用につながる行動に絞って投資する方針です。プリセールスとポストセールスへの投資を厚くしており、詳細は翌日のセッションで扱うとのことです。

今年度（7 月以降）に Frontier transformation engineer badge を取得した個人は 2,000 人にのぼり、強い差別化要素だと述べています。

### 5.2 IDC の調査

Heather 氏は、IDC が（キーノートでの紹介を受けて）調査レポートを公開する予定であることを紹介しています。注目点として挙げたのは、**AI リーダーは、AI 成熟度の低いパートナーに比べて収益の乗数（revenue multiplier）が 67% 高い**という結果です。パートナー自身が AI を活用して成熟度を高めることは、個人の生産性向上だけでなく収益にも結びつくことが、この調査で裏付けられたと説明しています。

### 5.3 成功するパートナーの 3 つの特徴

「将来のパートナーはどうあるべきか」という質問がよく寄せられるため、Heather 氏は 1 枚のスライドに自分の見解をまとめています。

1. **顧客の成果に合わせて提供する**：何を達成したいのか、どうやってそこに至るのかというエンドツーエンドの成果を示す。
2. **収益化とスケーラブルな価値**：ライセンスを売る時代は終わり、利用と消費、デプロイ後の価値、継続的な進化が焦点になる。今週ステージで触れた usage-based billing は今後提供される。Copilot を導入すると Azure テナントが立ち上がるため、Copilot ビジネスに関わるパートナーにとっては新しい収益源になる、という説明もあります。
3. **自身が AI を活用するパートナーになる**：Copilot を使い、Autopilot（聞こえた表記のままです）が使えるようになったらそれも使って、自社のビジネスを前に進める。そのうえで、体験を自分の言葉で語る。

### 5.4 EY とのファイヤーサイドチャット

Heather 氏は、EY が今年 11 の partner of the year を受賞したこと、そのうち Frontier Transformation Partner of the Year も受賞したことを紹介しています。以下は Jason Hunt 氏の回答の要点です。

**Customer Zero の実践**

EY は約 400,000 人の従業員全員に Copilot を展開しました。Jason 氏によると、社内の運用はすべて Microsoft 上で行っています。「PowerPoint で AI にできることを語る」のではなく、「自分たちの実体験」を顧客に伝えられるのが強みだと説明しています。展開から得た学びは、**課題は技術ではなく、導入定着（adoption）、ガバナンス、人、変革だった**ことです。その規模の人数をどう動かすか、どんな道をたどったかを顧客に語れることが価値になっています。

今年末までに、社内のすべてのエージェントを Agent 365 で監視・管理する計画です。Copilot が「AI を使う」ことを従業員に教えたのに対し、Agent 365 によって人とエージェントが協働して顧客に価値を届ける形に進む、という位置づけです。

**Ask EY Tax**

EY は 4 つのサービスラインに分かれています（tax、audit、consulting、EY Parthenon）。このうち tax では、単一のエージェントではなく数百のエージェントの集合体である **Ask EY Tax** を、約 40,000 人の税務プロフェッショナルが毎日使っています。100% Microsoft 上で構築されたものです。チームの知識と経験を、すべての案件に一貫した形で提供するもので、効果は次のとおりです。

| 項目 | 効果 |
| ---- | ---- |
| ドキュメント処理 | 70% 削減 |
| リサーチ | 40% 削減 |

これにより、顧客に提供する価値は下準備の作業から、税戦略についての助言へと移っています。Jason 氏は、EY は 100 年の歴史を持つ会社であり、技術は変わっても基本は変わらず、事業の土台は信頼だと述べています。エージェントの導入でも、ガバナンスを組み込んで顧客から信頼され続けることが重要だという考えです。

**プログラムで役に立ったもの**

最も価値があったものとして、Jason 氏は **Frontier Accelerate** を挙げています。Microsoft と多くの時間を使い、顧客との構想（envisioning）、概念実証（PoC）、デプロイを速く進め、価値の議論に早く入れるようになったとのことです。Copilot specialization と Agentic Business Solutions specialization は、現場で顧客や Microsoft のフィールドに対して、実績と人材の育成が裏付けられていることを示すのに役立っているそうです。

さらに Frontier transformation engineering badge にも期待しており、hypervelocity engineering の研修を多数の社員に行っています。非エンジニアも参加しており、かつて CRM を構成していたビジネスアナリストのように、顧客のドメインや業界を理解している人が、コードを書いたことがなくても VS Code をインストールし、HVE Core を入れて、バッジの取得に取り組んでいるといいます。

### 5.5 エージェント型のパートナー体験

Heather 氏は、Microsoft とのやりとりをエージェントと AI でより良くする取り組みを 1 枚のスライドにまとめています。

| 区分 | 内容 |
| ---- | ---- |
| 今利用できるもの | Partner Center AI assistant、licensing navigator、partner marketing center pro |
| 近日提供（1 月までに） | Partner Center の health dashboard、sales recommenders、Partner Center for Sales |

- **partner marketing center pro**：キュレーションされた GTM コンテンツを取得し、自社のロゴを入れて、そのまま市場に出せるセルフサービスの仕組みです。多言語に対応しています。
- **health dashboard**：年初のパートナービジネスプランで立てた目標に対して、現在の位置を確認できます。遅れている領域では、次に取るべき行動や利用できるリソースも示されます。
- **sales recommenders**：Microsoft が持つシグナル（Web サイトへの訪問、イベント参加、問い合わせなど）をもとに、話をすべき顧客を推薦します。アカウントの一覧だけでなく、なぜ推薦するのか、次の最善の行動は何かまで示されます。
- **Partner Center for Sales**：パートナーと Microsoft の営業担当者を結び、共同で co-sell を進める Teams 上の環境です。

### 5.6 Frontier に向けた 4 つの発表（Steve Thomas 氏）

**(1) Agentic Partner Capability Score（近日提供・現時点では未提供）**

間接リセラーと小規模な SI（システムインテグレーター）が、エージェントの構築とデプロイにビジネスを移していくことを狙ったものです。取り組むほどプログラム内でポイントが貯まり、そのポイントによって将来の designation や specialization に早く到達でき、インセンティブへのアクセスも早まります。Steve 氏はこれを「ビジネストランスフォーメーションのためのもの」と位置づけています。

**(2) Frontier Partner Specialization（Partner Center で登録可能）**

トップクラスのチャネルパートナーと SI が対象です。顧客のために AI エージェントやプラットフォームを構築、管理、デプロイ、ガバナンス、セキュリティ確保している大手企業を想定しています。Steve 氏自身が「基準は非常に高い」と述べています。Copilot、Fabric、Foundry など複数の製品にまたがる専門性が必要で、他の specialization と、個人が取得する Frontier Transformation Engineering badge によって証明します。

**(3) ディストリビューター向けの認定（名称は不明）**

世界中の CSP ディストリビューターが対象です。ディストリビューターは、マーケットプレイスや共同の P2P の動きを通じてイノベーションを届け、リセラーのトレーニングとイネーブルメントを担っています。そうした役割を認める基準を整えているところで、登録は今日から可能です。リソースは画面のリンクにまとめられています。この項目の正式名称は、トランスクリプトからは確認できません。

**(4) Frontier Accelerate for Marketplace（FAM）**

Steve 氏が「Ignite におけるプログラム面で最大の発表」と呼ぶものです。対象はソフトウェア企業で、組織ではなくパートナーの**アプリ（ソリューション、知的財産）**を単位とします。マーケットプレイスでの「構築・公開」「成長」「差別化」の 3 段階に、それぞれ専用のベネフィットが用意されています。

Steve 氏は、「名前を変えただけ」「同じものを別の箱に詰め直しただけ」ではなく、ベネフィットの水準を引き上げ、導線を簡素化し、Microsoft の多様なベネフィットを 1 つの傘の下にまとめたものだと強調しています。

| 段階 | 主なベネフィット |
| ---- | ---- |
| Build and publish | スポンサーシップが最大 $30,000 増加。条件を満たせば現金インセンティブが最大 $80,000 |
| Grow | 顧客案件の獲得や次のアプリ開発のためのスポンサーシップが最大 $425,000 |
| Differentiate | Certified software designation を取得した場合が対象。スポンサーシップはほぼ倍増の最大 $2.1 million |

このほか、エンド顧客を Azure に移行するためのインセンティブが最大 $160,000 あると紹介されています（どの段階の特典かは、発話では明示されていません）。さらに、Frontier Accelerate for Marketplace の premium offer に登録して支払うと、全段階を通じて**人間のエージェント（human agent）が伴走**します。パートナーからの要望が特に多かったベネフィットの 1 つだと説明しています。

### 5.7 スキリング

Steve 氏は、スキリングを「プログラムの礎（cornerstone）」と呼び（音声認識では "scaling" と聞こえる箇所もあります）、2 つの基盤を紹介しています。

**Partner Skilling Hub** は、新しい 4 つのモダリティを束ねる中心的なプラットフォームです。

| モダリティ | 対象・目的 |
| ---- | ---- |
| Certification ready | エンジニアが designation や specialization に必要な認定を取り、ベネフィットを得る |
| Sales ready | 営業チームが顧客への提供価値を高める準備をする |
| Tech deal ready | プリセールスチーム向けの技術的なデリバリーのスキリング |
| Project ready | デプロイ後のシナリオを対象にした、デリバリー向けのスキリング |

Steve 氏は、これまで技術認定や技術学習は豊富だった一方、プリセールスや営業のライフサイクルへの注力が少なかったと指摘し、この差を埋めるものだと説明しています。

もう 1 つが **Frontier Transformation Engineer badge** です。Skilling Hub に統合されており、認定の取得、Tech deal ready と Project ready の修了、追加のエンジニアリングコースの修了という 3 つの進捗を追跡して、バッジの取得につなげます。なお、バッジが載っているプラットフォームの名称は、トランスクリプトでは "Titan" と聞こえますが、音声認識の都合で表記が確定できません。

1 月に開始されるものとして、次の 2 つが挙げられています。

- **AI Value Accelerator Bootcamp**：営業チームが、案件や顧客との会話に備えるためのブートキャンプです。Skilling Hub で検索できます。
- **消費（consumption）の学習パス**：案件を獲得した後に、導入定着を進め、利用を増やすためのものです。FinOps、セキュリティ、ガバナンスなどを扱います。学習パスの名称は "Cowork ME7" と聞こえますが、音声認識の都合で表記が確定できません。

また、Steve 氏は将来の方向性として、Skilling Hub の 4 つのモダリティを、プログラムの評価にもより深く組み込んでいく考えを示しています。現在、プログラムは「performance、skilling、customer success」で評価しますが、skilling は認定への依存が大きい状態です。今回は発表されていませんが、今後は認定以外への依存を高めていく方向だとして、準備を促しています。

プログラム自体を学べるコースとしては、**GTM Titan**（音声認識の都合で表記が確定できません）が紹介されています。オンデマンドの学習コースで、go-to-market の基礎から co-sell までを幅広くカバーします。

### 5.8 PDM に関する質問、ベネフィットキット

発表の途中で、「PDM を付けてもらえないか」という質問が取り上げられます。質問者は「自分のブースで 3 年連続で最も多い質問だ」と話しています（話者は特定できません）。Steve 氏は、これが直接の答えではないとしたうえで、目的の達成に役立つ 2 つのサービスを紹介しています。

- **Partner concierge**：プログラムについて学ぶためのサービス。GTM のスキリングだけでは足りない場合に、人間のエージェントが一緒に伴走します。
- **Technical pre-sales and deployment**：ソリューションアーキテクチャ、デリバリーの技術面、セキュリティ、Partner Center のアカウント管理などを扱います。

続いて Customer Zero のベネフィットです。現在、ベネフィットキットは launch、core、expanded の 3 種類で、プロダクト、サポート、マーケティングのベネフィットを提供しています。今回の更新は次のとおりです。

1. すべてのベネフィットキット（designation まで）に Copilot Business を拡充する。
2. M365 E7 SKU と、単体の Agent 365 を、modern work と security の specialization のベネフィットに追加する。
3. solution partner designation と specialization に含まれる Copilot Studio のクレジットを増やす。
4. **Advanced benefit kit** を新設する。core と expanded の間に位置するもので、M365 Business Premium や Teams などの生産性 SKU を 25 ライセンス、Azure $3,600 分、Copilot Business と Enterprise Copilot が含まれる。

1〜3 の更新は Partner Center で利用可能になっており、Advanced benefit kit も含めて現在有効だと説明しています。登録・検証済みのパートナーは対象で、登録して活用してほしいとのことです。Steve 氏は、AI の能力を一部の人の専門性にとどめず、組織の強みにしたいという狙いを語っています。

> 補足：1 の「Copilot Business」の部分は、トランスクリプトでは "co-pilot business" と聞こえます。

### 5.9 デバイスパートナー向けの新しい designation（Diana Parker 氏）

Diana 氏は、Frontier の機会は「クラウドからエッジまで」広がり、AI PC は顧客がそれを実感する場所だと説明しています。ローカル処理とクラウドを組み合わせるハイブリッドインテリジェンスと、安全なプラットフォームによって、顧客は安心して AI を導入できるとしています。ただし、デバイスだけでは足りず、パートナーが適切な PC を作り、価値を説明し、デプロイと有効化まで担う必要があると述べています。

そこで今回初めて、デバイスパートナーの能力を認める 2 つの solutions partner designation が MAICPP に加わりました。担う役割は「build、sell、deploy」の 3 つで、designation との対応は次のとおりです。

| 役割 | 内容 | 対応する designation |
| ---- | ---- | ---- |
| Build | 顧客が必要とするシリコン、フォームファクター、機能を備えた商用 Windows AI PC を作る | Solutions partner for Windows devices OEMs |
| Sell | AI PC の価値を説明し、適切なデバイスを提案し、需要を作る | （発表では対応する designation に触れていません） |
| Deploy | PC をデプロイし、有効化し、モダンマネジメントする | Solutions partner for Windows device providers |

既存の solutions partner designation のモデルを土台にしており、プログラムのベネフィット（プロダクトのリソース、サポート、レディネス、go-to-market の機会）が得られます。取得には、performance、skilling、customer success の 3 領域で **100 点中 70 点**が必要です。要件にはデバイス特有の内容が反映されますが、枠組みは既存のプログラムと同じです。

提供開始は 11 月 20 日からとされていますが、Diana 氏は「今週後半に有効化できるようになる」とも述べています。準備は今から始められ、管理者は QR コードから Partner Center の membership dashboard でスコアを確認できます。管理者でない人は、もう 1 つの QR コードから designation について知ることができます。

### 5.10 Specialization

Steve 氏は、specialization を designation の上にある、プログラムの最上位の階層だと説明しています。技術的な能力に強く結びつき、FY27 の会話にも対応づけられるとのことです。

- **M365 Copilot specialization と 4 つの security specialization**（cloud security、data security、identity and access management、threat protection）：いずれも監査（audit）が必須になりました。約 6 か月前の夏頃に、パートナーからのフィードバックを受けて変更されたもので、Partner Center ではすでに反映されています。今年の更新時期に備える必要があります。Copilot の specialization は **Frontier Accelerate for Copilot** の入口にもなっています。
- **Agentic Business Solutions specialization**：Power Automate、Power Apps、Copilot Studio をベースに、自動化やソリューションを構築し、Frontier transformation を進める能力を認めるものです。Partner Center ですでに利用できます。
- **Healthcare の specialization**：業界に特化した初めての specialization です。**Dragon Copilot** をデプロイ、管理、販売する能力を示します。Steve 氏は、specialization のポートフォリオにおける大きな転換だと述べています。

**Digital sovereignty** は、購買サイクルのかなり早い段階で顧客から出る、ビジネス上重要なテーマだとしています。最初の会話では、データレジデンシー、オペレーターのアクセス、AI ワークロードがどこで動くかに目を向ける必要があります。Microsoft は Microsoft sovereign cloud を提供しており、パートナーは sovereign public、sovereign private、sovereign partner ecosystem の全体で役割を担えます。この specialization で認められると、Frontier Accelerate for Azure のうち digital sovereignty に関する支援が受けられるようになります。

**Azure Local** は、ハイブリッドおよび sovereign private cloud 向けです。機密性の高いワークロードを管理された環境にデプロイしたい顧客、ハイブリッドまたは完全な切断環境を必要とする顧客が対象です。Steve 氏は、単発のデプロイにとどまらず、政府・医療・金融などでの複数年の契約を想定してほしいと述べています。最初のデプロイから、移行の相談、準備状況の評価、マネージドサービスの継続までを通して、マネージドプラクティスを築くための明確なロードマップが得られるそうです。

### 5.11 Co-sell

Steve 氏は、co-sell を「プログラムがパイプラインに変わる場所」と呼んでいます。うまくいくパートナーは、co-sell を単発のキャンペーンではなく、プラクティスの中に組み込み、毎月運用する「システム」として扱っているといいます。4 つのステージは次のとおりです。

1. **能力の実証**：designation や specialization など、これまでの発表内容がここにつながります。達成した認定を Microsoft に示して記録する。
2. **アカウントの優先順位付け**：Microsoft が持つ顧客の propensity（見込み度）ツールを使う。
3. **パイプラインの共有と対応**：自社のパイプラインを共有し、Microsoft から届く機会に対応する。
4. **インセンティブとベネフィットの活用**：前述の technical pre-sales and deployment の人的サービスも含めて、案件の成立につなげる。

これらがつながることで、パイプラインの質の向上、案件の進行の高速化、収益性の向上が得られると説明しています。画面のリンクには、このシステムを段階的に解説する動画シリーズが用意されています。

### 5.12 インセンティブ

インセンティブ（現金によるキャッシュバック）は、大きく 2 つに分かれます。

| 区分 | 内容 | 解放される条件 |
| ---- | ---- | ---- |
| 取引ベース | 主に CSP を想定。CSP インセンティブと co-op を解放する | capability score。performance、skilling、customer success の capability score で最大 25 ポイント（聞き取りの都合で、細部は確定できません） |
| エンゲージメントベース | MCI（Microsoft Commerce Incentives）のプラットフォーム。資金支援付きの envisioning、PoC、デプロイなどを解放する | designation と specialization |

Steve 氏は、取引ベースのインセンティブを agentic の方向へ進化させている最中だと述べ、これは発表の冒頭で話した内容にあたる、と補足しています。

その他の発表は画面にまとめられており、関連するセッションへの参加が促されています。特に ASFP や PSFP を使っている人には、サポート関連のセッションが役立つとのことです。

## 9. まとめ

MAICPP は、Microsoft とパートナーを結ぶ単一のプログラムで、Frontier に向けて、差別化、スキリング、go-to-market、co-sell、インセンティブを一体で進めるものです。今回の発表の中心は次の点です。

- ソフトウェア企業向けの **Frontier Accelerate for Marketplace**（build、grow、differentiate の 3 段階で、最大 $2.1 million のスポンサーシップなど）
- 近日提供の **Agentic Partner Capability Score** と、すでに登録できる **Frontier Partner Specialization**
- デバイスパートナー向けの **2 つの新しい solutions partner designation**（100 点中 70 点が必要）
- Copilot、M365 E7、Agent 365 を加えたベネフィットキットの拡充と、新しい **Advanced benefit kit**
- Partner Skilling Hub の 4 つのモダリティと、Frontier Transformation Engineer badge
- 4 つのステージで運用する co-sell と、取引ベースおよびエンゲージメントベースの 2 種類のインセンティブ

発表の最後の呼びかけは、Customer Zero に取り組み、自分に合ったプログラムのベネフィットに登録すること、そして全部に手を出さず「1 つの行動を起こす」ことでした。
