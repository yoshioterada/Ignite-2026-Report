## 1. はじめに

## 5. 発表内容の詳細

### 5.1 導入：エコシステムの規模と FY27 の優先事項

Gustavo 氏はまず、6 月末に終わった FY26 と、FY27 の Q1 についてパートナーに謝意を示しました。Microsoft のパートナーエコシステムは、世界で 50 万社を超え、アジア太平洋では 10 万社に届きつつあると説明されています。当日夕方には Partner of the Year の表彰イベントがあり、会場にいる Partner of the Year Award の対象となったパートナーに拍手が呼びかけられました。

FY27 は、3 つの優先事項と、アジア全体で 1 つのエンドツーエンドのストーリーで始めたとのことです。

| 優先事項 | 発表での説明 |
| --- | --- |
| 変革（transform） | 製品とエコシステムの両面で最大の資産である install base を「スーパーパワー」として使い、AI の能力で提供内容を変革する |
| 活性化（activate） | enablement だけでは足りない。営業チームやパートナー担当チームが、オファーを実際に動かせる状態にする |
| スケール（scale） | 機会が非常に大きいため、規模を出す。そのために GTM（go-to-market）を agentic にする。パートナーのビジネスモデルによって、個別の対応が要る部分と、エージェントで進められる部分がある |

### 5.2 これまでの成果と、市場の見方

過去 15 か月の進捗として、次の点が挙げられました。

- Azure の CSP の成長で 1 位（Gustavo 氏は「ABCs」という言い方をしており、細部は聞き取り不明瞭です）
- Microsoft 365 の CSP の成長で 1 位
- Copilot でも 1 位

1 位なのになぜ Microsoft はさらに求めるのか、という質問に対しては、市場の成長が「パーセントではなく倍率」になっているからだと答えています。新規参入者には install base がなく、それを収益化できないが、Microsoft には install base と製品の両方があるため、自分たちを変える力がある、というのが理由です。

また、Satya Nadella 氏が当日朝の発表で Copilot を「operating system for work」と話したことに触れ、これが今回の機会だと述べています。

### 5.3 パートナーからのフィードバックと事例

Microsoft は、AI の経済性の明確化、予測可能な co-sell（音声上は "call sell" と聞こえ、表記が確定できません）、それに沿ったプログラムを、7 月 1 日から開始したと説明しました。過去は、7 月中旬に発表して 10 月に動き始める形だったが、今年は 7 月 1 日から稼働させたとのことです。パートナーからのフィードバックの多くはすでに反映されており、今後も歓迎するとしています。

Gustavo 氏は、課題や、成約したい案件があるときは、**後からではなく、進行中に、具体的に** Microsoft に伝えてほしいと繰り返し述べています。

### 5.4 Rachel Bondi 氏との対談

Gustavo 氏が 3 つの質問を投げ、Rachel 氏が答える形です。

**質問 1：今後 12 か月（まずは残り 7 か月）の SME&C の最大の機会と、AI が顧客の需要をどう形づくっているか**

Rachel 氏は、今回アジアから来場した顧客が過去最多で、技術の進みが速いため最新情報を得に来ていると述べています。顧客は Microsoft のプラットフォームのストーリーと、パートナーと一緒に進められる点を気に入っているそうです。顧客から聞く内容は 3 つです。

1. **Copilot とそのビジョンを理解したい。** 顧客の Copilot のイメージは 2 年前で止まっていることがある。Cowork の登場や、当日見た Autopilot、Workspaces を紹介し、Copilot が multimodal であり「UI for AI」であることを伝え続ける必要がある。Microsoft 社内では、Autopilot の版を 5 か月使っており、社内で最も使われているエージェントになっている。
2. **クラウドへの移行の指針が欲しい。** AI の話になると、顧客はすぐにクラウドへの移行を考える。一部の市場では Fabric の成功が大きな前進になった。データだけでなく、セキュリティと、インフラ・データ・セキュリティそれぞれのアーキテクチャを整える話でもある。
3. **業界別の事例が欲しい。** 直前の顧客ラウンドテーブルでも、金融サービスの顧客が「最初に作るべきエージェントは何か」と尋ねた。パートナーは、どの業界に強いかを明確に伝えてほしい。顧客はプラットフォームの話を聞くと、すぐに具体的な use case と事業への影響を知りたくなる。

Gustavo 氏は、これらがすべてパートナーの収益機会（近代化の後の継続的な managed services や retainer を含む）だと補足しています。

**質問 2：顧客が選ぶパートナーに求める「スーパーパワー」は何か**

変わらないのは、信頼できるアドバイザーであり、成果とビジネス価値を示してくれることです。新しいのは次の 2 点です。

- 顧客は **月次の技術レビュー**（最新の技術と、できること）を求めている
- 顧客は、パートナーが自分自身でどう AI を使っているかを聞きたがる

Rachel 氏は、将来のパートナーの姿として、AI を自ら使い、Microsoft プラットフォームの最前線にいて、それを顧客にビジネス価値の言葉で語れる存在を挙げています。Gustavo 氏は、これを customer zero と呼び、顧客の信頼につながると述べています。

**質問 3：パートナーが持ち帰るべき 1 つの行動**

Rachel 氏の答えは、**顧客のビジネスリーダーと話すこと** です。これまでは技術チームと話すことが多かったが、経営層や取締役会は事業部門に「何をしているか」を問い続けているため、Microsoft と一緒にビジネスリーダーに会いに行ってほしいという提案です。そのために作ったアプリを、アジアのすべてのパートナーに提供する、と述べています。Microsoft 社内では、すべての営業担当に展開済みで、このツールを使った顧客との約束が 2,000 件を超えたそうです。次項で紹介します。

### 5.5 Frontier demo builder skill（動画での紹介）

対談の中で、約 90 秒の動画が上映されました。内容は次のとおりです。

- パートナーが苦労するのはアイデアではなく、スピード、一貫性、顧客に合った提示だ、という問題設定
- 営業担当は agentic AI playbook から始め、顧客、デモの種類、業界、use case を選び、国、市場規模、既存の Microsoft 環境、顧客が抱える課題などの情報を加える
- 対象は **13 の業界、77 の業種（vertical）、284 の use case**
- ワークフローが、顧客の文脈に合わせたプロンプトを生成する。そのプロンプトを Cowork に貼り付けてスキルを動かすと、約 4 分で会議用のパック一式ができる
- 生成物は 4 つ：(1) 顧客に合わせた frontier transformation のプレゼンテーション、(2) 顧客自身の言葉で use case を示す HTML のクリックスルー・デモ、(3) 発表者向けの準備ガイド、(4) 会議後のフォローアップ用の顧客向け leave behind

Rachel 氏は、自身の顧客会議の進め方も説明しています。まず通常どおり顧客の事業ニーズをヒアリングし、約 20 分の時点で「業界に合わせた、上位 3 つの use case のデモをしてもよいか」と尋ねます。技術担当のメンバーが同席し、4 分で作ったデモを実行するそうです。会議の終わりに、顧客が自社の技術チームに「4 週間以内にこれが欲しい」と言う例が多いとのことです。

パートナー側への提供については、Frontier Badge パートナーとはすでに進めており、会場のパートナーにも Excel の形で今アクセスを渡すと述べています（「なぜ Excel なのかは聞かないでほしい。アプリはあるが、Excel で渡す」という趣旨の発言）。ビジネスリーダーと話せるよう、今後どう届けるのが良いかは一緒に考えたい、とのことです。

> 補足：use case の数は、動画では 284 と読み上げられましたが、後半の Gustavo 氏の発言では「264 だったと思う」とあり、数字が一致していません。本書では動画の数値を記載しています。

### 5.6 Frontier transformation：4 つのステップと、パートナーの機会

Gustavo 氏は、ビジネスモデル（ディストリビューション、通信事業者の直販、SI、これまでトランザクション中心だったパートナー）にかかわらず、Microsoft の提供するものの上に、自社の IP を築けると述べています。画面には 4 つのステップが示されていますが、実際にはフライホイールに近く、自社の IP を載せるための基準線として使ってほしいという説明でした。4 つのステップの名称は音声からは読み取れないため、以下は語られた順に内容を整理したものです。

- **Copilot**：Satya 氏が話したとおり、仕事の UI であり OS。顧客のセグメントによっては、インターフェースの簡素化と生産性の向上が特に重要になる。Copilot を使うユーザーを増やすのが最初のステップ。
- **Work IQ と顧客データ**：OneDrive、Exchange、Teams などのコラボレーションデータが出発点として最初から使える。次のステップは、顧客自身のデータを IQ の環境に載せること。データベースの近代化と Fabric IQ との統合がその次の段階になる。
- **データの保護と Agent 365**：「従業員が持ち込む AI でいいのではないか」と顧客に聞かれたら、データを守る観点で答える。従業員が入れ替わると情報が持ち出される恐れがあるが、この仕組みならデータを設計段階から守れる。標準機能に加え、Agent 365 の固有の機能もあり、サービスやマネージドサービスの機会になる。
- **エージェントの構築**：エージェントはどのプラットフォームでも作れるが、生産性データ、オペレーショナルデータ、分析データを統合できると特別なものになる。これらは過去に導入したシステム（オンプレミスから近代化したものを含む）にあり、そのデータを AI で公開できる。

発表では、セキュリティ、データの近代化、サービスの IP、GTM の力の 4 つの観点で、各機会にどう取り組むかが示されています。GTM については、長年築いた比類のない力を入り口として使うことが語られました。パートナーには既存の顧客関係と契約の仕組みがあるため、顧客が AI を使っていなければ AI を導入し、データベースを近代化していなければ Fabric に載せる、といった提案がしやすいという考えです。同時に、新しい領域や新しいコストセンター・利益センターに売る力を一緒に育てる必要がある、とも述べています。

### 5.7 FDE の実践と AI native な SI

Gustavo 氏は、ここ 6 か月で frontier partner になることについて何度か話してきたと述べ、agentic GTM と customer zero に続き、技術面の話をしました。

- 会場に **FDE のプラクティス** を持つ人がいるかを尋ねています。FDE は「deployed engineers」を表すと説明され（聞こえたままの表記です）、顧客と共同開発・共同創造する市場の動きだとしています。顧客と継続的に価値を生んできたのがこの形だとのことです。知らない場合は調べてほしい、持っていない場合は自社なりの形と価値提案を考えてほしいと述べています。
- FDE の柱は技術的な深さです。顧客が始め方を知らない場合は、顧客との共同投資が重要になることもあります。
- 長く同じ形で事業を続けることのリスクにも触れています。Microsoft 自身も、ライセンスからクラウド、AI へと転換してきた経験があるそうです。
- 市場では「AI native SI」や「AI native パートナー」と呼ばれる会社が、システム統合のプロジェクトを全く違うやり方で考えている。見積もりに工数を使わず、アセスメントも、大量の書類も作らず、実際にエージェントで作業をする。顧客に価値を出すまでの期間が非常に短い。
- Rachel 氏のデモのように、デモだけでなく、PoC や、顧客がその日から使えるものまで作れる体制を持つことを勧めています。その仕組みがない場合は、Microsoft の partner solution architects を活用して一緒に作りたいとしています。

### 5.8 パートナーマーケティング（Lily 氏）

Lily 氏は、Asia Partner Marketing Team の PMM の一員として、パートナーの CMO と連携し、Microsoft のマーケティングのリソースやプログラムの使い方を支援していると自己紹介しました。

**クイズ（「Miss Busters」と聞こえます）**

4 問のクイズで、正解者にプレゼントを配る形でした（選択肢が読み上げられていない問題があり、選択肢は分かりません）。

| 問 | 内容 | 答え・説明 |
| --- | --- | --- |
| 1 | B2B の購買担当が営業と話す前に、いくつの接点（touch point）があり得るか | 答えは C。2026 年の最新調査に基づき、後の発言で「28 の接点」と説明された |
| 2 | FY27 に Microsoft がアジアで計画しているパートナー向け投資で最大のプールはどれか | 答えは A の **co-op 資金**。パートナー・インセンティブ・プログラムで得る収益の **40%** が co-op 資金に入る。Microsoft とパートナーの共同投資で、需要創出、スケール、人員、研修などに使うマーケット開発資金。他の選択肢として、TPM、ローカル資金、show step（聞き取りのまま）、MCI ワークショップなどがあるが、最大は co-op |
| 3 | アジアの co-op のうち、顧客の需要創出に使われている割合は | 目標は 50%（最新の調査で、世界のトップパートナーは co-op の少なくとも半分を需要創出に使うため）。アジアの実態は **36%** で、3 分の 1 強にとどまる |
| 4 | 自社のマーケティングのビジネスインパクトを測っていないパートナーの割合 | Omdia の最近の調査で、**ほぼ半数** が測っていない（アジアではなく世界の数字。アジアはもっと良いと思う、との補足） |

Lily 氏は、CXO の人は CMO と co-op のマーケティング計画や ROI を確認する時間を取ってほしいと述べています。また、28 の接点のそれぞれに、適切なオファーと顧客向けメッセージで十分なリソースを割くために co-op を使えるはずだと説明しています。「測らなければ継続的な改善も繰り返しの実行もできない」とも述べています。

**frontier partner の 3 つの習慣**

*習慣 1：顧客の需要創出に資金を使う*

調査では、62% のパートナーがマーケティングに使う割合が 10% 未満という状況（発話は「62% of the partners invest less than 10% of their dollars on marketing」）で、frontier の最良のパートナーは co-op の **72%** を需要創出に投じているとのことです。マーケティングの形式は問わず、ソーシャル、デジタル、コンテンツ、テレマーケティング、プロダクト、イベントなど何でも歓迎だと述べています。

事例として、アジアの小さな SI である Novatech（綴りは聞き取りのまま）の CEO Justin 氏が紹介されました。「Road trip with Copilot」として、Copilot のロゴを貼ったキャンピングカーを購入し、チームと一緒にアジアを回る 20 か所のツアーを今期（Q2）に実施中です。「copilot lab on the move」「copilot coffee chats」「copilot discovery session」を、街ごと、ビルごとに行っているそうです。留守を預かるマーケティングチームとテレセールスチームが、道中で得たリードを追跡し、第 1 週、第 2 週、第 4 週と、発見から成約までの流れで進めています。Lily 氏は良いマーケティングかどうかは別として、パートナーの情熱と粘り強さを示す例だと紹介しました。

*習慣 2：プログラムとオファーを最大限に活用する*

frontier partner は、メニューを知り、価値を重ね（stack）、活性化し、積極的に成約につなげます。Q1 の実績として、**プログラム利用率 300%**、**Copilot トライアルの目標達成率 140%** が挙げられました。「プログラムが多すぎる」という声に対し、Q2 に開始したものを、3 つの柱（1: 聞き取りが不明瞭ですが需要創出・パイプライン構築に当たる柱、2: 案件の加速、3: 利益の拡大）に整理した 1 枚のマップが示されています。整理すれば、それほど多くはない、というのが Lily 氏の主張です。新しい発表やプログラムを、構造化してチームに持ち帰ってほしいと述べています。

*習慣 3：ターゲットを定め、測る*
