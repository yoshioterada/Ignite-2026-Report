# THR938 Partner Skilling as a Growth Lever for Revenues & Profitability

## 1. はじめに

このセッションは、Microsoft Partner Skilling 部門が、パートナー企業向けのスキル開発（skilling）を「収益と利益率を伸ばすための投資」として説明する短いセッションです。登壇者は、Microsoft が自社の営業データベースとスキルデータベースを突き合わせて分析した結果と、外部調査会社 Forrester によるパートナーへのインタビュー調査の結果を並べて紹介しています。

後半では、Frontier（発表では用語の定義は語られず、人とエージェントが協働する顧客の進化段階や、Frontier ワークロードという文脈で使われています）に向けた新しいスキルプログラムが紹介されます。中心は、2026 年 6 月に開始された **Frontier Transformation Engineer** です。単に知識を学ぶだけでなく「実際に使える能力（applied capability）」を示すバッジとして位置づけられています。

## 3. 何に関する発表か

テーマは、パートナーのスキル開発が売上・利益にどれだけ効くのかをデータで示し、そのうえで Frontier 時代に向けて Microsoft が用意しているスキルの仕組みを紹介することです。

登壇者はまず、レーシングカーのたとえで話を始めています。全員の車にニトロブースト（Frontier や AI）が付いている状況では、勝つのは「コーナーをどう曲がるか、ピットストップをどう行うか」というノウハウを持つチームだ、という話です。AI を持っていること自体は差別化にならず、顧客のさまざまな状況に合わせてソリューションを組み立て、複雑な話を単純にしていく力が差を生む、というのが全体の前提です。登壇者は、Microsoft Partner Skilling がスキルのカタログと提供形態（モダリティ）を Frontier レベルに引き上げ、パートナーを十分に備えさせようとしている、とも述べています。

発表の流れは次のとおりです。

1. 冒頭のたとえと、前年のデータサイエンス分析の振り返り
2. Partner Skilling の go-to-market 戦略（Sales Ready、Tech Deal Ready、Project Ready、Certification Ready、マイクロスキリング）
3. 顧客側で起きている変化（IDC の調査、Frontier の 3 段階、顧客の課題）

5. Frontier スキルの新しい取り組み（Frontier Transformation Engineer ほか）
6. Partner Skilling Hub の案内と締め

## 4. 発表者が伝えたいメッセージ

中心のメッセージは、**スキル開発は研修コストではなく、測定できるビジネス投資である**という点です。登壇者は、パートナー企業のスキル担当者が、経営層に「スキル開発の価値」を説明するのに苦労していると述べています。社員を顧客の仕事から離して研修に出すことになり、その時間に見合う価値を示しにくいからです。そこで Microsoft が使った分析手法を紹介し、パートナー自身も同じ方法で価値を示せるようにしたい、というのが意図です。

もう 1 つは、AI の時代に必要なのは製品知識だけではない、という主張です。顧客に向き合う方法論（engagement methodology）を身につけ、「知識」から「実際に適用できる能力」へ進むことが勝ち筋だと説明しています。

## 5. 発表内容の詳細

### 5.1 前年の分析結果と、今回の再実験

登壇者は、前年の同じシアターのセッションで、Microsoft Research の **double machine learning** アルゴリズムを使い、自社の営業データベースとスキルデータベースに対してデータサイエンスの実験を行った結果を話したと振り返っています。そのときの結果は次の 2 つでした。

| 項目 | 結果 |
| --- | --- |
| スキルを受けたパートナーと受けていないパートナーの比較 | スキルを受けたパートナーのほうが **3.2 倍** 改善 |
| Project Ready のトレーニングを受けた学習者を持つパートナー | **4.3 倍** の影響（influence） |

今回は、同じ実験を Frontier の製品レベルでやり直した、と説明しています。

### 5.2 Partner Skilling の go-to-market 戦略

Microsoft は、顧客案件のライフサイクル全体でパートナーを支援する、という考え方でオファリングを用意しています。単なる認知（awareness）にとどまらず、関心（intent）を知識に、知識を「実際に適用できる能力」に変えていく流れです。

顧客案件には、会話を始める人、ソリューションをまとめる人、実際に構築する人がいます。そのため、パートナー組織のあらゆる役割を支援する、という方針で次のカタログが整理されています。

| カタログ | 対象と内容 |
| --- | --- |
| Certification Ready | 基礎となるドメイン知識。高度なロールベース認定と基礎認定の両方を扱う。登壇者は「最低限の共通基盤（lowest common denominator）」と位置づけている |
| Sales Ready | 営業担当者向け。顧客との会話に使えるインテリジェンスを提供する |
| Tech Deal Ready | ソリューションの組み立て方を学ぶ。ソリューションアーキテクチャからコスト要素を引き出し、部材表（bill of material）を作成し、効果的な提案書を作るところまで。SA やチャネルパートナーの助けになっているとのこと |
| Project Ready | 設計・デプロイのノウハウ。すべてのソリューション領域をまたぎ、開発者・ビルダー向けに Level 300 と Level 400 のコンテンツがある |
| マイクロスキリング | 最小限の時間で全体像を把握したい人向けの新しい提供形態。営業・技術の両方のジャーニーがある |

登壇者は、スキル提供の方法論とモダリティ（形態）を進化させてきたと説明しています。

### 5.3 顧客側の状況：IDC の調査と Frontier の 3 段階

顧客側の状況として、IDC の調査が紹介されています。登壇者の説明では、2030 年までに機会が 2026 年または 2027 年比で 4.5 倍の速度で増え、**3.1 兆ドル**の機会になるとされています。同時に、AI ユーザーの 65% がすでにこの曲線に遅れ始めている、という数字も挙げています（数字は聞こえたまま記載しており、前提条件までは発表で詳しく説明されていません）。登壇者は、顧客は取り込みたいと思っている一方、パートナー側がノウハウの面で遅れているかもしれず、そこを解決したいと述べています。

Frontier の姿は、次の 3 段階で説明されています。

1. **ステージ 1**：人がアシスタント（Copilot や Cowork）を使う
2. **ステージ 2**：エージェントと人がチームになり、一緒に問題を解く。主従や師弟ではなく、チームワークとして捉える
3. **ステージ 3**：人が主導し、エージェントが運用する（human-led, agent-operated）。人がビジネス目標と SLA を決め、エージェントが実行する

この進化の途中で、顧客は「プレッシャーポイント」に直面するとして、登壇者は次を挙げています。

- **拡大する AI 資産の管理**：調査では 2030 年までに世界で少なくとも 5 億（half a billion）のエージェントが存在するとされており、組織内のエージェントの棚卸しや追跡をどうするかが課題になる
- **AI が広がる中でのセキュリティと信頼**：信頼は Microsoft のあらゆる取り組みの中核であり、セキュリティをどう高めるか
- **承認された AI ソリューションの利用拡大（adoption）**：エージェントを作ることと、マーケティングや調達を含めて利用を広げることは別のノウハウである

> 補足：登壇者は「5 つのプレッシャーポイントがある」と述べていますが、トランスクリプトで具体的に説明されているのは上の 3 つです。残り 2 つは発表では確認できませんでした。

登壇者は、利用・消費（consumption）の拡大は多くのパートナーにとって重要なスキルだと述べ、消費を軸にしたスキルプログラムがあることにも触れています（「ME7」と聞こえますが、音声認識の都合で表記が確定できません）。

### 5.4 スキル投資の効果：inside-out と outside-in

登壇者は、スキル投資の価値を示すために 2 つのアプローチを取ったと説明しています。

- **inside-out**：Microsoft 内部の機械学習実験。営業（コマーシャル）データベースとスキルデータベースを double machine learning で分析し、スキルを受けたパートナーと受けていないパートナー、あるいはスキルの度合いが高いパートナーで、売上も連動して動くのか、関係は直線的なのかを調べた
- **outside-in**：Forrester に依頼し、パートナーへのインタビューで同様の収益性調査を行った

double machine learning は Microsoft Research の成果で、オンラインで調べられると登壇者は述べています。この実験手法は、パートナー自身が経営層にスキルの価値を示す際の参考にもなる、という位置づけです。

**Microsoft 側の分析結果**

登壇者の説明では、Microsoft 側で約 300 万人をトレーニングし、パートナー側で約 100 万人を認定した、直近 1 年間（"last year" と発話）の影響を測定したところ、**92.4 億ドル**（9.24 billion）の影響（influence）を生み出した、と述べています。これはパートナーの総売上の約 **14.96%** に相当します。

**Forrester の調査結果**

スキルに多く投資したパートナーのグループでは、ROI が **217%** 向上したと説明しています。登壇者によると、これは売上（トップライン）と利益（ボトムライン）の両面の ROI です。具体的な点は次のとおりです。

- 営業・プリセールスの準備が進んだことで、商談サイクルの日数が短くなっている
- デリバリー・運用の場面では、あるパートナーの事例研究で、特定の顧客案件について **6,790 万ドル**（67.9 million）の純マージン（net margin）が測定された

登壇者は、これらの結果を、スキル開発はビジネス投資であり、その価値は今や測定できる、という根拠として示しています。

**コア製品と Frontier の比較**

同じ数字を掘り下げると、GitHub、Copilot Studio、Microsoft Foundry、Fabric などの Frontier ワークロードでは、コアワークロードよりも価値の加速が大きいことが分かったと説明しています。

### 5.5 Frontier Transformation Engineer

登壇者は、2026 年 6 月に **Frontier Transformation Engineer** を開始したと説明しています。これは、業界で使われる FDE（forward deployed engineer）の手法に対する Microsoft の答えだと位置づけられています。Frontier Partner Summit を開催して多くのパートナーを招いたとも述べています。

実績として、次の数字が挙げられています。

- 受講登録したパートナーの学習者：**37,000 人以上**
- バッジを取得（マッチ）した人：2,300 人以上 / 2,500 人（発話で揺れがあり、最後には 2,500 人がバッジを取得したと述べています）

登壇者は、これを業界でも高い水準のバッジだと述べ、競合の FDE バッジとの比較も勧めています。競合には認定に偏ったものやコースに偏ったものがあるのに対し、このバッジは複数の要素を組み合わせたものだという説明です。

**対象となる人物像**

登壇者の説明では、想定しているのは次のような人です。

- 経験 10〜15 年程度で、コンサルティング的な考え方を持つ
- インフラ、アプリ、データ、セキュリティなどを、左から右まで通しで理解している
- 顧客の前に 2〜3 週間座り込み、素早くディスカバリーを終えて、**エージェント型の MVP** を持ち帰る

**3 つの柱**

| 柱 | 内容 |
| --- | --- |
| 認定（Certification） | プロコード開発者だけでなく、ビルダーも対象。認定として A 103、AB 100、GitHub 300 が挙げられ、さらに GitHub 600 を追加するところ（認定名は音声認識の都合で表記が確定できません） |
| Project Ready ワークショップ | 設計とデプロイのノウハウを学ぶ。開発者向けは Azure の Agent 関連トレーニング（Microsoft IQ、Fabric、Agent 365 を使用。名称は音声認識の都合で確定できません）。ビルダー向けは Copilot Studio を使い、GitHub Harness（聞こえたまま）を Copilot Studio の中でどう使うか、Work IQ や Fabric IQ などの IQ とどうつなぐか、さらに観測の層にあたる Agent 365 とどう連携させるかを学ぶ |
| 方法論 | 製品スタックだけでなく、顧客への関わり方（engagement methodology）を教える |

方法論について、登壇者は次の点を強調しています。

- 製品に詳しいだけでは不十分で、顧客のソリューションをうまく進めていく知恵が必要である
- 今は、人間をエンドユーザーとするアーキテクチャを作る時代ではなく、エンドユーザーが自律的に動くエージェントになりうる。そのため設計の考え方が根本的に異なる
- 顧客に最初に「解こうとしているのは 5 万ドルの問題か、50 ドルの問題か」と問いかけ、顧客の考え方を転換させることが大切（発話では "$50,000 problem $50 problem" と聞こえます）

これらは **hypervelocity engineering** と呼ばれる方法論の中で教えており、Frontier Center of Excellence や業界向けのコンテンツ、コースもあると説明しています。全体では **96 時間**分の学習内容です。登壇者はこれを、applied capability（実際に適用できる能力）の典型例だと述べています。

### 5.6 その他の Frontier バッジと AI ロールプレイ

Frontier のバッジは、すでに 3 つ提供されています。

- Frontier Transformation Engineer
- Frontier Executive
- Frontier Sales Professional

加えて、**1 月**中にさらに 4 つのバッジを提供できるよう準備していると述べています。

Frontier Sales Professional（FSP）には、Frontier の営業向けトレーニングコンテンツがあり、さらに AI を使ったロールプレイ会話が追加されたと紹介されています（"second nature based" と聞こえますが、製品名の表記は音声認識の都合で確定できません）。営業担当者は AI を相手に提案の練習ができ、AI が提案の出来を評価します。

登壇者はこうした一連の取り組みを **Titan framework** と呼んでいます（Frontier Transformation Engineer が 1 つ、Frontier Sales Professional が別の 1 つ、という説明でした）。これらはすべて Partner Skilling Hub で提供されています。

### 5.7 Partner Skilling Hub と締め

登壇者は、Partner Skilling Hub で次のコンテンツが利用できると案内しています。

- マイクロスキリングのモジュール
- **Tech Deal Ready アクセラレーター**：顧客シナリオを与えられ、アーキテクチャがどうなるかを考え、アーキテクチャの各ポイントを順にたどってコストや部材表を作る練習ができる
- 短時間で学べるコンテンツと、長時間のコンテンツの両方。ジャーニーとして Proficient（熟練）ジャーニーと Titan ジャーニーがある（聞こえた表記のまま）

登壇者は、Partner Skilling Hub のブースに立ち寄って質問してほしい、このセッションの後でも話せる、と述べて終えています。Partner Skilling Hub について、改善点のフィードバックも歓迎しています。
