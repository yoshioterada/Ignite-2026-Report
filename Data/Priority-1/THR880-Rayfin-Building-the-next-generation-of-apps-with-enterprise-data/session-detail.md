# THR880 Rayfin: Building the next generation of apps with enterprise data

## 1. はじめに

このセッションは、コーディングエージェントで作ったアプリケーションを、企業のデータに安全につないで本番環境で動かすための仕組み **Rayfin** を紹介する 25 分のシアターセッションです。

エージェントを使えばアイデアから動く POC まで数分で到達できます。しかし、企業の本番環境ではデータベース、認証、バックエンドの設定、既存データへの安全な接続、コンプライアンスとガバナンスへの準拠が必要です。Rayfin はこれらを、アプリを **Microsoft Fabric** に公開（publish）することで引き受ける、という位置づけで説明されます。後半では、Rayfin 向けの新しいツール **Fabricator** のライブデモと、一般提供（GA）を含む Ignite での発表内容が紹介されます。

## 4. 発表者が伝えたいメッセージ

Ben 氏の主張は、**コーディングエージェントで作るアプリに、エンタープライズのコントロールを最初から組み込める**ということです。ソフトウェア開発者はデータベースの準備、認証の配線、バックエンドの構成、既存の顧客データへの安全な接続を、会社のコンプライアンス・ガバナンスのルールに従って行う必要があります。IT 管理者は、ルールが守られ、適切な人だけが適切なデータにアクセスできるようにする責任があり、この新しい世界ではむしろ難しい仕事を負っている、とも述べています。

事例面では、Microsoft 社内でもデザインチーム、財務チーム、プロダクトマネージャーが、自分たちのデータの上に安全にアプリを作っていると紹介しています。

## 5. 発表内容の詳細

### 5.1 エージェント時代のアプリ開発と、本番に必要なもの

発表者の周りでは、友人や家族を含め、ほぼ全員がエージェントでアプリを作っています。自宅の生活管理用のアプリを作る段階から、企業の本番環境に移る段階になると、エージェントが標準で出してくれるものだけでは足りなくなる、と述べています。

### 5.2 Rayfin の仕組み

Ben 氏は、Rayfin を次のように説明しています。

* **コーディングエージェントは選べる**：GitHub Copilot app（Rayfin プラグインを利用）、Power BI Desktop アプリ（今週 Power BI チームが発表した新機能）、パートナーの Replit。どれを使っても構いません。
* **エージェントは Rayfin の SDK と CLI と対話する**：SDK により、アプリ全体を**コードで定義**します。データスキーマ、関数、ポリシー、ストレージなど、アプリが動くために必要な要素（プリミティブ）をコードで定義するため、エージェントがそれらを理解して操作しやすくなる、という説明です。
* **ローカルで実行できる**：定義したものはローカルで動かせます。
* **公開すると Fabric 上にリソースが作られる**：共有する準備ができたら Fabric に公開します。データベース、ストレージ、データコネクタなどが Fabric 内にリソースとして作られ、エンタープライズ規模とガバナンスが最初から付いてくるとしています。

実績として、Rayfin と Fabric apps は 6 月に公開され、数か月で **10 万を超えるアプリがデプロイされた**と述べています。数だけではなく、アプリを作る人の種類が広がっている点を、最もうれしい点として挙げています。

### 5.3 Fabricator

Fabricator は、Rayfin を使って Fabric app を作る新しいツールです。Sachin 氏は、もともとアプリケーションをテストするために自分が始めたオープンソースプロジェクトだと話しています。社内の多くのビジネスユーザーが使い始め、「Fabric apps を始めるのがずっと簡単になった」という反応があったため、**翌週（as of next week）に Microsoft のオープンソースプロジェクトとして正式に移す**予定だと述べています。

Fabricator の特徴として、次の点が語られています。

* 必要な SDK やツールのセットアップが必要だが、最初にそれらを**自動でインストールし、手順をガイドする**。
* 新しいプロジェクトを始めると、基本的なアプリケーションの骨組みを作り、正しい SDK とツールをインストールする。
* アプリケーションをローカルで起動する。Rayfin アプリケーションをローカルで実行する機能は、Ignite でリリースされたもので、公開前に開発ループを素早く回せる。
* 自分がアクセスできるワークスペースの一覧表示や、新規作成、キャパシティの割り当てもできる。

### 5.4 Rayfin と Fabric app の違い

よく聞かれる質問として、Ben 氏は次のように答えています。**Rayfin は Fabric app を作ってデプロイするためのツールセット**であり、Fabric にデプロイされたあとは、Fabric のガバナンスの仕組みがすべて使えます。

### 5.5 6 月以降に追加された機能

6 月のパブリックプレビュー時点の Fabric app は、認証、セマンティックモデルへの接続、MSSQL データベースで構成されていました。その後、次のものが追加されています。

| 時期 | 追加された機能 |
| --- | --- |
| FabCon Europe | functions、MSSQL に加えて Postgres のサポート |
| （時期は発話で特定されていないが、デモで紹介された機能） | Private sites：Fabric のサイトにアクセスすると自動でログイン画面が出て、認証前にクライアント側のコードも見えない。すべての Fabric app でデフォルトで有効 |
| Ignite | storage（画像やファイルは OneLake に保存）、app telemetry、custom claims、Fabric IQ への接続、admin app portal、CSP サポート、共有機能の追加、Pro ライセンス対応 |

Ignite で追加された機能の中身は次のとおりです。

* **app telemetry**：自分でメトリクスやログを設定・確認したいという要望が多く、さらに重要なのは、**エージェント自身がメトリクスやログを照会して、アプリの問題を診断できる**ことだと説明しています。発表者はこれを日常的に使っているそうです。
* **custom claims**：既定の Entra ロールを超えて、アプリ内で独自のロールとアクセスを定義できる。
* **Fabric IQ への接続**。
* **admin app portal**：発表者が「大きな注力点の 1 つ」と呼び、今後数か月も力を入れて進めるとしている領域です。テナント管理者が、作成されたアプリケーションを把握し、コントロールできるようにします。エージェントでのアプリ作成が進み、テナント管理者の見えないところでアプリが作られている現状への対応という位置づけです。ガバナンスのハブから、管理者は作成されたすべてのアプリを見られます。アプリをブロックするなどの操作もできます。たとえば、フロントエンド側で誰かが電話番号を共有してしまった場合にブロックできる、という例が挙げられています。（ハブの名称はトランスクリプトでは「OneLink governance hub」と聞こえ、音声認識の都合で表記が確定できません。）
* **セキュリティ機能**：CSP サポートがアプリケーションに組み込まれる。
* **共有機能**：アプリへのアクセスをリクエストできる。アプリを共有する際に、そのアプリが使うすべてのリソースを確認でき、アプリだけでなく背後のリソースへのアクセス権をオン・オフで切り替えられる。
* **Pro ライセンス対応**：発表者の記憶では翌週に提供開始予定で、Power BI Pro ライセンスで Fabric app を作れるようになる。

### 5.6 一般提供（GA）と始め方

Ben 氏は、Ignite 最大の発表として、**Rayfin と Fabric apps が一般提供（GA）になった**と発表しています。始め方として、次の入り口が挙げられています。

* **Fabricator ツール**：aka.ms/fabricator（もしくは間もなく Sachin 氏の GitHub）からダウンロードできる。
* **Power BI Desktop**：レポートだけでなくアプリも作成できる。中身は Fabric app。
* **GitHub Copilot app**：発表者がアプリを作るときによく使う方法で、Rayfin プラグインがある。
* **Replit**：Fabric のデータに安全につなぎたい場合に使える。

## 6. デモ・手順

このセッションにはライブデモがあります（Sachin 氏）。画面は音声から見えないため、以下は発話で語られた範囲に限ります。

### 6.1 デモ 1：タスクトラッカーを作ってローカル実行し、公開する

1. Fabricator を起動します。必要な SDK やツールが自動でインストールされ、完了するとページが表示されます。
2. 新しいプロジェクトを開始します。基本的なアプリの骨組みが作られ、SDK とツールがインストールされ、完了するとアプリがローカルで起動します。
3. 「simple task tracker を作って」と指示します。時間の都合で、単純なアプリを作ると断っています。エージェントは入力を解釈し、UI とともにデータベースが必要だと判断します。
4. 変更内容を確認します。語られたのは次の点です。
   * **データサービスが有効化**された。デプロイ時にこのアプリにデータベースが必要だと伝わる。
   * **Task クラス**が作られた。UI で作ったタスクのデータを保存するもので、Rayfin SDK の **entity デコレーター**が付いている。デプロイ時にデータベースのテーブルに変換される。
   * ロールとポリシーが定義され、**すべてのタスクは作成者本人だけが見て編集できる**。別のユーザーには見えない。
5. アプリに戻り、タスクを入力してチェックを付けます。ここまでローカルで動いています。
6. Fabricator には別ユーザーの視点でテストする機能があるため、ローカルにテストユーザーを作成します。RLS が働いていることを確認し、自分のユーザーに戻すと、自分のタスクだけが見えます。
7. ワークスペースの一覧表示や新規作成、キャパシティの割り当てを行い、アプリを公開します。公開時に Fabric に接続してデプロイします。このアプリはデータベースが必要なので、データベースが作られ、接続されます。Fabric の認証も組み込まれ、別途 Entra アプリケーションを設定する必要はありません。
8. デプロイ後、アプリに戻ります。Fabric の認証が自動で組み込まれており、ログインが必要です。ローカルでデータを入れていたものとは別に、デプロイ先は新しいインスタンスなので、データベースが新しく作られ、ノートも新しいセットになっています。これらのデータは OneLake に現れ、その上に別のアプリを作ったり、下流の分析に使ったりできると述べています。

### 6.2 デモ 2：以前に作ったダッシュボードアプリ

Sachin 氏は、以前に作った「あらゆる機能を詰め込んだ」アプリも見せています。

1. 「セマンティックモデルに接続して、ダッシュボードを作って」と依頼して作ったアプリです。セマンティックモデルがあり、とてもカスタムな見た目のダッシュボードを作りたい、という典型的な Fabric app のタイプだと説明します。
2. Foundry モデルにも接続しており、リクエストに対して LLM の推論ができます。
3. 「去年、最も成長した地域は？」と尋ねます。モデルがクエリを生成し、ユーザーのスコープで実行できます。
4. 「売上の推移をチャートで見せて」と頼むと、推論してチャートが作られます。チャートをダッシュボードにピン留めし、チャートのノートも追加できます。
5. 裏側で Rayfin が作ったものとして、次を説明します。
   * セマンティックモデルに接続する**コネクタ**。ユーザーの資格情報を使うため、データに RLS やポリシーがあれば尊重される。
   * Web サイトのホスティング。キャンバスとビジュアルは React アプリケーションで、そのファイルも Fabric 上にホストされる。
   * Fabric の認証の配線。別途 Entra の認証アプリを作って承認・接続する必要がない。Fabric アイテムとして表示されるため、認証に Fabric が使われる。
   * ビジュアルを保存するための**データベーステーブル**。
   * ノートを保存する**ファイルストレージ**。
6. Fabric 上で、データベース（全テーブル付き）、ビジュアルのノートのストレージ、コネクタ、**function**（シークレットを持てる。シークレットストアが付属しており、Foundry に接続できる）が作成されていると見せます。アプリの読み込み回数などのメトリクスも、すぐに使える形で得られます。

## 7. 注意点・発表者の気付き

* エージェントが出す成果物だけでは、データベース、認証、既存データへの安全な接続、ガバナンス準拠といった企業の要件を満たすには不十分だ、というのが前提の主張です。
* ローカルでユーザーごとの見え方（RLS）を試してから公開する流れが、デモで示されています。
* 発表者は、エージェントでアプリを作る人がテナント管理者の可視性の外で増えていることを課題として挙げ、admin app portal を重点領域としています。
* Pro ライセンス対応の提供開始（発表者の記憶では翌週）と、Fabricator の Microsoft オープンソースへの移行（翌週の予定）は、発表時点の予定です。
* 発表では、GA でのリージョンや価格、制限事項などには触れていません。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

* **アイデアから POC まで数分**で到達できるエージェントの速さを活かしながら、本番向けのコントロールを組み込める。
* データベース、ストレージ、コネクタ、認証が Fabric 上で自動的にプロビジョニングされ、エンタープライズ規模とガバナンスがそのまま使える。
* ユーザーの資格情報で動くため、データの RLS やポリシーが尊重される。
* アプリのデータが OneLake に入り、他のアプリや下流の分析で使える。
* IT 管理者側は、admin app portal でテナント内のアプリを把握し、必要ならブロックできる。
* 事例として、Microsoft 社内でデザイン、財務、プロダクトマネージャーのチームが自分たちのデータにアプリを作っている。公開以降のデプロイ数は 10 万を超えている。

## 9. まとめ

Rayfin は、コーディングエージェントで作るアプリを、Fabric に公開することでエンタープライズ向けの運用に乗せる仕組みです。アプリを SDK でコード定義し、ローカルで試し、Fabric にデプロイすると、データベース、ストレージ、コネクタ、認証、メトリクスが用意されます。

デモでは、Fabricator でタスクトラッカーを作って RLS を確認し公開する流れと、セマンティックモデルと Foundry モデルをつないだダッシュボードアプリの中身が示されました。Rayfin と Fabric apps は Ignite で GA になり、Fabricator、Power BI Desktop、GitHub Copilot app、Replit から使い始められます。
