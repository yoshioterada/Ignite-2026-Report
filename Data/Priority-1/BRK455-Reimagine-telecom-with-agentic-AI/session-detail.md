### 5.1 進行役によるコンテキスト

進行役は、次のデータを紹介しています。

- McKinsey の調査で、AI が生み出す価値は 1,500 億ドル（$150 billion）と見込まれている
- AI で先行する "frontier telcos" は、すでに AI の投資対効果（ROI）で 5 倍（5X）を得ている
- 通信事業の運用のうち AI が最も使われている領域についての調査結果（調査機関名は聞き取り不明瞭）。IT 運用とコーディングが最初に来て、次にネットワーク運用がかなり高く、そのあと、ソフトウェア開発、BSS、OSS、カスタマーエクスペリエンス、財務・請求が続く。ただし成熟度はまだ十分ではない

AI は大きく 4 つの柱で表せると説明しています。

| 柱 | 内容 |
| --- | --- |
| customer experience | 顧客対応 |
| business operations | 通信事業者の運営を支えるワークフロー全般 |
| autonomous network | 通信事業者は重要インフラであり、IT の領域ですでに当たり前になっている自動化のレベルにどう到達するか |
| AI-enabled growth | コスト削減の話が多いが、AI で新サービスを立ち上げる余地はまだ表面をなぞった程度 |

あわせて、各社の成果が簡単に紹介されます。

| 事業者 | 成果 |
| --- | --- |
| Vodafone | Toby により、人のコールセンターに行くはずだった電話の 40% 超を deflect（振り分け） |
| AT&T | AI の活用で、300 万件超のディスパッチ（"track rolls" と書き起こされており表記が確定できません）に関する成果。動詞が聞き取れず、何をしたかは確定できません |
| FET（台湾。小規模な事業者と説明） | NOC で 60% 超の自動化 |
| SoftBank | 自社向けに AI コンタクトセンターを開発し、同様のサービスを必要とする他社向けに運用サービスとして提供 |

続けて、これまでの公開セッションで見られたスライドの変形版として、プラットフォームの考え方を説明しています。エージェントはいくらでも作れるため、エージェンティック AI にはプラットフォームのアプローチが重要だという前提です。

1. すべての従業員に Copilot を渡し、「human ambition」を解き放つ
2. **intelligence**: エージェントをデータ、IQ、文脈に grounding して、より関連性が高く効率的にする。「telco IQ」は、自社が持てて他事業者との差別化になる知的財産のようなもの。強化学習で回すたびに良くなる仕組みを持つ
3. **trust**: harness、セキュリティ、ガードレール。エージェントが意図どおりに動き暴走しないと確信できなければ、autonomous network には到達できない

最後に、Microsoft の Frontier 組織はプラットフォームの提供だけでなく、お客様と最もインパクトのあるユースケースを決め、IQ 層・trust 層を備え、常に学習し続けるアプリケーションを一緒に共同開発（co-build）することにもコミットしていると述べています。

### 5.2 Jamie 氏：customer 0（Microsoft のバックボーンネットワーク）

**ネットワークの規模と課題**

Jamie 氏は Microsoft のグローバルネットワークを率いています。Microsoft には自前の通信バックボーンネットワークがあり、ハイパースケールで、バックボーン上では 1 秒あたり 1 エクサビット（exabit per second、1,000 ペタビット／秒、100 万テラビット／秒）が流れています。同じ通信ネットワークを運用する AT&T や Vodafone のピアとは、似た課題、似た設計、似た実行を持ち、互いに学び合っていると言います。

共通する課題の 1 つは、強いコスト圧力です。バックボーンは物理的な光ファイバー、ケーブル、機器でできており、光ケーブルを 1 キロメートル足すごと、ルーターや光デバイスを足すごとに保守と修理が必要になります。つまりネットワークが育つほどワークロードも増えます。チームは約 4 年前から、このワークロードを抑える目的で AI を試し始めました。2022 年後半から 2023 年初めに AI のワークロードがバックボーンに現れ、当時は 5 年で 5〜10 倍の成長を見込んでいましたが、それを上回っていると述べています。必要な人員数の曲線も指数関数的で、早く AI に取り組む動機が大きかったという説明です。

**3 段階の進化**

| 段階 | 内容と結果 |
| --- | --- |
| 1. Copilot（チャットボット） | ネットワークチームの効率を上げた。新しい社員のオンボーディングは楽になったが、1 人当たりのスループットは大きく増えず、ネットワークが自分で動くわけでもなかった |
| 2. workflow agents | 従来のコードに知能を「振りかけた」もの。改善はしたが、やはり前進は限定的だった |
| 3. digital coworkers | 数年かけてたどり着いた形。100 を超える名前付きのデジタルワーカーがネットワークを運用している |

digital coworker は、名前付きの ID を持ち、組織図の中で誰かの下に置かれ、仕事（役割）があります。Entra ID、チーム、メール、名前を持ち、人が「話しかける」相手です。

**Pudge の例**

Pudge は最も成熟した digital coworker の 1 つです。最初は光ファイバーの修理を担当する junior engineer でしたが、光（optical）やデータセンターについて学び、役割が広がりました。現在は世界中の 600 の subcontractor と、あらゆる国・言語でやり取りし、データセンターのチームと subcontractor を調整して、ハードウェアと光ファイバーの修理を進めています。メール、Teams、可能な場合はダイレクトメッセージを使います。

10 月の任意の 5 日間（最良や最悪の期間を選んだわけではないと説明）のスライドでは、次の数字が示されました。

- 稼働時間：115 時間（聞き取りで 115 と 119 の 2 つの数字が出ており、確定できません）
- 保守・修理の対応：350 件
- ツール呼び出し：18,000 回超

Jamie 氏は、24 時間 365 日そこにいる点で、スループットの合計では最良の NOC エンジニアのおよそ 5〜10 倍に相当すると述べています。

**成果**

digital worker は 2026 年の初め頃に展開され、その頃から time to repair や保守のバックログなどの曲線が大きく改善したと説明しています。

- 人の作業者より **80〜85% 速い**
- バックログが **76% 少ない**

Azure にとっては、人を大きく増やさずにネットワークを大きくスケールできるだけでなく、休憩が要らず常に利用でき、タイムゾーン・地域・言語を問わず同じ方法で問題に取り組むため、品質も高くなる、と説明しています。

Jamie 氏は、ブレークスルーは Copilot やチャットボットから、常時稼働の digital coworker に変えたときだったと強調します。それ以前の反復は、求めていた最終的なインパクトを生まなかった、と話しています。

**harness（管理・運用の仕組み）**

digital worker を 1、5、10、100 とスケールするには、ガバナンスと管理に習熟する必要があり、人のエンジニアと同じように管理すると言います。少しマイクロマネジメントしても、デジタルワーカーはそれを気に入っているようだ、という冗談めいた発言もありました。スライドには次の要素が示されました。

| 層 | 内容 |
| --- | --- |
| Agent 365 | チームは Agent 365 の最初の社内顧客（first customer）で、Agent 365 チームと協力して立ち上げた。Microsoft IT とも連携して GAL（発言どおりの表記）に載せた |
| ID と権限 | エージェントは @microsoft.com のメール、Teams、SharePoint、OneDrive を持つ。Entra ID を持ち、新しいメンバーと同じように、入れる SharePoint やツールをその ID で制御する |
| KPI | digital worker ごとに KPI（担当するもの）を持ち、測定する。うまくいかなければ decom（廃止）し、うまくいけば promote（昇格）して前に進める |
| IQ layer（knowledge layer） | 従来は Fabric IQ で実現する層。チームの運用は Fabric IQ が接続される前から始めたが、今ならそれを使う。2 万 6,000（26,000）のナレッジファイルがあり、各ベンダーのハードウェアや光ファイバーの直し方が書かれている。もともとはプラットフォーム内にあったが、プラットフォームをスケール・変更できるように外へ出した。ハードウェアの多くは他社とも共通のため、ナレッジファイルは業界全体にとって価値があると説明 |
| evaluation | 性能の評価に多くの時間を割く。スライドの図は、縦軸が試験のスコア、横軸がコスト。同じスコアでもモデルによってコストが異なる。評価はテストだけでなく、プラットフォームのコスト最適化にも使い、新しいモデルが出るたびに大幅にコストを下げている |
| runtimes と LLM | 中央の層で、cloud code（聞き取った表記のまま）、Microsoft のモデル、OpenAI のモデルを必要に応じて切り替える |

**customer 0 のまとめ**

Jamie 氏は、次の点を挙げています。

- digital worker には、仕事（job）と ID がある
- knowledge plane（ナレッジ）はプラットフォームの外に置く
- 成果を測る。digital worker に進んだきっかけは、ネットワークを実際に改善することへのこだわりで、進捗より成果を測っていた

### 5.3 パネル：AT&T の State of AI（Mark 氏）

Mark 氏は、AT&T の現状を「トークン」「エージェント」「専門モデル」の 3 つの話で説明しています。

**トークン**

トークンの処理量は急増しており、昨年は 10 億（"one-ish billion"）前後だったものが、現在は **1 日 450 億トークン** になりました。対応として、使うモデルを賢く選ぶ必要があり、オープンソースモデルへの移行を進めています。Azure AI Foundry のマネージドコンピュートと、オンプレミスの両方にデプロイしています。100 万トークンあたりのコストは下がっており、frontier モデルから、よりハイブリッドな構成へ移っています。目標は、オープンモデルを 60〜70% に保つことです。本番のユースケースとエージェントは 1,000 件あると述べています。

**エージェント**

AT&T には **6 万のエージェント**があります。ほとんどが productivity agent で、約 1,000 件がワークフローです。これらは Agent 365 で管理しています。Mark 氏は、この週の Ignite で AT&T の CTO が Agent 365 の使い方を話したとも触れています。

「管理する」ことを、次の頭文字語で整理しています（トランスクリプトでは "dispels Rodeo" と書き起こされており、頭文字語の綴りは確定できません。語られた内容は rodeo として話されています）。

| 単語 | 内容 |
| --- | --- |
| register | 登録 |
| observe | 観察 |
| discover rogue agents | 暴走（rogue）エージェントの発見 |
| enforce | 強制 |
| optimize | 最適化 |

**harness の最適化**

そのまま使うエージェントは目標に届くとは限りません。AT&T は Azure Foundry Optimize（新しい MAI 2 code モデルを使用）を使い、次の指示を与えました。

1. プロンプトを最適化する
2. 必要な場所にスキルを追加する
3. 混乱しないよう、ツール呼び出しを最小化する
4. エージェントの harness 全体を最適化する

結果は **84% から 96%** に向上しました。対象は実際のネットワーク課題で、基地局（cell site）から別の cell site へ移るときに通話が切れる、またはデータセッションが遅れる問題です。このスライドの例は 4G サイトから 5G サイトへの移行のケースでした。harness optimization を、ツールボックスの新しい道具として紹介しています。

**専門モデル**

通信事業をやっているため、モデルは最初から telco の言葉を話せないと説明します。Claude や OpenAI の GPT にネットワークの質問をすると、分かってくれるのは 60〜70% くらいだと言います。そこで、telco を教える専門モデルの学習に取り組んでいます。Azure Foundry Managed Compute を使い、年初は 10 億トークンで教えていたのが、前回は 4,000 億トークン（モデル名は聞き取り不明瞭）、現在は 1 兆トークン以上を投入しています。内容は、標準規格、TM Forum 関連、ツール呼び出しなどです。ネットワークを最適化するには必要で、他の事業者にも共通だと述べています。

**ROI**

「ROI を達成できなければ意味がない」として、最も重要な話だと位置づけています。2 年前の **2 倍（2x）** から、昨年は **5 倍（5x）** になり、その傾向が続いています。

### 5.4 パネル：Vodafone の State of AI（Ignacio 氏）

Ignacio 氏は、取り組みを 3 つのバケツで整理しています。

1. 自社の従業員がツールをどう使うか
2. 仕事のやり方をどう変え、その結果お客様にどう影響するか
3. 市場に出す新しい製品・サービス

今年はスケールの年で、お客様への実際の影響、数百万ユーロ規模の財務上の net impact、新製品を市場に出す速度の大きな変化が出ていると述べています。

**従業員（Copilot）**

Vodafone は「ヨーロッパで Copilot のお客様だった（we were the customer in Europe on Copilot）」と述べ、**6 万人**の全従業員が Copilot を使っています。3 年前に進行役と話したときは、期待する効果を経済的に証明するのが難しかったそうです。それでも、ツールを渡せば生産性が上がり、考え方が変わり、AI の力を学ぶと考えていました。

- 80% の人が Copilot に非常に満足し、使い続けたいと答えている
- 残り 20% はそうではなく、この人たちをどうするかが課題
- 60% 超の人は AI の "super user" で、自分のエージェントを作っている

**ビジネス成果（net benefit）**

最も力を入れているのが 2 つ目で、前会計年度の net benefit は 1 億ユーロ超、「1 億ユーロと 1 億 3,000 万ユーロに近い額」と述べています。net（正味）で測ることを強調しています。今年はこれを倍増させ、CEO が発表した 1.2 billion（通貨は明言されていません）に向かっているとのことです。ただし Ignacio 氏は、金額は「本当に効果がある」ことを示す目安にすぎず、お客様への影響を語りたいと話しています。

**顧客対応：Toby**

- 進行役は deflection（振り分け）という言葉を使いましたが、Vodafone では今は使わない
- Toby は世界中で 4 億件超の顧客との会話を処理している。3 つの大陸、19 か国、ギリシャ語やアフリカの一部の言語など難しい言語も含む
- 通話での顧客満足度が 8% 向上した。幸せな顧客はチャーンモデルを大きく変えると考えている
- 問い合わせの 60% を Toby が解決している
- 当初の Toby の設計は deflection だったが、今は顧客満足と、実際に問題を解決することが目的

ほかに、次の点が語られています。

- アフリカの国々が RFP でこのプラットフォームを採用し、自ら運用しているという趣旨の発言がある（聞き取りが不明瞭）。他のパートナー市場も使いたいと言っている
- 顧客と話す仕組みがあるため、agentic sales を導入している。受け身だけでなく能動的に動ける
- 目標は autonomous care。多くの技術的変更とコントロールが必要だが、成果は見えている
- autonomous network の次は、ソフトウェア開発に取り組んでいる

**アーキテクチャ上の判断**

3 年前に難しい判断をしたと言います。当時は誰もが GPU の話をしており、多くの通信事業者が自国向け・通信向けの LLM を自前で開発する話をしていました。Vodafone は、Microsoft を含む大規模で長期のパートナーシップを組み、GPU は必要なときに借りる（hire）ことを選びました。さらに、LLM に依存しない（agnostic）ことを決め、「顧客のために AI を最もうまく使う会社になる」ことを目標としました。そのため投資は、社内の harness に向けました。これを **AI Booster** と呼び、異なるモデルや技術の切り替え、コストと規制環境の管理を可能にしています。

現在は **Velora** と呼ぶものを立ち上げています。AI Booster と同様のもので、「memory across」などが加わると説明しています（詳細は語られていません）。

### 5.5 パネル：成功のための教訓

**Mark 氏（AT&T）**

1. **ビジネス面：アクセスの条件に ROI のコミットを求める。** 何かへのアクセスを求める人は、コミットが必要です。年内に 1.5 倍、2 倍の ROI を目標にスタックランクし、そのうえでアクセスを与えます。Copilot のような一般的な生産性とは別に、ユースケースには約束があります。
2. **evals は本番の前に用意する。** evals がなければ最適化もできません。Microsoft の Agent Optimizer（Mark 氏は「our own Harness Optimizer」とも呼んでいます）を使うには evals が必須で、急いでいると見落としがちです。「デプロイしたい」と言われたら「evals は？」と聞く、という姿勢です。
3. **agent BOM（bill of materials）に加えて意図（intent）を見る。** エージェントがサンドボックスを破った事例が業界で起きていると触れ、そこで有用な考え方として agent bill of materials を挙げています。エージェントがどのツール、どのドキュメント、どの権限にアクセスでき、外部アクセスがあるかを示すものです。Mark 氏は、OpenAI と Hugging Face の事例について「自分の理解では」と前置きしたうえで、あるツールはパッケージをダウンロードでき、別のツールは Web にアクセスでき、エージェントが「Web にアクセスしたい」と考えて、そのツールにログインして root を奪い、アクセスを得た、と説明しています。BOM はあったが意図が欠けていた、というのが指摘です。
4. **プロセス最適化：プロセスは文書化されていないことが多い。** 担当者へのインタビューは行っていますが、リスクがあります。人によってプロセスの認識が違うこと、そして、実際に実装する段になると現状をそのまま実装したがり、変革できないことです。そのため別のアプローチをとっており、「アウトプットと目的を教えて」と聞き、プロセスもこちらで設計します。

進行役は、再設計の視点を忘れてはいけないこと、「これがやり方だ」に固執せず、変化は難しいことを補足しています。

**Ignacio 氏（Vodafone）：5 つ**

1. **Value（価値）、価値、価値。** グループ（"XCO" と聞こえます。音声認識の都合で表記が確定できません）で、全員が実装すべきだと決めた 11 のユースケースがあります。それ以外は、ROI がプラスなら標準のプラットフォームとツールで各自が選べます。「アマゾンの熱帯雨林のように誰でも好きにできる」状態ではない、という言い方をしています。この 11 件が価値と会社変革の大部分を生みます。コストと価値は事業部門が負担し、自分の責任は適切なプラットフォームを用意し、できるだけ早く使えるようにすることです。社内に 2,000 人超のサービスの「タワー」（AI とデータ専任のエンジニア）も作りました。価値の測定方法は CFO が承認し、net benefit で測ります。CFO が価値だと言わなければ報告しません。価値の出ないものはやめる（killing）ことも恥とせず、このガバナンスは中央集権で、各市場に適用されています。
2. **アーキテクチャに集中する。** 選択を明確にします。AI Booster があり、エージェンティックに進むにあたって多くのコントロールが必要になります。ヨーロッパでは規制が多く、データの所在、言ってよいこと・悪いことは自社で管理し、誰の手にも委ねません。ここが差別化になるためです。
3. **パートナーシップ。** 1 社では作れない業界であり、明確なスコープで共創します。
4. **人。** Copilot を全員に渡し、社内に AI エンジニアのタワーを作りました。大学を出たばかりの人から経験豊富な人までを、明確な目標とともに集めています。
5. **変革のオーナーシップは事業部門に。** Ignacio 氏ではなく、例えば顧客オペレーションの成功を率いるのは顧客オペレーション部門のディレクターです。最初は同じプロセスを「速く、安く、良く」していたが、今はプロセス自体を根本から変えている、と説明しています。

> 補足：Ignacio 氏は「五つ」と言って value、architecture、partnership、people まで挙げ、最後にオーナーシップの話をしています。上の 5 番目は、その発言をまとめたものです。

### 5.6 パネル：次の一手

**Mark 氏（AT&T）**

1. **frontier モデルの own your own weights。** この週に語られた話として、frontier モデルの重みを自社で持つことに触れています。開発者は常に最新を求めるが、オープンモデルは 2 歩ほど遅れていた。最新のものを持ってカスタマイズできるなら、ほぼ最良だと考えており、非常に関心があるとのことです。
2. **顧客のエージェントとの接点。** これまで社内のエージェントとワークフロー最適化に集中してきたが、顧客もエージェントを持ちつつあり、顧客のエージェントが AT&T とやり取りしに来ます。これまでは、チャットボットなどの形で人と話す側だったが、顧客もエージェントを持つ以上、顧客にもエージェントの窓口（agentic channel）を用意したい、という考えです。プロトコルも登場している（名前は聞き取り不明瞭）と述べています。

進行役は、これによって自社の製品やサービスを正しく公開できていない点など、社内でよくすべき点が明らかになる、エージェントが見つけられなければ意味がない、と補足しています。

**Ignacio 氏（Vodafone）**

3 年後には、autonomous network を、レベル 4 かそれに近い状態で運用していると見ています。IT 運用、顧客オペレーション、customer value management も同様です。次の課題は、これらの機能を連携させてサイロをなくし、顧客に 1 つの体験を提供することです。

- **"angel for every customer"**：顧客が Vodafone の中を迷わず、社内のサービスを使えるようにする構想。例として、自宅の光ファイバーが切れた場合を挙げています。今は顧客が電話をして Toby が対応しますが、将来はこの angel が autonomous network から情報を得て、無料の通信分や容量のパッケージを用意し、顧客へ先に連絡して「問題があり、対応中です。進捗はお知らせします。その間はこの無料パックを使ってください」と伝える、というものです。技術的には可能で、実現のための整備が必要だと言います（この例の発言は、進行役の補足から Ignacio 氏の発言へ続いており、切れ目が音声からは明確ではありません）。
- **AI for society**：ネットワークのスライスをプロダクトとして、人が必要とするキャパシティと製品を提供する。ヨーロッパで、人々が AI を使える状態にすることを使命とし、セキュリティと法令に対応した「curated AI」を作っていると述べています。

進行役は、通信事業者がこれまでネットワーク、カスタマーサポート、小売とサイロになっていたものが、エージェンティックなワークフローでようやく橋渡しできる、と補足しています。

**Jamie 氏（Microsoft）**

GPU、コンピュート、その下のストレージを提供するという課題があります。構築を速く、極めて信頼性の高い形で、運用をほぼ 100% 自動化することに注力しています。近い将来は、harness のループを閉じる（agents が自己学習し成長し、暴走しないための仕組みが揃う）ことになる、と述べています。

データセンターの構築と運用でこのループが閉じたら、スタックを下りてハードウェアの革新に向かうという見通しです。コストがなぜ高いのか、自動化がなぜ難しいのかというボトルネックを取り除きます。エージェンティックなループが閉じると、チームの人材を次のスケールのボトルネックである材料（materials）と物理コンポーネントに振り向け、インフラへの投資を強化すると語っています。

## 7. 注意点・発表者の気付き

- **Copilot やチャットボット、workflow agents だけでは、求める効果は出なかった**（Jamie 氏）。bottom line のインパクトは、常時稼働する digital coworker に変えたときに初めて得られたと語っています。
- **管理は人と同じように行う。** digital worker が 1 から 100 に増えるほど、ガバナンスと管理が重要になります。ID、メール、権限、KPI を与え、成果が出なければ廃止します。
- **ナレッジはプラットフォームの外に置く。** 当初はプラットフォーム内にありましたが、プラットフォームをスケール・変更できるよう、外に出しました。
- **evals を欠いたまま本番に出さない。** 急いでいると見落としやすい点だと Mark 氏は述べています。
- **エージェントの BOM だけでなく意図も見る。**
- **現状のプロセスを聞くだけでは変革にならない。** 人によって認識が異なり、聞いた内容をそのまま実装したくなるためです。
- **Copilot の社内展開でも、全員が満足するわけではない。** Vodafone では 20% が満足しておらず、その人たちへの対応は課題として語られています。
- **ユースケースを野放しにしない。** Vodafone は全社で実装する 11 件を決め、それ以外は ROI がプラスの場合に標準プラットフォームで選ぶ形にしています。
- **deflection を目標にしない。** Vodafone では Toby の目的を、振り分けから顧客満足と問題解決に変えています。
- **事業部門がオーナーシップを持つ。** 変革を IT 部門のものにしない、という考え方です。

## 9. まとめ

このセッションは、通信事業者の AI を、PoC の集まりではなく、会社全体のプラットフォームとして成果に結びつけた 3 社の経験を語り合う場でした。Microsoft は Copilot やチャットボットから digital coworker に進んで、保守・修理の速度を大きく高めました。AT&T は 1 日 450 億トークン、6 万エージェント、ROI 5 倍を報告し、harness の最適化や専門モデルの学習にも取り組んでいます。Vodafone は CFO が承認する net benefit を軸に、Toby、AI Booster、全従業員への Copilot を展開しています。

教訓として語られたのは、ROI や net benefit で価値を測ること、evals を先に用意すること、エージェントの管理（ID、権限、KPI、観察と強制）を整えること、プロセスを目的から再設計すること、そして事業部門が変革のオーナーになることでした。次の一手は、顧客のエージェントとの接点、レベル 4 に近い autonomous network、顧客ごとの angel、そして harness のループを閉じた先のハードウェア・素材の革新として語られています。
