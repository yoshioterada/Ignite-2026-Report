## 4. 発表者が伝えたいメッセージ

発表全体を貫くメッセージは、**セマンティックレイヤーがエージェント時代の土台になる**という点です。ビジネスの指標、ワークフロー、メタデータ、組織の暗黙知といったビジネスコンテキストはセマンティックレイヤーにあり、M365 の会話型分析、コンポーザブルなアプリ、自律的なアクションといったエージェント体験はすべてその上に載る、という考えです。発表者は「Power BI でレポートを作るたびに、実はセマンティックレイヤーを作っている」とも述べています。

もう 1 つは、AI がコンテンツ作成の機械的な作業を肩代わりするようになるので、人間は「作ったものが実際に使われているか」「エージェントに正しい質問をして舵を取り、結果が業務要件に合っているかを検証しているか」に力を注ぐべき、という点です。Sujata 氏は、大量のコンテンツがあっても使われなければ意味がないと語っています。

### 5.2 セマンティックモデルの強みとセマンティックレイヤーの重要性

セマンティックモデルは、企業の指標や KPI を定義する場所で、一貫して信頼できる回答を得るための「AI のアクセラレーター／イネーブラー」だと位置づけられています。ビジネスアナリストが得る数字とエージェントが返す数字を同じにし、組織全体で一貫して使うために、セマンティクスへ投資する必要があるという主張です。セマンティックモデルには、ビジネスに分かりやすいオブジェクト名や推論されたリレーションシップがあり、成熟した API やオープンな標準ファイル形式も備えているため、プロの開発にもエージェント開発にも使えると説明しています。

従来のメトリックレイヤーにも、指標と定義、基本的な結合、単純なフィルター、SQL 集計といったメタデータはあります。これに対して Power BI のセマンティックモデルは AS エンジンに支えられ、DAX によるフィルターコンテキストや、年初来（year to date）、前年比（year over year）といった高度な計算を持ちます。発表で挙げられた機能は次のとおりです。

- 高度な time intelligence（10 種類の時間計算のために 10 個のメジャーを書く「メトリックの乱立」を避けられる）
- 多対多と双方向フィルター
- 同義語（synonyms）
- 計算グループ
- ユーザー定義関数（指標とロジックの再利用）

### 5.3 Apache OSI と Snowflake との相互運用

こうした経緯から Microsoft は、Apache の incubating の取り組み（以前は OSI と呼ばれていたもの）に貢献したと説明されました。これは、軽量なセマンティックレイヤーを一度定義すれば、ベンダーやエージェント体験をまたいで使えるようにするオープンな標準形式です。Power BI のエージェントでも M365 のエージェントでも、他社製のエージェントでも同じコンテキストを使えるべきだ、という考えが背景にあります。

> 注意：この標準の名称は、音声認識では "Apache Oz"、"Ozzy"、"Aussie" など揺れて書き起こされています（音声認識の都合で表記が確定できません）。発表者自身が「以前は OSI と呼ばれていた」と述べているため、本記事では OSI と併記します。

相互運用の例として、Snowflake との協業が紹介されました。Snowflake Cortex や Snowflake の semantic views を使っていても、Fabric data agents（M365 上）で、Power BI セマンティックモデルのコンテキストを使えるようにしたい、という説明です。具体的には次の仕組みです。

- 各ベンダーが対応する標準形式の「基準となる OSI ドキュメント」がある
- Snowflake での定義と Power BI 固有の計算の間にある差分を扱うため、コンバーターを使う
- コンバーターは GitHub で公開されており、Power BI セマンティックモデルと OSI ドキュメントを相互に変換できる

あわせて、**DAX が OSI の公式な dialect として登録された**ことも強調されました。DAX のフィルターコンテキストによる柔軟なスライス・ダイスの力を、標準の側でも使えるようにすることが、貢献の前提だったと説明されています。

### 5.4 Fabric semantic views（今週発表・プレビュー）

近年、セマンティックモデルを「クリック＆ドラッグ」で作ってきた人がデータエンジニアリングを求められ、データエンジニアがデータ分析を求められるようになっています。この境界の曖昧化に対応するため、「データのある場所でセマンティクスを定義する」機能として **Fabric semantic views** が発表されました。指標と定義を共有・ガバナンスし、「一度定義すれば AI/BI の全シナリオで使える」ことを、オープン標準の上に実現するという位置づけです。

発表で説明された特徴は次のとおりです。

- Lakehouse に新しい入口があり、semantic view を定義するか、ファイルをアップロードして始められる
- メトリックは DAX のフル機能で定義できる
- データセット、リレーションシップ、ビジネスメトリックとその定義を YAML で記述する（Apache OSI の取り組みに対応）
- 同じメトリックが、Power BI のレポート、エージェント、DAX クエリのどこから問い合わせても同じ結果を返す
- 公開 API も用意されており、組織内でエージェント開発をする場合に直接呼び出せる（前のセッションで質問があったため、と説明）

発表者は、数か月前までは "coming soon" と言い続けていたが、今回プレビューとして触れる状態になったと述べています。

| 別のファイル形式 | YAML に加えて、"Tyndall" ファイル（音声認識の都合で表記が確定できません）に対応。アナリストでもエンジニアでも慣れた形式を選べるようにする |
| SQL でのメトリック定義 | DAX だけでなく SQL でも書けるようにし、DAX が得意でなくても使えるようにする |

### 5.5 ビジュアルとレポート作成の改善

発表者は、LinkedIn などでのユーザーの声を見ながら改善していると述べ、最近リリースされた主な改善を駆け足で紹介しました。多くは既にリリース済みで Power BI のブログに掲載されているため、スライドを撮影して確認してほしい、とのことです。

1. **モダンなビジュアルの既定値とデザインリボン**：PowerPoint のように、既定のデザインを選べば最初からきれいなレポートになる体験。テーマペインとカラーパレットで、全ビジュアル・全ページをまとめて更新でき、デザインリボンで素早く探せます。ダークテーマも含まれます。
2. **Web でのフルレポートリボン（プレビュー）**：Power BI Desktop のようなタブとアイコンを備えたリボンを、Web の編集・閲覧で使えます。書式のコピー（format painter）など、Desktop を開かずにできる操作が増えました。「リセットフィルター」ボタンについて不満の声があり、すでに対応済みとのことです。
3. **スライサー**：日付ピッカー（動的／静的な日付）と新しいドロップダウンスライサーが追加されました。「選択済みの項目を先頭に表示」は近日公開です。
4. **テーブルとマトリックス**：列幅の固定（データが変わっても幅が変わらない）、列のプラス／マイナス、自動展開（Excel のようなピボット操作）が使えます。フィルターペインを開かずに、ビジュアル上で直接フィルターする on-visual 体験は近日公開です。
5. **ガントチャート（パブリックプレビュー）**：タスク、期間、進捗をまとめて表示し、Power BI の中でプロジェクト計画を作れます。色に意味を持たせたり、詳細を追加したりできます。軸の自動スケーリング（auto scaling）と条件付き書式にも触れられました。

なお、発表者はガントチャートに「近日公開」とスライド上で書いたまま更新を忘れていたと述べ、すでにパブリックプレビューであると訂正しています。そのほかの機能は、「近日公開」と示したものを除いて、すでに GA だと説明されました（Web のフルリボンとガントチャートはプレビューと説明されている点に注意してください）。

### 5.6 配布：データをユーザーのいる場所へ

ここから Sujata 氏のパートです。「どれだけセマンティックモデルとレポートを作っても、使われなければビジネスへのインパクトは出ない」という前提で、配布の方法が紹介されました。

#### Office エコシステムとの統合

| 連携先 | 説明 |
| --- | --- |
| Teams | 同僚とのチャットから Power BI レポートに直接アクセスできる |
| PowerPoint | スクリーンショットではなく、ライブのレポートをスライドに埋め込める（機密レポートのスクリーンショットは IT 管理者が嫌がる、という趣旨の説明） |
| OneDrive / SharePoint | Fabric を使わないビジネスユーザー向けに、PBIX ファイル（発話では "PBX files" と聞こえます）を置いて開き、スライス・ダイスできる |
| Excel | Power BI セマンティックモデルを Excel から使い、探索できる |
| Outlook Web | ライブのビジュアル共有をパブリックプレビューで提供。メールに静的なスクリーンショットではなくライブのビジュアルを添付でき、ガバナンスを壊さない |

#### Org apps（GA）

Org apps は GA になり、次の拡張が紹介されました。

- 1 つのワークスペースに複数のアプリを持てる（従来は 1 ワークスペース 1 アプリの制限があった）
- Audience 機能で、対象ごとに見せるコンテンツのサブセットを指定できる
- パッケージできる Fabric のアーティファクトの種類が増えた（データサイエンス向けのノートブック、マップ、リアルタイムダッシュボードなど）
- CI/CD に関して、パイプラインに対応。アプリを更新・デプロイする前に変更を加えたいとき、デプロイメントパイプラインを使える

#### エージェント向けの配布：Fabric IQ MCP と M365 Copilot

人間だけでなく、エージェントへの配布も扱われました。

- **Fabric IQ MCP**：セマンティックモデルを含む Fabric 内の各ソースに対し、エージェントが DAX クエリを実行できる。カスタムエージェントを作る場合に、Power BI のデータにつなぐ手段になる
- **Microsoft 365 Copilot の Cowork**：Fabric IQ のプラグインが提供され、ビジネスユーザーがチャットでデータに関する質問をし、信頼できる結果を得られる。セマンティックモデルへの質問と、レポート内のコンテンツへの質問の両方に答えられる
- **Power BI 内**：同じ M365 Copilot の体験が Power BI にも入り、サービス内でレポートを見ることも、自然言語で質問することもできる
- **レポート横の Copilot ペイン**：Fabric IQ が加わり、レポートに表示されている内容だけでなく、その裏にあるセマンティックモデルにも質問できる
- **Copilot から制限する設定**：セマンティックモデルの設定として追加された。オンにすると、そのモデルは MCP や上記の Copilot 系の体験から問い合わせられなくなる。AI 向けの整備が進んでいないモデルを守るための設定（7 章も参照）

会場に「新しい Copilot アプリ（Cowork や code がある）を使っている人は？」と挙手を求め、使っている人がいることを確認する場面がありました。

### 5.7 エージェント開発

発表者は、エージェント開発を 2 つに分けて説明しています。

- **グリーンフィールド**：データの取り込み、変換、モデル作成、レポートやアプリ作成までを端から端までエージェントに作らせる。既存のセマンティックモデルの上にアプリだけを作らせるような小さいワークフローも含む
- **ブラウンフィールド**：要件や条件が変わり続ける既存のレポートやアプリを、エージェントの助けで改善・反復する

#### 土台：Power BI developer mode（GA）

土台は、最近 GA した **Power BI developer mode**（発表では "PDIP format" と聞こえますが、音声認識の都合で表記が確定できません）です。レポートとセマンティックモデルの「コード」にあたる形式で、エージェント開発だけでなく、バージョン管理や CI/CD にも欠かせないと説明されています。さらに、別のコーディングツールでエージェントが加えた変更が、Power BI Desktop に自動で反映されるようになり、再読み込みは不要です。

#### Authoring plugin と Desktop Bridge

発表者は、素の（vanilla）モデルで Copilot などのコーディングエージェントにレポートを作らせて、思うような結果にならなかった経験を会場に尋ね、その理由を 2 つ挙げました。Power BI の各形式を十分に学習していないこと、そしてレポートの見た目を見ていないことです。

そこで次の仕組みが用意されました。

- **authoring plugin**：セマンティックモデルのスキル、レポートのスキル、MCP をまとめたプラグイン
- **Power BI Desktop Bridge**：AI エージェントが Power BI 内のレポートのスクリーンショットを撮れるようにする仕組み。変更しながら自分で検証でき、「このカードがずれている」「切れている」といった指摘を人間が繰り返さなくて済む
- **ブラウザーベースの検証**：サービス上のコンテンツを扱うときに、エージェントがブラウザーで検証する

### 5.8 Fabric apps と report apps

コーディングエージェントはアプリ作成が得意だという流れで、**Fabric apps** が紹介されました。発表では、エージェントが Fabric のバックエンドをゼロから作れる仕組みとして "Raifin"（音声認識の都合で表記が確定できません）が挙がっています。HTML ファイルを作るだけではなく、フルスタックの Web アプリを端から端まで作ります。バックエンドには SQL データベース、コネクター、関数、認証などをまとめて持てると説明されています（一部の語は聞き取り不明瞭です）。

Power BI にとっての利点は、**セマンティックモデルに投資してきたガバナンスやセキュリティが無駄にならない**ことです。アナリストがレポートを作るために使ってきた同じセマンティックモデルを、エージェントがカスタム Web アプリを作るためにも使えます。

Fabric apps が向くのは、レポートの限界を超えたい場合です。

- レスポンシブなレイアウト、カスタム UI コンポーネント、複数ステップのワークフローといった、完全にカスタムな UX が必要
- ワークフローの起動、判断ループ、カスタムコードなど、完全にカスタムなアクションが必要

Power BI 開発チームの John 氏が作ったという Fabric app の例が示され、「これをレポートで作ることもできなくはないが、おすすめしない。コーディングエージェントで Web アプリとして作るべき」と説明されました。インスピレーションを得るために **Fabric apps gallery** も紹介されています。

その他の発表事項は次のとおりです。

- Fabric apps を簡単に作れる "Raven" プラグインがプレビューで発表された（前述の "Raifin" と同じものかどうかは、音声からは確定できません）
- Fabric apps で **関数（functions）** に対応し、LLM のエンドポイントを呼び出すような AI 連携ができる
- サインイン数やアプリのロード回数などを見られる、**標準搭載のメトリック**を追加した
- これらの体験が **Power BI Pro にも提供される予定**（Fabric を必須としない）と発表
- Org apps に Fabric apps を含められる（パブリックプレビュー）。Power BI レポートと Fabric apps を 1 つの Org app にまとめられる
- 作った Fabric apps は **Power BI Mobile** でも動作し、書き戻しやアクション機能を持つアプリもモバイルで動く
- **report apps** の体験を Power BI Desktop に持ち込む。パブリックプレビューで、数週間以内にリリース予定

### 6.1 Fabric semantic views のデモ（Uni 氏）

前のセッションでも同じデモをしたと断ったうえでの実演です。

1. Lakehouse を開き、context と system context のフォルダーを表示する。ここで軽量なセマンティクスを作り、将来的には AI context も置く
2. 「new semantic view」をクリックすると、プレースホルダーのファイルとして schema ファイルと metric ファイルが作られる
3. schema と DAX のメトリックを Lakehouse 内に直接書く。time intelligence も含まれる
4. 別チームが管理する財務の正規メトリック定義を継承したいケースとして、**OneLake shortcut** でそのファイルを Lakehouse にショートカットする。定義の所有者が更新すると、そのメトリックも更新される
5. 裏側では、自分で書いたメトリックと継承したメトリックを組み合わせ、定義したスキーマを持つセマンティックモデルが作られる
6. DAX クエリビューで問い合わせると、前年比成長が 81%、売上が 4,860 万（48.6 million）になる
7. そのセマンティックモデルの上に Power BI レポートを作り、フィルターしても同じ 48.6 million と 81% になる
8. セマンティックモデルを使った sales agent に「どの商品カテゴリの売上が最も高く、前年比成長はどうか」と尋ねると、computers と答え、同じ 48.6 million と 81% を返す

続いて、GitHub Copilot からの操作です。

1. GitHub Copilot で、「地域の営業チームが使える、OneLake に既にあるビジネスメトリック定義は何か」と尋ねる
2. 既存の semantic views のメトリックファイル（DAX で定義されたメトリック）が示される
3. それを、地域営業用の Lakehouse にショートカットで継承する。ショートカットやファイルの作成、不足しているメトリックの追加も、チャットで行える
4. 追加メトリックを加えた semantic view を作成して公開する
5. 公開後のレポートには 2.2 million と 19.1% が表示される。レポートや DAX クエリビュー、M365 のエージェントのどこから問い合わせても、同じ値が返る

> 補足：発表者は、このあとのデモ（semantic view 作成の agentic skills に関するものと思われますが、内容は語られていません）を「時間の都合で省略する」と述べて、ビジュアルの話に移りました。

### 6.2 Rui Romano 氏によるエージェント開発のデモ（Sujata 氏が紹介）

Sujata 氏本人の操作ではなく、Rui 氏が作ったデモを見せる形です。

Lakehouse のデータから、エージェントにセマンティックモデルを作らせ、2 種類のレポートを作らせて、後で選ぶというシナリオです。入力は 3 つです。

- **Markdown ファイル**：命名規則、パーティションの扱い、スタースキーマなどのモデリングのベストプラクティス（シンプルなファイルと紹介）
- **PNG**：デザインの指針（タイポグラフィ、パレット／色、ロゴ）
- **プロンプト**

デモは次の順で語られました。

1. GitHub Copilot アプリで、先に紹介したプラグインを導入する。スキルと MCP が使えるようになる
2. デザインファイルと Markdown ファイルをエージェントに渡す
3. 「この Lakehouse を使った direct link のセマンティックモデルを作り、これらのフィールドを使い、レポートを 2 つのスタイルで作る」という趣旨のプロンプトを与える。スタイル 1 は KPI カードを上に横並び、スタイル 2 は KPI カードを左に配置
4. エージェントが 2 つのサブエージェントを並列に起動して作らせる
5. まず計画を作らせ、人間が計画を検証・確認してから、問題なければ実行を開始する
6. セマンティックモデルが作成され、続いて 2 つのサブエージェントがスタイル 1 とスタイル 2 のレポートを並列で作成する。チャットには、検証中のレポートのスクリーンショットが表示される
7. サービスでセマンティックモデルを確認する。メジャーは命名規則に従い、スタースキーマにもなっている
8. レポートを確認する。スタイル 1 は KPI カードが上、スタイル 2 は KPI カードが左にある

### 6.3 Raven plugin による Fabric app 作成のデモ（Sujata 氏）

1. コーディングエージェント（ここでは GitHub Copilot アプリ）で customize をクリックし、plugins を開く
2. Raven plugin を検索して有効にする
3. チャットで作りたいものを伝える（このコーディングエージェントでは音声入力も使え、自然な言葉で話せる）。例として「Contoso sales ワークスペースのセマンティックモデル（名前は sales and opportunity）を使った Fabric app を作って」と伝える
4. 要件を書いた Markdown ファイルと、先ほどと同様のデザインガイダンスを添付する
5. エージェントが計画を作る。計画を検証し、要件に合っているか確認してから実行する
6. 時間の都合で早送りし、完成したアプリを見せる

完成したアプリについて、次のように語られました。

- 要件にないアニメーションが追加されていた
- カスタムアイコンが入っていた
- ホバーするとツールチップが出て、ユーザーのメールアドレスをコピーできる
- ダークモードとライトモードがある。デザイン要件にダークモードの指定はなかったが、エージェントが自分で判断して作った

### 6.4 Power BI sticker factory app のデモ（関数と AI 連携）

Fabric apps の関数で LLM のエンドポイントを呼ぶ例として、チーム内の開発者が作ったとされる「Power BI sticker factory」アプリが示されました。

1. 画面には生成の候補（suggestions）が表示される
2. カスタムのステッカーとして「say no to pie charts」を指定する
3. 生成のスタイルを選ぶ
4. generate をクリックすると、LLM のエンドポイントを呼び出して、そのステッカーが生成される

作り方の説明は次のとおりです。Foundry 上に OpenAI のエンドポイントがあり、その API キーを、安全な方法でコーディングエージェントに渡して、エンドポイントの呼び出し方を理解させます。

### 6.5 Power BI Desktop の report apps のデモ

1. Power BI Desktop で、新しい report app の体験を作成する
2. 使いたいセマンティックモデルを選び、作りたいものを入力して Enter を押す
3. 先のコーディングのデモと同様に処理が進み、Fabric app が作られる
4. 完成したアプリは、カスタムアプリらしいスタイルで、ダークモード／ライトモードの切り替えなどもある
5. 編集モードに切り替えられ、インラインでタイトルなどを直接編集できる。チャットによる自然言語の指示と、直接編集の両方が使える
6. 公開（publish）できる

## 7. 注意点・発表者の気付き

- **エージェントが作った計画は人間が検証する**：Rui Romano 氏のデモでも Raven plugin のデモでも、実行前に計画を確認することが繰り返し強調されました。
- **コンテンツの量と利用は別物**：AI で簡単に大量に作れても、実際に使われるとは限りません。人間は適切な質問をしてエージェントを導き、結果が業務要件を満たしているかを検証する役割だと説明されています。
- **セマンティックモデルが AI 向けに整っていない場合**：「問い合わせられる状態ではない、散らかったセマンティックモデル」を持つ組織が多いことを前提に、セマンティックモデル単位で **Copilot から制限する設定**が追加されました。設定をオンにすると、MCP や Copilot 系の体験（上記 5.6 のもの）からそのモデルを問い合わせられなくなります。AI 対応の整備には時間がかかるため、整うまでビジネスユーザーから問い合わせさせないために使えるという説明です。
- **素のコーディングエージェントでは Power BI のレポートが期待どおりにならない**ことがある、と発表者が認めています（5.7 参照）。
- **生成 AI は要求外の演出を加えることがある**：Fabric app のデモでは、アニメーション、アイコン、ダークモードがエージェントの判断で追加されました。
- **Fabric apps とレポートの使い分け**：完全にカスタムな UX や、ワークフロー・判断ループ・カスタムコードを含むアクションが必要なら、レポートで無理に作らず、アプリにすべきだという考えです。
- **機能の提供段階**：semantic views、Web のフルレポートリボン、Raven plugin、Org apps での Fabric apps、Outlook Web でのライブビジュアル共有、ガントチャートなどはプレビューです。Org apps、Power BI developer mode は GA。semantic views の SQL メトリックや「選択済みを先頭」「on-visual フィルター」などは近日公開です。

## 8. 利用者にとっての利点

発表で語られた利点を整理します。このセッションでは具体的な顧客事例や成果の数値は紹介されていません。

- **指標の一貫性**：セマンティックモデルや semantic views で一度定義すれば、レポート、DAX クエリ、エージェントのどこから問い合わせても同じ数値（デモでは 48.6 million と 81%）が返る
- **ベンダー間の相互運用**：OSI に対応した標準形式とコンバーターにより、Snowflake の定義などとも行き来できる
- **財務などの正規定義の継承**：OneLake shortcut で、他チームの定義をそのまま継承し、更新にも追従できる
- **レポート作成の手間の削減**：デザインの既定値、テーマペイン、Web のフルリボンなどで、クリック数が減る
- **配布先の広がり**：Teams、PowerPoint、OneDrive / SharePoint、Excel、Outlook Web、M365 Copilot の中でデータを使える
- **エージェントによる作成と自己検証**：機械的な作業をエージェントに任せ、Desktop Bridge で自己検証もさせられる
- **既存投資の活用**：Fabric apps でも、セマンティックモデルに作り込んだガバナンスとセキュリティがそのまま使える

## 9. まとめ

Power BI のセマンティックモデルは、これからのエージェント体験の土台と位置づけられています。そのため Microsoft は Apache OSI に貢献し、DAX を公式 dialect に加え、Fabric semantic views をプレビューとして発表しました。

ビジュアルとレポート作成では、デザインリボン、Web のフルリボン、スライサー、テーブル／マトリックス、ガントチャートが改善されています。配布では Org apps の GA、Fabric IQ MCP、M365 Copilot の Cowork での利用が示されました。

エージェント開発では、Power BI developer mode（GA）、authoring plugin、Desktop Bridge によって、エージェントがセマンティックモデルやレポートを作り、自分で検証できるようになります。さらに Fabric apps と report apps によって、レポートの枠を超えたカスタムアプリもエージェントと一緒に作れるようになります。

一方で、作ることが簡単になるほど、作ったものが使われているか、要件に合っているかを人間が確かめる役割が重要になる、というのが発表者のメッセージでした。
