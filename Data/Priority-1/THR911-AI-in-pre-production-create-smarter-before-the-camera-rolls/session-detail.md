# THR911 AI in pre-production: create smarter before the camera rolls

## 1. はじめに

このセッションは、映画・テレビ・広告といったメディア制作の「撮影前（プリプロダクション）」で AI をどう使うかを扱う 25 分のシアターセッションです。インドの Galleri5 が Azure と Microsoft Foundry の上に作った AI スタジオと、その中核となるクリエイティブ・エージェント「Miro」を題材に、制作コストや制作期間がどれだけ変わるのか、どんな構成で作られているのかが対談形式で語られます。

メッセージは、AI は人の創造性に取って代わるものではなく、クリエイターが「意図」を伝えるとエージェントが計画から実行までを担い、人は承認や判断に集中できるようになる、というものです。大手メディア企業が期待するセキュリティの作り込みや、Microsoft との共同開発・共同の営業活動についても説明されています。

> 注意：このセッションでは、画面を使ったライブデモは行われていません。導入の後、対談に入る前に短い動画が流されますが、動画の内容は音声からは確認できません（スライドと口頭の説明が中心です）。

## 5. 発表内容の詳細

### 5.1 メディア業界での AI と 3 つの課題（Microsoft 側の導入）

Silvia 氏は冒頭で、AI を「おそらく私たちの生涯で最大の変革」と呼び、業界への影響額を **800 億〜1,000 億ドル**と見積もっていると述べています。すでに、メディア分野で働く人の **約 60%** が、AI のおかげで以前はできなかった仕事をしていると答えている、という数字も挙げています。

AI の領域で影響している課題として、**speed gap、scale gap、value gap** の 3 つを挙げています。

| 課題 | 説明（発話の範囲） |
| --- | --- |
| speed gap | 映画をつくるには数か月から数年かかる |
| scale gap | 説明が明示されていません。speed gap の直後に、プロセスが非常に断片化していて端から端まで自動化しにくいこと、受け渡し（ハンドオフ）やデータの断片化が多いことが語られており、どちらの課題の説明かは発話からは区別できません |
| value gap | マネタイズ、パーソナライゼーション、広告収益の成長といった価値を生み出しにくい |

そのうえで、AI がもたらす機会として次の 3 点を挙げています。

1. **コンテンツ制作の革新。** シネマティックな動画を、約 1% のコスト（聞き取りが乱れており、「1 対 100」とも話しています）で作れる。人の才能と創造性を中心に置いたまま、という前提つき
2. **メディアのインテリジェントなオーケストレーション。** ハンドオーバーを乗り越え、メディアのプロセス全体にわたって知能を組み合わせる
3. **メディアのマネタイズ向上。** 大規模なパーソナライゼーションで、広告の効果を高める。消費者ごとに、興味や個性に合わせた広告を届けるイメージ

事例として、Galleri5 のコンテンツ制作のほか、次の 2 件にも触れています（詳細は話されていません）。

- **Kantar**：これまで考えられなかった速度と規模で動画を分析できる
- **Premier League**：**18 億人**のファンとのやり取りを大規模にパーソナライズする。これまで不可能だったとのこと

そして、ユースケースごとではなく **プラットフォームとして** 取り組む考え方を紹介しています。クリエイターを中心に置き、副操縦士（copilot）のようなやり取りを備え、**multi-model by design**、コンテキストと harness を使って、意味のあるワークフローを実現し、**セキュア by design** で信頼できるもの、という構成です。ショート形式と、中〜長尺の形式の両方に使えると説明されています。

### 5.2 Galleri5 のクリエイティブ・エージェント

動画の上映後、Galleri5 側が「Gallerify AI Studio」と、物語をシネマティックな動画に変換するために作ったクリエイティブ・エージェントを紹介しています。このエージェントは、**創造的な意図を高品質なシネマティック動画に変換する**ものです。すでに AI による TV 番組を 1 本作り、現在は AI による映画を制作中だと述べています。動画は、プロンプトを工夫してやり取りするのではなく、意図を説明するだけで作れるとのことです。これがエージェントの基本的な役割だ、という説明です。

### 5.3 成果：コスト・期間・試行回数

Galleri5 側は、AI が映画、テレビ、広告映画といった創造産業に浸透して以降、次のような数字が見られると述べています。

| 項目 | 内容 |
| --- | --- |
| 制作費 | 1 億ドルの映画が、約 1,000 万ドルになりうる |
| 制作期間 | 3 年の制作サイクルが、最短 3 か月に圧縮されうる |
| セット | 映画で 1 つだけでなく、数百のセットを持てる。その分、数百の創造的な可能性がある |
| 事前の検討 | 放送前に、多くの事前計画と A/B テストができる |
| ローカライズ | ある地域で作った番組を、言語・文化・習慣・伝統に合わせて他地域に展開できる。すべてを撮り直す必要がない |

エージェントの効果として、動画モデルを自分でプロンプトして品質の高い動画を得るには **約 100 回**の試行がかかることがあるのに対し、エージェント（Galleri5 の Miro）を使うと、考えて計画を立てる分、**最短 5 回**ほどで高品質なシネマティック動画が得られるとのことです。これにより、時間とコストで「**約 60〜80% の削減**」が見られるという説明です（Silvia 氏も、マルチモーダルでコンテキストを持つプラットフォームにより、プロンプトやトークンのコストを **50〜80% 減らせる**と述べています）。「トークンの経済（tokenomics）の時代に、効率的な方法を見つけることが重要」という趣旨の発言もありました。

また、大きな動画では「コストが 10%」といった数字にも触れていますが、前後の文脈が曖昧で、何に対する 10% かは発話からは確定できません。

### 5.4 エージェントの動き方

Galleri5 側が説明した Miro の流れは次のとおりです。

1. 文脈（context）を理解する
2. 計画（planning）を立てる
3. **pre-flight QC**：プロンプトを出す前に品質確認を多く行う
4. モデルの実行
5. レビューと仕上げ

例として、テレビ番組「Mahabharat」（Galleri5 側の説明では 50 エピソードが完成）では、1 エピソードに **約 21 のステージ**があり、そのうち動画生成のステージは **最後の 1 つだけ**です。残りは、計画、実行、品質チェックなどで、最後のステップを最適化し、使うトークンをできるだけ減らすための工程だと説明されています。

### 5.5 エージェントがもたらす 5 つの利点

制作現場での利点として、Galleri5 側は次の 5 つを挙げています。

| 利点 | 説明 |
| --- | --- |
| キャラクターの一貫性 | 映画、番組、広告のどれでも、キャラクターが一貫して見える |
| コヒーレンス（整合性） | 50 エピソードある Mahabharat で、第 1 話と第 50 話が違って見えてはいけない。感情や演技も一貫させる |
| 低コスト | モデルが良くなっても、高品質な出力のためにコストが増え続けるわけではない |
| 企画から実行まで | エージェントを「意図を理解して動く、非常に賢いエグゼクティブ・アシスタント」のようなものにしたい |
| プリビズと承認 | イエス・ノーを返す承認のステップが多くなる |

クリエイターの役割は、やり方を学ぶことから、承認する側に移る、という説明です。Silvia 氏は、これによって **自己強化学習（self-reinforcement learning）** が働き、モデルではなくプラットフォームが、使うたびに良くなる、と補足しています。

### 5.6 Microsoft との協業

Silvia 氏が「プラットフォームを共同で構築した。この co-building（いわゆる FDE の進め方）の利点は」と尋ね、Galleri5 側は「Microsoft とは過去 2 年間、よいパートナーシップだった」と答えて、3 点を挙げています。

1. **基盤レベルでの活用。** Foundry IQ や Microsoft のインフラを使ってエージェントを構築している。本当の強みは、モデルではなく harness、コンテキスト、そして Foundry のインフラの上に作ったスキルのアーキテクチャ
2. **共同開発。** ISC チームや多くの FDE と近い距離で、研究開発を一緒に進めた。特に、クリエイティブな制御を可能にする SLM の開発は、共同開発したものが多い
3. **joint GTM（共同の市場展開）。** すでに、シンガポール最大級の放送会社の 1 社を顧客にしている。両社で一緒にチームに紹介し、安心を提供した結果。今後は世界のメディアエージェンシーに、Copilot、Microsoft marketplace、Galleri5 のエージェントを組み合わせ、企業に安全性の保証（「IP とデータは保護される」）を示して進めたい

Silvia 氏は、Galleri5 は急成長したスタートアップのようなものだとしたうえで、Azure 上に構築するのは「スタートアップの機動力」と「大企業の後ろ盾」を組み合わせる賭けだと述べています。基盤とプラットフォームを出発点とし、marketplace による営業と、harness と IQ 層での共同開発も得られる、という整理です。

### 5.7 アーキテクチャ

Galleri5 側が示したアーキテクチャは、上から次の 5 層です。

| 層 | 説明 |
| --- | --- |
| ユーザー | 脚本やブリーフなどを渡す |
| Miro | クリエイティブ・ブレイン。ここで思考が行われる |
| Harness | Galleri5 自身の IP。スキルのアーキテクチャで、全体をオーケストレーションする |
| サブエージェント | SLM を含め、各種モデルが使われる層 |
| クラウド実行 | インフラの層 |

Foundry は、harness、エージェント、クラウド実行のすべてにかかわり、Azure のインフラがガードレールを提供すると説明されています。Silvia 氏は、Azure 上の基盤であり、Foundry を通じて **数千のモデル**にアクセスでき、フロンティアモデルの最良のものも、SLM とそのファインチューニングも使える、と補足しています。

### 5.8 信頼（トラスト）の設計

Galleri5 側は、スライドの右側にモデルがあり、顧客の入力をそのままモデルに送らないと説明しています。間に次のようなチェックを挟みます。

- アイデンティティとアクセス
- サニタイズ
- ガードレール

データに「PI data」（聞こえた表記のままで、音声認識の都合で確定できません）が多く含まれる可能性があり、それをモデルに渡したくないため、顧客のデータがモデルに届く前に多くのステップを置いている、とのことです。Silvia 氏は、大手メディア企業が期待する安心であり、この harness のセキュリティと、「常に学ぶ強化ループ」による差別化された IP が価値を生む、と述べています。

### 5.9 利用事例

Galleri5 側は 2 つの例を挙げています。

**1. テレビ番組**

Gallerify AI Studio で、TV 番組や映画を完全な形で作れるとのことです。2 シーズン、最大 **50 エピソード**のシリーズを作り、エピソード間の連続性を保っています。ストリーミングと放送向けに作られていて、全国放送と OTT プラットフォームで公開されました。第 1 シーズンは **2,650 万人**が視聴し、第 1 話だけで約 **650 万人**が視聴したと述べています（Silvia 氏が「2,600 万人の視聴者です」と念を押しています）。

**2. Shein の SNS 向けクリエイティブ**

インドの Shein（音声認識の都合で表記が確定できません）が、Instagram ページのクリエイティブやパフォーマンス広告を Galleri5 のスタジオで作っている、という例です。A/B テストを行い、非常に速いペースで広告を出し、インドの多様な顧客層向けにローカライズ・翻訳できていると説明されています。

Silvia 氏は、「すべての企業はコンテンツ企業でもある」という見方から、マーケターが一人ひとりに関連するコミュニケーションを作る機会であり、1 つのコンセプトを多言語で素早く、追加コストなしで展開できると補足しています。

## 7. 注意点・発表者の気付き

- **本当の強みは、モデルではなく harness とコンテキスト。** Galleri5 側は、自分たちが提供する価値はスキルのアーキテクチャと文脈の層にあると説明しています。
- **品質確認はプロンプトの前に行う。** 1 エピソード約 21 ステージのうち、動画生成は最後の 1 つで、その前の計画・品質チェックが最後の出力のトークン消費を減らします。
- **入力をそのままモデルに渡さない。** アイデンティティとアクセスの確認、サニタイズ、ガードレールを挟み、「PI data」をモデルに渡さない設計にしています（表記は音声認識の都合で確定できません）。
- **人が判断する場面は残る。** 制作の途中で多くの承認が必要になり、創造性と人の野心を中心に置く、という前提も語られています。
- 数字の扱い：コスト削減率は、「60〜80%」「50〜80%」「10%」など、文脈によって表現が揺れています。何を基準にした削減かは、発表では詳しく説明されていません。モデル数も、「Foundry で数千」「10,000 以上」と発話に揺れがあります（メタデータの概要は「100+ models」）。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **制作コストと期間の圧縮**：1 億ドルの映画が約 1,000 万ドル、3 年の制作が最短 3 か月。
- **試行回数の削減**：動画モデルを直接プロンプトすると約 100 回かかるところ、エージェントなら最短 5 回で高品質な動画が得られる。

## 9. まとめ

Galleri5 の事例は、クリエイターの意図を受け取って計画、品質チェック、モデル実行、仕上げまでを担うエージェント（Miro）を、Azure と Foundry の上に構築することで、制作の費用と期間を大きく縮められることを示しています。差別化の中心は、モデルそのものではなく、harness、コンテキスト、スキルのアーキテクチャにあります。

Microsoft とは、基盤の利用、共同開発、joint GTM の 3 つの面で協業しており、すでにシンガポールの放送会社を顧客にしています。利用事例としては、2 シーズン 50 エピソードの TV シリーズと、Shein の SNS 広告が挙げられました。今後は、実写と AI を組み合わせるハイブリッド制作と、Copilot との統合を目指すとのことです。
