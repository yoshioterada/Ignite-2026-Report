# THR977 From Reports to Reasoning: Reinventing PPM with AI and Power Apps

## 1. はじめに

このセッションは、プロジェクトポートフォリオ管理（PPM：Project Portfolio Management）の事例紹介です。AI を使った「バイブコーディング」で、読み取り専用のレポートだった体験を、シミュレーションと対話ができるアプリに作り替えました。登壇者は、ポートフォリオの選択、シナリオプランニング、シミュレーションの進め方が、AI によって自分と自分の会社の仕事でどう変わったかを、ライブデモを中心に説明しています。

核になるのは、デンマークで最大の製薬会社向けに、**最初の依頼から本番稼働までを 3 週間、担当は登壇者を含む 2 人だけ**で作り上げたという点です。データは Dataverse に置き、画面はモデル駆動型アプリの中に HTML の Web リソースとして作っています。AI は、ローカル PC 上のモデルでも、クラウドの Copilot でも使えるようにしてあります。

このセッションでは、画面を使ったライブデモが行われています。後半では、3 週間の開発で得た 3 つの学びも語られました。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/THR977](https://ignite.microsoft.com/en-US/sessions/THR977)

## 4. 発表者が伝えたいメッセージ

登壇者が伝えたいのは、**AI を使ったバイブコーディングによって、PPM の分析体験を数週間で、しかも顧客の事情（データを外に出せない等）に合わせて作れるようになった**ということです。登壇者の会社には、1 年半以上をかけて作った「What If」という製品が以前からあり、今回の 3 週間という期間はそれと比べて語られています。

従来は、Power BI で見るレポートは読み取り専用で、シミュレーションをしたいポートフォリオマネージャーは、データを Excel に出して手で変更を試し、その結果を PowerPoint でエグゼクティブ向けのレポートにまとめていました。これを毎週、最近では毎日（関税の上下、地政学リスクによる ROI への影響、トークンコストの変動などがあるため）やり直す必要があります。この作業を置き換えるために、画面側を AI で作り直した、というのが発表の骨格です。なお登壇者は、トークンのコストはまだポートフォリオに現れていないのに、お金は使われている、という点にも触れています（詳しくは別の機会の話題としています）。

もう 1 つのメッセージは、AI の使い方を 1 つに固定しないという設計です。顧客は、米国と欧州の間の緊張がある状況で、特定の AI だけに賭けたくないと考えました。そのため、PC 上のローカルモデルと、クラウドの Copilot のどちらでも、同じシナリオのデータについて対話できるようにしています。

## 5. 発表内容の詳細

### 5.1 従来の仕組みと課題

登壇者によると、ここ 5 年ほどの顧客支援の構成は、次のようなものでした。

| 役割 | 使っていたもの |
| --- | --- |
| レポート（読み取り専用） | Power BI |
| データとアプリ | Dataverse とモデル駆動型アプリ（自社のものは XPM という名前） |
| 変更のシミュレーション | Dataverse や Power BI から Excel にデータを出して試す |
| エグゼクティブ向け報告 | PowerPoint |

シミュレーションの結果をレポートにするたびに、この流れをやり直す必要がありました。この状況を良くしたいと考え、今年の 4 月に取り組んだ新しい作り方（発話では "this year" とだけ述べられ、西暦は語られていません）が、今回の事例の出発点です。

なお、同社にはすでに、1 年半以上をかけて作った「What If」という製品がありました。今回の取り組みは、それとは別に、AI で新たに作ったものです。

### 5.2 新しい作り方と顧客の要件

登壇者は、自分はプロの開発者ではなく MVP だが、今は誰もがある程度はコードを書ける時代だとして、AI にコードを書かせる「バイブコーディング」でこの課題に取り組みました。結果として、デンマーク最大の製薬会社（登壇者は社名を挙げておらず、「調べれば分かる」と話しています）向けに、最初の依頼から本番稼働まで **3 週間**、登壇者ともう 1 人の 2 人で完成させたとのことです。

顧客からの要件は次のとおりでした。

- ポートフォリオのデータと対話（チャット）できること
- さまざまな変更をモデル化できること
- 人員やお金が尽きるといった制約を設定できること
- ポートフォリオの意思決定は学ぶのが非常に難しいため、ユーザーをガイドしてくれること
- Dataverse とポートフォリオのデータに対して、**どの AI モデルでも**チャットに使えること
- レポートを PowerPoint に共有できること

最後から 2 つ目の要件の背景には、米国と欧州の間の緊張があり、AI の選択肢を複数持つ必要があったと説明しています。データを外部に送らずに、このノート PC 上のローカル言語モデルで Dataverse のデータを扱う例が、あとのデモで示されています。

構成は、Dataverse の上に載せたモデル駆動型アプリが中心で、そこに **HTML の Web リソース**を置いています。登壇者はこれを、その日の基調講演でも触れられていた手法として紹介しています（「今朝の基調講演でご覧になったかもしれませんが」という言い方でした）。チャットツールでもバイブコーディングのツールでも、ダッシュボードはすばやく作れるという位置づけです。

画面の作り方も説明されています。Power BI で使えるカスタムビジュアル（発話では table sorter、donut chart などが挙がっています）を調べ、スクリーンショットを撮り、「これとこれが欲しい」と AI に伝えて、同等のコントロールを HTML で作らせました。Power BI での体験を HTML ページで再現するところから始めたそうです。その後、ローカル LLM や Copilot のようなクラウドのプロバイダーを使いたいという要望が出ました。

### 5.3 ライブデモ（1）ウェルカムページと Dataverse のデータ

最初に、モデル駆動型アプリにログインした直後のウェルカムページが示されました。ユーザーに合わせた表示で、ログインしているのが誰か、今日の日付を把握しており、データはライブです。登壇者は、これをレポートだと言う顧客もいると話しています。プロジェクト、タスク、リスクのリンクや、インフラ関連のプロジェクトを深掘りするダッシュボードもありますが、AI の新しい世界では「アプリにログインした人を迎えるページ」にすぎない、と位置づけています。

データはすべて Dataverse にあり、特別なことはしていません。アプリは、最新の Copilot 関連の機能を有効にしたモデル駆動型アプリです。プロジェクトを開くと、次のような画面があります。

- ガントチャートのタイムライン
- リソース計画
- 予算（財務のグリッド。ベネフィットやコストセンターごとのコストの計画に使う）

ガントチャートについて登壇者は、どの計画ツールが一番良いかという議論はずいぶん前にやめた、人は使いたいものを使えばよく、データさえ集められればよい、と述べています。画面の例では、steer code（steering committee のことと思われますが、音声認識の都合で確定できません）が承認した開始・終了日に対し、実際は第 3 四半期に進めているプロジェクトがあり、登壇者はこれを問題だと述べています。これらはすべて Dataverse に保存されたデータです。

その下に、**この顧客にとって「魔法が起きる場所」**があり、Dataverse 上のすべてのプロジェクトのポートフォリオを表現しています。ここが、Power BI のカスタムビジュアルから最初に作り直した部品です。

### 5.4 ライブデモ（2）選択とリアルタイムのシミュレーション

ポートフォリオのビジュアルでは、1 つまたは複数のプロジェクトをクリックして選択（解除も可能）できます。選択するたびに、その時点で使っているコストが即座に表示されます。この顧客の場合は、選択に応じて消費するリソースもリアルタイムで見え、選択を増やすと、下のヒートマップに問題が現れ始めます。

登壇者は、これが非常に速く、**Dataverse 上に 1,000 件のプロジェクトがあっても高速に動く**と述べています。顧客が最初に心配したのが速度だったとのことです。時間軸上でプロジェクトを動かして、影響をその場で確認することもできます。登壇者は、Power BI だけでこれを行うのはほぼ不可能だと話しています。なお、この操作はシミュレーションだけで、データは保存し直していません。

次に、制約の設定が示されました。全プロジェクトを選択して予算の制約を追加すると、全体のコストは **163 million**（通貨単位は発話では確認できません）と表示されます。そこで「使えるのは 70 million だけ」と設定すると、その 70 million で最も価値が大きくなる組み合わせが示されます。

どのプロジェクトが選ばれるかは、プロジェクトのソート（ランキング）によります。プラスを押すと、Dataverse にある列が一覧で表示されます。プロジェクトに追加した数値・通貨型のフィールド（金額、リスク低減、苦情の件数など）はすべて対象です。例として NPV や、回収期間（月）が挙げられていました。

### 5.5 ライブデモ（3）ランキングの重み付けと「必ず実行」

全プロジェクトを戦略的価値だけで並べた場合の順位が、まず示されました。そこに経営層が「必ず実行しなければならないプロジェクト（must run）」を指定してくることがあります。その場合は、上位 5 つの位置を押さえる形で、先頭に差し込めます。

また、戦略的価値だけが基準ではない場合は、複数の基準を組み合わせ、重みを付けることもできます。登壇者は、これは 4 ポイント、これは 10 ポイント、NPV は 7 ポイント、といった具合に配点すると、合計が自動的に 100% に正規化され、その組み合わせに基づく確かなランキングが得られると説明しています。

### 5.6 ライブデモ（4）ガイド付き優先順位付け

顧客のポートフォリオは 1,000 件のプロジェクトがあり、手作業で 1 つずつ選ぶ余裕はありません。そこで、**ガイド付き優先順位付け（guided prioritization）** を作っています。小規模なポートフォリオ向けのシンプルな方法と、大規模向けの方法があります。大規模向けは、どのポートフォリオをこのシナリオに含めるかを選ぶところから始まります。選択のたびに、背景のデータがリアルタイムで並べ替え・絞り込みされると説明しています。

デモの手順は、次のように語られました。

1. 含めるポートフォリオを（1 つまたは複数）選ぶ。ここでは、先ほどと同様にすべてを選ぶ
2. 次に「必ず実行するもの」を選ぶ。経営層だけでなく、「すでに開始しているプロジェクトはすべて含める」といった条件も使える。ここでは開始済みのものを必ず含め、残りの中から決める形にした
3. 「何を重視するか」を選ぶ。ドライバー間の比較を延々と行うのではなく、顧客が事前に決定ポイントを設定している（strategy first、growth、financial return、momentum、balanced）。これ以外を使いたい場合は、head to head（1 対 1 の比較）で比べることもできる。ドライバーを追加すれば、そこにも表示される。登壇者は、これは昔の Project Online や Project Server にあった**ペアワイズ比較**と同じ考え方だと説明している
4. ここでは速い方法として、strategy first を選んで次へ進む
5. ベースライン（このシナリオを作る前）と現在の順位が比較され、順位が上がったプロジェクトと下がったプロジェクトが表示される。登壇者は、これは情報の表示だと述べている（具体的な順位の変動幅の発話は音声認識が乱れており、確定できません）
6. 次へ進むと、**スイートスポット**が分かる。現状で 120 million を使っている地点も示される。スイートスポットは、163 million ではなく **37**（単位は発話では明示されていません）を使う点で、特定された価値の半分以上が得られる。価値の残りの部分を取るために、その先のお金をすべて使うことになる
7. 次へ進むと、右側の判断結果に応じて、「資金配分する（funded）」ものと「保留（parked）」のものに分かれる。プラスを押して追加することもできる
8. 最後は難しいリソースキャパシティの話。同じコストでより多くの仕事を入れるために、プロジェクトを時間軸上で動かすかどうかを検討する

スイートスポットについて、登壇者は、これを見ると「悪いアイデアばかりのポートフォリオなのではないか」と感じるとも述べています。必要なのは追加のお金ではなく、より良いアイデアだ、という言い方です。お金があっても、より少ない金額で同じ結果に近づく別のスイートスポットがあることを経営層に見せることには価値がある、という考えです。

また、トークンの話にも触れています。人手の代わりにトークンに 100 万 USD を使ったらどうなるか、という問いです。これは別の機会に話す話題だとしたうえで、ポートフォリオ管理の「4 つ目の次元」になるとの見方を述べています。この日のデモには含まれていません。

### 5.7 ライブデモ（5）PowerPoint のエグゼクティブレポートとシナリオ比較

シナリオを作ったら、保存できます（この場では保存していません）。そのシナリオを PowerPoint で見せたい場合、登壇者は「Executive report」をクリックします。現在のビューか、別のシナリオを選んで「プレビュー」を押すと、0.5 秒未満（登壇者の見立て）でプレビューが表示され、「ダウンロード」を押すだけで PowerPoint が手に入ります。

ここでは **Power Automate のフローは使っておらず、実行時に AI も動いていません**。数値はすべてそろっているため、PowerPoint のテンプレートの正しい場所に、正しいグラフとしてデータを書き込むだけです。AI の役割は、この仕組みを作る段階にありました。登壇者は、顧客がすでに使っている PowerPoint のサンプルを AI に渡して、作らせたと説明しています。以前は、顧客ごとに別の自動化ジョブを使って、1 レポートあたり 2〜3 週間かかっていた作業だそうです。

続いて「シナリオ比較（compare scenarios）」が示されました。今のシナリオと、過去に作った他のシナリオを、フロンティア曲線（お金を使う量とスイートスポットを同時に表示するもの）で比べられます。複数の決定ポイントやグラフを追加することもできます。

### 5.8 ライブデモ（6）ローカルモデルとクラウド AI との対話

登壇者がこのセッションで特に面白いと考えているのが、AI の部分です。作ったデータと対話したいときは、「copy to AI」をクリックします。選択肢は 2 つあり、まずローカル版が示されました。

**ローカルモデル**：画面の下に「ローカルモデルが動作中」と表示されます。登壇者のノート PC には **LM Studio** が入っており、RAM は 128 GB です（登壇者は、基調講演で新しいノート PC を RAM 多めで買える話があったと触れ、少ない RAM でも動くが強力なコンピューターは必要と説明しています）。ノート PC にデプロイしてあるモデルのうち、小さいもので十分なのでそれを選び、今作ったシナリオを要約させています。

実演では、AI がポートフォリオシナリオの要約文を書き、同時に、その情報に基づくダッシュボードが左側でリアルタイムに作られていきました。どちらもローカルで動く AI によるもので、登壇者は、インターネットを切っても動くと述べています。テキストにマウスを重ねると、AI がデータを視覚的に要約した箇所が分かるようにもしています。保存すると、結論（verdict）、懸念事項、アクションが、シナリオと一緒に保存されます。

**クラウド AI（Copilot）**：保存したシナリオ（実演では "Ignite demo"、scenario two、scenario one）を選び、「copy to Copilot」をクリックすると、システムのプロンプトとデータを含む Markdown 形式の内容が、クリップボードに入ります。データ量はかなり長いと登壇者は述べています。登壇者は Copilot Studio の MVP でエージェントに組み込む方法も分かっているものの、この顧客は**好きなチャットボットを使えること**が条件だったので、エージェントには組み込めなかったと説明しています。

そこで、チャットボットには標準の Microsoft 365 Copilot を使い、貼り付けて Enter を押すだけで動かしています。コピー＆ペーストだけで、グラウンディングも、特別なコンテキスト設定も、エージェントもなく、**標準の Copilot とシステム内のコピーボタンだけ**です。その後、続けて「これを PowerPoint にして」と頼めば、先ほどのように PowerPoint が作られる、と説明しています。なお、Copilot の回答が返ってくる場面の画面は、音声からは確認できません。

まとめとして登壇者は、顧客は Dataverse のデータをもとに、シナリオを瞬時にシミュレーションし、PowerPoint を 1 秒未満で作成し、安全性やクラウドへの不信がある場合はローカル AI を使い、そうでなければ好きなクラウドのエージェントを使える、と述べました。これが 3 週間で本番稼働したものです。

### 5.9 3 週間で得た学び

登壇者が挙げた学びは 3 つです。

1. **顧客が開発期間中ずっと関われること。** 3 週間で「おそらく 38 回」のリリースを行ったと述べています。朝に作りたいものを描き、1 時間後に作って、業務側の人に試してもらい、フィードバックをもらって、また作る。アジャイルには慣れていたが、ここまでではなかったとのことです。顧客がテストとフィードバックのために期間中ずっと参加できないと、実用的にならないという考えです
2. **Dataverse があるとセキュリティは任せられること。** Dataverse 上で HTML をバイブコーディングする限り、セキュリティを心配する必要がありません。適切な権限のない同僚に共有しても、見えません。誰が何を見られるかを気にせず、創造的に作れるのは贅沢だと述べています
3. **データをクラウドに送れない制約があり得ること。** ヨーロッパで大きな問題になっているが、他の地域でもそうかは分からない、と前置きし、登壇者自身がそれに賛成しているわけではなくても、前提条件だと述べています。その場合は、創造的になる必要があり、この事例では自分のノート PC を使うことでした

最後の呼びかけとして、紹介したツールについて詳しく知りたい場合は、スキャンするか（音声認識の都合で、何をスキャンするのかは確定できません）、会場に残って質問してほしい、とのことです。自分で試したい人には、Power BI や Excel で気に入っているものを探してスクリーンショットを撮るか、手書きで描いて、それをバイブコーディングで作ってみることをすすめています。なお、トランスクリプトは、このすすめの文の途中で終わっており、続きは確認できません。

## 6. デモ・手順

このセッションでは、モデル駆動型アプリを使った**ライブデモ**が行われました（登壇者が冒頭で live demonstration と述べ、画面を操作しながら説明しています）。画面の細部は音声からは確認できないため、語られた範囲で、流れを順に整理します。

1. ログイン後のウェルカムページを表示する（ユーザーと日付を認識し、データはライブ）
2. Dataverse 上のプロジェクトのガントチャート、リソース計画、予算の画面を見せる
3. ポートフォリオのビジュアルでプロジェクトを選択し、コストとリソースの消費、ヒートマップをリアルタイムで確認する
4. プロジェクトを時間軸上で動かして影響を見る（データは保存しない）
5. 全プロジェクトを選び、予算の制約を追加する。163 million を 70 million に制限すると、最適な組み合わせが示される
6. ランキングの列（NPV、回収期間など）を追加し、重み付けで合計を 100% に正規化する。must run のプロジェクトを上位に差し込む
7. ガイド付き優先順位付け：ポートフォリオ選択 → must run → 重視するドライバー（strategy first を選択）→ ベースラインとの比較 → スイートスポット → funded / parked → リソースキャパシティ
8. Executive report でプレビューを開き、PowerPoint をダウンロードする
9. シナリオ比較（フロンティア曲線）を見せる
10. 「copy to AI」でローカルモデル（LM Studio）に要約させ、ダッシュボードを生成する。結果を保存すると、結論・懸念・アクションが一緒に保存される
11. 「copy to Copilot」で Markdown をコピーし、Microsoft 365 Copilot に貼り付けて実行する

## 7. 注意点・発表者の気付き

- **顧客の関与が前提です。** 3 週間でおそらく 38 回のリリースを重ねる進め方では、顧客が期間中ずっとテストとフィードバックに応じられることが必要だと、登壇者は強調しています
- **ローカル AI には PC の性能が必要です。** 登壇者のノート PC は RAM が 128 GB です。少ない RAM でも動くが、強力なコンピューターが必要と説明しています
- **Copilot 連携は「コピー＆貼り付け」です。** 好きなチャットボットを使えることが条件だったため、エージェントとして組み込まず、グラウンディングも、特別なコンテキスト設定もしていません
- **データをクラウドに送れないことが前提になる場合があります。** ヨーロッパでは大きな問題で、登壇者は賛否とは別に、前提条件として扱う必要があると述べています
- **パフォーマンスの懸念への回答。** 顧客が最初に心配した速度は、Dataverse 上で 1,000 件のプロジェクトがあっても高速だったと説明しています
- 使用した AI モデル（バイブコーディングに使ったものも、ローカルで動かしたモデルも）の名称は、発表では語られていません

## 8. 利用者にとっての利点

発表で語られた効果は次のとおりです。

- 最初の依頼から本番稼働まで 3 週間、2 人で実現した（既存の What If 製品には 1 年半以上かかっていた）
- Power BI だけでは難しかった、時間軸上での移動や選択のリアルタイムなシミュレーションができる。1,000 件のプロジェクトでも高速
- エグゼクティブ向けの PowerPoint のプレビューが 0.5 秒未満で表示され、ダウンロードすればそのまま使える。以前は顧客ごとの自動化で 1 レポート 2〜3 週間かかっていた

- データを外部に送らずにローカルモデルで分析でき、そうでなければ好みのクラウドのチャットボットも使える
- Dataverse のセキュリティがそのまま効くため、HTML を自由に作ってもアクセス制御を別に作らなくてよい

## 9. まとめ

このセッションは、Power BI、Excel、PowerPoint に分かれていた PPM の作業を、Dataverse 上のモデル駆動型アプリと HTML Web リソースにまとめ、バイブコーディングで 3 週間・2 人で本番稼働させた事例です。プロジェクトの選択、予算制約、重み付けランキング、ガイド付き優先順位付け、スイートスポットの提示、PowerPoint の自動出力、シナリオ比較までを、ライブデモで示しました。
