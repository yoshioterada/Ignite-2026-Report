# THRSP1131 Accelerate business with AI-powered agreements from Docusign

## 1. はじめに

このセッションは、契約（agreement）の管理を、Microsoft の製品群の中で完結させる方法を、2 人の登壇者が紹介する約 25 分の登壇です。DocuSign が提供する DocuSign IAM（Intelligent Agreement Management）プラットフォームを、Copilot Studio、M365 Copilot、Dynamics 365 とつなげたときに、どんな業務の流れができるのかを、3 つのデモで見せています。

発表の出発点は、「契約の遅れの原因は電子署名そのものではなく、その前後の、まだ手作業でばらばらなワークフローにある」という見立てです。そのうえで、(1) DocuSign MCP コネクタで作るカスタムエージェント、(2) Dynamics 365 に組み込まれた IAM for Sales、(3) まだ提供されていない Work IQ MCP コネクタ（先行紹介）の 3 つを順に見せています。

このセッションでは、画面を使ったデモが 3 本行われています（登壇者自身が「3 つのデモ」と述べています）。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/THRSP1131](https://ignite.microsoft.com/en-US/sessions/THRSP1131)

## 4. 発表者が伝えたいメッセージ

Joyce 氏は、すべての売上、顧客関係、従業員との関係は契約から始まり、その多くが DocuSign を通っていると述べます。問題が起きるのは電子署名の工程ではなく、その前後のワークフローです。売上の遅れ、案件の停滞、顧客の離脱、サプライヤーのインセンティブの取りこぼしといった影響は誰もが感じているのに、原因を理解している組織は少ない、という指摘です。

その原因として、金融サービスからヘルスケア・ライフサイエンスまで、上級リーダーから共通して聞く 3 つのテーマが紹介されました。

| 根本原因 | 説明 |
| --- | --- |
| 断片化したプロセス | チームや地域ごとに契約の進め方が違い、単一のプロセスを前提にできない |
| 分断されたツール | チャット、メール、表計算、文書を行き来するコンテキストスイッチが、案件のクローズや停滞に影響する |
| 活用されていないデータ | 更新日、義務、リスクなど重要な条件が PDF に閉じ込められ、行動にも洞察にもつながらない |

個別にはどれも「ちょっとした面倒」ですが、合わさると、契約プロセスが組織の中で最も遅い工程になっている、というのが発表の見方です。多くの組織は、ワークフローを 1 つ、ポイントソリューションを 1 つ、特定チーム向けの AI ツールを 1 つと、1 歩ずつ解決しようとしますが、Deloitte の調査では、AI を使ったワークフローを単独で導入した場合の ROI 改善は **3%** にとどまるとされています。問題は単一の工程ではなく、営業から調達、調達から法務、法務から財務といった、工程の間の受け渡しにあるからです。必要なのは、もう 1 つのポイントソリューションではなく、エンドツーエンドで解決するプラットフォームだ、というのが DocuSign の主張です。

さらに、そのプラットフォームは、利用者が既に働いている場所、つまり、この会場の人にとっての Microsoft の中に入っていなければならない、と述べています。

## 5. 発表内容の詳細

### 5.1 DocuSign Intelligent Agreement Management プラットフォーム

DocuSign の Intelligent Agreement Management プラットフォームは、契約のライフサイクル全体を 1 つのプラットフォームで扱うものです。発表では、3 つのフェーズ（作成、締結、管理）にわたって AI 搭載の機能があると説明されました。

| 要素 | 説明 |
| --- | --- |
| Agreement Manager | DocuSign 自身の契約リポジトリ。契約が DocuSign に入った時点、またはサードパーティから来た時点で、主要な条件、日付、当事者を抽出する |
| Workflow Builder | Power Automate に似た、ノーコードのワークフロー自動化ツール。契約ワークフローを作り、電子署名や承認への回付、DocuSign Agreement Desk（別の単独製品）を通じた法務チケットの作成、Dynamics など外部ソースの読み書き、エージェントの呼び出しができる |
| DocuSign Iris | 契約向けに作られた DocuSign 独自の AI エンジン。汎用的な LLM と違い、契約のデータセットと DocuSign の契約に関する専門知識で学習されており、リスクや義務の可視化とワークフローの高速化につながる |

最近出た新しい AI 機能として、次の 2 つが紹介されました。

- **DocuSign MCP server**：Copilot Studio のようなサードパーティのプラットフォームから、独自のエージェントを作り、契約から洞察を取り出す、DocuSign のワークフローを起動する、といった DocuSign のアクションを呼び出せる
- **DocuSign Agent Builder**：Copilot Studio と同様の、DocuSign 自身のエージェント用スタジオ。DocuSign のエージェントを作り、他のサードパーティのソースも呼び出せる。契約のコンテキストから離れずに、DocuSign プラットフォームの中でファーストパーティのエージェントを使える

### 5.2 Microsoft との 3 つの連携

Joyce 氏は、DocuSign の機能を、チームが既に働いている場所に届けるため、Microsoft のスタックに直接組み込んできたと述べ、次の 3 つを紹介しました。

1. **DocuSign MCP Connector for Copilot Studio**：DocuSign のツールを Copilot Studio に持ち込み、自然言語で契約の送信、署名、追跡を行う AI エージェントを作れる。直近のリリースで、M365 Copilot と Microsoft Cowork にも統合された
2. **IAM for Sales in Dynamics**：営業担当が Dynamics 365 を離れずに、契約を作成、締結、管理できる。自動化されたワークフロー、文書生成、電子署名、DocuSign Iris による AI のガイド付き回答が、CRM を出ずに使える
3. **Work IQ MCP connector for DocuSign Iris**（先行紹介）：方向が逆で、Microsoft を DocuSign に持ち込む。Work IQ がメール、チャット、ファイルを、契約が存在する場所のコンテキストに引き込む。**このコネクタはまだ出荷されていません**が、今後の方向性を見せるために紹介する、と明言されています

### 5.3 DocuSign MCP server の位置づけ

ここから Purnima 氏が説明します。DocuSign MCP server は、DocuSign の連携方法における「根本的なアーキテクチャの転換」を表すものだとされます。M365 Copilot、Copilot Cowork、Copilot Studio といった Microsoft の AI ツール・アプリと、すべての契約の正となる情報を持つ DocuSign IAM プラットフォームとの間の「結合組織」と説明されました。Microsoft Copilot Studio で使えるようになった DocuSign MCP Connector を使うと、カスタムエージェントが DocuSign に直接アクセスして契約のコンテキストを取り出せます。そして、信頼できる契約の結果を、ユーザーが Microsoft のアプリを離れずに受け取れる、という説明です。

### 5.4 ユースケースの紹介（デモ 1 の後）

Joyce 氏は、デモが示すのは一例であり、IAM と Copilot を組み合わせるユースケースは数多くあるとして、2 つを挙げました。

- **ベンダー管理**：Copilot が Teams と Outlook のメッセージを要約し、DocuSign のワークフローを起動して発注書の契約を送る。署名後の情報は ERP システムに入る
- **人事**：Copilot が DocuSign 経由でオファーレターを生成し、署名を得て、HRIS を更新して各項目を事前入力する

### 5.5 IAM for Sales の位置づけ

Purnima 氏は、IAM for Sales を、Microsoft Dynamics 365 のような CRM に契約管理を直接持ち込むものと説明します。CRM に埋め込まれた体験を実現し、営業担当が作業の流れの中にとどまれるようにして、摩擦を減らし、Dynamics のデータを使った契約生成のプロセスを合理化することで、手作業を減らし、案件の実行を速めるという位置づけです。

### 5.6 Agreement Manager と Ask Iris

署名済みの契約は Agreement Manager に流れ込み、Iris が主要な条件を抽出します。すべての契約が検索でき、契約の所在と、そこに書かれた条件を素早く確認できます。

新機能として、Agreement Manager に組み込まれた DocuSign の AI アシスタント **Ask Iris** が紹介されました。「主要な条件を要約して」「この契約の概要を教えて」と尋ねると、数秒で要約が返ります。引用（citation）をクリックすると、該当の条項が契約書のどこにあるのかが分かります。契約の正となる情報は DocuSign にありながら、Microsoft のエコシステムで毎日使うアプリの中に IAM を通じて届く、という説明です。

## 6. デモ・手順

デモは 3 本です。いずれも画面を使って進められていますが、画面上の操作の細部（ボタンの位置など）は音声からは確認できません。

> 補足：デモは、David、Sarah、Tom、Mike、Rebecca といった架空の登場人物のシナリオを語る形で進みます。デモ 1 は「David が〜する」という三人称の語りで、ライブ操作か録画かは音声からは判別できません。デモ 2 と 3 の間には、画面の切り替えのために待ってほしいという発言があります。

語られた流れは次のとおりです。

### 6.1 デモ 1：DocuSign MCP コネクタ（金融サービス、Purnima 氏）

シナリオは、Fontada Financial（音声認識の都合で表記が確定できません。後半では Fontara とも聞こえます）のリレーションシップマネージャー David が、DocuSign MCP で作ったカスタムエージェントを M365 Copilot で使って、日々の業務を自動化するというものです。背景として、リレーションシップマネージャーやファイナンシャルアドバイザーは、顧客ポートフォリオ全体の契約、手数料表、修正契約を管理しており、通常は SharePoint、ファイルドライブ、メールを探し回り、PDF を開いて条件を手で確認してから、下流の処理を始める、と説明されています。

1. David は Copilot への 1 つのプロンプトで、ポートフォリオ全体の契約をスキャンし、アドバイザリー手数料が 1% を超えている顧客を挙げるよう、エージェントに頼む
2. エージェントは DocuSign MCP コネクタを使い、Agreement Manager（Iris を搭載した DocuSign の集中契約リポジトリ）から契約の洞察を直接取得する。AUM やアドバイザリー手数料の割合、更新条件などの主要条件は、DocuSign が既に抽出済み
3. 数秒で、全顧客の優先度付きビューが得られ、特に目立つ顧客として Stellogica（音声では Stella Logica とも聞こえます）が出てくる
4. David が Stellogica の主要条件の要約を頼むと、PDF を開いたり条項を探したりせずに、DocuSign の元文書に基づく、検証済みの洞察が返る。コンプライアンス上の義務、支払条件、更新日などが含まれる
5. 要約は手数料の食い違いも裏付け、問題を検証済みの形で確認できる。これを踏まえ、コンプライアンスを保ちながら少額の手数料引き下げで顧客との関係を強められると判断する
6. 運用担当に修正契約の作成を依頼するのではなく、エージェントに「Stellogica のアドバイザリー手数料を 0.75% に更新して送って」と頼む
7. エージェントは、再び MCP を使って DocuSign のワークフローを起動する。ワークフローは、Dynamics のアカウントレコードの値で修正契約を事前入力し、顧客に送る
8. 顧客側の視点に切り替わり、Stellogica の Sarah が修正契約を受け取る。DocuSign の AI 機能で変更箇所を素早くハイライトして確認し、リレーションシップマネージャーとの数回のやり取りの後に署名する
9. その後、副署名のために回付される。完全に署名されると、修正契約は Dynamics のアカウントレコードに自動で添付され、CRM との同期が保たれる
10. 署名済みの契約は Agreement Manager にも自動的に流れ込み、Iris が AUM、アドバイザリー手数料の割合、その他の日付や商取引条件といった主要な洞察を抽出する。これらの洞察は MCP コネクタを通じて Copilot からも利用できる

Purnima 氏は、リレーションシップマネージャーは一度も Copilot を離れなかったこと、DocuSign IAM が MCP コネクタを通じてエージェントに契約のレイヤーを提供したことをまとめています。契約から洞察を取得し、CRM を参照するワークフローを起動し、署名に回付するまでを、自然言語だけで、日々の仕事の中で行える、という説明です。なお、このエージェントは Copilot Studio 向けの DocuSign MCP コネクタで作られており、同じ方法は他の契約ワークフローにも適用できる、とされています。

### 6.2 デモ 2：IAM for Sales（Dynamics 365、Purnima 氏）

シナリオは、Fontara（音声認識の都合で表記が確定できません）のエンタープライズ営業担当が、Dynamics の商談の中から、新しいベンダーに MSA を送るというものです。

1. 営業担当が「start with DocuSign」ボタンをクリックする。法務が承認済みの文書テンプレートを持つ、事前に用意された（承認済みの）ワークフローの一覧が表示され、CRM のデータともつながっている
2. フォームには、商談レコードから、顧客名、顧客のメールアドレス、契約金額などが自動で入る。営業担当は追加のフィールドを入力して送信する
3. 送信後は、顧客に直接送るのか、法務や財務の追加承認を経るのかに応じて、ワークフローを組める。送信するとリクエストが DocuSign の Agreement Desk に自動で作成され、全チームが「契約がどこで止まっているか」を同じ画面で見られる。Agreement Desk は、Dynamics の同じ商談レコードにも埋め込まれており、営業担当は複数のアプリを行き来しない
4. このリクエストは法務に回付されたため、法務担当 Tom の視点に切り替わる。Tom は DocuSign で作業しており、営業担当が作ったリクエストを開き、詳細タブで内容を確認する
5. Tom は文書タブで MSA の初稿を添付し、顧客の Sal にメールで送る
6. 顧客は Fontara から MSA をメールで受け取り、Word にダウンロードして赤入れ（修正）を行い、Fontara の法務に送り返してカウンターレビューを求める
7. 顧客がメールで送ってきた修正は、法務が Agreement Desk に新しいバージョンとして追加できる。その後、Word で編集する。通常は、契約書をページごと、条項ごとに手作業で確認、修正し、顧客と連絡する必要がある
8. Agreement Desk の AI 支援レビューを使って、このプロセスを効率化する。プレイブック（組織が既に承認している内容の指針）を AI 支援レビューで使い、法務は、フラグが付いた条項を素早く確認して必要な修正を加え、会社の方針に沿って自動更新条項も追加する。問題なければ「save request」をクリックすると、新しいバージョンが Agreement Desk のリクエストに自動で添付される
9. 数回の議論の後、双方が合意に至り、署名の準備が整う。Fontara の法務は、最初の MSA から実際に何が変わったかについて、AI が生成した要約を取得できる。変更内容がまとめられ、問題がなければ承認して、営業担当に戻す
10. 営業担当は、Dynamics から出ないまま、リクエストが署名の準備完了になっていることを確認する。監査証跡（何が起き、何が変わったか）を見て、ボタンで、Dynamics に埋め込まれた Agreement Desk から署名のために送る。顧客にメールで送られる
11. 顧客は合意済みの改訂版を受け取り、確認して署名する。Dynamics にも同じステータスが反映され、リクエストがクローズしたことが分かる
12. 署名済みの契約は Agreement Manager に流れ込み、Iris が主要条件を抽出する。続いて Ask Iris で要約や引用の確認を行う様子が語られました（5.6 を参照）

### 6.3 デモ 3：Work IQ MCP コネクタ（先行紹介、Purnima 氏）

まだ提供されていない機能で、「将来の方向性の先行紹介」であり、独占プレビューとして扱ってほしい、と断りがありました。

シナリオは、Fontara がベンダー「data vault」の新しいデータプラットフォームを評価していて、先に進むにはデータ処理契約（DPA）の承認が必要、というものです。交渉はメールで行われがちで、vendor data vault の Rebecca が最新の更新をメールで送ってきます。調達の Mike がベンダーとやり取りする一方で、法務は同じメールスレッドに入っておらず、最新の議論も、新しい条件も、何が合意されたかも分からない。コンテキストが失われ、意思決定が遅れる、という問題設定です。

1. Mike は既に Agreement Desk にリクエストを作成し、DPA の初版を添付してある（出発点）
2. 今朝、Rebecca が、新しい価格、コンプライアンスの選択肢、未解決の質問などを含む最新版をメールで送ってきた。通常は、Mike がそのメールを法務に転送するか、リクエストを更新する必要があり、時間がかかり、ミスも起きやすい
3. Work IQ が DocuSign エージェントに統合されていると、エージェントはメールからコンテキストを直接引き出し、数秒でメールを解析して主要な更新点を要約する
4. 「この交渉の分断を解消して」とエージェントに頼むと、エージェントはメールの更新を 1 つの文書にまとめ、同じリクエストに添付する。1 つのプロンプトで、すべてエージェント的に進み、契約のコンテキストとメールのコンテキストが 1 か所にまとまる
5. 画面では、エージェントがメールの要約を独立した文書として添付し、リクエストを確認する全員が参照しやすいように、構造化されたメッセージも追加している。Rebecca のメールの DPA 第 3 版も、このリクエストに添付されている
6. 法務は、エージェントが抽出した要約、文書としてのメールのコンテキスト、初版と最新の 2 つの DPA バージョンを 1 か所で確認できる。さらにプレイブックを実行して、Fontara の基準に照らして条件を検証し、承認の判断に役立てられる

Purnima 氏は、メールを探し回る必要も、チームを追いかける必要もなく、コンテキストの見落としが無く、案件が署名までスムーズに進む、と説明しています。このパターンは、契約管理のさまざまなライフサイクルや、業種ごとのユースケースに広げられるとも述べています。

## 8. 利用者にとっての利点

発表で語られた効果は次のとおりです。

- Deloitte の調査で、AI 支援ワークフローを単独で入れた場合の ROI 改善は 3% にとどまる。工程間の受け渡しも含めて解決する、エンドツーエンドのプラットフォームが必要だという主張
- 営業担当は Dynamics を離れずに契約を作成、レビュー、署名まで進められ、Agreement Desk により、全チームが同じ画面で契約の停滞箇所を確認できる
- リレーションシップマネージャーは Copilot を離れずに、契約の洞察の取得から修正契約の送信、署名、CRM への添付まで進められる
- 法務は、プレイブックを使った AI 支援レビューと、AI が生成する変更点の要約で、ページごと・条項ごとに手作業で確認する従来のやり方を速められる
- 署名済みの契約は Agreement Manager に流れ込み、主要条件が抽出されて検索でき、Ask Iris で質問や引用の確認ができる

> 補足：発表では、これらの効果を示す定量的な成果数値（時間の短縮率など）は、Deloitte の 3% の言及以外には示されていません。

## 9. まとめ

DocuSign は、契約の遅れの原因を、署名そのものではなく、断片化したプロセス、分断されたツール、PDF に閉じ込められたデータにあると捉え、エンドツーエンドの IAM プラットフォーム（Agreement Manager、Workflow Builder、Iris）で解決すると主張しました。Microsoft との連携としては、Copilot Studio 向けの DocuSign MCP Connector（M365 Copilot や Microsoft Cowork にも統合）、Dynamics 365 向けの IAM for Sales、そして未提供の Work IQ MCP コネクタの 3 つが紹介されました。3 つのデモで、Copilot から署名まで進む金融サービスの事例、Dynamics の中で営業と法務が契約を回す事例、メールの交渉内容を DocuSign のエージェントが集約する事例が示されました。最後に、2 つの QR コードが案内されました。1 つは Microsoft と共同で提供しているワークショップ（Copilot のスキルを磨く内容）、もう 1 つは DocuSign の AI エージェントを探索して動画シリーズを見られるものです。登壇者は、当日の終わりまでブース 1455 で質問に応じると述べています。
