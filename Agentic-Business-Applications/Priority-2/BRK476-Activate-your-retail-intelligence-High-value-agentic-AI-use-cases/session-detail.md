# BRK476 Activate your retail intelligence: High-value agentic AI use cases

## 1. はじめに

このセッションは、小売業が AI エージェントをどこで価値に結びつけるかを、Microsoft の小売・消費財担当と Columbia Sportswear の技術リーダー 2 名の対談で語る発表です。前半は Microsoft 側から、小売業の変化と「自社の知見（組織のインテリジェンス）をどう活かすか」という枠組みの説明があり、後半は Columbia Sportswear の 2 名が、エンジニアリング、運用、エージェンティックコマース、人間の関与、導入で驚いた点を実体験として話しています。

結論として繰り返し語られたのは、**難しいのはモデルではなくデータであり、ガバナンスと運用モデルの整備も同じくらい重い課題**だという点です。画面を使ったデモは行われていません。スライドと対談が中心です。

Amy は、誰もが AI のモデルを使える時代には、モデルそのものは差別化要因にならないと述べました。差別化できるのは、顧客データ、ロイヤルティデータ、店舗スタッフの知見、店舗ごとの需要シグナル、商品や仕入先に関する専門性といった、自社の「組織のインテリジェンス」を事業部門をまたいで結びつけ、活用することだという主張です。

Columbia Sportswear の 2 名の発言は、この主張を裏づける内容でした。Rama は、モデルは競合も同じものを使えるので、取り組むべきは自社データの整備（機械が読める形への充実化と、エージェント経由のチャネルへの提供）だと話しました。Dan は、既存の非効率な業務に AI を載せても非効率なまま速くなるだけで、業務そのものの見直しが必要だと述べています。

## 5. 発表内容の詳細

### 5.1 小売業の変化と組織のインテリジェンス（Amy）

小売業界は、消費者の好みの変化、サプライチェーンに影響する地政学的な変化、店舗とインターネットの使い分けの変化など、多くのシグナルによって変化が速まっています。この変化に対して学び、反応するために、組織の知識を最大限に活かすことが今回の話題です。

価格の安さや広告費の規模で競う方法もありますが、いま面白いのは、組織のインテリジェンスで、購買体験、品揃え、製品のつくりこみを差別化できる点だとしています。そのために必要なのは、顧客データ、ロイヤルティデータ、店舗スタッフが知っていること、各店舗の需要シグナル、商品・仕入先の専門性といった、社内に散らばるデータの上にインテリジェンス層を置き、計画、判断、行動を速く、差別化されたものにすることです。結果として、品揃えが強くなり、顧客のロイヤルティが高まるという説明でした。

ユースケースは、シーズンに何を買うかを決める商品企画チーム、サプライチェーンと物流センター、店舗にまたがって現れます。上流と下流をつなぎ、事業の重要なデータをもとに推論させることが重要だとしています。

### 5.2 4 種類の IQ と信頼（Amy）

基調講演のテーマとして、組織図ではなく「仕事の流れ図（ワークチャート）」を活かすという話があったと紹介されました。エージェントと人がチームをつなぐと、ワークチャートは一つの組織図よりも強力になるという考えです。

エージェントが事業全体で価値を出すには、業務の文脈にもとづいている必要があります。Amy は IQ を次のように整理しました。

| 観点 | 対応する製品 | 説明 |
| --- | --- | --- |
| 従業員の働き方 | （発話では製品名が確認できません） | 店舗の標準作業手順や、シーズン前の計画・予測のやり方、判断に使えるデータなど。エージェントを重ねることで成果までの速度が上がる |
| 事業の動き方 | Fabric IQ | チームをまたぐ事業データを、人とエージェントの全員がアクセスできるようにして土台を揃える |
| 知識の集まり方 | Foundry / Foundry IQ | 事業全体の判断ポイントと知識を支える |
| Web データ | Web IQ | Web 上のデータを取り込み、判断の根拠にする |

これらを組み合わせて文脈を活かす企業を、Microsoft は「Frontier Firm」と呼んでおり、小売ではこれが Frontier Retailer にあたるという説明です。

もう一つの柱が信頼です。ブランドと運用のリスクを増やさずに可視性を高めるために、オブザーバビリティ（可観測性）、セキュリティ、ガバナンスが重要だとし、Microsoft Agent 365 はエージェントの管理基盤（コントロールプレーン）のような機能を持つと紹介しています。インテリジェンスと信頼がそろうことで、より重要な業務プロセスにエージェントを自信を持って展開できるという位置づけです。

### 5.3 Columbia Sportswear の自己紹介

Rama は、Columbia Sportswear の商用テクノロジー部門を率いています。同社はポートランドを拠点とするブランドで、創業者の母親が自分の息子（現在の CEO の Tim Boyle）に着せて製品を試してから出荷していた、という逸話が語られました（創業者の名前は音声認識の都合で表記が確定できません）。

Dan は、ファッション小売業界に 27 年以上いると自己紹介しました。製品開発テクノロジーチームと、エンタープライズアーキテクチャチームを率いています。後者は、AI のテクノロジー戦略を定め、チームが責任を持って安全に、速く価値を出せるようにする役割だと説明しています。

### 5.4 Columbia 独自のインテリジェンスと、エージェントを優先する背景

Rama は、Columbia にとって最優先なのは「アクティブな人々を、自分の情熱につなぐこと」だと話しました。AI は、適切な製品を即座に、個人に合わせて提示することで、それを助けられるとしています。独自のインテリジェンスとしては、屋外用途での消費者理解を含む数十年の製品知見、特許を持つ製品イノベーション、数十年分の運用知識を挙げました。これらを AI と組み合わせて、次の冒険に合う製品を消費者に提案できるという説明です。

エージェントが優先課題になった理由として、Rama は次の 2 点を挙げています。

1. Columbia ブランドには、より広く、より若い消費者層まで届けて成長を高める複数年戦略（Project Accelerate、報道でも知られているとのこと）がある
2. 消費者の商品の探し方が変化している。従来の検索やウェブサイトではなく、会話型やエージェント経由で買い物をする人が増えており、その場で自社ブランドが見つかり、意図を理解して関連製品を提示できなければならない

Rama は、検索やウェブサイトの最適化だけに取り組むのは「昨日の課題に取り組んでいる」ことになるとも述べました。Rama 自身、Tahoe への旅行を ChatGPT で計画し、推薦まで受けたという例を挙げています。Amy も、体格の違う子どもが 2 人いる家庭では、買い物が「会話」に近く、雨具選びでも会話形式のほうが合うという体験を紹介しました。

Dan は、素早く動くために、実験を重ねて事業に必要な価値を定義し、パイロットで価値を測定することが最も重要だと話しました。AI が自社のインテリジェンスにどう関わるかを理解し、適切なツールで適切なアクセスを得ることも挙げています。

### 5.5 パイロットから本番展開へ

終わらないパイロットの問題について、Dan は、いまは以前にも増してアジャイルであることが重要だと答えました。

- 一度に多くを抱え込まない
- 作るものと、事業への価値、成功基準を明確に定義する
- 測定を前提に作る（オブザーバビリティは設計、構築、本番での監視のすべてで重要）
- 指標を達成し、証明できたら拡大する。拡大後も継続的に改善する

これは過去 10 年以上の進め方と変わらないとしたうえで、さらに速くするために、作ったものをパターン、再利用できる部品、スキルとして整え、土台にすることを挙げています。本番稼働後も、まだ効果が出ているか、変更すればもっと価値が出ないかを測り続ける必要があるとしました。小売ならではの点として、デジタルに加えて店舗があり、店舗でパイロットして成功を確認してから広げる方法もあると述べています。

Amy は、Walmart.com にいた頃の経験から、店舗と EC を持つことが差別化の機会になったこと、チャネルをまたいだ体験（オムニチャネル）の重要性に触れました。

### 5.6 エンジニアリングの変化

Rama は、エージェントが静的コード解析、リポジトリ解析、コードレビュー、静的な単体テスト、結合テストといった繰り返し作業を、人間よりずっと速く処理するようになったと話しました。これにより、エンジニアはアーキテクチャや複雑な事業課題の解決に時間を使えます。

次の段階は、エージェントが Columbia の STLC 標準（略語は音声認識の都合で確定できません）を理解し、AI エージェントやソリューションを作る際にそれを反映して、コードに違反を持ち込まないようにすることだとしています。

文脈の与え方とガードレールについての質問には、GitHub Copilot と GitHub を使って、安全なアプリケーションとソリューションを作るためのコードのガードレールを定義していると回答しました。定義し、実証できたら一般化していくという説明です。

### 5.7 運用：消費者が気づく前に

Dan は、デジタルの運用は、常時（24 時間 7 日）稼働していたい重要領域だと話しました。出発点は、環境のテレメトリとオブザーバビリティの基盤です。エージェントの時代にはダッシュボードは少し古く感じられるとしつつ、これらのシグナルをオブザーバビリティツールやダッシュボードに流し、AI とエージェントがそれを使って、従来よりずっと早く根本原因を特定していると説明しました。

人も引き続き関与し、エージェントが重大度の可能性と次の手順などの推奨とツールを提示します。小さな問題には、安全な場合にエージェントが自分で動けるように自動化を組み込むこともできるが、現在は人が関与する形から始めているとのことです。目的は、消費者が問題に気づかないよう、事前に見つけることと、運用の安定性を高めること、そしてエンジニアの負担を減らして機能開発に集中させることです。

ホリデーシーズンを控え、大きなセールの日の 1 週間前だという話が出たあと、Rama が、現在パイロット中で計画中のユースケースを補足しました。事業には毎日の予測値があり、予測からの乖離をエージェント（運用エージェント）が裏で自動検出し、誰かが報告する前に先回りして検知して、対応を促すというものです。Amy は、自動化をエージェントに任せつつ人が関与し、システムへの信頼が高まるほどこの循環が強くなると整理しました。

### 5.8 エージェンティックコマース

会場で聞いたことがある人は少数でした。Amy は、この言葉が広い世界を指すため、何を意味するのか分かりにくい用語だと述べています。

Rama は、エージェンティックコマースが何かはまだ「分かった」とは言えず、旅は始まったばかりだと前置きしました。最初に注目しているのは、**製品データを機械が読める形にすること**です。同社には、豊富な製品データ、消費者のレビュー、技術仕様があり、たとえば OmniHeat や OmniWind といった技術について、消費者にも機械にも伝わる必要があります。早期の学びは「難しいのはモデルではなく、データの準備だ」という点で、データを充実させ、エージェント経由のチャネル向けにインデックス化することが最初の一歩だとしています。モデルは競合もまったく同じものを使えるからです。

Amy は、自分が検索エンジンマーケティングの世界で育ち、キーワードが中心だったことを振り返り、いまは人が商品について話す言葉を商品カタログに反映し、データを充実させる方向に変わったと述べました。エージェンティックコマースでは最後の決済に注目が集まりがちですが、基礎データによって発見の体験が豊かになる点を高く評価しています。

Dan は、製品情報を担当する立場から、人が製品を実物で見る前にエージェントが先に見る世界では、**全チャネルで製品の見え方に一貫性を持たせること**が重要だと述べました。消費者が理解しにくい技術的な説明ではなく、フィット感や着心地といった、消費者にとっての意味が伝わるメッセージが必要だとしています。Amy は、これは製品に詳しい販売員と話すような体験に近く、従業員の負担を減らす効果もあると補足しました。

### 5.9 人間の関与とエージェントの ID

Dan は、AI は人がより良く、より速く判断するための道具だと位置づけました。競争力は判断の速さと質から生まれ、ブランドを守り、消費者と会社の財務にとって正しいことをするために、人が重要な判断を下す場所を慎重に決める必要があるとしています。

エージェントの観点では、**ID が重要**だと述べました。エージェントには ID と役割があり、アクセスできるものとできないものがあるべきです。信頼は小さく始めて育てるもので、最初から管理者権限を与えず、小さなユースケースで人が監視し、判断に加わり、スキルを積み上げて信頼を築くという方法を示しました。

また、人の判断とスピードの両立が大切で、エージェントにより多くの意味づけや事業知識を組み込めば、間違った方向に時間を使わずに済み、人が判断しながら速度も落とさないと述べています。Amy は、過去には問題も起きたが、重要な地点を見極める学びは速く進んでいるとしました。

### 5.10 導入で驚いた点

対談の最後に「これまでで驚いたこと」を尋ねられ、次の点が挙がりました。

- **コスト管理**：トークンと予算。小売は利益率に注意が必要なので、コスト管理が重要（会場の会話で出た点）
- **データ**：Rama は、最も難しいのはモデルではなく、複数のシステムに分断され品質が不十分なデータだと述べました。外部（エージェント経由のチャネル）に役立つ形に充実させることが最大の課題で、これができればモデルの利用と価値創出は容易になるとしています
- **ガバナンスと運用モデル**：AI でチームの運用が変わる中で、これらが最も難しい領域の一つ
- **モデル選択**：Amy は、モデル選択への関心が強いが、仕事に合ったモデルを選べる制御があれば必要以上にコストをかけずに済むと述べました。Rama は、基調講演で語られたように（講演者名は音声認識の都合で確定できません）、費用対効果を考慮してモデルが自動で選ばれる方向に Microsoft が投資しており、小売のように予算に敏感な企業に役立つとしています。難しいのは、データを充実させ、品質を保ってモデルに取り込める状態にする、自社の側の課題だとも述べました
- **変化の速さ**：Dan は、AI の進化の速さに加え、人、組織、事業プロセス、特にデータが引き続き重要だと述べました。エージェント活用の相当な部分は、成果を出すために働き方を変えることだとし、非効率な既存プロセスに AI をかぶせても、非効率なまま速くなるだけだと指摘しています
- **エージェントとの対話**：基調講演でエージェントがチームの一員として登場したことに少し驚いた、と Dan は話しました。エージェントには ID があるので納得できる一方、エージェントが人に何かを依頼してくる場面での対話のあり方も考える必要があるという趣旨です。Rama は、人とエージェントを招待して共同作業できるワークスペースに期待していると述べました

Amy は、Walmart のマーケティング担当だった頃、価格変更の余地という、投資判断を変えるはずのデータが商品企画チームには見えるのに自分には見えなかった例を挙げ、エージェントと基盤データがあれば（データが正確ならば）判断が賢く、速くなり、成果も強くなると話しました。

## 7. 注意点・発表者の気付き

- モデルは競合も同じものを使えるため、差別化要因にはなりません。難しいのはデータの充実と品質です（Rama）
- 既存の非効率な業務に AI を載せても、非効率なまま速くなるだけです（Dan）
- エージェントに最初から管理者権限を与えず、小さく始め、人が監視して信頼を築きます（Dan）
- ガバナンスと運用モデルは、最も難しい領域の一つです（Rama）
- コスト（トークンと予算）の管理は、利益率が重要な小売では特に大切です
- 検索やウェブサイトの最適化だけでは「昨日の課題」に取り組むことになり、エージェント経由のチャネルでの発見されやすさを考える必要があります（Rama）
- エージェンティックコマースについては、まだ答えが出ておらず、学習中という姿勢です（Rama）
- 運用エージェントによる自動対応は、現在は人が関与する形から始めています。乖離検知のユースケースは「パイロット中・計画中」であり、提供済みの成果として語られたものではありません

## 8. 利用者にとっての利点

発表で語られた効果や期待は次のとおりです。成果の数値は、発表では示されていません。

- エンジニアが繰り返し作業から解放され、アーキテクチャや複雑な事業課題に時間を使える
- 運用で、シグナルから根本原因をより早く特定でき、消費者が気づく前に問題に対処できる。運用の安定化により、エンジニアは機能開発に集中できる
- 事業の予測からの乖離を、人が報告する前にエージェントが検知できる（パイロット中）
- 製品データを機械が読める形に整えることで、エージェント経由の購買でも製品が見つかり、理解される。消費者にとっての意味が伝わる説明は、販売員と話すような豊かな体験にもつながる
- チームをまたぐデータとエージェントにより、判断が賢く、速くなる
- モデルが費用対効果で自動選択される方向の投資が、予算に敏感な小売に役立つ

## 9. まとめ

Microsoft の Amy は、自社固有のデータと知見を、4 種類の IQ と Agent 365 による信頼の仕組みと組み合わせることが、モデルが共通化する時代の差別化になると説明しました。Columbia Sportswear の Rama と Dan は、エンジニアリング、運用、エージェンティックコマースの各領域で実践と早期の学びを共有しています。共通する教訓は、データの整備、小さく始めて測定し拡大する進め方、エージェントの ID と人の関与による信頼の積み上げ、業務プロセスそのものの見直しの 4 点です。

締めくくりとして Amy は、小売の Frontier 変革に向けた推奨事項を 3 つ示しました。

1. 自分の事業部門で最も困っている領域を見極めて、ユースケースに優先順位をつける（運用とエージェンティックコマースが例として挙がりました）
2. エージェントを作り、試す。これまで技術者ではないと考えていたチームも、ツールを使って学べる。これを「学習のシステム」と呼ぶ
3. 小売向けのプレイブック（Frontier に近づくためのヒントと、事業部門別の内容）を、スライド下部の QR コードから参照する
