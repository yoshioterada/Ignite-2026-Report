## 5. 発表内容の詳細

### 5.1 Dynamics 365 ERP MCP サーバーの現状

MCP サーバーの「form interaction tools」は、アプリケーション上でフォームを見つけ、ボタンをクリックし、ビジネスロジックを実行するという、画面操作に近い形で動きます。データに対する CRUD（作成・読み取り・更新・削除）は「data tools」で、フォームの操作ツールは CRUD だけでなく、アプリケーションでできることをほぼすべて実行できると説明されています。エージェントに適切な権限を与えれば、データとビジネスロジックに対して操作できます。

この 1 年の改善として、次が挙げられました。

- 各リリースで、MCP サーバーへの小さな改善が続いている（リリースドキュメントで更新を案内している）。
- パフォーマンス改善の展開が始まっている。速度が上がり、ツール呼び出しの回数が減って、システムへの操作が効率化される。
- MCP サーバーの応答に、返されたレコードへの**ディープリンク**が含まれる。アプリケーションに戻ってワークフローを続けたり、データを検証したりできる。
- **添付ファイル**をアプリケーション内で扱える。
- **ダウンロード可能なリソース**があり、システムからエージェントにリソースをダウンロードして、コンテキストとして取り込める。

### 5.2 次のリリースの MCP 構成（MCP configurations）

MCP サーバーには、これまでハードコードされていた設定があり、最大値などを自分で調整したいという声がありました。そこで、複数の構成を作成し、エージェントがその構成を呼び出すことで、シナリオごとに設定を最適化できるようになります。

### 5.3 エージェント向けのセキュリティの刷新（10.51 で展開）

現在の MCP サーバーは、エンタープライズ品質の認証を完全にサポートしています。エージェントを通じてリクエストするユーザーは、アプリケーションで可能なことを超えては実行できません。F&O のセキュリティフレームワークのロール、デューティ、権限が常に適用されるためです。

一方、過去 1 年で最も多かった要望は、「**管理者が、エージェント経由ではアプリケーション経由より少ない操作しか許可したくない**」というものでした。そのため、10.51 で展開されるセキュリティフレームワークの大幅な刷新で、AI 時代に向けた近代化が行われます（バージョンは「10.51」と「10.051」の両方に聞こえ、表記は確定できません）。

- セキュリティ管理者は、ユーザーがアプリケーションから F&O にアクセスする場合に適用するロール、デューティ、権限と、エージェント、Cowork、Copilot などのクライアントから F&O にアクセスする場合に適用するものを、別々に定義できる。
- ユーザーごと、エージェントのシナリオごとに、細かく権限セットを定義できる。
- リクエスト時には、ユーザー ID と、エージェント ID またはアプリケーション ID（構成による）の両方が渡されるので、アクセス元の「面（surface）」に応じてセキュリティプロファイルを適用できる。

画面の例として、2 つのセキュリティロールが示されました。1 つは標準的な「accounts receivable clerk」で、もう 1 つは「accounts receivable clerk – agent」です。後者は、管理者が前者をコピーして、エージェント経由では許可したくない操作をすべて削除し、別の名前を付けたものです。ユーザーにロールを割り当てるとき、そのロールを「エージェント」にも割り当てられる、というのが新機能です。Jared 氏は、セキュリティカーネルの深い部分のコードを更新したと述べています。

### 5.4 Work IQ への Dynamics 365 ERP の統合

キーノートでも Microsoft IQ、Work IQ などの IQ が大きなテーマでした。Dynamics 365 Sales や CE が Work IQ で利用可能になっているのと同様に、ERP も Work IQ に統合されます。Word、PowerPoint、Outlook などの生産性アプリ、他のビジネスアプリケーション、Dataverse、Power Apps が 1 つの面にまとまり、Copilot や Cowork を開くだけで、セキュリティで許可された範囲のツールを単一のエンドポイント経由で使えます。

Work IQ との連携は、Work IQ MCP サーバーの 2 つのツールで実現しています。

| ツール | 内容 |
| --- | --- |
| **Ask** | 読み取り専用のクエリ。自然言語で、データに対する Q&A ができる。ACS 上の索引データと Dataverse search を使い、全文検索で素早く回答する。パブリックプレビューで、F&O の全データの一部が対象。最もよく使われる 42 のエンティティが有効になっており、データ利用の大きな割合を占めるが、全体ではない |
| **do action** | Ask で扱えないシナリオ向け。Dynamics 365 ERP MCP サーバーが、Work IQ の do action ツールの裏側につながっており、ERP MCP サーバーで有効な 65 万の操作が Work IQ から使える |

### 5.5 AI descriptions と business skills

Jared 氏は、これら 2 つが、組織のビジネスのやり方（IQ）をエージェントに伝える層だと位置づけています。

**AI descriptions（数週間前にパブリックプレビュー）。** アプリケーションのメタデータ（列名、ツールチップ、名前）をエージェントは読んで判断できますが、F&O のデータモデルには、人間が見ても分かりにくく、エージェントも混乱する箇所があります。AI description は、そのメタデータを補い、オブジェクトをエージェントがどう使うべきかの説明を付ける機能です。フォーム、エンティティ、列などに追加でき、エージェントがより適切にオブジェクトを選び、作業の流れの中で使い方を理解できるようになります。

**Business skills（今日からパブリックプレビュー）。** 10.51 のビルドを開くと、環境で使えるはずだと述べています。agent skills の仕様をもとに構築されており、仕様面で他と大きく変えたことはないという説明です。ERP のコンテキストを持ち込み、**セキュリティと追加の制約を付けて、組織内で共有できる**点が特徴です。

目的は、Copilot が Work IQ に接続したときに、ERP の使い方と「自社のやり方」の文脈を持てるようにすることです。組織固有のポリシー、プロセス、手順を定義して、エージェントの作業を導くスキルを作成します。

Cowork、Claude、Copilot Studio などにもスキルの仕組みはありますが（Anthropic がスキルの仕様を書いたとのことです）、ERP に専用のフレームワークが必要だと考えた理由が説明されました。business skills は、**F&O に保存され、F&O のセキュリティモデルで保護される共有可能なリソース**です。セキュリティロールに共有すると、そのロールのユーザーは、MCP サーバーと Work IQ を通じて、どのハーネスからでも同じスキルを使えます。そのため、組織のだれもが、どのクライアントを使っても、一貫したプロセス・ポリシー・手順に従えます。

スキルには 2 つのソースがあります。

1. **組み込みスキル（built-in skills）：** business skills が、アプリケーションオブジェクトツリー（AOT）の新しいノードとして追加された。AOT でアプリケーションを開発する ISV（発話は「building applications in X」で、言語名は音声認識の都合で確定できません）は、フォーム、テーブル、エンティティ、コードクラスと一緒に、エージェントがそのアプリケーションを使うための「知識」を出荷できる。Microsoft も、基本オブジェクト向けの組み込みスキルのライブラリを出荷している。
2. **カスタムスキル（custom skills）：** 顧客、または顧客と協働するパートナーが、アプリケーション内で作成する。顧客とシナリオを話し合い、ポリシーと手順を文書化して保存し、デプロイして、セキュリティロールで共有できる。

### 5.6 ERP in Work IQ が使える場所

ドキュメントに載っているとして、手短に紹介されました。

- **Copilot Studio**（カスタムエージェントの構築時）と **GitHub** で使える。Work IQ のリモート MCP サーバーを追加すれば、どのエージェントからでも ERP が使える。
- **Cowork** は、Ask と do action の両方に対応する。
- **Microsoft 365 Copilot Chat** は唯一の例外で、Q&A シナリオのみ。M365 の場合、Work IQ 上の ERP MCP はまだ使えず、将来対応する予定。

## 6. デモ・手順

**デモは、事前に録画しておいた会話を見せる形式で行われました。** 「短いセッションのため、あらかじめ質問して回答を得てあり、エージェントが動くのを待たずに、会話をたどる」と説明されています。画面の細部は音声からは確認できないため、語られた範囲だけを記します。

### 6.1 ERP MCP サーバーによる在庫分析と business skill の作成

1. ERP MCP サーバーを接続したエージェントに、次の趣旨を依頼する。「動かない在庫に現金が寝ている一方で、顧客が実際に注文する品目の在庫は切らしている。分析してほしい」。与えたコンテキストはこれだけで、business skill は適用していない。
2. MCP サーバーがエントリポイントを見つけ、ツールを実行して、サーバーに対してクエリを実行し、データを取得する。
3. エージェントはその分析に基づき、ダッシュボードと推奨事項を作成する。2 文のプロンプトから、ダッシュボードが返ってきた。
4. 例として、ハイエンドスピーカーが 1,000 台在庫にあり、1 台も売れていない、という点が問題として強調されている。軽減の方法も推奨される。
5. 会話を続けて調整することもできる（データの追加、ダッシュボードの変更、色の変更など）。内容が望みどおりになったら、「これでいい。business skill を作成して」と依頼する。
6. エージェントが business skill を書き、MCP サーバー経由で F&O に作成する。
7. アプリケーションで確認すると、「inventory health analysis」というスキルがある。エージェントが説明文（description）を書いており、エージェントは、この説明文で MCP サーバーや Work IQ 経由でスキルを見つける。手作業で新規作成して、内容を書くこともできるが、エージェントに作らせるほうが簡単だと述べている。
8. 作成後は、アクセスを管理できる。この時点では全員に共有されているが、特定のセキュリティロールだけに限定できる。例として、HR ポリシーを含むスキルは、アクセス権のない人には見えず、エージェントの作業の中でも使えないようにできる。

### 6.2 Cowork から Work IQ 経由でスキルを使う

1. Cowork で「inventory health の business skills は何があるか」と尋ねる。
2. スキルが返され、完全な操作が実行される。ユーザーにアクセス権があるため可能で、Work IQ 経由で取得される（前の例は ERP MCP サーバーへの直接接続だったが、ここは Work IQ 経由）。
3. 推奨アクションの選択肢が表示され、クリックすると、アプリケーション内でそのアクションが実行される。Jared 氏は、MCP サーバーは CRUD だけではなく、アプリケーションのロジックに基づいて操作を実行できると述べている。

### 6.3 キャッシュフロー分析のスキル

別の business skill として「cash flow analysis」が紹介されました。

1. 「キャッシュフロー分析をして、問題の特定と改善案を推奨して」と依頼する。
2. 売掛金、買掛金、パイプライン、回収履歴が表示される。
3. 推奨として、支払期限を過ぎた相手への督促メールの下書きが提示され、クリックして進められる。

どちらの例も、business skill によって、ユーザー・組織・ハーネスをまたいで一貫して再現できるプロセスになる、という説明です。

## 7. 注意点・発表者の気付き

- Ask は現在パブリックプレビューで、F&O のデータ全体ではなく、よく使われる 42 エンティティが対象です。
- Microsoft 365 Copilot Chat では、ERP は Q&A のみで、Work IQ 上の ERP MCP はまだ使えません。
- セキュリティの刷新は 10.51 で展開される、business skills は 10.51 のビルドで確認できると述べられています。
- 録画のデモでは、エージェントに与えたコンテキストは短いプロンプトのみで、business skill は適用されていませんでした。一方で、スキルがない状態でも MCP サーバーのコンテキストだけで分析が進むことが示されました。
- 発表では、business skills のパブリックプレビュー期間中の制約や価格については触れられていません。

## 8. 利用者にとっての利点

発表で語られた内容に基づきます。顧客事例や定量的な成果は紹介されていません。

- ユーザーが、エージェント経由でアプリケーション以上のことをできないよう、F&O のセキュリティが常に適用される。さらに、エージェント経由のみ権限を絞ったセキュリティプロファイルを定義できる。
- business skills により、どのクライアントからでも、組織で一貫したプロセス・ポリシー・手順で作業できる。スキルは F&O のセキュリティロールで共有を制限できる。
- AI descriptions で、分かりにくいデータモデルの意味を、エージェントに補足できる。
- ISV は、アプリケーションと一緒に、エージェント向けのスキルを出荷できる。
- Work IQ 経由で、Copilot、Cowork、Copilot Studio、GitHub などから、ERP の Q&A や操作を単一のエンドポイントで使える。

## 9. まとめ

Dynamics 365 ERP MCP サーバーは、ERP のデータとビジネスロジックをエージェントにつなぐ基盤で、この 1 年で、ディープリンク、添付、ダウンロード可能なリソース、パフォーマンス改善が加わりました。次のリリースでは、MCP 構成と、エージェント経由の権限を別に定義できるセキュリティの刷新が入ります。

さらに、ERP は Work IQ（Ask と do action）に統合され、AI descriptions と、今日からパブリックプレビューになった business skills によって、組織のやり方をコンテキストとしてエージェントに渡せます。Jared 氏は、business skills と Work IQ のパブリックプレビューを今日発表すると改めて述べ、プライベートプレビューに協力したパートナーに感謝を伝えました。そのうえで、パブリックドキュメント「ERP in Work IQ」（URL は聞き取れませんでした）で今日から試せると案内して、締めくくりました。
