# BRK525 Building agentic financial services solutions with Microsoft

## 1. はじめに

このセッションは、金融サービス業界のパートナー企業と顧客に向けて、Microsoft のプラットフォーム上でエージェント型の金融ソリューションを作る方法と、その事業機会を説明するものです。業界の AI 活用データ、Microsoft 365 Copilot・Microsoft IQ・Fabric・Foundry を組み合わせた構成、Moody's による実例、質疑応答の順で進みます。

主な結論は、**「情報へのアクセス」から「エージェントが支援する意思決定」へ移ること**、そして**接続（チャットボットや MCP）を作るだけでなく、成果（アウトプット）で価値を出すこと**です。金融データの提供企業にとっては、Copilot が新しい配布チャネルと収益機会になる、という主張も語られます。

### 5.1 業界コンテキスト：AI 導入の効果

最初の登壇者は、すでに成果を出している顧客として、次の例を挙げています。

| 顧客 | 発表で語られた成果 |
| --- | --- |
| Barclays | Copilot を約 10 万人の従業員に提供し、約 100 万時間を削減 |
| Investec | クライアントと過ごせる時間を 200 時間以上創出 |
| UBS | スピードを活かして、より速い意思決定 |
| BlackRock | 市場投入までの速度を高め、新商品を提供 |

また、調査に基づく数字として、リテール銀行の年間 AI 利益ポテンシャルは約 3,700 億（370 billion。通貨単位は発表では述べられていません）、アセットマネージャーはカバレッジを約 3〜5 倍に増やせる可能性があるとしています。エージェントのデプロイメントは、グラフ上で四半期ごとに 11 ポイント増えていると説明しています。

さらに、「技術の変化が速いので待つべきか」という顧客からの質問に対し、早く動く企業ほどリードを広げているというデータで答えています。

**IDC による成熟度別のリターン**

IDC は組織を AI 成熟度で 3 グループに分けています。

| グループ | AI 投資に対するリターン |
| --- | --- |
| Laggards（遅れている企業） | 0.84 倍（中立の 1.0 を下回る） |
| Neutral | 発表では数値に触れていません |
| Frontier firms | 2.84 倍（Laggards の約 3.4 倍） |

Frontier firms は AI を先に採用し、全社的な戦略を持ち、エージェント型 AI を広く使う企業です。金融サービス業界は他の業界より進んでおり、**31% の企業が Frontier** だと述べられています。

### 5.2 Microsoft の調査データ

Work Trend Index の調査で、Copilot の会話テレメトリを見ると、やり取りの **49%** が「分析・推論・判断」に関するもので、文章作成や書式設定、簡単な質問への回答ではありませんでした。AI は事実を探す道具ではなく、「思考のパートナー」として使われているという説明です。

また、AI ユーザーの上位 16% を「Frontier professionals」と呼び、次のように述べています。

- 約 80% が、1 年前にはできなかったことが AI でできるようになったと回答
- 半数を超える人が、作業の前に、自分でやるか AI に任せるかを意図的に考える
- 43% が、スキルを失わないよう、あえて自分で行う作業を残している

仕事の単位が「タスク」から「アウトカム」に変わり、Microsoft 365 のエージェント利用は前年比 15 倍に増えたとのことです。

### 5.3 顧客とデータプロバイダー、2 つの立場

技術パートの登壇者は、元は大手企業の CTO だった経験を話したうえで、「同じコインの 2 つの面」として次の 2 つの立場を示します。

- **顧客**として、これらの技術を採用する立場
- **金融データプロバイダー**として、データを顧客やパートナーに配布する立場

PIMCO と State Farm は、今週のセッションで紹介されている顧客として挙げられ、「ぜひ見てほしい」と案内されています。従業員を支援するデータソリューションを作り、さらに顧客にもデータを配布している例だという説明です。投資リサーチでは、アナリストが 30 日かけていた作業が 3 日になり、8 か月でのペイバックになるという数字も語られています（どの顧客の数字かは、発表では明示されていません）。

Moody's、GetAbstract、D&B、AlphaSense といったパートナーは、エージェント型のプラットフォームを作ってデータを配布していると紹介されています。データプロバイダーにとっては、AI 時代のリーダーになれることと、新規ユーザーの獲得や新しいサブスクリプションにつながる**新しい配布チャネル**を得られることの 2 点が意義だと説明します。例として、Microsoft 社内で AlphaSense（トランスクリプトでは音声認識の都合で別表記）のデータを使う人は 100 人だが、10,000 人にしたい、とも述べています。

### 5.4 なぜ Copilot を「1 つの UI」にするのか

登壇者は、成果が生まれる場所はメールやチャット、Word であり、「50 個のボットは要らない、1 つで十分」という考えを述べます。「すべての AI を束ねる 1 つの UI」を作っている、というのが Copilot の位置づけです。

> 補足：登壇者は、聴衆への導入として「来週、Microsoft が OpenAI を買収すると発表される」と自信ありげに話し、すぐに「正確だったか？ 全く違う」と述べています。Copilot は知っていることの範囲でしか賢くなれず、Moody's や LSEC（音声認識の都合で表記が確定できません）のような世界最高水準のデータと組み合わせて分析する必要がある、という例えとして使われています。

Copilot とデータプロバイダーのデータを組み合わせて、投資銀行のアナリスト業務、四半期レビュー、アセット・ウェルスマネジメントなど、通常は数週間かかる業務を単一の画面で行えるようにしているそうです。KYC や投資分析のソリューションも、世界水準のパートナーとともにスタック内に構築していると述べています。

### 5.5 データをつなぐ：OneLake と Microsoft IQ

「Microsoft だけの世界ではない」ため、利用者は Amazon、Snowflake、Databricks などを使っています。登壇者は、すべてを Azure に移す必要はなく、Oracle、Snowflake、ServiceNow などを接続し、**OneLake** でデータへのアクセスのインターフェースを統一することを勧めています。課題は、データを見つけて、アクセスして、簡単に使えるようにすることです。誰が質問したか、ガバナンス、監査可能性といった信頼の確保も重要だと述べます。

構成要素の説明は、次のようなコーヒーのたとえで進められます（登壇者が使ったたとえです）。

- Alexa スピーカーに「コーヒーを入れて」と頼む。これが **Copilot** というインターフェースによる基本的なタスク
- 「フレンチプレスで入れて、パントリーの豆を確認して、Costco に発注して」のような、ターンごとの自動化や、ユーザー・顧客向けの設定は **Copilot Studio** と **Power Platform** によるカスタマイズ
- Dimitrios 氏が自宅の庭でコーヒーの木を育て、コーヒーマシンまで作る、というのは、**Fabric と Foundry** を使って好きなものを作る
- Microsoft はプラットフォーム企業として、コーヒーを「すぐに届け」、パートナーが自分の「コーヒー事業」を育てるのを助ける

データは、素材（ingredients）としても、完成品としても、カスタムソリューションとしても提供でき、MCP だけでなく、カスタムのスキルやパターンを作ることで「自分のデータをこう見せたい」を実現できると説明しています。例えば、Goldman Sachs が帳簿を締める（close the books）やり方と Walmart のやり方は大きく異なるため、顧客ごとにカスタマイズできる点が重要だという説明です。

**提供時期と期間**

登壇者は、今日紹介する内容は**今すぐ使える**と述べています。データプロバイダーは誰でも Microsoft のプラットフォームへの接続とインターフェースを作れ、**約 3 週間**でデータを公開できる状態にできる、という説明です（「約 3 週間」は「I'd say」という控えめな言い方でした）。Copilot のプラットフォームを通じてデータを設定し、カスタムアプリケーションを作ることもできます。

**3 つの IQ と Microsoft IQ**

大手クレジットカード会社の CTO から「あらゆる情報を問い合わせる統合エージェントを作る」と言われた話が紹介されます（SharePoint の休暇規程、ServiceNow のチケット、Oracle の総勘定元帳など）。これを自分で作らなくても、Microsoft がすでに基盤とコネクタを用意しているという説明です。データソースへのコネクタは「10 回中 9 回」はすでに組み込まれているとも述べています。

また、重要なデータセットは ERP や CRM ではなく、**メール、チャット、ドキュメント**だという考えです。新しいクレジットラインを開く、シンガポールにオフィスを開くといった仕事は、そこで行われるためです。

| 製品 | 発表での説明 |
| --- | --- |
| Work IQ | 自分・チーム・会社が知っている知識を集めて見られるようにする |
| Fabric IQ | 分散したシステムのデータを 1 つの画面にまとめる。オントロジー（意味づけ）を与える |
| Foundry IQ | データを知識とエージェントに発展させる。顧客ごとに異なる知識の索引を反映できる |
| Microsoft IQ | 上の 3 層を統合し、セキュリティ、制御、ガバナンスを提供する |

インターフェースはすべて Copilot の 1 つの UI です。**一度発行すれば、Word、Excel、PowerPoint、Copilot、Teams のすべてのユーザーに届く**と説明されています。発行の前には、データのレビューとコンプライアンス確認も支援するそうです。あわせて、初期的な金融の機能、グラフ、セマンティックな知識を構築していると述べています。

登壇者は、リスクやリサーチの業務を速くしたいという文脈で、顧客・パートナーによる例を挙げています。不正対応が **45〜60 日かかっていたものが 4〜5 時間**になったという例です。資本市場の分野でも優れた取り組みがあるとだけ述べています。

### 5.7 Moody's の取り組み（Dimitrios 氏）

Dimitrios 氏は、Moody's Corporation のうち、旗艦は格付け機関のほうで、自分たちは、リーダー的な統合リスクプロバイダー、エンティティ情報プロバイダーとして事業を進化させてきたと説明します。

**保有するデータ**

- 公開・非公開（主に非公開）企業の世界最大級のデータベース
- 企業の firmographics に関する **6 億件超**のデータポイント
- それらの企業の財務諸表 **2 億件超**
- 詳細な所有関係のリンク
- ニュース、M&A 案件、IP、コンテンツ
- リスクとコンプライアンスに使う取引情報

これは自社で一から作ったデータではなく、多くの買収を経て形成されたものだと説明しています。

**GenAI 対応のために行ったこと**

1. データ層の整理（クリーンアップ）と、データポイント同士の接続
2. 提供方法を GenAI 対応に変更。API、スマート API、MCP、または zero copy での提供
3. データ層だけで終わらず、実際の業務フローを支援する洞察の提供。これまで強みがあり、今後さらに投資したい領域として、信用リスク（企業向け融資を含む）、第三者リスク管理（KYC・コンプライアンス、早期警戒、継続モニタリング）、不動産分析（property analytics）、サイバー

> 補足：Dimitrios 氏が取り組みの柱として挙げたのは、データ品質・接続・リネージ（規制の厳しい顧客が多いため）、洞察の提供、効率性の 3 点です。効率性には、他社プロバイダーを使う顧客も含めて自社コンテンツを簡単に使えるようにすること、MCP で生データを使う顧客が**コンテキスト内のトークンを使いすぎない**ようにコスト効率を高めることが含まれています。コストは自社ではなくエンドクライアントのコストだと説明しています。

**早期警戒（early warning）の例**

早期警戒は新しい概念ではなく、信用リスクやサプライチェーンリスクなどの悪化を示すシグナルを見つけるものです。GenAI を使って、次のことを行うと説明しています。

- 社内の情報を統合し、信用リスクだけでなく、サイバーリスク、サプライチェーンリスク、規制・訴訟リスク、不正リスクも評価する
- リスクだけでなく、将来の事業成長を示すポジティブな兆候も捉える

ニュースを例に、1 万社があり各社に 1 日 1,000 件のニュースがあるなら、MCP でニュースを取り込んで自分で指標を作ると、処理のコストが大きくなります。そこで、裏側で効率よく処理し、**生のコンテンツではなく、ビジネスユーザーが欲しい最終的なアウトプット**を提供する、という考え方です。

**提供の形**

登壇者は、これらはスライドだけでなく、実際に動いているものだと述べています。階下のブースで確認でき、トライアルも用意されているとのことです。Copilot（Teams、Excel）の中で使うことも、コンテンツと分析を集中的に使って自社でさらにソリューションを作ることもでき、「Databridge」（聞こえたまま。音声認識の都合で表記が確定できません）や Snowflake のプロバイダーと連携してデータを提供することもできます。提供方法には特にこだわらないという立場です。

### 5.9 Q&A

**Q1. 1 年前と比べて、これらのクラウドベースのソリューションの採用はどう変わったか**

Microsoft 側の登壇者は、年ごとに大きく伸びていると答えています。以前は事実を探すだけだったのが、今は推論ができ、調査、作業計画の作成、アクセス可能なデータへの接続までを含む長時間のタスクを任せられるようになった、という説明です。数字として、前年の決算時点では Copilot ユーザーが 500 万人、今は 3,000 万人、次の決算ではさらに増える、と述べています。

Dimitrios 氏は、Moody's の自社の状況として、商用融資のワークフローで約 1,500 のクライアントがおり、GenAI を使っているのはその **30〜50%** 程度と回答しました。1 年前は 10% 未満だったそうです。ただし、数字以上に顧客の期待が変わったと言います。アナリストにとって、Copilot に Moody's がないことは考えられなくなっており、顧客は「主要プラットフォームにデータと分析があるはずだ」と思っています。予算サイクルの影響で、来年にさらに採用が進む可能性もあるとのことです。

続く発言（話者は特定できません）では、ビジネス側の問いは「やるべきか」ではなく「なぜやらないのか」に変わっており、同業他社も顧客もそれを求めているので、まずプラットフォームに足を踏み入れ、収益化の仕組みを探るべきだと述べています。課金がサブスクリプションからトークン課金などに移るのか、といった問いも出てくるとしています。

Dimitrios 氏は、顧客の使い方も変わったと言います。以前は、ビジネスユーザーが投資メモや与信メモのために必要なコンテンツを Copilot に入れていました。今は組織としてコンテンツと洞察を一元化し、全社に展開できるスケーラブルなソリューションを作る議論が増えています。

Microsoft 側の登壇者は、Moody's は寛大で、Moody's にアクセスできる人は自動的に Copilot でも使える、と述べています。一方で、データパートナーによっては、Copilot で 500 ページの文書を要約したり、PowerPoint を作ったりできる新しい製品になるため、ユーザーあたり月 1,000 ドルだったものが 1,500 ドルや 2,000 ドルになるなど、ビジネスモデルが変わる例もあるそうです。あるデータパートナーは、直近の四半期に、AI が生成したデータ・投資で **2,500 万ドル**を得たと語られています（どのパートナーかは言及されていません）。

**Q2. 人が中心のワークフローの先、フルエージェント型の投資運用はいつ頃か（6〜12 か月先の見通し）**

## 7. 注意点・発表者の気付き

- **接続だけで終わらせない**：どこにデータがあるかを探して接続するだけでは足りず、「何を成果として届けるか」を考えるべきだと繰り返されています。例えば 10 億ドルを Microsoft 株に投資する場合、Moody's の格付けを取得し、CFO に渡す投資リサーチ分析を作るという成果から考えます。その分析で Moody's のデータが 90% を占めるなら価値が高いが、5% なら価値は何かを問われる、という考え方です
- **規制の厳しい環境では human in the loop が残る**：責任の所在が重要なため、融資判断やコンプライアンス判断では、当面なくならないと Dimitrios 氏は述べています
- **監査可能性**：何を使い、なぜ判断したかを証明できる必要があります
- **データの前処理**：Moody's は、買収を経て形成された自社データを、まず整理し接続するところから始めたと述べています
- **トークンコスト**：MCP で生データを提供すると、顧客のトークン消費が増えるため、コスト効率を考えて提供形態を設計したと述べています
- **ビジネスモデルの変化**：サブスクリプションからトークン課金などへ移行する可能性があり、データプロバイダーはその問いを考える必要があるという指摘があります

## 9. まとめ

このセッションは、金融サービス業界の AI 活用を、効率化の次の段階である「新しい成長・能力・成果」の段階として位置づけています。IDC の調査（Frontier firms のリターンは 2.84 倍、Laggards は 0.84 倍）や、早く動く企業ほどリードを広げているという主張が、その背景です。

Microsoft の構成は、Copilot を 1 つの UI とし、Copilot Studio や Power Platform でカスタマイズし、Fabric（OneLake、Fabric IQ）、Foundry（Foundry IQ）、Work IQ を Microsoft IQ として統合するものです。データプロバイダーは、約 3 週間で接続を公開し、一度の発行で Microsoft 365 の各アプリに届けられると説明されています。Moody's の例では、Copilot 内で複数の国の信用情報を統合し、約 4 週間で作り上げています。

パートナーへのお願いは、マーケットプレイスや agent store を通じて収益化すること、そして接続ではなく成果で価値を出すことです。規制の強い金融の意思決定では、当面 human in the loop と監査可能性が前提になる、という点も確認されています。
