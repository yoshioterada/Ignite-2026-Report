# THRSP1061 How to keep up when everyone wants more AI

## 1. はじめに

このセッションは、Microsoft 365 を預かる IT 管理者に向けた、約 20 分の実務的な話です。AI の導入が求められる一方で、ガバナンスの仕事（AI が何にアクセスできるか、どう使われているか）が増え続けている状況で、「どうやって追いつくか」を扱います。

登壇者は、ShareGate の VP of Product である Benjamin Nylam 氏です。ShareGate 製品に接続された 2,000 を超えるテナントのテレメトリと、約 1,700 人の IT 担当者への調査結果を根拠に、現場の実態を数字で示します。そのうえで、Microsoft が標準で持つレポートと SharePoint Advanced Management の使いどころと制限、そして**スケジュールで年に数回見直すのではなく、常時（always on）で統制する**という考え方を紹介します。

登壇者は冒頭で、ベンダーのピッチはしないと断っています。また、話の最後には ShareGate の無料アセスメントと関連のブースにも触れますが、中心は製品に依存しない運用上のヒントです。

画面を使った短い実演（レポートの見方や、サイトアクセスレビューの開始）が終盤にあります（6 章）。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/THRSP1061](https://ignite.microsoft.com/en-US/sessions/THRSP1061)

## 3. 何に関する発表か

テーマは、AI の活用が進むほど増える**ガバナンス運用の負荷**と、その追いつき方です。

登壇者の実感として、Copilot は個人の作業（資料やシートの作成、Microsoft 365 内のデータ収集など）の時間を節約してくれます。一方で、ガバナンスに掛かる時間は増え続けています。社内では、スキルが誰にでも作れるようになって混乱が起き、個人のスキルがあちこちに作られ、各自のコンピューターでエージェントが作られて環境内のものにアクセスしようとしたそうです。作られた成果物は、その時点の作成者の権限で生成され、中身のコンテンツごと共有されて拡散（sprawl）していく、という問題意識です。

発表の流れは次のとおりです。

1. 問題提起と調査の概要（約 1,700 人への調査、2,000 超のテナントのテレメトリ）
2. IT の現状：仕事が増え、気付くのが遅い
3. Microsoft 標準のレポートと管理センターの制限
4. 2,000 超のテナントのデータ：過剰共有、非アクティブなサイト、継承の分断、ラベル
5. 接続後の最初の 90 日で人々が取り組むこと、データ品質、検索からの除外
6. ステークホルダーを動かすピッチデッキの作り方
7. 常時ガバナンスの考え方、シャドー AI、SharePoint Advanced Management
8. 画面での実演と持ち帰りの要点

## 4. 発表者が伝えたいメッセージ

メッセージの中心は、**「年に数回の点検ではなく、常時動く統制に移る」**ことです。

登壇者は、調査の結果、71% の IT 担当者にとって、AI の登場は仕事を大きく増やしただけだったと述べています。誰も仕事が減っておらず、同じ人数と時間でずっと多くをこなしている、という状況です。そして、多くのチームは、月次や四半期のレポートなど**スケジュールに従って**、あるいは遅れて問題に気付いています。時間を節約できているのは、ポリシーや Microsoft 365 のアクセスレビューなど、プロアクティブに動く仕組みを持つチームだと説明します。

また、Microsoft の言う理想（あらゆる場所の機密ラベル、自動化された DLP）と現実には差があります。登壇者は、ShareGate に接続された 2,000 を超えるテナントで見えている現実を示します。機密ラベルの整備が進んでいなくても、あまり心配しすぎなくてよい、みんな同じ状況だ、と励ます場面もあります。そのうえで、アクセスと共有の過剰な状態（oversharing）を管理下に置くことが、自分たちにとっての防衛線だと位置づけています。

さらに、重要なのは**エンドユーザーの説明責任**です。IT だけで毎日大量に作られるコンテンツを見ることはできないため、サイトアクセスレビューなど、利用者や所有者を巻き込む仕組みを勧めています。

## 5. 発表内容の詳細

### 5.1 調査とテレメトリの概要

登壇者は、このセッションのために 2 つのデータを用意したと説明します。1 つは約 1,700 人の IT 担当者が回答した調査です。もう 1 つは、ShareGate に接続されたすべてのテナントのテレメトリで、接続したときに何に苦労するか、テナントの状態がどうなっているかを素早く把握するためのものです。

登壇者は、Microsoft の言うことだけを聞けば、すでにどこにでも機密ラベルがあり、DLP が自動化されているはずだが、それは現実ではないと述べています。セッション終了時の QR コードから、プロンプトパックやガイドも入手できると案内しています。

### 5.2 IT の現状：仕事が増え、気付くのが遅い

調査で見えたことは次のとおりです。

| 内容 | 数値・傾向 |
| --- | --- |
| AI の登場で IT の仕事が増えた | 71% |
| 問題への気付き方 | 多くはスケジュール（月次・四半期のレポート）か、手遅れになってから |
| 気付いたときの対応 | 定期レビュー、ユーザー監査、インシデントを契機に動く |
| 時間を節約できているチーム | ポリシーやアクセスレビューなど、プロアクティブな仕組みを動かしている |

多くの組織は 90 日前後の四半期ごとにレビューを行います。問題はその**間**に起きる、と登壇者は言います。機密ファイルの共有や、顧客データが Anyone リンクとともに外へ出る例があります。登壇者は、この日の会場で聞いた話として、テナントをスキャンしたところ、「People in your org」リンクで会社全体に共有されているリンクが 4,000 以上見つかった例を紹介しています。見つけた後は、置き換えるか削除するかを決める必要があります。見つけるのが 90 日に一度では時間的な空白が大きく、その間にリスクが顕在化する、という説明です。

### 5.3 Microsoft 標準のレポートと管理センター：使えるが制限がある

登壇者は、Microsoft 標準のレポートや管理センターは使うべきだとしたうえで、制限を覚えておくよう強調します。当日の発表で Microsoft が governance hub を含む発表をしていることにも触れています。

| 手段 | 制限・使い方の注意 |
| --- | --- |
| アクティビティレポート（ユーザーアクティビティ、管理 API） | データは最大 28 日分。28 日ごとにエクスポートして別の場所に蓄積しないと、遡った可視化ができなくなる |
| 権限のスナップショット | 30 日に 1 回しか実行できない。再実行を忘れないこと。共有リンクの状況は素早く見えるが、誰がいつ共有したかは分からない |
| サイト一覧のエクスポート | 100 サイトずつのグループ、最大 1,000 サイトまで CSV にエクスポートできる（SharePoint 管理センター） |
| 監査 | 180 日分の監査ログ。誰が何をしたかが分かるが、別の管理センターで取得する必要がある |

登壇者のおすすめは、**エクスポートした CSV を、自分専用の SharePoint ドキュメントライブラリに溜めていく**ことです。ライブラリに入れておけば、タグ付けなども不要で、SharePoint の新しい HTML ページ機能と Copilot を使って、レポート、ダッシュボード、ビューを生成させられる、という説明です。

### 5.4 「AI が何を出したか」は答えにくい

調査では、AI が機密データを表に出したかどうかを「分からない」と答える割合が 3 倍高い、という結果です（比較対象は発話からは確定できません）。登壇者は、AI が人々に何を伝え、何にアクセスでき、何を生成したのかを突き止めるのは今も非常に難しく、どこにも決定的な答えはないと述べます。

そこでの答えとして挙げるのが、**アクセス（oversharing）の管理**です。長年のデータ全体でアクセス権が正しいか、部署ごとに権限と共有を確認し、更新し続けるほど、セキュリティ事故や機密情報の漏えいの確率は下がります。漏えいの多くは偶発的ですが、頻度は増えています。コンテンツの生成速度は上がり続け、2〜3 人の IT チームが、成果物、ドキュメント、サイト、ページ、会話を通じた共有を管理するのは困難です。このため、**継続的に更新・修正する仕組み（always on governance）**を作ることが最善だと述べます。調査では、**53% が AI の届く範囲を完全には把握できていない**と答えています。

### 5.5 2,000 超のテナントのデータ

登壇者が示した、ShareGate に接続された 2,000 を超えるテナントの状況は次のとおりです。ShareGate は、接続して無料のアセスメントを素早く実行し、現状を見せる使い方を想定しているそうです。

| 項目 | 結果 |
| --- | --- |
| 少なくとも 1 つのワークスペースが「Everyone except external users」で共有されている | 約 98%（ワークスペースはサイト、Teams、グループなどを指す） |
| 非アクティブなサイトがある | 100%。中央値は約 290 サイト |
| 権限の継承が分断されたサイトがある | 93% |
| 機密ラベルを 1 つも定義していない | 35% |
| 最も状況の悪い 10% | 数万件規模の Anyone リンクを持つ |

登壇者は、これらを次のように解説します。

- **非アクティブなサイト**：テナントの規模にもよるが、おそらく少なくとも 300 のワークスペースが、LLM、エージェント、ワークフローなどに取り込まれる古いデータの源になっていると登壇者は述べます。将来ガバナンスに投資する際の難度も上げます。
- **継承の分断**：SharePoint で個別に権限を管理することにした状態のことです。サイトの中にはライブラリ、フォルダー、ドキュメントがあり、各階層で誰かが共有を押している可能性があります。共有を止めることはできませんが、そのたびにガバナンスで設計した権限の階層構造が壊れ、全体像が見えなくなります。外部共有ユーザーは誰か、共有した本人は、配下が継承することを理解していたか、といった点が分からなくなります。エンドユーザーは、そこまで気にして共有していません（「共有しておけばいい、時間がない」と登壇者自身も認めています）。
- **機密ラベル**：機密ラベル、DLP、Purview 管理センターによる統制は正しい方法だと登壇者も認めています。しかし現実には、ラベルは作られていても、ポリシーが付いておらず、ポリシーに基づく自動展開もされていないテナントが大半です。Purview の設定には時間と予算が必要で、組織の規模、プロセス、ポリシー（輸出管理の対象か、従業員 50 人の会社か）によって大きく違いますが、「通常は 3 か月ほど掛かる」と述べています。
- **エンドユーザー**：AI が絡む場面で、最も大きな漏えい要因を作るのはエンドユーザーであり、Anyone リンクがあちこちに作られている、と述べています。

### 5.6 接続後の 90 日間と、データ品質への対応

ShareGate に接続したテナントが、最初の 90 日間に何に取り組むかは、利用状況に基づいて次のように説明されます。

- ほぼ全員が **oversharing のレビュー**に取り組みます。どこに過剰共有のリスクがあるか、どのサイトで共有が最も多いか、直接権限が最も多いか、共有リンクが過剰か、という視点です。
- 登壇者は、ShareGate を使うかどうかは問わないとして、サイトや部署ごとのレポートを出し、**小さく始めて**、過剰共有の多いところから対処することを勧めます。**90 日に 1 回や、時間があるときではなく、常時動く形にすること**が最善だという主張です。

次に、**データ品質**の懸念が挙がります。AI が生成するコンテンツや成果物が正しくない、元の情報が誤っていてデータが古い、バージョン管理の誤用や、あちこちにコンテンツを置いたことが原因、という相談が多いそうです。Copilot は、閲覧が多く最終アクセスが新しいものなどから最善の答えを出そうとしますが、データ品質の問題は残ります。対策は次のとおりです。

- できるだけ**アーカイブ**し、理想は削除する。残す必要があれば Microsoft のアーカイブを使う。
- **RCD や restricted search** を設定し（RCD の正式名称は発話では語られていません）、特定のサイトを検索結果、ひいては Copilot の結果から完全に除外する。「まだ準備ができていない、今は制御できない」場所は、検索や AI による自動化の対象から外す、という使い方です。
- 統制が効かなくなった場所は、ステークホルダーに理由を説明し、アセスメントを実行して価値を訴えたうえで、アクセスを絞る。

### 5.7 ステークホルダーへのピッチデッキ

登壇者が社内でも顧客にも非常に役立ったと述べるのが、**ピッチデッキを AI に作らせる**ことです。Copilot や Claude（音声では「Cloud」と聞こえます）など使っているものを、ガバナンスのデータ（エクスポートした CSV など）につなぎ、ステークホルダー向けに「現環境のリスク分析」のデッキを作らせます。内部データにつないだ MCP、あるいは Microsoft 365 に接続して使う方法があります。

登壇者は、これなら、デッキを作ったことがなくても、言葉遣いや用語の調整、結果（アウトカム）志向への移行を助けてくれると言います。「仕事が多くてできない」と言うだけではなく、AI でスピードと成果を追う経営側に、リスクや成果の観点で提示すれば、彼らもコストを抑えたいと考えているため、伝わりやすい、という説明です。

### 5.8 常時ガバナンス、インシデント、シャドー AI

調査のスローガンとして挙げられたのは、「遅く気付く、死角のある、より多くの仕事」です。対策は短期集中ではなく**常時ガバナンス**です。

- **インシデント**：1,700 人の IT 管理者の回答では、77% が昨年少なくとも 1 件のガバナンス上のインシデントを経験しました。主な原因は、古いアクセス、監査・コンプライアンスの欠落、oversharing です。
- **プロアクティブな効果**：「1 年のうちにインシデントがあったか」という問いで、プロアクティブに常時監視しているチームは、問題や緊急事態が少なくなる、と述べています。発話には「最大 30%」「10% 少なく」といった数字が聞こえますが、何に対する割合かが不明瞭なため、数値は確定できません。
- **Shadow IT / Shadow AI**：登壇者は、現在は「SaaS は無料」だと言います。社内で誰でも無制限のトークンを使えるようにしたところ、マーケティングや財務の担当者が小さなアプリを作り、あちこちで各種データにアクセスしているそうです。以前は安全なソリューションを探していたところ、自分たちで作る流れになっています。この項目は今後大きく増えると予想し、どこに何があり、何にアクセスしているかの可観測性が重要になる、と述べています。

### 5.9 SharePoint Advanced Management

登壇者は、SharePoint Advanced Management（SAM）は pro 機能の位置づけですが、Copilot ライセンスがあれば利用できるようになる、と説明します。取り上げられた機能は次のとおりです。

- **Data access governance**：「Everyone except external users」の共有リンクなど、共有に関する検出結果（findings）を確認できます。
- **サイトアクセスレビュー**：利用者の説明責任を担保する仕組みです。IT だけで毎日大量に作られるコンテンツを見るのは無理で、Copilot ワークスペースなど各自が各所で同時に作る時代には、エンドユーザーに賭けるしかない、と述べています。最低でもスケジュール運用にし、理想は、何かを検知して利用者や所有者に自動で能動的に確認を求める形です。
- **Restricted site access**：前に説明した、検索や AI の対象から特定の場所を外す話と並べて触れられ、「このサイトは今は要らない、外したい」ときにブロックする、という使い方が語られました（詳しい説明は発表ではありません）。

同日の発表で、一部の新機能は 12 月に提供される予定で、まだテナントにないかもしれないが、当日公開されたブログで紹介されている、と説明しています。上述の制限（28 日、30 日に 1 回）はあるものの、まず取りかかるための最低限の価値は得られる、という位置づけです。

## 6. デモ・手順

セッションの終盤で、登壇者は「little demo here」と述べ、SharePoint のレポート画面を見せています。語られた範囲の内容は次のとおりです。画面の細部は音声からは確認できません。

1. **アクティビティレポート**：機能一覧を見せます。「あちこちを回って答えを探す必要があるが、答えは多くある」と述べます。SharePoint のアクティビティセンターにも洞察があり、レポートや Data access governance から各種レポートを実行できます。
2. **制限の確認**：画面上で、データが直近 28 日分であることを示しています。
3. **共有リンクの確認**：「Everyone except external users」の共有結果を見ます。結果が出るまでに時間が掛かる場合があります。登壇者は、結果が常に即座に出る形が好みだと述べます。
4. **結果のダウンロード**：ダウンロードは自分のコンピューターに行われ、自動化するにはワークフローを自作しなければなりません。ライブラリに入れておくよう勧めています。
5. **サイトアクセスレビューの開始**：Data access governance から、サイトアクセスレビューを開始します。登壇者は「とても簡単」と述べ、対象のサイトを選ぶ流れだと説明しています。

登壇者は、レビューをスケジュール（30 日・90 日ごと）にすると、利用者がなぜ依頼されたのか分からなくなるため、レビューが必要な場所をプロアクティブに検知する方法を探すことを勧めています。輸出管理などで厳格なプロセスと適合の証明が必要な場合は別だが、テナントを統制するだけなら、より自動的なものが望ましい、とも述べています。

## 7. 注意点・発表者の気付き

- **標準レポートの期限**：アクティビティ系のデータは約 28 日分、権限スナップショットは 30 日に 1 回。放置すると見えなくなる、または古いままになります。
- **監査ログは 180 日**：取得には別の管理センターが必要です。
- **ダウンロードは手作業になりがち**：自動化するにはワークフローの自作が必要です。
- **スケジュール運用の弱点**：90 日の間に事故が起きます。また、スケジュールで依頼されたレビューは、利用者が理由を理解しにくくなります。
- **機密ラベルは理想だが時間が掛かる**：通常 3 か月ほど。登壇者は、ほとんどの組織がまだ設定できていないとして、「心配しすぎなくてよい」と述べています。
- **新機能の提供時期**：一部は 12 月提供予定で、今のテナントにない可能性があります。
- **すべてを IT が見ることはできない**：エンドユーザーの説明責任と、検知に基づく自動依頼が必要です。

## 8. 利用者にとっての利点

発表で語られた利点・成果は次のとおりです。

- プロアクティブな仕組みを持つチームは、時間を節約できている。常時監視のチームは問題も少ないという趣旨の説明もある（数値は不明瞭）。
- 標準レポートの CSV を自分専用のライブラリに蓄積し、Copilot で HTML レポートやダッシュボードを生成できる。28 日で消えるデータを溜めておけば、遡っての可視化にも使える。
- Copilot や Claude にガバナンスデータを読ませたピッチデッキは、ステークホルダーへのリスク説明に役立つ。
- 登壇者の所属である ShareGate は、無料アセスメントと MCP を提供している（発表の終わりでの案内）。

## 9. まとめ

AI の導入で IT のガバナンス業務は増えており、多くのチームは四半期ごとのレビューで、遅れて問題に気付いています。2,000 を超えるテナントでは、98% に「Everyone except external users」のワークスペースがあり、100% に非アクティブなサイトがあり、93% に権限継承の分断があり、35% が機密ラベルを 1 つも定義していません。

登壇者の処方は、標準レポートと SharePoint Advanced Management を、制限（28 日、30 日、180 日）を理解したうえで使い、エクスポートを蓄積し、小さく始めて、**常時動く仕組みへ移す**ことです。持ち帰りの要点として挙げられたのは、テナントを一巡して調べ（sweep）、1 つ直し、ポリシーにし、常に自動にする、という流れです。

発表の最後に、ShareGate のブースで配るピン（プロンプトパックの URL 付き）と、ShareGate による無料アセスメント、MCP の案内がありました。
