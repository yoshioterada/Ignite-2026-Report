## 1. はじめに

### 5.5 顧客事例

Shiv 氏は、150 社の中からいくつかの例を紹介しています。

**保険業界の顧客（融資の審査）**

融資の組成に 1 週間以上かかっていたため、顧客が他社へ移り、融資の件数が伸びていませんでした。カスタム開発を行い、Azure AI agents を使って、融資の組成から実行までを **10 分以内**に短縮したと説明しています。Azure ネイティブの機能と、client zero で得た学びを組み合わせた成果です。

**製薬業界の顧客（規制対応の文書チェック）**

創薬に必要な規制関連の文書について、多数のコンプライアンスチェックが必要で、これが数日かかっていました。GitHub Copilot のネイティブ機能でエージェントを作って本番に展開し、地域ごとに異なるコンプライアンス用のバリエーションも用意しました。グローバルな製薬顧客のためです。結果として、処理が **1 分**に、コストは**処理する文書 1 件あたり 1 ドル**に下がったと述べています。

**Project Vector（動画）**

メールのスレッドや添付ファイルに埋もれたプロジェクトの知識を、Microsoft のサービスだけで、統治された検索可能なナレッジベースにする例です。内容は 6 章に書きました。Shiv 氏は、非構造化データを抱える顧客から「プロジェクトがあり、知見があり、関わる人がいるのに、ナレッジが消えてしまう」という実際の課題が聞かれたと説明しています。この事例から、再利用できるナレッジエージェントとナレッジ記事を作れたそうです。

### 5.6 エージェントをスケールさせる「ファイアウォール」と 5 つの取り組み

Shiv 氏は、エージェントは簡単に作れるが、スケールさせるのが難しいという話が各所で語られていることに触れ、企業が越えるべき関門を「ファイアウォール」と呼んで整理しています。例として次が挙がりました。

- **パイロットから本番へ**：多くの PoC は本番にたどり着かない。どう取りまとめるか。
- **スプロール（乱立）の抑制**：3,000 を超える、使われず ROI も出ていない古いエージェントがある顧客がいて、それらを隔離（quarantine）した。
- **ライセンスとトークンの管理**：価値を生む形で消費されるようにする。
- **エージェントの民主化**：Wipro は、世界中の citizen developer とエンジニアから **29,000 を超える**エージェントを開発した。ただし、すべてのエージェントはセキュリティスキャンと脆弱性スキャンの厳格なプロセスを通り、顧客に持っていけるエンタープライズグレードのものにしている。
- **ROI は最後ではなく、各段階で見る。**

これを受けて、「自己資金で回る（self-funded）エージェント型企業」を目指す 5 つの取り組み（key moves）が説明されました。

1. **産業化（industrialize）と本番までの道筋**：Copilot Studio 上に、ビジネス・機能別のユースケースのライブラリを持ち、本番稼働のエージェントは **350 以上**。Ramu 氏が述べた成果に寄与している、という位置づけです。
2. **一貫したプラットフォーム**：単一のプラットフォームにそろえることで、コストと、プラットフォーム間での作業の受け渡しを管理しやすくし、**コストを 40% 削減**した。
3. **経済面の把握**：使われていないライセンスは回収して再利用し、本当に必要な人が使えるようにする。
4. **ガードレール付きの民主化**：定められたガードレールを守るよう、COE や、定期的に開く council の仕組みで運用する。
5. **各段階での価値の証明**。

> 補足：本番稼働のエージェント数について、5.1 では「75 以上」、ここでは「350 以上」と語られています。発表ではこの 2 つの関係は説明されていません。

### 5.7 agent economy：Copilot command center と 3 階層の計測

価値を証明するための agent economy は 4 つの柱で構成されると説明されました。これらを **enterprise command center（copilot command center）**で扱います。

| 柱 | 内容 |
| --- | --- |
| Licenses | 割り当てに応じて価値が出ているか |
| Lifecycle | 構築から廃止（retire）まで |
| Tokens | すべてのエージェントに予算と責任者（owner）を持たせ、問い合わせができるようにする |
| Identity | 各エージェントが何をしているかが分かるようにする |

効果の追跡は、3 つの階層で行います。

- **ユーザー・チームの階層**：最も基本的な単位
- **事業部（business unit）の階層**：サイクルタイム、スループット、cost to serve
- **企業全体の階層**：価値、運用コスト（run cost）、キャパシティ

進め方としては、立ち上げる前にベースラインを取り、テレメトリを作って追跡します。レビューは、アウトプットやスループットだけでなく価値に着目して行い、最も ROI の高いエージェントに再投資します。

### 5.8 Microsoft を選ぶ 4 つの理由

Ramu 氏は、企業にとって選択肢は多い中で、Wipro が顧客向けに評価する際の、Microsoft の差別化点を 4 つ挙げています。

1. **独立性（independence）**：Foundry で多様なモデルを選べるため、最も低いコストでインテリジェンスを使える。
2. **相互運用性（interoperability）**：Fabric と Foundry により、多様な環境との統合（heterogeneity）を実現できる。開発者が GitHub をより広く使っていることも挙げられた。
3. **信頼（trust）**：Entra ID、Purview、Defender に深く取り組んでおり、これを Agent 365 につなげている。エンタープライズグレードの ID を作ることが重要で、Ramu 氏は「このような製品は他に見たことがない」と述べている。
4. **スケール**：多くのエンドユーザーが Microsoft の製品をすでに広く使っており、それがスケールに効く。

さらに、Wipro が Microsoft スタックの上に加えているものとして、次が挙げられました。

- **独立性（モデルの選択）**：顧客のニーズを理解し、どのモデルを選ぶかを複数の顧客・ユースケースで実践してきた。約 **2,000 の業界ユースケース**（10 セクター、6 機能にまたがる）を作り、モデル選択のテンプレートを用意している。
- **相互運用性**：エージェントと Wipro のプラットフォームの連携で、精度を高める。
- **信頼とスケール**：規制や PII などのデータに関する顧客の期待と、Microsoft スタックでのスケールという観点だと述べるにとどまり、詳細は語られていません。

### 6.2 Project Vector の動画

ナレーションでは、Microsoft のサービスだけを使い、Azure、Microsoft Fabric、Azure AI Foundry、Copilot Studio で構築した AI ナレッジアシスタントとして紹介されています。課題は、メールの山、Excel のプロジェクト計画、Word の分析のどこかに知見があるのに、経営層が「何が遅れているか、リスクは何か、誰が担当か」を知るために、人が手作業で探している点です。仕組みは次の順です。

1. メールが届くと、**Event Grid** が即座に **Azure Function** を起動する。
2. 関数は、メールを構造化 JSON（送信者、受信者、件名、スレッド、タイムスタンプ）と、添付ファイルすべてのマニフェストとして書き出す。
3. **Azure AI Document Intelligence** が、スプレッドシートや Word 文書の添付を読み、表とキーバリューペアを抽出する。
4. **Microsoft Fabric** のメダリオンアーキテクチャで整理する。Bronze に抽出した生データ、Silver にメールと添付のきれいなテーブル、Gold では **Azure AI Foundry の LLM** が、プロジェクト、リスク、アクションといった重要事項を抽出する。
5. これらのインサイトをチャンク化・ベクトル化して **Azure AI Search** に入れ、キーワードだけでなく意味で答えを探せるようにする。
6. **Vector Assistant**（Copilot Studio のエージェント）は、このナレッジのみに基づいて回答する（Web 検索はオフ）。回答は Microsoft Teams の中で、平易な英語で返る。
7. 遅れている作業ストリームを、メールに添付されたプロジェクト計画のとおりに挙げ、出典も示す。
8. 経営層向けには、1 クリックで、リスク、アクション、担当者のダッシュボードが開く。

ナレーションは、メールとドキュメントで動くあらゆるプロセスに使える、再利用可能な blueprint であり、「あなたの受信箱が、ナレッジベースになる」とまとめています。
