# BRK418 What’s new and what’s next for Windows Server

## 1. はじめに

このセッションは、Ignite 2026 の週に基調講演で発表された **Windows Server 2028**（パブリックプレビュー開始）について、方向性と新機能を 2 人の登壇者が分担して説明するものです。登壇者は冒頭で、本来のセッションタイトルは Windows Server 2028 を含む名前になるはずだったが、情報解禁前だったため現在の題名になった、と話しています。

内容は 3 つの章で進みます。

1. Windows Server 製品の戦略的な方向性（なぜ、どこへ向かうのか）
2. 2025 とプレビュー中の Windows Server 2028 の新機能
3. 次の Ignite（2027）までに見えてくるもの

前半は、「コンピュート・ストレージ・ネットワーク・データベース」という従来の 4 本柱に、**インテリジェンス（推論、token factory）** を加えた 5 本柱という考え方と、オンプレミスの推論基盤を束ねる「inference factory fabric」のライブデモが中心です。後半は、**既定でセキュア（secure by default）** への方針転換、レガシー機能の削除、ストレージ・ネットワーク・アップグレード・クラスタリング・管理に関する変更点が、駆け足で紹介されます。

最後に、Windows Server 2025 向けの hotpatch 無料化、AVD hybrid の GA、Windows Server 2016 のサポート終了（ESU）についての案内があります。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/BRK418](https://ignite.microsoft.com/en-US/sessions/BRK418)

## 5. 発表内容の詳細

### 5.1 Windows Server の現状と、これまでの 20 年

冒頭で Neil 氏は、FY26 はサーバービジネスにとって非常に良い年だったと報告しています。Azure 上の Windows Server、Azure Arc を接続した Windows Server のハイブリッド、そして従来型のビジネスの、すべてが成長しました。特に従来型のビジネスは、5 年間で最も強い年に近い成長だったとのことです（具体的な数値は語られていません）。

Windows Server の役割は、20 年以上にわたる「計算基盤とアプリケーション配信の信頼できる土台」だという位置づけです。まず企業のネットワークとアイデンティティをつなぎ、次に業務アプリを動かす仮想化・コンテナー基盤を築いてきました。そして今年、新しく **ハイブリッドインテリジェンス** を加えます。この「Big Four が Big Five になる」という言い方が、発表全体の枠組みです。

| これまで（Big Four） | 今回加わるもの |
| --- | --- |
| コンピュート、ストレージ、ネットワーク、データベースサービス | インテリジェンス（推論、token factory） |

また「どこで動くか」も重要だと述べています。Windows Server は Azure でも大規模に動き、100% クラウドの顧客も、100% オンプレミスの顧客もいて、ハイブリッドの顧客は増え続けている、という認識です。Microsoft は「顧客のいる場所に合わせる」としています。

### 5.2 今後 10 年の「変わらない 4 つの柱」

Neil 氏によると、2028 のロードマップを検討する際には、その 3 年後、さらにその 3 年後も見据えたそうです。2034 年に必要になる具体的な機能は予測できませんが、投資の指針になる **長く続くテーマ** は見えるとして、次の 4 つを挙げています。

1. **セキュリティ**：SQL Server などの重要なアプリや、ネットワーク・ストレージ基盤を動かす Windows Server を守ることが最優先の仕事です。Microsoft 自身も Windows Server で動いていると述べています。毎リリース、trusted launch virtual machines や confidential virtual machines のような技術に投資し、さらに機能というより、OS のセキュリティの基準そのものを引き上げて「出荷時点で既定で安全」にしていきます。

   > 注意：IT 管理者に向けて、これは本気の話だと強調されました。ベースラインが上がるため、管理者は **そのベースラインを慎重に検証する必要が出てきます**。20 年間のやり方のままでは、新しいツールで加速する攻撃者に追いつけない、という理由です。

2. **Azure の価値を届ける**：Arc を通じて、価値の高い Azure サービスをどこにいてもハイブリッドクラウドに提供します。同時に、Windows Server 資産のうち Azure に移すのが適切な部分を、希望する速さで Azure に移せるようにします。毎リリースで両方向に投資します。
3. **Hybrid intelligence**：オンプレミスの計算基盤が久しぶりに大規模に作り直される、その「最初の数イニング」にいるという認識です。毎リリース、小売拠点や企業データセンターに置く inference factory の設定、デプロイ、管理、スケール、保護を助ける AI 推論機能に投資します。
4. **その時々の課題を解く**：上の 3 つを達成しても、2031 年や 2034 年の時点で、その時の問題を解決できなければ製品として選ばれません。そのため毎リリース「今の問題」を見ます。例として、Eldon 氏が話すと予告された「仮想化プロバイダーから Hyper-V への移行」が挙げられています（ただし、この移行について詳しい説明は、実際には語られませんでした）。

### 5.3 Hybrid intelligence：token factory という 5 本目の柱

#### 「適切な知能を、適切な場所に、適切な価格で」

Neil 氏は、この 1 年、世界各地の顧客が推論計算の一部をオンプレミスの **token factory** に移していると話します。AI サービスはクラウドで生まれましたが、顧客は「適切な知能を、適切な場所に、適切な能力で、事業のコスト構造に合う価格で置くにはどうするか」と問い始めているというのです。

この問いに答える場所は 3 層あります。

| 層 | 内容 |
| --- | --- |
| クラウド | Azure と Microsoft Foundry が提供できること |
| Token factory | データセンターや支店にある推論基盤。従業員の AI 体験の「推論の頭脳」 |
| クライアント | 従業員が手にするデバイスの能力（この週に Windows 11 チームが発表した、Copilot Plus PC の RTX Spark などに言及） |

「適切」の中身は次のように整理されています。

- **場所**：業務の種類、規制環境、知的財産の機微さ、パブリッククラウドに置くか自分で所有・管理するかによって決まります。
- **能力**：従業員が日々行う仕事に、どのモデル・harness・ハードウェアの組み合わせが適するか。
- **価格**：AI の計算がスケールするほど収益が伸びる顧客は、次の 100 万出力トークンの限界費用を気にしません。一方、その限界費用を非常に気にする顧客もおり、そうした顧客はクライアント、クラウド、token factory の配置を最適化して、能力・配置・価格が安定する均衡点を探します。

Neil 氏は、この問いの答えは「or」ではなく「**and**」だと述べます。100% ローカルでクラウドの AI を一切使わない組織も、100% クラウドでデバイスやデータセンターのトークンを一切使わない組織も、ごく少数にとどまるという見立てです。話をした顧客の大多数はハイブリッドだったとのことです。

#### Microsoft の役割と、一貫したガバナンス

Microsoft は Azure、Windows クライアント、Windows Server をまたいで、デバイスとサービスのポートフォリオを一貫させます。Foundry カタログのモデルをどこでも使えるようにし、3 種類のカタログや 3 種類のデバイスを使い分けなくて済むようにします。自前のモデルや harness を持ち込む場合も同様です。ガバナンスとセキュリティも、クラウド、推論対応クライアント、データセンターの token factory で別々のツールにならないようにする、という説明です。

顧客が次に抱く不安は、「200 万ドル分の token factory を導入し、何千ものエージェントが動いていて、怖い」というものだと紹介されています（これは Neil 氏が顧客との会話として語った例です）。これに対する Microsoft の答えは 2 つです。

| 仕組み | 役割 |
| --- | --- |
| **Agent 365** | エージェントに **アイデンティティ** を割り当てる。「このエージェントは Neil の延長」「このエージェントは隣で動く SQL Server データベースの延長」のように位置づける |
| **Microsoft execution containers（MXC）** | **強制** のための仕組み。「このエージェントはソフトウェア開発用でソースコードにはアクセスできるが、経理データベースにはアクセスできない」「このエージェントはエアギャップ内にある」といった制約をコンテナーで担保する。ネットワーク面の対策を信頼したうえで、さらにコンテナーで囲む |

Agent 365 と MXC は、クラウド、クライアント、token factory の 3 層で一貫して使えると説明されています。

#### Windows Server の 3 つの優先事項

Windows Server が担う token factory 層について、Neil 氏は 3 つの優先事項を挙げています。

1. **シンプルさ**：すぐ立ち上げて一貫して使えること。今使っているアイデンティティシステムと統合できること（企業の ID・認証の仕組みをやり直させる製品は買われない、という主張）。
2. **ハイブリッド**：単体の製品ではなく、全体の一部であること。発表では GitHub の "Fusion router"（音声認識の都合で表記が確定できません）や、Agent 365、MXC との統合に言及しています。
3. **ハードウェア対応**：推論基盤は動かすハードウェアの質で決まるため、サーバーノード向けの主要な推論プラットフォームを Windows Server がサポートすること。

#### 新しいアクセラレーター 2 製品

Windows Server 2028 の波に合わせて、次の 2 つが発表されました。

| 製品 | 提供時期・特徴 |
| --- | --- |
| **DGX Station for Windows Server** | Windows Server 2028 の GA 時に提供予定。NVIDIA との協業。Windows クライアント向けの DGX Station も発表済みで、Windows プラットフォームなら両方を提供しやすい、と説明されています |
| **AMD Instinct MI350P** | PCIe の単体アクセラレーターカード。Windows Server 2025 向けに 2027 年前半にプレビュー、その後 Windows Server 2028 でも利用可能。144 GB の HBM3E を搭載（聞こえた数値）。1 枚で factory を動かすことも、1 ノードに複数枚を挿して agentic なソフトウェアエンジニアリング用サーバーをスケールすることもできる |

加えて、サポート対象のアクセラレーターは幅広く、Intel と AMD の、意味のある推論ができる CPU も含まれます。「食料品店に行くのにいつも Ferrari に乗る必要はない」という例えで、推論に常に最高性能のハードウェアは要らず、業務タスクに必要なものを選べばよい、と説明しています。

#### DGX Station for Windows の紹介ビデオ

ここでビデオが上映されました。録音には、NVIDIA の Grace Blackwell 300 推論プラットフォームの性能と Windows の馴染みやすさを組み合わせたデバイスであること、という説明が残っています。Windows Server 2028 では、普段事業を動かしているのと同じツール、プロセス、コンプライアンスのベースライン、認証ポートフォリオが、GB300 を搭載したワークステーション型・ラックマウント型のデバイスで使えるようになる、という内容です。

それに続いて、Windows 11 向け・Windows Server 2028 向けのどちらの DGX Station にも関心がある人は、画面の QR コードから声をかけてほしいという案内がありました（映像の音声か登壇者の発言かは、録音からは区別できません）。

#### Inference factory fabric（限定プレビュー）

Neil 氏は、748 GB のコヒーレントメモリ（聞こえた数値）と B300 の力でも足りない顧客がいると続けます。1 つの token factory から 50、500 へとスケールする場合、従業員のデスクごとにストレージクラスターを置かないのと同じように、計算を中央化して抽象化する仕組みが必要です。

Neil 氏の主張は、**token factory は従業員にとって、自分が使う harness に並ぶ追加モデルにすぎないものであるべきで、従業員が「672 番の token factory の IP アドレス」を知る必要はない** というものです。そこで、**Microsoft Foundry を Windows Server 2028 技術で作った token factory フリートに拡張する限定プレビュー**が発表されました。ストレージ、ネットワーク、コンピュート、データベースの配信と同じように、AI factory を「ファブリック」として管理できるようにする狙いです。これは Windows Server TAP プログラムの一部で、早期アクセスのビットは TAP に参加して入手します。このあと Neil 氏は、デモを始める前に、まず構想を説明しています。

構想として語られた内容は次のとおりです。

- 企業の顧客は、「エージェント型コーディングにはこのモデル」「推論にはこのモデル」「業務プロセスにはこのモデル」と標準化を進めている。その複雑さをエンドユーザーから隠す。
- ファブリックは、前面の「入口」（durable namespace）として機能し、クラスターを抽象化する。
- 必要に応じて Azure の Microsoft Foundry を取り込み、ハイブリッドを実現する。フロンティアモデルの力が必要なとき、ピーク需要でモデルの処理能力を急増（surge）させたいときなどが例です。
- 経済的に最適な構成として、データセンターには「P80」の推論計算能力（聞こえた表記のままです。意味は発表では説明されていません）をプロビジョニングし、残りをクラウドに逃がす、という考え方も語られました。
- 将来的には、企業ポリシーでこのファブリックを制御し、「Neil は何にアクセスできるか」「Neil のチームは何にアクセスできるか」「別の事業部は何にアクセスできるか」を決められるようにする。

デモの後、Neil 氏は TAP への参加を再度呼びかけ、案内（URL か QR コード）を画面にしばらく出したままにして、参加者がスマートフォンで読み取れるようにしました。この後 Eldon 氏に交代します。

### 5.4 Windows Server 2028：セキュリティ

ここから Eldon 氏の担当です。最初に「Windows Server 28」と言えるのが嬉しい、とも述べています（これまで社内では「V next」と呼ぶことになっていたため）。

#### Secure by default への方針転換

従来の Windows Server は、アプリの互換性を優先して「開いた状態」で出荷され、セキュリティベースラインや文書を公開して、何をロックダウンするかは顧客が判断していました。2028 では、この考え方を根本から変えます。

- **まず Server Core から**、出荷時点でセキュリティベースラインを既定で適用する。
- 動かないアプリがあれば、後から緩める。
- 狙いは、「次へ」を押すだけの経験の浅い管理者でも OS が既定で安全であり、後からロックダウンするプロセスに頼らなくてよい状態にすること。

> 注意：Eldon 氏は、これにはアプリ互換性のリスクがあると明言しています。「crawl, walk, run（這う・歩く・走る）」の段階的なアプローチで、Server Core のみを対象とし、デスクトップエディションにも適用すべきかについても意見を求めています。リリースまでの 1 年間でフィードバックを元に調整したい、という立場です。

#### Hyper-V：Azure の技術をオンプレミスへ

Azure にすでにある **trusted launch virtual machines** と **confidential virtual machines** を、Hyper-V を使うオンプレミスのデータセンターに持ち込みます。

> 注意：Confidential VM は MVP（最小構成）から始まり、徐々に拡張されます。最初は **ステートレスな VM** が対象で、**アテステーション（構成証明）は Azure 経由**で行われるため、最初のバージョンでは **切断環境（disconnected）をサポートしません**。

#### レガシーコンポーネントの積極的な削除

従来は「使っている人は少ないだろうが、残しても害はない」として古い機能を残していましたが、その方針を変えます。理由は、AI ツールがセキュリティ脆弱性を驚異的な速度で見つけているためです。Eldon 氏は、10 月の更新（発表では "10B" とも聞こえます）で、Windows の歴史上最も多くの MSRC（発話は "MSRCs"）を投入したと述べ、開発チームが総力で脆弱性の修正にあたっていると語っています。古いレガシープロトコルの上に作られ、書き直さない限り安全にできない部品があるため、それらを削除します。

ただし、そうした古いコンポーネントを今も使っている場合でも、Windows Server 2025 には 10 年のライフサイクルの間は残ります。

特に今から考え始めるべき項目として次が挙げられました。

> 注意：**レガシー BIOS のサポートを削除する**ため、Windows Server 2028 は **Gen2 VM が必須**になります。**Gen1 VM に新しい Windows Server をこれ以上デプロイしないでください。** 2028 へのインプレースアップグレードには Gen2 VM が必要になります。このスライドの持ち帰りポイントは「今日から Gen2 VM を使い始めること」だと Eldon 氏は強調しています。

#### ファイルサービス、Active Directory

- ファイルサービス：**SMB1 プロトコルを削除**。SMB の MFA 機能と、構成ドリフトを防ぐポリシーを検討中と説明されています。
- Active Directory：ポスト量子コンピューティング対応は「旅」であり、Windows Server 2025 で一部を取り込み済み、2028 でさらに進め、2028 以降にも続く。AD とセキュリティ、管理に関する強化は多数あるが、時間の都合で駆け足で進める、と述べています。

### 5.5 Windows Server 2028：インフラストラクチャ

#### ストレージ

- **ネイティブ NVMe**：Windows Server 2025 に導入済みで、既定では無効。レジストリキーで今日から有効にできます。Windows Server 2028 では **既定で有効** になります。IO 性能（IOPS）が上がり、IO レイテンシと CPU オーバーヘッドが下がります。クライアントにも提供予定で、Windows Insider ビルドで確認できます。
- **NVMe over Fabrics**：イニシエーターが 28 に入ります。出遅れていることは認めつつ、約 2 週間後に Insider ビルドへ強化を投入するとし、性能は「Linux を打ち負かす」ほどになる見込みで、ブログで詳細を案内するとのことです。SAN を使う人向けの機能という位置づけです。
- **ReFS をブートボリュームに対応**：ReFS には「このシナリオでは動かない」という細かい制約が多くありましたが、これを解消し、NTFS とのシナリオ・機能の同等性を目指します。

#### ネットワーク

- **耐障害性（resiliency）**：CrowdStrike の事案に触れ、サードパーティの更新でシステムが動かなくなる事態に OS が耐えられるようにする、Windows の大きなレジリエンス施策の一部だと説明されています。クライアント向けの施策がサーバーにも来ます。その大きな変更が、**ネットワークドライバーをカーネルモードからユーザーモードへ移す** ことです。
- **Zero-touch DNS**（聞こえた表記のままです）。
- **ソフトウェア定義ネットワーク（SDN）**：現在は VM（アプライアンス VM）で提供されていますが、OS に統合されたサービスになり、アプライアンス VM が不要になります。

#### アップグレード

アップグレードの基本は 2025 と同じです。

- メディアによる **N-4 アップグレード** をサポート。
- **Windows Update 経由のフィーチャーアップデート**：既定では無効ですが、オプトインで有効にできます。ノートパソコンと同様に、ボタン 1 つ、再起動 1 回で次のリリースに上がれます。
- **アンインストール（ロールバック）**：Windows 11 クライアントの仕組みをサーバーに持ち込みます。ただし期限は約 2 週間で、それを過ぎると前のリリースに戻せません。

#### フェイルオーバークラスタリング

- **Cluster-Aware Updating（CAU）** の強化：これまで CAU は別コンポーネントで、クラスターサービスに多数の WMI 呼び出しを行っていました。1 つの不良な WMI プロバイダーが WMI 全体に問題を起こしうるため、更新の信頼性が落ちていました。そこで CAU を **クラスターサービスに統合** し、ネイティブのクラスター API を呼ぶ形にして信頼性の問題に対処します。
- **VBScript の削除**に伴い、モダンなスクリプト手段として、従来の GenScript リソースに代わる **PowerShell GenScript リソース** をクラスタリングに用意します。

### 5.6 Windows Server 2028：管理

Eldon 氏は、次のセッションで Jeff 氏（姓の記載なし）が VMode（Windows Admin Center の virtualization mode）に 1 コマ全部を使って説明し、これは GA したばかりだと紹介しています。なお、Neil 氏は冒頭の 4 つの柱の紹介で、Windows Admin Center の virtualization mode のセッションが「満席のはず」なので早めに行くよう促し、Jason Roszak 氏のセッションで Intune for Windows servers が発表されたことにも触れています。これらは、サーバー管理が引き続き重要であり、クラウドとオンプレミスにまたがる現代的なツールが必要だという認識の表れだと説明されています。

Eldon 氏は、管理戦略を次のように整理しました。

- 長年ほとんど進化していない古い MMC 群については、**Windows Admin Center（WAC）が管理の答え**です。Hyper-V Manager には投資せず、Windows Admin Center に新しい **virtualization mode** を導入します。SCVMM の代替として、フリート管理、スケーラビリティ、状態の永続化も担う、と説明しています。
- **Entra**：現在の Windows Server には Entra ID との統合がなく、アイデンティティは Active Directory だけでした。2028 では **Azure Identity（Entra）をネイティブに OS へ統合**します。大きな変更だと述べています。
- **Intune for Windows Server**：Neil 氏が触れたとおり、大きな発表です（Neil 氏は冒頭で、Jason Roszak 氏のセッションで Intune for Windows servers が発表されたと触れています）。クライアント中心で少数のサーバーがある組織なら Intune、クラウドの視点で運用するなら Azure Arc が合うかもしれない、と述べ、選択肢を尊重する姿勢を強調しています。オンプレミス、クラウド、ハイブリッドのどれでも歓迎で、特にハイブリッドが伸びていると説明しています。

#### ネイティブツール

- **PowerShell 7** が標準搭載（inbox）になる。クライアントにも来る。
- **Sysmon** が標準搭載になり、トラブルシューティングを簡素化。
- **WinGet** が Server Core で利用可能に。

#### Dynamic desktop

Windows Server 2008 R2 の頃にあった「Server Core にデスクトップを追加したり外したりできる」機能が **戻ってきます**。Eldon 氏が想定するのは、深夜 2 時にサーバーが止まり、CLI で手探りになる場面です。デスクトップを追加して Windows Explorer やイベントビューアーを GUI で使って復旧し、終わったらデスクトップを再びアンインストールして本番に戻せば、バイナリのフットプリントを抑えられます。主にサーバーダウン時のシナリオだと位置づけています。

#### WOW64 の削除

Windows Server は 2008 R2 以降 64 ビット専用ですが、32 ビットアプリを動かす **WOW64** は長年同梱されてきました。2028 では、secure by default の一環として **WOW64 サブシステムを削除** します。ただし feature on demand として追加できるので、32 ビットの基幹業務アプリがあれば戻せます。これにより、特に 32 ビットのマルウェアに対して OS がより安全になるとのことです。

Windows Server のリリースは **2〜3 年ごとの予測可能なケイデンス**で、Insider ビルドを入れて、今から計画を始めてほしい、と促されました。

### 5.7 Windows Server 2025 向けの案内、AVD hybrid、2016 のサポート終了

最後に、時間がないとしてまとめて紹介された項目です。

- **Arc の hotpatching が無料に（Windows Server 2025）**：重要・重大なセキュリティ更新を、再起動なしで適用できます。再起動は毎月ではなく四半期に 1 回になります。2 か月はセキュリティ更新のみで、その後に完全なベースライン更新と再起動を行う、という流れです。
- **AVD hybrid on Windows Server**：RDS や VDI を Windows Server 上で使っている大きな導入基盤に「進む道がなかった」状況に対し、9 月 1 日に GA した AVD hybrid が選択肢になる、と案内されています。
- **Windows Server 2016 のサポート終了と ESU**：移行が遅れている場合、購入できる **Extended Security Updates（ESU）** で、さらに 3 年間、重要・重大なセキュリティ更新が受けられます。統合サポート契約があれば break-fix サポートも含まれ、規制対応が必要な場合（銀行の例が挙げられています）にも対応できるとの説明です。

> 注意：ESU があるからといって先延ばしを続けてよいわけではない、と Eldon 氏は釘を刺しています。

理由として、次の点が挙げられました。

- AI が脆弱性を驚異的な速度で見つけており、10 月更新では Windows 史上最多のセキュリティ更新が出ました。ただし、それらを **古い旧バージョンすべてにバックポートするわけではありません**。
- 規制対応の要件は Windows Server 2025 と 2028 に反映されます。ポスト量子コンピューティングも、一部は 2025 に降りますが、多くは 2028 で行われます。

結びの言葉は、「2016 や 2019 に居座って安心してはいけない」「過去 10〜20 年と同じ Windows Server のアップグレード計画は、変える必要がある」というものです。Eldon 氏は「状況は変わった。より積極的になり、セキュアであるために最新の状態を保ってほしい（stay current to stay secure）」と繰り返しました。Microsoft は更新、修正、ハードニングを出し続けているので、そのための道のりを一緒に進んでほしいとも呼びかけています。

最後の要点として挙げられたのは、ハイブリッドの話、Windows Server 2028 がプレビュー中であること、Windows Server Insiders を確認することの 3 点です。

## 7. 注意点・発表者の気付き

- **セキュリティベースラインの既定適用は、アプリ互換性のリスクを伴います。** 管理者は新しいベースラインを検証する必要があります。まず Server Core のみが対象で、フィードバックを求めています。
- **Gen2 VM が必須になります。** 2028 へのインプレースアップグレードには Gen2 VM が必要なので、新規デプロイは Gen2 にします。
- **Confidential VM の最初のバージョンには制約があります。** ステートレス VM のみで、アテステーションは Azure 経由のため、切断環境では使えません。
- **古いコンポーネントを削除します**：SMB1、レガシー BIOS、VBScript、WOW64（feature on demand で追加可能）。2025 には 10 年のライフサイクルの間は残ります。
- **ロールバックは約 2 週間** に限られます。
- **ESU は延命策であり、解決策ではありません。** 旧バージョンへのバックポートは行われません。
- Inference factory fabric は **限定プレビュー** で、Windows Server TAP 経由での提供です。発表されたのは構想とデモで、一般提供の時期などは語られていません。
- AMD Instinct MI350P と DGX Station for Windows Server の提供時期は、前者が 2027 年前半（Windows Server 2025 向けプレビュー）、後者が Windows Server 2028 GA 時です。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **推論を置く場所を選べる**：クラウド、token factory、クライアントを組み合わせ、規制、知的財産、コストの事情に合わせて配置できる。Foundry カタログ、Agent 365、MXC は 3 層で一貫して使える。
- **Token factory の抽象化**：従業員は個々のサーバーを意識せず、追加モデルとして使える。ピーク時はクラウドに逃がせる。
- **既定で安全な OS**：経験の浅い管理者でも、「次へ」を押すだけで安全な状態になる。
- **性能・信頼性の向上**：ネイティブ NVMe（IOPS 向上、レイテンシと CPU オーバーヘッド低減）、ネットワークドライバーのユーザーモード化、CAU の信頼性向上。
- **更新と運用の負担軽減**：Windows Update によるフィーチャーアップデート（1 回の再起動）、約 2 週間のロールバック、Arc の無料 hotpatch による再起動の月次から四半期への削減。
- **管理の選択肢**：Windows Admin Center の virtualization mode、Entra のネイティブ統合、Intune か Arc かを選べること、PowerShell 7・Sysmon・WinGet の標準搭載、必要時だけデスクトップを追加できる dynamic desktop。

## 9. まとめ

Windows Server 2028 は、コンピュート、ストレージ、ネットワーク、データベースに推論（token factory）を加えた 5 本柱の最初のリリースとして、パブリックプレビューが始まりました。前半では、クラウド・token factory・クライアントの 3 層で「適切な場所、能力、価格」を探すハイブリッドの考え方、DGX Station for Windows Server と AMD Instinct MI350P の追加、そして token factory をファブリックとして束ねる限定プレビューが紹介されました。後半では、既定でセキュアな Server Core、Gen2 VM の必須化、SMB1・VBScript・WOW64 などの削除、ネイティブ NVMe の既定有効化、ロールバック対応のアップグレード、Entra と Intune の統合、dynamic desktop の復活が説明されました。

今すぐできる行動は、Windows Server TAP（aka.ms/WSTAP）または Insider でプレビューを試してフィードバックを送ること、新規 VM を Gen2 で作ること、そして Windows Server 2016 や 2019 に留まっている場合は ESU に頼らず移行計画を見直すことです。
