# THR933 Power agentic connectivity across SAP and Microsoft with Work IQ

## 1. はじめに

このセッションは、Microsoft Copilot と SAP の Joule（発表では "Jewel" などと書き起こされています）を、どのような方式でつなぐのかを整理する約 20 分の登壇です。Microsoft で SAP との global co-innovation（発表では "co-novation" と聞こえます）パートナーシップを率いる Peter Berman 氏が、連携の方式を「UI 経由」「API」「MCP」「A2A」の 4 段階で説明します。

結論として語られたのは、次の 2 点です。

- Microsoft 側から SAP を使うときは、まず autopilot（ブラウザ操作ができるエージェント）で試し、価値が確認できたら API や MCP の連携に進む。
- SAP 側から Microsoft のデータを使うときは、Graph API を個別に呼ぶのではなく、**Work IQ** に任せる。SAP の Joule と Copilot の連携も、Work IQ を使う形に作り直されている。

発表の途中で、autopilot を使って「Copilot と Joule の連携を 3 分で一から作る」という趣旨のデモ（録画）が上映されます。

## 5. 発表内容の詳細

### 5.1 Microsoft と SAP の「1 つの統合プラットフォーム」

Peter 氏は、スタックを層ごとに説明しています。

| 層 | 説明 |
| --- | --- |
| インフラ（Azure） | SAP 向けに設計されたチップと VM があります。ネットワークで、SAP システムを Fabric、Power BI、Teams と結び付けます。 |
| プラットフォーム | SAP の Business Technology Platform（BTP）は Azure 上で動きます。Microsoft 側は Azure のフルスタックを提供し、セキュリティとして Sentinel と Entra ID を挙げています。 |
| ガバナンス | 前日に、SAP のエージェントも Agent 365 から統治できるようにすると発表されました（SAP のエージェントを今後構築する人向け）。 |
| データ | 前年に、SAP の Business Data Cloud と Fabric の接続が発表されました。Azure Databricks とはすでに接続済みです。 |

Entra ID は、エージェントどうしの連携（agentic interconnectivity）で特に重要だとして、デモの中で理由を示すと述べています。

エージェントの層では、2 年前に Copilot と Joule の連携が発表されました。これは単純な連携で、テキストを転送するだけのものでした。それを、より新しいエージェント型の接続アーキテクチャに作り直している、という説明です。

### 5.2 エージェントが増えた世界での課題

Peter 氏は、聴衆の多くが SAP も Microsoft も使っている前提で、現在のエージェントの状況を挙げます。

- Microsoft 自身のエージェント（researcher、analyst など）
- 自分たちで作る Copilot のエージェント
- パートナーのエージェント（Adobe、SAP、Workday、ServiceNow など。Salesforce とのパートナーシップも発表済み）
- IT ヘルプデスクや市場調査など、各社が個別に作ったエージェント

こうした小さなチャットボットやツールが点在する中で、「どうつなぐか」が問いです。Peter 氏は、聴衆に持ち帰ってほしいものとして、autopilot の力、MCP・A2A・API（および UI ベースの連携）という連携パターン、そして Copilot と Joule を例にした具体的な動き方の 3 つを挙げました。

### 5.3 autopilot とは

デモに使われたのは、基調講演などで発表された autopilot です。Peter 氏によると、現在は Microsoft Frontier program で提供されているバージョンで、画面では今も "Scout" と呼ばれています。将来は Microsoft 365 Copilot の中のタブの 1 つになる予定で、機能は同じだと説明しています。ブラウザのウィンドウを開き、そこで操作を行えるのが特徴です。

### 5.4 連携方式の 4 段階

Peter 氏は、デモのあとで連携方式を整理しています。

| 段階 | 説明 |
| --- | --- |
| UI 連携（プロンプト転送） | UI を介して 1 つのテキスト（質問）を渡し、1 つのテキストの回答を受け取る。2 年前の Copilot と Joule の連携と技術的にはほぼ同じ。すでに公開されており、誰でも使え、一部の用途には有用。「計画もコンテキストも自分が持ったまま、1 つのタスクだけを頼む」イメージ。 |
| API | ブラウザを開かず、UI の下側の API で同じことを行う。UI より優れているが、ID、セキュリティ、ファイアウォールを検討する必要があり、まだ技術的で手間がかかる。 |
| MCP | 1 つのエージェントが「ツール箱を開いて、ここに道具があり、使い方はこうです」と示す方式。API の上に標準化された説明が付くため、他のエージェントがどの API を選ぶかを理解でき、特定のタスク用の 1 つのツールにとどまらず、さまざまなツールを使える。 |
| A2A | 2 つのエージェントが共通の成果に向けて協力する別のフレームワーク。 |

Peter 氏は、API 連携が向く場面として、Copilot で作ったエージェントがプロセスの最後に 1 回だけ投稿を行う場合や、サービス担当者が使うアプリから 1 件のサービスリクエストを投稿する場合を挙げています。また、API を「道具（ドリル）を渡されても、どのビットを使い、どれくらいの速さで回すかは分からない」状態にたとえています。これに対し MCP は、道具の使い方まで説明を付けて渡す方式、という位置づけです。

SAP のユースケースに当てはめると、次のように使い分けられます。

- 最下層（UI）：autopilot で、SuccessFactors の研修を受ける、休暇を取る、といった個人の操作を試せる。非常に遅く手間がかかるが、個人が AI のユースケースを試す方法として使える。
- 全従業員（あるいはパートナーの顧客企業の従業員）が同じツール（休暇の申請、時間の登録など）を使いたい場合は、エージェントの一部として API ベースのツールを持つのが適している。
- 強力なツールセットが必要なら MCP。Peter 氏は MCP を、現時点で主導的なフレームワークと見ていると述べています。

### 5.5 顧客の現状

Peter 氏が Microsoft から SAP へ向かう方向で顧客を見ると、多くは従来型の API ベースの連携を使っています。Copilot のスキルやプラグインを作り、ツールとして使うか、ワークフローの一部として使うかのいずれかで、チャット画面のツールとして使うことが多いそうです。

MCP については、SAP と関わる方法が複数あると述べています。

- API Management 側で行う
- BTP 上で行う
- パートナーコミュニティによる ABAP での方法もある

こうしたツールは増えつつあるものの、多くの顧客は、SAP が既製のプラグインとして Copilot に提供することを望むはずだ、と説明します。これが前日に発表された内容でもあります。A2A も初期の採用が見られ、一部の顧客は自前で作っていますが、agent gateway が使えるようになり、SAP が用意する仕組みへ切り替えたい顧客も出ているそうです。

API では利用者が使えるツールを 1 つずつ制御したくなります。一方で、ハードウェアとドライバーの世界で言う「プラグアンドプレイ」のように、SAP や Microsoft、あるいは Salesforce（"headless" と呼んでいるとのこと）が MCP サーバーを提供してくれれば、ユーザーとしての自分のコンテキストを渡すだけで、そのシステムで人としてできることがすべて使える、と述べています。

### 5.6 SAP から Microsoft へ：Work IQ

逆の方向、つまり SAP などの外部エージェントから Microsoft 365 を使う方向では、Work IQ が使われます。Peter 氏は Work IQ を、「Microsoft 365 の MCP サーバーのようなもの」と呼んでいますが、技術的には正確ではなく、A2A としても REST API としても使えると補足しています。

外部のエージェント（ServiceNow や SAP など）が、ファイルを取得する、テキストをアップロードする、メールを送る、Teams のメッセージを送る、といったことをしたい場合に、Microsoft の MCP サーバーを自分で作る必要はなく、Microsoft に任せたい、という位置づけです。

前日の発表では、SAP がこの Copilot と Joule の連携を作り直しており、Joule が Copilot との連携に **Work IQ** を使う、と述べられています。期待される効果は次のとおりです。

- エージェントにとってより豊かな（agent-ready な）体験
- トークンが少なくて済む
- レイテンシーが低い
- ファイルは Microsoft のクラウドにとどまり、既存のセキュリティ、ガバナンス、Purview のラベルが維持される

### 5.7 Graph API と Work IQ の違い

これまで、ファイルの取得やメール送信には Graph API が使われてきました。Peter 氏は、決まった処理（静的なもの）ならこれで問題ないとしています。ただし、Microsoft 側で見ると、**Graph API の利用は過去 1 年で 10 倍になった**そうです。Graph は無料で、今後も無料で、廃止されることはない、と明言しています。

一方で、外部のエージェント（Joule など）が「このメールを探して」「この SharePoint を探して」「このチケットに関連する顧客の問い合わせは何か」と尋ねる場面を考えます。Graph API では、メールの送信や書き込みなど個別の、とても細かい（raw な）エンドポイントを順に呼び、データをすべて集めて持ち帰り、大量の LLM トークンを使って推論することになります。デモで見たように、文脈が足りなければ再度やり直し、往復が増え、トークンのコストも高くなります。

これに対して Work IQ は、メールなどを含むあなた自身の IQ として、すべてがあなたのコンテキストに基づいており、質問への答えがはるかに速く簡単に得られると説明されています。外部のエージェントに対して、何ができるかの完全な説明を渡し、ユーザーとコンテキストを保ち、より効率的で速く、安全になる、という説明です。これが MCP の将来像だと述べています。

また、これまで数百社の顧客が、プロンプト転送の技術による Joule と Copilot の連携を使ってきたとのことで、今回の変更は SAP の顧客にとって大きな転換になる、と述べています。

### 5.8 次のステップ

Peter 氏は、次のように整理しています。

- **Microsoft 側から始める場合**：autopilot などで「AI のユースケースとして妥当か」を試す。ブラウザベースなら autopilot が推論して動く。少し遅く、テキストを読んで中身を理解する必要があるが、そこから始める。自分で連携を作り、価値を示し、簡単なものから始める。数千人のユーザーが必要とする、明確で詳細なユースケースだと分かったら、API ベースの連携や MCP を検討する。SAP からどう統治するかによって選択肢は複数あり、今後より簡単になるだろう、と述べています。
- **SAP 側から始める場合**：すでに独自の Joule エージェントや、ServiceNow、「cloud」（Claude の可能性がありますが、音声認識の都合で確定できません）などで作ったエージェントがあるなら、Work IQ に重い処理を任せることを考える。エージェント向けのコンテキストはトークンが少なく、はるかに速いとして、その程度を **80% 速く、80% 少ないトークン**だと説明しています（「I think」と留保を付けています。根拠は付録のスライドにあり、セッション後にダウンロードできるとのことです）。SAP 自身もこの連携を作り直しています。
- **ガバナンス**：エージェントを作ったあとは Agent 365 で統治し続ける。SAP と Microsoft は、この領域でも双方向で協力している。

## 6. デモ・手順

このセッションにはデモがあります。ただし**ライブではなく、事前に録画した動画**で、Peter 氏は Teams で録画し、2.5 倍速にしたと説明しています。冒頭では「3 分で一から作る」と言い（これは「ちょっとしたトリック」だとも述べています）、後半では「5 分かかった」とも述べており、所要時間の数字は音声からは確定できません。画面の詳細も音声からは分かりません。語られた順に整理します。

1. autopilot に、api.sap.com（SAP の統合に関する Web サイトで、統合を検索できる Joule のチャットボットが載っている）へ行くよう指示する。
2. その上で、「SAP と Microsoft をどう統合するか」という質問をするよう指示する。
3. 画面の右側に autopilot の推論、左側に autopilot が開いたウィンドウが表示される。
4. 最初の問題として、autopilot はログインできない。「自分としてログインして」と頼んでも、autopilot にはユーザーの ID と認可がないため、Peter 氏が自分でパスワードを入力し、done を押す。
5. SAP の Web サイトに戻り、ポップアップが出る。autopilot がポップアップを読み、閉じる。
6. autopilot が Joule に「Microsoft Copilot を SAP とどう最もよく統合できるか」と質問する。Peter 氏は、この単純な連携の欠点がここで出ると説明している。遅いこと、そして質問文のテキストしか渡らないこと。
7. 返ってきた答えは Microsoft Sentinel と SAP の何か（"SAP Calm" と聞こえます）についてで、Peter 氏が Copilot についての発表資料を作っているという文脈が伝わっていないため、的外れになっている。autopilot 自身も、有用だが的確でなく、狭く、やや的外れだと評価している。
8. Peter 氏は「言いたかったことは Copilot と Joule の連携だ」と、具体的に尋ね直すよう指示する。やり取りの往復が発生する。
9. 長い答えが返ってくる。A2A ゲートウェイや MCP ゲートウェイについて触れており、Peter 氏が全画面にして読む。選択肢は 3 つで、MCP gateway（integration suite 経由のもの、Joule Studio で SAP が提供するもの）と、SAP の agent gateway 経由の A2A が挙がった。
10. 結果として、Peter 氏は「5 分で Copilot と Joule を統合できた」と述べている。Peter 氏は、これは企業システムのツールではなく Web 上の Joule を使ったもので、概念を理解してもらうためのものだと述べている。

Peter 氏は、autopilot で Web ベースのアプリ（SuccessFactors、Ariba など）にアクセスできるとして、Ignite への移動経路を 3 つ調べる、日付やホテル料金を調べる、SuccessFactors の必須コンプライアンス研修を行う、といった例を挙げています。研修は試してみて実行できたものの、自分で受けている、と述べています。

## 7. 注意点・発表者の気付き

- UI 連携（プロンプト転送）は、質問文だけが渡るため、会話のコンテキストが失われ、的外れな答えが返りやすい。往復を重ねて直す必要がある。
- autopilot には利用者の ID と認可がないため、SAP の Web サイトへのログインは本人が行う必要があった。
- UI 連携は遅く、手間がかかる。Peter 氏は、プリンシパル伝播（principal propagation）、ID、認可といった重い作業に入る前に、ユースケースを試す用途に向く、と位置づけている。
- API 連携では、ID、セキュリティ、ファイアウォールを検討する必要がある。
- Graph API を外部エージェントから直接使うと、往復とトークンのコストが増える。ただし Graph API 自体は無料で、廃止されない。
- デモは企業システムではなく、Web サイト上の Joule を使ったものである。

## 8. 利用者にとっての利点

発表で語られたものは次のとおりです。

- Joule と Copilot の連携が Work IQ を使う形に作り直されることで、エージェント向けに整ったコンテキストが得られ、トークンが少なく、速くなる（Peter 氏は「80% 速く、80% 少ないトークン」と述べ、「I think」と留保しています）。ファイルは Microsoft のクラウドにとどまり、既存のセキュリティ、ガバナンス、Purview のラベルが保たれる。
- SAP のエージェントも Agent 365 から統治できる。
- SAP と Microsoft の統合された基盤（Azure 上の SAP 向け VM、Fabric、Power BI、Teams、Business Data Cloud と Fabric の接続など）が使える。
- 試すだけなら autopilot で簡単に始め、必要が明確になった段階で API、MCP へ進める。

## 9. まとめ

Peter Berman 氏は、Microsoft と SAP の連携方式を、UI によるプロンプト転送、API、MCP、A2A の順に整理しました。個人の試行は autopilot、全員で使う限定的なツールは API、強力なツールセットは MCP、というのが使い分けの目安です。

SAP から Microsoft への方向では、Graph API を個別に呼ぶのではなく、Work IQ を使うことで、トークンが 80% 少なく、80% 速くなる（Peter 氏は「I think」と留保しています）うえ、データは Microsoft のクラウドにとどまります。Joule と Copilot の連携も Work IQ を使う形に作り直されており、SAP のエージェントは Agent 365 で統治できるようになる、という発表でした。
