# BRK436 Scaling Azure infrastructure: From intelligence into enterprise impact

## 1. はじめに

このセッションは、Azure のハードウェア基盤を設計している Microsoft のエンジニアリング責任者が、AI 時代の Azure インフラを「シリコン → メモリ → ネットワーク → セキュリティ → データセンター（電力・冷却）」の順に、層ごとに解説したものです。主な聴衆として、エンタープライズアーキテクト、技術リーダー、意思決定者、パートナー、開発者が想定されています。

結論は、**計算資源やメモリ、容量をただ足すだけではなく、モデルからデータセンターまでを 1 つの統合システムとして共同設計（co-design）することで、性能・電力効率・コストを同時に改善する**という考え方です。発表では、自社設計の AI 推論用アクセラレータ Maya、Arm ベースの CPU Cobalt 200、データ処理用の Azure Boost DPU、CXL を使ったメモリ再設計、AI 向けの 3 種類のネットワーク技術、ハードウェア起点のセキュリティ、800V DC 給電や液冷（マイクロ流体冷却）などが、数値付きで紹介されました。

### 5.2 発想の転換：Norman Berlow の逸話

発表者は、Azure President の Rani Borker 氏が以前のキーノートで紹介した話として、農学者 Norman Berlow の逸話を引いています（人名はトランスクリプト上の綴りのままで、音声認識の都合で表記が確定できません）。

何世紀もの間、作物を増やすには土地・水・肥料といったリソースを足すのが基本でした。ところが 1950 年頃から限界に突き当たり、肥料を増やしても小麦は背ばかり高くなり、茎が弱くて倒れてしまうようになりました。そこで彼は「植物そのものを設計し直したらどうか」と問い、茎が太く丈の短い小麦を作って収量を大幅に改善し、約 10 億人を飢えから救ったとされ「緑の革命の父」と呼ばれています。

発表者はこれを AI インフラに重ねます。答えは単にリソースを足すことではなく、問題への取り組み方そのもののパラダイムシフトにあるという考えです。

### 5.3 シリコン：3 つのアーキテクチャ

Azure には現在 3 種類のシリコンアーキテクチャがあります。思想は「適切なコンピュート要件に、適切なシリコンとアーキテクチャを当てる」というものです。

| シリコン | 役割（発表での説明） |
| --- | --- |
| CPU（Cobalt） | 汎用およびエージェント型コンピュートで最良の価格性能 |
| AI アクセラレータ（Maya） | ベクトル・行列演算に最適化。推論性能、推論あたりのコスト、推論あたりの電力で最良を目指す |
| DPU（Azure Boost DPU） | ネットワークとストレージ上で大量のデータが動くときのインライン処理に最適化 |

#### Maya（AI 推論用アクセラレータ）

Maya は推論を軸にした設計思想（書き起こしでは「inference worst」と聞こえ、正確な言い回しは確定できません）で、推論に使う 1 ワット・1 ドルを最大限に生かすことを目標に作られました。プログラム全体を導いた洞察は 2 つです。

1. 推論はコンピュートの問題ではなく、データ移動の問題である。
2. 推論効率はシリコン単体ではなく、システム全体の特性である。

この考えに基づき、モデル、ハーネス、オーケストレーション層からデータセンターまでを念頭に、ゼロから **software-defined data flow architecture** という新しいアーキテクチャを作りました。コンピュートとデータを非常に高い局所性で配置できるため、データの移動に要するエネルギーを最小化できるという説明です。この思想は、SoC におけるコンピュートとメモリ帯域のバランス、ゼロから作った scale-up ネットワーク（データフローアーキテクチャの延長）、推論向けのラックスケールアーキテクチャとデータセンターへの展開にも引き継がれています。

現状と数値は次のとおりです。

- **Maya 200** はすでにフリートで本番稼働しており、Microsoft の製品・サービスの推論を実際に処理しています。
- **Maya 300** は最近発表されたもので、200 に対してラックレベルで約 7 倍の推論スループットとされています。
- GPU ベースのシステムと比べ、2027 年（calendar 27）には 1 MW あたりのトークン数が 40% 多くなる見込みです。
- Maya プラットフォームを、来年の Maya 300 から複数ギガワット規模にスケールさせることを約束しています。

ラックスケールでは、シリコンとシステムの電力効率を最適化し、**1 ラックに 96 個のアクセラレータを、わずか 167 キロワットで**搭載しました。前世代と比べて HBM 帯域は 5 倍、ワットあたりの HBM 帯域はほぼ 2 倍、HBM 容量は 2.7 倍になっています。

展開の観点では、1 GW の導入枠があれば約 575,000 個の Maya アクセラレータを配置できます。他社の GPU と比べると、同じ電力枠で約 1.8 倍の密度です。発表者は「チップ対チップの性能で競争しようとしているわけではない」と断ったうえで、デプロイ全体で得られる集計トークンスループットでは 1 MW あたり 40% 多くのトークンが得られ、1 トークンあたりのコストも低い、と説明しています。

#### Cobalt（Arm ベース CPU）

Cobalt については、覚えてほしい点として次の 3 つが挙げられました。

1. 最高性能のコア IP を確保したこと。パートナーの Arm と密に連携し、最先端プロセスノード上の Neoverse V3 アーキテクチャを採用しました。
2. コア IP は出発点にすぎず、TDP、メモリサブシステム、プラットフォーム設計、セキュリティ、可用性までを SoC とプラットフォームに作り込んだこと。
3. Cobalt に「クラウドファースト」な機能を入れたこと。

Azure 向けに最良の価格性能のクラウドプラットフォームを作ることが目標で、**Cobalt 200 は前日の発表で GA になりました**。Cobalt 100 に対して約 50% 優れているとのことです。

顧客にとっての意味として、次の点が示されました。

- SPECint のような業界標準ベンチマークで「最大 60%」の向上（比較の基準は発話からは明確に聞き取れません）。
- SoC とプラットフォームを Microsoft 製品と顧客向けに調整した結果として、SQL、Teams、Dataverse などで大きな向上が得られています（具体的な数値は音声からは読み取れません）。
- エージェント型コンピュートで追跡し始めたベンチマーク（サンドボックスの作成と復元にかかる時間、ツール実行にかかる時間、一定の電力枠に詰め込めるサンドボックス数）でも非常に良い結果が出ています。発表者は、この日の午後に Cobalt 200 についての別セッション（エンジニアが OpenAI も招いて話す）があると案内しました。

**クラウドファースト機能その 1：VM 単位の電力モニタリングとテレメトリ。** ハイパースケーラーとしては初めて、VM ごとの電力モニタリングとテレメトリをシリコンに組み込みました。クラウドでは多数の顧客 VM を動かしますが、VM ごとに必要な電力と性能は異なります。このテレメトリとシリコン機能により、重要な VM の性能に影響を与えずに、システムの電力を**約 35% 削減**できます。これにより、同じ電力枠にもっと多くのサーバーを置く（oversubscribe する）ことができ、性能を手放さずに同じリソースへより多く詰め込めると説明されています。

**クラウドファースト機能その 2：オンダイアクセラレータ。** 特定のワークロードを高速化するダイ上のアクセラレータです。例として SQL が挙げられました。トランザクションを処理しながら定期的にバックアップを取る場合、アクセラレータが無いと貴重な CPU サイクルをバックアップに使い、トランザクション処理が遅くなります。ソフトウェアベースの圧縮アルゴリズムと、オンダイアクセラレータ（または Intel の Quick Assist 技術）を使う構成を比べると、**バックアップが最大 2.5 倍高速**になり、**トランザクション処理への影響は 50% 減少**します（この部分は音声認識の乱れが大きく、Cobalt 側のアクセラレータの名称は確定できません）。

発表者は Intel との協業にも触れています。Xeon 上の Intel Quick Assist 技術について、ファームウェアからドライバー、SQL までフルスタックで取り組み、**Intel Quick Assist 技術の最初の仮想化されたクラウド実装**になったと述べています。

#### Azure Boost DPU

AI やデータ中心のワークロードでは、コンピュートとストレージの間でネットワーク上を大量のデータが動きます。そのデータをインラインで、信頼性高く、低電力かつ高セキュリティに処理する必要があります。

発表者は、従来型のハイパースケーラーのストレージサーバー（2 ソケットの Xeon、PCI スイッチ、アクセラレータカードで構成され、合計で約 300 W）を例に挙げ、Azure Boost DPU ではこれらの機能を電力効率の高い 1 つの ASIC にまとめたと説明しています。専用のプログラミング OS（data flow operating system）と自社のストレージスタックを組み合わせることで、**性能は 4 倍、電力は 3 分の 1** になりました。これは、同じ電力効率でより多くのストレージ容量を提供できることを意味します。

### 5.4 メモリ：CXL で再設計する

AI によりメモリ需要が急増しています。発表者は、ここ数年のビット成長が驚異的であること、供給への強い圧力のためここ 1〜2 年で価格が 4 倍に上がったことを示しました。そのため、メモリはもはやコモディティではなく、資本支出や Azure に置ける容量そのものを左右する要素になっており、フリートに入れる 1 GB ごとを最大限に使い切れるよう、根本から再設計する必要があるとしています。

従来のアーキテクチャでは、CPU に 12 または 16 チャネルのメモリを直接接続します。これに対し CXL（発話では "compute expressing technology" と聞こえます）は、次の 2 つの選択肢を開きます。

**CXL expansion。** 同じサーバーに第 2 階層のメモリを追加できます。従来より多くのメモリを載せられるうえ、第 2 階層には別の種類のメモリを使えるため、DDR5 が逼迫していれば DDR4 を追加することもできます。

**CXL pooling。** VM ごとに必要なメモリ量は違います。CPU に一定量を直接接続する従来の構成では、貴重なメモリを使われないまま抱える（stranding）状況が起きがちです。そこでメモリの一部をプール型のアプライアンスに切り出し、VM の要求に応じて動的に割り当てることで、フリート全体のメモリ利用率を高められます。発表者はこちらについて「有望な結果が出ている」と述べるにとどまり、具体的な数値は示しませんでした。

**事例 1：M シリーズ高メモリ VM。** CXL expansion を使った M シリーズの高メモリ VM のプレビューを発表済みで、ブログも公開されています。メモリ集約型ワークロードで合計 8 TB のメモリを必要とする顧客に対し、従来は CPU あたりに直接接続できる量の制約から 4 ソケットのプラットフォームが必要でした。新しいアーキテクチャでは、同じ 8 TB を**2 ソケットのプラットフォーム**で、より柔軟かつシンプルに提供できます。対象ワークロードは SAP HANA や SQL などで、旧構成から移行すると **vCPU あたりの性能が 26% 向上し、パッケージ電力は 47% 減少**します。

**事例 2：DDR5 と DDR4 の混在サーバー。** CXL コントローラーの背後なら、同じ技術のメモリを付ける必要はなく、より低コストなメモリを使えます。そこで DDR5 と DDR4 を混載したサーバーを作りました。この DDR4 には、フリートから退役した古いサーバーのメモリを再利用でき、まだ十分に長い寿命が残っています。多くのワークロードの要件を満たしつつコスト効率が上がり、DDR5 が逼迫してサーバーを出荷できない場合でも、導入できる容量を増やせます。

この取り組みは Intel と進めており（Intel の flat 2LM 技術）、Intel の Xeon CPU 上で、CXL expansion メモリを使うクラウド VM を仮想化して提供した最初のクラウドプロバイダーだと述べています。

### 5.5 ネットワーク：AI のための 3 つの技術

AI ではネットワークが性能の背骨になります。新しい AI データセンターのネットワークケーブルの総延長は、地球を 4 周できる長さだと紹介されました。従来のクラウドと AI では要件が大きく異なるため、役割の違う 3 つの新しいネットワーク技術が生まれたとして、scale-up、scale-out、scale-across の名前が挙げられました。ただし scale-across については、トランスクリプト上で個別の説明はありません。

#### Scale-up ネットワーク

アクセラレータ同士を、高帯域・低遅延のファブリックで密に結合するネットワークです。取り組みは 3 つあります。

1. **マルチラック化。** 現在の scale-up ネットワークは 1 ラックに収まる範囲に限られますが、複数ラックにまたがる scale-up ネットワークへ進めます。ワークロードを複数ラックに広げられるので、より大きなモデルを扱え、小さなドメインで起きるリソースの stranding も避けられ、アクセラレータの利用率が上がります。
2. **銅から先進的な光接続へ。** 銅は到達距離と帯域に限界があります。光にすることで、より大きなラック群を、単一階層・1 ホップのネットワークで接続できます。
3. **Ethernet の拡張。** Ethernet は scale-up 向けに作られたものではありませんが、拡張できるのが強みです。scale-up に必要な帯域、遅延、信頼性を高める機能を加え、業界のパートナーとオープンかつ透明な形で進めています。

業界との協働の例が 2 つ紹介されました。

- **OCI**（発話では "optical computer interface"）：scale-up ネットワーク向けの光インターフェース標準を、オープンかつ協調的に作る世界初の仕様だとされています。
- **OCP の Ethernet for scale-up network ワーキンググループ**：パートナーが集まり、Ethernet の上に載せる機能を決めています。これにより、汎用のスイッチやケーブルを使えてコストを低く保ちつつ、scale-up に必要な機能を得られます。

Microsoft の目標は、scale-up ネットワークのための、相互運用可能でマルチベンダーの健全なエコシステムを推進することです。

#### Scale-out ネットワーク

数百 GPU にまたがる大規模ジョブでは、ネットワーク部品が故障することを前提にする必要があります。「部品は壊れるが、ジョブは失敗させたくない」ので、故障があってもネットワークが動き続けることが求められます。

そこでパートナーと協力して **MRC（multipath reliable connections）** を導入しました。packet spraying（発話では "packet string" と聞こえます）、順不同配信（out of order delivery）、マルチパスといった技術を取り入れ、学習ワークロード向けに、高い耐障害性と性能を両立するネットワークを実現するものです。MRC はすでに **Fairwater データセンターで製品化**されています。

### 5.6 セキュリティ：ハードウェアを起点にする

発表者は、AI 時代にプラットフォームを守るための指針を 3 つ挙げました。

1. セキュリティはハードウェアに根ざし、裏付けられていること（ソフトウェアだけではない）。
2. 強い分離（isolation）を提供すること。
3. 検証可能で、オープンかつ透明で、高い完全性で監査できること。

顧客は最も機密性の高いデータを Azure に持ち込むため、あらゆる攻撃面を押さえる必要があるという前提で、次の技術が紹介されました。

| 技術 | 発表での説明 |
| --- | --- |
| Confidential computing | 信頼された実行環境（TEE）を構築します。AMD、Intel、Arm と密に連携し、データが転送中・使用中・保存中のいずれでも保護され、信頼境界の外に出ないようにします。クラウド事業者もデータにアクセスできないため、ソブリンクラウドに不可欠と説明されています。 |
| Caliptra | オープンソースの root of trust。CPU などのコンポーネント上のファームウェアをすべて認証し、ファームウェアの完全性を保ち、悪意あるコードが無いことを確かめます。 |
| Azure Boost | コントロールプレーンとデータプレーンの分離のためのセキュリティ技術を内蔵。管理作業が顧客のデータプレーンの作業を妨げたりセキュリティ問題を起こしたりしないよう、完全に分離します。 |

さらに、すべてのサーバーに入っている 2 つのハードウェア革新が詳しく紹介されました。

**Datacenter Secure Control Module（DCSCM）。** すべてのサーバーに搭載され、OS よりも下の層でハードウェアを保護します。ファームウェアや管理コントローラーに侵入されると壊滅的な事態になりますが、DCSCM は secure BMC を備え、OS の下で動作します。システムが起動する前、ソフトウェアが保護できるようになる前から、ハードウェアが保護します。プラットフォームの root of trust を持ち、帯域外（out of band）でアクセスできます。

**Azure Integrated HSM。** 最近導入されたもので、機密性の高い鍵（金融記録、ビジネストランザクションなど）を持つ顧客向けです。従来は集中型の HSM（hardware security module）を使いますが、HSM はネットワーク上にあるため、ネットワーク越しのアクセスが脆弱性、遅延、性能ボトルネックを生みます。そこで専用のシリコンを作りました。非常に高いセキュリティを持ち、FIPS 140 レベル 3、耐タンパー性を備えた HSM を、Azure のすべてのサーバーに小さな専用ハードウェアとして実装します。**鍵は信頼境界の外に出ません。** 鍵管理や暗号処理が必要なときも、ネットワーク越しの集中型 HSM を使わず、ローカルで高速かつ高い安全性で実行できます。

HSM はこれまで閉じたプロプライエタリな製品で、あるメーカーから別のメーカーへ鍵を移すのが難しい状況がありました。発表者は「皆が鍵の持ち込みと保護の障壁を下げれば、全員が恩恵を受ける」という考えから、ファームウェア、ソフトウェア、プロトコルをオープンソース化し、時間をかけてチップの RTL もオープンにしたい、と述べています（RTL は「できれば」という言い方です）。

### 5.7 データセンター：持続可能性、電力、冷却

データセンターは地域社会の中にあるため、設計・建設・運用を極めて持続可能な形で行う必要があります。これは 1 つの施策では実現できず、低炭素の建材、水の管理（water stewardship）、クリーンエネルギーの再利用技術、廃熱の再利用やハードウェアの再利用による廃棄物の抑制など、複数の角度から取り組んでいると説明されました。その中で発表者が特に思い入れがあるのが、電力と冷却です。

#### 電力：グリッドからチップまでの再設計

従来のアーキテクチャでは、高電圧を受け取り、何段階もの変圧器で段階的に電圧を下げてラックに届けていました。これに対し、2 つの革新を順に取り入れています。

1. **Mount Diablo（disaggregated power rack アーキテクチャ）：** 800V DC を直接ラックまで届けられます。余計な変換のロスをなくし、はるかに高密度なラックをデータセンターに配置できます。業界のパートナーと標準的な方法を作る取り組みでもあります。
2. **ソリッドステートトランス（solid-state transformer）：** 電力配送の次の仕様として投資しています。バンドギャップが大きくスイッチング周波数の高い先進的なパワー半導体を使い、レガシーなアーキテクチャよりずっと効率よく電力変換できます。800V DC をそのまま配電し、Mount Diablo を通して降圧できます。**60% 小型**でスペースを節約でき、スマートグリッドや電力事業者にとっても好都合とされています。

#### 冷却：液冷を前提にした専用設計

AI により液冷インフラへ移行しており、Microsoft は電力密度・信頼性・持続可能性に合わせた、専用設計の液冷施設を構築する考えです。階層ごとの取り組みは次のとおりです。

| 階層 | 取り組み |
| --- | --- |
| チップ | 先進的なコールドプレートや現在使っている技術では熱の余裕が尽きるため、将来の技術に投資している。冷却液の分配方法も検討している。 |
| ラック | 保守性、漏水検知、マニホールド、クイックディスコネクトなどを検討している。ラックを堅牢で効率的にする。 |
| 施設 | 冷却液の温度、化学組成、分配方法、そして水を使う蒸発冷却に対して最も効率的な冷却技術で熱交換を行う方法を検討している。 |

#### マイクロ流体冷却（microfluidics）

次世代シリコンでは発熱が大きくなり、それを取り除く必要があります。冷却液を熱源に近づけるほど効率が上がるため、マイクロ流体冷却のプログラムを進めているとのことです。ここで発表者は短いビデオクリップを再生しました。クリップの内容（ナレーション）は次のとおりです。

- マイクロ流体冷却は、自然に着想を得て AI でカスタマイズされた、チップ冷却のブレークスルーである。
- 冷却液が最も必要な場所に届く。精密にエッチングされた微細な流路を、各 CPU・GPU に合わせて作り、最も高温の領域へ冷却を向ける。
- これにより、より高速で、より賢く、より効率的に動く新しいチップアーキテクチャが可能になる。

## 7. 注意点・発表者の気付き

発表の中で、前提・制約として語られた点を整理します。

- **インフラの意思決定は何年も先を見て行われる。** 発表者は最後に、これらのインフラ上の決定は、ワークロードが実際にフリートで動く何年も前に下されると述べています。
- **単一の特効薬は無い。** Copilot のスループット 4 倍は、全層にわたる地道な作業とクロス最適化の成果であり、1 つの層の変更によるものではないと強調されました。
- **新技術はフリート全体に信頼性高く展開してこそ意味がある。** 新技術の発明そのものではなく、それを大規模フリートに確実に載せることが課題として挙げられています。
- **Maya は「チップ対チップの性能」を競うものではない。** 評価軸はデプロイ全体のトークンスループットと、1 MW あたり・1 トークンあたりのコストです。
- **メモリはコモディティではなくなった。** 価格が 4 倍になり、容量や資本支出を左右する要因になっています。
- **CXL pooling はまだ「有望な結果」の段階。** 発表では具体的な効果の数値は示されませんでした。
- **Mount Diablo や OCI、OCP の取り組みは、業界との協調（標準化）を前提にしている。**
- **Integrated HSM のオープンソース化範囲。** ファームウェア・ソフトウェア・プロトコルをオープン化し、RTL は「時間をかけて、できれば」という位置づけです。

## 9. まとめ

AI インフラの課題は、トークン需要の急増、エネルギーと資本の制約、レガシー構成の限界、脅威環境の変化、地域社会との関係という 5 つに集約されます。発表者の答えは、リソースを足すのではなく、Berlow が植物を設計し直したように、シリコンからデータセンターまでを 1 つのシステムとして設計し直すことでした。

具体的には、推論用の Maya、GA となった Cobalt 200、データ処理用の Azure Boost DPU、CXL によるメモリの再設計、scale-up と scale-out のネットワーク（MRC は Fairwater で製品化済み）、ハードウェア起点のセキュリティ（DCSCM と Azure Integrated HSM）、800V DC 給電と液冷・マイクロ流体冷却が紹介されました。performance per watt や performance per dollar は手段であり、本当の成果は、顧客がエージェントを本番に持ち込み、容量を気にせずスケールし、機密データを安心して預けられることだと締めくくられています。
