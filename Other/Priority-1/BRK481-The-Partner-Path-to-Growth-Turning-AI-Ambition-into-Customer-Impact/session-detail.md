# BRK481 The Partner Path to Growth: Turning AI Ambition into Customer Impact

## 1. はじめに

このセッションは、Microsoft のパートナー企業（SI、ISV など）に向けた、Ignite 当日のキーノートの内容を「パートナーにとってのビジネス機会」に翻訳して伝えるセッションです。技術的な実装やデモを見せる内容ではなく、Microsoft の go-to-market（顧客への提案・販売の進め方）、パートナー向けプログラムの新しい特典、そして 3 社のパートナーによるパネルで構成されています。

発表の中心になっているのは次の 4 点です。

1. Microsoft が顧客の要望を整理した「8 つのカスタマーアウトカム（conversations）」と、Ignite の発表内容の対応づけ
2. 新サービス Azure Catalyst によるオンプレミスからクラウドへの移行・モダナイズの機会
3. パートナー調査から見えてきた「将来のパートナー像」の 3 つの変化
4. Microsoft AI Cloud Partner Program（MAICPP）の新しい特典と、Frontier Accelerate などの投資

パネルでは、Icertis、Accenture、Insight の登壇者が、AI 活用の現場で何が変わったかを語っています。

> 補足：このセッションの録音には話者ラベルがありません。また、音声認識の誤りと思われる固有名詞が複数あります（詳細は 7 章に記載）。本ドキュメントでは、聞こえた綴りのまま、あるいは「音声認識の都合で表記が確定できません」と注記して記載します。

## 4. 発表者が伝えたいメッセージ

全体を通した主張は、**AI をパイロット（PoC）の段階から「成果（outcome）」の段階に進めるには、Microsoft とパートナーが同じ枠組みで顧客と向き合う必要がある**、というものです。

## 5. 発表内容の詳細

### 5.1 冒頭：frontier transformation

最初の約 1 分は、複数の短いコメントが続く導入です（話者は特定できません）。内容は次のとおりです。

* frontier transformation という言葉を今年作った。AI は生産性や効率化以上に人類の役に立つべきで、創造性、イノベーション、成長につながるものだ
* AI は人間の野心（human ambition）の流れの中にあるべきで、AI ソリューションで最も重要なのは intelligence と trust だ
* AI の信頼性は、与えるデータ・コンテンツ次第である
* Azure を使うと、以前は 2 週間かかっていたことが 2 日でできるようになった
* 顧客のコストとリスクを下げることが重要で、1 回で終わりではなく顧客の行きたい場所まで一緒に進む
* 「Microsoft は最大のパートナーだ」

そのあと登壇者は、顧客に出ている成果はパートナーなしには実現しなかったと謝辞を述べ、自身と Anne（Enterprise Partner 部門の GM）で話をしたあと、パートナーパネルに移ると説明しています。

### 5.2 go-to-market の枠組み：frontier と core、8 つのアウトカム

7 月に Microsoft が示した枠組みが、改めて紹介されました。

* 最上位に frontier transformation のビジョン（ナラティブ）がある。
* 実行は 2 つに分かれる。**frontier** は「業界が向かう先」で、顧客がエージェントとインテリジェンスで事業モデルや成果を伸ばす領域。**core** は、frontier 側の取り組みを実現するために、インフラへどう投資するかを顧客が尋ねてくる領域（別の箇所では「事業の中核（core of the business）」とも説明）。
* 顧客が Microsoft に求める **8 つのアウトカム**に、マーケティング資料、営業資料、インセンティブなど go-to-market の全体を合わせている。

この 8 つのアウトカムを、Microsoft は「conversations」と呼んでいます。顧客との対話にしたいからで、Microsoft の営業にも、質問して相手の話を聞き、アウトカム間を行き来する「situational fluency」を持つよう促していると説明しています。

例として、次のような組み合わせが挙げられました。

* 「human ambition の流れで AI を使いたい」顧客が、Amplify Intelligence（インテリジェンス層）も求める場合
* ubiquitous innovation としてエージェントを大規模に展開したい顧客が、その前にデータとアプリケーションをクラウドに移行する必要がある場合

このように、顧客に合った出発点を選び、複数のアウトカムをまたいで機会を広げることがパートナーにとってのチャンスだ、という説明です。

なお、8 つのアウトカムの名称全体は、発表では一覧としては読み上げられていません。トランスクリプトに出てきた名称は、Frontier、Amplify Intelligence、ubiquitous innovation などの断片のみです。

> ご参考：キーノートの発表内容は「book of news」としてまとめられており、Microsoft AI Partner Program の Ignite 向け資料や、パートナー開発マネージャー（partner development manager）経由で入手できると説明されています。

### 5.4 Azure Catalyst とパートナーの機会

Cyril 氏は、メインステージでは取り上げられなかったと思う発表として、**Azure Catalyst** を紹介しています。多数の資産を 1 つにまとめ、オンプレミスからクラウドへの移行・モダナイズを支援する「統合されたエージェント型の体験」と説明されています。

* エージェントを使うと 70% 速いという数字がスライドに示された。
* 対象はライフサイクル全体：オンプレミス環境のアセスメント、計画、移行、コードのモダナイズ。
* アセスメント結果とダッシュボードを出力し、ガイダンスを示し、コードとデータベースのモダナイズまで実行する。
* 移行用プロダクトや GitHub Copilot など既存の資産を 1 つのサービスにまとめる。コードのモダナイズの実行は GitHub Copilot が担う。
* 数百万行規模のコードのモダナイズを、短期間・低コストで行うパートナーや顧客が出てきている。

パートナーにとっての意味として、次の点が説明されました。

1. 半年以上前に作った移行・モダナイズの事業計画（ビジネスケース）は、Azure Catalyst と追加ツールで作り直す余地がある。
2. 顧客がデータ、インフラ、基幹業務アプリを分断されたオンプレミスに置いたままでは、frontier に到達できない。この移行自体が AI の機会である。
3. コスト面で「モダナイズは不可能」とされていたオンプレミス資産にも対象が広がり、より多くの案件を早く進められる。マージンが上がる実証ケースもある。
4. パートナー自身のツールや IP を組み合わせ、移行にとどまらず、継続的な最適化、セキュリティ、end-to-end のデータ・AI 基盤へ広げられる。データがクラウドに入れば、Microsoft IQ を通じて Copilot につなぐ流れも開ける。

### 5.5 将来のパートナー像：調査から見えた変化

Microsoft は過去 6 か月に、大規模な調査と、事例ベースの調査でパートナーの意見を集めたと説明しています。「皆さんに聞いた内容であり、事業の進め方を指示するものではない」という前置きつきです。背景として次の 3 点が挙げられました。

* 新しい技術やプロダクトが毎日出ており、Azure Catalyst のように新しい機会が生まれている。
* 顧客は Microsoft やパートナーをサプライヤーではなく、事業の中核を担うパートナーと見ている。AI により、技術の議論が IT 部門から経営層（boardroom）に移っており、パートナーが boardroom への入り口になる場面も多い。
* 顧客は成果を期待している。パイロットは多数行われ、「次のステップ」に進む局面にある。

そのうえで、パートナー像の変化として 3 つが示されました。

**1) end-to-end outcomes**

顧客はポイントソリューションではなく、事業課題の解決や機会の獲得を求め、そのための専門性につながりたいと考えています。実現方法はパートナーによって異なります。

* 8 つのアウトカムすべてにまたがって実行し、Copilot から Fabric、セキュリティ、Foundry まで一貫して担うパートナー
* 得意領域を持ちつつ、関係の深いパートナー 1〜3 社と組み、アウトカムをまたいで進めるパートナー（partner to partner）

**2) 経済モデルの変化**

従来は time and materials（時間と工数）が主流でしたが、顧客は価値の提供に基づく契約や関係を求め始めています。長期的な取り組みも、短期で価値を出して長期につなぐ形もあり得ます。これは Microsoft とパートナーの関係にも影響し、パートナーから Microsoft に対しても「価値を届ける支援」が求められると述べています。

**3) AI-powered partner**

パートナー自身が、自社の業務を AI で再発明する必要があるという点です。自社のエージェントやファクトリー（仕組み）を作り、精度・速度・価値を上げる。生産ライン、開発者、IP（ISV であれば自社ソフトウェア）をどう変えるかを考える。さらに、Microsoft IQ の上に「partner IQ」を載せ、エンジニアリング、プロダクト、マーケティング、セールスを結ぶ、という例えが語られました。

Cyril 氏は、この内容を **「wet paint（塗りたて）」** と表現し、今後も変わり得ると断っています。Microsoft 側の対応として、end-to-end のアウトカムの支援、エンタープライズから小規模までの営業チームでの対応、価値ベースの考え方を挙げています。

AI-powered partner の具体例として、Microsoft Learn の **Microsoft Learn MCP server** が紹介されました。

* 人が Microsoft Learn に調べに行く代わりに、エージェントが情報を集め、ドキュメント、RFP、コーディングに自動的に反映できる。
* Cloud Adoption Framework、well-architected のベストプラクティス、Copilot 導入・活用・エンドユーザー向けトレーニングの情報にアクセスできる。

### 5.6 MAICPP の新特典と Frontier 関連の投資

ここからは Anne が、4 つの「cross-solution 領域の投資」を説明しています。冒頭で、Azure、Copilot、BizApps のパートナーが会場に多くいることに触れています。

**(a) MAICPP の新しい特典（solution destination partner、specialization partner などの各ティア向け）**

1. Microsoft 365 E5 を超える **Microsoft ME 7**（のちの発言では「E7」とも）ライセンスが特典パッケージに加わる。「フルスタックを動かすため」と説明。
2. observability と FinOps に欠かせない **Agent 365** のライセンスも提供する。
3. Azure と Copilot の両方で開発しているパートナー向けに、**Copilot（co-work）クレジットを 2 倍にする**。

自社の MAICPP のティアを確認し、特典を使い切るよう呼びかけています。

> 補足：トランスクリプトでは「solution destination partner」という聞こえ方でした。音声認識の都合で表記が確定できません。

**(b) Frontier Transformation Engineer**

7 月に発表された認定（バッジ）で、Microsoft の forward deployed engineer に相当するものと説明されています。

* 顧客先でクロスディシプリンの仕事をするエンジニアに必要な能力を、Microsoft の forward deployed engineering チームと検討して設計した。
* 認定の品質基準は高く、追加で約 100 時間のトレーニングが必要。Anne は、チームから承認を求められた際、「Microsoft のエンジニアのうち何人が現実的に取得できるか」をまず確認したというエピソードを語っている。
* 7 月に発表し、9 月に運用開始。以降、このコミュニティから毎月少なくとも 500 人以上が取得している。さらに 30,000 人前後が登録し、取得に向けて進んでいる。
* 特徴として、Microsoft の **hypervelocity engineering** の方法論とフレームワークをパートナーに提供している。

**(c) Frontier specialization と Marketplace**

* 顧客からソリューション領域の境界が曖昧になっているという声があり、**Frontier specialization** を発表した。かなり高い品質基準で、開始には Copilot specialization、data security、identity and access management、AI apps and agents の各 specialization が必要（聞こえたとおりの並びで、各名称は音声認識の都合で確定できません）。
* Microsoft の営業・マーケティングは、この specialization を顧客に向けて推進するという。
* **Microsoft Marketplace**：特に ISV と IP パートナー向けに、co-sell だけでなく、Microsoft のチャネルを活用でき、複数の市場・言語に展開できる。「Commerce 7 by 24」と聞こえる発言があり、24 時間 365 日の取引を指す可能性がありますが、音声認識の都合で表記が確定できません。繰り返し販売できるソリューションを持つ IP パートナーに勧めている。

**(d) Frontier Accelerate**

7 月に発表された、顧客に対する Microsoft の取り組みです。パートナーと共に、信頼できる専門性、投資、チームのスキル向上を提供し、ソリューション領域、機能、Marketplace を探索できるようにする。「ワンフロントドア」で、GTM ツールやガイダンスを含む統合された投資を目指していると説明されました。

会場で Frontier Accelerate を使っている人を尋ねたところ、半数ほどでした（これに対して Anne は「かなりの投資を逃している」と述べています）。今回の Ignite で、human ambition・intelligence・trust の各層に沿った新オファーが加わりました。

| 領域 | 新しいオファー |

### 5.7 パートナーパネル

#### 質問 1：Azure でのプロダクトイノベーション（Icertis に対して）

Icertis は契約管理プラットフォームの ISV と紹介されています。回答は次のとおりです。

* Azure AI services の利用は 2018 年に開始。当時は顧客の「データの中身を知りたい」という要望に応じた contract intelligence だった。
* 現在、顧客は「仕事の流れの中で使えること」を求めている。製品は Foundry サービスを活用し、**Defender for Cloud** によりインシデントが 50% 減り、対応速度が 80% 向上した。
* **Fabric** では、メールやエスカレーションを契約オブジェクトに変換し、チャットの中に埋もれないようにして、業務フローに組み込んでいる。これは Fabric IQ につながる。
* キーノートで発表された Salesforce とのコネクタを歓迎している。Icertis は従来 Dynamics 365 や Salesforce との統合を自前で作ってきたが、それが減らせる。
* **Copilot** により自然言語で利用できる。例として、「契約はいつ失効し、更新日はいつか」と顧客が尋ねると、契約を直接参照して答え、Copilot のユーザーが法務に通知を送って更新を起動できる。
* Foundry、Fabric、Copilot の 3 つを contract management の「triple play」と表現している。

#### 質問 2：AI 時代の最大の機会と向かい風（Accenture と Insight に対して）

2 人分の発言があり、どちらが Accenture でどちらが Insight かは音声から特定できません。

**発言 1（以下、「コンテキスト」を軸にした話）**

* 18 か月ほど前は、HR 向け Copilot、カスタマーサービスのチャットボット、要約ツールなど、ユースケース単位のポイントソリューションを売っていた。いまは変革やプロセスの再発明に移り、「コンテキストを売っている」。
* Microsoft IQ によって、エンタープライズの **context platform（共通のビジネスコンテキスト層）** を立ち上げられるようになった。ポイントソリューションでは ROI が限られていたが、いまは大きな規模で価値を引き出せる。
* 長く「POC purgatory」にあり、事業の収益化や損益（P&L）への影響が見えなかったが、P&L への影響が見え始めている。
* エージェントはバックエンドの個別システムではなく、このコンテキスト層と対話する。1 つのドメインから始め（営業、マーケティング、財務など）、エンタープライズ全体の IQ へとスライス（slice）ごとに積み上げる。重複して作る必要がなく、エージェントは再利用できる。
* かつてのエージェントはサイロ化し、事業の一部しか見えなかったが、Enterprise IQ と context platform により、全体を見渡せる。再利用性と、広い範囲での利用が利点で、実際の KPI への効果が出始めている。

**発言 2（セキュリティの話）**

* 機会であり向かい風でもあるのは、**セキュリティ**。本番に出す前に環境を堅牢にする必要がある。
* Agent 365 と E7 は大きな底上げになる。多くの組織は適切なガードレールやポリシーなしで進めており（ハイパースケール、ローカル、ハイブリッド AI のいずれの場合も）、本番前のその段階が最初の機会になる。
* E3 や E5 の顧客に、Agent 365 の体験を提案する会話ができる。エージェントだけでなく、アプリまで含め、データがどこに触れ、エージェントがどう動くかを可視化し、プレイブックも出てきている。
