## 5. 発表内容の詳細

### 5.1 教育現場での AI の利用状況

教育は、Microsoft の用語でいう「frontier industry」（常に最新技術を導入する業界）とは言いにくい分野です。それでも、登壇者が示した数字では、AI はすでに広く使われています。

| 対象 | 発表された数字 |
|---|---|
| リーダー（教育機関の管理者層） | 92% がすでに AI を使っていると回答（必ずしも agentic とは限らない） |
| 教員 | 88% が日常的に AI を実装・利用している |
| 学生 | 「92」と述べている（単位は聞き取れませんが、文脈上は割合です）。課題の補助から、課題の代行まで様々な使い方をしている |
| ティーンエイジャー | 91% が、授業での AI の影響を何らかの形で心配している。依存や、理解せずに使うことになる可能性も理解している |

用途として挙げられたのは次のとおりです。デッキは共有されるので、写真を撮ってよい（NDA の内容はない）と案内されています。

- **リーダー**：運営・管理業務の効率化、学生の成績や改善点の把握
- **教員**：授業計画や単元計画のアイデア出し、学生がどこでつまずいているかの理解
- **学生**：情報の検索と要約、カリキュラムに関する質問、より深い洞察を得る質問。さらに、教員が提供した素材を、自分の好む形に作り替えてもらう使い方（学習管理システム上の素材を自分に合うように調整させる）も始まっている

> 補足：登壇者は「このような使い方は、教員やリーダーにはまだあまり想定されていないが、特に高等教育の学生は同じことが自分にもできると気づき始めている」と述べています。

### 5.2 教育現場の懸念

登壇者は、AI の広がりに懸念が伴うことを挙げ、「正しく進めるにはこれを考慮する必要がある」としています。

- **学術的な誠実性（academic integrity）**：教員や、ある面では学生も、これを最大の課題と感じている。登壇者は、この日の午後にブースを訪れた人から聞いた話として、「ある授業で、学生がすべてを AI に任せ、AI の説明をコピー＆ペーストして、批判的に読んだり分析したりしない」という例を紹介した
- **AI への依存（dependency）**：AI が多くのことを助けられる反面、完全に肩代わりしてしまう問題になりうる。登壇者は、Microsoft の製品でも教員への助言でも、「AI にできること・できないこと」を定義し、学習が実際に起きるよう教育的アプローチを保つことを重視していると述べた
- **データ、プライバシー、セキュリティ**：誰がアクセスできるのか、モデルの学習に使われるのか。登壇者は、「Microsoft ではデータを取得せず、モデルの学習にも使わない」と説明した。さらに懸念がある場合は、自分の環境で動かすことも、Azure の環境で可能だという
- **AI リテラシー**：学生が AI の使い方を知っているか、教員が学術の場に適切に取り入れられるか、というスキルセットの話で、AI リテラシーの取り組みが利用可能だと触れている

### 5.3 AI は「就職の必須要件」

登壇者は、学校に通うことを人生の「2 つ目のキャリア」と見なして、卒業後の準備を考えると、AI を理解して使いこなす力が不可欠になると述べました。根拠として、LinkedIn のデータ分析を挙げています。2015 年には AI の要件がなかった職種の **70% 超** が、現在は AI の要件を持っているという内容です。「AI が必要になるかどうかではなく、すでにここにある」という説明で、Microsoft 社内でも日々の仕事で AI を使うことは要件になっている、と付け加えています。

### 5.4 製品の成熟度の段階

製品面では、基調講演で紹介された製品を軸に、使い方の成熟度を次の順で説明しました。

| 段階 | 説明 |
|---|---|
| Copilot | アシスタントとして使う。質問でき、Web のコンテンツにアクセスでき、提供した情報について推論できる |
| Work IQ | もう少し進んだ段階。組織のデータ（Microsoft 365、Teams、Word、Excel など）が使われ、それらの中から情報を見つける |
| plugins と Cowork | skills（標準的な運用手順 = SOP）を定義して使う。教育に置き換えると、AI で扱いたい各シナリオ（助成金の選定、助成金申請書の作成スキル、研究分析など） |
| Cowork と Autopilot | 登壇者は Autopilot について「できれば近いうちに全員が使えるように」と述べている |

上の 2 つ（Copilot と Work IQ）が導入の入口で、成熟度が上がっていく起点だと説明されています。教育の変革を本気で考えるなら、skills、Cowork、Autopilot を見ていくことになります。

シナリオの例として **accreditation review（認定審査）** が挙げられました。長いプロセスで多くの文書と手順が必要ですが、ほとんどの組織には標準的な運用手順があります。それを Cowork に取り込み、見たい内容や状況更新のしかたを説明できます。

> 注意：登壇者は、Cowork には一定の成熟度が必要で、「いきなり飛び込む」ことはできず、段階的に育てていくものだと述べています。はじめの一歩としては、**Work IQ による research briefs（リサーチ概要）** が簡単な例として挙げられています。これらの文書はすでに誰かの OneDrive にあることが多く、複数の文書を集めてまとめるものです。

全体としては、「利用者が安心して質問できる → 機能を知る → 意味のあるシナリオを見つける → 実装を始める」という一連の流れを作ることが重要で、そこからシナリオが次々と見えてくる、という説明です。

### 5.5 Microsoft Education の製品

登壇者は、Microsoft が用意している体験として次を紹介しました。

- **Copilot**：基調講演で紹介された新しい「ホーム体験」が、多くの従業員や教員にも役立つ
- **Teach module**：Microsoft Education チームが作った、教員向けの入門レベルのアプリケーション。授業準備に AI をどう使えるかを考える入口で、授業計画の拡張、単元モジュールの作成、学習アクティビティの作成などを、カリキュラムに合わせて支援する（発言では、学生が学習アクティビティを作る支援とも聞こえますが、区別は確定できません）。のちのデモでは、授業計画、宿題と評価、学習アクティビティを扱う「agentic application」と説明されている
- **Study and learn**：学生向けのエージェント。特定のトピックの学習を助け、答えを与えるのではなく答えへ導く。Microsoft が導入した教育学的な概念が組み込まれている

### 5.6 拡張手段：Copilot Studio と Microsoft Foundry

登壇者は、「教育向けの AI を閉じた箱にしたくない」と述べて、拡張の入口を 2 つ示しました。

1. **Copilot Studio（makers 向け）**：「Python アプリで LLM を呼び出すようなことはしたくない」人向け。登壇者も自分はエンジニアだが、それはしないと述べている。Copilot Studio でエージェントを作る流れは、次のとおり
   1. 指示（instructions）を決める
   2. 使いたいデータを決める
   3. 体験をどう見せるかを決める
   4. そのエージェントをどこに表示するかを決める
2. **Microsoft Foundry（エンジニア向け）**：使うモデルを含めて、完全な制御、柔軟性、カスタマイズ性がある。Foundry には **2,000 以上のモデル**がある。基調講演で触れられたモデルの調整（tweaking）も利用できる。OpenAI や Anthropic のモデルではなく、自分が用意したオープンソースモデルを使うこともできる

「AI を使いたい」ならまず Copilot、Teach module、学生向けの Study and learn。「作る側」でカスタマイズしたいなら Copilot Studio と Microsoft Foundry、という整理でした。

### 5.7 教育向けの MCP servers

教育に合わせるための重要な要素が **MCP servers** です。スライドでは、黄色が Microsoft 製、灰色がパートナー製でした。

- 教育機関のすべてが Teams の課題機能を使っているわけではないため、**Canvas、Moodle、Blackboard** など、教育分野の主要なパートナーと協力して MCP server の作成を支援している
- スライドに示された MCP server は、private preview または一般提供（GA）の状態ですでに利用可能。Canvas の顧客向けのものも存在する
- 出版社の McGraw Hill は、Copilot、Copilot Studio、Microsoft Foundry に接続された MCP server についてプレスリリースを出している

利用のルートは 3 つあります。

1. Microsoft Education のルート（登壇者のチームが構築しているもの）
2. Copilot のルート（MCP に対応）
3. 自分で構築するルート

### 5.8 構築できるシナリオの例

登壇者は、自分たちが作ったものと、これから作れるものを、高等教育と K-12 に分けて紹介しました。

| 領域 | シナリオ例 |
|---|---|
| 教育・学習（共通） | シラバスの草案作成、学習ガイドの作成、コース計画 |
| 高等教育 | 研究、助成金申請書。必要なデータを取得し、ひな形（blueprint）に沿って作成する。採択されなかった理由、あるいは採択された理由を分析し、他の申請に再利用する、といった使い方も挙がった |
| K-12 | 交通管理（transport management）、家庭との連携（family engagement）、保護者面談のコミュニケーション。高等教育と似たシナリオも多いが、相手が幼いため実装が異なる |

登壇者は、網羅的な一覧を作るなら「あと 100 は足さないといけない」と述べています。「多すぎる」と感じる人には、**Copilot や Cowork をブレインストームの相手にする**ことを勧めており、自分も毎日そうしていると説明しました（例：「高等教育向けに、Cowork が意味を持つユースケースを考えて提案して」）。

### 5.9 Education MCP server の発表

今週、Microsoft Education として発表したのが **Education MCP server** です。Microsoft の製品を何らかの形で使っていれば、今日から private preview に申し込め、**GA までは追加費用なし**で、MCP で公開されるすべての機能にアクセスできます。登壇者が挙げた対象は、課題や成績などです。

また、Canvas や Moodle などを使っている場合も同じだと説明しています。MCP server は、データを Copilot に取り込むための手段で、デモの趣旨は「Copilot が教育向けに何をできるか」を見せることだと述べています。

## 6. デモ・手順

デモは、登壇者が「残り 5 分」と述べて、画面を複製して始めました。画面の細部（ボタンの位置や表示内容）は音声からは確認できません。語られた範囲を、順番に記載します。

### 6.1 Copilot で Education MCP server を使う

1. 画面に表示されたのは、通常の Copilot。登壇者は、Teach module を別のタブで開いておいた（授業計画、宿題と評価、学習アクティビティを扱う agentic application という説明）
2. Copilot でやったことは、**データソースを開き（プラス記号の下）、Education MCP server を有効にしただけ**。登壇者は「それだけ」と強調した
3. この MCP server が持つ MCP tools には、**読み取り（read）と書き込み（write）**の 2 種類がある。read では、課題、成績、フィードバック、ルーブリック、学生に送ったメッセージなど、Teams for Education でアクセスできるものすべてを取得できる。Canvas のサーバーを接続すれば、Canvas 上のものすべてが対象になる
4. すでに実行済みの結果を使って説明した。想定は代数（algebra）の授業で、学生の成績を見て、**誰がうまくいっていて、誰が脱落しそうか**を把握したい、というもの。デモ環境は 1 クラス 5 人
5. 登壇者が Copilot に与えた指示は、ごく短い 2 文程度で、「代数のクラスの各学生について、課題と成績、未提出かどうかなどの概要をください」という趣旨。登壇者自身、プロンプトとしては良くない（プロのプロンプターなら指摘する）と認め、多くの判断を Copilot に任せたと述べている
6. Copilot は、自分で次のように進めた：MCP server を使うことを判断し、**タスクリストを作成**し、データを収集し、**Python スクリプトを実行**した（タスクリストの中身は後で見せると言ったが、このセッションの語りでは詳細に触れられていない）
7. 結果が表示され、学生ごとの所見も含まれていた。登壇者は、うまくやっている学生と、つまずき始めている学生が分かると説明した。クラス平均の作り方などのデータ分析の概念を教える必要がなかったことも述べている
8. この結果は、Word や Excel にエクスポートでき、Teams のメッセージで上司（supervisor）に送ることも、より個人的に学生に送ることもできる
9. 登壇者は、指示にはこの 2 文以外に具体的な手順がなく、「何を達成するか、どう進めるか」は Copilot 自身が決めたと説明している

登壇者は、10 クラスを持つ教員、授業が大規模化し予算が減る中で「より少ない資源でより多くを行う」必要がある状況、高等教育では通常 TA が行うがその支援も必要、という背景を述べています。

### 6.2 Copilot Studio で同じ MCP server を使う

1. 「自分で作りたい」場合に Copilot Studio を使う、と説明した。認証を先にしておくべきだったと述べ、会場の Wi-Fi が遅くて読み込みに時間がかかった
2. 同じ MCP server を Copilot Studio にも接続できる
3. Copilot Studio では、**指示（instructions）を 8,000 文字まで**、好きなだけ詳しく書ける
4. 画面右側には MCP servers が表示され、**Work IQ** や **Education IQ** に接続できる（表示のとおりに述べている）
5. 例として、「授業計画（lesson plan）がここにある。それに基づいて、授業の復習のための課題を作り、学生に合わせて調整して」といった指示を出せる、と説明した。Copilot が、これらの概念を使って作成してくれるという説明で、実際の出力は表示されませんでした（時間切れ）

> 補足：登壇者のデモは、タイマーの赤ランプ（終了の合図）で終わりました。Copilot Studio での実行結果までは示されていません。

## 7. 注意点・発表者の気付き

- **学術的な誠実性と AI 依存**：教員の相談として、学生が AI の説明をコピー＆ペーストするだけで考えなくなるという例が示されました。AI が肩代わりしすぎないよう、教育学的アプローチと「AI にできること・できないこと」の定義が必要だという立場です
- **データの扱い**：Microsoft はデータを取得せず、モデル学習にも使わない。自分の環境で動かしたい場合は Azure 環境で可能です
- **Cowork は段階的に**：いきなり飛び込まず、Work IQ の research briefs のような簡単な例から始め、成熟度を上げていきます
- **プロンプトは雑でも動くが、最適ではない**：登壇者は、デモで使った指示が「プロのプロンプターには評価されない」ものだと認めています。そのうえで、Copilot が多くの選択を行う強みを示すためのものでした
- **MCP server の提供状況**：スライドの MCP server は private preview から GA まで混在しています。Education MCP server は private preview で、GA までは追加費用なしです
- Autopilot は「できれば近いうちに全員に」と述べており、現時点で全員が使えるとは説明されていません

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **教員の負担軽減**：授業計画、単元、学習アクティビティの準備を Teach module が支援する。デモでは、成績や課題の分析を短い指示で行い、その結果を Word や Excel、Teams で共有できた
- **学生の学習支援**：Study and learn は、答えを与えずに答えへ導く
- **研究の効率化**：助成金申請書の作成を、データ取得とひな形に沿った作成で自動化できる（採択・不採択の理由の分析も含む）
- **既存システムとの接続**：Canvas、Moodle、Blackboard などのパートナーとの MCP server により、Teams 以外の学習管理システムのデータも Copilot、Copilot Studio、Microsoft Foundry で使える
- **柔軟な構築**：エンジニアでなくても Copilot Studio で、エンジニアなら 2,000 以上のモデルから選べる Foundry で、エージェントを作れる
- **データの保護**：Microsoft はデータを取得せず、モデルの学習にも使わない

## 9. まとめ

教育機関の管理者、教員、学生はすでに AI を広く使っており、AI は就職の必須要件にもなりつつあります。一方で、学術的な誠実性、AI への依存、データのプライバシー、AI リテラシーという懸念にも向き合う必要があります。登壇者は、Copilot、Work IQ、Cowork、Autopilot という成熟度の段階を示し、入口は Copilot や Work IQ の簡単な使い方から始めることを勧めました。

Microsoft Education は、Teach module や Study and learn を提供し、Copilot Studio、Microsoft Foundry、MCP servers で拡張できるようにしています。今週発表された Education MCP server は private preview として GA まで追加費用なしで試せ、デモでは、短い指示だけで Copilot が成績や課題のデータを分析して結果を出す様子が示されました。
