# BRK447 Build the future of software on Microsoft

## 1. はじめに

このセッションは、ソフトウェアを開発・販売している企業（ISV など）が、Microsoft と組んで製品を「作り（build）」「収益化し（monetize）」「拡大する（scale）」ための道筋を紹介するものです。Cyril Belikoff 氏が全体の枠組みを説明し、Elastic、Icertis、Core AI の 3 社がパートナーとしての実体験を語り、最後に Marketplace への出品を支援するセルフサービスのツール「App Advisor」がデモで紹介されます。

## 5. 発表内容の詳細

### 5.1 Build：作る段階での Microsoft の支援

Cyril 氏は、build の領域を次の 3 つで説明しました。

**GitHub と GitHub Copilot**：ソリューションを作るためのツール群。既存ソリューションのモダナイズや、新規開発を、エージェント体験で加速する、という位置づけです。

**Microsoft IQ**：約 1 年前に発表され、今年かなり成熟したものとして紹介されました。ソフトウェア企業は、自社のデータとコンテキストでアプリケーションやエージェントを拡張でき、自社の IQ を Microsoft IQ と組み合わせて、顧客が自分の IQ（インテリジェンス基盤）を作る際の価値を高められる、と説明しています。顧客は自社の業務固有の情報を追加します（「Coke IQ」や「Alaska Airlines IQ」が例として挙げられました）。ソフトウェア企業は、そこに自社版の IQ を差し込める、という考えです。

**Microsoft Foundry**：パートナーから、AI 体験のスケール、品質、安全性とガードレール、パフォーマンス、コスト管理を高めるプラットフォームだと評価されている、と紹介されました。Alaska Airlines のデモでは、体験を微調整（fine tune）しながら改善する「ヒルクライミング（Satya 氏が言う stair climbing / hill climbing）」を進め、最後のステップでは別のモデルを検討し、この事例では Microsoft の AI モデルを選んだ、と述べています。選べるモデルは 11,000 以上に加え、フロンティアモデルなどがあるとのことです。

Cyril 氏は、今週発表された内容のうち、ソフトウェア企業に関係するものとして次を挙げました。

| 発表内容 | 説明 |
| --- | --- |

### 5.2 Monetize：Marketplace で収益化する

Cyril 氏は、「Marketplace は Microsoft が売る場所ではなく、皆さんが売る場所」であり、価値提案のすべてがパートナーの出品から成り立つと強調します。顧客に対しては、次のように説明していると紹介されました。

- すべてのユースケース向けの AI アプリとエージェントがある
- クラウドソリューション、業界ソリューションなどが揃っている。Azure だけではなく、Copilot プラグイン、Teams アドイン、Dynamics 365 コネクターなどもある
- 顧客は、Microsoft のエコシステム上で作られ、信頼でき、Microsoft と連携していることが分かるものを、ここで発見する
- 発見（discover）、試用（try）、購入（buy）に加え、Microsoft 365 管理コンソールや Azure テナントとの連携があり、購入後のプロビジョニングまでシームレスにつながる

ソフトウェア企業にとっての機会として、次が挙げられました。

- **世界中の数百万の購入者**にリーチできるグローバルなマーケットプレイスである
- エージェント体験を含むセルフサービス機能があり、顧客が自然言語で Marketplace と会話して探せる。例えば「Azure と連携し、Copilot に組み込める医療向けソリューションを教えて」と尋ねると、候補が表示され、比較や、AI を使った質問（「A と B の点で、この 3 つは同等か」など）もできる
- 取引の形は、クリックして購入する公開の取引のほか、**プライベートオファー**、複数当事者のプライベートオファー、チャネル向けの再販対応オファーがある。システムインテグレーターやチャネルなど、パートナーエコシステムとつながる仕組みがある

### 5.3 Scale：規模を広げる 3 つの手段

Cyril 氏は、Marketplace は市場に出る最初のステップで、さらに次の 3 つの機会がある、と説明します。

**（1）コア製品**

- Microsoft 365 のシート数は、Cyril 氏の記憶では約 3 億 5,000 万
- Copilot の有料シートは、直近で把握している数字として 3,000 万
- これらは Marketplace を通じて自社製品を接続できる導入基盤。Agent 365 が、次に接続すべき導入基盤になりそうだと述べている
- 例えば、Copilot プラグインや、Azure 上で動く M365 アドインを作れば、Microsoft のエコシステムを製品面で活用できる

**（2）エコシステム**

Microsoft 製品を再販するパートナーは多く、Microsoft 製品と並べて提供できるソリューションを探しています。パートナーを見つけてつながる方法があり、すでに Marketplace から販売されています。

**（3）プログラム：Frontier Accelerate for Marketplace**

ソフトウェア開発企業（SDC）向けのプログラムです。次のような支援が語られました。

- ソリューションの構築と、Marketplace へのオンボーディングの支援
- Marketplace に出品した後の追加の特典（クレジットやインセンティブ）。Marketplace で売るほど、より多くの価値が得られる
- 得た特典は、go-to-market、マーケティング、製品体験への再投資に使える

### 5.4 Marketplace に載るまでの流れ

Cyril 氏は、ソフトウェア企業にとっての流れを次のように説明しました。

1. Microsoft Partner Center で、ソリューションを公開（publish）する
2. 認証と検証が行われる。例えば、Copilot プラグインとして本当に動作するか、Azure で実行されているか、など
3. カテゴリー分けされ、Microsoft Marketplace の体験（Web ストア）に表示される
4. カタログは、右側の各コンポーネントにフェデレーション（連携）される

連携先の例は次のとおりです。

- Microsoft Copilot の中のエージェントストア：Copilot と連携して認証を受けたソリューション、Dragon Copilot（Copilot のヘルスケア版）で動くソリューション、Azure 上で動く大規模言語モデルなどは、Marketplace カタログから自動的に製品内の体験に載る。要件を満たせば、Microsoft 製品への道が自動的に開く、と説明された
- チャネルパートナー：6 社のチャネルパートナーが、Microsoft の Marketplace を自社のマーケットプレイスに組み込んでいる。Marketplace に入れば、幅広いディストリビューターとそのリセラー網にも露出される

### 5.5 パートナーパネル（Elastic、Icertis、Core AI）

Cyril 氏が司会を務め、3 社のゲストが、自社の AI 活用と Microsoft との関係を語りました。

#### Elastic（David Chow 氏）

- Elastic は検索の会社で、開発者や、増えつつあるエージェントが、大量の非構造化データから答えを正確かつ素早く見つけられるようにしている
- Microsoft Marketplace には 5 年以上出品している。無料トライアルがあり、その後、購入して有料顧客になれる
- AI による最大の変化として、無料トライアル／Marketplace 体験でのオンボーディングのパーソナライズを挙げた。ユーザーのユースケースをよりよく理解し、メール、チュートリアル、オンボーディング用の資産を調整する
- 大量の AI に対処する話として、Elastic は検索機能を使って、オブザーバビリティとセキュリティの製品も提供している。アプリケーションログやセキュリティログを検索して脅威を特定できる。攻撃側も AI を使っているため、守る側も AI で応じる必要があり、Microsoft と Microsoft Foundry の AI を製品開発に活かしている
- Marketplace の価値：顧客がいる場所で会えること。SMB では、Microsoft の信頼とブランドの約束が価値になり、信頼できるベンダー／パートナーとして見つけてもらえる。エンタープライズでは、購買の柔軟性、プライベートオファーの作成、Microsoft へのコミットメントの消化（drawdown）に Elastic の購入を含められること

#### Icertis（Brad 氏）

- 創業当初から AI 企業で、初日から Microsoft のスタックの上に作られた「Microsoft shop」。AI の進化が、市場への出し方や解決する問題を問い直す契機になった
- Icertis は、**AI ネイティブな契約インテリジェンスプラットフォーム**。契約を取り込み、署名までのプロセスを効率化するが、変革が大きいのは、契約が締結された後の使い方。契約上の約束や義務、文書内のインテリジェンスを、上流・下流のシステムやナレッジワーカーに届ける
- Microsoft が IQ で企業内の状況を提供し、Icertis が企業がサプライヤーとの間で結んだ約束（またはその逆）を提供する。そのコンテキストにより、ナレッジワーカーが知的な判断を下し、行動できる
- 「Microsoft のプラットフォームなしでは成功できなかった」。複雑なコンテキストと事業価値の課題を解いており、量の勝負ではない。「Fortune 100 で、Microsoft と一緒に hundreds of millions を生み出している」という趣旨の発言がある（通貨や単位は聞き取れません）。Microsoft のスタックによる構築と統合は「table stakes（前提条件）」で、自社は独自の IP に集中できる
- グローバル企業としては、データセンターの地理的な広がり、データレジデンシー要件、ソブリンティ（主権）が重要で、Microsoft にその方向に進化し続けてほしい
- 製品統合の価値：Microsoft 365、Dynamics、Copilot のスタックを通じて、ナレッジワーカーのいる場所（CRM や、契約の修正のための Word プラグインなど）に、判断に必要なコンテキストを届けられる。リーチの広さと、ビジネスユーザーに届くことが重要で、それが共同での収益化につながる

#### Core AI（Chief Commercial Officer）

- 設立から 10 年余りの AI ネイティブな、エージェントプラットフォームの提供企業。最新リリースを Azure 専用で発表した。Microsoft とのパートナーシップは約 2 年で、Foundry とも深く統合している。Foundry から Core のインスタンスを呼び出すこともできると話している（"Foundry Council" と聞こえる箇所があり、音声認識の都合で表記が確定できません）。自社を「最大のエージェント型プラットフォーム提供企業」（"largest agentic platform provider"）と称している
- 規制業界（金融サービスとヘルスケア）で、ソリューション主導で提供している。プラットフォームでの処理量は年間 110〜120 億件のインタラクション。その基盤となるスケールのインフラは、ほぼ Azure が支えている
- 自社でも自社製品を使っている（「Customer zero」）。顧客に販売する従業員体験ソリューションを社内でも使っており、Morgan Stanley の 80,000 人のアクティブユーザーが使うもの（聞こえたままの表記です）と同じ単一のエージェント機能を、社内のリソースも使っている、と話した

Cyril 氏はこの点を受け、先進的なパートナーは自社を「customer zero」として使っており、営業担当者が使えるなら売れる、Microsoft も同じだ、とコメントしています。

**業界特化のエージェントから始める理由**（Core AI の回答）：

- エージェント型ワークフロー自動化では、成果へのシフトが起きている。ここ 3〜4 年の自動化で簡単な問題は解決済みで、残っているのは、人が介在し、行き来し、組織やステップをまたいでコンテキストを保ち、複雑な調整が必要な長時間のワークフロー
- そのためにはドメインの理解が必要で、まず業界特化のエージェントとワークフローから始める。例として、米国の上位 5 行に入る銀行は年間約 5 億件のインタラクションを扱うが、汎用的なエージェントを提示しても通用しない
- Microsoft のパートナーは、Microsoft の業界アドバイザーと緊密に連携するべきである。顧客との場で、同じ言葉で話し、信頼性をもたらす。自社のエージェントは業界非依存だが、提案するときは業界と成果に特化している

**Microsoft との関係で価値を感じる 3 点**（Core AI）：

1. **Marketplace** は強力。ただし、営業担当者は「もう 1 ステップ増える」ため Marketplace を使わない理由を探すので、組織内の規律が必要。Marketplace で取引しなければ Microsoft に自社が何をしているかが伝わらず、Marketplace での取引実績に基づいて、リソースやサポートが提供される
2. **共同開発（co-build）** は本物だが、投資が必要。Core AI は Agent 365 のローンチ顧客で、「Lifter program」にも参加している（名称は音声認識の都合で確定できません）。統合は深く、簡単ではないが、投資すれば Microsoft からの見返りも大きく、製品チームまで届く
3. **リーチ**：EBC やイノベーションハブなどを通じて、顧客との場に入れてもらえる（EBC は略称のみで語られ、正式名称は語られていません）

| 3 人目 | 公共部門を例に、FedRAMP のような準拠の構築と、販売チャネルの両面で投資が必要で、Marketplace も同じ。Microsoft の優先事項を理解して一緒に取り組めば、適切な場所・時間に現れられる |

### 5.6 App Advisor（デモ）

Olivia 氏が、App Advisor を紹介しました。詳しい流れは 6 章にまとめます。概要は次のとおりです。

- App Advisor は **Frontier Accelerate for Marketplace の一部**で、アプリやエージェントを、構想から Marketplace への出品まで導く、Microsoft のインタラクティブなセルフサービスの道筋
- ガイダンス、ツール、エージェント体験を組み合わせ、構想（envision）、構築（build）、公開（publish）、成長（grow）を支援する
- 自分のソリューションに合わせた推奨（適切な出品タイプの提案や、出品内容の最適化のヒント）が得られる

Cyril 氏は、このあとのコメントで、出品内容の最適化機能は既存の出品にも使え、Marketplace 内のエージェント体験が探すものを理解している、と述べています。顧客は自然言語で Marketplace を検索するため、製品ページを最適化すれば AI 体験に見つけてもらいやすくなる、という説明です。

### 5.7 クロージング

Cyril 氏は、Frontier Accelerate for Marketplace について、構築、公開、販売拡大、差別化を支援し、セルフサービスの資料だけでなく人によるサポートもあると改めて述べ、利用しないのは、セルフサービスの支援、人の支援、インセンティブを置き去りにするようなものだ、と呼びかけました。最後に、Marketplace と App Advisor の QR コードが示され、フィードバックを求めて終了しました。

## 6. デモ・手順

デモは Olivia 氏が行った **App Advisor** です。架空のソフトウェア企業 Proseware（音声認識では「ProServe」などとも聞こえます）向けに、事前に用意した資料を使って、構想から出品内容の下書きまでを実演するもの、と説明されています。画面の細部は音声からは確認できません。語られた順に整理します。

1. App Advisor でいくつかの質問に答える。回答に基づいて、適切なステップに案内される。最初の回答は「アプリまたはエージェントの構築の支援がほしい」「Microsoft Azure で構築している」。Proseware の創業者は試作品を持ち、Marketplace で商用化したいが、開発を進める前にアーキテクチャの判断のトレードオフと出品タイプの考え方を知りたい、という設定
2. 同じ疑問を持つ企業向けに、**AI envisioning**（動画ワークショップシリーズ）が案内される。画面を下にスクロールすると、build、publish、grow のプロジェクトライフサイクル全体が見える。AI envisioning は、ソフトウェア企業がアプリを作って出品するときの商用化のステップを説明するもので、最近、ガイド付きワークブックなどが追加された。内容は、アーキテクチャから本番まで、購入者の準備から商用化まで、顧客価値から販売成長まで。App Advisor の build の最初のステップに組み込まれているため、離れずに動画を見られる。新しい動画は継続的に追加される
3. offer（出品）を開始する。公開のために、**agentic fast fill** 機能が出品タイプを検出し、手元の資料から **20 を超える項目**を入力する
4. この想定ではまだパブリッシャーとして登録していないため、ワークフローを離れずに登録する。会社名などの基本情報を入力し、法的連絡先に適切な人物を指定する
5. 入力後、処理に 1 分ほどかかる旨のポップアップが出る。Proseware の Web サイトの製品ページ URL を使い、裏でエージェントが、(a) 製品の販売方法に基づいて適切な出品タイプを推奨し、(b) ベストプラクティスに基づいた質の高い Marketplace 出品の下書きを書き、(c) 製品のスクリーンショットとロゴを取り込んで適切なサイズにする
6. 「データはお客様のものである」と説明された。Microsoft は特定の項目の事前入力に使うが、保存はしない
7. エージェントの提案として、出品タイプは **transactable SaaS offer** と表示された。概要と価格オプションの詳細が表示され、確認して作成する
8. エージェントが再び Proseware の製品ページから情報を取り込み、各項目に詳細を入力する。ID と名前の提案が出る。エージェントが入力した項目には **「AI generated」のタグ**が付き、編集するとタグは消える。人が常に関与できる、という説明
9. 出品の説明文は、自社の既存資料から用意した下書きをそのまま使っている（製品メッセージに投資済みなので手戻りを避けたい、という設定）。製品の機能、顧客価値、仕組みと出品詳細が書かれている
10. 顧客から見た出品のプレビューを確認し、気づいた点を編集する。細かい調整を除き、自分で入力したのは連絡先だけで、数分で済んだ、と説明された
11. 販売プランの設定：段階的な販売プランを設定している企業の成績が良く、無料トライアルが売上を後押しするというデータがある。既定で 3 つのプランが用意され、それぞれ無料トライアルがある。App Advisor に入力した内容は Partner Center にも同じ内容で表示され、Partner Center で出品の設定を仕上げて、顧客向けに公開する
12. **出品の最適化（販売成長のツール）**：公開済みの出品に対し、エージェントによるテストを実行して、ベストプラクティスと比較する。複数の観点で出品がスコア付けされ、改善案が示される。推奨事項はダウンロードしてマーケティングチームに共有するか、出品に移動してすぐ更新できる。予備的な分析では、推奨を受けて出品を更新した企業は、**トラフィックが 16% 増加**した、と説明された
13. 出品の最適化後は、リードの生成と管理、顧客やチャネルとの交渉による取引、Azure クレジットなどの特典、co-sell を活用する方法を学べる

> 補足：デモの手順 1〜11 では、実際に操作した画面の詳細（ボタン名や入力値）は語られていません。

## 7. 注意点・発表者の気付き

- **Marketplace での取引を徹底する**：営業担当者は「もう 1 ステップ増える」ため Marketplace を通さない理由を探しがちだが、取引しないと Microsoft に自社の取引が伝わらず、Marketplace の取引実績に基づくリソースやサポートも得られない（Core AI の発言）
- **co-build には投資が必要**：統合は簡単ではないが、投資すれば Microsoft からの見返りも大きい（Core AI の発言）
- **SMB 向けには製品説明ページに明記する**：エンタープライズ向け企業が SMB に売りたい場合は、製品の説明ページにその旨を書くよう呼びかけられた
- **build と go-to-market の両方に投資する**：公共部門の FedRAMP 準拠の例を挙げ、Marketplace も同じだと述べられた（ライトニングラウンド 3 人目の発言）
- **ドメインへの特化**：複雑な業務ワークフローには、汎用エージェントではなく業界特化のエージェントが必要（Core AI の発言）
- **App Advisor のデータの扱い**：事前入力に使うが保存しない、とデモの中で説明された
- **要件**：Copilot の中のエージェントストアなどに自動で載るのは、要件を満たす（認証を受ける）場合だけ

## 8. 利用者にとっての利点

このセッションの「お客様」は、主にソフトウェア企業（パートナー）です。語られた利点は次のとおりです。

- **リーチ**：世界中の数百万の購入者、Microsoft 365 / Copilot の導入基盤、チャネルパートナー 6 社（5.4）への連携
- **取引の柔軟性**：プライベートオファー、複数当事者のプライベートオファー、再販対応オファー。エンタープライズ顧客は Microsoft へのコミットメントの消化に購入を含められる（Elastic の発言）
- **出品の工数削減**：App Advisor の agentic fast fill が 20 を超える項目を入力。デモでは、自分で入力したのは連絡先ほかごく一部で、数分で済んだ
- **出品の改善**：推奨を受けて出品を更新した企業は、トラフィックが 16% 増加（予備的な分析）
- **支援**：Frontier Accelerate for Marketplace による、セルフサービスの資料、人によるサポート、Marketplace に出た後の特典
- **パートナー事例**：Elastic（Marketplace に 5 年以上、SMB での信頼と、エンタープライズでの購買柔軟性）、Icertis（Microsoft 365・Dynamics・Copilot を通じたリーチ）、Core AI（Azure 上での年間 110〜120 億件のインタラクションの処理）

## 9. まとめ

顧客が Frontier を目指すなかで、ソフトウェア企業は Microsoft のプラットフォームで作り、Marketplace で売り、Microsoft の製品・エコシステム・プログラムで規模を広げられる、というのが発表の骨格です。作る側では GitHub Copilot、Microsoft IQ（Work IQ、Fabric IQ、Foundry IQ と business plugins）、Microsoft Foundry、今週発表された新サービスが紹介されました。

パネルでは、Core AI が Marketplace での取引の徹底と共同開発への投資を挙げ、ライトニングラウンドでは、ソリューションと成果に集中すること、作るだけでなく一緒に売ること、build と go-to-market の両面に投資することがアドバイスとして出ました。最後に App Advisor のデモで、アプリ・エージェントの構想から出品の下書き、出品後の最適化までを、エージェントの支援で進める流れが示されました。

Marketplace と App Advisor には QR コードで案内されており、Frontier Accelerate for Marketplace は、まだ使っていない場合は活用するよう、繰り返し呼びかけられています。
