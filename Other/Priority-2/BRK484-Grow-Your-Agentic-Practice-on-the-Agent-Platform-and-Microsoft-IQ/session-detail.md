## 3. 何に関する発表か

エージェント時代に、パートナーが自社の事業（プラクティス）をどう育てるかがテーマです。発表者は、顧客が求めることを次の 3 つにまとめています。

1. 仕事を進め、仕事のやり方そのものを見直す手助けが欲しい。
2. 自社の業務を理解するエージェントが欲しい。
3. 信頼でき、拡張でき、経済的なエージェントが欲しい。

この 3 つは、今週のセッション全体で繰り返し出てくる枠組みである Human ambition（人間の意欲）、Intelligence（知性）、Trust（信頼）に対応します。

発表の流れは次のとおりです。

1. 状況の整理（ガバナンスの成熟度、投資対効果の差、繰り返し出てくる 5 つの悩み）
2. 人間の意欲：エージェントを繰り返し作り、スケールさせる（鉱業と SaaS 事業者の例）
3. 知性：業務を理解するエージェント（Microsoft IQ の使い始め方、ライセンスナビゲーターの事例、学習ループ）
4. 事業の組み立て方（AI ファクトリー、助言から運用まで）
5. 信頼：安全に、大規模に動かす（専門サービス会社の事例、Agent 365、FinOps for AI）
6. パートナーが売れる提供メニューと人材育成、次の一手

## 4. 発表者が伝えたいメッセージ

**問いは「誰がエージェントを作っているか」ではなく、「エージェントで業務プロセスを端から端までどう変えるか」です。** その実現を支える柱として、次の 3 点を挙げています。

- 繰り返し作れる仕組み（再現性）：1 つの成功例ではなく、100 回できる形にします。
- 業務の文脈：エージェントが自社の業務を理解するよう、データと知識を整えます。
- 信頼：エージェントを可視化し、安全とコストを管理します。

もう 1 つの強いメッセージは、Microsoft が提供するのはプラットフォームの一部であり、**顧客の業務を知っていること（ノウハウ）はパートナーの価値である**という点です。

## 5. 発表内容の詳細

### 5.1 状況の整理

最初に挙げられた数字は、成熟したガバナンスモデルを持つ組織が 21% という点です。そこに大きな機会があると述べています。また、先進的な顧客（フロンティア顧客）が得ている投資対効果は、それ以外の顧客とかなり違うとも話しています。

顧客から繰り返し出てくる悩みを、発表者は 5 つにまとめています。

1. エージェントに自社の業務をより理解させたい。
2. コストが急上昇している。適切なモデルと適切なツールを、適切なタスクに使えているかを知りたい。
3. 価値が出ているかを知りたい。変更したら価値がどう変わるかも知りたい。
4. 自社のどこにエージェントがあるか分からない。すべてが Microsoft のプラットフォーム上にあるわけではないので、把握、統制、管理したい。
5. AI で開発は速くなったが、製品の出荷は速くなっていない。そのため、ビジネス側との連携と、仕様駆動開発、ビジネス側と開発側の「常に有効な契約」としての要件が課題になる。さらに、クラウドへの展開、テスト、変更管理を速くする必要がある。

### 5.2 人間の意欲：繰り返し作り、スケールさせる

発表者は 2 つの例を挙げています。

**例 1：鉱業の顧客。** 採掘から港までの流れで最大の課題は、サプライチェーンの混乱です。採掘した鉱石は社内で運搬し、鉄道で精製しますが、鉄道の障害や検査があり、欠陥の検出も遅れがちです。価値が出た進め方は、共有のデータと AI の基盤を作り、その上にアシスタント用のアプリケーションを置くことでした。

1. 基盤をつなぐ：データを移動せずに取り込みます。データレイクは Fabric、Azure Databricks、Foundry のナレッジベースなど、複数の方法で束ねられます。
2. その上にエージェントを作る：顧客の価値の流れ（バリューストリーム）をまず見つけ、それを複数の部門で再利用します。一度きりのプロセス修正ではなく、基盤を通じて広げます。
3. ビジネス向けのプラグインを取り入れ、知識を体系化して、作る複数のエージェントに展開します。

**例 2：ソフトウェア企業（SaaS 事業者）。** 最上位のフロンティアモデルは、作っているエージェントに使うには非常に高価です。そこで、コストを抑える必要があります。モデルとコンテキストの最適化という FinOps の実践が鍵になり、継続的な改善のループを後で説明すると述べています。

### 5.3 知性：Microsoft IQ の使い始め方

発表者は、すでに出発点がある、と強調します。ゼロから作る話ではありません。

| 項目 | 発表での説明 |
|---|---|
| Work IQ | Microsoft 365 Copilot を使っていれば Work Graph が組み込まれています。エージェントから Work IQ に MCP でアクセスするには、API の設定で 2 行ほど有効にすれば済む、と説明しています。最も早く価値が出る入口と位置づけています。 |
| Fabric IQ | 2,000 万個（発話は 20 million）の意味モデル（セマンティックモデル）があり、多くのチームが作った Power BI ダッシュボードにはそれぞれ意味モデルがあります。これを MCP 経由で Copilot に直接つなげられ、Fabric 側の容量ユニット（CU）は消費されません。 |
| Foundry IQ | これまで Azure AI Search を通じて、RAG と埋め込みベクトルを提供してきました。非構造化データを意味による順位付け（セマンティックランキング）に取り込みます。Web IQ にもアクセスでき、採算面（経済性）が大きく改善した、とのことです。 |

Work IQ の例として、営業の値引きの説明があります。取引は最終的に CRM に記録され、値引き率は 25% だったとします。そこに至る過程は、Teams の会話、チャット、メールにあります。競合がいたこと、条件によって 12% の値引きから 25% の値引きになったことなど、**判断の理由（推論）を残せる**ようになります。

また、現在よく見る利用のパターンも紹介されています（2 週間ごとに変わるとのことです）。社内向けの専門エージェント、ワークフロー自動化、コンテンツ処理、データとの対話です。Fabric IQ の意味モデルと Copilot の組み合わせも、このパターンに含まれます。エージェントのプラットフォームの順位も上がっています。業種では、小売、資本市場、ヘルスケア、金融サービスが多く、意外性はないとのことです。

顧客の関心は 2 つのパターンに分かれます。

- 商業的に重要な、深いシナリオ：より高い価値のある知能が必要で、GPT-6.2 Astra や Fable 5.2 のようなモデルでの検証が必要になりうる、と述べています（モデル名は音声認識の都合で表記が確定できません）。
- B2C や B2B2C の規模のシナリオ：Sol、Terra、Luna のようなモデル（同上）に、適切な文脈と、コンテキストエンジニアリングを組み合わせ、複数部門に広げます。

後者のようなケースでは、最適化、ファインチューニング、モデルルーティングといったプラットフォーム側の能力が必要になります。

ソフトウェア開発ライフサイクルとエージェント型エンジニアリングについては、ここでは掘り下げず、翌日 15 時のセッション（Sandy 氏と Matt 氏）を案内しています。AI ランディングゾーンは、Ben Brower 氏らによる木曜のセッションが案内されました。WAF（Well-Architected Framework）で得た知見のうち、PoC から本番に移るときの課題を、AI ランディングゾーンの機能とリポジトリにまとめつつあります。形は 2 種類で、AI ゲートウェイ型と AI ランディングゾーン型です。

まとめとして、発表者は次の 3 領域を示します。影響を出すエージェントを作ること、シナリオを見つけること、すべての作り手（ビジネスアナリストも開発者も）を支援すること（Copilot のスーパーアプリのコードタブ、Cowork などを IQ につなぐ）。そして最後に、セキュリティとガバナンスです。

### 5.4 知性：ライセンスナビゲーターの事例

Microsoft の社内事例で、ライセンスの方針を理解するのに 1 時間以上かかることもある、という課題から始まりました。社内のマーケティングエンジニアリングのチームが、従来型の知識エンジニアリングに取り組んでいます。

1. ドキュメントを整理し、構造を作り直す。
2. ライセンスモデルの適切な箇所にタグを付けて、正しい参照を取得できるようにする。
3. 利用者ごとの窓口（チャネル）を用意する。

さらに重要なのは、どの知識の要素とタグを出すかをセマンティックのリランカー（再順位付け）に判断させるためのタグ付けだ、と説明されています。パターン 3 として、知識エンジニアリング、事前の評価、チャネルでの利用を一式にしたものを挙げています。

### 5.5 Microsoft IQ で「顧客の IQ」を作る：行動の呼びかけ

発表者の呼びかけは次の 3 つです。

1. **領域を 1 つ選ぶ。** 先に挙げた出発点（データとの対話、ナレッジベース、組織内の人とプロセスの動き）から選びます。開発分野の例もあります。Teams の会話、チャット、定例のスクラムミーティングから、どの PR を上げる必要があるかを見つけ、Work IQ と GitHub Copilot を使って開発ライフサイクルに自動で取り込む、というものです。
2. **ビジネスプラグインを作る。** 今朝のキーノートで見たとおり、スキル、情報源、人を組み込みます。プロセスを再構想して、適切な文脈を作り、適切なエージェントに公開します。
3. **測定して広げる。** Fabric を通じた IQ の共有に今後取り組みます。ビジネス拡張に関する作業は、今後数か月で進みます。パートナーが自社のデータや知的財産（IP）をつなぐことが、よくある質問になっているとのことです。コンテキストを意識したエージェントを構築するセッションも、今週あります。

要するに、エージェントの機会を自分のものにすること、業務プロセスを分解すること、自社の IP を加えて顧客の IQ を作ることです。

### 5.6 学習ループ：評価から最適化まで

今週の発表の大きな部分は、GitHub、Fabric、Foundry のプラットフォームの能力を束ねることだと述べています。その上で、改善の学習ループを次の順に説明しています。

1. **評価から始める。** 組み込み、またはカスタムの評価器を、エージェントが処理している実際のトラフィックに対して実行します。
2. スコアが下がったら、トレースを見て、どのトレースを新しい評価のユースケースにできるかを見極めます。
3. エージェントオプティマイザーで、成功基準に対してエージェントを評価し、構成を生成して改善します。品質、レイテンシ、成功した結果あたりのコストを比較し、承認してからデプロイします。
4. 新しいモデルが出たら、モデルルーターで、レイテンシや性能の観点で最適化する価値があるかを確認します。
5. エージェントの調整では、トレースから、多く呼ばれているツールやナレッジベース（トークンを消費しているもの）を見つけます。その結果、どのビジネスプラグインを作るべきかが分かり、トークンコストを減らせます。
6. ここまでの次の段階が、モデル自体です。今朝の Alaska Airlines の例のように、同じ成功基準のもとで、マネージドトレーニング（管理された学習）を使います。強化学習のループを実装し、Foundry 上のオープンウェイトモデルを、計算資源を含めてカスタマイズする形です。

このように最適化の周りに事業（プラクティス）を作る余地がある、と述べています。

### 5.7 エージェントファクトリーと事業の組み立て

ソフトウェアファクトリー、AI ファクトリー、エージェントファクトリーという考え方の進化を整理します。発表者が強調するのは、Microsoft が提供できるのはプラットフォームの要素で、業務の知識とノウハウはそれを超える、という点です。必要なことは次のとおりです。

- 顧客の出発点を理解する。
- 責任ある AI のための承認を整える。
- ガードレールを設ける。
- プロセスを作り直すための変更管理を整える。

今週開かれた顧客の諮問会議でも、これらが顧客の求める支援だと分かったそうです。そのため、事前の助言役（アドバイザー）を担うことが大きな機会です。「AI が事業に役立つ場所はどこか」から、「事業を変革するアイデアが 1,000 件ほどある。どこから始め、何が成果につながるか」に問いが変わっています。ボトムアップか、トップダウンか、という選択があります。

最大の学びは、ビジネスリーダーを 1 つの部屋に集め、**ビジネスのプロトタイピングワークショップ**を開くことだったと述べています。リーダーがプロトタイプを見て触れ、どの機能が最も強力かを考える形で、数時間で実施できます。そこから、技術チームを、絞った経営層向けの課題に集めるボトムアップの「エージェント型ハック」につなげます。これで、重要な領域でのビジネス効果が裏付けられます。その後に、ソリューションの設計、測定、改善を行います。

プラットフォームエンジニアリングについては、次の点を挙げています。

- ランディングゾーンを整える。
- ドキュメントインテリジェンス、音声、検索のような、多くのエージェントが使いたがる技術パターンを整える。
- IQ のプラットフォームを、各エージェント領域で使える共通の「レゴブロック」として使う。
- ソフトウェア（エージェント）ファクトリーで、PoC から本番へ俊敏に進める。

その上で、実践の領域が 2 つに分かれます。モデル、ツール、知識、IQ に対する価値のための継続的な最適化と、FinOps とトークン経済です。今週は Agent 365 でも多くの機能が発表されたと触れています。

### 5.8 信頼：専門サービス会社の事例（AI ファクトリー）

ここから Kirill 氏が話します。テーマは、エージェントを安全に、大規模に動かすことです。

事例は、大手顧客に戦略的助言とコンサルティングを提供する、専門サービス会社です。小さなチームが、新しい AI アプリごとに、セキュリティとデプロイの土台を作り直して、納品の時間を失い続けていました。そこで AI ファクトリーを作りました。GitHub、Foundry、ID と監査の制御を備えたエージェントのプロトタイプを一度作り、以降のすべての AI アプリで再利用しています。

**新しい AI アプリの本番化にかかる時間が 89% 短縮されました。** この数値は顧客の報告であり、コーディングエージェントの管理されたベンチマークではなく、LLM のベンチマークでもなく、トークンコストの話でもない、と繰り返し断っています。

パートナーの打ち手は、エージェントの納品ファクトリー（再利用できる IP）を売り、その後の継続的なエージェント運用（エージェントオプス）を売ることです。仕組みは 3 つのステップです。

1. **取り込みとプロトタイプ。** 発見の段階で学んだことを、動くエージェントのプロトタイプにします。顧客に早い段階で実物を見せます。顧客との 2 回目の打ち合わせで、本番相当のプロトタイプを作ってコーディングする、1〜2 週間以内に届けるべきだと述べています。分析のしすぎ（分析麻痺）に陥らないためです。使う製品は Copilot Studio、Microsoft Foundry、GitHub Copilot です。
2. **土台を作り、再利用する。** 話の中心です。GitHub Copilot が開発を支え、Foundry が下に座り、全体を ID、監査、デプロイの制御が囲みます。認証、アクセス制御、監査証跡、デプロイの自動化を一度作り、すべてのアプリで使います。小さなチームは、同じ配管作業ではなく業務ロジックに集中できます。繰り返し可能であることが肝で、「100 回できるか」の視点で考え、意図的に取り組むよう勧めています。
3. **安全に公開する。** 公開前にテストします。自動テストと評価で納品の一貫性を高め、評価は Foundry が受け持ちます。先の 89% はここにあたる、と説明しています。

### 5.9 信頼：Agent 365 によるエージェントの全体管理

典型的な企業には 3 人のリーダーがいて、エージェントの全体について別々の質問をします。

| 立場 | 質問 |
|---|---|
| CIO | 環境内でどのエージェントが動いていて、誰が所有しているか |
| CISO | 侵害されたエージェントはいないか。アクセス制御はどうか。安全に動いているか |
| ビジネスリーダー | TCO と ROI。エージェントが出している価値と、そのコスト |

Agent 365 は、この 3 人に 1 つのビューを提供します。キーノートで多くの新機能が追加されたと述べています。エージェントがこのビューに入る方法は 3 つです。

1. Microsoft のエージェント（Copilot Studio のエージェント、Foundry のエージェント）は、そのまま表示されます。
2. LangChain や OpenAI の Agents SDK などで作ったエージェントは、Agent 365 SDK を通じて接続し、同じポータルに追加されます。
3. 市場の主要なエンジン（聞き取りでは Core AI、Zendesk、Manos。表記は音声認識の都合で確定できません）は、標準で統合されています。ほかのプラットフォーム（Vertex AI、Bedrock、Databricks、Agentforce）も、Agent 365 SDK で接続できます。

結果として、1 つのポータルで、すべてのエージェントの動作場所と所有者が分かり、管理できます。

セキュリティ担当の「どのエージェントから心配すべきか」という問いに対しては、IT とセキュリティが同じビューで作業します。セキュリティが一度ルールを決め、エージェントに必要な最小限のアクセスだけを与えます。IT は新しいエージェントが来るたびにそのルールを適用するので、安全な状態かつ所有者付きで始まります。IT が危険なエージェントを見つけたら、セキュリティが同じビューから封じ込めます。時間が経つと、今日の例外が明日のポリシーになります。

### 5.10 信頼：FinOps for AI

ビジネスリーダーの問いは「やる価値があるのか」です。FinOps for AI の詳細は別の部屋のセッションがあり、録画の視聴を勧めています。ここでは主要な概念を説明しています。

- 調査によれば、CFO の 56% がコスト最適化を最優先事項の 1 つに挙げています。
- CEO の 77% が、性能を守るためのコスト効率の高い取り組みを進めています。
- スライドには、Goldman Sachs によるトークン消費の 2030 年までの成長予測として「24%」と表示されています。発表者はこれを「24 倍」と言い換えて、タスクあたりのコストが同じなら AI の請求も 24 倍になる、と説明しています。% と倍の食い違いについて、発話では確認できません。

上のとおり、経営の方針は「効率的であれ」です。そこで AI を戦略的投資として、財務の規律で管理することが必要で、パートナーが顧客の AI コストと事業価値を、計画、統制、運用する支援をできる、と述べています。枠組みは 3 つで、継続的なループです。

| 段階 | 内容 |
|---|---|
| 計画 | AI 支出の予測と予算を立てる |
| 統制 | ガードレール、上限、アラートを設定する |
| 最適化 | 投資から最大の価値を得る |

トークンノミクスと AI の FinOps について、チームを育成するための新しい学習コースがあり、スライド下部にリンクがあります。

ペルソナ別の問いは次のとおりです。

| ペルソナ | 問い |
|---|---|
| 開発者 | 無駄なく優れた AI を作るには |
| IT | 安全かつ手頃に拡張するには |
| ビジネス | 何に投資し、成果は出たか |

それぞれに合う製品や提供メニューが、スライド下部に並んでいます。挙げられたのは、プロビジョニングスループットユニット（PTU）、予約、Azure の Savings Plan、新しい AI Flex Plan、そして規模に応じた環境コストを見積もる Azure 料金計算ツールです。

キーノートで発表された新製品の **Agent 365 Business Analytics** は、ビジネスリーダー向けです。エージェントの価値とコストをドル建てで見られます。支出を計画、予測、統制し、コスト最適化の推奨に対応し、平易な言葉で質問できます。IT がユーザーライセンス側を、ビジネスが従量課金側を負担するため、両者の運用モデルを作るツールが必要です。IT が一部をビジネスに委任するために、委任アクセスがあります。

### 5.11 パートナーが今日から売れる提供メニュー

プラットフォームが整っても、顧客が止まる場所が 2 つあります。

**障壁 1：優先順位のついたユースケースがない。** 対策は、Frontier transformation discovery workshop（フロンティア変革の発見ワークショップ）を提供することです。顧客の AI のニーズを成果に合わせ、ユースケースを価値で順位付けし、ロードマップを共同で作ります。規制の厳しい業界のように、安全なユースケースから始める道も、重要な業務プロセスを AI で強化する大胆な道もあります。顧客ごとに AI への意欲は違います。

**障壁 2：アイデアと MVP の間で止まる。** 「300 件のユースケースを洗い出した」あとで、3 か月で技術が変わり、やり直す、という例を挙げています。対策は技術ワークショップです。1 対 1 でも 1 対多でも実施でき、ホワイトボードによる設計セッションのテンプレート、アーキテクチャ設計のテンプレート、サンドボックスでのプロトタイプを備え、MVP で価値を実証して終えます。数か月ではなく数日で、アイデアから、動くコードを持つ MVP へ進むことが狙いです。この進め方は、Frontier Company が直接の案件で使っているやり方でもあります。

この 2 つはパートナー主導で今日から販売できる提供メニューで、Frontier Accelerate for Azure が支えています（リンクはスライドにあります）。

### 5.12 人材育成（スキル習得）

パートナーのスキル習得は、MAICPP の最大の投資分野の 1 つです。認定、営業、技術商談、プロジェクトの各段階に対応した支援を、複数のタイムゾーンで、12 言語（発表者は「今はもっと多いかもしれない」と付け加えています）で提供していると述べています。

納品チームを育てるなら、中心になるバッジは **Frontier Transformation Engineer** です。Microsoft の Frontier Company と、自社のフォワードデプロイドエンジニアリング（FDE）のやり方を基に作られました。学習の道筋には約 100 時間の内容があり、Copilot、Foundry、Fabric、Microsoft IQ、業界知識、AI COE、フォワードデプロイドエンジニアリング、ハイパーベロシティエンジニアリングを 1 つのコースにまとめています。今年の夏の開始以降、2,000 人超が約 100 時間を修了し、バッジを取得しました。MAICPP のすべてのパートナーが受講でき、FDE の体制を作るなら全エンジニアを送るよう勧めています。

### 5.13 次の一手

1. **自社が最初の顧客になる。** 自分たちが使っていない技術を、顧客が信頼するはずがありません。まず自社の事業で Microsoft IQ を使い、顧客には実体験を話します。Microsoft 社内でも Work IQ を毎日使い、作っているほぼすべてのエージェントに組み込んでいる、とのことです。
2. **スキル習得の資料をチームに共有する。** 多くは無料で、MAICPP の特典として利用できます（年会費を払っているので使うよう促しています）。強調されたのは、Microsoft IQ の新しい学習、FinOps for AI、Frontier Transformation Engineer の 3 つです。
3. **拡張を計画する。** Microsoft IQ、FinOps for AI、Agent 365 を含む新しいプラクティスを育て、再現性のある案件にします。新しい技術ワークショップを大規模に使い、フロンティアに向けた人材を育てます。

## 8. 利用者にとっての利点

発表で語られた利点と成果です。

- 専門サービス会社の事例では、新しい AI アプリの本番化の時間が 89% 短縮されました。再利用できる基盤（認証、アクセス制御、監査証跡、デプロイ自動化）により、業務ロジックに集中できます。
- Work IQ の導入により、値引きの判断理由のような、推論の履歴を残せます。
- Fabric IQ の意味モデルを MCP で Copilot につなげても、Fabric 側の CU は消費されません。
- ライセンスナビゲーターにより、1 時間以上かかることもあったライセンス方針の理解を支援する、社内事例があります（具体的な短縮時間は発話では確認できません）。
- Agent 365 で、CIO、CISO、ビジネスリーダーが 1 つのビューで、エージェントの所在、所有者、アクセス、価値とコストを把握できます。
- Agent 365 Business Analytics で、エージェントの価値とコストをドル建てで見られ、支出の計画、予測、統制ができます。
- 技術ワークショップにより、アイデアから MVP まで数日で進められます。

## 9. まとめ

エージェント時代のパートナー事業は、3 つの柱で整理できます。繰り返し作れること（人間の意欲）、業務を理解する文脈を持つこと（知性）、信頼できること（信頼）です。使い始めは Work IQ、Fabric IQ、Foundry IQ のような出発点があり、領域を 1 つ選び、ビジネスプラグインを作り、評価から始める学習ループで測定して広げます。運用では、Agent 365 でエージェントを可視化し、FinOps for AI で計画、統制、最適化を回します。パートナーが売れる提供メニューは、発見ワークショップと技術ワークショップです。人材は Frontier Transformation Engineer のバッジで育てます。最初の一歩は、自社が最初の顧客になることです。
