# BRK419 From VMware to Hyper-V: Hyperscale virtualization in your datacenter

## 1. はじめに

このセッションは、VMware からの移行先として Hyper-V を検討している IT 管理者向けに、Windows Server 2025 の実績、次期版 Windows Server 2028 の新機能、そして今週一般提供（GA）になった **Windows Admin Center Virtualization Mode（vMode）** を、デモ中心で紹介した発表です。発表者自身が「デモ盛りだくさんのセッション」と予告したとおり、ほぼ全編がデモで構成されています。

中心となるメッセージは、**VMware のお客様はすでに Windows Server のお客様であり、Hyper-V という実績あるハイパーバイザーを追加費用なしで持っている**という点です。vMode は Windows Server のライセンスに含まれる無償の仮想化管理ツールで、「ダウンロードして 5 分以内にクラスターの管理を始められる」ことを目標に作られたと説明されています。

## 5. 発表内容の詳細

### 5.1 Windows Server 2025 の実績と Microsoft の方針

発表者によれば、Windows Server 2025 は「圧倒的な差で、最も速く採用された Windows Server」です。アップグレードしやすくする投資と、セキュリティの改善、Active Directory、ファイル、ストレージ、ネットワーク、Hyper-V と、プラットフォーム全体の改善がその理由とされています。

Hyper-V 関連で挙げられた 2025 の機能は次のとおりです。

- GPU パーティショニング、GPU とライブマイグレーション、GPU と高可用性、GPU プール
- 動的プロセッサ互換性
- ワークグループ Hyper-V クラスター
- ローカルストレージで高い性能を出すネイティブ NVMe
- Hyper-V 向けのネイティブ ReFS 重複除去と圧縮
- Network ATC、ネイティブ SDN

発表者は、Exchange と SharePoint が先にクラウドへ移ったように、クラウドへの移行は進むが、オンプレミスに残るものも当面ある、という認識を示しました。今週話した顧客は全員がハイブリッドだったとのことです。また、Microsoft の時価総額は Azure と AI に支えられており、それがすべて Hyper-V で動いているので、Hyper-V は同社にとって根幹の技術だと説明しています。

### 5.2 Windows Server 2028 の概要

次期版の名称が Windows Server 2028 であることは、今週発表されました（それまでは vNext と呼んでいました）。発表者は 2028 のテーマとして、アクセスとセキュリティの水準を上げること、エンタープライズ基盤の高速化（NVMe over Fabrics を含む）、大規模な運用管理、ハイブリッドインテリジェンスの 4 つを挙げました。ハイブリッドインテリジェンスについては、同日に行われた Windows Server 2028 の新機能紹介セッションを見てほしいとのことです。

Hyper-V に関する 2028 の新機能として、次が説明されました。以下はいずれも、現時点で提供済みの機能ではなく Windows Server 2028 での提供予定です。

| 機能 | 説明 |
| --- | --- |
| トラステッド VM 起動 | 物理サーバーで行っている測定付きの構成証明（アテステーション）を、VM の起動プロセスにも適用する。TPM を持つ VM を、Host Guardian Service やシールドファブリックを構築せずにライブマイグレーションやレプリケーションできる（チェックボックスで有効化） |
| 強化された Server Core | 展開時点で業界のベースライン（DISA STIG など）に沿ってロックダウンされている。現在は出荷後に利用者がロックダウンする方式 |
| GUI の追加・削除 | Server Core の上に GUI を追加したり、削除したりできる機能が復活する |
| Hyper-V VM ロードバランシング V2 | 現在のロードバランシングは粒度が粗いという VMware 顧客の声に対応。クラスタリングに既にある機能を前面に出し、vMode で細かい負荷分散を行えるようにする。VMware の DRS を意識した説明で、VM の性能を 5 秒ごとに採取し、1 分ごとに移行の要否を判断する動作が例に挙がった |
| そのほか | 異種プロセッサのサポート、ハードウェアを認識する RSS、ATC の改善 |

さらに、トラステッド起動を土台にして、Azure で提供している**コンフィデンシャル VM**をオンプレミスにも提供する計画が、2028 の機能として語られました。コンフィデンシャル VM では、利用者が証明書を持ち、ファブリックを運用する Microsoft でも VM の中身を見られない、と説明されています。

### 5.3 vMode の概要と要件

vMode は、仮想化管理に専念した専用ツールです。クラスター、ストレージ、ネットワーク、ATC の展開まで行い、Hyper-V が入っていなければそれも構成します。一方で、ドメインコントローラーの管理やパッチ適用は行いません。

発表者は使い方を次のように説明しました。8 台のサーバーをラックに入れ、Windows Server 2025 をインストールして最新の状態にし、ドメインに参加させるだけにします。Hyper-V もクラスタリングも有効にしません。その状態で Windows Admin Center にいくつか質問に答えて展開を指示すれば、再起動後には VM を作れる状態になる、という流れです。

Devonna White が説明した要件と特徴は次のとおりです。

- **費用**：Windows Server のライセンスに含まれ、追加費用はない。従来の管理モード（Administration mode）の Windows Admin Center も同様に無償。
- **ゲートウェイ**：Windows Server 2025（または、パッチを適用した 2022）を搭載した 1 台のゲートウェイマシンが必要。Network ATC に対応している必要がある。最小要件は 4 vCPU、メモリ 8 GB、ディスク 10 GB。
- **アーキテクチャ**：従来の Windows Admin Center は状態を持たず、クラスターやサーバーを単体で管理する設計だった。vMode は「ファブリック」の管理を目的とした、アプライアンス型のモデルで、エージェント方式と PostgreSQL データベースを使う。ライフサイクルの管理は製品側が担う。
- **規模の目標**：1,000 ホスト、25,000 VM。
- **System Center Virtual Machine Manager（SCVMM）**：不要。
- **提供状況**：月曜日に一般提供を開始し、ブログ記事も公開済みで、すぐにダウンロードできる。

そのほか、幅広いストレージ（特に SAN）への対応、VLAN と SDN のサポート、Azure Arc への一括オンボーディング、VMware からの VM 変換機能の統合が特徴として挙がりました。

### 5.4 ゲスト講演：Accutech の Phil Moss（顧客の現場の状況）

Phil Moss は、VMware から Hyper-V への移行が大きく加速していること、その会話には必ず管理ツールの話が含まれることを語りました。顧客は vCenter に慣れているため、できるだけ簡単に移りたいと考えているそうです。従来はここで SCVMM が提案されてきました。成熟した製品でエコシステムも充実している一方、導入が複雑で、管理の負荷とコストがかかるという認識です。顧客からは「1 年以内にやらなければならない」「更新のたびに 10 倍の費用を払いたくない」と言われるとのことです。

そこで求められるのが軽量な管理手段で、以前はフェールオーバークラスターマネージャーと PowerShell がその役割でした。しかし、移行元の経験に近く、vCenter のように感じられるグラフィカルな管理画面を求める組織が多く、vMode はそこに応えていると Phil は評価しました。管理層の構築に 18 か月〜2 年をかけずに済み、Windows と Hyper-V の価値を早く得られる点が大きな利点だという話です。Network ATC も顧客に好評だったとのことです。

また、顧客からは「vMode は周辺のエコシステム（監視、ストレージなど）に対応するのか」とよく聞かれ、SAN ベンダーやネットワークベンダーとの連携ができる拡張性がその答えになると述べました。銀行や公共機関の組織が、SCVMM の導入を予定していたところ、vMode の登場を受けて切り替え、多くの場合数百万米ドルのコストと時間を節約できたと話しています。VMware 担当者のトレーニングや移行も簡単になるとのことです。

Jeff Woolsey は、SCVMM の課題はコストだけでなく構成と設定の手間にあると補足しました。Tivoli や HP OpenView のような従来のエンタープライズ管理製品は、設定が難しく高価で、データベースが必要で、その維持管理や専用の教育も要る、特注で重量級の仕組みだったという説明です。vMode は軽量で 5 分以内にインストールでき、パッチ適用や監視などは、ゲストを Azure Arc に接続してクラウドから管理することで、運用の一貫性が得られると述べました。標準作業手順（SOP）も、SCVMM の場合は大きなものだったのが、vMode では小さくなり、再利用が進むという比喩も使われました。

## 6. デモ・手順

デモは、実機の操作画面と、事前に録画された動画（インストール）で行われました。画面の細部は音声からは確認できないため、語られた範囲を実施順に書きます。

### 6.1 vMode のインストール（動画）

Devonna White が、ほぼ実時間で再生している録画動画を使って説明しました（少しだけ早送りしているとのことです）。

1. Windows Admin Center を知っている人には見慣れたインストーラーを使う。追加された画面は 1〜2 つだけ。
2. 新しい画面でモードを選ぶ。Virtualization mode に必要な前提コンポーネントがなければ、取得するかどうかを確認され、承諾すると製品側が入手する。
3. PostgreSQL データベースのユーザー名とパスワードを入力する。後でアクセスする場合に備えて、どこかに保存しておくよう勧められた。
4. インストールが終わるとログイン画面が表示される。ユーザー名とパスワードを入れてサインインすると、管理対象のオンボーディングを始められる。

### 6.2 スタンドアロンホストのオンボーディング

Jeff Woolsey が実演しました。最初にスタンドアロンホストを見せた理由として、パブリックプレビュー中に、非常に古くて均一でないハードウェアを使っている顧客が多いと分かったことを挙げています。異なるメーカーのサーバーを混ぜてクラスターにしないよう強く勧めたうえで、そうしたハードウェアを再利用したい場合は、クラスターではなくスタンドアロンの Hyper-V ホストとして使えばよい、という提案です。

なお、同一の NIC、同一のファームウェア、同一の PCI スロットでそろえる運用は Azure Local が徹底していることで、Windows Server ではそこまで求めないものの、守るべきベストプラクティスだと述べています。

1. リソースグループを作成する。名前は Redmond とした。
2. Windows Server 2025 しか入っていない 3 台のホストを、コンピューティングとしてリソースグループに追加する。追加時にドメイン参加が必須で、簡易的な検証が走る。3 台は、すべて異なるハードウェア。
3. 「クラスターにする」は選択しない。ストレージはローカルストレージを使い、既定のストレージパスが表示される。
4. 展開が始まる。エージェントのインストール、Hyper-V が未構成の場合の構成、ストレージパスの存在と動作の確認が自動で行われ、進行状況がすべて画面に表示される。
5. 完了すると、ノード 1〜3 が稼働状態になる。
6. ノード 1 で VM を作成する。名前、仮想プロセッサ、メモリ、ネットワークとストレージを設定すると、3 台のセットアップと VM 作成が完了する。

### 6.3 クラスターのオンボーディング

標準ワークフローが同じである点が強調されました。

1. スタンドアロンのときと同様にリソースグループを作成し、サーバーを追加する。今回は「クラスターにする」を選び、クラスター名を指定する。
2. ネットワークを決める。NIC を指して用途を伝えるだけでよい。ある NIC はコンピューティングと管理用、別の NIC はストレージ用として指定すると、用途ごとに異なるオフロード設定を含め、最適な構成が自動で適用される。デモでは Intel の Ethernet アダプター（型番は音声から「EA10」と聞こえますが、音声認識の都合で表記が確定できません）をストレージ用、Mellanox の Connect 6（同じく表記は確定できません）をコンピューティングと管理用にした。
3. ストレージは SAN も使えるが、デモではローカルストレージを選んだ。クラスターなので、既定の VM 保存先は 1 か所で設定すればクラスター全体に反映される。
4. 内容を確認して、オンボーディングを開始する。各サーバーにエージェントが展開され、Hyper-V の構成を確認し、すべての NIC が Network ATC で正しく設定される。
5. 2 ノードのクラスターが完成し、スタンドアロンのときと同じく VM を作成できる。

Network ATC には、設定したあとで誰かが NIC の設定を誤って変更しても、正しくない状態を検知して自動的に元へ戻す、統合された正常性監視と修復の機能があります。発表者は「金曜日に Jeffrey Snover が誤って設定をいじっても」という冗談を交えて説明しました。

### 6.4 vMode のバックアップと復元

Devonna White の実演です。ここで守る対象は**vMode のゲートウェイ**、つまり vMode の背後にあるデータベースと一部の設定であり、VM 自体のバックアップではありません。VM のバックアップには別の手段があり、「パイプラインに何かあるかもしれない」という程度で、具体的な計画は語られていません。vMode は GA したばかりの v1 であることも率直に伝えられました。

1. 階層の最上位（ルート）で、バックアップと復元のツールを開く。
2. バックアップ先のパスとパスワードを指定する。パスワードはデータの暗号化と復号の両方に使う。
3. 復元時は、バックアップ（中身は判読できないデータ）を選び、パスワードを入力して復号する。
4. 数回のボタン操作で、データベースを復元し、バックアップ時点の状態にゲートウェイを戻す。
5. 復元中にサービスの再起動のため 403 エラーが表示されるが、問題はない。ログイン画面に自動的に移動し、戻ってくると元の状態になっている。

### 6.5 Azure Arc へのオンボーディング

1. Azure にサインインする（1 クリック）。Windows Admin Center のゲートウェイが Azure テナントに関連付けられる。
2. ルートに戻り、Azure Arc ツールを開く。
3. デモ環境は 1 クラスターのみ。クラスター内のすべてを選び、Azure Arc にオンボードする。
4. サブスクリプション、リソースグループなど、Azure Arc で通常必要な情報を入力する。

100 クラスターある場合はどうかという想定質問に対して、Azure Arc の手順はエージェントのダウンロード、インストール、Azure への接続の 3 ステップで、これらを並列に実行できるため、すべてのノードを同時にオンボードできると説明されました。進行状況はワークフローの状態ペインに表示されます。

### 6.6 ホットパッチの有効化

Azure Arc に接続したマシンでは、ホットパッチを**無料**で使えます。以前は有償だったが、数か月前に変更されたと Jeff Woolsey が補足しています。再起動の回数は、従来の年 12 回程度から、四半期に 1 回の年 4 回程度に減ります。

デモでは、オンボードした 2 ノードのクラスターで、ホットパッチのチェックボックスを選び、有効化をクリックするだけでした。Jeff Woolsey は、これは物理サーバー（VM を動かしているホスト）のホットパッチであり、ホストの再起動を避けられる点が重要だと補足しました。Windows Server 2025 であれば、物理、仮想、クラウド、他社クラウドのどこで動いていても、Azure Arc に接続すれば無料で有効にできます。

### 6.7 レプリケーション監視（Hyper-V レプリカ）

Hyper-V レプリカは、15 年以上前から Hyper-V に組み込まれている VM のレプリケーション技術です。ストレージに依存しないため、共有ストレージのないローカルストレージだけの 2 台のサーバー間でもレプリケーションできます。SAN ベンダーによるフルレプリケーションを使うこともできます。課題は、全体を一覧する手段がなかったことで、vMode が初めてそれを提供します。

1. ホストのゲートウェイツールから「Replication Monitor」を開く。
2. このシステムの VM レプリケーションが、正常性（重大、警告、正常）、同期の傾向、レプリケーション負荷、復旧テストの形で一覧表示される。
3. 「重大」を選ぶと、重大なエラーだけに絞り込める。
4. 同期の傾向から、RPO（目標復旧時点）や最終同期からの経過時間を確認できる。
5. レプリケーション負荷は、高・中・低で確認できる。
6. レプリケーションの詳細画面では、ホスト、グループ、正常性、クラスターの各フィルターをドロップダウンで選べる。ソースアドレス、IP アドレス、復旧ポイントなどの情報も見られる。

追加料金はかからないと、ここでも強調されています。

### 6.8 トラステッド起動（Windows Server 2028）

機能の説明に続き、vMode 上で設定する様子が実演されました。トラステッド起動は、物理サーバーでは電源を入れた瞬間から OS とハイパーバイザーに引き渡すまで測定と構成証明を行っているものを、VM にも持ち込む機能です。

構成要素として、既定で有効なセキュアブート（署名されたブートコンポーネントだけを読み込み、ウイルス対策ソフトから見えない早い段階の攻撃であるブートキットやルートキットから VM を守る）と、VM の分離されたファームウェア層で動く仮想 TPM が説明されました。現在の Windows Server 2025 では、TPM を持つ VM をライブマイグレーションしても、Host Guardian Service とシールドファブリックがなければ TPM が一緒に移動しません。2028 では、これがチェックボックスで済むようになる予定です。

1. Hyper-V ホストの設定で「分離されたゲスト」を構成する。クラスターにいることを認識して、クラスター全体に反映するかどうかを確認される。
2. ゲストのアテステーション（構成証明）の設定で、アテステーションサービスのプロバイダーを設定する。これもクラスター内の全ノードに反映される。
3. 新しい VM を作成する。名前を付けると、セキュリティの種類として「標準」または「トラステッド起動」が選べる（2028 で新しく加わった項目）。トラステッド起動を選ぶ。
4. 保存先を決めて作成する。
5. 作成した VM の詳細を開くと、仮想 TPM があり、セキュリティの種類がトラステッド起動になっている。
6. 管理者名とパスワードを入力して、ゲストのアテステーションを有効にする。

この結果、VM は起動プロセス全体が測定され、他のサーバーへ安全にライブマイグレーションでき、Hyper-V レプリカによる複製もできる、と説明されました。

### 6.9 ストレージパートナーとの連携（プレビュー）

SAN への投資は手放せないという顧客の声を受け、ストレージベンダーが vMode 用のプラグインを自社で作る形が取られています。「NetApp のストレージを最もうまく管理できるのは NetApp であり、Microsoft が NetApp や Hitachi のプラグインを作るべきではない」というのが発表者の考えです。両社の了承を得て、Ignite で見せています。

**NetApp**（デモ後の説明で「プレビュー中」と明言）

1. ストレージのタブで、リソースを追加する。NetApp はファイルベースのストレージなので、IP アドレスとファイルサーバーのストレージを入力して次へ進む。クラスタリングやネットワーク、ストレージの設定は不要だった。
2. vMode に組み込まれた NetApp Storage Manager 拡張が表示される。
3. ボリュームの追加とストレージの追加を実行すると、NetApp のアレイと通信し、ストレージとプロトコルを構成する。ホストまたはクラスターへのマウント、サービス品質（QoS）、NetApp の重要な機能の設定ができる。
4. プロパティ、権限、性能を確認できる。
5. サイズ変更の例として、30 GB のボリュームを 35 GB に拡張した。

追加の質問は NetApp のブースで受け付けているとのことです。

**Hitachi Vantara**

Fibre Channel と iSCSI のブロックストレージが中心の SAN ベンダーです。こちらも Hitachi が書いたプラグインとして紹介されました。

1. スナップショットのワークスペースで、Hitachi Vantara SAN のスナップショットを確認する。
2. 概要では、スループット、IOPS、容量、レイテンシーなどの性能を確認できる。
3. NetApp と同様に、ストレージのプロビジョニングと接続ができる。

### 6.10 VMware から Hyper-V への VM 変換

VM 変換ツールは、VMware から Hyper-V への移行を簡単にするための機能です。前提として、WAC ゲートウェイに PowerCLI をインストールする必要があります。

1. VM 変換を構成し、vCenter の認証情報を入力して、vCenter 上の VM の一覧を取得する。
2. 移行する VM を選ぶ。
3. 移行中も、VMware 上の VM は稼働し続ける。この操作は読み取り専用で、移行元の VM には変更を加えない。
4. 最初の同期（大きな転送）を行う。
5. 残りの差分が少なくなったところで、VMware 側の VM を停止する。
6. 最初の同期以降の変更分だけを、差分として転送する。
7. 結合して Hyper-V 上で VM を起動する（デモでは、移行元 VM の電源オフの段階、差分転送を経て、起動するところまで見せた）。

元の VMware の VM はそのまま残り、停止したまま保管（アーカイブ）するなど、扱いは利用者の判断に任せられます。

## 7. 注意点・発表者の気付き

- **クラスターにはそろったハードウェアを使うこと。** 異なるメーカーや世代のサーバーを混ぜたクラスターは避け、そうした機器はスタンドアロンホストとして使うよう勧めています。
- **vMode のバックアップ対象は限られる。** バックアップ・復元機能が守るのは vMode のデータベースと一部の設定で、VM のバックアップは含みません。vMode は v1 であると、発表者自身が認めています。
- **ゲートウェイの前提。** ドメイン参加が必要で、ゲートウェイは Windows Server 2025 または、パッチ適用済みの 2022 です。VM 変換にはゲートウェイへの PowerCLI のインストールが必要です。
- **PostgreSQL の資格情報は保管しておく。** 必要になったときのために、保存するよう案内がありました。
- **復元時の 403 エラー。** サービスの再起動によるもので、問題はないと説明されました。
- **ホットパッチの条件。** Azure Arc に接続していることが条件です。
- **提供状況の区別。** vMode は GA 済みです。Windows Server 2028 の機能（トラステッド起動、コンフィデンシャル VM、VM ロードバランシング V2 など）は今後の提供で、NetApp の連携はプレビューです。Hitachi Vantara は、デモ後の説明でプレビューと明言された発話は確認できません。
- Phil Moss は、拡張性（監視やストレージ、SAN・ネットワークベンダーとの連携）の話題に関して「Jessica が数分後に話すと思う」と述べましたが、その人物の名前は音声認識で確定できず、実際に登壇した発話も確認できません。

## 8. 利用者にとっての利点

- **費用**：vMode は Windows Server のライセンスに含まれ、追加費用がありません。ホットパッチも Azure Arc に接続すれば無料です。
- **導入の速さ**：「5 分で管理を始める」という目標で作られており、SCVMM を使わずに済みます。Phil Moss は、構築と管理層の整備に 18 か月〜2 年かけずに済む点を価値として挙げました。
- **既存資産の再利用**：SAN への投資を維持でき、ストレージベンダー自身がプラグインを提供します。異なるハードウェアもスタンドアロンホストとして活用できます。
- **VMware 経験者の習得しやすさ**：Phil によると、vCenter に近い感覚で使え、標準作業手順（SOP）の再利用が進みます。同氏は、銀行や公共機関の組織が、SCVMM ではなく vMode を前提に展開を計画している例に触れ、数百万米ドルのコスト削減と時間の短縮が得られたと話しました。
- **運用の一貫性**：Azure Arc に接続すると、パッチ適用や監視などをクラウドから管理でき、オンプレミスと同じ運用ができます。
- **再起動の削減**：ホットパッチで年 12 回程度の再起動が年 4 回程度になります。

## 9. まとめ

- Hyper-V は Microsoft 自身の事業を支える基盤で、発表者は今後 10 年の方針として投資を続けると明言しました。
