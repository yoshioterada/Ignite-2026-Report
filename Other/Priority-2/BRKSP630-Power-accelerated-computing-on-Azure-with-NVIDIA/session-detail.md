# BRKSP630 Power accelerated computing on Azure with NVIDIA

## 1. はじめに

このセッションは、NVIDIA の Dave Salvatore 氏と Microsoft Fabric チームの Maraki 氏が、Azure 上での NVIDIA アクセラレーテッドコンピューティング（GPU による高速計算）を紹介する内容です。前半は、エージェント型 AI によって推論に求められる性能がどれほど上がったか、そして NVIDIA プラットフォームが Azure でどう位置づけられているかの説明です。中盤では、GPU で高速化した Fabric のデータウェアハウス（GPU-accelerated Fabric DW）を、デモと数値で紹介しています。

最も大きなメッセージは、AI アプリケーションの性能は計算基盤だけでなくデータ基盤にも左右されるため、両方を GPU で高速化する価値がある、という点です。GPU-accelerated Fabric DW は現時点では限定的なパブリックプレビューです。

## 5. 発表内容の詳細

### 5.1 エージェント型 AI で高まる要求

Dave 氏は、今年はエージェント型 AI の年だと述べたうえで、AI の置き場所もユースケースも多様であり、どれも最終的にはデータで動くと話しました。アプリの出来を左右するのは、結局データセットだという考えです。

約 3 年前の ChatGPT の登場を、同氏は AI にとっての iPhone モーメントと呼びました。それまで AI は漠然とした話題でしたが、自然言語で質問して答えを得るという、学習コストの低い使い方が一般に伝わったためです。当時のチャットボット型アプリは、入力シーケンス長、KV キャッシュ（Key-Value キャッシュ）のサイズ、やり取りの往復数のいずれも、現在の基準では控えめでした。サブエージェントもありませんでした。

現在のエージェント型 AI は、チャットの 100 倍以上厳しいと同氏は見積もっています。

- 入力シーケンス長：中央値で約 142K。コーディング用途では 100 万トークン規模の話も出ている。
- KV キャッシュ：100 万トークン以上に拡大。計算済みのキー・値を再計算せずに使い回すための仕組みで、重要な役割を担う。
- 往復数：ユーザーだけでなく、エージェントがツールやサブエージェントを呼ぶため、構成要素間のやり取りが大幅に増える。

また、今年初めから現在までにトークン数が 34 倍に増えたこと、その伸びが今も急であることが示されました。Satya 氏らが基調講演で触れたとおり、性能と同時にコスト効率が重要で、コスト面でも成り立って初めて多くの組織が AI を拡大できる、とも話しています。

### 5.2 最近の発表

Dave 氏は、NVIDIA と Microsoft がそれぞれブログを公開していると前置きして、次の点を挙げました。

- **Vera Rubin と ベアメタルのコンフィデンシャルコンピューティング**：Microsoft はこれをテクニカルプレビューとして提供し、特にコンフィデンシャルコンピューティングを重視している。暗号化によって GPU と CPU の間に信頼された実行環境（TEE）を作る技術で、Grace Blackwell では主に GPU だけが対象だったが、Vera Rubin では Vera CPU も対応し、ノード全体で信頼された実行環境が持てる。
- **エッジからクラウドまで**：Azure Local が、Jetson デバイスと RTX Spark ベースのデバイスに対応した。RTX Spark は GPU 機能を持つ Arm ベースのプロセッサで、複数のノート PC と Dev Box に搭載されている。さらに液冷の大型デスクトップワークステーション（発話では RTX station と言っていますが、名称に自信がない様子でした）もある。これらは Windows で動き、Azure Local や Foundry Local を使った開発機として使える。準備ができたら Azure 環境へ容易に移して拡張できる。
- **モデル**：Nemotron ファミリーが Foundry で利用できる。NVIDIA のオープンモデルのほぼすべてが Foundry で提供されている。BioNeMo モデルは Microsoft Discovery で利用できる。ヘルスケア・ライフサイエンス向けのモデル。
- **ライセンス**：これらはオープンモデルで、開発してデプロイしたものは利用者のものになる。Nemotron などの利用条件は非常に開かれた仕様だと説明されました。

### 5.3 AI ファクトリー：生産的、長寿命、融通が利く

NVIDIA は AI ファクトリーという言い方をします。AI の進化が速いため、ファクトリーは生産的であるだけでなく、長寿命で、融通が利く（fungible、多用途の意味）ことが大切だという整理です。

**生産的**：ほぼすべての AI ファクトリーは電力制約を受けます。データセンターに入る電力と冷却能力は決まっているため、その電力枠から絞り出せるトークン数が売上にもコストにも直結します。Grace Blackwell（前世代）から Vera Rubin（現行世代）への比較として、SemiAnalysis（技術系の媒体でベンチマークを実施）のデータが示されました。Dave 氏は、一定の対話性能の条件で、メガワットあたりのスループットが 30 倍になると説明しています。発話上のベンチマーク名は Agent X と聞こえますが、音声認識の都合で表記が確定できません。

**長寿命**：約 10 年前の Volta 世代が今も契約されています。Ampere 世代は 3 年コミットの新規契約が続いており、Grace Blackwell（GB200）から始まった NVL72 系のプラットフォームでは、最長 10 年のオプション付きのコミットが続いていると述べました。Azure とその顧客に価値を提供し続けているという説明です。

**融通が利く**：AI だけでなく、データ分析、データ処理、従来型の機械学習、可視化、金融分析などに使えます。可視化の例として Omniverse があり、工場全体を仮想環境に作ってパラメーターを調整し、建物の基礎を掘る前に試せるデジタルツインが挙げられました。AI のパイプラインでは、事前学習、事後学習（強化学習を含む）、推論、エージェントのすべてに対応します。さらに、モデルやフレームワークの高速化、Azure などのパートナーのアプリが NVIDIA 上で最も良く動くようにする協業、約 1,000 万人の CUDA 開発者というエコシステムも強みとして挙げられました。

### 5.4 新しい世代はコストでも有利になりうる

SemiAnalysis が指摘した内容を補足するスライドとして、直感に反する話が紹介されました。最新世代は時間単価が高めでも、性能差が価格差より大きければ、総額では節約になるという内容です。逆に、会社のコストを下げるつもりで 2 世代、3 世代前を選ぶと、低価格インスタンスの隠れたコストが生じる場合があると指摘しました。常にそうなるとは限らず、NVIDIA が世代を重ねて観察してきた傾向だという位置づけです。

### 5.6 Microsoft Fabric と GPU-accelerated Fabric DW

ここから Maraki 氏の担当です。

**Microsoft Fabric とは**：従来のデータ基盤は、処理とクレンジング、非構造化データのデータレイク、構造化データのウェアハウス、トランザクション用の ERP、レポーティングなど、製品がばらばらでした。Fabric は、これらをまとめた統合データプラットフォームで、データからの洞察と AI 駆動のワークロードに対応する、と説明されました。

**直面している課題**：AI の時代には、データエージェント（ChatGPT や Claude など）の利用が広がっています。Fabric チームは、データ基盤そのものを AI ワークロードの規模に合わせられるかを課題にしています。業界ごとの例は次のとおりです。

- ヘルスケア：臨床医やリーダーが、患者の洞察と組織運営のために、タイムリーなデータと複雑な分析を必要とする。従来型の分析と AI 駆動の分析の両方がある。
- 製造：大規模レポートが分析と意思決定を遅くする。委託業者の対応頻度や必要な物資の把握に、AI を多用するワークロードを使うことがある。
- 保険とリスク：届いた請求を評価し、どう配分して対処するかをリスク管理者が判断する。

共通する課題は、終わりのないチューニングや過剰なプロビジョニングなしに拡張できる、対話的で予測可能な分析基盤です。性能を調整し続けたり、負荷に応じてスケールを上下したりせずに、洞察に集中したいというニーズです。

**GPU-accelerated Fabric DW**：発表で示された数値は次のとおりです。

- Synapse Data Warehouse に対して最大 19 倍高速
- 競合に対して最大 7 倍高速で、最大 60% 低コスト
- 実行基盤は NVIDIA のアクセラレーテッドコンピューティング。NVIDIA のチームとのエンジニアリング協業に謝意が述べられた

仕組みと使い方：従来のデータウェアハウスはクエリの要求に合わせてスケールします。さらに高速な洞察が必要な場面、例えば上でエージェントが動き、10 人だけでなくその人たちのエージェントや他の部署も同時に使うような、同時実行数が増える場面で、ワークスペース設定から GPU アクセラレーションをオンにします。オンにすると Fabric インスタンス内のすべてのデータウェアハウスに自動で適用されます。データを移動する必要も、新しい種類のプラットフォームをプロビジョニングする必要もありません。これまでと同じようにクエリを実行するだけです。

背景として、受賞歴のある研究（Cod Speed 論文、aka.ms/CodSpeed）に基づくと紹介されました。数年前からパートナーと考えてきた取り組みで、ほかにも賞を受けているとのことです。

**効果が出る領域**：縦軸にレイテンシ、横軸に同時実行数を取って考えます。ETL は同時実行数が少なくレイテンシが高い領域で、1 日に数回動けば足り、3 秒で終わる必要はありません。一方、スライドの薄い青の領域では、需要の多いアプリケーションやレポートに対し、低レイテンシで高い同時実行をしっかり支える必要があります。GPU アクセラレーションは、その答えの一つだという位置づけです。

### 5.8 オープンモデルとオープンソース、まとめ

Dave 氏は締めとして、NVIDIA のオープンモデルのほぼすべてが Microsoft Foundry で利用できることを再度挙げました。高品質なモデルとアプリにはデータセットが重要だという点とつなげ、AI の進化を支えてきた燃料の一つがオープンソースのソフトウェア、フレームワーク、そして今はオープンモデルだと話しました。NVIDIA はこれらのプロジェクトに多く貢献しており、Linux カーネルを含む Linux オペレーティングシステムへの貢献も続いていると述べています。

Dave 氏はまとめで、データベースは「データが置かれている場所」であり、データウェアハウスを GPU で高速化できることは、AI アプリケーションを展開するまでの開発の道のりで重要な要素だと話しました。また、Azure のクラウドデータやアプリサービスに、NVIDIA の高速化技術とライブラリを組み合わせたフルスタックの協業により、Azure 上のサービスや NVIDIA のモデルが最良の状態で動くと述べています。

## 6. デモ・手順

Maraki 氏が、GPU-accelerated Fabric DW のデモを行いました。画面の細部は音声からは確認できません。語られた内容は次のとおりです。

1. 画面の左は GPU アクセラレーションなしの従来の Fabric データウェアハウス、右（緑）は同じデータウェアハウスの GPU 版。比較用のアプリケーションを作成している。
2. 注目するのは横軸の同時実行数。まず 1 から 10 に増やして実行する。GPU 側（緑）は 1.3 秒で完了し、従来側（紫）は約 36 秒かかった。
3. 同時実行ユーザーを 10 から 100 に増やす。GPU 版は 1 秒あたり約 100 クエリを処理し、5 秒で完了した。従来側は 268 で終わった（単位は明示されていませんが、他の数値と同じく秒と読めます）。
4. 250 同時実行ユーザーに増やす（100 ユーザーに追加のエージェントなどが加わった状況を想定）。GPU 版は 1 秒あたり 100 クエリのスループットを維持し、11.4 秒で完了した。従来側は 600 秒余り（682 秒と記憶していると本人が述べた）。
5. この例では GPU 版が約 60 倍速いという結果になった。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- データを移動せず、ワークスペース設定をオンにするだけで、既存のデータウェアハウスすべてに GPU 高速化が適用される。クエリの実行方法も変わらない。
- 同時実行数が増える環境（人とエージェントが同時に使う場合）でも、低レイテンシを保てる。デモでは 250 同時実行で 11.4 秒だった。
- 競合比で最大 7 倍高速・最大 60% 低コスト、Synapse Data Warehouse 比で最大 19 倍高速。
- UNC Health では、レポートと分析で約 5 倍の性能向上。
- 最新世代はメガワットあたりのスループットが高く、電力制約のある AI ファクトリーでの ROI（投資対効果）向上につながる。
- 開発から本番への移行：RTX Spark 系デバイスなどで Azure Local を使って開発し、Azure に容易に移せる。

## 9. まとめ

エージェント型 AI は、長いシーケンス、大きな KV キャッシュ、多くの往復によって、チャットの 100 倍以上の負荷を生み、今年だけでトークン数も 34 倍になりました。NVIDIA は、生産的・長寿命・融通が利くという三つの観点で Azure とフルスタックで協業しています。その一例が GPU-accelerated Fabric DW で、設定をオンにするだけで同時実行時の性能が大きく伸び、デモでは 250 同時実行で約 60 倍の差が示されました。現在は限定的なパブリックプレビューで、参加希望者は QR コードのフォームから申し込みます。NVIDIA と Microsoft のブースや関連セッションも案内されています。
