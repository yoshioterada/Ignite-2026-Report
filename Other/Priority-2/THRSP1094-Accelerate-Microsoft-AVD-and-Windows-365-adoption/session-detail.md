# THRSP1094 Accelerate Microsoft AVD and Windows 365 adoption

## 1. はじめに

Fleet Control は今週、Microsoft Ignite で初めて公開された製品で、発表時点ではプレビューの申し込み受付中です。早ければ 1 月初旬にプレビューを開始し、一般提供は上半期を予定していると案内されています。

## 5. 発表内容の詳細

### 5.1 市場の動向

発表者は、AVD と Windows 365 の採用を後押ししている要因として、次を挙げました。

- 従来型 VDI の更新見積もりが想定より高く、他の選択肢を探す組織が増えている
- Microsoft の技術が近年大きく進歩し、AVD と Windows 365 の両方が成熟した
- 同業の組織が AVD や Windows 365 へ移行して成功しているのを見て、経営層が自社も移行すべきかを問い始める。Liquidware の主な業界は、医療、金融、政府機関
- Microsoft Azure Consumption Commitment（MACC）：大口顧客が Microsoft と結ぶ Azure の利用コミットメントです。発表者の理解では、AVD、そして近く Windows 365 も、コミット済みの利用額を消化できます。従来型 VDI の中間層をなくし、設備投資（CapEx）を減らして運用費（OPEX）に移せるため、Azure 全体の計画の中で予算を立てやすくなる、という説明です。

Liquidware は 2009 年から、組織が最適なデスクトップを提供するための製品を市場に出しており、Microsoft のこのプログラムには、前身の RDMI、WVD の時代からパートナーとして参加している、と述べています。

### 5.2 Liquidware の既存製品

発表者は、次の製品を紹介しました。いずれも、仮想、クラウド、物理を問わず、現在の Windows デスクトップの提供方法すべてで動作するとのことです。

| 製品 | 説明 |
| --- | --- |
| FlexApp | ベースイメージにインストールせずにアプリを提供する、モダンなアプリ配信 |
| Profile Unity | ユーザー環境（ペルソナ）の管理。プロファイルだけでなく、ポリシー、ユーザーが作成したデータへのアクセス、場所（社内か自宅か）に応じたマシンの動作、必要なアプリやリソースまでをまとめて扱う。FSLogix と連携することも、それに代わってより良くすることもできる |
| Stratosphere UX | デジタル従業員体験（DEX）の監視と最適化。ユーザー体験の検証、AVD や Windows 365 などの適正サイズ化に使う |
| リアルタイム DEX 修復 | デスクトップで起きていることをリアルタイムに見る機能。タスクマネージャーより多くのテレメトリを確認でき、1 時間前、2 時間前、前日など過去にさかのぼって当時の状態も確認できる。「毎週月曜に起きる問題」の調査などに使えると説明された |

Stratosphere UX の例として、米国最大級の住宅ローン会社で AVD 環境を適正サイズ化し、支出を減らしながら容量を増やした事例が触れられています（詳細は話されていません）。

### 5.3 事例：大手保険会社と FlexApp

従業員が約 17 万人の世界最大級の Windows 365 顧客の 1 社（発表者の表現では「世界最大かもしれない」）が事例として紹介されました。欧州と米国に拠点を持ち、数十の関連会社を持つグローバルな保険会社です。

- 従来型 VDI（Citrix を含む）、物理デスクトップ、Windows 365 の 3 種類でデスクトップを提供していた
- どの方法でも同じ手段でアプリを届けたい。Intune では配信が遅れることがあり、ログオン時にちょうど間に合う配信を求めていた
- アプリは 800 以上
- App-V は試したが、特殊なアプリをすべてパッケージ化できなかった。発表者によれば App-V はサーバーのサポートが終了し、クライアントのみサポートが続く状態で、そもそも良い選択肢ではなかった
- FlexApp を選んだ決め手は、複数の管理者が同時にアプリのパッケージ化を担当できること。800 以上のアプリを分担して作業できた

**パッケージ化の流れ（発表者の説明）：** 自宅の PC にアプリをインストールするのと同じで、「次へ」を進めて完了させるだけです。VHDX のコンテナーが作られ、保存先として Azure Blob Storage かローカルネットワークを聞かれます。完了するとすぐにテストでき、限られたユーザーに配ることもできます。互換性は 99% 超で、対象としたアプリの 100% をこの方式にできた顧客もいると述べています。

アプリはオン・オフで切り替わる形になり、環境にはインストールされません。このため、時間とともにマシンを遅くする「Windows の腐敗（Windows Rot）」がベースイメージに起きません。この事例では、イメージの数が 75% 減りました。アプリの更新も簡単になったと説明されています。

### 5.4 Fleet Control の概要

Fleet Control は、AVD と Windows 365 向けの企業規模の管理製品です。**顧客自身のテナントにデプロイされるため、安全性が高い**とされ、金融、医療、連邦政府といった厳しい環境を想定して、この形で最初に提供するそうです。

開発の背景として、AVD と Windows 365 を Azure ポータルで手作業で管理して手に負えなくなっている組織があること、チューニング、サイズ設定、ユーザー割り当て、イメージ適用などで画面を行き来する必要があることが語られました。Fleet Control は AVD と Windows 365 の部分を 1 つのコンソールにまとめます。

顧客から聞いていた「AVD 環境が時間とともにずれる」問題に対しては、**8 種類を超えるドリフトを検出し、自動で修正する**と説明されました。オートスケールに加え、他の製品で使っている技術を応用して RAM と CPU の使用を最適化し、節約額を初日から証明できるとしています。

**5 つの成果：** 初日からの節約、1 つのコンソールによる統制、自律性と自己修復、テナント内で動かす安全で閉じた環境、そして従来型 VDI からの「脱出計画」です。FlexApp と Profile Unity をすでに使っていれば、Fleet Control で AVD を用意すると、短期間でユーザーがログオンできるようになります。従来環境で使っていたアプリがコンテナーとして届いて即座に有効になり、Intune の処理を待たず、ペルソナ、ポリシー、ユーザーのデータにも初日からアクセスできます。製品は単品（アラカルト）で選べ、のちにバンドルも用意される予定です。

**Windows 365 向けの機能：** クラウド PC のプロビジョニング、サイズ変更、再起動、スナップショット、復元を一括で行えます。イメージ管理は AVD と共通で、AVD で使ったイメージを少し変えて Windows 365 に使うこともできます。管理者やユーザーごとに、触れるクラウド PC を限定することもできます。

## 6. デモ・手順

デモは、Jack Smith が **録画した映像を流しながら説明**する形式です（ネットワークの状況を考えて動画にした、と述べられています）。持ち時間は約 12 分で、全機能ではなく主な部分だけを見せています。画面の細部は音声からは確認できないため、語られた順に整理します。

1. **ホームとランチパッド：** 作業の起点となるホーム画面があり、手順が順番に並び、よく使う操作をランチパッドに置ける。使い方を製品自身に質問でき、質問は顧客が選んだ LLM（大規模言語モデル）プロバイダーに送られる。
2. **フリート全体の把握：** 環境の健全性、節約額の推移、環境で起きたイベントが 1 か所に表示される。複数のワークステーションを回ってイベントを確認する必要がない。
3. **コストの可視化と削減：** 実際の消費量を示し、基準値からどれだけ節約できたかを見せることが目的。ワークステーションを常時稼働にせず、朝に数台、9 時に数台といった具合に起動時刻をスケジュールでき、プロビジョニングやセッション構築の実行時刻を指定できる。エラーや問題があれば警告が出る。
4. **自然言語による質問：** 「何に注意が必要か」「何が遊休状態か」などと聞くと、見るべき点と対処が AI 的な回答で返ってくる。発表者は、リファレンスマニュアルを引いたり検索しまくったりする時代の終わりが見えてきたと話した。
5. **プール：** 環境内のプールと、その使用リソースを、Azure の複数のブレードをたどらずに確認できる。マシンが稼働しているか、プールをドレイン中かも見える。
6. **ガバナンス：** 人が指示するまで何も実行されない。既存の AVD がある環境では、そこから引き継げるが、管理対象とするものを明示的に選ぶ必要がある。大きな判断は人の操作が必須で、一部には自動修復がある。
7. **アクセス割り当てとガイド付きチェック：** アクセスは Entra で割り当てる。ロールを割り当て、ガイド付きチェックを通す。プール作成時には、構築可能な数と、ライセンス上残っている台数が示される。クォータを上げる必要があれば、プロビジョニング前に分かる。なお、Active Directory は将来のハイブリッド対応として検討中との趣旨で話されたが、確定した約束としては語られていません。
8. **自己修復：** ゲスト内のエージェントが正しく動いているかを確認し、動いていなければ、エージェントを復旧する手順（ランブック）を実行する。手順は編集でき、標準で組み込まれたフローも用意される予定。
9. **ギャラリー：** イメージごとにギャラリーがあり、従来の AVD のように公開・非公開のイメージが混ざらない。作業の履歴は手順ごとにタイムラインで記録される。
10. **イメージ更新：** テスト段階を経て、少人数のテスターに配ってから本番に昇格する。ロールアウトは追跡・検証され、強さを選べる。全員をすぐに追い出して再構築することも、警告だけ出して次回のログオン時に反映する穏やかな方法も選べる（後者は重要な環境向け）。
11. **クラウド PC：** 同じコンソールから Windows 365 のクラウド PC も管理できる。
12. **監査：** 個別のプール操作とは別に、全体の監査ログがある。セキュリティ要件に応じて、操作の記録を書き出し、必要な日数保管できる。誰が何をしたか、何を指示したかを記録する。

## 8. 利用者にとっての利点

- 更新費用が高い従来型 VDI から脱却する選択肢が持てる（発表者の言う「脱出計画」）。
- 費用面：CapEx から OPEX への移行、MACC の活用、初日から示せる節約額、オートスケールと RAM・CPU の最適化。
- 管理面：AVD と Windows 365 を 1 つのコンソールで扱える。8 種類を超えるドリフトの自動検出と修正。監査ログ。
- アプリ配信面（FlexApp）：ベースイメージが軽くなる。互換性は 99% 超で、保険会社の事例ではイメージ数が 75% 減った。
- ユーザー面：FlexApp と Profile Unity の組み合わせで、ユーザーが初日から、慣れたアプリと環境で作業できる。
- テナント内展開により、金融、医療、連邦政府のような厳しい環境でも使いやすい形になっている。

## 9. まとめ

Liquidware は、プロジェクトの 85% が AVD か Windows 365 を含むという実感から、これらを管理する新製品 Fleet Control を Ignite で初めて発表しました。1 つのコンソールでの管理、8 種類を超えるドリフトの自動修復、初日から示せる節約額、テナント内での展開、従来型 VDI からの移行支援が柱です。

Fleet Control は 1 月初旬にプレビュー、上半期に一般提供の予定で、FlexApp、Profile Unity、Stratosphere UX などの既存製品はすでに利用できます。詳しい確認はブース 5320R、またはプラットフォームガイドで案内されています。
