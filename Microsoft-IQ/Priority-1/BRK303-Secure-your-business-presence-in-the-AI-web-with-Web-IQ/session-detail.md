## 5. 発表内容の詳細

### 5.1 導入: 3 つの Web の時代

Dave 氏は、AI への投資が、州間高速道路網、月面着陸、宇宙ステーション、マンハッタン計画を合わせた費用より大きいという趣旨の数字を挙げ、昨年だけで投資が 130% 増えたと述べています（前半の文は音声が途切れており、正確な比較対象は確認できません）。

変化があまりに速いため、消費者は **3 つの Web の時代を同時に生きており、ビジネスもそうでなければならない** と説明しています。

| 時代 | 内容 |
| ---- | ---- |
| Human web | 人間がブラウザーのタブを多数開いて自分で作業する Web。企業とインターネット全体がこの需要に最適化されてきた |
| LLM web | AI に助けを求め、アシスタントが分かりやすく回答を示す。ただし、多くの場合、最後の仕上げは人間が行う |
| Do it for me web | 「全部やっておいて」と AI に頼む。一部のカテゴリーではこちらに移りつつある |

人はタスクによって、これらを行き来します。顧客も同じです。なぜ重要かの数字として、次が示されました。

- お気に入りのチャットボットとチャットする人は、話題に関係なく、チャットしなかった人より、そのセッションで購入する可能性が **53% 高い**。
- 買い物が中心のチャットでは、そのセッションで購入を完了する可能性が **4 倍**。

エージェントのトラフィックについては、4 月に 3 つの時代の話を始めたときのグラフでは、いずれ人間のトラフィックを超えると見込んでいました。Cloudflare の CEO は 3 月に、おそらく年末か 2027 年に起きると述べましたが、実際には 2 か月後の 5 月に起き、現在、インターネットのトラフィックの **3 分の 2 以上は人間ではありません**。

LLM Web でもエージェント Web でも、ブランドに必要なことは同じで、「見られ、推薦され、最終的に選ばれること」です。

### 5.2 エージェントはどこから情報を得るのか（Brian 氏）

これまで人は Bing、Google、DuckDuckGo のような検索エンジンで情報を探してきましたが、それらは人間向けに設計されています。AI アシスタントやエージェントには、直接取り込んで推論し、質問への回答や行動に使える、関連性の高い最新の情報が必要です。これが Microsoft が Web IQ を作った理由だと説明しています。

### 5.3 Web IQ とは

Web IQ は、AI エージェントに現実世界のインテリジェンスをもたらします。

- モデルは推論には優れるが、知識には限界がある。訓練日以降のことは知らず、Web IQ がなければ「機内モード」で動いているようなもの。
- Web IQ は、エージェントに Web、ニュース、画像、動画、そして Ignite で発表された places、weather、commerce などへのアクセスを与える。
- Microsoft の長年の検索の経験の上に、現在の AI エージェントの要求に合わせて一から作り直した新しいスタックである。
- 「モデルがインテリジェンスを提供し、Web IQ がそれが働くための知識を提供する」。

モデルに grounding が必要な理由は 2 つです。1 つ目は **鮮度（freshness）** で、製品の発売、価格変更、ニュースなど世界は常に変わり、モデルは訓練後のことを知りません。2 つ目は **深さ（depth）** で、モデルが製品について少し、あるいは多くを知っていても、全仕様、現在のオファー、特定の店舗の在庫までは分かりません。Web IQ は、モデルの知性を、現実世界の新しく詳細な情報で補完します。

例として、「最新の下取りオファーを含めて最安で買える電話機はどこか、近くのどの店に在庫があるか」という質問と、天候警報に合わせて保守作業員の予定を組むエージェントが挙げられました。推論は単純でも、情報が最新でなければなりません。モデルが高性能になっても grounding の必要性は消えず、むしろ重要性が増す、という考えです。

#### Web IQ Commerce

ショッピングの例として、従来の Web ページに頼る AI 体験（タイトルや価格、いくつかの選択肢しか見つからないことがある）と、Ignite で発表された新機能 **Web IQ Commerce** を使う場合の比較が示されました。Web IQ Commerce は、属性、画像、オファーを含む **400 億を超える製品オファー** にアクセスできます。エージェントは顧客の望みをよく理解し、製品をマッチさせられるようになり、「製品を見つけること」と「適切なものを選ぶ手助けをすること」の違いが生まれる、と説明しています。企業にとっての含意として、AI が推薦する時代には、自社製品についてアクセスできる情報の質が重要で、エージェントは理解できないものを推薦できない、と述べています。

#### 導入状況と Microsoft IQ での位置づけ

- Web IQ は、Copilot、ChatGPT、Mistral など、世界の主要な AI 体験の grounding にすでに使われている。
- 金融、製造、旅行、エネルギー、テクノロジーなど、さまざまな業種の数百の組織が Web IQ で構築している。
- Microsoft では、エージェントを 2 種類の知識源につなぐ。組織の内側（Work IQ、Fabric IQ、Foundry IQ が、人、データ、組織の知識を扱う）と外側（Web IQ が、市場、競合、顧客など外の世界につなぐ）で、これらは Microsoft IQ の一部である。企業の意思決定は両方の理解に依存する、と説明しています。

### 5.4 AI から見た自社ビジネスと Clarity の位置づけ

Brian 氏は視点を企業に戻します。Web IQ は、世界の情報を AI システムに取り込み、エージェントがそれを使って質問に答え、選択肢を比較し、推薦します。ところで AI アシスタントは、顧客が自社の Web サイトを訪れる前に、自社製品や競合製品を評価して推薦しているかもしれません。自社が判断の場に登場しているか、AI が自社についてどんな情報を見つけているか、推薦されているのは自社か他社か、という問いです。そこで **Microsoft Clarity** が、AI 体験の洞察をビジネスに戻してループを閉じます。「Web IQ は AI が自社を理解する手助けをし、Clarity は自社が AI にどう見えているかを理解する手助けをする」と整理されています。

### 5.5 エージェントはどのようにブランドを見つけ、評価するか（Dave 氏）

Dave 氏は、エージェントが企業を見つけるとき 3 つのことをする、と説明しています。

1. **見る（読む）**: エージェントは構造化データを好む。製品、サービス、ブランド、ストーリーの価値を、読み取れる形で公開する必要がある。単純なテキストで、詳細の深さまで伝わるようにする。エージェントが見られないものは、読めず、検討されず、処理されない。**エージェントをブロックしていれば、店は事実上閉まっている**。
2. **考える**: 読み終えると、疲れも怠けもせず、顧客レビュー、競合、製品フィード、ソーシャルでの話題などを調べ、ユーザーのためにより良い仕事をする方法を考える。そのため、ブランドは消費者の口の端にのぼり、自社サイト以外の場所でレビューされ、語られる必要があり、ブランドマーケティングが「ルネサンス」にあると述べています。
3. **推薦する（三角測量）**: 人間と同じように、エージェントは「企業は何を主張しているか」を見たうえで、それが真実かを照合する。

例として、サステナビリティのマーケットリーダーであると主張し、2019 年のブログ記事で B Corp 認証を取得したと書いている企業が挙げられました。人間なら信頼できそうなサイトだと思うかもしれません。エージェントは、整理されたテキストを読んだうえで Reddit や製品フィードを確認し、2019 年のブログ記事が更新されていないと気づきます。そして、この主張をした会社が本当に存在するのか分からず、見つからない、消費者に共有しない、と判断する、という筋書きです。ここから、**自社のブランドとストーリーを自社だけではコントロールできず、裏付け（corroboration）が必要**だと述べています。

### 5.6 Microsoft Clarity の AI visibility

Dave 氏が関わるブランドは、「何が起きているのか」「どう表現されているのか」「どう改善できるか」という 3 つの質問をしてくると言います。これに対する答えとして、Clarity（Dave 氏は「Clarity」に「明確さ」の意味をかけて紹介しています）が紹介されました。

- Clarity は無料の行動インテリジェンス製品で、すでに **300 万以上のサイト** で使われ、増え続けている。
- 当初は、人間がサイトをどう体験するかを見るヒートマップとセッション録画の分析プラットフォームだった。
- 今回、AI visibility のレポートが追加され、**エージェントが自社をどう体験するか** が分かる。AI クローラーがサイトにどうアクセスするか、コンテンツがどのトピックに使われているか、競合が自社の代わりに選ばれている箇所はどこか、を示す、この種で初の製品と説明されている。
- 多くの人はこの種の質問に答えるツールにすでに料金を払っているかもしれないが、目標は **AI visibility を有料機能ではなく基本機能にする** こと。

#### 用語: grounding queries と query fan out

消費者が LLM に grounding が必要な質問をすると、LLM はそれを複数のクエリに変換して grounding サービス（Web IQ）に送ります。これが **query fan out** です。Web IQ は、そのクエリのコンテンツを取得・ランク付けし、短い、または長いテキストのスニペットを LLM に返し、LLM がどれを使って回答を組み立てるかを決めます。

#### Citation ダッシュボードの用語

| 用語 | 意味 |
| ---- | ---- |
| Citations | grounding クエリへの応答として Microsoft が表面化したコンテンツを、AI が使うこと。実際に引用されているページが分かる |
| Share of authority | 同じクエリに対する全引用のうち、自社サイトが占める割合 |
| AI referral traffic | 総トラフィックのうち AI 経由の割合。ほぼ常に小さいが増加しており、コンバージョンなどの価値では比重以上に効く、と述べている |
| Branded | 買い手が社名で尋ねる場合。発見の「チートコード」だが、獲得しなければならない。branded の定義は設定できる |
| Non-branded | カテゴリー（高級車、ハイキングブーツなど）を尋ねる場合。権威として認められる必要がある |

画面の右側には実際の grounding クエリが表示され、中央にはトピックごとにまとめられ、円グラフの下に branded と non-branded の内訳が示される、と説明されています。

### 5.7 エージェントトラフィックの増加と Agent activity ダッシュボード

Dave 氏は、最近の 3 週間で agentic sessions が **88% 増えた** と紹介しています。例として、運転免許を取る娘の DMV 予約の監視や、父親を連れて行くスプリングトレーニングのサイトの監視を、エージェント（Muse など。名称は音声認識の都合で確定できません）に任せている話を挙げています。

エージェントが自社サイトで行き止まりになれば、機会を失います。Clarity は、エージェントが実際にサイトで何をし、どこで詰まるかを初めて示します。また、エージェントがまだ行っていないかもしれないタスクをシミュレーションできます。

Agent activity ダッシュボードの上部には、次が表示されます。

- agentic sessions の数
- それが人間とエージェントの全トラフィックに占める割合
- クリックまたは **smart event** を含むセッションの割合（smart event は Clarity が割り当てるもので、エージェントが何かを達成しようとしていたことを示す）

### 5.8 好循環（Clarity、GEO、Web IQ）

Dave 氏は、Web IQ と Clarity で作ろうとしている好循環を次のように示しています。どこからでも始められますが、Dave 氏は Clarity から始めます。

1. **Clarity**: 現状と理由についての洞察を与える。
2. **GEO（generative engine optimization）**: 洞察に基づいて行うこと。コンテンツの変更や、カテゴリーで不足していた場合の新しいコンテンツの作成など。
3. **Web IQ**: grounding として、その成果を、世界最大級の LLM や多くの企業を含むシステムに取り込み、増幅する。Microsoft だけのものではないと述べています。

3 つの Web がある今、これは常に変わる動的な領域で、システムは継続的に変化に追随する必要がある、というのがここでの結論です。

### 5.9 Q&A

**Q1. Web IQ で grounding クエリの結果をランク付け、あるいは信頼する情報源を選べるか（FAA や FlightAware と United の情報が食い違った例）**
登壇者の回答は 2 点です。まず、Web IQ は関連性を考慮し、さまざまな情報源を提供し、ランク付けも行います。次に、特別な、または既知の情報源に絞り込む機能として、Ignite で発表した **Scopes** があります。Web IQ の web インスタンスなどで、含めるドメインを最大 10,000、除外するドメインを最大 10,000 まで指定でき、除外は常に include より優先されます。

**Q2. Clarity はエージェント自体の記録も含む同じ製品で、まだ無料か**
登壇者は「そうです。無料です」と答えています。Clarity は、GA のような分析プラットフォームに追加できる無料ツールで、ヒートマップやセッション録画を提供していました。Web IQ を始めてデータが入ってくると、人間の Web とエージェントの Web を組み合わせられると考え、エージェントの活動を Clarity に加えたとのことです。Clarity の AI visibility は「上流（AI の段階）」、次に AI がサイトに来る段階、最後に人間が来る段階、という流れで捉えられると説明しています。QR コードからリンクに行き、帰宅途中にインストールすれば、帰宅するころには自分のドメインに関連する grounding クエリが見られる、無料で「後悔のない」選択だ、と述べています。

**Q3. ChatGPT のように AI 内で広告が出始めているが、Clarity でどう扱うか**
登壇者は、まだ初期段階だと答えています。Clarity の現在のレポートは、citation（LLM が回答に使い、ビジネスを引用したもの）と、agent analytics（ChatGPT や Copilot の内部ではなく、自社サイトに来るエージェント）です。

Clarity に追加すべきものは多いとしたうえで、例えばコマース関連で、価格オファーを（広告かどうかを問わず）消費者に出したときのクリックやエンゲージメントを見られるようにするのは論理的だと述べています。質問者が挙げた広告との連携も関心のある領域ですが、まだ提供されていないという回答です。

質問者は、広告が増えるとオーガニックの結果が排除されるのではと懸念を述べました。これに対し登壇者は、他社のことは言えないとしたうえで、Copilot の広告についての Microsoft の核となる原則は「**広告はオーガニックに影響を与えない。表示される場合は明確に区別される**」ことだと述べています。信頼を壊すことが、この波を壊す最も早い方法の一つだとも述べています。

**Q4. Commerce のような専用エンドポイントと、汎用 Web をいつ使い分けるか（開発者向けの助言）**
Brian 氏は、Web、image、video、commerce と多数のエンドポイントがあると答えています。製品についてのクエリを web に送っても製品は返りますし、レビューや評価など幅広い情報が欲しい場合は web も使えます。commerce に直接送れば、特定の製品、価格などの詳細な情報、web より多様な店舗が返ってくる可能性があります。もう一つ、**Auto** というエンドポイントがあり、適切なエンドポイント（複数も可）を選び、1 回の呼び出しで LLM に情報を返します。デフォルトの高速版と、エンドポイントを複数回反復して情報を集める、より高度な版の 2 種類があります。詳細とコード例は、翌日の別セッションで説明するとのことです。

Q4 の回答に続けて、別の登壇者が、質問されていないがと前置きして、マーチャント向けの助言も加えました（話者は文面から特定できません）。マーケットプレイス（Microsoft、Google、Meta など）に送るフィードは、これまでも一定の品質と深さがあったが、今は **できるだけ広く深くすることが極めて重要** です。例として、エアコンの在庫が近所の店にあることを知ることが重要で、在庫のような情報は追加作業でリアルタイムに反映できます。価格やレビューも頻繁に変わるため、両者は連動します。

**Q5. データはどのリージョンに保存されるか（欧州からの質問）**
登壇者は、EU のデータ主権のニーズを認識しており、**EU 専用エンドポイント** を用意していると答えています。これを呼び出すと、GDPR の観点で、送ったデータはすべて EU 内に保存されます。北欧と南欧に複数のデータセンターがあり、使うかどうかは選べます。使わない場合は、事業継続の観点も含めて全世界のデータセンターを利用します。使う場合は、データと呼び出しを欧州内に保てます。

**Q6. データの保持期間やリテンションポリシーは定義できるか**
登壇者は、2 つの選択肢があるとして、**ZQL（zero query logging）** を挙げています（綴りは音声認識の都合で表記が確定できません）。ZQL を使うと、送ったクエリを保存しませんが、システムがそのお客様のシステムについて学習を続けないというトレードオフがあります。使わない場合は、クエリは時間とともに集約され、個々のクエリは見ず、例えば「iPhone 18 Pro が昨日の朝に 400 万回検索された」といった集計的な情報を保持します（例示として語られた数字です）。最終的に消えるのは、13〜18 か月ほどの間とのことです。規制産業などで必要なら前者を選べる、と説明しています。

## 7. 注意点・発表者の気付き

- エージェントをブロックしていると、店は事実上閉まっているのと同じ。
- 自社サイトの主張は、エージェントがレビュー、Reddit、製品フィード、返品などの消費者行動と照合する。古い記述（例: 更新されていない 2019 年のブログ記事）が残ると、信頼されない可能性がある。
- Clarity の AI visibility は始まったばかりで、広告との連携や、価格オファーへのクリックの把握といった領域は「まだ提供されていない」と述べられている。
- Web IQ の ZQL を使うと、クエリは保存されないが、そのお客様のシステムについての学習も進まないというトレードオフがある。
- Auto エンドポイントの詳細は、時間の都合でこのセッションでは扱われず、別セッションで説明されるとのこと。Q&A の他の回答にも、別セッションで詳しく扱うという言及がある。

## 8. 利用者にとっての利点

- **AI visibility が見える**: 自社の引用状況、grounding クエリ、branded／non-branded、agent の行動を無料の Clarity で確認できる。
- **エージェント向けの修正点が分かる**: 失敗したタスクの原因と推奨される次のステップが示され、次に来るエージェントがタスクを完了できるように直せる。
- **情報の鮮度と深さの確保**: Web IQ による grounding で、最新の価格、オファー、在庫などをエージェントに提供でき、Web IQ Commerce は 400 億を超える製品オファーにアクセスできる。
- **情報源の制御**: Scopes で、含めるドメインと除外するドメインをそれぞれ最大 10,000 まで指定できる。
- **データ要件への対応**: EU 専用エンドポイント（GDPR 対応でデータが EU 内に保存）と ZQL（クエリ非保存）がある。

## 9. まとめ

AI アシスタントとエージェントが購買判断に関与し、すでにインターネットのトラフィックの 3 分の 2 以上が人間ではない中で、ビジネスには「見られ、推薦され、選ばれる」ことが求められます。Web IQ は、エージェントに最新で詳細な現実世界の情報（Web、ニュース、画像、動画、places、weather、commerce など）を提供する grounding サービスです。Clarity は、AI がどのように自社を引用し、エージェントが自社サイトで何をし、どこで詰まるのかを無料で可視化します。エージェントは構造化データを読み、外部の情報で裏付けを取って推薦するため、自社サイトの情報、第三者の評価、更新状況をそろえることが重要です。Clarity で洞察を得て、GEO で改善し、Web IQ で広げる循環を継続的に回すことが、発表の結論です。
