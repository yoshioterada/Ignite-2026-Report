# BRK299 Give agents and people the business context to act with Work IQ

## 1. はじめに

このセッションは、Work IQ が「Business Apps」（Dynamics 365 などの CRM / ERP や Power Platform のカスタムアプリ）のデータとアクションも扱えるようになったことを、デモ中心で紹介する発表です。メールや Teams の情報だけでなく、基幹業務のデータにも Copilot やエージェントが最初の日から届くようになります。登壇者は「スライドよりデモの方がずっと多い」と最初に断っており、架空の製薬会社を舞台に、営業担当者の 1 日と、自動化されたワークフローまでを順に見せています。

押さえておきたい点は次の 3 つです。

* Work IQ の Business Apps 対応（Dynamics 365 とカスタムアプリ）は、このセッションの日に**一般提供（GA）**になったと告知された。
* 業務の文脈を与える仕組みとして、**セマンティックモデル**と**ビジネススキル（business skills）**がデモされた。どちらも GA。
* Agent 365 による管理（観測、ガバナンス、セキュリティ、コスト）とライセンスの考え方まで説明された。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/BRK299](https://ignite.microsoft.com/en-US/sessions/BRK299)

冒頭で、James 氏は「Carmen」というたとえを使いました。社内の誰もが頼る、20 年勤めて何でも知っている人です。Carmen は誰が何を担当しているか、仕事がどう進むか、どのコンテキストを引くべきかを知っています。一方、AI エージェントには 20 年かけて学ぶ時間はありません。エージェントを作って自動化を進める側が求めているのは、20 年ではなく 20 日以内に価値を出すことだ、とも話しています。**エージェントにも初日から Carmen と同じ文脈を持たせられるようにしたい**というのが、発表の中心の考えです。

2. 作りたいのは 1 つのエージェントではなく多数であり、ソリューションを 1 つずつ個別にカスタマイズするとスプロール（乱立）と管理コストが膨らむ。
3. システム全体が、Carmen のように時間とともに**学習して改善**してほしい。

また、ビジネスプロセスは一直線ではなく、複数の関係者（営業担当、プランナー、財務の承認など）が受け渡す「リレー」であり、コンテキストが端から端まで流れ、ビジネス上のガードレールも維持される必要がある、と説明しています。

## 5. 発表内容の詳細

### 5.1 Work IQ と Business Apps の位置づけ

James 氏は、Work IQ を「アプリケーションでの仕事の進め方と、従業員や自動化が使う新しい Copilot・エージェントの層との間を埋めるもの」と説明しています。過去 10 年間に Dynamics 365 やカスタムプロセス自動化（Power Platform）へ投資してきた資産の**コンテキストとアクション**が、Work IQ で使えるようになりました。この日に Julie 氏のブログが公開されたとも紹介されています。

### 5.2 Julie 氏の事例シナリオ：Caldova

舞台は架空の製薬会社 Caldova で、人気の製品は Caldovax です（製品名の綴りは音声認識の都合で揺れており、確定できません）。以降のデモは、営業担当者（account manager）とそのチームが、Copilot を初日から使い、さらに自動化されたエージェント型のワークフローで仕事が回る様子を示しています。

営業担当者の 1 日は、販売データ、商談とアカウント、財務のシステムなど多数のタブを行き来する状態です。セッションが切れて、やり直すこともあります。サプライヤー選定の考え方についても、同僚と話すために知っておく必要があります。これを「Copilot だけで済ませられる」というのがデモの出発点です。

### 5.3 Work IQ の 3 つの利点（Julie 氏）

Work IQ は自分のためだけでなくエージェントのためのものです。Copilot Studio のエージェント、GitHub Copilot で作るエージェント、カスタムエージェントのいずれからも使える、エージェント構築のプラットフォームだと説明されました。Work IQ 上で作る理由として、3 つが挙げられています。

1. **データがすでにある**：メールなどのデータが既に Work IQ にあり、そこに業務の文脈を足すだけでよい。
2. **トークンの最適化**：トークンの観点で最適化している。
3. **データは元の場所に残る**：セキュリティポリシーも含め、データを移行する必要はなく、既存のセキュリティを尊重する。

### 5.4 セマンティックモデル

デモで Julie 氏が説明した仕組みです（操作は 6 章）。

* Work IQ が「SRD」のような社内用語を理解できるのは、**セマンティックモデル**があるためです。キーワード検索ではなく、営業担当者が使っているアプリケーションに基づいて意味を理解します。
* セマンティックモデルは**自動生成**され、利用者は何もしなくてよいと説明されています。テーブルの要約、テーブル間のリレーション、ビュー（Dynamics や Power Apps で組織が作っているもの）から、メタデータを生成します。生成のオン・オフは設定できます。
* アプリにメタデータが十分にない場合は、**用語集（glossary）**で補えます。例として、SRD は「supplier review deals for Caldovax products（Caldovax 製品のサプライヤーレビュー案件）」と定義されています。
* セマンティックモデルは GA。

### 5.5 ビジネススキル（business skills）

* 業務プロセスの手順を**ビジネススキル**として符号化（コード化）し、Work IQ を理解する他のサービスからも使えるようにします。デモの例は、サプライヤー推薦とベンダー契約（award）の手順で、**22 ステップ**あり、「こんなものを誰が覚えていられるだろうか」と話しています。
* 名前と説明で構成されます。**説明は特に重要**で、オーケストレーターがユーザーの質問に応じてどのビジネススキルを実行するかを判断するのに使われます。
* ゼロから作る方法のほか、他で作ったスキルを再利用できます。**Anthropic のスキル仕様**に沿っているため、既存のものをアップロードすればビジネススキルに変換できます。
* ワークフローなどから学習して、どのようなビジネススキルが良いかを提案する新機能もあります。
* ビジネススキルは **Dataverse のレコード**として保存され、**ソリューションに対応**しているため、ALM（アプリケーションライフサイクル管理）に従えます。dev でテストして prod へ展開できます。
* セキュリティロールやセキュリティグループで共有を設定でき、編集または閲覧のみを選べます。個人に直接アクセスを与えることもできます。多くの顧客から、組織のポリシーとロジックを安全に保存して使えることが重要だと聞いている、とのことです。
* **バージョン履歴**があり、保存だけ（アクティブ化しない）にもできます。Work IQ が使うのは**アクティブなバージョンだけ**で、現在の（保存したが未アクティブな）バージョンは使われません。
* ビジネススキルも GA。

### 5.6 Copilot Studio のワークフローとエージェント

Copilot Studio の **workflows**（比較的新しい機能）を使うと、決まったステップを設定できます。デモの例では、在庫が少ないときや、大きな注文が入ったときに、サプライヤー推薦のアラートを上げます。トリガーは「商談の追加または変更」で、チェックの後に、**エージェント**を呼び出します。ワークフローがエージェントに渡すのは、トリガーされた商談（トピック）だけで、設定はほとんどなく、メッセージ 1 つとのことです。

エージェントの指示はごく単純です。サプライヤーレビューや購買契約のカバレッジなどを実行するよう伝えているだけで、**具体的なやり方は指示に書いていません**。それらは、すでにビジネススキルに保存されています。エージェントは **Work IQ tools** を通じて、セマンティックモデルとビジネススキルを使います。

同じエージェントは、対話型のチャットにも、ワークフローから自律的に動かすことにも使えます。実行履歴には、レコードを変更したことで自律的に実行された回があり、新たに大きな数量が要求されたときに複雑な分析が行われます。アプリケーションごとにつなぎ合わせなくても、1 つのワークフローで、エージェントと Work IQ に任せられるという説明です。

### 5.7 顧客の声（ビデオ）

スウェーデンで Microsoft AI の導入パートナーとして活動する企業の Andreas 氏（トランスクリプトの表記は "Andreas Alden from Mavericks Consulting"。音声認識の都合で表記が確定できません）が、ビデオで次のように語りました。

* Business Applications in Work IQ により、顧客の AI がビジネス、言葉、プロセス、専門知識を理解する。
* 例として、醸造所では、バッチをリリースしてよいかの判断に、attenuation、CIP、fermentation といった用語と、その関係の理解が必要。
* 用語集で語彙を定義し、専門知識を再利用可能なビジネススキルとして取り込める。バッチのリリース判断から品質管理の記録まで。
* Work IQ はデータにアクセスするだけでなく、セマンティックモデリングで、チームと同じように推論する。関係性を理解し、ビジネスルールを適用し、可視化やレポートを生成し、推奨の理由を説明する。

### 5.8 Agent 365 による管理（James 氏）

James 氏は、管理者向けに、Agent 365 が Work IQ のコントロールプレーンも担うと説明しています。4 つの柱ごとに次のとおりです。

| 柱 | 内容 |
| ---- | ---- |
| 観測 | Agent 365 では、エージェントと AI 自動化のすべてと、その動作を可視化できる。Work IQ 上に作られたエージェント（例：Copilot Studio のサプライヤー推薦エージェント）のトレースは、開発者が Copilot Studio で見られるほか、Agent 365 の観測ログにも含まれる。管理者は完全なトレース履歴と Work IQ の span を確認できる。Microsoft 365 の Agent 365 管理センターで利用でき、新機能として、トレースを Application Insights にエクスポートし、リアルタイムの監視に使える。監査とコンプライアンスにも対応する |
| ガバナンスと制御 | Business Apps を Work IQ で有効にする**環境**を選べ、その環境の中でも**どのアプリ**を有効にするかを選べる。Julie 氏が Agent Builder でグラウンディングに追加できたアプリの一覧は、ユーザーがアクセスできるアプリだけでなく、組織が有効にした環境に基づく。プレビュー中のフィードバックに基づく機能で、たとえば dev や sandbox 環境だけを有効にするといった段階的な展開ができる |
| セキュリティ | Agent 365 の他の部分と同様に Entra と連携し、**呼び出すユーザーの代理として認証**する。権限は昇格せず、既存のセキュリティ（デモでは営業担当者の CRM と ERP へのアクセス権）が実行時に尊重される。すでに SOC チームの承認を得たアプリケーションを、Work IQ の背後で有効にしても、そのセキュリティが適用される |
| ビジネス分析（支出） | AI の支出を把握・予測するための Agent 365 の business analytics。課金が時間とともに変動するため重要。**Work IQ は、この体験で課金・支出のプランを事前に設定していないとアクセスできない**。Biz Apps と Work IQ のテレメトリと支出は同じ体験に流れ、詳細なトレースも同じ分析体験に流れる |

## 6. デモ・手順

デモは Julie 氏が行っています。録音は音声のみのため、画面の細部は確認できません。冒頭で「2 人以外の登壇者」として、社内の何でも知っている人 Carmen を描いたビデオ（Work IQ と Copilot を紹介する広告のような映像。発表者の 1 人は、これを最初に見たのは Monday Night Football だったと話しています）が流れました。

### 6.1 1 日目：Copilot Chat（Work IQ オン）で質問する

1. Copilot で、Work IQ をオンにした状態で「Show SRD opportunities」と尋ねる。「SRD」が何かは、実はこの営業担当者と Caldova の人しか知らない。
2. Work IQ は、キーワード検索ではなく、アプリケーションに基づいて意味を理解し、SRD が supplier review deals だと分かる。Sales Hub アプリからデータを取得して表示する。引用（citation）をクリックすると、元のレコードを確認できる。
3. 調達担当の Adele に連絡するため、「Teams メッセージで Adele に送って」と依頼する。Adele が誰か、どのアカウントかを理解して、SRD 商談のリストを送るという説明だった。
4. 「これらの SRD 商談に関連する product item code は何か」と尋ねる。表示されているのは 2 件だが、1 つの商談には多数の製品が紐づきうる。内部では、商談のテーブル、製品、さらに item code を参照している。Caldovax が登場し、引用もつく。財務と運用（ERP）への参照も含まれる。CRM と ERP という 2 つの異なるアプリケーションにまたがっている。
5. 「この item code のオープンな購買発注（purchase order）を表示して」と尋ねる。item code から finance and operations の購買発注まで複数の場所に質問をルーティングするため、やや複雑で、時間がかかるかもしれないと説明したが、そのまま結果が読み込まれた。この item については 2 件のオープンな購買発注があり、引用をクリックすると finance and operations のレコードが開く。

### 6.2 2 日目：新メンバーのオンボーディング用エージェント

1. 先輩の営業担当者が、特定のナレッジに基づく Agent Builder のエージェントを作ってある、という設定。
2. 「Woodgrove とのディスカッション（Caldovax の standing order）の準備を手伝って」と依頼する（トランスクリプトには "sending order" と "standing order" の両方の表記があり、音声認識の都合で確定できません）。プロンプトには、Woodgrove が顧客であること、standing order が商談名であることは書かれていない。それでもエージェントは答えられる。
3. 仕組みを見る。自動生成されたセマンティックモデルがいくつか並んでおり、Sales Hub 用のものがある。クリックすると構成が見られる。営業担当者が知る必要はないが、メーカー（作り手）は知っておくとよい。
4. セマンティックモデルは、テーブルの要約、テーブルのリレーション、ビューなどのシグナルから生成される。オン・オフを設定できる。
5. 「Configure」から「configure table sources」を開き、opportunity テーブルを見る。そのテーブルの設定には、商談が何についてのものかの要約があり、Work IQ はそれでテーブルを使うかを判断する。リレーション（商談と製品コードなど）も理解している。
6. さらに下へ進むと、supply review deals（SRD）のビューがある。Work IQ はセマンティックモデルでその意味を知っており、略語についても、用語集（glossary）を設定してあるため理解している。
7. エージェントの作り方を見る。非常に単純な指示と、ナレッジとして読み込んだ **supplier selection policy（サプライヤー選定ポリシー）文書**、そして Dynamics 365 と Power Apps が付与されている。これらは、生成済みのセマンティックモデルをすべて使う。
8. 新メンバーが質問すると、裏で適切な情報（商談の商業的価値、関連する拡張リクエストなど）を取得し、ナレッジのポリシーを読んで、「このリクエストは推奨のみで処理すべき」といった回答を出す。

### 6.3 Cowork でビジネススキルを使う

1. Cowork で、先ほどと似た質問（SRD の商談、その商談の対象製品）をすると、Chat と同じ答えが得られる。Chat でも Cowork でも、どちらも Work IQ に支えられているため、答えは一貫している。
2. タスクの実行を試す。以前に始めておいた draft tender award を表示する。「下書きの award は作成されていない。保留中の権威ある入札（authoritative bid）のため、この情報は空白だが、構わず進めよう」という状況で、レコードを作成する処理を実行する（トランスクリプトでは "tender award" と "vendor award" の両方が聞こえ、表記が確定できません）。
3. 完了した結果は、下書きのベンダー award が作成・検証されたことと、ステータス、変更されたレコードを示している。
4. Cowork がこれを実行できるのは、Work IQ がビジネスアプリを理解しており、さらに「ベンダー award の作り方」の手順がビジネススキルとして符号化されているため。
5. ビジネススキルの画面を見る。上部が名前、その次が説明（オーケストレーターがどのスキルを実行するか決めるために重要）、その下が業務ロジックが書かれた指示。「recommend supplier and initiate vendor」の手順で、22 ステップあることをスクロールして見せた。
6. 共有設定のアイコンから、セキュリティロール、ポリシー、セキュリティグループ、編集または閲覧のみ、個人への直接アクセスを設定できることを示した。
7. 変更して「保存のみ」を選ぶと、バージョン履歴に、以前のバージョンと現在のバージョン（current と active）が表示される。アクティブなものだけを Work IQ が使う。保存してアクティブにするか、削除するかを選べる。

### 6.4 Copilot Studio のワークフロー

1. workflows でサプライヤー推薦アラートのワークフローを開く。トリガーは商談の追加または変更。その後にチェックがあり、エージェント（supply recommendation alert）を呼び出す。
2. エージェントの指示は単純で、やり方は指定していない。Work IQ の項目を開くと、ビジネスアプリが有効で、他の生産性アプリケーションと一緒に使われている。
3. 履歴を開き、インタラクティブなチャットでの利用と、レコードの変更で自律的に実行された回があることを示す。
4. 新しい大きな数量が要求されたときの実行結果として、複雑な分析が行われていることを示す。

## 7. 注意点・発表者の気付き

* **ビジネススキルの説明文は重要**：オーケストレーターが、どのスキルを実行するかを説明文で判断する。
* **アクティブなバージョンだけが使われる**：保存しただけの現在のバージョンは Work IQ に反映されない。テストでは、dev 環境でもすぐ有効化したくない場合に、保存のみにしてバージョン履歴で確認できる。
* **用語集で補う**：アプリのメタデータが不十分なときは、用語集（glossary）で意味を伝える。
* **前提となるライセンス**：Work IQ を使っても、アプリ自体のライセンス（Dynamics、Power Apps、またはペイアズユーゴー）は引き続き必要。
* **支出プランの事前設定**：Work IQ は、課金・支出のプランを事前に設定していないとアクセスできない。
* **従量課金**：Cowork、Copilot Studio、Work IQ API 経由の利用は、Work IQ への呼び出し数に応じた課金。
* **GA とプレビューの境界**：Cowork 統合と、Dynamics 365 の残りの ERP アプリは、まだプレビュー（または作業中）。

## 9. まとめ

Work IQ に Business Apps が加わり、Dynamics 365 と Power Apps のカスタムアプリのデータとアクションを、Copilot、Agent Builder、Copilot Studio、Cowork から使えるようになりました（Cowork 統合はプレビュー）。仕組みの中心は、自動生成されるセマンティックモデルと、業務手順を符号化するビジネススキルの 2 つで、どちらも GA です。

デモでは、営業担当者が 1 日目に Copilot へ質問して CRM と ERP の情報を得て、2 日目には新メンバー向けのエージェントが文脈を理解して答え、Cowork がビジネススキルに従って下書きのレコードを作成し、Copilot Studio のワークフローが商談の変更をきっかけに自律的に分析する様子が示されました。管理面では、Agent 365 が観測、ガバナンス、セキュリティ、支出の 4 つの柱で Work IQ を支えます。Copilot Chat と Agent Builder の利用は Microsoft 365 Copilot の権利に含まれ、それ以外は従量課金です。
