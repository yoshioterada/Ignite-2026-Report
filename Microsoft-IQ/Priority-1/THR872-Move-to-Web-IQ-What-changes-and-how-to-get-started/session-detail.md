# THR872 Move to Web IQ: What changes and how to get started

## 1. はじめに

このセッションは、Foundry で Grounding with Bing を使ってきた開発者が、後継の **Web IQ** へどう移行するか、移行すると何が変わるかを説明する 25 分のシアターセッションです。前半で Microsoft の登壇者が Web IQ の概要と Foundry での位置づけを説明し、後半では Microsoft パートナーの Cloudforce 社と University of Birmingham が、自社の AI プラットフォーム「Nebula One」で Grounding with Bing から Web IQ に切り替えた経験を語っています。

最初に結論を書くと、Foundry を使っている場合、**移行のために利用者がやるべき作業は発表では求められていません**。Foundry 上の Web 検索（general web search）はすでに Web IQ に切り替わっており、既存の仕組みはそのまま動き続けると説明されています。

## 3. 何に関する発表か

Web IQ は、エージェントに**最新の Web 上の根拠（evidence）と出典情報を渡す「Web グラウンディング層」**です。発表では、すでに火曜・水曜に Web IQ のディープダイブ・セッションが行われているため、Web IQ の紹介は入門レベルにとどめ、今回は「Grounding with Bing から Web IQ in Foundry への移行」に焦点を当てると説明されています。

発表の流れは次のとおりです。

1. Web グラウンディングが必要な理由と、Web IQ の概要（6 つのエンドポイントと Auto）
2. 鮮度・速度・品質とコストのベンチマーク
3. Foundry での提供状況と、Grounding with Bing との違い
4. Cloudforce 社（Nebula One）の移行プロセスと成果
5. University of Birmingham の活用状況
6. 学生の利用シーンを想定した 2 つの比較例（Grounding with Bing と Web IQ の回答を左右に並べたもの）

## 4. 発表者が伝えたいメッセージ

発表全体を通した主張は、**「Web IQ は Grounding が向かう先であり、Foundry の利用者は順次そこへ移行している。移行すれば、速度・正確さ・トークン効率が上がる」** という点です。Microsoft の登壇者は「Web IQ is where grounding is going」と述べ、Foundry 上の現行利用者をすべて Web IQ に移すと説明しています。

その根拠として、Microsoft 自身のベンチマークと、Cloudforce 社が自社プラットフォームで得た結果（12.5 倍速い Web 検索など）が示されました。さらに Cloudforce 社は、単に差し替えるだけでなく、**Web IQ の機能を生かすよう自社コードを最適化すると、さらに速度が上がる**という実体験も共有しています。

## 5. 発表内容の詳細

### 5.1 なぜ Web グラウンディングが必要か

どれほど優れたモデルにも知識の境界があります。モデルは学習した内容について推論できますが、世界は変わり続けています。昨日変わったことを尋ねても、モデルは答えを知りません。それどころか、**間違った答えを返そうとする**場合があります。

Web グラウンディングは、質問を受けたときにエージェントが Web から最新の根拠を取得し、出典とともにモデルへ渡す仕組みです。これにより、記憶だけに基づく回答から、「今起きていること」に基づく回答へ移れると説明されています。

発表では例として「Ignite の 1 日目に何があったか」という質問が使われました。モデルの学習データには発表内容が無いので、最新の報道を調べる必要があります。グラウンディング API が Web から関連する根拠を出典情報つきで取得し、モデルはそれを使って 1 日目の発表をまとめます。役割分担は次のように整理されています。

| 担当 | 役割 |
|---|---|
| Web IQ | 根拠を取得する |
| モデル | 根拠を回答に変える |
| アプリケーション | まとめ方と引用（citation）の見せ方を決める |

### 5.2 Web IQ の 6 つのエンドポイントと Auto

Web グラウンディングは、従来型の Web 検索だけを指すものではありません。エージェントが必要とする情報は、Web サイトの場合もあれば、ニュース速報、画像、動画、物理的な場所の情報の場合もあります。すでに読ませたい URL が分かっている場合もあります。

Web IQ は、これらを **web、news、images、video、places、browse の 6 つの専用エンドポイント**で提供します。それぞれ、エージェントに異なる種類の情報へのアクセスを与えます。

さらに、エージェントが検索基盤の仕組みに詳しくなくて済むよう、**Auto** という単一の入口が用意されています。Auto は上記の機能から適切なものを選び、結果をまとめて返します。細かく制御したいときは個別のエンドポイントを使い、オーケストレーションを Web IQ に任せたいときは Auto を使う、という使い分けです。どちらの場合も、目的は「回答を裏づけるのに必要な出典情報つきの関連する根拠をモデルに渡す」ことだと説明されています。

### 5.3 ベンチマーク

良い Web グラウンディングには、優れた回答、高速性、低コストの 3 つが同時に必要だという前提で、次の結果が示されました。

| 観点 | 発表された結果 |
|---|---|
| 鮮度（freshness） | 各プロバイダーが新しいコンテンツをどれだけ見つけ、回答がどれだけ最新かを比較。**Web IQ Auto が 87.5 で、テストした全プロバイダー中で最高** |
| 速度 | Web IQ の応答は **154 ミリ秒**（8 リージョンで測定）。次に速いエンジンの約 2 倍速い |
| 品質とコスト | 2,850 クエリで測定。より良い回答を、より少ないトークンで返す |

登壇者は、モデルに多くの情報を渡すことではなく、**適切な情報を渡すこと**が重要で、それがコスト面でも利点になると説明しています。

また信頼性については、Web IQ は発行元（publisher）と連携し、その意向を尊重するとしています。AI が信頼できるコンテンツに基づいて回答できるよう、詳細なコンテンツ制御（content controls）を最近発表したとも述べています。その詳細は、このセッションでは説明されていません。

### 5.4 Foundry での提供と Grounding with Bing との違い

今週（Ignite の週）から Web IQ が Foundry で利用可能になった、と発表されました。具体的には次のとおりです。

- Foundry の prompt agents における general web search は、Web IQ で動くようになった
- toolbox のサポートは「coming soon」（近日対応予定）

現在 Foundry で Grounding with Bing を使っている人への案内は明確で、**「何もする必要はありません。切り替えはすでに行われています」** と説明されています。Responses API や Foundry agents を使っている場合、その裏側はすでに Web IQ で動いています。サービスが Grounding with Bing から Web IQ へ移行する間も、既存のソリューションは動き続けるという説明です。

両者の違いについて、登壇者は次のように整理しています。

| | Grounding with Bing | Web IQ |
|---|---|---|
| 返ってくるもの | 質問すると完成した回答が返る。中身の根拠は見えない | 根拠そのもの（ランク付けされたパッセージ、タイトル、URL、タイムスタンプ）が返る。引用に使える |
| 対象 | （Web 検索のみ） | Web 検索に限らず、news、images、video、browse、places、Auto でもグラウンディングできる |
| 利用場所 | Foundry に限定 | Foundry の外からも利用可能 |

Web IQ では、どのモデルを使うか、エージェントが根拠をどう扱うかを開発者が決めます。登壇者は、より速い回答と少ないトークンにつながるとも説明しています。

**変わらない点**は 2 つです。サインインには引き続き Microsoft Entra ID を使い（トランスクリプトでは "Intra ID" と聞こえます）、課金は引き続き Azure を通じて行われます。

### 5.5 Cloudforce 社と Nebula One

ここから Husein Sharaf 氏（Cloudforce の founder & CEO）と Tim Packwood 氏が登壇しました。Cloudforce は、**Nebula One** という製品を提供する Microsoft パートナーです。Nebula One は、世界中の大学で使われている「セキュアな AI プラットフォーム」と紹介されました。数字は次のとおりです。

- 米国、カナダ、英国、EU、オーストラリア、ニュージーランドの **100 を超える大学**で利用
- 学生を含む **400 万人以上**のユーザーが利用
- 今週、Microsoft Partner of the Year（Education、グローバル）に 2 度目の選出

プラットフォームは 2 年以上前から稼働しており、当初から Azure サービスを使う設計です。Foundry の上に構築され、Cosmos、APIM（API Management）、Azure Container Apps などを使って機能を提供している、と説明されています。学生・教員・研究者は常に最新情報を必要とするため、当初から Web グラウンディングに Bing を使っていました。Husein 氏は、Bing は十分にうまく動いており今も動いているが、改善の余地は常にある、と述べています。

### 5.6 Cloudforce 社の移行プロセス

Web IQ を知ったときに、「ぜひ試したい」と考えたそうです。進め方は次の順でした。

1. **既存の検索ツール呼び出しを Web IQ に差し替えた。** プラットフォーム側の最適化は一切せずに試したが、速度・正確さ・トークン効率の面で、すぐに効果が見えた。
2. **ベンチマークを実施した。** OpenAI と Anthropic の 2 プロバイダーの 6 モデル（利用者が日常的に使う代表的なモデル）で比較し、Web IQ はすべての指標で勝った。Husein 氏によれば、その差は僅差ではありませんでした。
3. **5 つの大学パートナーでパイロットを行い、本番投入した。** 全員から好評で、特に大学は予算圧力が強く、プラットフォーム運用で最大のコストがトークンであるため、トークン効率が大きな利点になった。
4. **Web IQ の機能を生かすようにプラットフォームを最適化した。** Grounding with Bing では使えなかった機能を活用した結果、検索結果を返すまでの**レイテンシがさらに 3 倍高速化**した。

Husein 氏は、単純な差し替えにも効果はあるものの、本番に入る段階で最適化することが追加の利点を生むとして、これを推奨しています。

Auto については、これまで Web 検索を複数回に分けて、ニュース、画像、動画などを取得していたものが、Web IQ Auto では 1 回の呼び出しで済むようになったと説明しています。1 回の呼び出しにまとめると、レイテンシだけでなく、必要な情報だけを取得するのでトークン効率の面でも利点があり、繰り返し検索するループも不要になります。

現在の状況は、Web IQ がすでに本番稼働しており、**Web IQ Auto は今学期中に 100 以上の全大学で本番投入される予定**です。

### 5.7 移行を検討する人への 3 つのヒント

Husein 氏は、Grounding with Bing からの移行を考える人に、次の 3 点を勧めています。

1. **最も難しいユースケースで、Web IQ と従来のグラウンディングの両方を試す。** 「サンフランシスコの今日の天気」のような簡単な質問では、正確さにあまり差が出なかった。現実の難しい質問では差がはっきり出た（Cloudforce のテストでの結果）。
2. **既存のグラウンディングのコードを減らす。** Cloudforce の従来のコードは、ユーザーの 1 つの質問を複数の検索に分解し、結果を集約してモデルに渡し、回答を作る、というかなり複雑なものだった。Web IQ（特に Web IQ Auto）によって、そのうち **90% を削除**できた。開発者の保守するコードが減り、今後の保守コストも下がる。
3. **総所有コスト（TCO）を試算する。** Web IQ には、他の Web グラウンディングと同様に 1,000 検索あたりの料金がかかる。ただし、移行で得られるトークン効率も含めて、利用者に展開した場合の TCO で評価してほしい。

### 5.8 Cloudforce 社が得た成果

Husein 氏が示した結果は次のとおりです。

| 指標 | 結果 |
|---|---|
| Web 検索の速度 | **12.5 倍高速** |
| LLM の最初の単語が出るまでの応答 | **2 倍**の改善（"2x increase in the response in terms of generating that first word"） |
| モデルに送られる Web コンテンツの量 | **48% 減少** |
| 難しい質問に正しく答えられる割合 | 大きく向上（具体的な数値は語られていません） |

学生は「せっかち」で、「2 秒より長くかかると気が散って別のことを始める」ため、速度はユーザーの定着にも影響する、と説明されています。Husein 氏は、従来の Bing ベースのソリューションも悪くなく苦情も多くなかったと断ったうえで、今回は「はっきり測定できる形で良くなった」としています。

### 5.9 University of Birmingham の事例

Tim Packwood 氏は、University of Birmingham（英国の大規模な研究大学）の立場から話しました。雑談的な地元紹介を除いて、要点は次のとおりです。

- 英国（そしておそらく世界）の大学は厳しい財政状況にあるが、AI は大学にとって「存続を脅かすもの」であると同時に「存続に関わる機会」でもある
- Microsoft と Nebula One と連携することで、高度なエージェント型 AI を **40,000 人**に展開でき、コストは**席ごとのライセンス（per-seat licensing）の場合のおそらく 10 分の 1 未満**
- 今年前半に **2,000 ユーザー、4 か月間のパイロット**を実施。手応えを得て、全教職員と学生が**ファイルと Web の両方でグラウンディングされたエージェントを作成できる**ようにした
- エージェントの作成数は、ゼロから**月に約 1,000 件**に。そのうち約 60% はあまり良くないが、約 40% は革新的な製品・ツールになりつつある
- 信頼でき安全で、単一の場所に閉じない文脈で会話をグラウンディングできることは、教育上の大きな成果である
- 「エージェントは新しい教育リソース」であり、今後は PowerPoint やファイル、試験の代わりに、教育や研究を届けるエージェントを作るようになる
- 大学には、企業が雇いたい人材、つまり AI を使える将来のエンジニアを育てる責任がある。Web IQ を、安全で、グラウンディングされ、準拠した（GDPR 準拠の）システムに組み込んで多くの人に提供できる。利用者には非常に高度なコンピューターサイエンティストもいれば、AI に最初の質問を入力することを怖がっている歴史学者もいる
- 英国でも学費が上がっており、最大の関心事は「どうやって就職するか」。この技術を授業や日常で自由に使わせることは、将来の卒業生を育てる重要な要素である

### 5.10 比較例（Grounding with Bing と Web IQ の回答の並置）

登壇者は、学生が Nebula One でこの機能をどう使うかの典型例を 2 つ示しました。画面の左が Grounding with Bing、右が Web IQ の回答で、音声からは、並べて見せながら説明したことが分かります。画面の細部は音声からは確認できません。

**例 1：University of Birmingham の学生（大学提供の住居に住む学生）**

ルームメイトが飲み物をノートパソコンにこぼし、電源が入らなくなりました。学生は「新しいものは買えない、母には言えない（母が残業して買ってくれたものだから）」と相談します。

- Grounding with Bing の回答：電源を抜く、助けを求める、大学のヘルプラインに連絡する、といった内容で、**技術的には正しい**。ただし、大きな違いを生む情報が欠けていた。
- Web IQ の回答：**「寮（hall）の保険を確認してください」** と答えた。University of Birmingham の公式サイトに、学生に提供される保険の情報があるが、それは入れ子になった PDF の中にあった。従来は Grounding with Bing でその情報にアクセスできなかったが、Web IQ は自動でその内容を取り込み、該当箇所への**引用（citation）を付けた**。ユーザーが引用をクリックすると、公式サイトから取得した PDF に直接移動できる。

Tim 氏は、この例に関して、大学は長い年月をかけて成長しており、「デジタルが前提」という考え方で作られているとは限らないと述べています。125 年の歴史がある同大学は、5 つの学術カレッジがそれぞれ別の方向に動いており、データは様々な場所に散在しています。是正のための投資は進めているものの、Web IQ はその複雑さの上に層を重ね、従来のコンテンツ管理やレガシーシステムを、学生が簡単にたどれるようにできる、と説明しています。「Bing も良い仕事をするが、Web IQ はより良い」というのが Tim 氏の評価です。

**例 2：米国の卒業間近の学生**

SK Hynix が近くに工場を開設したと聞いた学生が、就職機会と、その工場で何人を採用・育成する予定かを質問します。

- Grounding with Bing の回答：技術的には正しいが、**育成予定のエンジニアの具体的な人数を確認できなかった**。
- Web IQ の回答：同様の回答に加えて、**育成予定のエンジニアの具体的な人数**まで示した。この情報は**韓国語のニュース記事**に載っていた。

登壇者は、外国語のウェブサイトや、従来型でない Web サイトについても、Web IQ がより包括的に検索し、**インラインで翻訳まで行う**ことを確認している、と説明しています。外国語コンテンツを取得して自前で翻訳する方法を考える必要がなくなる、という点です。

## 7. 注意点・発表者の気付き

- **Foundry 利用者の移行は自動。** 既存の Grounding with Bing は動き続けるため、何もする必要はありません。ただし、これは Foundry 上の利用者についての説明です。
- **差し替えだけで終わらせない。** Cloudforce 社は、単純な差し替えでも効果があったが、Web IQ の機能を生かす最適化で、レイテンシがさらに 3 倍高速化したと述べています。
- **評価は難しい質問で行う。** 簡単な質問では差が小さく、現実の難しい質問で差が大きく出たという経験です。
- **TCO で判断する。** 1,000 検索あたりの料金がかかることを前提に、トークン効率による削減も含めて試算することを勧めています。
- **toolbox のサポートは近日対応予定。** 現時点では、Foundry の prompt agents における general web search が Web IQ で動いています。
- Cloudforce 社は、従来の Bing も悪くなく、苦情も多くなかったと断っています。発表で示された差の例は、入れ子の PDF や韓国語の記事のような、取得しにくい情報に関するものでした。
- ベンチマークの数値の多くは、Microsoft 自身または Cloudforce 社の測定です（算出方法の詳細は発表では語られていません）。

## 8. 利用者にとっての利点

発表で語られた効果をまとめます。

- **速度**：Web IQ の応答は 154 ミリ秒（8 リージョン測定、次点の約 2 倍）。Cloudforce 社では Web 検索が 12.5 倍高速化し、LLM の最初の単語が出るまでの応答も 2 倍になった
- **トークンとコスト**：モデルに送られる Web コンテンツが 48% 減った。大学にとって最大のコストであるトークンの削減は大きな利点になった。University of Birmingham は、席ごとのライセンスよりおそらく 10 分の 1 未満のコストで 40,000 人に展開できると語っている
- **回答の質**：難しい質問への正答が増えた。入れ子の PDF 内の保険情報や、韓国語の記事にある人数など、従来は取得できなかった情報が引用付きで返った
- **コードの簡素化**：Cloudforce 社は従来のグラウンディングコードの 90% を削除でき、保守負担が減った
- **根拠の透明性**：ランク付けされたパッセージ、タイトル、URL、タイムスタンプが返り、引用に使える。選択するモデルとエージェントの動かし方は開発者が決められる
- **利用範囲**：Foundry の外でも使え、news、images、video、browse、places、Auto にも対応している
- **既存の運用が変わらない**：サインインは Microsoft Entra ID、課金は Azure のまま

## 9. まとめ

Web IQ は、エージェントが最新の Web 情報を出典つきで取得するためのグラウンディング層で、Grounding with Bing の後継です。完成した回答ではなく、ランク付けされたパッセージや URL などの根拠そのものを返す点が大きな違いで、6 つのエンドポイントと Auto を備え、Foundry の外でも使えます。

Foundry の prompt agents の Web 検索は今週から Web IQ で動いており、Foundry 利用者は何もしなくても移行済みです。Cloudforce 社の Nebula One では、差し替えだけでも効果があり、最適化でさらに速度が上がりました。Web 検索は 12.5 倍高速になり、Web コンテンツのモデル送信量は 48% 減り、University of Birmingham は 40,000 人への展開を、席ごとのライセンスよりおそらく 10 分の 1 未満のコストで行えると語っています。移行を考える場合は、難しいユースケースでの比較、グラウンディングコードの簡素化、そしてトークン効率を含む TCO の試算が勧められています。
