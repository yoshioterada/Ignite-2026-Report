# BRK468 Geospatial intelligence for industrial resilience and sustainability

## 1. はじめに

このセッションは、衛星画像や気象データなどの「地理空間（geospatial）データ」を、企業の業務データと結び付けて、リスクを事前に把握し、行動につなげる方法を紹介するものです。軸になる製品は **Microsoft Planetary Computer（MPC）** で、発表の後半では、一般提供（GA）と述べられている **Microsoft Planetary Computer Pro** が画面を使って紹介されます。

流れは次のとおりです。まず Microsoft の担当者が、地理空間データとは何か、なぜ扱いにくいのか、MPC がその課題にどう応えるかを説明します。続いて EY のパートナーが、自社のレジリエンス（resilience）ソリューションの画面を使って、洪水リスクを施設ごとに評価する例を見せます。最後に Microsoft の担当者が、同じ結果を再現可能な形で大規模に作る仕組みを、実際の製品画面で示します。「物理世界の変化が自社の資産や取引先にどう影響するか」を AI で扱いたい方に向けた内容です。

## 3. 何に関する発表か

**地理空間データ**とは、「何であるか」と「どこにあるか」を併せ持つデータです。発表では次のように整理されています。

| 種類 | 説明 |
| --- | --- |
| ベクター（vector） | 建物の位置や外形、道路のルートといった、地図上の点・線・形 |
| ラスター（raster） | 衛星画像のように、地球の一部をピクセルの格子として表したもの |
| 気象データ | 特定の場所・時間に何が起きたか、またはどんな状況が予想されるか |

どんな事業もどこかで動いており、電力会社なら地域全体の送電線、穀物会社なら畑やサイロや鉄道、都市なら道路や配管や建物を持ちます。嵐、洪水、熱波、火災などの影響を受けるため、どの資産が影響を受けるか、どの業務が止まりうるか、どこで行動すべきかを知るために「場所」が事象と事業をつなぐ、という説明です。

1. 地理空間データの基礎と、扱いにくさ（形式、結合、解釈）
2. Microsoft Planetary Computer の仕組み（取り込み、カタログ化、API、既存ツールとの連携）
3. See / Understand / Predict / Act の 4 ステップ
4. EY のレジリエンス・インテリジェンス・ソリューション（画面を使った紹介）

6. まとめ（得られる利点）と Q&A

## 5. 発表内容の詳細

### 5.1 地理空間データが扱いにくい理由（Yves 氏）

ビジネスのテーブルと比べて、地理空間データは次の 3 点で扱いが難しいと説明されました。

1. **形式が違う**：衛星画像はピクセルの格子、送電線は形状、センサーは測定値を継続的に流し、天気予報も別の形です。多くの場合、これらをまとめるには異なるツールや処理の層が必要になります。
2. **結合のしかたが違う**：ビジネステーブルなら顧客番号で注文と顧客を結合しますが、地理空間データは多くの場合「場所と時間」でつなぎます。例えば「この洪水区域にどの資産があるか」「今後 72 時間で自社の業務や資産に何が起きるか」を知るには、場所と時間の概念が必要です。
3. **意味づけが難しい**：衛星画像には何百万ものピクセルがあります。小売店の駐車場の車の数を数えて季節ごとの活動を測る場合を例にすると、画像を処理し、AI モデルで車を見つけて数え、さらにマーケティング、営業、運用のテーブルと結合する必要があります。

### 5.2 Microsoft Planetary Computer の仕組み

MPC は、数年前に始めた投資です。顧客、業務、資産についてはすでにコンテキストがありますが、資産を取り巻く物理世界が欠けていることが多いため、MPC が「地理空間コンテキスト（物理世界のコンテキスト）」を提供します。構成は 3 つの部分です。

| 部分 | 内容 |
| --- | --- |
| 取り込み（ingest） | 気象の測定値、衛星画像（NASA、NOAA、European Space Agency の公開画像）、ベンダーから調達した商用データ、ドローンや動画で収集した自社データ、現地調査や資産の位置情報を 1 か所に集める |
| カタログ化 | データを処理し、場所と時間で整理して、「特定の時間・場所で何があったか」を検索できるようにする。Azure のサービスであり、顧客のテナントで動き、コンプライアンス、ガバナンス、監査、セキュリティ、ロールベースのアクセス制御に従う |
| API | 画像を探すだけでなく、画像から指標や統計（例：植生指数）を取り出す API を提供する。AI との統合もあり、AI ワークフローを載せてオブジェクトの検出、地図の作成、コンピュータービジョンのモデルを使える |

出力は多くの場合、**GeoParquet または Delta 形式**です。MPC はバックエンドのサービスであり、ユーザーは普段のツールを使い続けられるからです。

- データエンジニア：Fabric、Fabric Map、OneLake を使い続ける（Delta 形式でエクスポートされるため接続できる）。Databricks も同様。
- AI の担当者：モデルを Foundry に置く。MPC は API で Foundry と連携する。
- GIS ユーザー：Esri の ArcGIS やオープンソースの QGIS などと連携する。

変わるのはユーザーインターフェースではなく、**カタログ化され、日々の問いに答えるよう最適化された構造化情報（コンテキスト）にアクセスできる**点です。そのうえで、リスクとレジリエンス、サプライチェーン、資産、運用などのビジネスアプリケーションにつなげられます。ビジネスユーザーは、地理空間の専門家でなくても地理空間に関する質問ができる、とされています。

### 5.3 See / Understand / Predict / Act

Copilot、エージェント型のアーキテクチャ、各種ツールのいずれで問い合わせても、処理は次の 4 ステップで共通すると説明されました。例として、テキサスの電力会社に嵐が近づくシナリオが使われています（送電線と変電所を持ち、「嵐がどこにあるか」ではなく「どの資産が嵐にさらされるか」を知りたい場合）。

1. **See（見る）**：天気予報などの情報を得る。衛星画像で送電線や変電所沿いの植生を評価し、リスクが高い箇所を調べることもできる。
2. **Understand（理解する）**：資産や変電所ごとにテーブルに入れ、API を実行して「この変電所は、植生指数が平均より高く、その地域の天気予報のリスクも高いので、リスクが X%」といった、資産ごとの統計の表を作る。
3. **Predict（予測する）**：嵐やハリケーンがどこへ向かうかを予測する。Foundry にはすでにいくつかのモデルが公開されており、その 1 つが **Aurora**。AI の気象モデルで、同時に多数のシミュレーションを実行できる。出力は、コンテキスト内の資産情報と結合される。
4. **Act（行動する）**：Power BI、Fabric、自社のエージェントアーキテクチャなど、すでに使っているツールにシグナルを送る。業務が止まりそうなら、先回りして対応できる。

どのシナリオでも同じで、エネルギーのほか、食品・飲料や公共部門などが例として挙げられました。山火事、台風、ハリケーンなど、世界で実際に起きている事象も例示されています。

### 5.4 EY のレジリエンス・インテリジェンス・ソリューション（Luke 氏）

Luke 氏は、EY は数年にわたり Planetary Computer と取り組んできたと述べ、サプライチェーン、リスク、予測などの業務に新しいデータをもたらすと説明しています。

#### 背景：資産を単独で見ない

資産と聞くと港、オフィスビル、工場のように目に見えるものを思い浮かべますが、それは物理世界と周辺の環境とつながっています。見るべきは次のような点です。

- 電気、水、通信、交通の拠点
- サプライヤー
- 従業員（どこに住んでいるか）、周辺のコミュニティ

サプライチェーンは、ジャストインタイムの物流、サプライヤーの統合（数の減少）によって、よりスリムになっています。気候と環境のリスクはより深刻で頻繁になっています。一方で、衛星やセンサーは毎日、地球規模でデータを集めており、AI も観測データを大規模に処理できるようになりました。土地の分類だけでなく、変化の検出や測定、天気の予測も、以前より速く精度が高くなったと述べています。

見た目は問題のない施設でも、システム全体にストレスがかかったときに運用と経済的な成果がどうなるかが重要です。道路が塞がれて作業員が資産にたどり着けないか、電力は届くか、想定していなかった 100 年に 1 度の洪水区域にないか、といった点です。長年冠水しなかった場所に産業施設が建てられたが、誰も把握していなかった洪水リスクが、深刻な気候事象で突然現実になった、という顧客の例も挙げられました。

#### 画面を使った紹介

EY が顧客に提供しているのが、**resilience intelligence solution** です。次の点が語られました。

1. 多くのリスクダッシュボードは、地図に危険度を重ねたハザードのダッシュボードだが、ここでは**事業が気にすること**に焦点を当てている。
2. ある組織の 42〜43 か所の施設一覧のなかから、1 か所が突出していることが画面に出ている。
3. ダッシュボードには、気候ハザードだけでなく、**運用への影響と財務への影響**も表示される。
4. 施設の周囲の様子が見える。近くに川があり、道路があり、作業員が住んでいるかもしれない開発が見える。
5. Planetary Computer 経由で、洪水マップや洪水の深さ（flood depth）を、EY が顧客のデューデリジェンスや投資判断に使う既存のリスクモデルに取り込んでいる。
6. 施設周辺のピクセルにズームインすると単独では問題なさそうだが、ズームアウトすると、運用を妨げうるリスクが見える。
7. 道路との交差が多く、メンテナンスの担当者がたどり着けるか、水道や電力が影響を受けるかが問題になる。
8. Sentinel 2 のデータに切り替えると、都市の成長が見え、将来は浸食（erosion）が要因になるか、今投資すべきことがあるか、という問いが出る。
9. 運用データ（性能、出力、依存するサプライヤーやリソース）も表示される。これらは顧客がすでに持っている企業データである。

Luke 氏は、持ち帰ってほしい点として、**地理空間データをビジネスデータと一緒に動かすのは非常に難しく、Microsoft Planetary Computer Pro がそこを解決している**ことを挙げています。これは複雑なデータエンジニアリングを使わずに実現できる初めての方法だという趣旨です。

#### Resilience Capital

Luke 氏は、**resilience capital** という考え方も紹介しました。プライベートエクイティ、ポートフォリオ、電力会社、データセンター、製造業などは巨額の資本を投資しています。資産だけでなく、周辺のシステムへの投資（コミュニティへの投資、資産を囲む防護壁の設置、道路の強化など）も重要です。レジリエンスの知見は、資本の意思決定を改善できます。具体的には、次の領域です。

- 価値の保護と創出
- 介入策の特定
- レジリエンスの定量化
- 資本の配分

Resilience Capital は、資産、組織、周辺のコミュニティを守る投資を、創出または維持することの経済的便益を測るインテリジェントなプラットフォームだと説明されています。長期的な影響と、損失につながる混乱とを比べた財務判断を後押しします。

### 5.5 Microsoft Planetary Computer Pro（Nora 氏）

Nora 氏は、Luke 氏が示したのは 1 つの施設のレジリエンスとその価値であり、EY がその施設が洪水に遭ったことをどう知ったのか、そしてそれを全施設で、条件が変わるたびに繰り返すにはどうするのか、という問いから始めました。それを担うのが Planetary Computer Pro で、ソリューションをスケーラブルで再現可能にするものだと位置づけています。

Planetary Computer Pro は「物理世界のインテリジェンスのためのプラットフォーム」で、次の 3 つの価値があるという説明です。

1. **物理世界のデータを 1 か所に集める**：衛星画像、地形データ、天気予報、組織自身のサプライヤーや施設の位置情報を、常に最新で一貫した 1 つのガバナンス付きカタログに集める。
2. **生の観測を「意思決定レベルのシグナル（decision grade signals）」にする**：独自のバージョン管理された手法（methodology）を作成でき、ルーチンのジョブを希望の頻度でスケジュールでき、1 回の実行で全拠点を対象にできるスケールがある。得られるすべての値には実行 ID（run ID）が付き、その値を、元の実行まで追跡できる。
3. **ビジネスがすでに動いている場所に、物理世界のシグナルを AI として届ける**：Fabric への OneLake ショートカット、Foundry のエージェント向けの MPC Pro ツールを提供する。

#### 製品画面での紹介（語られた順）

- 物理世界の観測の例として、**2025 年 12 月の Snoqualmie Valley の洪水**を、厚い雲の中でも見通せる**レーダー画像**で示した。
- この画像から、Contoso の **12 か所の拠点すべて**について洪水エクスポージャーを計算した。結果は 1 拠点につき月ごとに 1 行のテーブルになる。
- Earth AI のモデルも、同じ種類の物理世界のデータを使って同じプラットフォームで動き、出力は同じテーブルに入る。Yves 氏が説明した Aurora（AI の天気予報）が例である。
- 物理世界のデータから取り出したシグナルは、ビジネスデータと並んで同じテーブルに載る。画面には Contoso の収益と施設、レーダー画像から計算した洪水エクスポージャー、地形データから得た標高の情報、Aurora による降雨予報が並んでいる。
- これらを合わせると、**標高が低く、昨年洪水に遭い、今後も大雨の見通しがある拠点が 4 つ**あることが分かり、ウォッチリストの作成に使える。
- 洪水エクスポージャーの値をクリックすると、その手法、設定、背後にある **10 枚の衛星画像（scene）**が表示される。これにより、エージェントが根拠として引用でき、人間も計算の各ステップを遡れる。

> 補足：画面の細部（UI の配置など）は音声からは確認できません。上記は、語られた範囲のみです。

今後の拡張として、地球に関する測定値を専門的な用語ではなく**平易な言葉で呼べる**ようにし、あらゆる AI エージェントが標準的なツールを通じてそれらの測定値にアクセスできるようにする、と述べられました。

### 5.6 まとめとしての整理（Nora 氏）

どの組織も物理世界のどこかで動いており、そこで起きることが資産、顧客、サプライヤーの成果に影響します。サプライヤーの工場が洪水区域にある、配送ルートが山火事で寸断される、木が送電線にかかる、作物の収量が伸び悩む、といった例が挙げられました。データは存在しますが、グリッドやピクセルで、場所ごとに整理されていて、事業の意思決定の単位になっていません。また、リスクはフェンスの境界で止まらず、水、エネルギー、交通、サプライのシステムを通じて伝わります。

このため多くの組織は、**「周囲で何が変わっているか」「自社にどう影響するか」「どこで行動すべきか」**という問いにまだ答えられていません。Planetary Computer Pro は、企業のための地理空間コンテキストとして、物理世界のデータをまとめ、意思決定レベルのシグナルにし、Fabric、Foundry、チームが使うツールに届けます。EY のようなパートナーは、レジリエンスの方法論、業界の専門知識、経済モデルを加えて、シグナルを判断に変えます。同じアーキテクチャは、嵐に備える電力網、グローバルなサプライヤーを管理する食品会社、重要インフラを守る政府にも当てはまると述べられました。

### 5.7 Q&A

| 質問 | 回答の要点 |
| --- | --- |
| Azure Maps と組み合わせて地図に描画できるか | 「Yes and no」。Fabric Map とネイティブ統合があり、その基盤は Azure Maps と同じプラットフォーム。Fabric Map から MPC の API を呼び出して、ラスタータイルを直接可視化できる |
| （TomTom の参加者からのコメント）AI が地理空間データと連携するには、データを理解しやすくするオントロジーが重要。TomTom は Fabric で OneLake 上のカタログとして提供できるよう取り組んでいる | 参加者は、このデモのデータに安定した ID が付けば、統合しやすく読みやすくなるとも述べた。登壇者は、方向性が合っており、すでに Fabric とともに予備的な取り組みを進めていると応じた。参加者は翌日の関連セッションにも言及した（時刻は聞き取りが不明瞭で確定できません） |
| Esri と競合するのか。置き換えか、クラウド上で同様の GIS 機能を作る計画か | 競合しておらず、今後もそうならない。Esri は高度に専門化された強力な GIS ツール。Planetary Computer は、より下位の層に位置し、専門的な GIS ではなく、AI とデータのプラットフォームとして、Esri のような専門機能をプラットフォームに取り込む。MPC はバックエンドのサービスで、GIS ユーザーは ArcGIS などを、Fabric・OneLake ユーザーは Fabric Map などを、使い慣れたツールのまま使える |
| Azure ポータルで見つけられ、エンタープライズデータや Foundry と接続できるか | 完全な Azure サービスで、ほかの Azure サービスと同じデプロイ手順。Azure portal で扱える |

| 価格と課金のメーター | データ管理の GA 機能は、ストレージ型の課金モデルに近く、取り込んで保管するデータ量に対して支払う。分析と AI の前処理の機能は、現在プライベートプレビューで、価格は未公開、まだ課金していない。価格モデルは、顧客に代わって処理したデータ量で支払う、コンピュートに近い形になる。Azure の価格ページへのリンクは後で共有すると述べられた |

EAM に関する議論のなかで、EY の変革プロジェクトに触れた発言（EY からの登壇者は Luke 氏）がありました。その内容は、位置情報は SAP、Oracle、IBM などの ERP と結び付いたデータプロダクトとして扱われてきたが、位置に関する文脈（植生、天候など）はなく、天気は第三者のデータとして BI ツールやデータレイクに取り込まれてきた、というものです。Planetary Computer Pro では、新しい属性や測定値をオントロジーの位置情報に結び付けられ、リスクスコアのモデリングにも使えます。これを Planetary Computer なしで行うのは大規模なデータエンジニアリングで、通常は数百万ドル規模になりうる、という経験談です。

## 7. 注意点・発表者の気付き

- 地理空間データは、形式、結合方法、意味づけの 3 点で扱いが難しい。
- 資産を単独で見ず、電気、水、通信、交通、サプライヤー、従業員、コミュニティといった周辺のシステムを含めて見る必要がある。
- 単独では問題のないように見える施設でも、周囲まで見ると、洪水や道路の遮断などのリスクが見えることがある（EY のデモより）。
- 分析と AI の前処理の機能は、現在プライベートプレビューで、価格は未公開。GA なのはデータ管理の機能（Q&A の回答）。
- 前提条件や制約についてのまとまった説明は、発表ではありませんでした。
- ポジショニングは「バックエンドサービス」で、専門的な GIS ツールや EAM の置き換えではない（Q&A より）。
- トランスクリプトでは、Planetary Computer の製品名が MPC と Planetary Computer Pro の両方で語られています。GA と明言されたのは Planetary Computer Pro です。

## 8. 利用者にとっての利点

Nora 氏が、4 つの利点を挙げています。

| 利点 | 内容 |
| --- | --- |
| Speed（速さ） | 条件の変化に応じて常に進化する「生きたシグナル」が得られる（静的な 1 回限りの調査ではない） |
| Scope（範囲） | 資産だけでなく、その周囲のシステム全体が見える |
| Confidence（確信） | 根拠のある答えが得られ、取締役会、投資家、規制当局に対して意思決定を説明できる |
| Economic value（経済価値） | 物理世界のシグナルから、資本が守られている箇所と危険にさらされている箇所が分かり、最も価値を守れる場所へ投資を振り向けられる |

そのほか、発表では次の点が語られました。

- ユーザーは普段のツール（Fabric、Databricks、Foundry、ArcGIS、QGIS など）を変えずに使える。
- 導入してすぐに、NASA、NOAA、European Space Agency などの公開データセット（約 130 件、100 ペタバイト）を無料で使える。
- 複雑なデータエンジニアリング（Luke 氏は、通常は数百万ドル規模になりうると述べた）を使わずに、地理空間データをビジネスデータと組み合わせられる。
- すべての値に手法、設定、元の衛星画像までの記録が付くため、人間もエージェントも根拠を追跡できる。

## 9. まとめ

地理空間データは、「何がどこにあるか」を表す強力なデータですが、形式、結合、意味づけの面で扱いにくく、業務データと結び付ける作業に手間がかかります。Microsoft Planetary Computer は、データの取り込み、場所と時間によるカタログ化、API、既存ツール（Fabric、Databricks、Foundry、ArcGIS、QGIS）との連携によって、物理世界のコンテキストを企業に提供します。

EY の例では、洪水の深さや衛星データを、運用データや財務への影響と同じ画面で見ることで、施設のリスクを「事業の言葉」で捉えられることが示されました。Planetary Computer Pro の画面では、Contoso の 12 拠点について、レーダー画像からの洪水エクスポージャー、標高、Aurora の降雨予報を同じテーブルに並べ、4 つの注視すべき拠点を導き、すべての値を根拠まで遡れることが紹介されました。

Microsoft Planetary Computer Pro は一般提供されており、発表者は「自社が事業を行う場所について、まだ答えられていない問いを 1 つ選んで始めてほしい」と呼びかけています。
