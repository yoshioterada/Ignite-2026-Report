# BRK298 Bringing conversational analytics to where decisions happen

## 1. はじめに

このセッションは、Microsoft Fabric のデータを「人が普段仕事をしている場所」で対話的に使えるようにする取り組みを紹介するものです。前半は、Fabric IQ のツール群を Microsoft Copilot の Chat や Cowork、Excel、GitHub Copilot などから使う「汎用（generalist）」の体験を説明します。後半は、特定の領域に特化した「専門家（specialist）」として使える Fabric data agent の新機能とデモを紹介します。

発表の軸は、**同じ Fabric IQ の基盤（ガバナンスされたデータと同じツール群）を、いろいろな会話型の画面から使えるようにする**ことです。45 分の枠ですが、質疑応答の時間はほとんど取れませんでした。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/BRK298](https://ignite.microsoft.com/en-US/sessions/BRK298)

## 3. 何に関する発表か

Fabric IQ は、Fabric のデータ資産に含まれるビジネス上の文脈・価値・関係性を取り出すという考え方の仕組みです。発表では、その文脈が次の層から来ると説明されています。

- 運用に関するインテリジェンス（operational intelligence）の層
- ビジネスインテリジェンス（Power BI）の層
- OneLake に蓄積されたデータと文脈

これらが Fabric data agent とどう関わるか、そして data agent でどんな「特別に作り込んだ体験」を作れるかが後半の主題です。

1. Fabric IQ の位置づけと、Power BI のセマンティックモデルから始める理由

## 5. 発表内容の詳細

### 5.1 Fabric IQ と、現在 GA になっているもの

Sara 氏によると、現在 generally available なのは、Power BI のセマンティックモデルの上に作られた体験です。ツール群は 1 つの MCP として統合されており、そのツールが次の場所で使えます。

- Copilot Chat
- Cowork
- GitHub Copilot
- Foundry（作り込んだエージェントを構築する際）

前日のキーノートで、ChatGPT と Anthropic の Claude との連携が発表されたと触れられています。同じ Fabric IQ をそれらからも使える、という説明です。

### 5.2 Chat、Cowork、MCP の使い分け

Cowork はまだ新しいため、なぜ Chat と Cowork を使い分けて見せたのかとよく聞かれる、という前置きのあとで、次の整理が示されました。

| 体験 | 向いている用途・ユーザー | 補足 |
| --- | --- | --- |
| Chat | 最初に使う場所として、ほぼ全員に向く。素早い質問や分析 | M365 Copilot アプリのほか、Teams や Edge でも使える |
| Cowork | 長時間かかる非同期の作業。複雑な PowerPoint の作成、変更すべきプロセスの特定、会議の設定、確認のリマインダー設定など | Copilot アプリ内で使える |
| MCP | 技術者・開発者向け。上に何かを作りたい人 | VS Code や GitHub Copilot アプリで使う |

Sara 氏は、Microsoft では長く Copilot が複数あったが、今回は「1 つの Copilot、多くのツール」へ統合する動きだと説明しています。データへの回答を Microsoft Copilot に載せたのは、同じ Copilot を Fabric や Power BI にも持ち込み、ビジネスユーザーが回答を得る場所を 1 つにするためだと話しています。そこでは Work IQ（Teams のチャット、プレゼン、同僚との会話などの文脈）がデータに「色を付ける」ので、データと一緒に扱うことが重要だという考えです。

Power BI Copilot で要望が多かった機能のうち、memories（記憶）と history（履歴）は、この統合によって使えるようになったと述べています。

また、Power BI の顧客は様々な使い方をしているため、Microsoft Copilot や Teams だけでなく、Claude や ChatGPT からも、同じガバナンスとセキュリティの効いたデータにアクセスできるようにするという方針です。

### 5.3 Excel への展開

Excel でも Fabric IQ を使えるようにする、という説明です。多くのビジネスユーザーや経理チームが Excel で仕事をしているためです。Excel の Copilot でデータの質問ができるようになるほか、ピボットテーブルの作成ができる点が「より刺激的」な点として紹介されました。デモは 6 章に記載します。

### 5.4 Fabric data agent の位置づけと新機能（概要）

Amir 氏は会場に data agent を知っているか尋ね、かなりの人が使った経験があることを確認しています。そのうえで、data agent に入る主な改善点を次のように挙げました。

- インタラクティブなグラフの強化（テキストだけでなく見やすい可視化が欲しいという声に応えるもの）
- 高度な分析ツール
- SQL と DAX の生成の強化
- 回答の高速化と、利用チャネルをまたいだ一貫性
- 標準ランタイムで最大 1,000 行を返す機能
- ontology との連携の強化と、エンドユーザーからのフィードバックループ（この項目の説明は聞き取りが不明瞭です）
- エージェントのオブザーバビリティ

1,000 行の件は、顧客から長く要望されていた機能であり、標準ランタイムでようやく使えるようになったと説明されています。続報として、全結果を Excel ファイルとしてダウンロードできる機能も近く提供するとのことです。

また、data agent は Copilot Chat で近く GA になる予定で、日々の作業中の Copilot Chat 上で data agent と会話し、洞察を得られるようになるとのことです。

### 5.5 data agent を Fabric apps で使う

Amir 氏によると、今週 Fabric apps の一般提供（GA）が発表されました。data agent は Fabric apps と統合でき、ダッシュボードとチャットを両方備えたアプリを作れます。ダッシュボードで洞察を得ながら、data agent とのチャットでさらに洞察を得られるという構成です。近く data agent のユーザー体験からも使えるようになるそうです。

エンドユーザーが data agent をアプリ経由で使いたがる傾向があり、CLI や GitHub Copilot アプリで data agent からダッシュボードやアプリを作り、Fabric の中でも外でも共有できる、と説明されました。この機能は「今後数週間で展開を始める」とのことです。

### 5.6 セマンティックモデル設定、クエリテンプレート、トピック

**セマンティックモデルの設定。** これまで「prep for AI」でセマンティックモデルを AI 向けに準備できました。今回、data agent 側でもセマンティックモデルの設定ができるようになります。テーブルと列の選択、データソースの説明、データソースへの指示を設定できるほか、**サンプルの DAX クエリ**も与えられます。lakehouse や SQL 系のデータソースでは以前からサンプル SQL クエリを与えられましたが、DAX でも同様に要望されていたと説明されています。prep for AI の設定は無くならず、data agent にインポートして使えます。

**クエリテンプレート。** 顧客から「回答を速く、同じ質問には同じ答えを」という要望が多く、数か月取り組んできた機能だと説明されました。

- パラメータ付きの再利用可能なクエリテンプレートで、エージェントがパラメータを埋める
- 検証済みの内容がソースの中に保存される
- クエリ履歴やサンプルクエリから昇格させることも、エージェント上で直接作成することもできる
- 回答は数秒で返り、どの利用先でも同じ回答になる（ロジックの扱いに関する説明は聞き取りが不明瞭です）
- Fabric IQ でも利用できるようになる

**トピックによる大きな指示。** 指示文には文字数の上限があり、もっと多く与えたいという声があったため、トピックが導入されます。常にエージェントに送られる必須の指示と、質問との関連性に応じて動的に選択・呼び出される大きな指示（トピック）に分けられます。選ばれたトピックは推論ステップにも表示されるので、正しいトピックが使われたかを確認し、デバッグに使えます。

### 5.7 A365 との統合とオブザーバビリティ

**A365 との統合。** A365 は、管理者が場所を問わずエージェントを管理・統制する中心的な場所として位置づけられています。Fabric の data agent もこれと統合されます。

- 管理センターで、エージェントの作成者、公開者、権限、利用状況を確認できる
- Microsoft Purview で、エージェントの各アクションの監査記録を確認できる
- Microsoft Defender で、エージェントの実行やモデル呼び出しをクエリできる

これは今後数週間で、すべての本番リージョンに展開される予定です。

**オブザーバビリティ。** Amir 氏は A365 と区別して説明しています。A365 は主に管理者がエージェントの動きを監視するためのもの、オブザーバビリティはエージェントを本番に出したビルダーのためのもので、ログやトレース、エンドユーザーの質問、エラーの原因を把握して改善につなげるためのものです。

- Application Insights を設定し、そのインスタンスを data agent に指定するだけで、ログとトレースがそこに送られる
- 送信の有効化は常に管理者が制御する（セキュリティとプライバシーを重視しているとのこと）
- Azure Monitor で Application Insights のインスタンスを見たり、Foundry のオブザーバビリティからプロジェクトに接続して、ダッシュボードの作成や本番での回帰の確認ができる

### 5.8 OptiGuide、Build with AI、Foundry 連携

**OptiGuide。** 「複雑な分析」のために data agent に追加できるツールの 1 つで、すでに private preview、近く public preview になると説明されています。自然言語での最適化機能で、「なぜ」型の質問を英語の平易な言葉で尋ねられ、モデリングやコードは不要です。中断や需要変動などの what-if シナリオをオンデマンドで試せ、最適化がなぜその推奨を出したかの説明も得られます。OptiGuide は唯一のツールではなく、クエリだけでなくより複雑な分析的質問へ進むための新ツール群を追加する計画だとのことです。

**Build with AI（creator agents）。** 数か月前に出たデータエージェント構築用の機能で、顧客の反応は「圧倒的に肯定的」とのことです。今回の強化点は次のとおりです。

- ドキュメントやコンテキストを置くだけで data agent を構成できる
- 新しい構成、クエリテンプレート、トピックを生成できる
- これまで lakehouse と SQL データベースのみだった対象が、セマンティックモデルにも対応し、DAX クエリを生成できる

**行数の上限。** これまでは 25 行を超えて返してほしいという要望があり、1,000 行まで返せるようになりました。以前はプレビューランタイムでの提供でしたが、標準ランタイムでも使えます。Excel ファイルとしての全結果ダウンロードも近く提供し、Fabric、Copilot Chat、Foundry、Copilot Studio、独自アプリなど、すべての利用チャネルで同様に使えるとしています。

**Microsoft Foundry での Fabric IQ。** Foundry で独自のエージェントを作る際に data agent やセマンティックモデルを追加できます。一貫性、レイテンシ、トレーサビリティを改善し、Foundry チームと協力してエンドツーエンドのオブザーバビリティとトレースを強化したと説明されています。

### 5.9 Sara 氏のまとめでの補足

まとめの中で、Sara 氏は Amir 氏の話の中で目立たなかった点を補足しています。

- クエリテンプレートとトピックは、作成者がデータの使い方についての文脈をエージェントに渡す手段です。data agent では分かりやすいが、セマンティックモデルでも同じく価値があり、Fabric IQ を使う場面でこの文脈を活かしたいと述べています。大きな指示や、スキルのような形の指示にも対応します。
- 「専門性の低い専門家に価値があるか」という問いかけのうえで、OptiGuide や各種の構成を使うと、セマンティックモデル全体ではなく、特定の質問に必要な部分だけに絞り込めると述べています。
- デモで見たユーザー定義関数も、強力な手段として挙げています。
- オブザーバビリティは「エージェントの時代の王様」であり、A365、オブザーバビリティ、フィードバックのループが、エージェントがビジネスユーザーの役に立っているかを確認するために重要だという考えです。

## 6. デモ・手順

このセッションには、画面を使ったデモが 4 つあります。いずれも、音声のナレーションや発話で進められた範囲のみ書きます。画面の細部は音声からは確認できません。Excel のデモでは「ちょっと止めます」「再生すると」という発言があり、data agent のデモは開始時に「音声をください」と求めたうえで、ナレーション付きの映像が流れています。

### 6.1 Copilot Chat と Cowork での再ルート分析（Sara 氏）

Zava Airlines の運用担当者という設定です。Houston 発の便に問題があり、Miami への再ルートを検討するという課題が与えられます。

1. 通常は Power BI のレポートで供給状況、在庫、需要の急増を調べるが、今回は Power BI やレポートを指定せずに、課題の文脈だけを Chat に渡して分析を依頼する。
2. ソースを確認すると、普段使っているレポートが使われていた。自分の利用状況が、どのコンテンツを出すかに影響していると説明している。
3. 「約 300% の増加」という数値が、Power BI レポートの数値と一致することを確認する。Copilot が Miami は別の都市（トランスクリプトでは「Monterey」。聞き取りが確定できません）とのトレードオフと述べた内容も、同じデータで確認できる。
4. 再ルートの手順は会議やメールの中にもあるため、Work IQ に接続して、会議からデータを取り出し、次のアクションと担当者を整理するよう依頼する。
5. Cowork に切り替え、長めの非同期の作業を依頼する。同じ Power BI データと Work IQ の文脈を使い、関係者との会議の設定、アジェンダの提案、議論用のデッキの作成を求める。関係者は誰かをプロンプトで指定せず、Graph、仕事上の関係、メールから見つけさせる。
6. 結果として、会議案、見つかった関係者、アジェンダが示され、Cowork の中から送信できる。デッキも作られ、ソースが正しい Power BI データかを確認できる。

Sara 氏は、数字をレポートからプレゼンにコピー＆ペーストする時間を減らし、意思決定の枠組みを考える時間に使えることが、ビジネスを前に進めると述べています。

### 6.2 Excel でピボットテーブルを作る（Sara 氏）

1. Excel で Fabric IQ のツールを @メンション し、「ヨーロッパの IT 支出の計画との差異」という質問をする。通常どおり、適切なコンテンツを探して回答が返る。
2. 続けて「これでピボットテーブルを作って。地域と期間を見たい」と依頼する。
3. 接続されていない通常のブックから始めるが、Copilot がデータへの接続の同意を求めるポップアップ（外部データ接続を許可するか）が出る。
4. 同意するとセマンティックモデルへの接続が作られる。フィールド名は指定していない。

ピボットテーブルはセマンティックモデルに接続されたままなので、データチームがモデルを更新・更新処理すると追随します。ピボットテーブルの通常のツールも使え、Copilot の選んだフィールドが気に入らなければ変更できます。静的なファイルにエクスポートせず、ガバナンスを保ったまま使える点が強調されました。大きなフィールド一覧から何を選べばいいか分からないビジネスユーザーの出発点になる、という説明です。

### 6.3 data agent の構築・公開・フィードバック（映像のナレーション）

ナレーションの主語は構築者（ビルダー）です。後で Amir 氏が「かなり長いデモ」と総括しています。

1. data agent を、売上のセマンティックモデル（retail sales performance）と在庫の lakehouse に接続済みである。
2. 先月最も売上が多い商品を質問する。最新の完全な月は 10 月で、首位は Trail Pro 45 リットルのバックパック、売上は 80,000 ドル強。
3. 安全在庫の目標を下回る店舗と不足数を質問する。予約済みの在庫を除いた利用可能数で、Seattle downtown は利用可能 14 個、目標 30 個で 16 個不足。
4. 来週の需要予測のために、ユーザー定義関数（Python）を使う。この関数は平均日次売上と需要トレンドから期間の需要を推定し、利用可能在庫、入荷予定、安全在庫目標から発注量を算出する。
5. Tools タブでこの関数（retail demand forecast function）を追加する。接続しただけでは関数が有効にならないため、構成画面で forecast reorder を選んで有効にする。
6. 「Seattle downtown は来週何を発注すべきか」と質問する。data agent はセマンティックモデルから需要の基準値とトレンド、lakehouse から利用可能在庫と入荷予定を取得し、関数に渡す。回答は、7 日間で 54 個の発注。予測需要 50 個、利用可能 14 個、入荷予定 12 個、安全在庫 30 個を維持する前提で、入力値と関数呼び出しも確認できる。
7. 説明文を付けて公開する。説明文により、ビジネスユーザーは売上、在庫リスク、発注量について質問できると分かる。
8. ビジネスユーザーとして Microsoft Copilot Chat で「Add Content」から Fabric を選び、公開した retail demand and inventory data agent を選ぶ。
9. Seattle Downtown で先月最も売上の多い衣料品と、その利用可能在庫の安全在庫目標との比較を質問する。Summit shell jacket が 13,000 ドル超でトップ、利用可能 38 個で、安全在庫目標の 13 個を 25 個上回っている。回答に親指を上げ、コメントを付ける（回答は正しく正確）。

11. 引用を開くと、入力、計算、元のクエリが表示される。確認したうえで、予測に親指を上げ、洞察が有用だったとコメントする。
12. Data Agent Builder の画面に戻り、Monitoring でユーザーのフィードバックを確認する。Microsoft Copilot からの 2 件の評価とコメントが表示され、指示やツールの改善に使える。

Amir 氏は、構築者がエージェントを作り、エンドユーザーの手に渡し、フィードバックで指示を改善するという一巡のループを示すデモだと説明しています。質問の内容、満足度、間違えている箇所が分かるという点です。

## 7. 注意点・発表者の気付き

発表では、制約や失敗談はあまり語られていません。計画・提供時期に関する次の点が、発表で明示されています。

- CLI や GitHub Copilot で data agent からアプリを作る体験の展開は「今後数週間」
- 標準ランタイムでの 1,000 行返却は提供済み（「ついに」と表現）だが、全結果の Excel ダウンロードは「近く」
- A365 統合は「今後数週間で、本番リージョン全体に展開」
- OptiGuide は private preview で、近く public preview。ほかの新ツールは「計画中」
- data agent の Copilot Chat での GA は「近く」
- オブザーバビリティのログ・トレース送信は管理者が有効化する

また、デモでは、回答の引用や推論ステップ、ソースデータで根拠を確認することが繰り返し示されました。Sara 氏は、自分のチームが作った指標やビジュアルと、Copilot が示す洞察を照合できる点を挙げています。具体的な提供日や GA の時期（日付）は、発表では示されていません。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- ビジネスユーザーが、普段の作業場所（Copilot Chat、Teams、Edge、Excel、ChatGPT、Claude）から、同じガバナンス・セキュリティの効いたデータを使える
- 既存のセマンティックモデルの資産（リレーション、指標、権限）を、エージェント型の体験で再利用できる
- レポートから数字を転記する手間を減らし、意思決定の検討に時間を使える
- Excel のピボットテーブルがセマンティックモデルに接続されたままになり、静的エクスポートが不要になる
- data agent は、複数のデータソース（セマンティックモデル、lakehouse）と、関数などのツールを組み合わせて回答できる
- クエリテンプレートやトピックにより、回答が速く、一貫したものになり、デバッグも容易になる
- 管理者は A365 経由で、ビルダーはオブザーバビリティで、エージェントの動作を把握できる
- フィードバックを通じて、エージェントの指示とツールを継続的に改善できる

なお、顧客名や導入事例、定量的な成果の数値は、このセッションでは紹介されていません。

## 9. まとめ

Fabric IQ は、Power BI のセマンティックモデルを起点に、Copilot Chat、Cowork、Excel、MCP（GitHub Copilot など）、さらに ChatGPT や Claude へと、同じツールと同じガバナンスのまま広がります。専門家が必要な場面では、Fabric data agent に複数のデータソースとユーザー定義関数を組み合わせて、公開し、Copilot Chat や Fabric apps で使えます。

data agent には、セマンティックモデル設定とサンプル DAX、クエリテンプレート、トピック、A365 連携、Application Insights によるオブザーバビリティ、OptiGuide、Build with AI の強化、1,000 行の返却が加わります。Sara 氏は、エージェントが何をしているかを知る手段が重要で、A365 とフィードバックのループで、ビジネスユーザーの役に立っているかを確認できると締めくくっています。
