# THR1019 Azure Friday with Scott Hanselman: Kinectify fights financial crime

## 1. はじめに

このセッションは、Azure Friday の初のライブ収録として行われた約 25 分のシアターセッションです。Scott Hanselman 氏が、ゲーミング業界向けのマネーロンダリング対策（AML）プラットフォームを提供する Kinectify の CTO、Mike Calvin 氏にインタビューします。

内容は大きく 2 つです。1 つは、架空の「Walter White」のプレイヤーデータを使った、疑わしい取引の検知から調査レポートの生成までのデモです。もう 1 つは、そのプラットフォームを Azure でどう構築したか、AI をどこに足したか、という技術の話です。結論は、**AI は既存の機械学習やデータ基盤の上に、意味のある場所へ加えるもの**であり、チャットボットだけで成り立つものではない、という点です。

## 3. 何に関する発表か

Kinectify は、カジノ、スポーツブック、デイリーファンタジーなどのゲーミング事業者から、プレイヤーと取引のデータを受け取り、マネーロンダリングや犯罪の可能性を分析するプラットフォームです。発表の流れは次のとおりです。

1. マネーロンダリングとは何か（ゲーミングでの例）
2. デモ：データの送信から、アラート、調査レポートまで
3. 使っている AI と機械学習
4. Azure 上の構成
5. 開発から得た学びと、AI 時代の専門性

## 4. 発表者が伝えたいメッセージ

Mike 氏の主張は 3 点にまとまります。

- **AI は魔法のブラックボックスではない。** 実際の仕組みには、デシジョンフォレストなどの従来型の機械学習と、データサイエンス・データエンジニアリングのチームの仕事があり、LLM はその上に要約や説明のために加えている。
- **最初から最適化し、データを理解する。** コストと性能の最適化、データの適切なモデリング、可観測性が、スケールの土台になった。
- **専門性は価値を持ち続ける。** AI でこれまでになく速く、良いソフトウェアを作れる。ただし、ソフトウェアを作ったことのない「vibe coder」とは、AI の使い方が違う。

## 5. 発表内容の詳細

### 5.1 マネーロンダリングの基本

Mike 氏の説明では、違法な手段で大金を得ても、そのままでは使えません。収入に見合わない暮らしを政府が不審に思うからです。そこで、そのお金を正当なものに見せる必要があります。方法の 1 つとして、カジノに持ち込んで損失を最小限にし、「Mike がカジノで 10 万ドル勝った」という記録を残す、というやり方が語られました。ほかの方法として、Scott 氏が冗談で洗車店を開くことに触れ、Mike 氏が大きな貸倉庫に現金を置く案も挙げています。

対象となる顧客は、カジノ、スポーツブック、デイリーファンタジーなどです。

### 5.2 データの取り込み

- 顧客は、プレイヤーと取引のデータを、Kinectify の**公開 API** に送ります。
- 送信は、日次や時間単位の大きなバッチと、ストリーミング型の準リアルタイムの両方に対応しています。
- 送信が成功すると、API は **202 Accepted** を返します。これは「データ構造は正しく受け取り、処理を始める」という意味で、すぐに画面で見られるという意味ではありません。処理は非同期で、**Azure Service Bus** や **Azure Functions** など複数の Azure のサービスを通ります。
- ほとんどのデータは、公開 API から数ミリ秒でプラットフォームに入る、と説明しています。

### 5.3 検知の仕組み

Mike 氏は、単純な異常検知を超えて、**時間をかけた行動**を見ると述べています。マネーロンダリングを示す行動に対し、大量の取引データから検出するアルゴリズムを開発してきたという説明です。

多額のお金を使うこと自体は不審とは限りません。大金で遊ぶ人は実際におり、顧客は上客との関係を保ちたいので、不審でないものは不審と扱わないようにしている、と述べています。そのうえで、その人が使っているお金が、使ってよいお金かどうかを理解する手助けをする、という位置づけです。位置情報の例として、ふだんシアトルで取引している人の取引が突然ヨーロッパに現れる場合も、似た種類の処理だと説明しています。

### 5.4 AI と機械学習の使い方

Scott 氏は「AI を使って検知する、と聞くと、ChatGPT に全部入れていると誤解されがちだが」と問い、Mike 氏が実態を説明しました。

| 要素 | 内容 |
|---|---|
| LLM | 生成・拡充したデータの要約とレビューに使う。従来の機械学習が何をしているかの説明にも使う |
| 従来型 AI | デシジョンフォレストなど。**Azure Machine Learning** で学習 |
| deep analysis | 最近リリースした新機能。テナントごとにモデルを学習し、取引監視アラートに対する担当者の判断（disposition）の傾向から学ぶ |
| KYC モジュール | 最近完成した、完全にエージェント型のモジュール。約 20 のエージェントが、Semantic Kernel と Microsoft Agent Framework、Python と C# にまたがって連携する（トランスクリプトでは「Symantic Kernel」と聞こえます） |

deep analysis の狙いは、**誤検知率を 1 桁％に下げること**で、業界では「ゲームチェンジャー」だと述べています。AML ソフトウェアの誤検知率は、従来は 80〜90% の範囲が一般的で、それが許容されてきたとのことです。

Kinectify は 2021 年に始まり、ChatGPT が一般的になる前にプラットフォームを LLM なしで作りました。そのあとで、意味のある場所に LLM を重ねています。規制対象のプラットフォームでは、説明可能性と透明性が極めて重要なので、機械学習の動作を説明する用途も含まれます。

### 5.5 Azure 上のアーキテクチャ

| 領域 | 使っているもの |
|---|---|
| コンピュート | すべてコンテナー化し、**Azure AKS** 上で動かす。取り込みの量に応じて弾力的にスケールイン・アウトする |
| 運用データストア | **Cosmos DB**（広く使用） |
| 分析 | Cosmos DB のミラーリングで **Fabric** にデータを移し、分析の作業をできるだけ Fabric 側で行う |
| メッセージング | Service Bus と **Event Hubs**。Event Hubs が Service Bus ベースの取り込みを置き換えつつあり、運用データストアを経由せず直接 Fabric にデータを終端できる |
| 監視 | **Azure Application Insights**（初日から APM、トレース、ログ集約に使用） |

スケールの上下を起こす主な要因は、取り込みの処理です。Fabric との新しい統合で、このスパイクを少しならせると期待している、とのことです。

データ量の規模として、年に数十億件の取引が流れ込み、運用データベースに取り込んだデータは約 25 TB に達していると述べています。

### 5.6 開発から得た学び

Scott 氏は、同じように大量でバースト的なデータを扱い、人の判断を挟み、必要な場所に AI を加える事業を持つ人に向けて、何を伝えたいかを尋ねました。Mike 氏の答えは次のとおりです。

- **最初からコストと性能を最適化し、データを理解する。** Mike 氏は Kinectify に来る前は大規模な SaaS の経験が長く、データを最初に正しくモデリングする重要性を知っていたと言います。それが Cosmos DB や AKS での効率のよいスケールにつながったという説明です。
- **可観測性を重視する。** どのシステムがどのレベルで使われ、いつ限界や増強の必要に達するかが分かるテレメトリを用意し、Azure Application Insights を初日から APM、トレース、ログ集約に使っています。
- **専門性は価値を持ち続ける。** Scott 氏は、このシステムは「vibe では作れない」ほど大変な仕事で、クラウドスケール、Kubernetes、データサイエンスの専門家がいると指摘し、専門性が失われるのではと不安な人に何を伝えるかを尋ねました。Mike 氏は、これほど速く良いソフトウェアを作れる時代は無かったので前向きに捉えてほしい、と答えています。専門家の AI の使い方は、ソフトウェアを作ったことのない vibe coder とは違うという考えです。ツールを使い、わくわくして、合理的かつ賢く採用してほしいと話しています。発話の一部が欠けていますが、AI は万能の解決策ではないものの、業界に大きな影響を与えるはず、という趣旨の発言もありました。

## 6. デモ・手順

このセッションには、Mike 氏による画面を使ったデモがあります。架空のシナリオは、ドラマの登場人物 Walter White が、現金の山を合法的なお金に見せようとカジノに行く、というものです。画面の細部（画面レイアウトや入力値）は音声からは確認できないため、語られた範囲で書きます。

**シナリオ：** Walter が 10,000 ドル単位の 100 ドル札の束をスロットマシンに入れ、遊ばずに引き出しのバウチャーを印刷し、現金をバウチャーとして持ち出す（闇市場の通貨のように使うこともできる）。

1. Walter のプレイヤーレコードを、Kinectify の公開 API に送る。続けて取引データも送る。
2. API が **202 Accepted** を返す。取り込みが成功し、処理が始まったという意味だと説明される。
3. 分析担当者の画面で、Walter のプレイヤー情報を見る。カジノのオンボーディング時に集めた情報を取り込み、疑わしくなると Kinectify 側でも情報を拡充する。
4. 取引データの一覧を見る。Walter が 1 台以上のスロットマシンに現金を入れ、バウチャーを印刷して、cage（バウチャーを持っていく窓口）に持っていく様子が分かる。ただ、素人目には問題なさそうに見え、検知は難しいと述べられる。従来は、顧客がスプレッドシートで取引を眺めて見つけていた。
5. **取引監視アラート**を見る。アラートは、Walter が **immediate withdrawal**（現金を機械に入れてから、遊ばずにそのまま引き出す）を行ったことを示す。何が起きたかが顧客に伝わり、証拠を確認できる。
6. 担当者（人）が内容を確認し、アラートに対する判断（disposition）を行う。事実だと判断すれば、ケースを作成して調査を続ける。調査の一環として、**enhanced due diligence レポート**や KYC を実行できる。（途中で誤ってボタンを押し、いったん戻ってから Walter のレコードに戻っている。）
7. **enhanced due diligence レポート**を開く。マルチエージェントのシステムによるもので、集めた生データを基に、LLM が人生のさまざまな領域を要約する。関係性の関連づけも行う。ページは少し遅いと断りがあり、表示されると、Walter の居住地と、さまざまな形で関連する人々が分かる。Scott 氏は「不正（fraud）版の ancestry.com のようだ」と表現している。

収録の最後に、Scott 氏は、テストデータとして Walter White の関連人物（Jesse、Skyler、Walter Jr.）が登録されていることに触れています。

## 7. 注意点・発表者の気付き

- **202 は「完了」ではない。** 処理は非同期で、受け付けられても、すぐに画面で見られるとは限りません。
- **人が判断する。** アラートの確認、ケースの作成、調査は、人が最終的な判断をします。Scott 氏が「どの程度自律的にするかは、人が決められる」という趣旨で話し、Mike 氏は人がアラートを判断して調査を続ける流れを説明しています（自律度の設定そのものは発表では説明されていません）。
- **多額の取引だけでは不審とみなさない。** 顧客が上客との関係を保てるようにするためです。
- **説明可能性と透明性。** 規制対象のプラットフォームでは極めて重要だと述べています。
- **既存の仕組みを捨てない。** LLM は、決定的に動く既存のシステムの上に、説明や使い勝手のために重ねています。
- **可観測性。** どのシステムがどの程度使われ、いつ限界やスケールの必要が来るかを示すテレメトリを、初日から用意しました。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- 以前はスプレッドシートで取引を見ていたのに対し、**取引監視アラート**で、起きたことと証拠を確認できる。
- deep analysis により、誤検知率を 1 桁％に下げることを狙う（従来は 80〜90%）。数値は目標で、実績値は発表では示されていません。
- KYC モジュール（約 20 のエージェント）が、不利なメディアや法的情報などを集め、対象の人物と関係があるかを判断する。
- enhanced due diligence レポートで、要約と人物の関連づけを得られる。

なお、Mike 氏は、一般の利用者が気にする点として「カジノで年に一度 300 ドル使う人が怖がる必要があるか」という Scott 氏の問いに、「安心してよい。捕まえたいのは犯罪者（人身売買、麻薬取引、テロ資金供与に関わる人）だ」と答えています。

## 9. まとめ

Kinectify は 2021 年から AML プラットフォームを Azure で構築してきました。AKS、Cosmos DB、Fabric、Service Bus、Event Hubs、Application Insights などを使い、年に数十億件の取引を扱っています。AI は、その上で必要な場所に加えられています。LLM は要約や説明、Azure Machine Learning で学習した従来型のモデルは検知や deep analysis に使われます。

Mike 氏は、データのモデリングと最初からの最適化、可観測性の重要性を挙げ、AI 時代でも専門性は価値を持つと述べています。Scott 氏は、このシステムは「vibe で作れるものではなく、大変な仕事だ」と指摘し、クラウドのスケール、Kubernetes、データサイエンスの専門家が土台にあることを挙げました。Mike 氏は自分のチームに「ツールを使い、わくわくして、合理的かつ賢く採用してほしい」と伝えているとのことです。詳細は Kinectify の Web サイトで確認できます。
