## 5. 発表内容の詳細

### 5.1 背景：誰もが作れる時代と新しい Microsoft Copilot

Anna 氏は、AI によって誰もが作り手になれることが大きな変化だと話しています。マーケティング、財務、HR などのビジネスチームが自分たちのソリューションを作れるようになり、開発者は AI に退屈な部分を任せて、より価値の高い仕事に集中できます。適切なガードレールがあれば、すべてのエージェントとアプリを統制し、IT が管理下に置けるとも説明しています。

9 月末に「新しい Microsoft Copilot（the intelligence built for work）」が発表されたと紹介されました。AI アシスタントとしてチャットできるほか、複数ターンが必要な複雑なタスクを任せられ、Copilot の中でエージェント、スキル、アプリを作成できます。どこで作ったエージェントも Copilot に持ち込んでユーザーに提供できます。パートナーもエージェントやプラグインを作っており、Microsoft 製のものに加えて広がりがある、とのことです。

### 5.2 エージェントを作る 3 つの道筋

| 対象 | 推奨される場所 | 説明 |
| ---- | ---- | ---- |
| ビジネスユーザー | Copilot（Agent Builder） | 自然言語で、軽量なエージェント、スキル、アプリ、ワークフローなどを作る |
| 上級ユーザー（"makers"）、プロの開発者 | Copilot Studio | エージェント、アプリ、ワークフローを 1 つの統合プラットフォームで素早く作り、業務プロセスを組み直す |
| プロの開発者（ソフトウェアエンジニア）、ミッションクリティカルで高度なカスタマイズが必要なチーム | GitHub、Copilot、Foundry | 多くの顧客がこの道を選んでいる |

3 つの道筋は補完関係にあり、複数のレベルでつながっている、と Anna 氏は説明しています。

### 5.3 各道筋の詳細

#### Agent Builder（Copilot Chat の一部）

数分で軽量なエージェントとスキルを作れます。Anna 氏が挙げた例は、チームに新しいメンバーが入ったときのオンボーディングです。見るべき SharePoint サイトやファイル、会うべき人はチームごとに異なります。そこでマネージャーが Agent Builder でエージェントを作り、選んだナレッジソースにつなげると、そのエージェントは許可したソースからだけ回答します。作ったエージェントはチームと共有でき、IT チームに公開依頼して組織全体で使うこともできます。Copilot Chat に含まれており、Copilot ライセンスがあれば今日から使えます。

**プラグインとの関係**：Agent Builder で作ったエージェントは、プラグインのパッケージに含められます。プラグインは、エージェント、スキル、MCP サーバー、ツールを 1 つにまとめたパッケージで、1 回作れば Copilot Chat や Cowork など複数の場所で使えます。顧客は自社のプラグインを作って Microsoft 365 管理センターで管理できます。パートナーは Partner Center に提出し、Microsoft Marketplace で公開して、Teams と Copilot からも使えるようにできます。

#### Copilot Studio

企業の業務プロセスは複雑で、エージェントだけでは足りないという考えから、エージェント、ワークフロー、アプリを 1 か所で作れる環境として紹介されました。3 つの役割は次のとおりです。

* エージェント：推論してアクションを取る
* ワークフロー：実行するプロセスに構造を与える
* アプリ：人、作業、チームの協働が行われるユーザーインターフェース

今週発表された **agent account** と **memory** の機能により、エージェントに専用の ID とメモリを持たせ、Copilot、Teams、Outlook で @メンションして仕事を割り当てられます。「デジタルなチームメイト」のように使え、メモリによって過去のやり取りを覚えるため、時間とともに回答が正確になっていく、という説明です。

データ接続については、Work IQ、Foundry IQ、MCP サーバー、1,400 以上のコネクタ（サードパーティや基幹業務システム向け）を通して接続できます。Agent2Agent（A2A）プロトコルもサポートし、A2A に対応する他のエージェントとつなげられます。モデルは、Claude、OpenAI、Grok、Mistral などフロンティアラボのモデルと Microsoft AI のモデルから選べます。新たに発表された **Auto Mode** は、タスクに応じてモデルを自動で割り当て、コスト効率と性能を両立させるとのことです。

また、エージェントにはコンテキスト、ツール、オーケストレーションが必要だとして、**Microsoft Copilot Harness** が紹介されました。8 月に発表された GitHub Copilot Harness を改名したもので、Copilot、Copilot Studio、Foundry、GitHub の 4 つの領域に現れるため改名したと説明しています。エージェントの実行と構築のための Microsoft の基盤レイヤーであり、Copilot Studio の全モデルで動作します。顧客から非常に肯定的なフィードバックと品質スコアの向上が得られているとのことです。

#### Foundry（開発者向け）

GitHub で自分のコードを使って作り、Foundry で実行・最適化する道筋です。1 万を超えるモデル、Microsoft IQ を通した企業ナレッジを使え、Azure のグローバル規模のコンピュートとソブリン制御で動きます。Agent 365 が、Foundry で作ったエージェントの管理と可観測性も担います。Copilot や Teams など顧客のいる場所に公開できます。

Foundry での構築ステップは次のように説明されました。

1. **作る**：GitHub Copilot で自然言語で記述する prompt agent から始めるか、Microsoft agent framework で自分のコードを持ち込む。
2. **実行する**：Foundry Agent Service がマネージドランタイムとして、ホスティング層、コンテナー、スケーリング、セキュリティを提供する。各セッションは専用のサンドボックスで動き、各エージェントは自分の Microsoft Entra ID を持つ。
3. **グラウンディング**：Microsoft IQ、Foundry のツール、メモリで接続する。
4. **観測と改善**：エンドツーエンドのトレースとエージェント評価（agent evals）で、エージェントの判断を見て改善する。

#### 道筋の使い分けと相互接続

Anna 氏は、誰が作るか、何を達成したいか、どの程度の複雑さと制御が必要かで決まるとして、次のように整理しました。

* 個人の生産性を上げ、AI に慣れたいビジネスユーザーは、今日から Copilot でノーコードで作れる。
* CLI、VS Code、GitHub を使うプロの開発者で、より広いモデル選択やオープンソースモデルを使いたい場合は、GitHub Copilot と Foundry。
* Copilot Studio でプロトタイプを素早く作るプロの開発者も多い。
* Copilot Studio のエージェントを **MCP として公開**すると、リモート MCP サーバーになり、GitHub Copilot などの開発者ツールから呼び出せる。
* Copilot Studio のエージェントを、A2A プロトコルで Foundry のエージェントと接続できる。
* Copilot Studio は Foundry IQ に直接接続でき、Azure のデータを Copilot Studio のエージェントに使える。

### 5.4 Agent Builder：よくある 2 つのパターン

Ned 氏は、Copilot Chat が Copilot で最も使われているエージェント、Researcher が 2 番目に使われているエージェントで、その両方の立ち上げに携わったと自己紹介しています。毎週数百万人が Copilot 上で直接エージェントを作っており、よく見られるパターンとして次の 2 つを挙げています。

1. **Authoritative Guidance（権威あるガイダンス）**：Copilot も汎用的な案内は出せますが、公式な情報源だけに基づき、毎回一貫した案内が必要なときにエージェントを作ります。例は、公式ソースだけで答える HR のセルフサービス用エージェント。
2. **Standardized Deliverables（標準化された成果物）**：毎週のように作る文書で、他の人にも同じ指針に従ってほしいときにエージェントを作ります。例は、ブランドガイドラインと法務要件に従ったマーケティング投稿。

会場には QR コードで、自分の組織がエージェントを何に使っているかを回答する時間が設けられ、従業員のセルフサービス、オンボーディング、サポート、チケットのトリアージ、標準化された成果物（翻訳エージェントなど）といった回答が紹介されました。

### 5.5 Agent Builder の新機能と Ned 氏のユースケース

デモの前後で、次の新機能が紹介されています。

* Agent Builder は **SharePoint でも使える**ようになった（今週発表）。
* エージェントに**スキル**を追加できる（1〜2 週間前にリリース）。スキルはモデルに段階的に開示されるため、より長い指示を持たせられる。スキルにはスクリプトが含まれることもある。
* 他のエージェントを自分のエージェントに**リンク**できる（展開中）。
* Work IQ の拡張として、Power BI の背後にある **Fabric** のデータへのグラウンディング（有効にするだけ）、SharePoint の**リスト**へのグラウンディング（データベースのように使える）、本物のデータベースが必要な場合の **Dataverse**（Dynamics のデータ）、**Outlook Actions**。
* 共有時に、利用者だけでなく**共同編集者（co-owner）**を追加できる。
* エージェントの**利用統計**（モニタリング）。
* **Copilot tuning** を Agent Builder に統合することを前日に発表した。
* 今後の予定として、フルのプラグインを作れること、時刻だけでなく「会議に出席しなかった」「メールが届いた」などのイベントに基づくスケジュール実行、バージョン履歴（最後の正常版に戻すため）が語られました。

### 5.6 管理者向け：管理センターでの統制

Ned 氏は Microsoft 管理センターの Copilot / エージェントのセクションで、次の 3 点を見せました（詳細は 6.3）。

1. **コネクタ**：基幹業務システムのデータを Copilot が使うための手段。事前構築された大規模なライブラリから追加でき、Copilot がアクセスできるものを管理者が決めると、エージェントもそれにアクセスできる。
2. **エージェントの一覧**：毎週数百万のエージェントが作られているため、組織内で使われているエージェントを All Agents で確認できる。不明なものはブロックでき、利用が多いものは組織全員にインストールできる。
3. **共有の設定**：組織全体への共有を無効にすると、全社への公開には管理者の承認が必要になる。

エージェントを有効にすることは Agent Builder を有効にすることでもあり、人々が自分の業務プロセスを保存するエージェントを作れる、と説明されています。

### 5.7 組織で広げるための土台（Anna 氏）

* **Microsoft IQ** は、すべてのエージェントのコンテキストで、4 つから成る。Work IQ（M365 のデータ）、Fabric IQ（ビジネス分析、Power BI の数字）、Foundry IQ（Azure のデータ）、Web IQ（Web 上の最新の公開情報）。
* **ガバナンス・コンプライアンス・可観測性**の基盤は Agent 365、Entra、Purview、Defender など。Azure、Foundry、Copilot の背後にあるのと同じサービス。
* **Agent 365** は、「AI の資産は何か」「何をしているか」「何のリスクがあるか」「いくらかかるか」の 4 つの問いに答える。管理者はどのエージェントを展開するかとアクセス権を承認でき、各エージェントには明確な所有者と定義された権限がある。リスクの検知と、問題が起きたときの制御もできる。
* **AI 支出の管理**：顧客から、利用量ベースのエージェントで予算が読めなくなったという声があったとして、3 つのステップが示された。Copilot Credit Estimator で予算を見積もり、Cost Management Dashboard でユーザー単位またはエージェント単位の支出を管理する。範囲は Cowork、Copilot Studio、Work IQ API にまたがり、IT は設定した予算に対する状況を確認できる。
* **Frontier Accelerator Program**：Web サイト、Microsoft の営業担当、パートナーを通じて参加できる、エンドツーエンドの特典パッケージ。専門知識、人材、投資、スケールを組み合わせて提供する。リンクはスライドに掲載されており、他のセッションの案内もあった（具体名は音声からは確認できません）。

## 6. デモ・手順

Ned 氏がライブデモを行っています。録音は音声のみのため、画面の細部は確認できません。デモで使うデータは Ned 氏本人の実データで、一部は伏せていると話しています。

### 6.1 作成済みのエージェント（Shiproom Reporter）を使う

Ned 氏のチームは、毎週ステータスレポートを作り、shiproom（リスクと遅延を確認する会議）でレビューしています。以前は作成に数時間かかり、Copilot で減らしたが繰り返しの作業が残っていたため、スペシャリストとして動くエージェントを作った、という背景です。

1. Copilot で「/shiproom reporter」と入力すると、メニューにエージェントが表示される。Enter を押すと、Copilot 内で Shiproom Reporter と直接対話できる。
2. 詳細として、Azure DevOps の Epics ボードを使うこと、自分向けの「top of mind」メールを Work IQ で調べること、参照用に含めたドキュメントに従うこと、その他の要件が指定されている。
3. 実行中に、Ned 氏は「Shiproom Reporter に自分自身を作るよう頼んでしまった」と気づき、正しくは今週のレポートを作ってもらうものだったと話した。そこで、改めて「今週のレポートを書いて」と頼み、結果には前日に作っておいたものを表示した。
4. 結果は実際の Word 文書で、チーム全員が共同編集・コメントでき、会議でもライブで使っている。リーダーシップの決定事項と次のアクションを求める指示に従い、Azure DevOps の実際の項目を取り込み、リスクや期限超過の項目を示している。順調な項目の中から、さらに確認が必要なものを自分で判断して挙げる、とも説明した。例として、Copilot tuning の Agent Builder への統合が順調であると記載されていた。

その他に日常的に使うエージェントとして、次の 4 つが紹介されました。

* 求人の職務記述書を、Microsoft のレベルの指針と法務要件に従って作るエージェント（Ned 氏が採用中のため作成）
* チームの別のメンバーが作った、仕様書（spec）作成エージェント。競合情報や最新の指標を、チームの手順に従って調べる
* オンボーディング用エージェント（YouTube のデモで見せたタイプ）
* Employee Self-Service エージェント：HR や IT ヘルプデスクの質問に答える、Microsoft 社内で最も使われているエージェント

左側にエージェントをピン留めでき、「agents」から最近使ったエージェントの一覧を見たり、新規作成に進んだり、「more agents and plugins」でプラグインのタブに移動できます。Agent Builder で作ったエージェントはすべてプラグインとしてラップされ、このタブに表示されます。他の人から共有されたエージェントや、管理者が承認したエージェント（Microsoft 製で、管理者が承認済みなので信頼できる）も見られます。

### 6.2 エージェントを作る

1. 「Add」から「New Agent」を選ぶ（左側の「Agents」→「New Agent」と同じ）。
2. プロンプトを入力する。通常は「Shiproom のレポートを作るものを作って」と言って何度かやり取りするが、デモでは 1 つの大きなプロンプトにまとめてある。以前に手作業で作った shiproom 文書を例として参照し、Azure DevOps に接続し、標準化された指針に従うための要件を指定している。
3. エージェントが、要件を具体的な指示とスキルに変換する。名前と説明が生成される。アイコンは物足りないので、アイコンをタップして変更する（画像生成も可能だが時間がかかるため、普段使っているアイコンと色を選んだ）。
4. 生成された指示は手動でも編集できるが、チャットで AI に書いてもらうことを推奨しており、「Suggest Improvements」をクリックすると、プロンプトが入力される。「Send」を押すと、Copilot が改善案を検討し、選択肢を示す。この例では「情報の優先順位を付けたいようだ」という質問が出て、「Submit」を押すと指示が改善された。
5. スキルが自動で追加されていた。中を開くと、より詳細な指示が含まれていて、スクリプトも書かれていた（例：期限超過かどうかを判定する日付の比較）。Ned 氏はコードを書いていない。
6. 他のエージェントをリンクする。プラグインのページからエージェントを参照し、「Agent Builder Spec Reviewer」を選ぶ。shiproom レポートを読んだ人が、予定されている機能の仕様書をレビューしたい場面を想定している。仕様書をレビューするエージェントは、チームの別のメンバーが作ったもので、その人が今日スキルに関する 2 つのセッションを行うと案内していた。
7. ナレッジを設定する。
   * Work IQ から、以前に手書きしたドキュメント（構成の参照用）、自分と上司の「Top of Mind」メール、Teams を指定する。Teams は、すべての会議のトランスクリプトではなく、「+」で shiproom の定例会議シリーズだけに絞る。これにより、前の週に話した内容が今週のレポートに反映される。
   * Power BI を使っているなら Fabric のデータにグラウンディングできるが、このエージェントでは使わない。
   * Copilot コネクタは、管理者が追加済みのもののうち、DevOps 用を有効にして、基幹業務の作業項目を直接取得できるようにする。デモでは Exchange 用も有効にしたと説明している（聞こえた表記のままです）。
   * Web Search は、市場調査や競合比較には便利だが、このエージェントでは不要なのでオフにする。
8. 推奨プロンプト（suggested prompts）を設定する。ユーザーにエージェントの使い方や AI の使い方を教え、よくあるパターンをすぐ実行できるようにするもの。
9. 設定メニューの中にある **Outlook Actions** で、エージェントがメールや会議依頼の下書きを作れる。送信はしないので、ユーザーが「Send」を押す必要がある。レポートをメールで送る場合は 1 クリックで済む。
10. 「Preview」でテストする。Copilot 内と同じ見た目で、推奨プロンプトも表示される。標準の shiproom レポートを生成するプロンプトを送るが、完了を待たずに「Create」を押した。
11. 作成直後は非公開で、自分だけがアクセスできるが、管理者はその存在を確認でき、共有できる。

### 6.3 共有・監視・管理

1. 「Share」を押すと、Office 文書と同じ見慣れた共有ダイアログが表示される。ユーザーとグループに共有できる。今回は Anna 氏に共有し、チャットだけでなく**エージェントの編集**もできるようにして、共同作成者にした。相手にメール通知が届くため、利用を促せる。
2. 例として添付した文書に Anna 氏がアクセス権を持っていなかったため、アクセス権を付与するか確認され、「はい」を選んだ。これで Anna 氏もエージェントを使うときに同じデータにアクセスできる。
3. 利用状況の画面（1〜2 か月前に展開）で、総セッション数、日次アクティブユーザー、時間経過ごとのエンゲージメント、使われているナレッジ（Azure DevOps を呼んだか、メールを検索したか、会議シリーズとトランスクリプトを見たか）を確認できる。共有した直後のため、デモでは実際の数値はない。エージェントが想定どおり使われ、価値を出しているかが分かる。
4. 利用が多く、全員向けのストアに出したい場合は、「…」メニューから「submit to the org catalog」で管理者に承認を申請する。管理者が承認に使う基本情報を入力する。
5. Microsoft 管理センターに切り替え、Copilot とエージェントのセクションで 5.6 の 3 点を示した：コネクタの「Add Connection」、Agents タブの All Agents（ブロックと全員へのインストール）、組織全体への共有をオフにする設定。

## 7. 注意点・発表者の気付き

* **失敗とその対処（デモ）**：Ned 氏は、Shiproom Reporter に「自分自身を作る」よう頼んでしまい、前日に作った結果を使いました。デモでは実際のデータを使っており、日付などは伏せています。
* **指示は AI に書かせる**：生成された指示は手動で編集できるが、チャットで AI に書いてもらうことを推奨しています。
* **ナレッジは絞る**：Teams はすべての会議のトランスクリプトを検索させず、必要な会議シリーズに絞ることが示されました。不要な Web Search はオフにしています。
* **Outlook Actions は送信しない**：メールや会議依頼は下書きまでで、送信はユーザーが行います。
* **ナレッジのアクセス権**：参照文書へのアクセス権がない相手に共有すると、権限の付与を確認されます。
* **作成直後は非公開**：まず自分だけで使い、共有してから組織カタログへの申請に進みます。
* **利用量ベースのエージェントで予算が読めなくなった**という顧客の声があり、Agent 365 の支出管理が紹介されました。
* **Agent Builder と管理**：エージェントを有効にすると Agent Builder も有効になります。組織全体への共有をオフにすれば、管理者の承認を経るようにできます。

## 9. まとめ

Microsoft には、エージェントを作る道筋が 3 つあります。ビジネスユーザーは Copilot の Agent Builder、メーカーと開発者は Copilot Studio、プロの開発者は GitHub と Foundry です。これらは MCP や A2A でつながり、作ったものは Copilot に持ち込んで配布できます。

Agent Builder でよく見られる使い方は、権威あるガイダンスと標準化された成果物の 2 つです。デモでは、1 つのプロンプトから名前、説明、指示、スキルが生成されました。そこにナレッジ、コネクタ、Outlook Actions を設定してエージェントを作り、共同編集者を追加して共有し、利用状況の画面を見せ、組織カタログへの申請方法まで示されました。管理者は、管理センターでコネクタ、エージェントの一覧、共有の設定を使って統制できます。

組織全体で広げるための土台として、Microsoft IQ（Work IQ、Fabric IQ、Foundry IQ、Web IQ）、Agent 365 による可視化と制御、AI 支出の管理が紹介されました。最後に、エージェントを作って成果が出た人には、LinkedIn で事例を共有してほしい、という呼びかけで終わっています。
