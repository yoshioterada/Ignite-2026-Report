# BRK462 Putting AI to work for nurses with Dragon Copilot

## 1. はじめに

このセッションは、看護師の業務を支援する AI クリニカルアシスタント **Dragon Copilot for Nurses**（トランスクリプトでの表記は Dragon Copilot for Nursing）の紹介です。ドキュメンテーションの負担軽減から、日々の勤務全体を通した認知負荷の軽減までを扱います。看護の現場や医療 IT に関わる人向けの内容です。

発表者は Brian Weirich 氏で、看護の経営層（chief nurse）を務めた経験者の立場から、導入時に必ず出てくる 4 つのテーマ、今月の public preview に入る機能、Mercy Health の導入成果、そして会場との質疑を話しました。

## 3. 何に関する発表か

Dragon Copilot for Nursing は、勤務時間を通して看護師を助ける AI クリニカルアシスタントです。ドキュメンテーションだけが対象ではありません。重要な情報を継続的に読み取り、分析して看護師に知らせ、質の高いケアを支えます。目指すのは、ドキュメンテーションの負担だけでなく、看護師が抱える全体の認知負荷を下げ、複雑なワークフローをできるだけ単純にすることです。Brian 氏は個人的な目標として、「看護師の時間を再び人間的なものにする（rehumanize）」と語っています。

発表の流れは次のとおりです。

1. 導入で必ず出る 4 つのテーマ
2. シミュレーションモード（デモ）
3. flow sheet 対応の拡大
4. Dragon Copilot Chat
5. スマートルーム連携
6. Mercy Health の成果
7. Q&A

## 4. 発表者が伝えたいメッセージ

Brian 氏は、自身が看護の経営層として同じ技術を複数ベンダーで導入した経験から、導入の落とし穴を「チートコード」として先に共有すると述べています。ポイントは、技術そのものよりも、**習慣、話し方、基準、練習**といった現場の運用の側にあります。

もう 1 つのメッセージは、看護師の時間を取り戻す効果が、残業、記録の遅れ、看護師の負担感、患者体験といった指標に表れる、ということです。ただし Microsoft は顧客のデータ（Epic、Slicer Dicer、Power BI ダッシュボードなど）にアクセスできないため、共有できるのは顧客が許可したか公開した数字だけだと断っています。

## 5. 発表内容の詳細

### 5.1 導入で必ず出る 4 つのテーマ

| テーマ | 内容 |
| ---- | ---- |
| 1. 古い習慣をやめる（Break old habits） | 電子カルテ（EHR）の copy forward ボタン（過去のアセスメントのコピー＆ペースト）。速くて慣れていて安全に感じるが、看護管理者の立場では「安全とは正反対」。新しい習慣を導入するなら、やめる習慣を特定する必要がある |
| 2. ケアを声に出す（Narrate care） | Ambient AI が拾うのは、看護師が口にしたアセスメント、観察、行動だけ。例えば「Okay, good」だけでは臨床上の結果ではなく、どこに何を記録すべきか分からないので、精度が低いというフィードバックにつながる。「深呼吸してください。肺の音を聴きます。肺の音は全体にきれいです」「右上葉に crackles が聞こえます」のように、行動と結果を患者に向けて言う |
| 3. 明確な基準を決める（Set clear standards） | charting by exception や、charting within defined limits を使っている現場では、ambient との組み合わせに戸惑いが出る。例えば、ambient が defined limits に正常所見を入れたのに看護師が削除し始める、あるいは例外を記録しているのに正常所見も記録してしまう、といった余計な作業が生まれ、時間とクリックを減らす目的に反する。期待値を揃えるのはリーダーの役割 |
| 4. 本番前に練習する（Practice before go live） | ケアを声に出すのは看護師にとって自然ではない |

4 つ目について、Brian 氏は意外だった点を述べています。最も苦労するのは、技術世代だと思われていた**若手の看護師**でした。経験を積んだ看護師が技術に抵抗するだろうと考えていましたが、多くの顧客でそうはなっていません。若手は、自分のアセスメントを患者の前で声に出す自信がないためです。例えば心音を聴いて雑音がありそうでも確信が無いとき、患者に「雑音は無い」と言われるのを避けて、口にしないことを選ぶ、という説明です。

### 5.2 シミュレーションモード

この学びから、Microsoft は **simulation mode**（デモ／シミュレーションモード）を作りました。看護師が練習できる環境で、2 つのスタイルがあります。

| スタイル | 内容 |
| ---- | ---- |
| Conversational care | デジタルの患者にアセスメントの質問をし、AI が答える。会話から記録が反映される |
| Monologue care | 患者が会話できない（例: クリティカルケア）場面向け。医師の口述に似て、看護師が自分のアセスメントを声に出す。物語形式の記録ではなく、該当するセルに入れる |

デモの直後に「今月のリリースで public preview」という説明が続きます。ただし、その対象が simulation mode なのか、次項の flow sheet 対応の拡大なのかは、発話上は明確ではありません（flow sheet 側は「今月の public preview 以降」と説明されています）。

### 5.3 Flow sheet 対応の拡大

Flow sheet は病院ごとに異なり、固有です。Dragon Copilot は、現場がすでに使っている flow sheet に合わせるため、新しい flow sheet に切り替える必要はありません（Brian 氏は、ただし flow sheet が時間とともに散らかるので整理することは勧めています）。

今月の public preview 以降、急性期（acute care）の病院で、flow sheet で記録している現場なら、任意の flow sheet にマッピングできる、と説明されています。

- ケア環境: med surg（最初に始まった領域）、救急部、クリティカルケア
- 対象: 成人と小児
- 職種: これまでは med surg の看護師とペイシェントケアテクが中心。今回、理学療法、呼吸療法、ケースマネジメントなどにも拡大

### 5.4 Dragon Copilot Chat

多くの人が個人のスマートフォンに好きな言語モデルを入れており、看護師も同様です。Dragon Copilot Chat は、その体験をアプリ内に持ち込むもので、看護師が 1 日を通して話しかけられます。Brian 氏は「ポケットの中の preceptor」と例えました。ユニットで何でも知っている先輩のような存在、という意味です。

| 用途 | 内容 |
| ---- | ---- |
| 勤務中の会話の記録 | 勤務中に録音したすべてのトランスクリプト（発表者は「12 時間分、24 時間分に及ぶこともある」という趣旨で話しています）はキューに保存され、Dragon Copilot が把握している。例えば「患者の娘さんはいつ迎えに来る？」と聞くと、「今日の 3 時」と答え、根拠が今朝 9:15 の会話であることも示す |
| 薬剤・処置のガイド | 病院が使っている外部の信頼できる情報源に基づいて答える（例: chemo port のフラッシュの方法）。ウェブ全体には行かない |
| 院内の方針・手順 | 院内ポリシーから答える（例: 低血糖のプロトコル、濃厚赤血球を接続するときのバイタルサインの頻度、服装規定、休日のローテーション） |
| よくある質問 | 例: CBC の採血管の色。頻出の質問で、badge buddy が用意されているほどだ、と説明されている |
| ドキュメンテーション | 構造化された flow sheet や、各種ノートの記録を支援 |

### 5.5 スマートルーム連携

スマートルームは、病室内のカメラ、マイク、デジタルのコミュニケーションボードなどを備えた技術ですが、Brian 氏は、業界共通の定義は無いと断っています。室内にマイクがあれば、そのスマートルームのベンダーと連携できます。現在、パートナーとして Hello Care、Care Agility、Stryker（音声認識の都合で表記が確定できません）の名前が挙がり、今後さらに増える予定です。

現状、ambient のために多くの人が使っているのはスマートフォンですが、スマートルームがあれば不要になります。ワークフローは次のとおりです。

1. 看護師が病室に入る。スマートフォンを取り出したりログインしたりする必要は無い
2. 顧客と協力して設定する **wake word** を言うと、録音が始まる
3. できるだけ多く録音するほど、データが増える。水を足す、便器を替えるといった場面でも、痛みや直近の血圧の話が出る。看護師が記録したい内容が含まれる
4. 看護師が記録に移ると、ソフトウェアが「聞き取った内容、記録したい内容」を示し、同意するかを問う

どの場合も、保存する前に必ず**看護師による確認（validation）**があります。「human in the loop は常に必要」と述べています。

### 5.6 Mercy Health の成果

Mercy Health は、private preview の最初期からの顧客で、共同開発も行い、大規模に展開しています（複数の病院、数千人の看護師）。詳細は、スライドの QR コードから Mercy の事例（動画の証言を含む）で読めます。発表者はこの直前に、Showcase（展示）でもデモを見られると案内しています。データは顧客のものであり、Microsoft が共有できるのは顧客が許可したもの、または公開したものだけです。Mercy は 4 つの領域を見ています。業務効率、患者体験、ドキュメンテーションの質（EHR にどれだけ早く、どれだけ正確に入るか）、看護師のウェルビーイングです。

| 領域 | 指標 | 結果 |
| ---- | ---- | ---- |
| 業務効率 | flow sheet に費やす時間 | 22% 削減（1 シフトあたり約 30 分に相当すると、Brian 氏が他の顧客の計算から補足） |
| 業務効率 | 追加の残業（シフト終了後に記録を終わらせる時間） | 29〜56% 削減 |
| ドキュメンテーションの質 | 記録の遅延（latency） | 11.7% 削減 |
| （分類は明言なし） | モバイルの使用（モバイルファーストの現場） | 180% 増加 |
| 患者体験 | HCAHPS の看護師コミュニケーションに関する質問 | 20% 増加 |
| 看護師のウェルビーイング | 認知負荷（導入前後のアンケートによる主観データ） | 65% 削減 |
| 看護師のウェルビーイング | 時間的な余裕の実感（同上） | 65% 改善 |

Brian 氏の補足は次のとおりです。

- 看護師は時間給の従業員で、記録を終えないと帰れない。医師のように「自宅で寝る前に記録する（pajama time）」ことができないため、12 時間のシフトが 13〜13.5 時間になる。ここが残業削減の意味
- 看護師が作業の 2 時間後に、過去にさかのぼって記録すると、早期警告システムや早期悪化の予測モデル（例: 敗血症のアラート）が、チャートの現在の情報を読む前提と合わなくなる。データが入っていなければ、それらのアルゴリズムは意味を持たなくなる
- これらの指標は、看護師不足の中での採用と定着にも役立つ

### 5.7 Q&A

| 質問 | 回答の要点 |
| ---- | ---- |
| 部屋にいる複数の声（小児科など）はどう扱うか（質問文は聞き取りにくい部分があります） | 部屋にいるすべての声を聞いており、看護師、患者、保護者の声を含むトランスクリプトが得られる。小児科ではすべての声からの情報がチャートに必要になる。だからこそ、看護師が「聞き取った内容と記録したい内容」を確認する |
| プライバシー・同意はどうしているか | Microsoft 側の話はできないとして、以前の chief nurse としての経験を回答。同意は必要で、州により one consent と two consent がある。自分の州は one consent 州で、入院時の treatment 同意書の文言に、滞在中は AI や機械学習を含む高度な技術を使う旨を入れた。医師や放射線科も同様の技術を使っているため、個別に区別しなかった。看護師の話し方が変わるので、病室に掲示を出し、看護師には質問への答え方の talking points を渡した |
| Dragon Copilot と Copilot は別ライセンスか、Microsoft 365 とどう統合されるか（看護師の配偶者のための質問） | 回答できる立場にない（営業側ではない）。誤解させたくないとして、推測としては別だと述べたうえで、別チームの担当なので、後で連絡してほしいとした |
| サポートされている信頼できる情報源（MCP）の一覧はあるか | 一覧は大きいため、後で送ると回答。Elsevier のような看護特有の情報源を含め、集約を進めている。現時点でのマスターリストには、多くの薬剤ガイドが含まれる |
| Epic の ambient 提供との比較・統合はどうか（質問者は ambient 領域の競争を指摘） | Epic 固有の提供内容は把握していない（開発に専念しているため）と回答。現在 Epic に統合・組み込まれており、スタンドアロン版もある。どう見せるかは顧客次第。Microsoft は誰とでも素早く統合できる点で、最も有利な立場にあると考えている |

## 6. デモ・手順

デモは 1 本で、Brian 氏が simulation mode の操作を見せました（画面の再生と思われますが、形式は発話から確認できません）。画面の細部は音声から確認できないため、語られた範囲だけを記します。

1. 看護師が simulation mode にログインし、ケア環境（care area）を選ぶ
2. その環境の患者リストが表示される（すべて架空）。患者には診断と病歴がある
3. 患者（トランスクリプトでは "Stephen Wound"。音声認識の都合で表記が確定できません）を選び、背景情報を読む
4. conversational care か monologue care かを選ぶ。tips が表示され、シミュレーションに入る
5. 看護師役が患者に痛みの程度を尋ね、デジタル患者が「脚がまだ痛い、今は 7 くらい」などと答える。看護師が腫れを確認し（押すと両脚にわずかなへこみがある）、血圧を確認する、という会話が続く
6. 停止すると、患者と看護師の発言のトランスクリプトが生成され、EHR の flow sheet に反映される
7. flow sheet をスクロールし、反映された項目をクリックすると、フィードバックが表示される。「この言い方は良かった」「次はこう言うと、より正確に反映され、より多くの flow sheet が埋まる」といった内容で、看護師の時間の節約につながる

Brian 氏は、会話はスポーツチームの話題を振ることもでき、どんな返事が返るか分からない、と冗談を交えています。

## 7. 注意点・発表者の気付き

- Ambient AI は、看護師が口にしたことしか記録できません。「Okay, good」のように、結果を言わない発話では正しく記録できません。
- 若手の看護師のほうが、自信が無く、声に出すことに苦労します。ベテランが技術に抵抗するとは限りません。
- charting by exception との組み合わせでは、正常所見を削除する、例外と正常を二重に記録する、といった余計な作業が生まれます。基準を決めるのはリーダーの役割だと述べています。
- 患者・家族の声も録音されるため、保存前に必ず看護師が確認します。
- 同意の取り方は州により異なります（one consent / two consent）。発表者は、入院時の treatment 同意書に AI の利用を入れた例を紹介しました。
- 顧客のデータは顧客のものであり、共有できる指標は限られます。
- Dragon Copilot と Copilot のライセンスの関係は、発表者は回答できませんでした。

## 8. 利用者にとっての利点

発表で語られたのは、前掲の Mercy Health の数字です（5.6 参照）。要点を挙げます。

- flow sheet の時間が 22% 減り、追加の残業が 29〜56% 減った
- 記録の遅延が 11.7% 減り、モバイルの使用が 180% 増えた
- HCAHPS の看護師コミュニケーション項目が 20% 増えた
- 看護師の自己申告で、認知負荷が 65% 減り、時間的な余裕の実感が 65% 改善した（導入前後のアンケートによる主観データ）
- 既存の flow sheet を変えずに使える（新しい flow sheet に移行する必要が無い）

Brian 氏は、これらが看護師不足の中での採用・定着に役立つ指標だと述べています。

## 9. まとめ

Dragon Copilot for Nurses は、ドキュメンテーションにとどまらず、看護師の勤務全体の認知負荷を下げることを狙っています。導入では、copy forward などの古い習慣、ケアを声に出す練習、charting by exception との整理、go live 前の練習という 4 点が課題になります。そのための simulation mode、既存 flow sheet への対応拡大、Dragon Copilot Chat、スマートルーム連携が紹介されました。

成果としては Mercy Health の指標が示され、共同登壇者の Kim 氏の事例は聞けませんでした。個別の質問は、Brian 氏がセッション後も残って対応すると述べています。
