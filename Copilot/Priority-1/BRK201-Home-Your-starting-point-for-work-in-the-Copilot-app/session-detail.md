# BRK201 Home: Your starting point for work in the Copilot app

## 1. はじめに

このセッションは、Microsoft Copilot アプリの新しい入り口である **Home** を紹介する 45 分のブレークアウトです。Home は、質問して答えをもらう **Chat** と、仕事を任せて完成物を受け取る **Cowork** を 1 つの入力欄にまとめ、プロジェクト、プラグイン、オートメーション、Word・Excel・PowerPoint の編集までを 1 画面に集めたものと説明されています。

構成は、Copilot がここまで進化してきた経緯の説明、Home のライブデモ（Chat から Cowork まで）、そして今後のロードマップ（Today、auto-routing、Intelligent UI）の 3 部です。Copilot を日常業務でどう使い分けるのか、これから何が変わるのかを知りたい人向けの内容です。

## 3. 何に関する発表か

### 3.1 テーマと背景

Annie 氏は、ここ数年 Copilot を拡大するなかで、最先端のモデル（Frontier intelligence）が急速に進歩し、質問に答えるだけでなく、複雑な問題を推論し、複数ステップの仕事を引き受け、利用者に代わってエージェントとして動けるようになった、と説明しました。そのため Copilot は、主にチャットのアプリから、AI を使う仕事の全域を引き受けられるものへ進化する必要があった、という位置づけです。

進化は 3 つのことを行って実現した、とされています。

1. **Copilot の統合**：8 月に、Microsoft 365 のエンタープライズ向け Copilot とコンシューマー向け Copilot を 1 つに統合した。仕事用と個人用のアカウントを行き来しやすくし、Web・モバイル・デスクトップの入口も簡素化した。
2. **コア体験の改善**：応答品質と遅延など、基本に立ち返って体験を整えた。
3. **新しい働き方の実現**：下の 4 つのモードを 1 つの体験に載せた。

### 3.2 4 つの働き方

| モード | 発表での説明 |
| --- | --- |
| Chat | 尋ねると、Copilot が支援する |
| Cowork | 任せると、Copilot が実行する |
| Code | 説明すると、Copilot が作る |
| Autopilot | ゴールを設定すると、Copilot が利用者の代わりにバックグラウンドで作業を続ける |

作業が変わるのに合わせて、これらを 1 つの Copilot の中で使えます。機能が増えるのに合わせて簡素化も進めており、その結果が、新しい仕事の出発点である **Home** だという流れです。

### 5.1 Copilot の進化を示す数値

| 指標 | 内容 |

### 5.2 Home のツアー（Sergey 氏）

Sergey 氏は、Home を「Copilot の出発点」で、実際の仕事の進め方に合わせて作ったものと説明しました。

#### Chat と Cowork を 1 つの入力欄で

- **Chat** は始まりの場所です。質問する、調べる、文書の最初のドラフトを作る。速く、毎回利用者が関与できます。
- **Cowork** は大きなタスクを任せる場所です。仕事を説明すると、Cowork が動いて完成物を持ち帰ります。例として、予測分析や顧客向けブリーフィングが挙げられました。
- **近いうちに（"soon"）**、Chat と Cowork のモードを選ぶ必要すらなくなります。「やりたいこと」を言えば、Copilot が使う機能・モード・モデルを決めます。

#### モデルと Auto

Copilot は「multimodal by design」で、最先端のモデルを幅広く提供し、ラインアップも継続的に更新されています。好きなモデルを選べますが、多くの人は選ぶ必要がありません。**Auto** モードでは、Copilot が適切なモデルを選び、タスクに合わせて推論の度合いも調整します。仕組みの詳細は、後半の auto-routing の説明に譲っています。

#### Home に加わる新しい要素

| 要素 | 発表での説明 |
| --- | --- |
| Today | タスク、Teams のメッセージ、メールを 1 つの画面にまとめ、「今頭にあること」を毎日のフィードとして見せる |
| Autopilot | 「デジタルなチームメイト」。名前、役割、ゴールを与えると、仕事を進めてくれる。Home で管理・やり取りする |
| Automations | 利用者のカスタムワークフロー。Home で表示、変更、実行、停止ができる |
| Plugins | Copilot にできることを拡張する。アプリ、スキル、ツールをつなぎ、Copilot を「専門家」にする |

> 補足：Today は、Sergey 氏のツアーでは Home の新要素として紹介され、Annie 氏のロードマップ部分では「これから来る機能」として改めて紹介されています（5.3 参照）。トランスクリプトからは、現時点でどこまで提供されているかは確認できません。

#### Recents と Projects

- **Recents**：Chat と Cowork のタスクを、1 つのリストで保持します。2 つの会話履歴を行き来する必要がなく、中断したところから再開できます。
- **Projects**：仕事のコンテナーです。Chat と Cowork のタスクを、共有のコンテキストと、Copilot がそれまでに作ったものと一緒にまとめます。1 つの仕事に集中できます。

#### Plugins

Sergey 氏は、Copilot を「人間の野心のためのプラットフォーム」にしたいと述べ、その本当の力は拡張性にあると説明しました。プラグインには、チームが仕事を進めるのに必要なスキル、コネクター、ツールがまとまっています。

- 例えば、sales plugin につなぐと、Copilot が営業シナリオ向けの新しい機能を得る。以前は設定に時間がかかったワークフローやデータへのアクセスが、最初から使える。
- IT 管理者がプラグインを一度承認すれば、Chat、Cowork、Code、Autopilot のどれでも使える。

#### Home の中の Office

Word、Excel、PowerPoint の機能を、Copilot の中でそのまま使えます。Copilot とチームメンバーの両方と共同で作成・編集できます。同僚が Copilot を使っていても、単体の Word・Excel・PowerPoint アプリを使っていても、共同作業はシームレスだと説明されています。Sergey 氏は、「単なるビューアではない」「Office に期待される機能を妥協しない」と強調しました。

### 5.3 ロードマップ（Annie 氏）

後半のロードマップでは、Home に来る 3 つの機能が紹介されました。

#### 5.3.1 Today

Annie 氏は、Today を「初の、プロアクティブな single pane of glass 体験」と紹介しています。

- メール、カレンダー、Teams のメッセージ、会議、タスクを 1 か所にまとめる。
- 見逃したこと、最も重要なこと、注意が必要なことを浮かび上がらせる。
- さらに、利用者に代わって**仕事を前に進める**。
- Copilot だけでなく、**Teams と Outlook にも**同じ体験を提供する。どこで仕事をしていても、一貫した Today が使える。
- 空のプロンプトボックスではなく、Home を開いたとき、まず最も注意が必要なことから始まる。

#### 5.3.2 Auto-routing

現状は、プロンプトを入れるとき、Chat か Cowork を手動で選ぶ必要があります。auto-routing では、この判断を Copilot が引き受けます。利用者はプロンプトを入れるだけで、Copilot が Chat と Cowork のどちらに回すかを決めます。

Annie 氏は、画面を示しながら、「リスクのある顧客を見つけて、計画づくりを助けて」というプロンプトを例に、内部で何が起きているかを説明しました。

1. まず、**その組織で許可されているモデル**を確認する。これは管理者が設定でき、管理者の制御下にある。
2. 次に、**モード**を決める。Chat（素早い質問、ブレーンストーミング、最初のドラフトに向く）か、Cowork（より複雑な複数ステップの仕事を任せる）かを選ぶ。
3. 最後に、**モデル**を決める。プロンプトの意図とクエリに基づいて、最良のコストで最高の品質の結果を出せるモデルを選ぶ。

目指すのは、「最適なモード」と「最適なモデル」を Copilot が選ぶことで、利用者が考えなくて済むようにすることです。Annie 氏はこの考え方を「super router」とも呼んでいます。

#### 5.3.3 Intelligent UI

現在は、プロンプトに対してテキストが返ってくるのが一般的ですが、目的によっては、読むより見られるものの方が役立つことがあります。最新のモデルでは、Copilot が**視覚的に豊かで、インタラクティブなカスタム UI をその場で生成**できます。社内でテスト中で、顧客に届けたいと述べています。

動画（話者は "Speaker 1" と表示される別の人物）では、次の例が示されました。

- 「来週の会議のうち、1on1 はどれか、本当に大事なものはどれか、飛ばしたり任せたりできるものはどれか。先週と比べてどうか」と尋ねる。
- Copilot は文章で答える代わりに、質問に合わせて回答を**その場でデザイン**する。画面の最上部に週の全体像が表示され、続いて予定の競合（conflicts）が示される。インタラクティブで、日ごとにクリックして重なりを確認でき、Copilot が対処法を伝える。
- 1on1 については、参加するもの・任せるもの・飛ばすものの区別が示される。先週との比較では、会議の総数は減ったが、競合は増えている。これで、どこに注目すべきかが分かる、という説明です。
- 同じ内容を Intelligent UI なしで見せると、すべて入ってはいるが「文字の壁」で、スクロールが多い。「読める答えと、使える答え」の違いだと説明された。

### 5.4 クロージング（Sergey 氏）

Sergey 氏は、新しい Home の要点を次のように振り返っています。

- ナビゲートしやすく、これまで以上に強力
- Office のフルパワーを、妥協なく Copilot に持ち込む
- プラグインと拡張性により、Copilot が「やるべき仕事」の専門家になる
- ここまでの内容は**今すぐ利用できる**（"all of that is available right now"）。Today、auto-routing、Intelligent UI はこれから

Intelligent UI によって、Copilot は質問に答えるだけの存在から、没入感のある体験を作る存在へ移る、とも述べています。ほかの Ignite のセッションの案内と、会場での質問の受け付けも案内されました。

## 6. デモ・手順

ライブデモは、AJ Brush 氏と Justin Chando 氏が行いました。AJ 氏は冒頭で「ライブデモ」と明言しており、ライブで実演する形式です。ストーリーは、Caldova（音声認識の都合で表記が確定できません）の launch lead「Amber」という想定で、Meridian のローンチと、来週のリーダーシップレビューを控えている、という状況設定です。

> 注意：録音は音声のみのため、画面上のボタン名や配置の細部は確認できません。以下は、語られた順に整理したものです。デモ中には、画面の読み込みが遅れる場面（Plugins 画面）もありました。

### 6.1 前半：Chat、Office、プロジェクト、スキル（AJ Brush 氏）

1. 研究チームから新しい文書が届き、リーダーシップが顧客の声の要約を求めている、という設定。入力欄には Chat と Cowork の両方があり、タスクごとに切り替えられる。今回は **Chat** を使う。
2. Copilot に、ローンチチーム向けの 1 ページの Word ブリーフィングを作るよう依頼する。内容は、顧客の上位 3 つのテーマ、対処すべき重要な懸念、トーキングポイント。書式の指定も添える。
3. 実行中に、モデルセレクターを見せる。使っているのは **Auto** で、Copilot が品質と速度のバランスからタスクに最適なモデルを選ぶ。モデルは頻繁に変わるため、Copilot に任せられるという説明。好きなモデルがあれば選べる。Anthropic や OpenAI などの主要ラボのモデルが Copilot に集まっており、Anthropic のモデルや GPT を選べる。クレジットを使うモデルとして「Fable」と聞こえる名前も挙げられた（音声認識の都合で表記が確定できません）。
4. 1 ページのブリーフィングが完成し、自動的に **Office in Copilot** で横並びに開く。「フルの Office」で、AJ 氏のお気に入りの機能と紹介された。
5. ヘッダーが少し詰まっていると感じて、Return を押して調整する。ブリーフィングには、顧客の上位 3 テーマ、ローンチ時の「access delays（アクセスの遅延）」への注意、リーダーシップ向けの 3 つのトーキングポイントがある。ズームを 120 に上げて見やすくする。
6. 同僚の Mona に、この懸念に同意するか、追加があるかを聞くためのコメントを書き、Comment を押す。Office として、Mona が文書にアクセスできることを確認し、共有し、通知する。
7. セッションを閉じ、三点ボタンから、このセッションを新しい **プロジェクト**（名前は「Launch Research」、色は緑）に移動する。セッションのコンテキストは保たれる。
8. 研究チームから毎週新しい資料が来る想定で、Copilot に「このプロセスと形式を customer research briefing の**スキル**にしてほしい」と依頼する。Chat のまま実行する。**Chat でのスキルは、ちょうど GA した**と説明された。
9. 待っている間に、大事なものを**ピン留め**できることを見せる。例として、delivery workback schedule と、お気に入りのエージェント（Zendesk agent）をピン留めする。
10. Copilot が customer research briefing のスキルを作成し、検証し終える。入力した顧客リサーチに基づく（grounded）スキルで、顧客テーマとリーダーシップ向けトーキングポイントを出す。保存する。
11. このスキルは Chat と Cowork の両方で使え、同僚と共有もできる。同じ形式をリーダーシップ向けに全員で使える。
12. Plugins 画面を開こうとするが表示が遅れ、更新を試みる（すぐ表示されるので、と言って先に進む）。Plugins では、エージェント、スキル、コネクターが 1 か所にまとまっており、Chat、Cowork、Autopilot にまたがって見られる、と説明された。
13. Launch Research の Chat に戻り、Justin 氏にバトンを渡す。

### 6.2 後半：Cowork とオートメーション（Justin Chando 氏）

1. 設定：ローンチでは多くのことが速く動いており、全員を追従させる 1 つのスプレッドシートが必要。同僚の Mona がプロジェクトの更新をメールで送ってくるため、Copilot にメールを確認させ、project launch tracker のスプレッドシートに追加すべきものがないか調べてもらいたい。
2. Copilot に「Mona がメールを送ったら、スプレッドシートを更新して」と依頼する。
3. **Work IQ のコンテキストピッカー**から、仕事のコンテンツを追加する。M365 のデータ（People、ファイル、SharePoint、OneDrive、メール、Teams のメッセージとチャネルなど）にアクセスできる、と説明された。
4. People から Mona を選ぶ（自社の「正しい Mona」）。
5. スラッシュコマンドで、project launch plan を指定し、Enter で送信する。
6. Copilot は、これを **Cowork** で実行するのが最適と判断する。1 回限りの答えではなく、メールを継続的に確認する必要があるため。Chat のコンテキスト、ファイル、スキル、ツールは、何もしなくても Cowork で使える。
7. 新しい**オートメーション**が作られる。イベントベースのトリガーで、Outlook のメールを監視し、Mona からのメールが来たことを検知して、内容を推論し、スプレッドシートを更新すべきかを判断する。更新は、新しいコピーやバージョンではなく、**その同じファイル**に対して直接行う。
8. Next を押し、Outlook のアクセス許可を許可して、オートメーションを有効化する。これで、イベントベースのトリガーが設定される。
9. 右上から、編集、一時停止、削除ができる。
10. 左側には、新しい **Automations** ページがあり、イベントベースのトリガーに加えて、スケジュールされたタスクも一覧される。例として、「weekly one-on-one prep pack」（毎週、組織と自分の直属の部下、今週の 1on1 を確認し、毎回準備を整える）がある。その下には、おすすめのオートメーションがいくつか表示される。
11. 左側の会話（Cowork の会話）を、先ほどと同じプロジェクトに移動して整理する。

Justin 氏は、Chat からプロジェクトでのリサーチ、再利用できるスキルの作成、Office のフルパワー、Cowork でのイベントベースのトリガー（オートメーション）、そしてプロジェクトによる整理、という流れを、デモのまとめとして振り返っています。

## 7. 注意点・発表者の気付き

- **機能の提供時期に注意。** 「Chat と Cowork の選択が不要になる」は "soon"、Today / auto-routing / Intelligent UI はロードマップ上の機能として紹介されています。Intelligent UI は社内でテスト中の段階です。
- **スキルの提供状況。** Chat でのスキルは、デモの時点で GA したと説明されました。
- **管理者の制御。** プラグインは、IT 管理者が一度承認すれば、すべてのモードで使えます。auto-routing では、組織で許可されたモデルが最初に確認され、これは管理者が設定できる、と説明されています。
- **デモの環境。** Plugins 画面の表示が遅れる場面がありました。
- 提供地域、ライセンス、料金などの条件については、発表では触れられていません。

| 繰り返し作業 | スキルを作って、Chat と Cowork で再利用し、同僚と共有できる。メールをトリガーにしたオートメーションで、スプレッドシートを自動更新できる |
| 拡張 | プラグインで、スキル・コネクター・ツールを追加し、Copilot を専門家にできる。IT 管理者の承認は一度で済む |
| 製品の改善実績 | 遅延 25% 減、満足度 2 倍、会話数 2 倍、デイリーアクティブユーザー 8 倍（いずれも Annie 氏が示した数値） |

## 9. まとめ

Home は、Chat と Cowork を 1 つの入力欄に置き、Recents、Projects、Plugins、Automations、Office の編集を同じ場所に集めた、Copilot アプリの新しい出発点です。デモでは、Chat で Word のブリーフィングを作り、それをプロジェクトに整理し、スキルとして再利用できる形にし、さらに Cowork で Mona のメールをトリガーにしたオートメーションまでを、同じ流れの中で見せました。

今後は、Today、auto-routing、Intelligent UI が加わります。Today は仕事を前に進めるプロアクティブな画面、auto-routing は最適なモードとモデルを Copilot が選ぶ仕組み、Intelligent UI は答えをその場で見やすい UI として生成する取り組みです。
