# THR855 From goals to done: AI-powered work management with Microsoft Planner

## 1. はじめに

このセッションは、Microsoft Planner が Microsoft 365 のさまざまな Copilot と結びつき、「計画を立てる」だけでなく「タスクを終わらせる」ところまで担うようになってきた、という内容を紹介する約 25 分のシアターセッションです。

発表の中心は、架空のユーザー Amber と Carol を主人公にした 3 本のデモです。休暇明けのキャッチアップ、新規プロジェクトの立ち上げと実行、そして Autopilot による期限切れタスクの自動フォローが、順に示されます。最後に、これらを支える新しい基盤「unified plans」の説明があります。

この記事では、Planner の機能が Copilot 本体・Planner agent・Cowork・Autopilot の中でそれぞれどう使われたかを、語られた順に整理します。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/THR855](https://ignite.microsoft.com/en-US/sessions/THR855)

## 5. 発表内容の詳細

### 5.1 デモ 1：休暇明けのキャッチアップ（Copilot と Planner）

シナリオは、2 週間の休暇から戻った Amber が、近づく製品ローンチに向けて状況を把握する、というものです。Amber は何が変わったか、不在中に何が決まったか、自分が対応すべきことは何かを Copilot に尋ねます。

Copilot は Amber の仕事のコンテキスト（メール、Teams のチャット、Planner のデータ）を横断して調べ、要点をまとめたブリーフィングを返します。その中で、次のような点が示されたと説明されています。

- ローンチ準備上のギャップとして、新しい responsible AI の開示要件への対応が必要になっている
- 未決事項と、他の人が Amber の対応を待っている作業がある
- 次の行動として、サポートの詰まりの解消、担当の整理、ローンチ成果物のフォローアップがある

ブリーフィングには根拠となる参照が付き、確認が必要な情報には Amber 自身で検証するよう印が付いている、との説明です。

続いて Amber は、自分に対応が必要な項目すべてについて、期限と文脈を付けたタスクを作るよう Copilot に依頼します。Copilot がタスクの保存先を尋ね、Amber は Planner を選びます。Planner の My Tasks リストを開くと、作成された 8 件のタスクが並んでいます。

My Tasks では、次のような見せ方が紹介されました。

| ビュー・機能 | 説明されている内容 |
| ---- | ---- |
| Upcoming タブ | 期限日ごとにまとめて表示される |
| Flagged emails | メールのフォローアップ項目を追跡できる |
| Assigned to me | すべてのプランで自分に割り当てられた仕事を追跡できる |
| 並べ替え・グループ化 | 自分の考え方に合わせて任意に整理できる |

さらに Amber は、チャットで Copilot が示した文脈を見て、世界各国の AI 開示要件を調べるタスクを My Tasks に自分で追加します。このタスクの割り当てドロップダウンからは Copilot のエージェントを選べるため、調査タスクとして Researcher を割り当てます。Researcher は直ちに作業を始め、メッセージは **TaskChat**（タスク内のチャット）に送られます。Amber は TaskChat で Researcher に返信でき、ここでは国ごとの比較概要レポートを依頼しています。出力が出来上がるとチャットに届き、Amber はレビューして、問題なければタスクを完了にします。

発表者は、文脈がすべてタスクの中に残り、Researcher と別のスレッドを立てる必要がない点を強調しています。Amber は数分で、休暇明けのキャッチアップから先回りした作業までを済ませた、という見せ方でした。

### 5.2 Planner と Copilot 本体の変化（Howard 氏の概要説明）

デモ 1 を受けて、Howard 氏は大きな変更点を 2 つ挙げています。

1. **Planner のスキルが「mainline Copilot」に入った。** より本格的な計画づくりには Planner agent が引き続き使えます。しかし、Planner agent を開かなくても、通常の Copilot チャットの中でタスクを保存し、プランを作るなど必要なことができます。
2. **新しい My Tasks ビュー。** 数年前に約束していた To Do と Planner の統合が、このタイミングで実現するという位置づけです。To Do の使いやすさとシンプルなリスト管理を、ユーザー体験とストレージの両面で Planner に持ち込みます。個人のタスクは **default plan** に保存され、現在展開中の新しい統合基盤の一部になります。

### 5.3 デモ 2：新規プロジェクトのプランを作り、割り当てる

次のシナリオでは、Amber が社内の請求アプリ「Waypoint」を出荷するプロジェクトを任されます。プランの構成を手作業で組み立てたくないため、達成したいゴールを Copilot に説明し、Planner にプランを作るよう依頼します。

Copilot は、データ基盤やユーザー体験などを含む構造的な進め方を提案します。提案には、タスク、ゴール、バケット、優先度、期限が含まれます。**作成前に Amber が提案をレビューでき**、問題なければ Copilot に作成を指示します。作られたプランには、提案どおりのタスク、ワークストリーム別のバケット、ゴールがあり、タスクはゴールに紐づいています。メッセージ内のリソースから、そのプランへ直接移動できます。

次に Amber は Planner 内の Planner agent を使い、チームの職能（data engineering、QA など）を伝えて、どのタスクをどの職能に割り当てるべきか提案させます。Copilot はプランを読んで提案を出しますが、これはあくまで提案で、最終的な判断は Amber にある、と強調されています。提案に納得したら、各職能に当たる人の名前を伝えて、その提案に沿って割り当てるよう依頼します。割り当て案はもう一度確認する機会があり、**保存を 1 回クリックするだけ**で、Copilot がプランに割り当てを反映します。個々のタスクを手でクリックして割り当てる手間が不要になる、という説明です。

### 5.4 デモ 2（続き）：Planner agent にタスクを任せる

データモデルを作成するタスクを Planner agent に割り当てるデモです。割り当てると Amber 自身も割り当てられ、エージェントの成果物をレビューする **human in the loop** の役割になります。エージェントはすぐに作業を始め、その様子は「AI agent activity」タブで確認できます。

ボードビューでは「AI agent tasks」でグループ化でき、エージェントの進捗を追跡できます。入力が必要な場合や完了できなかった場合は「Couldn't complete」バケットに移り、完了するとレビュー待ちのバケットに移動します。タスクを開いて Agent activity タブを見ると、出力が **Loop コンポーネント**で表示されています。そのためエージェントにコメントを残すことも、直接入力して編集することもできます。得られたデータモデルは「かなり包括的」と評されました。発表では、Planner agent は最新のモデルで動いており、最良の出力が得られるとも述べられています。Amber は確認して、タスクを完了にします。

### 5.5 デモ 2（続き）：Cowork と Planner plugin

より深い作業のために、Cowork を使います。**Planner plugin** を Cowork に入れると、Cowork がプランとタスクのデータに直接つながります。plugin ストアで Planner を検索して install するだけで導入でき、Planner と組み合わせて「考えつくほとんどのこと」ができると説明されています。

**(1) ダッシュボードの作成**

1. Amber が、先ほどのプランのダッシュボードを依頼します。プランの中で自分で状況を読み解かなくても、すぐ全体像が分かるようにするためです。
2. これは Planner plugin の built-in skill で、Planner のチャートビューに似たものが出来上がります。出力の見た目について確認が必要な場合は、Cowork が質問します。
3. 完成すると、HTML 形式のダッシュボードが表示されます。残りの作業、優先度やゴールごとの進み具合が確認できます。
4. 多くのチームにはステータスレポートのテンプレートがあるため、Amber は自分のチームのテンプレートのリンクを Cowork に渡し、ダッシュボードの更新を依頼します。標準のダッシュボードだけに縛られません。
5. Cowork がプランのデータを読み、テンプレートを埋めます。できあがりには、エグゼクティブサマリー、プランの健全性、タスクの進捗、週あたりの完了数が含まれます。それだけでなく、想定されるリスクと対策も載っており、単にタスクを数えるだけの分析を超えている、と説明されています。

**(2) 期限が危ないタスクの実行**

1. プランの中に、ヘルプセンター記事のタスクがあり、リスクありとされています。
2. Amber は多くを説明せず、このタスクの作業を始めるよう Cowork に依頼します。詳細は Planner のノートに、関連する添付ファイルはタスクにあるため、Cowork がそれらを取得して使います。情報が足りない箇所は Amber に確認します。
3. Cowork は 4 本のヘルプセンター記事のドラフトを作成します。完了後、ドラフトをリンクしてタスクを in progress にするか尋ねられ、Amber は承諾します。
4. 4 本の記事はかなり詳細で、情報が足りない部分は人が入力できるようにハイライトされています。Cowork は、チームにない内容を書いたふりをしません。何を公開するかの最終判断は常に人にある、という説明です。
5. Planner 側のタスクは in progress になり、4 本の添付ファイルも付いています。会話は Cowork で始まっても、文脈は Planner に残る点が強調されました。

**(3) Excel からの移行**

1. Amber のチームは Excel でもプランを管理しています。Excel へのリンクを渡して、Planner にプランを作るよう Cowork に依頼します。
2. Excel は Planner のフィールドや機能と 1 対 1 に対応するとは限りません。そこで Cowork は、引き継げない項目や、直接対応しない項目を示し、どうマッピングするかの入力を求めます。Amber が回答することで、移行後の姿に意外なことが起きないようにします。
3. Excel には 100 を超えるタスクと 350 を超えるチェックリスト項目があり、すべて Planner に移されました。バケットも、100 を超えるタスクも、ステータスも引き継がれています。

**(4) Premium プランの読み取りと Basic プランへの移行**

ここまでの作業は、統合された **basic plan** タイプの上で行われていました。Amber のチームには premium plan もあります。発表では、AI 機能が最も豊富に使えるのは basic plan だと説明されています。Cowork には **Dataverse connector** があり、Dataverse の情報を読めるため、premium plan に対しても basic plan と同様の分析が**読み取り専用**でできます。

Amber は premium plan の上位リスクを尋ね、Cowork は Dataverse からプロジェクト情報を読んで、注意すべき主要リスクの要約を返しました。さらに、最新機能と主要な AI 連携は unified basic plan にあるため、この premium plan を basic に移行したいと考えます。「この plan から basic plan を作って」と依頼するだけで Cowork が実行し、元の premium plan と同じ情報を持つ basic plan ができます。従来は手作業が多かった作業が自動化される、と述べられています。

### 5.6 Planner plugin と Planner agent の強化（Howard 氏の補足）

Howard 氏は、Cowork 向けの新しい plugin について次のように補足しています。

- 現在出荷の準備を進めている段階で、**Frontier Public** で試すことができ、近く GA にする予定
- Planner の中にあるツールが基本的にすべて Cowork から使える
- plugin であるため、キーノートで触れられたとおり、Autopilot や Copilot の code 系の環境でも動く。新しい plugin フレームワークの展開に合わせて、エコシステム全体で使えるようになる（聞き取りでは「Copilot code」と聞こえますが、正式名称は音声認識の都合で確定できません）
- インポート、作成、タスクの完了、Planner の文脈からのコンテンツ作成などを自動化できる
- 試してフィードバックを送ってほしい。plugin をより良くするため、フィードバックを見ている

Planner の中の Planner agent も強化されたとして、次を挙げています。

- 背後のモデルが新しくなり、**GPT-6** を使っている（発表の発言どおり）
- 左側のペインのコンテンツを、右側のエージェントとのチャットで編集できる。Planner 内で完全に統合されている
- タスクの更新や、Planner agent へのタスクの割り当てができる
- チャットだけで終わらず、ヘルプドキュメントや動画など、コンテンツそのものを作る

### 5.7 デモ 3：Autopilot の Fern が期限切れタスクをフォローする

最後に急遽入ったというデモです。ペルソナは、同じ launch プランを扱うマーケティングマネージャーの Carol で、Carol には Autopilot の「**Fern**」が割り当てられています。（プラン名は「Caldova Assist」と聞こえますが、音声認識の都合で表記が確定できません。）

Carol には、顧客向けローンチのメールキャンペーンというタスクが 1 件割り当てられており、期限が過ぎています。これまでは Planner を自分で開かないと気づけませんでした。そこで Carol は Fern に、次の内容の routine を作るよう依頼します。

- 毎日、そのプランから Carol に割り当てられた期限切れタスクを探す
- 期限切れがあれば、自律的にドラフトを作り始める
- そのドラフトを Teams とメールで Carol に送って確認させる
- Carol のフィードバックを受けて Fern が再度作業し、更新を送る

デモの流れは次のとおりです。

1. routine が「routines」タブに作成される。短いプロンプトから、Carol の求めた内容を満たす複雑な routine が作られた、と説明された
2. routine は午前 9 時に実行されるよう設定されている。ここでは待たずに、その場で手動実行する
3. 数秒後、Teams に Fern からのメッセージが届き、作成されたドラフトへのリンクが付いている
4. メールも届き、Fern が確信を持てなかった、確認すべき点が書かれている
5. ドラフトを開くと、キャンペーンの数通のメールが、件名、プレビューテキスト、本文に入れる内容とともに作られている

発表者は、最初から完璧にはならないため、Carol が Fern と一緒に編集していく、と断っています。重要なのは、Carol が遅れていることに気づく前から、Fern がドラフトを用意してくれた点だとされています。

### 5.8 各 Copilot の使い分けと unified plans（Howard 氏の説明）

Howard 氏は、Planner が複数の Copilot に統合されていることを、スライドで次のように整理しています。

| 場面 | 説明されている内容 |
| ---- | ---- |
| Autopilot | 状況を常に最新に保ち、タスクを終わらせる手助けをしてくれる個人アシスタントとして優れている |
| Copilot（1 つ目の発話） | より深いプロジェクト管理に向く。複数のプランを見渡して、リスク評価などを行う portfolio 的な使い方もできる |
| Copilot（2 つ目の発話） | 「タスクを作る」「プランを作る」といった、仕事のシンプルな管理に向く |

> 注意：トランスクリプトでは、2 つ目と 3 つ目の行がどちらも「Copilot」と発話されています。発表ではそれぞれが Cowork と Copilot 本体のどちらを指すのかは明言されていないため、発話のままに記載しました。

なお、Copilot では音声機能が追加されたと説明されています。話しかけて「このタスクを 5 つ作って」と頼めるようになりました。

最後のスライドは、**unified plans** に関する取り組みです。

- Planner の**まったく新しいサービス**を構築した。basic plan を作ると使われるサービスで、basic plan にも custom columns などの premium 機能が含まれる
- この新サービスが、すべての Copilot、Teams 連携、Outlook 連携の背後にある
- unified plans を紹介する大きなブログを前日に公開しており、スライド下部のリンク（aka.ms unified plans）から読める
- 近いうちに、ユーザーはプランの種類を選ぶ必要がなくなる。1 種類のプランを作れば全機能が含まれ、ライセンスに応じて使える機能が絞られる
- basic plans、premium plans、To Do を、1 つの基盤と 1 つの UI に統合する。共通の API を持ち、Planner が作る MCP もこの基盤の上に作られる
- すべての Copilot に、似たデータ構造と API で情報が供給される
- sovereign cloud を含むすべてのクラウドで利用可能にする。展開は始まっていて、GCC にはすでに展開を開始し、DoD は「50% くらい」まで進んでいる

## 6. デモ・手順

このセッションではデモが行われています（画面を見せながらのナレーションで、実演の中心は Robin 氏です）。録音は音声のみのため、画面上のボタン名や入力した文言の細部は確認できません。以下は語られた内容です。

### 6.1 休暇明けのキャッチアップ（Copilot → Planner → Researcher）

1. Amber が Copilot に、不在中に変わったこと、決まったこと、自分への対応事項を尋ねる
2. Copilot がメール・Teams・Planner の情報からブリーフィングを返す（根拠の参照付き、要確認の印付き）
3. 自分に対応が必要な項目について、期限と文脈付きでタスクを作成するよう依頼する
4. 保存先を聞かれて Planner を選ぶ。My Tasks に 8 件のタスクが作られる
5. My Tasks の Upcoming、Flagged emails、Assigned to me、並べ替え・グループ化を確認する
6. 各国の AI 開示要件を調べるタスクを追加し、割り当てに Researcher を選ぶ
7. TaskChat で Researcher とやり取りし（国別の比較レポートを依頼）、出力をレビューして完了にする

### 6.2 プラン作成から割り当て、エージェント実行まで

1. ゴール（Waypoint の出荷）を説明して、Planner にプランを作るよう Copilot に依頼する
2. 提案（タスク、ゴール、バケット、優先度、期限）をレビューしてから、作成を指示する
3. Planner agent に職能を伝えてタスクの割り当て案を出させ、各職能の担当者名を伝えて割り当てを依頼する
4. 割り当て案を確認し、保存を 1 回クリックして反映する
5. データモデル作成のタスクを Planner agent に割り当てる（Amber 自身も human in the loop として割り当てられる）
6. AI agent activity タブとボードビュー（AI agent tasks でグループ化）で進捗を追い、完了後に Loop コンポーネントの出力をレビューして完了にする

### 6.3 Cowork と Planner plugin

1. plugin ストアで Planner を検索して install する
2. ダッシュボードを依頼し、HTML のダッシュボードを得る
3. チームのステータスレポートのテンプレートのリンクを渡し、ダッシュボードの更新を依頼する
4. ヘルプセンター記事のタスクについて、作業を始めるよう依頼する。4 本のドラフトが作られ、タスクのリンクと in progress への変更を承諾する
5. Excel のリンクを渡してプランの作成を依頼し、マッピングの質問に回答する。100 を超えるタスクと 350 を超えるチェックリスト項目が Planner に移る
6. Dataverse connector 経由で premium plan の上位リスクを尋ねる（読み取り専用）
7. 「この premium plan から basic plan を作って」と依頼し、basic plan を得る

### 6.4 Autopilot の routine（Fern）

1. Fern に routine の作成を依頼する（毎日、Carol に割り当てられた期限切れタスクを探し、ドラフトを作成し、Teams とメールで送る）
2. routines タブに routine が作られる。午前 9 時の実行設定だが、その場で実行する
3. Teams のメッセージ（ドラフトへのリンク付き）とメール（要確認事項付き）が届く
4. ドラフトを開き、キャンペーンメールの件名、プレビューテキスト、本文の内容を確認する

## 7. 注意点・発表者の気付き

- **最終判断は人にある。** プランの提案、割り当て、記事の公開内容のいずれも、エージェントは提案や下書きを出し、人が確認する流れだと繰り返されています。
- **エージェントは情報を補わない。** Cowork が作ったヘルプ記事では、情報がない部分がハイライトされ、人が追記する前提になっていました。
- **Excel からの移行は 1 対 1 とは限らない。** 引き継げない項目や直接対応しない項目は Cowork が指摘し、マッピングは人が決めます。
- **Premium プランは Cowork からは読み取り専用。** AI 機能が最も豊富に使えるのは basic plan（unified）で、premium から basic への変換を Cowork に任せる流れが示されました。
- **初回から完璧ではない。** Fern のドラフトについて、最初の 1 回で完成するものではなく、編集が前提だと述べられています。
- **plugin はまだ Frontier Public の段階。** GA は近日予定とされ、日付は示されていません。
- **展開途中の機能がある。** unified plans は展開中で、GCC には展開開始済み、DoD は約 50% と説明されています。

## 8. 利用者にとっての利点

発表で語られた利点は、主に作業時間と手間の削減、そして文脈の一元化です。

- 休暇明けの状況把握から、タスク作成、調査の開始までを数分で行える
- プランの骨組み（タスク、ゴール、バケット、優先度、期限）の作成と、タスクの割り当てを手作業でやらなくてよい
- 調査・データモデル・記事ドラフトなどのタスクを、エージェントに任せられる。会話や成果物がタスクの中に残る
- チーム独自のステータスレポートのテンプレートを使ってダッシュボードを作れる
- 100 を超えるタスクと 350 を超えるチェックリスト項目を持つ Excel のプランを、Planner に移せる
- premium plan を手作業なしで basic plan に変換し、最新の AI 連携を使える
- Autopilot の routine により、Planner を毎日開かなくても期限切れの作業に気づき、ドラフトまで受け取れる
- 将来的にはプランの種類を選ばずに済み、ライセンスに応じた機能が 1 つの基盤・UI・API で提供される

## 9. まとめ

Planner は、計画やタスクの管理にとどまらず、Copilot 本体、Planner agent、Cowork、Autopilot といったエージェントと結びついて、仕事を実際に終わらせる場所へと広がっています。個人のタスクは To Do の使い勝手を取り込んだ My Tasks と default plan に集まり、Planner のスキルは Copilot 本体からも使えるようになりました。

Cowork 向け Planner plugin は Frontier Public で試せ、近く GA の予定です。その背後にあるのが、basic・premium・To Do を 1 つに束ねる unified plans の新しい Planner サービスです。いずれのデモでも、提案と下書きはエージェントが出し、最終判断は人が行う、という形が一貫して示されていました。
