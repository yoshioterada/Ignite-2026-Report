# BRK228 What Microsoft Benefit Is Right for Your Use Case?

## 1. はじめに

このセッションは、「AI を導入したいが、どこから始め、どう投資し、どう広げればよいか」という悩みに対して、Microsoft が用意している支援プログラムの **Frontier Accelerate** を紹介する 45 分のブレークアウトです。

構成は大きく 2 つです。前半は、Sarah、Alex、Priya という 3 人の架空のシナリオで「AI で何が変わるか」を示し、そのうえで Frontier Accelerate の内容（専門家の支援、投資・節約の仕組み、スキル開発）を説明します。後半では、Telefonica Germany の事例を、動画と、同社のテクニカルリードとのトークで紹介します。

結論として語られているのは、**テクノロジーだけでは成果は出ず、「専門家の支援」「投資の後押し」「スキル開発」の 3 つがそろったとき成果につながる**という点です。

## 3. 何に関する発表か

### 3.1 テーマと背景

発表の出発点は、「AI のアイデアはあるのに、実装する時間が足りない」という、参加者の多くが当てはまる状況（冒頭の挙手で「満席」と表現）です。そのうえで、Deloitte の調査として、次の数字が示されました。

- 調査対象は、3,000 人を超えるビジネス・IT リーダー
- **70% を超えるリーダー**が、AI が売上を押し上げると期待している
- 実際に成果が出ているのは**約 30%** にとどまる

そこで、「成果を出している 30% は何が違うのか」が問いになり、それに対する答えが、テクノロジーに加えて「正しいパートナーシップ」を組み合わせる Frontier Accelerate だという流れです。

## 5. 発表内容の詳細

### 5.1 3 つのドア

登壇者は、AI の効果が出る領域を「3 つのドア」にたとえました。

| ドア | 内容 |
| --- | --- |
| Everyday work（日々の仕事） | すべての従業員が、毎日より良く働けるようにする |
| Business processes（ビジネスプロセス） | 仕事の流れの摩擦を取り除く |
| Secure foundation（セキュアな基盤） | 自信を持って AI をスケールできるようにする |

発表では、「始める場所に正解は 1 つではない」とされています。以降のシナリオは、**あくまで仮想のものです**（hypothetical scenarios と説明）。

### 5.2 シナリオ 1：Sarah（日々の仕事）

Sarah は、6 週間後に新製品をローンチしようとしています。やることは次のとおりです。

- すべてのメール、チャット、メッセージを追いかける
- 日々変わるコンテキストを踏まえた計画を作る
- 上司など関係者に向けて状況報告（status report）を作り、適切なタイミングで適切な人にフォローアップする

課題は、情報が散らばっていることと、作業の多くが手作業であることです。登壇者は「AI はタスクを助けるが、仕事を完了させることはまれ」とも述べています。

ここで示された解決策は次のとおりです。

- アプリに組み込まれた Copilot で、会話や意思決定を早く把握できる。
- 人、プロジェクト、会話から適切なコンテキストを引き出す。これを「Work IQ が働いている」と表現しています。
- ステータスレポートは Cowork が最初から最後まで処理し、エージェントがフォローアップを追跡して、期限を過ぎたものを管理する。
- Sarah は、**レビューして承認し、統制を保つ**だけでよい。「プロジェクトを追いかける側から、率いる側へ」というのがキーメッセージです。

### 5.3 シナリオ 2：Alex（ビジネスプロセス）

Alex は Sarah の会社でサプライチェーンを率いています。Sarah が発売する製品を顧客に届ける役割です。仕事は 3 つに集約されます。

1. 顧客の注文を順調に進める
2. 顧客に影響が出る前にサプライチェーンの問題を把握する
3. 自分たちに固有の要件に合うようにプロセスを作り直す

想定の問題は、ローンチの 1 週間前に主要サプライヤーが遅延する、というものです。Alex は、影響を受ける注文の特定、供給の振り替え先の確認、互いに連携していないシステムやチームをまたいだ情報の突き合わせをしなければなりません。それらを揃えたときには、すでに問題が顧客に届いて不満が出ています。

同じ遅延を、技術を使って「再生」し直すと、次のようになります。

- Copilot とエージェントが注文を順調に保ち、営業・サービスチームに通知して、**顧客に先に連絡できるようにする**。
- Dynamics 365 のエージェントが、遅延を早く見つけ、在庫の振り替え先の選択肢を提案する。
- Alex のチームは、**Copilot Studio** で、サプライヤーへの確認を行う独自のエージェント（supplier check-in agent）を作れる。新しい部品を継ぎ合わせる必要はなく、既存の業務システムとデータソースに対応している。

要点は、「混乱に後追いで反応するのではなく、先回りできる」ことです。

### 5.4 シナリオ 3：Priya（セキュアな基盤）

Priya は、同じ会社で AI のセキュリティを担当しています。Sarah と Alex が導入したすべてのエージェントの安全性を確保する立場です。次の 3 つをしなければなりません。

- すべてのエージェントとユーザーの動きを可視化する
- 誰が・何がどのデータにアクセスできるかを制御する
- すべてのデバイス上の、すべての人の機密データを守る

課題は、「AI とエージェントが、守れる速度を超えて増えている」ことです。登壇者は、「AI は、見える速度より、制御できる速度より、保護できる速度より速く広がっている」と表現しました。Priya は AI を止めたいのではなく、**安全に「イエス」と言いたい**立場として描かれています。

解決策として挙げられたのは次の 3 つです。

| 製品 | 発表での役割の説明 |
| --- | --- |
| Agent 365 | 会社内のすべてのエージェントを把握し、所有者、アクセスできる範囲、廃止すべきものを知る |
| Entra | エージェントと人が、必要なアクセスだけを持てるようにする |
| Purview と Defender | 過剰共有（oversharing）を防ぎ、脅威を発生前に防ぐ |

さらに、これらを別々のツールとして組み合わせる必要はなく、**Microsoft 365 E7** で、従業員が使うインテリジェンスと Priya が求める信頼が 1 つのソリューションにまとまる、と説明されています（E7 の中身の詳細は、発表では説明されていません）。

### 5.5 Frontier Accelerate

3 つのシナリオを受けて、登壇者は「テクノロジーは可能性を作るが、それを実現するのは適切なパートナーシップ」であり、それが成果を出している 30% の違いだと述べています。この考え方の延長として紹介されたのが **Frontier Accelerate** です。Frontier Accelerate は、Microsoft の専門家、投資に関する特典、スケールの支援を 1 つにまとめた、**簡素化された Microsoft のベネフィットパッケージ**と説明されました（動画でも紹介）。

動画で語られた内容は次のとおりです。

- 変革のビジョンを実践に移す支援として、Microsoft のスペシャリストと認定パートナーが、スケール可能なソリューションの計画と構築を支援する。
- 投資からより多くの価値を得るため、利用可能な価格オファー、資金面のリソース、節約の機会を探せる。
- チームが新しい技術を実践できるよう、セルフペースの学習と、専門家主導のトレーニングで有能なチームを育てる。
- 計画、ソリューション構築、チームの準備に至るまで、専門パートナーのネットワークが支える。
- これらの特典は Microsoft のソリューション全体に及ぶ。始めるには、Microsoft のアカウントチームか認定パートナーに連絡する。

動画のあと、登壇者は「Frontier Accelerate は 1 つのソリューションに限定されない」と強調し、このセッションでは **Copilot、ビジネスプロセス、AI-ready な生産性** に焦点を当てると述べています。

登壇者は、どこから始めても成果を加速させるのは次の 3 つで、それぞれが先ほどの 3 人のシナリオに対応していると説明しています。

1. **専門家（Expertise）：** 始めるための自信になる。適切な専門家は、Priya が AI を大規模に守るために、どこから始めてどう広げるかを知る助けになる。
2. **投資（Investments）：** スケールするためのもの。適切な投資支援は、Alex がサプライヤーのエージェントを最初の工場の先へ広げる助けになる。
3. **スキル開発（Skilling）：** 習慣として定着させるためのもの。適切なスキル開発は、Copilot と Cowork を Sarah から彼女のチーム、組織全体へ広げる助けになる。

この 3 つがそろうと、テクノロジーを成果に変えやすくなる、という説明です。

#### 5.5.1 信頼できる専門家（Trusted expertise）

「社内にノウハウを一から作ることなく、実践的な支援を受けて立ち上げたい」場面向けの特典が紹介されました。

| 特典・サービス | 発表での説明 |
| --- | --- |
| FastTrack | Microsoft のスペシャリストが、Microsoft 365 Copilot とセキュリティソリューションの導入・定着を支援する |
| 専門パートナー | 組織や業界に合った実践的な専門知識を提供する |
| Dynamics 365 Activate | **プレビュー中**。既存の業務アプリケーション環境を評価し、移行と実装の道のりを加速する |
| Cloud Accelerate Factory | 名前のみ紹介（詳細な説明なし） |
| security for AI assessment / AI readiness assessment | 目標に対して現在地を把握するためのアセスメント |

#### 5.5.2 節約と投資（Savings and investments）

Alex が複数の工場にエージェントを展開したい、という先ほどの想定を引き合いに、複数の場所で同時に AI を使いたいが、予算が課題になる、という前提で次の内容が紹介されました。

- **AI Flex Plan**：Ignite で**本日発表**された、最新の購買モデル。Copilot、Foundry、Security、GitHub、Microsoft IQ などごとに別々の予算を立てなくても、Microsoft の AI 特典全体にまたがって支出できる、と説明されました（列挙された製品名のうち 1 つは、音声認識の都合で表記が確定できません。トランスクリプトでは "Perception" と聞こえます）。「それぞれ専用の予算枠が必要だった状態を置き換える」という位置づけです。
- **Copilot の試用とプロモーション**：大規模に投資する前に、価値を確かめられる。

#### 5.5.3 スキルを持ったチーム（Skilled teams）

Sarah のシナリオを引き合いに、「技術は、人が実際に使って初めて効果が出る」という前提で、個人・チーム・組織の 3 段階が説明されました。

1. **個人**：AI Skills Navigator を通じた、無料のセルフペース学習とオンデマンドのラボ。自分の役割に合わせて、自分のペースで学べる。
2. **チーム**：discovery sessions で、チームの日常業務のどこに AI が当てはまるかを見つける。
3. **組織全体**：「AI in a day」ワークショップで、組織全体に展開し、全員の 1 日に AI がどう違いを生むかを確認する。

これらは特典のごく一部であり、Web サイトに詳細があること、Microsoft のアカウントチームや専門パートナーが、組織や業界に合う組み合わせを見つける支援ができることも案内されました。

### 5.6 顧客事例：Telefonica Germany

#### 5.6.1 紹介と動画

事例パートの Microsoft の登壇者は、Telefonica Germany を、ドイツの 4 つのモバイルネットワーク事業者の 1 つで、数百万人の顧客にサービスを提供している会社と紹介しました。取り組みの出発点は、**信頼と顧客データの保護**で、Copilot をスケールし、その後エージェントのプラットフォームに進むために、セキュアな基盤が必要だったと説明されています。

続いて流れた動画の内容は次のとおりです（動画内の発言のため、発言者は特定できません）。

- 通信業界では、データの信頼・セキュリティ・機密性が極めて重要。ドイツ政府の要件は単純で、「データが環境の外に出てはならない」。
- 複雑な環境があり、データを守ることが重要。誰も「3 か月で達成できる」とは信じていなかった。
- フランチャイズ・間接パートナー経由で販売しており、約 13,000 のオペレーターがいる。彼らは自分のハードウェアで作業しており、顧客データ（銀行口座、住所など）を扱う。
- 一時的に「応急処置（duct tape）」で対応することもできたが、構造的な解決を選んだ。
- 代替案は、完全な仮想マシンを渡してブラウザーを起動させる方法だったが、実際にはアプリだけを公開する（publish）方式にした。ネイティブに見え、利用者のデバイスで動き、より安全である。ハードウェアとソフトウェアを切り離し、**PC のハードディスクに顧客データは存在しない**。
- 3 つのレイヤーで構成する（次の表）。
- 最初の 2 週間で 3,000 ユーザー、フル展開は**予定どおり**完了。運用コストは **90%** 削減、プロビジョニングは **80%** 削減、13,000 ユーザーが稼働。

| レイヤー | 動画での説明 |
| --- | --- |
| Entra ID | MFA、パスキーなど、Entra の標準機能によるセキュリティ層 |
| Windows 365 | アプリを公開し、その背後に Web アプリケーションを置くことで、直接はアクセスさせない（音声では「Windows 360」と聞こえます） |
| DLP（Purview）と条件付きアクセス | プロセスに必要なデータへのアクセスは与え、持ち出しが許可されないものはブロックする |

> 補足：トランスクリプトでは製品名が "Windows 360"（動画）と "Windows 365"（Raid 氏の発言）の 2 通りに聞こえます。本書では、Raid 氏の発言に合わせて Windows 365 と表記しています。

#### 5.6.2 Raid 氏とのトーク

Microsoft の登壇者と Raid 氏の対談で語られた内容を、質問ごとに整理します。

**役割と解決したかった課題**

- Raid 氏は、アプリケーションと新技術を、従業員にとって使いやすい形で導入することと、良いユーザー体験を重視していると述べています。
- 課題は、13,000 人のユーザーが間接パートナーとして、フランチャイズ経由で製品を販売しており、自前のハードウェアを使っていること。銀行口座や住所といった機微なデータを扱うため、安全な場所にデータを置く必要がある。
- すでに Citrix などの別のソリューションがあり、1 年を通じて複雑になり管理しづらくなっていた。そこで、「応急処置を重ねるのではなく構造的な変化」を求めて、**Windows 365** を選んだ。

**専門家の支援（Expertise）**

- 3 か月（90 日）で 13,000 ユーザーというスケジュールで、多くの課題があった。汎用的な支援ではなく、すでに同様のことを経験した人が、自社環境で実際に手を動かしてくれる支援が必要だった。
- Microsoft は、その専門性を提供した。例として、SailPoint を Azure に導入するといった、同社が抱えていた具体的な問題に対する専門家の支援がある。
- また、プロバイダー（パートナー）が実装に参加できるよう、Microsoft が支援した。

**投資（Investment）**

- 13,000 ユーザー規模の大きな投資のため、数字が成立している必要があった。テストや試行の余裕はなかった。
- Microsoft から良い商用オファー（commercial offer）を受けた。さらに、バウチャー（vouchers）により、パートナー（音声では「M3」と聞こえます。表記が確定できません）がプロジェクトを支援できる体制が整った。
- 結果として、良い商用オファーを通じて投資の一部が戻り、パートナーも直接プロジェクトを支援できた。

**導入と変更管理（Adoption and change management）**

- Copilot を導入する際は、ドイツには労使協議会（workers' council）があり、AI や Copilot の導入に多くの要件があった。
- ライセンスを払っても、誰も使い方が分からない状態を避けるため、適切なトレーニングが必要だった。
- 同時に **2,000 人超のユーザー**へ Copilot を導入したため、多くのトレーニングが必要だった。Microsoft のソリューションアーキテクトやクラウドエンジニアがトレーニングを提供し、**ドイツ語のネイティブスピーカーによる実施**が求められた。理解できる言語で学べたため、日々の業務に取り入れられた。
- 労使協議会への対応では、Microsoft Germany が自社でどう解決したかの経験を共有してくれた。これが、労使協議会の支持を得る方法を見つけるのに役立った。

**成果**

- 最大の成果は**信頼（trust）**。90 日間で 13,000 人という、小売りに属する重要なユーザー群（会社の収益に直結するため、中断は許されない）への展開が成功した。
- 「信頼は自動的にイネーブラーになる」と述べ、プロジェクトが成功すると、次はより大きなプロジェクトを任される、という例を挙げています。
- 運用コストについて、Raid 氏は **13,000 人で 80% 減**と述べています（動画では運用コスト 90% 減、プロビジョニング 80% 減とされています。発表では両者の違いについての説明はありません）。

**今後の予定**

## 7. 注意点・発表者の気付き

## 8. 利用者にとっての利点

## 9. まとめ

AI の成果を出している組織は 30% にとどまる（Deloitte の調査）という前提で、このセッションは、成果を分けるのは技術だけではなく、**専門家の支援、投資の後押し、スキル開発**の 3 つだと説明しました。Microsoft はこれらを、簡素化されたベネフィットパッケージ **Frontier Accelerate** にまとめています。

Sarah（日々の仕事）、Alex（ビジネスプロセス）、Priya（セキュアな基盤）という 3 つの入り口のどこから始めても使えます。Ignite で発表された AI Flex Plan や、プレビュー中の Dynamics 365 Activate も、この中に含まれています。

Telefonica Germany の事例では、13,000 ユーザーを 90 日で Windows 365 に展開し、2,000 人超に Copilot を導入しました。Raid 氏のアドバイスは、「ソリューションではなく、問題から始める。ユーザー体験を忘れない」というものでした。
