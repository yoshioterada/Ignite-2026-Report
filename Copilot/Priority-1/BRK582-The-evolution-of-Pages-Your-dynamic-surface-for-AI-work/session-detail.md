# BRK582 The evolution of Pages: Your dynamic surface for AI work

## 1. はじめに

このセッションは、Microsoft 365 の新しいファイル形式である **Pages** を、デモ中心で紹介する 45 分のブレークアウトです。Pages は、Word、Excel、PowerPoint に続く「4 つ目の種類」のファイルとして語られており、登壇者は「AI canvas for work」と呼んでいます。HTML を基盤にして、見た目が豊かで、更新され続け、共同編集もできる成果物を、プロンプトから作るという内容です。

発表の前半は、「ページ」という道具の歴史から Pages の位置づけを説明しています。後半は、Cowork などを使った多数のデモです。レポート、ダッシュボード、3D の製品モデル、スペックなどが、短いプロンプトから生成される様子が示されました。Copilot の次の成果物形式に興味がある方向けの内容です。

> 注意：デモの対象は Frontier プログラムで順次提供される機能です。提供状況は 9 章のまとめと 5.10 の記述のとおり、発表時点の予定です。

## 4. 発表者が伝えたいメッセージ

登壇者が繰り返したのは、次の 3 点です。

- **Pages は成果物を「生きた」ものにする。** 従来の成果物は、作った瞬間から更新されない「dead documents」でした。Pages は常に更新でき、毎朝自動で更新するレポートも作れます。
- **best of the web × best of M365。** Web の表現力と適応性を持ちつつ、M365 としてのセキュリティ、コンプライアンス、共同編集を備えています。
- **作業の中心は、成果物を作ることから、目標を達成することへ。** agent に指示して成果物を生成させる使い方が広がり、Pages はその成果物の置き場所になります。

## 5. 発表内容の詳細

### 5.1 ページの歴史と、作る人・読む人の広がり

登壇者は、Pages の話を 4,000 年前のパピルス（古代エジプト）から始めています（2,000 年前に現代的な紙が生まれたとも述べています）。ページは、頭の中にあるものを他の人が見られる形にし、持ち運べて、本人がいなくても読めるようにしました。ただし、紙は高価で、スキルと知識のある一部の人しか使いこなせませんでした。

客席への問いかけとして、読み書きできる大人の数が、できない大人を上回ったのはいつか、という話がありました。答えは 1950 年代で、現在は 80% 程度です。1990 年代に Web が登場すると、ページは双方向になりました。インターネットのアクセスが世界の 50% を超えたのは 2016 年ごろで、「読む」側の格差は約 30 年で縮まったと説明しています。

では「作る」側はどうか。JavaScript の開発者は約 2,000 万人で、プロでない人を含めて倍の 4,000 万人としても、世界人口の 0.5% 未満です。残りの **99.5%** は、Web ページを十分に作れないことになります。AI の時代には、アイデアを自然言語で表現し、AI がそれを伝えられる形にしてくれます。

### 5.2 assistant の時代から agent の時代へ

もう 1 人の登壇者は、モデルの力で、本来は何百人もの専門家が必要なものを作れるようになった点が大きな変化だと述べています。ただし、assistant の時代は、同じ作業を速く・専門的にこなすだけで、Word や PowerPoint、Excel を開いたら、何を入れるかは自分で決める必要があり、運転席には人がいる状態です。

agent が登場すると、人は成果物の作成者から、agent に指示して欲しいものを生成させる立場に変わります。日々の役割は、成果物を作って伝えることから、**目標を達成すること** に移りつつあるという主張です。最初の登壇者は、これは、アイデアを持ち、伝え、何かが起きてほしいという、紙のページの時代から変わらない目的に近づく流れだと補足しています。

なお、この前後に短い映像が上映されましたが、音声のトランスクリプトには内容が含まれていません。登壇者は、映像について「約束した映画」と話すにとどまっています。

### 5.3 Pages の考え方：best of the web と best of M365

**best of the web** として、3 つの要素が挙げられました。

1. **表現力**：Web は表現が豊かで美しい。その芸術的な表現を、Pages を使うすべての人に届けたい。
2. **適応性**：仕事はスマートフォン、ブラウザー、さまざまな画面サイズで行われる。HTML と Web は、情報の一貫性を失わずに、それらの間を移動できる。デバイスや画面サイズごとにページを書き直す必要はない。
3. **agent が理解しやすい**：HTML など Web の基盤は、agent が非常によく理解しているコードである。

「どの agent やアシスタントに自然言語で頼んでも、きれいなページは作れるはずだ。Microsoft は何が違うのか」という問いに対する答えが、もう半分の **best of M365** です。登壇者が客席の IT 管理者に、「信頼された JavaScript で動く HTML が、社内データを共有して回る世界にワクワクするか」と尋ねたところ、手は上がらなかったとのことです。

Pages は、Word、Excel、PowerPoint に期待されることを、4 つ目の種類のファイルとしてすべて満たします。

| 観点 | 説明 |
| ---- | ---- |
| trusted and secure | コンプライアンスとガバナンスを備える。Word などと同じ場所に保存され、同じ方法で共有され、eDiscovery や監査証跡も同じように使える |
| collaborative | ページを生成した後に、手で調整したいときに、毎回 agent に頼まなくてもよい。直接編集できる |
| M365 native | Word、Excel、PowerPoint が現れる場所のすべてに表示される。Copilot、検索、Teams、共有など |

この 2 つを合わせたものが、AI canvas for work だという説明です。

### 5.4 提供される場所

デモは Cowork で行いますが、Pages は chat、workspaces でも利用可能になり、autopilot にも来る予定だと説明されています。4 つのエンドポイントに、Frontier の複数の段階を通じて展開されているとのことです。入手方法は最後に述べられています（5.10 を参照）。

### 5.5 既成の Pages の例

当日の朝に生成した Pages が紹介されました。実際に最初から使える状態の見本という位置づけです。

- **agentic wave のレポート**：硬い構造の文書から、没入感があり、生き生きして、創造性のあるものへ。アニメーションはオン・オフを選べる。スクロールに沿って各章が表示され、すべてライブで動的。クリックで操作でき、hover で詳しい情報が出る。ループの図があり、内容から自動でスライドショー形式のプレゼンテーションも作られる。
- **assistant 分野のレポート**：「パーソナルアシスタント」の分野の動向を追うために、毎朝生成するレポート（分野名は音声認識の都合で表記が確定できません）。当日の朝の時点の最新更新は 11 月 17〜18 日分で、「A16Z が、また別のパーソナルアシスタントのモデルに投資したようだ」という内容が読める。分野全体のタイムライン（履歴）も見られる。成果物が作った瞬間に「死ぬ」のではなく、時間をかけて自分自身を更新し続けるレポートだと説明されています。
- **株式市場と AI の分析**：データを、動くアニメーションに変換したもの。自動再生でも、一時停止して自分でスクロールして見ることもできる。登壇者の質問に対して、動画ではなくライブであり、タイトルなどを選んで編集して変更できる、と答えています。
- **consumer AI のレポート**：データに基づく、より没入感のある形式で、動向を伝える。

### 5.6 launch hub を作る：プロンプトから共有まで

デモは、Cowork でプロンプトを入力するところから始まります。詳細は 6 章に書きます。ここでは、デモの中で語られた考え方を整理します。

- **チャットの限界**：Suf 氏は、多くの agent では左側にチャットペインがあり、会話が 1 本の線形スレッドになるため、スクロールするとコンテキストや有意義な結果が失われると指摘しています。Pages では、キャンバス上のどこでも「edit Copilot」をクリックでき、その指示はバックグラウンドで実行されます。その間も作業を続けられるため、**キャンバスから複数スレッドの agent 指示を出せる** と説明しています（サイドチャットも使えます）。
- **自動更新**：「毎日午前 9 時に更新する」という automation を、ページに付けられます。
- **共有**：リンクだけでなく、ページを「コンポーネント」としてコピーして、メールに貼り付けられます。受信者は、同じライブでインタラクティブな内容を、そのまま見られます。
- **保存先**：ファイルは OneDrive に保存されます。Copilot アプリのライブラリには、作成した Pages が一覧で出ます。
- **画面サイズへの適応**：同じページが、画面サイズに合わせて変わります。登壇者は、手元にスマートフォンがないので、デモはできませんが、電話でも没入できる表示になると述べています。

### 5.7 1 つのプロンプトで作ったスタイルの例

Scott 氏は、**1 回のプロンプトだけで、追加の編集なしに** 作ったと説明する、複数の Pages を見せました。

- 化粧品（skin care）会社向けの、次の時代のマーケティングブリーフ。生成された画像、プラン、アニメーション付きで、選択肢を選べる。
- 日本で鉄道に乗る方法のガイド。選択肢を選び、支払いに使うカードの種類まで見られる。
- コーヒー 1 杯の産地をたどる、National Geographic 風のレポート。豆の産地からカップに届くまでを追い、湯気の小さなアニメーションもある。
- 自宅を貸し出す人のためのガイドライン。
- ビデオポッドキャストを作るべきかの分析。オプションを選ぶと、動画に投資すべきだという提案が表示された。

Scott 氏は、これらの成果物が **テンプレートではなく**、トピックに合わせてスタイルが異なる点を強調しています。

### 5.8 prompt expansion と、3D・シミュレーション・brand kit

**prompt expansion**

自分のプロンプトに自信がないとき、通常の Copilot chat に「write an expanded co-work prompt for the following prompt」のように依頼し、その後にプロンプトを続けると、Cowork 向けに拡張したプロンプトが返ってきます。それをコピーして Cowork に貼り、よい初稿を得て、手動でも Copilot でも編集できます。Microsoft のスタック全体を使うので、メモリ、グラウンディング、仕事のコンテキストを持ち、より豊かなプロンプトが返ってくると説明しています。OneDrive の内容にもアクセスできます。もちろん、望むものが明確なら、細かく書いて同じ結果を得られます。

**Web の多様な表現**

Suf 氏は、Pages が best of the web を持つので、画像、音声、動き、アニメーション、3D も使えると述べています。紹介された例は次のとおりです。

- **Prius のエンジン**：エンジンの概略図（schematics）を入れて、物理ベースで動く表現を得る。EV の形式、エンジンの連鎖の働き、回生ブレーキの様子などを見られる。OneDrive 内のグラウンディングに基づいて 3D モデルも生成されるとのことです（質問への回答）。
- **F1 のラップ比較**：合成データ（synthetic data）に基づく、同一の 2 台の Mercedes の、ラップごとの比較。複数のカメラアングルで映像のように再生でき、特定のコーナーだけを見たり、エネルギーの落ち込みや加速を確認したりできる。直近の鈴鹿（Suzuka）のレースのシミュレーションとのこと。データエンジニアリング、3D モデリング、インタラクティブなダッシュボードを合わせると、これまでは 100 人ほどが必要だったはずだと述べています。
- **cobot（協働ロボット）**：3D で分解でき、各部品を調べ、タグ付けやフィードバックを付けられる。
- **バッテリー駆動の自転車**：EV モードでの見え方を表示でき、部品を 1 つずつ取り出し、バッテリーの各層まで展開して見られる。共同で、全員がフィードバックを返せることも想像できると述べています。

**brand kit**

Suf 氏は、成果物をブランドに沿わせることが重要だとして、**brand kit のサポートが「今後数週間のうち」に来る** と述べています。例として、Xbox のブランドを適用したレポートが示されました。モデルがデザインを解釈するのではなく、ユーザーが管理できる強力なデザイントークンのライブラリに従う仕組みで、複数のトークンライブラリを持ち込むこともできます。

### 5.9 リサーチ、要約、スペック、社内データ

Scott 氏は、Pages がコンテンツを豊かにするだけでなく、情報を最初に集めることもできると説明しています。

- **Web の調査**：このセッションの準備として、「2 presenter experiences」（音声のまま。意味は確定できません）について調べるよう Copilot（Cowork）に依頼したところ、YouTube や Ignite などを検索して、さまざまなヒントをまとめた。
- **長大な文書の要約**：EU で施行される規制（数千ページ、何度か改正）を、読みやすい形に要約する。自分のためのパーソナライズされたレポートとして視覚的に読め、グラウンディングされているため、追加の質問で詳細を確認できる。
- **社内データの活用（スペック）**：新機能の議論は、会議で話され、トランスクリプトが残る。それらを指して、スペックを書くよう依頼できる。Suf 氏は「スペックはもう書かない。作る」と返しています。デモでは、ブランドなしのページと、brand kit を適用したページを見比べ、フォントやアイコンが変わる様子が示されました。ハイレベルな主張、操作できる例、選択肢の選択、最後に要件がまとまっています。初稿であり、誤解や誤訳があれば、他の文書と同じように直接編集できます。
- **データレイクの利用状況**：データレイクに保存した利用データを、コネクタ経由で取得してまとめ、毎日更新する。ステータスレポートにも向く。デモのデータは実データではないと断っています。

**コメントによる委任**

Pages では、チャットではなく「コメント」のメタファーを使います。ドキュメントの複数の場所にコメントを付けて、Copilot や同僚を @mention できます。同僚に依頼を送ることも、邪魔したくない場合は Copilot を @mention してタスクと編集を任せることもできます。Suf 氏が「仕事を自分に委任しているのか」と冗談を言い、Scott 氏が「はい」と答える場面がありました。「autopilot でも、まもなくできる」という発言もありました。

**データの取得元**

組織の外にあるデータは、Cowork の plugins オプションで取得します。Scott 氏は fabric のオプションを追加済みで、それ以外に数百のコネクタがあるため、情報の保存場所を問わず取り込んで、豊かな Pages のグラウンディングに使えると述べています。

### 5.10 利用可能になる時期と使い方

M365 では、これまで人と人のコラボレーションがありましたが、今後は人と agent、さらに **agent 同士のコラボレーション** も起こるようになります。ビジネスの成果を生み出すエコシステム上のものが、Pages になることを期待していると述べています。

提供の予定は次のとおりです。

- **Frontier Public**：まもなく、chat と workspaces で開始する。
- **Cowork と Autopilot**：その後（coming soon）。

使い方として、Frontier プログラムに参加していて chat を使える場合は、「create a page」と入力するか、下のメニューで More から「draft a page」を選ぶと、Pages モードになります。workspaces が使える場合は、New の下から dashboard または report を作成できます。

## 6. デモ・手順

このセッションは、デモが大部分を占めます。録音は音声だけなので、画面上の操作は語られた範囲に限ります。デモは Cowork 上で行われています（Copilot chat も一部で使用）。

### 6.1 launch hub の作成と共有（Scott 氏）

1. Cowork でプロンプトを入力して、Pages を作る。ブランドを反映させたいので、OneDrive の folder にある、Caldova Biopharmaceuticals のブランド素材を使う。
2. 状況設定：Caldova は、Onvexa という新薬を発売する。複数のチームが追う情報が、メール、さまざまなデータソース、文書に散らばっており、発売に向けて 1 か所で見たい。
3. 「Cowork は情報を集め、計画を立て、まとめ始める」。画面右にブランドの情報収集が始まる様子が表示された。launch hub のページを作り、毎日午前 9 時の更新も設定するよう依頼している。
4. 完了を待たずに、事前に実行した同様のプロンプトの出力に切り替えた。
5. launch hub を確認した。最上部に最重要事項を示すマイクロダッシュボード（主要な数値）。下にスクロールして、患者を対象とした試験（patient studies）の状況、安全在庫（safety stock）、11 月 24 日のレビューに向けた readiness curve が見られる。すべて操作でき、更新のたびに最新の情報になる（当日は 11 月 18 日で、翌日には改善する見込みと説明）。launch までの計画も表示され、各項目にジャンプできる。
6. 「単なる Web ページではなく Pages なので編集できる」として、「everything turns on Anterra」の表記がわかりにくいため、Copilot に Anterra の説明を追加するよう依頼した（Anterra の綴りは音声認識の都合で確定できません）。この間、Suf 氏が、キャンバス上の Copilot はバックグラウンドで動くことを説明した。
7. ページの automation を確認した。「launch hub daily refresh」がオンになっており、毎日 9 時に実行される。
8. 共有：share を選び、「copy as component」でコピーして、メールに貼り付けた。リンクだけでなく、ライブでインタラクティブな形で送れ、送信前にメール内で直接編集もできる。
9. 宛先は Suf 氏。受信者も編集できる。
10. Copilot アプリのライブラリで、作成した Pages の一覧を確認した。ファイルは OneDrive にあり、OneDrive のホームでも同じ launch hub が見える。「Suf が最近編集した」と表示された。
11. 共同編集：Scott 氏が Suf 氏に、「demand is running ahead of plan」などの文言を編集するよう促すと、Suf 氏が編集した（文言は音声が途切れており、完全には確認できません）。Suf 氏のカーソルが動く様子が見え、Suf 氏はメールの受信箱から編集している。Scott 氏も下の部分を編集でき、「Hello, Ignite」というやり取りもあった。

その後、デモの後半で（5.9 の内容のとおり）、スペック、データレイクの利用状況、コメントによる @mention の例を見せています。

### 6.2 prompt expansion（Scott 氏）

1. 通常の Copilot chat を開く。
2. 「write an expanded co-work prompt for the following prompt」に続けて、「theater seating charts」というプロンプトを送る。
3. 拡張された Cowork 向けプロンプトが返ってくる。足りなかった指示が補われている。
4. それをコピーして Cowork に貼り付けて送ると、よい初稿が得られる。

## 7. 注意点・発表者の気付き

- Pages は **テンプレートではない**。トピックごとにスタイルが異なる、という点が強調されました。
- 最初の出力は「初稿」であり、誤解があれば直接編集できます。
- プロンプトに自信がないときは、prompt expansion を使います。要件が明確なら、細かく書けば同じ結果が得られます。
- brand kit は、発表時点では「今後数週間」の予定で、まだ提供されていません。
- Pages の提供は Frontier を通じた段階的な展開で、Cowork と Autopilot は coming soon です。
- デモの一部で使ったデータ（データレイクの利用状況など）は、実データではありません。F1 のデータも合成データです。
- 発表では、料金、ライセンス、対応言語、既存の Copilot Pages との関係の詳細については触れられていません。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **専門知識がなくても豊かな成果物を作れる**：Web ページを作れる人が世界人口の 0.5% 未満であるのに対し、自然言語から、アニメーション、3D、ダッシュボードを持つ Pages を作れる。以前なら何百人もの専門家が必要だったものが、数回のプロンプトで作れる。
- **成果物が最新に保たれる**：毎朝更新されるレポートや、毎日 9 時に更新される launch hub など、時間をかけて自分で更新する成果物を作れる。
- **IT 管理者の要件を満たせる**：M365 と同じ保存場所、共有方法、eDiscovery、監査証跡、コンプライアンス、ガバナンス。
- **共同編集**：人間はメールやライブラリから共同編集でき、コメントで同僚にも Copilot にも作業を依頼できる。
- **画面サイズに適応する**：デバイスごとに書き直す必要がない。
- **データ連携**：OneDrive、メール、会議のトランスクリプト、データレイク、Fabric や数百のコネクタをグラウンディングに使える。

## 9. まとめ

Pages は、Web の表現力・適応性と、M365 の信頼性・共同編集・ネイティブな統合を組み合わせた、4 つ目のファイル形式です。登壇者は、AI によって人の役割が成果物を作ることから目標を達成することに移るなかで、Pages が人と agent、そして agent 同士の共同作業の場になると述べました。

デモでは、launch hub の作成から、毎日の自動更新、メールでの共有、リアルタイムの共同編集までが示され、1 つのプロンプトから生まれるさまざまなスタイルの Pages、3D やシミュレーション、スペックの生成などが紹介されました。提供は Frontier Public の chat と workspaces がまもなく、Cowork と Autopilot が続く予定です。
