# THR851 Skills in Microsoft Copilot

## 1. はじめに

このセッションは、Microsoft Copilot の「skills（スキル）」を紹介する約 25 分のシアターセッションです。skills とは、自分の仕事の進め方、手順、基準、出来上がりのイメージを、Copilot が繰り返し使える指示としてまとめたものです。

前半では、skills の定義、種類、プラグインとの関係、Microsoft が目指す 5 つの成果を説明します。後半では、登壇者が自分の専門知識を Copilot の対話だけで skill にし、共有し、別のアプリでも使い、最後に管理者向けのガバナンスまで見せるデモを行います。

結論は最後に Sara が語った一文に集約されています。**Build it once, use it everywhere, govern centrally**（一度作れば、どこでも使え、集中管理できる）という考え方です。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/THR851](https://ignite.microsoft.com/en-US/sessions/THR851)

## 3. 何に関する発表か

テーマは「個人やチームの暗黙知を、Copilot の再利用可能な機能に変える」ことです。登壇者は、どの組織にも「提案書の構成」「レポートのレビュー方法」「業務を一貫して進めるやり方」といった専門知識があると切り出しています。その知識が個人の頭の中にあるだけだと、説明の繰り返し、アウトプットのばらつき、知識移転の難しさにつながります。skills はこの問題への答えとして紹介されます。

発表の流れは次のとおりです。

1. skills の定義と 3 つの狙い
2. skills の 4 種類
3. プラグイン、skill、tool の関係と、統一プラグインレジストリ
4. skills 体験で目指す 5 つの成果
5. ライブデモ（作成、更新、他の製品での再利用、共有、Microsoft 提供の skill、管理センター）
6. まとめと次のステップ

## 4. 発表者が伝えたいメッセージ

発表を通じた主張は、skills が「専門知識を一度だけ組織の資産にする仕組み」だという点です。Sara は、skills が次の 3 点で課題に応えると説明しています。

1. 繰り返しのワークフローを、ワンクリックで実行できる形にする。複数の手順、プロンプト、よくある作業の背景情報をまとめる。
2. 統一プラグインレジストリにより、Copilot の複数の画面（サーフェス）で再利用できる。例として、Copilot chat で作った skill を、作り直さずに PowerPoint で使えると説明しています。
3. 構造化されたガイダンスとワークフローにより、組織の業務コンテキストに基づいた、信頼できて一貫した成果を出せる。

Kishore のデモは、この主張を実演する構成です。自分の専門知識で skill を作ってから、15 分で価値提案書（value proposition document）の準備を終えます。さらに IT 管理者が大規模に展開・管理する流れまで見せ、「個人の生産性だけでなく、組織全体で安全に使うこと」が目的だと語っています。

## 5. 発表内容の詳細

### 5.1 skills とは何か

Sara の定義では、skills は「Copilot にタスクを一貫して実行させる方法を教える、再利用可能な指示またはワークフロー」です。セッション冒頭で提示された課題は、専門家が「何が良い出来か」「何を含めるか」「出す前に何を確認するか」を知っていても、その知識が個人に閉じていると広がらないことでした。

### 5.2 skills の 4 種類

Microsoft における skills は 4 種類に分けて説明されました。

| 種類 | 説明 |
| ---- | ---- |
| Built-in skills | Copilot に標準で含まれる Microsoft の機能。例として PDF と Word ファイルが挙げられています。 |
| Microsoft build skills | Microsoft が作成し、ストア経由で配布され、管理者が管理する skills。 |
| Third-party skills | 顧客、パートナー、メーカー（makers）が作る skills。ストア経由または直接の統合で提供され、管理者ツールで統制されます。 |
| Personal skills | 個人が作る skills。リンクまたはストア経由で共有でき、作成者によるコントロールと管理者の監督があります。 |

これらはすべて、他の機能と並んで **プラグインストア** で見つけられます。

### 5.3 プラグイン、skill、tool の関係

skills は現在、プラグインとしてパッケージ化されて配布されます。発表での整理は次のとおりです。

- **プラグイン**：skills、tools、場合によっては agents をまとめるコンテナー。配布が可能で、実際に仕事が行われる場所につながります。
- **skill**：プラグイン内にある再利用可能な指示。Markdown ファイルとして保存され、手順や基準を記し、Copilot に仕事の進め方を教えます。
- **tool**：agent が呼び出せる最小単位の操作。データの照会、API の呼び出し、特定のタスクの実行などです。

skill と tool を組み合わせることで agent が装備され、agent がユーザーの代わりに作業を調整して実行できます。このパッケージを統一プラグインレジストリで公開すると、skill は 1 つのアプリに閉じず、対応する Copilot の各サービスで見つけて再利用できます。

### 5.4 目指す 5 つの成果

Sara は、skills 体験で Microsoft が目指す成果を 5 つ挙げました。

| 観点 | 内容 |
| ---- | ---- |
| Definition（定義） | 業界標準に沿った、Microsoft 全体で共通の定義を設ける。skill は「AI に仕事のやり方を教える再利用可能な指示」と位置づけます。 |
| Discovery（発見） | skills を探す入口を 1 つに統一する。プラグインストアが主な入口で、関連機能もここで見つかります。 |
| Experience（体験） | Microsoft Copilot 全体で、skills の呼び出し方と管理体験を共通にする。 |
| Portability（可搬性） | 統一プラグインレジストリにより、管理者が承認済みプラグインを公開すれば、skills を Copilot の各サービスで使える。 |
| Governance（ガバナンス） | 管理センターで、インベントリ、デプロイ、ライフサイクル管理を一元的に行える。 |

### 5.5 デモの設定

Sara は、Contoso の product marketing manager である Kishore が数時間後に leadership review を控えている、という設定でデモを導入します。Kishore は、製品ローンチ向けの value prop document と、それに付ける PowerPoint を用意する必要があります。同種の資料を長年に何十本も作ってきたものの、「何が良い出来か」という専門知識は自分の頭の中にしかありません。

そこで次の流れを実演すると説明しています。

1. Copilot で専門知識を skill にして Sara と共有する。
2. 同じ skill を Word などで再利用する。
3. Microsoft 提供のファーストパーティ skill を使う。
4. 管理センターで、IT 管理者が大規模に展開する様子を見る。

## 6. デモ・手順

このセッションにはライブデモがあります。録音は音声のみのため、画面上の細部（ボタン名や入力の全文など）は確認できません。以下は、Kishore が語った範囲を、語られた順に整理したものです。

### 6.1 プラグインストアで既存の skill を確認する

1. 何かを作る前に、プラグインストアを開く。ストアは agents、skills、connectors など、Copilot を拡張するもの全般の入口で、標準で 300 以上のプラグインがあると説明しています。Microsoft やパートナーが作ったものや、IT 管理者がデプロイしたものがあります。
2. 使える skill がないか見たが、該当するものは見当たらなかった。Kishore は、これは当然だと述べています。自分の組織の value proposition document の作り方は、組織の知的財産や基準であり、Microsoft は知らないからです。

### 6.2 Copilot の自然言語で skill を作る

1. Copilot Home から、自然言語で skill 作成の会話を始める。新入社員に教えるのと同じ要領で、value proposition document に含めるべき内容（誰向けか、何に役立つか、主な便益、取り組む課題）を入力した。
2. Copilot が下書きを作成。Kishore は内容を確認し、2 点を追加で依頼した。1 つは、機能ではなく成果（outcome）から書き始めること。もう 1 つは、裏付けのできない主張をしないこと。これらは自分の専門知識だと説明しています。
3. Copilot が反映した下書きを確認し、「良さそうです。これを skill にしてください」という趣旨の指示を出した。これで Copilot が skill を作成した。
4. 作成の待ち時間に、プラグインストアで別の方法を見せた。skill は Copilot 以外で作成することもでき、業界標準の形式であり、GitHub などで見つけたものをパッケージとして取り込める、と説明しています。デモでは、別のサードパーティ製品で作った、プロダクト仕様書をレビューするための skill をアップロードした。
5. アップロード時には、Copilot が業界標準の形式に合っているかや、Microsoft の基準を満たすか、責任ある AI の原則に沿うかを検証すると説明しています。検証後は、他所で作った skill でも、指示を見たり編集したりできます。
6. 作成された skill の画面に戻る。左側に Copilot との自然言語の会話、右側に skill の名前、説明、詳細な指示が表示されています。指示には、先ほど入力した内容がすべて含まれていると語っています。

### 6.3 skill を更新する

1. すべての value prop document に、詳細版とは別に使える「1 行のタグライン」を入れたいと気づいた。
2. 指示を直接編集することも、自然言語で頼むこともできる。ここでは自然言語で、1 行の value prop を含めるよう Copilot に依頼した。
3. Copilot が、Kishore の言う "optimized instruction generation" で指示を更新した。変更が指示欄に反映されたことを、スクロールして確認した。

> 注意：Kishore は「skill の指示は手で書かず、常に Copilot に生成させることを強くお勧めします」と述べています。また、skill は最初に情報をすべて揃えなくても作成でき、専門知識が増えたり「良い出来」が変わったりしたときに洗練していけると説明しています。

### 6.4 skill を使って新しい文書を作る

1. 新しいチャット（新しいホームページ）を開き、作成した skill を指定した。トランスクリプトでは skill 名が "campaign value proposition" と聞き取れます（音声認識の都合で表記が確定できません）。
2. 別の製品ローンチ向けの value prop document を作成するよう依頼した。Copilot の処理には数秒かかった。

### 6.5 skill を Sara と共有し、他のアプリで使う

1. 処理を待つ間に、プラグインストアで作成した skill を Sara と共有した。Kishore は「skill の共有は、ドキュメントを共有するのと同じくらい簡単」と述べています。
2. chat で作った skill は、Cowork でも使える。skill を探すと表示され、オンにするだけで使えます（トランスクリプト上の表記は "Cowork"）。
3. skill はプラグインとしてパッケージされているため、Word、Excel、PowerPoint、SharePoint、Microsoft Copilot Studio といった Copilot の各サーフェスで同じ skill が表示されます。作り直しは不要だと説明しています。

### 6.6 既存の下書きを skill で書き直す

1. Kishore は leadership review に向けて、粗いメモを集めた文書を用意していた。これは「リーダーに見せる状態ではない」とのことです。
2. 従来は、Copilot に再プロンプトして追加の指示を与える必要があった。今回は、作成した skill を呼び出し、「この粗い文書を、リーダー向けの内容に書き直して」と依頼した。
3. 事実はメモのまま保ち、skill に含まれるベストプラクティスに沿って構成と文章を書き直すと説明しています。Copilot は手持ちの事実を整理しているところだと語っています。

### 6.7 結果の確認

1. 別の製品ローンチ向けに作らせた新規文書が完成した。skill に入れたベストプラクティスに沿い、自分の基準を満たしていた。同僚に毎回説明したり、ゼロから手作業で作ったりする必要がない、と語っています。
2. 書き直した文書も確認した。事実はそのままに、skill の原則を適用して書き直されており、「leadership review に持っていける」と評価しています。

### 6.8 Microsoft 提供の skill で 1 枚のスライドにする

1. リーダー側は、25 枚のスライドではなく、要約が 1 枚になった資料を求める。そこで Microsoft の built-in（ファーストパーティ）skill を使う。Microsoft は「デッキを 1 枚のスライドにする」やり方を知っているので、自分で skill を書く必要はないと説明しています。
2. "Create A Summary Interactive Slide" という built-in skill を呼び出し、内容を 1 枚の要約インタラクティブスライドにするよう依頼した。
3. 生成には数秒かかり、デモ中に完成した結果を見せる場面は、録音からは確認できません（「準備ができたら戻って確認する」と話した後、管理センターの説明に移っています）。

### 6.9 管理センターでのガバナンス

Kishore は、ここから IT 管理者の立場の説明に切り替えています。なお、この部分は説明が中心で、具体的な画面操作は語られていません。

1. skills、Copilot の成果物、プラグインは、おなじみの Microsoft Admin Center と同じ場所で管理される。
2. Agent 365 の tools セクションに、パートナーが作ったもの、Microsoft のファーストパーティのプラグイン、エンドユーザーが作った skills が表示され、skills と MCP を管理できる。
3. 管理者は、プラグインや skill をブロックしたり、共有できる範囲を決めたりできる。

## 7. 注意点・発表者の気付き

- skill の指示は手で書かず、Copilot に生成させる。「optimized instruction generation」で作られるため、とのことです。
- skill は一度で完成させる必要がない。作成後も、自然言語での依頼で更新できます。
- 同じ skill は、新しい文書の作成にも、既存の文書の書き直しにも使えます。書き直しでは事実は変わらず、構成や表現が skill の内容に沿って変わります。
- Microsoft は、組織固有のプロセスや基準を知らない。そのため、組織の知的財産に当たる skill は自分で作る必要があります。逆に、汎用的な作業は built-in skill を使えば、作成の手間が省けます。
- 他所で作った skill をインポートすると、業界標準の形式かどうかと、責任ある AI の原則への適合が検証されます。
- 信頼性への懸念：顧客から「Microsoft、サードパーティ、エンドユーザー由来の plugin や skill が、どのくらい良く、信頼できるのかをどう知るか」という声を強く聞いたと説明しています。これに対し、組織内に現れる成果物を評価し、信頼でき、安全で、悪用されず、大規模に展開できるかを確認する機能を、**プライベートプレビューで近日提供予定** としています。管理センターを通じてそのガイダンスを提供する、とのことです。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- 個人の専門知識を、組織全体で一貫して使える形にできる。説明の繰り返しやアウトプットのばらつきが減る。
- デモでは、専門知識を skill にするまでが 3〜4 分、全体で 15 分程度という時間感覚で示された（Kishore の説明による）。
- skill を一度作れば、Copilot chat、Cowork、Word、Excel、PowerPoint、SharePoint、Microsoft Copilot Studio など、複数の Copilot サーフェスで再利用できる。
- 共有はドキュメントを共有する感覚で行える。
- Microsoft の built-in skill が用意されているので、一般的な作業は skill を作らずに済む。
- IT 管理者は、インベントリ、デプロイ、ライフサイクル管理に加え、ブロックや共有範囲の制御ができる。

## 9. まとめ

skills は、すでに持っている手順、基準、良い出来のイメージを、Copilot の複数のサーフェスで再利用できるようにする仕組みです。skill は Markdown の指示として、tools や agents とともにプラグインにまとめられ、統一プラグインレジストリを通じて配布されます。

デモでは、自然言語の会話だけで価値提案書の skill を作り、1 行のタグライン追加で更新し、新規文書の作成と既存メモの書き直しに使い、Sara と共有しました。管理者向けには、Agent 365 の tools セクションでの管理と、近日プライベートプレビューで提供予定の信頼性評価が紹介されています。

発表の最後に、skills やプラグインの仕組みをさらに学べるセッションが Ignite に複数あると案内されました。具体的なセッション名はトランスクリプトからは確認できません。
