# BRK218 SharePoint: Modernize your knowledge foundation for the AI era

## 1. はじめに

このセッションは、SharePoint 上のコンテンツを「組織の知識」に変え、Copilot やエージェントが使えるようにするための、Copilot in SharePoint の機能紹介と活用ガイドです。製品マーケティングの Rachel Solomon Nambi 氏と、プロダクトマネージャーの Cory Newton-Smith 氏が、画面を使ったデモを交えながら進めます。

構成は「日々の仕事（Everyday work）」「自動化（Automation）」「ナレッジ（Knowledge）」「公開（Publish）」の 4 つの切り口で、すべての土台に「信頼（Trust）」を置いています。顧客事例として、エンジニアリング企業 MAIRE（トランスクリプトの綴りどおり）が冒頭のビデオで登場し、2 日かかっていたレビューが 10 分未満になったと紹介されます。

主な新情報は、SharePoint tools in Work IQ（パブリックプレビュー）、Work IQ のコンテキスト強化（パブリックプレビューへ展開中）、Knowledge Bases（Frontier プレビュー）、Copilot in SharePoint の一般提供（GA）です。デモは複数あり、6 章にまとめています。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/BRK218](https://ignite.microsoft.com/en-US/sessions/BRK218)

## 3. 何に関する発表か

背景は、AI によってコンテンツが増える速度に、人間が整理・統治する力が追いつかないという問題です。権限が適切でない、あるいは共有しすぎのコンテンツがあると、AI はそれを素早く表に出してしまい、従業員は正しい情報を見つけられず、信頼もできなくなります。また、重要なプロセスが人手でコンテンツを探して解釈して動かす形に依存していると、壊れやすく、スケールしにくくなります。

そこで、AI の時代のコンテンツは「過去の仕事の記録」ではなく、「AI が新しい仕事をするためのコンテキスト」だというのが前提です。AI が組織化・理解・統治を大規模に支援できるので、すでに多くのコンテンツがある SharePoint がその出発点になる、という位置づけです。

発表の流れは次のとおりです。

1. 顧客ビデオ（MAIRE）と、なぜ今ナレッジなのか
2. SharePoint が Microsoft の AI の中で果たす役割と、秋の 4 つのリリース（Cory 氏）
3. SharePoint tools in Work IQ のデモ（Cowork によるフォルダー整理）
4. 4 つの切り口：Everyday work、Automation（Cory 氏）／Knowledge、Publish（Rachel 氏）
5. 今後の予定、導入の進め方、関連セッション、Co-build プログラム

## 4. 発表者が伝えたいメッセージ

中心となるメッセージは、「**組織の知識は AI 時代に最も持続する資産であり、SharePoint はそれを整理し、統治し、活用する場所**」というものです。MAIRE の例のように、ゼロからやり直すのではなく、すでにある知識（専門家のレビュー手順など）をスキルとして活かすことで、成果が出るとしています。

もう 1 つは、**一度にすべてを変革する必要はない**ということです。Cory 氏は、顧客の成長は 3 段階（日々の仕事、チーム規模、変革）で進むと説明し、各段階が前の段階に積み上がると述べています。そして、あらゆる場面で人が判断の主導権を持ち、回答が根拠を示すこと、権限、秘密度ラベル、ポリシーが一貫して尊重されることを重視しています。

## 5. 発表内容の詳細

### 5.1 顧客ビデオ：MAIRE

冒頭で、MAIRE の担当者によるビデオが流れました。語られた内容は次のとおりです。

- MAIRE は SharePoint の複数サイトで **1 ペタバイト超**のコンテンツを管理しており、SharePoint は知識の中核で、いまは AI の中核にもなっている。
- エンジニアリング企業なのでドキュメントが非常に重要で、1 プロジェクトあたり約 100 万件のドキュメントがある。
- エネルギー送電に重点を置き、世界中で産業プラントを設計・建設している。土木のレビューは最初の活動の 1 つで、互いに異なる数百のドキュメントを受け取る。情報の追跡には時間がかかり、情報が揃っていないと現場の作業に影響が出る。
- これまでは、この種の情報を扱うには 5 年の経験を持つ人が必要だった。Copilot を使うと、SharePoint のドキュメントのそばにあるシンプルなアクションボタンで実行でき、この要件は必須ではなくなった。レビューの時間は「数時間または数日」から「数分」に短縮された。
- レビューの時間が減っただけでなく、ワークフローを変え、レビューを**最初のフェーズに前倒し**できた。下流の活動に大きな利点があり、建設現場に必要な情報を時間どおりに届け、エンジニアリングの手戻りも避けられる。
- 同僚が積み上げた経験や知識を会社として利用可能にでき、特に若いエンジニアにとって意味がある。
- 以前は Copilot にコンテキストを説明する必要があると話していたが、Copilot が SharePoint の中にあるため、コンテキストを自動的に理解する。

Rachel 氏は、MAIRE が自社の専門知識を Copilot と SharePoint のスキルに変え、複雑なドキュメントの不足情報を早く見つけられるようにしたと要約し、1 回のレビューサイクルが約 2 日から 10 分未満になったと述べています。

### 5.2 なぜ今ナレッジなのか（Rachel 氏）

Rachel 氏は、SharePoint の規模を次のように示しました。

- SharePoint は Copilot が引用する業務ソースの第 1 位。
- 組織は毎日 **300 万の SharePoint サイト**と **20 億のファイル**を作成し、そのコンテンツに対して毎週約 **50 億の自動化ワークフロー**が動いている。
- これらのコンテンツは Work IQ を通じて、Copilot やエージェントに業務、組織、背後の知識に関するコンテキストを与える。

成果の例として、次が挙げられました。

| 事例・調査 | 内容 |
| --- | --- |
| Microsoft 社内の法務チーム | 72 時間の SLA が約 10 分に |
| Microsoft 社内の財務チーム | 約 12 週間のレポート作業が約 12 時間に |
| 社内評価 | 6 つの業務機能で、標準のドキュメントライブラリと、Copilot と SharePoint で強化した同じライブラリの回答を比較。すべての機能で平均約 **17 ポイント**向上 |
| 外部評価 | Microsoft が 2026 Gartner Magic Quadrant for Document Management でリーダーとして評価された |

### 5.3 SharePoint の役割（Cory 氏）

Cory 氏は、「1 枚だけ覚えるならこのスライド」として、SharePoint の AI における位置づけを説明しました。土台は、SharePoint のエンドツーエンドのガバナンスとコラボレーションで、その上にストレージ、コンテンツの理解、エージェント型検索、コンテンツの自動化、そして Knowledge Bases があります。これらは Work IQ を通じて、Copilot Chat、Cowork、Autopilot、Code、M365 アプリ、開発者が使うエージェントプラットフォームといった、人が普段いる場所に表れます。

SharePoint はファイルを 1 度だけ理解し（構造、エンティティ、メタデータ、権限を含む）、その理解を共有します。エージェントが同じファイルを何度もダウンロードして読み直す必要がなく、回答が速くなり、ツール呼び出しが減り、トークン効率が上がってコスト削減につながるという説明です。すべての段階で、既存の権限、秘密度ラベル、ポリシーが尊重されます。

### 5.5 切り口 1：Everyday work（日々の仕事）

人はコンテンツについて質問するだけでなく、実際の作業を AI に任せるようになっており、その作業はファイルの中身を理解するところから始まります。コンテンツ理解は次の 2 つの形で提供されます。

**(1) SharePoint tools in Work IQ。** ファイルを 1 つずつ開いて読み直す力技ではなく、Copilot とエージェントがサイトとファイルを使い、メタデータを取り出して、タスクに必要なものだけをコンテキストウィンドウに入れます。社内評価では、Work IQ に SharePoint tools を加えると、タスクの達成率（発話は "task rate"）が **70% から 85%** に上がり、トークンの使用量が **16% 減りました**。

**(2) Work IQ のコンテキスト強化（パブリックプレビューへ展開中）。** 開発者のカスタムエージェントに、Copilot と同じ深い理解を与えるもので、自前のドキュメントパイプラインを作る必要はありません。エージェントは次を受け取ります。

- エージェント向けの Markdown ファイル（ドキュメント構造を理解するため）
- 画像とサムネイル（図が見えなくなるのを防ぐため）
- 要約（ファイル全体を開く前に関連性を判断するため）
- ファイル内のセマンティック検索（答えのある箇所に直接たどり着くため）

作成面では、Copilot と SharePoint は、コンテンツを Word、Excel、PowerPoint のファイルだけでなく、**インタラクティブな HTML** にもできます。生成される HTML は Chart.js、Mermaid、Babylon、React、Fluent UI といったライブラリを使えます。近日中に D3.js、Topo.JSON（世界・国・米国郡のデータセット付き）、Floating UI、Lucid アイコンを追加する予定です。一方、直後の例では D3.js が「HTML サンドボックスで対応済み」とも語られています（発話上の食い違いで、どちらが正確かは確認できません）。今月出たばかりの機能として、SharePoint リストの上に D3.js を使った HTML ビューを作る例も紹介されました（デモの詳細は 6 章）。なお、同僚の Zach Rosenfield 氏の YouTube チャンネルに詳細の動画があるとの案内がありました。採用ガイドも案内され、製品内のプロンプトライブラリも近日出荷予定です。

### 5.6 切り口 2：Automation（自動化）

Cory 氏は、プレビュー期間に密に協力した 2 社をもとにした例を紹介しました。どちらもコンテンツと専門家の判断に大きく依存するプロセスで、「どこまで AI で再設計でき、同時に重要な判断を人の手元に置けるか」という同じ質問から始まったとのことです。節約できたのは時間や日ではなく**週単位**だと強調されています。

**(1) 標準化：スキルとして残す。** 誰かがうまくやった方法を**スキル**に取り込めば、Copilot が組織の全員に対して毎回同じやり方で実行できます。MAIRE のエンジニアは、レビュー手順をスキルにして、最も優秀なエンジニアのようにベンダーのドキュメントの不足情報を見つけられるようにしました。

**(2) 大手上場企業の財務チーム（四半期の決算開示資料）**

- 毎四半期、6 人がプレスリリース、投資家向けスライド、規制当局への提出書類、財務諸表からなる開示資料一式を作成する。正確で、ドキュメント間で一貫し、公開前に監査可能である必要がある。
- チームはソース資料を 1 つの SharePoint サイトにまとめ、ドキュメントライブラリ内の **Quick Steps** で起動するカスタムスキルを作った。
- ソースファイルから財務諸表を、引用付きのワークブックに抽出する。生成された下書きは、数値がソースと照合され、**完全一致、部分一致、未完了**のいずれかが付く。
- ユーザーがサイト内で四半期レポートを依頼すると、Copilot がソースの財務情報から下書きし、全ドキュメントで数値の一貫性を保ち、財務のレビュー用に根拠を残す。レビュー、承認、公開は引き続き財務チームが担う。
- 年間約 12 週間かかっていた作業が約 12 時間に。四半期あたり約 4 週間の節約になる。
- 信頼の作り方：顧客が自分たちのプロンプトと採点基準を提示し、そのプロンプトを何百回も実行した。最初のスコアは 40% だったが、ギャップを学んでスキルを改善し、顧客がチーム全体で使えると納得した **85%** に達した。

**(3) 約 9,000 人のグローバルコンサルティング会社（入札対応）**

- 入札資料は大規模で構造の揃わない複数ドキュメントのパッケージで届き、義務、認定、要件、コスト入力を手作業で抽出していた。品質を入札ごとに揃える再利用可能な方法がなかった。
- 入札 1 件あたり、受付、コンテンツ探索、統合、起草、レビューで**約 90 時間**の手作業があり、そのうち約 60 時間が執筆とレビューだった。Copilot が最も助けになる部分だと説明されています。
- 顧客は RFP プロセスを SharePoint のフローに組み込んだ。チームが応募を始めるとき、Copilot に依頼すると、**75 ページの RFP** を解析し、承認済みのソースに対応づけ、方向性と目次を決め、全ページを下書きし、公開基準に照らして提出物をチェックできる。判断と執筆は人が担う。
- 3 週間かかっていた最初のドラフトが約 4 日になった。約 **75% 高速**で、入札ごとに **88 時間以上**の手作業を削減できる。
- この事例は、木曜日の Breakout Session 217「Real-World AI Transformation with Copilot and SharePoint」で、Matt 氏と RK 氏が紹介する予定とのことです。

Cory 氏は、両方の例で人が判断を握り、回答が根拠を示していたこと、そして自動化は背後の知識の質に左右されること（コンテキストが散らばっていると、すべてのプロセスが砂の上に建つこと）を述べて、Rachel 氏に引き継ぎました。

### 5.7 切り口 3：Knowledge（Rachel 氏）

Rachel 氏は、コンテンツが散らばっていると人だけでなく AI も見つけにくくなるとして、まず「重要なことを軸にコンテンツを整理する」ことを挙げます。先の評価で回答が平均約 17 ポイント向上したのは、この仕組みが一因だと説明しています。

**オートフィル列とメタデータ。** AI 機能として SharePoint で初期から基盤になっている機能です。人にとって見やすくなるだけでなく、Copilot とエージェントがコンテンツをよく理解する助けになります。Copilot が列を追加し、全ドキュメントからメタデータを抽出し、ファイルが追加されると抽出を続けます。ライブラリ全体の整理が「数週間ではなく数分」で終わる、と述べています。

**Knowledge Base（Frontier プレビュー。先月展開）。** 優れたチームの知識は 1 つのファイルではなく、会議での判断、先週火曜に更新された仕様、議論に決着をつけたメールのスレッドなどに散らばっています。Knowledge Base では、ファイル、会議、メールといったチームが既に持つソースから、Copilot in SharePoint に作成を依頼できます。Work IQ の **knowledge compilation engine** がそれらを、Markdown として SharePoint に保存される、つながった Knowledge Base ページに変換します。人が読め、Copilot とエージェントは共有コンテキストとして使えます。社内の初期テストでは、Knowledge Base を使うエージェントは、応答が最大 **4 倍速く**、トークン効率が **30%** 高くなりました。

考え方は「一度整え、どこで作業していても最新に保つ」です。Copilot in SharePoint でも Cowork や Autopilot でもよく、チーム全員とすべてのエージェントが同じ信頼できるソースから動きます。

### 5.8 切り口 4：Publish（公開）

Rachel 氏は、SharePoint の公開は、イントラネットチームや社内広報、IT の仕事のように見られてきたが、AI によって「全員が公開する」時代になるとし、プロジェクトリードのステータスハブ、HR 担当のオンボーディングページ、エンジニアのライブダッシュボードを例に挙げました。

1. SharePoint ネイティブの豊かな体験を、既存のコンテンツとルック・アンド・フィールで速く作る。Copilot と SharePoint が、**インタラクティブな HTML ダッシュボードやニュースレターをページとして直接作成**できる。
2. SharePoint と Copilot の体験を組み合わせる。ページは静的である必要がなく、エージェントをページ上に置いて、コンテンツを見つけた場所で回答を得られる。新しい **Agent Chat web part** で、SharePoint ページからエージェントと直接チャットできる。

### 5.9 顧客の成長の 3 段階と今後

Cory 氏は、一度にすべてを変革する必要はなく、多くの顧客は 3 段階で成長すると説明しました。

| 段階 | 内容 | 補足 |
| --- | --- | --- |
| 日々の仕事 | 信頼できる知識について、尋ね、探し、推論する | Microsoft 365 Copilot ライセンスに含まれる |
| チーム規模 | 再利用できる知識の整理と、コンテンツの作成・整理・強化（メタデータ、Knowledge Base、公開のデモ） | |
| 変革 | 完全な業務プロセスを自動化し、スケジュールして大規模に動かす | 四半期決算と RFP 対応の例 |

各段階は前の段階に積み上がり、リターンが複利で増えるという説明です。Microsoft は毎月何か新しいものを出荷しているとも述べています。今年の Copilot と SharePoint が学んだこととして、プロジェクトファイルの整理とドキュメント生成、サイトの分析と最適化、メタデータエージェントとワークフローの操作、コンテンツの強化、エージェントとしてのドキュメントの共同作業、HTML ページとライブダッシュボードの作成が挙げられました。スキルはプロセスを成文化でき、Copilot プラットフォーム全体で共有されます。Knowledge Base はどのサイトにも追加できます。

**今後予定されるもの**：

- スケジュールとトリガーの両方でスキルを実行する、自然言語のワークフロー
- SharePoint と OneDrive の両方での Copilot Search
- ビジネスシステムを SharePoint 上のソリューションにつなぐ、組織のプラグインと MCP サーバー

最新情報は、公開ロードマップと、毎月の「What's New in Copilot and SharePoint」ブログで追えるとのことです。

**Co-build プログラム**は無料で、SharePoint の製品チームがともに、Copilot と SharePoint の価値の高いシナリオを、概念実証から本番までの道筋まで作り上げます。参加条件は次の 3 つです。

1. 本番化の計画を伴う実際のユースケース
2. ビジネスと IT の双方の関係者のコミットメント
3. チームが M365 Copilot ライセンスを持っていること

四半期決算と RFP の例はこの取り組みから生まれたとのことです。応募は約 1 週間でレビューされます。

また、「クライアント案件と契約の自動化」「営業資料のハブとしての SharePoint」「ナレッジベースの作成と追加」の 3 つの新しいデモ動画が用意され、QR コードで視聴できます。ブログは aka.ms/odspignite2026 です。

始め方として、次の 2 ステップが示されました。

1. まず、ユーザーに日々の仕事で Copilot を使い始めてもらう。Microsoft 365 Copilot ライセンスに含まれており、新たに購入するものはない。
2. 次に、コンテンツ管理者、サイト所有者、ナレッジ管理者など、大規模に作業するパワーユーザーに Copilot クレジットを付与する。

QR コードや画面上のリンクから、Copilot と SharePoint の概要、インタラクティブなシミュレーター、開始に必要な情報にアクセスできると案内されています。

## 6. デモ・手順

このセッションには画面を使ったデモが複数あります。録音は音声のみのため、画面の細部（ボタン名や配置）は確認できず、語られた範囲で記載します。なお、5.6 の財務チームと入札の事例は、デモではなく顧客事例の説明です。

### 6.1 Cowork によるプロジェクトフォルダーの整理（Cory 氏）

前提：ファイルが数か月にわたって雑に置かれ、構造も名前も整っていないプロジェクトフォルダーです。

1. SharePoint tools が Work IQ に入ったので、SharePoint ではなく Copilot アプリから作業する。Cowork とのチャットを開始し、このフォルダーを改善する計画を作るよう依頼する。
2. Cowork が計画を返す。フォルダー内のすべてのファイルを調べ、新しいフォルダー構造とファイルの命名を提案している。この時点ではまだ何も変更していない。
3. 内容に納得したら、Cowork に進めるよう伝える。
4. Cowork は実行の間も人を巻き込む。ファイル整理の移動について承認を求めてくる。
5. 承認すると、変更が行われる。
6. SharePoint のライブラリに戻ると、計画どおりに名前の変更と整理が済んでいる。

Cory 氏は、名前が明確で一貫していれば、Copilot は正しいコンテンツをより速く、より少ないトークンで見つけられ、コスト効率も上がると述べています。

### 6.2 SharePoint サイト内のインタラクティブな HTML 体験（Cory 氏）

SharePoint サイトの中にある、インタラクティブな体験を見せました。プロンプトから作られたもので（開発チームではなく）、サイトに実際にあるコンテンツをもとにしています。インライン HTML エディターで、チャットで説明するには面倒な小さな変更を素早く加えられます。以前は Power BI やカスタムコードで作っていたような可視化が、1 つのプロンプトで作れるという説明です。続けて、SharePoint リストの上に作った HTML ビューを見せ、D3.js（HTML サンドボックスで対応済み）を使って、データを動きのあるストーリーにできること、コーディング不要で既存コンテンツからのプロンプトだけで作れることを説明しました。

### 6.3 オートフィル列の追加（Rachel 氏）

1. フラットなリスト（フォルダーなし）のプロジェクトライブラリがある。ファイル名はまずまずだが、各ファイルの中身は分からず、整理しにくい。
2. Copilot in SharePoint に、オートフィル列とメタデータを追加するよう依頼する。
3. Copilot が列を追加し、各ドキュメントからメタデータを抽出する。ファイルが追加されれば、抽出を続ける。

### 6.4 Knowledge Base の更新と HTML ブリーフ（Rachel 氏）

1. 「Project Summit」の Knowledge Base がある。当初は Project Summit フォルダーのコンテンツだけで、毎週の会議の内容も取り込みたい。
2. Copilot アプリの Cowork に依頼する。Cowork が Knowledge Base を読み、更新を提案する。
3. 承認すると、Cowork が完了を知らせる。
4. ソースから Knowledge Base ページを開くと、11 月 1 日の週次同期の更新と、その会議で話した未完了のアクション項目が追加されていた。
5. 次に、リーダーシップへのプロジェクト報告用に、Knowledge Base の HTML ブリーフを Cowork に依頼する。リーダー層は詳細ではなく、重要点を強調した視覚的なものを求めている。
6. Cowork が Knowledge Base を、共有しやすい視覚的なブリーフにした。

### 6.5 HTML ニュースレターページの作成と公開（Rachel 氏）

1. 10 月 29 日の「Project Atlas」週次同期のノートから、インタラクティブなニュースレターを作るよう Copilot に依頼する。Project Atlas は、脳、心臓、肝臓、免疫療法といった医療分野の革新を追跡するプロジェクトという説明。
2. 事前に、ニュースレターの見た目を指定したスキルを設定してある。Copilot がそのスキルを呼び出して作成した。
3. 各治療領域のインタラクティブな概要が表示される。ページの残りも確認し、そのまま公開する。

### 6.6 Agent Chat web part の追加（Rachel 氏）

1. ページの「編集」を選び、ツールボックスを開き、Agent Chat web part を目的の場所にドラッグする。
2. そこからエージェントを接続する。
3. 保存して公開する。
4. ページ上でエージェントとチャットを始められ、スターターのプロンプトも表示される。SharePoint サイトを離れずに会話でき、続きを Copilot アプリで行うこともできる。

## 7. 注意点・発表者の気付き

- **権限と共有の見直し**：権限が誤っている、または共有しすぎのコンテンツは、AI がそれを素早く提示してしまい、従業員が正しい情報を信頼できなくなるとの注意があります。
- **人が判断を握る**：Cowork は変更を行う前に計画を示し、移動の承認を求めます。財務の例でも、レビュー、承認、公開は人が担います。
- **品質の確認**：財務チームは、自分たちの採点基準でスキルの回答を評価し、何百回も実行しました。最初のスコアは 40% で、改善して 85% に達しました。
- **整えた名前とメタデータが効く**：明確で一貫した名前は、Copilot がコンテンツを見つける速さとトークン消費に効きます。
- **前提条件**：Copilot in SharePoint を使うには M365 Copilot ライセンスが必要だと述べられています（Co-build の条件として）。
- **提供状況**：SharePoint tools in Work IQ と Work IQ のコンテキスト強化はパブリックプレビュー、Knowledge Base は Frontier プレビューです。

## 9. まとめ

このセッションは、SharePoint 上のコンテンツを、Copilot とエージェントが使える組織の知識に変える方法を、4 つの切り口（Everyday work、Automation、Knowledge、Publish）と、その土台である信頼で説明しました。

主な内容は、SharePoint tools in Work IQ（60 を超える操作）、Work IQ のコンテキスト強化、Knowledge Bases、Copilot in SharePoint の GA、Agent Chat web part などの機能と、MAIRE、財務チーム、コンサルティング会社の事例です。導入は、日々の仕事から始め、チーム規模に広げ、重要なプロセスを変革する 3 段階で進めればよく、日々の仕事の部分は M365 Copilot ライセンスに含まれると説明されました。

自社のプロセスを持ち込みたい場合は、無料の Co-build プログラムが案内されています。結びとして、組織の知識は AI 時代に最も持続する資産であり、SharePoint はそれを整理し、統治し、活用する手段だと述べています。
