# BRK206 Agentic productivity in Microsoft 365 apps

## 1. はじめに

このセッションは、Word、Excel、PowerPoint、Outlook に組み込まれた Microsoft 365 Copilot が、この 1 年でどう変わったかを、デモ中心で見せる 45 分のブレークアウトです。前半では Brian Jones 氏が、アプリの中で Copilot が行う作業を、業種別スキル、外部データへの接続、カスタムスキル、Brand Kits、変更履歴の監査といった切り口で紹介します。後半では Derek Johnson 氏が、Interactive Content（ドキュメント内に埋め込む対話型コンテンツ）、Copilot アプリ内での Office、毎日の仕事を整理する Today を紹介します。

発表全体の軸は、「Copilot に操作方法を聞く」段階から「Copilot にやりたい成果を伝えて任せる」段階へ移っているという点です。そのうえで、何をしたのかを確認でき、元に戻せる（コントロールできる）ことが繰り返し強調されます。

## 4. 発表者が伝えたいメッセージ

### 4.1 機能を覚える時代から、成果を伝える時代へ

Brian Jones 氏は、1999 年に Microsoft に入社して以来ずっと Office の領域にいて、キャリアの大半は「人ができることを増やすために機能を足し続けること」だったと話します。いまは、ユーザーが機能を意識せず、やりたいことを説明すれば、Copilot が機能を組み合わせて目的を達成する時代に変わりつつあるという考えです。難しい機能は UI を分かりやすくするのが大変だったが、いまは Copilot が引き受けてくれる、とも述べています。

### 4.2 コントロールと信頼

最初に出てくるユーザーの不安は、「重要な業務ファイルへのアクセスを Copilot に渡して、壊されないか」だと説明されます。これに対して、Copilot の編集箇所を可視化して、承認も取り消しもできるようにしたというのが、前半の一貫した答えです。変更履歴でも、人の編集と Copilot の編集を区別して見られることを示しています。

### 4.3 自社の業務に合わせて Copilot を訓練する

お客様が Copilot に求めるのは、Word や Excel をうまく使うことだけではなく、「自社のビジネスと業務プロセスを理解すること」だとされています。そのためのスキル、データコネクタ、Brand Kits といった仕組みを一通り見せるのが前半の狙いです。

### 4.4 Office は他の AI 体験の中にも現れる

後半で Derek Johnson 氏は、Office のフルの機能を Copilot アプリ（Chat、Cowork、Code）の中に持ち込むと説明します。さらに、毎日の仕事を先回りで整理する Today を紹介します。まとめでは「1 年前とは違う製品になっており、1 年後にはさらに違う製品になる」と述べ、ユーザーのコントロールを保ち、時間と手間を減らし、使った時間が仕事を前に進めることにつながる製品にしていく、と語っています。

## 5. 発表内容の詳細

### 5.1 この 1 年の Copilot と利用状況

Office アプリに Copilot が入ってから 1 年あまりです。最初は、質問して答えをもらい、人が操作する形（例: SQL 文の書き方や数式の書き方、目次の入れ方を聞く）でした。今年の早い時期に、Copilot がアプリ内で直接操作を実行する機能が加わりました。これは、操作方法を教えるのではなく実行まで行うという意味で、Brian Jones 氏は大きな転換だったと語っています。

その後に見えてきた変化として、次の点が挙げられています。

| 観点 | 発表で語られた内容 |
| ---- | ---- |
| 利用量 | ユーザー数、エンゲージメント、リテンションが大きく伸びている。 |
| 継続利用 | 週単位のリテンションを見ると、アプリ内の Copilot の利用は、保存やコピー＆ペーストのような基本操作に近い。一度使い方を覚えた人は毎週使う。現在の課題は、機能の発見（discovery）。 |
| プロンプトの変化 | 当初は「この数式を入れて」「ピボットテーブルを作って」「図形を挿入して」という基本的な指示だった。いまは、達成したい成果を説明する指示が増えている。例: チームに展開するビジョンのピッチ、Q3 の売上を予算と比較して差異を見る。 |
| 財務分野 | Excel の Copilot を財務で使う人のプロンプトの **50% を大きく超える** ものが、目標を説明する高いレベルの指示。 |
| 反復 | プロンプトエンジニアリングで「完璧な 1 本のプロンプト」を探すより、Copilot とやり取りを重ねる使い方が広がっている。 |
| 音声入力 | Brian 氏自身、Copilot で音声入力を日常的に使っている。AI に話すときは言い回しが雑でも意図を汲み取ってくれるので、以前は嫌いだった音声入力が使えるようになった、と話している。 |

この発表のスライドも、Copilot で作られたものだと紹介されています。Brian Jones 氏によると、このセッションの目標（Copilot の仕組みを理解してもらい、各社で広めてもらうこと）を Copilot Workspace に伝え、見せたいデモと時間を整理した Excel のスプレッドシートも用意して、そこから Copilot が一連のやり取りを元にこのプレゼンを作成しました。PowerPoint の機能やシェイプの配置を誰も意識せず、やりたいことを Copilot に説明しただけで作ったとのことで、アプリをまたいだワークフローの例として紹介されています。

### 5.2 Microsoft 365 Copilot のライセンスとモデル

Microsoft 365 Copilot ライセンスは、**月額の固定費で、従量課金ではない** と説明されています。Word、Excel、PowerPoint の機能がこのライセンスの中で使えるので、使う量の多い少ないは費用に影響しません。

モデルには **Auto** があり、プロンプトを見て、その場面に最適なモデルを選びます。書式の不一致を探すような基本的な作業には、単純で高速なモデルを使います。Q3 の目標と数値を比べる深い分析のような複雑な作業には、より複雑なモデルを使います。UI の既定は Auto ですが、モデルを自分で選ぶこともできます。選べるモデルは Anthropic、OpenAI、それに「SpaceXAI」（音声認識の都合で表記が確定できません）のものがあり、新しいモデルが出ると、Word、Excel、PowerPoint の Copilot に素早く追加されるという説明です。

### 5.3 On Canvas：作業の流れの中で使う支援

「On Canvas」とは、アプリの画面の中でそのまま使うという意味です。目的は、新しい作業方法を覚え直さなくても、AI が今のやり方を補完することだと説明されています。

- **Word の Rewrite**: Q3 レビューのカバーノートに、メールで届いた結果をコピーして貼り付けると、文書の他の部分と文体が合わない状態になります。右クリックして Rewrite を選ぶと、Copilot が周辺の内容を見て更新します。変更箇所には網掛けが付き、下部で承認するか、取り消すかを選べます。
- **Excel の数式提案**: `=` を入力すると、周囲の情報を見て、数式の候補を示します。目標に対する割合（percent of target）や、上にある報酬ティア表を参照して獲得ボーナスを計算する検索の数式が例として出ています。そのまま入力を続けて、提案を無視することもできます。
- **タスクペインでの改訂**: インテリジェンスブリーフ（intelligence brief）の文書で、推奨事項を明確にし、次のアクションを具体的にするよう依頼します。Copilot は文書全体を読み、エグゼクティブサマリーの追加、推奨される対応の更新、次のステップの明確化を、ハイライト付きで反映します。気に入らなければ理由を伝えて再実行でき、他の人と協力するように進められます。

### 5.4 業種別スキルとデータ接続

Brian Jones 氏によると、弁護士が Word を使う方法は自分の使い方とは大きく違います。そこで Microsoft は、forward-deployed engineers（お客様のもとに入って業界ごとの使い方を理解するエンジニア）を派遣し、最初の業種として **legal、finance、sales** から取り組んでいます。成果として、スキルとデータコネクタが追加されました。

- finance では LSEG や Moody's に接続できる（すでに契約している場合）。MCP サーバーを経由して、Excel での作業中にそのデータを使えます。
- legal では Harvey などに接続できる。

#### 法務（legal）のスキルのデモ

1. 既存の契約書を出発点にして「この既存の契約から新しい契約を起案して」と依頼します。古い条項が取り除かれ、テンプレートとして残った新しい文書ができます。
2. 新しい契約の条件が書かれたタームシート（term sheet）を指定します。Copilot はそれを読み、必要な情報を集めます。
3. Copilot は、タームシートの情報で契約書を更新します。途中で確認の質問が出て、値を答えて更新を進めます。
4. 加えた編集の一覧が表示され、それぞれをクリックして該当箇所に移動できます。確認して承認します。
5. 最後に、自社の条項の書き方を記した「NetDocuments」を使い、ベストプラクティスに沿うよう適用します。法務では修正履歴が重要なので、Track Changes が自動的にオンになり、変更が単語単位で確認できます。

#### 財務（finance）のスキルとデータ接続のデモ

1. Q3 の最終結果と見込み（projections）がある Excel で、variance analysis（差異分析）のスキルを指定して実行します。
2. 全体としては目標に近いものの、**APAC は目標をかなり下回り、EMEA はかなり上回っている** ことがすぐ分かります。地域別と事業ライン別に差異が分解され、地域の差であることが示されます。Copilot はいくつかの仮説を検討し、掘り下げるべき点を挙げます。
3. さらにデータが必要なので、Fabric に接続します。「Fabric の売上データを使って、Q3 でどの地域が最も遅れているか調べて」と依頼します。Copilot は Fabric に接続し、Fabric IQ を使ってクエリを実行して答え、さらに **Fabric のデータにライブ接続したピボットテーブル** を新しく作成します。このとき、重要になる掘り下げ（ドリルダウン）も備えています。
4. Q3 の締め処理で使った他のファイルがあるので、Copilot にそれらへの接続を依頼します。Copilot は Excel の Power Query を使います。Brian 氏が会場に利用経験を尋ねたところ、おおよそ 5% 程度で、使う人にとっては素晴らしい機能だが、Copilot によって誰でも使えるようになる、と説明しています。「Power Query を使って」と指示したわけではなく、「Q3 の締めのファイルをすべて取り込んで」と意図を伝えただけです。SharePoint のファイルに接続して新しい Power Query を作り、更新可能（refreshable）なデータになります。
5. 続けて「さらに分析して」と依頼すると、更新可能なデータを元にしたダッシュボードが作られます。数式は正しく組み立てられ、**検査可能で、固定値（ハードコード）は含まれません**。Excel の専門家が行うやり方だ、と説明されています。
6. 実際の取引データを見るため、銀行の Mercury への接続を依頼します。Mercury 向けの MCP コネクタがあり、「接続してデータを取り込んでよいか」という確認が出ます。許可すると、取引データがファイルに取り込まれます。分析の対象は Star Market という顧客です。

### 5.5 カスタマイズ：スキルの 3 つのレベル

お客様はそれぞれ独自の IP や業務プロセスを持っているので、既製のスキルの上にさらにカスタマイズしたいという要望が多いと説明されています。次の 3 種類が紹介されました。

| 種類 | 内容 |
| ---- | ---- |
| Personalization | Copilot を使うたびに従わせたい指示を、自分用に指定する。 |
| ファイルレベルのスキル | そのファイルで作業する全員に、Copilot が常に使うルールを定義する。 |
| グローバルスキル | どのファイルからでも呼び出せるスキル。 |

デモでは次のように見せています。

1. Excel の右上から Personalization を開きます。VLOOKUP ではなく XLOOKUP を使う、通貨の書式をどうするか、といった指示が例です。
2. ファイルレベルのスキルは、ブック内に置かれた 1 枚のシートに指示を書く形です。そのブックで Copilot を使うと、常にその指示に従います。
3. グローバルスキルでは、差異分析の一環として、利益率が低い箇所にラベルを付けるスキルを実行します。利益率の低い、掘り下げるべき箇所が特定され、書式が付きます。

ここまではマークダウンファイルを自分で書く形です。そこで、PowerPoint では **スキルを記録する** 例が示されます。

1. PowerPoint で操作を行うと、Copilot がその操作と書式を見て、スキルとして保存します。
2. Brian 氏はこれを、VBA を学んだときのマクロの記録になぞらえます。マクロの記録は特定のセルに固定されがちで壊れやすく、再利用するには手直しが必要でしたが、AI では「ただの指示のセット」になるため、中身を読んで確認できます。
3. 名前を付けると、呼び出せるスキル（callable skill）になります。
4. Excel のデータをコピーして PowerPoint に貼ると、見た目が好みに合いません。そこで作成したスキルを「Restyle this」として呼び出すと、記録した指示が実行され、好みの見た目になります。以後、表を取り込むたびにこのスキルを呼べます。

### 5.6 Brand Kits

会社のブランドは、色、アイコン、画像の使い方まで含めて守りたいものです。**Brand Kits** は、Copilot にブランドを学習させ、アプリをまたいでコンテンツを作成するときに使わせる仕組みです。自分の Brand Kit を作成できます。

PowerPoint でのデモの流れは次のとおりです。

1. 使いたいブランドを指定します。
2. 製品概要（product brief）の Word 文書を元に、ピッチ用のデッキを作るよう依頼します。Copilot はその文書を読んでプレゼンを作ります。
3. Copilot が確認の質問をします。Brand Kit のスタイルを使うか、画像はブランドの画像だけにするか、AI が作成した画像も許容するか、といった内容です。
4. 質問に答えると、文書の内容に基づきつつ、会社のブランドに沿ったプレゼンが作られます。
5. 共同作業者がブランドに従わないスライドを貼り付けていた場合は、Copilot に「このスライドも自社ブランドに合わせて更新して」と頼むと、Brand Kit が適用されます。

Brian 氏はさらに、ほかの agentic なアプリケーション（Autopilot など）にも触れ、AI が文書に対して長時間にわたって動く場面が増えていくと述べます。例として、プレゼンがブランドから外れていないかを確認し、外れていれば Brand Kit を再適用するエージェントが挙げられています。ただし、この部分は発表では方向性としての紹介にとどまり、詳細は説明されていません。

### 5.7 変更履歴と監査

共同編集（co-authoring）と複数ユーザーでの編集は Office の基盤で、その量は、全体の利用の伸びよりもはるかに速く増えているとされます。人数が増えるほど、誰がどう編集したか、Copilot が何を変えたかを知ることが重要になります。

デモでは、Change History に Maya、Dan、Priya の編集に加えて、関わったエージェントの編集も表示されることを見せます。続けて Excel でのデモがあります。

1. ファイルの様子がおかしいので、Copilot に「この 1 週間の変更を要約して」と頼みます。
2. Copilot は、Miguel、Colin、Karin が各日付に行った編集を、内容付きで示します。
3. Colin の編集が誤りだったので、「Colin の編集を取り消して」と頼みます。
4. 従来は古いバージョンに戻す方法もありましたが、Colin の後に 5 人が編集していた場合、その人たちの編集が失われます。Copilot は各人の編集を把握しているので、**Colin の編集だけを取り消し、他の人の編集は残せる** と説明されています。

おまけとして、過去数週間の出来事を、Quentin Tarantino 風などの語り口で物語にしてもらう遊び方も紹介され、「もう少し PG にするなら Shakespeare 風で」と話しています。

### 5.8 Interactive Content（Derek Johnson 氏）

ここから Derek Johnson 氏が登壇します。まず紹介するのは、Word、Excel、PowerPoint の Interactive Content です。Excel では新しい種類のシート、PowerPoint では新しい種類のスライド、Word では新しいビューとして現れ、**すべてドキュメントの中に収まる** のが特徴です。データは自動で更新され、アニメーションを備え、自然言語のプロンプトだけで編集できます。共同作業もでき、既存のファイルに追加しても、今使っている共有と共同編集の仕組みがそのまま使えます。

#### Excel

1. 通常のブックの下に新しいタブがあり、これが interactive canvas です。ワークシートのデータを元にしたダッシュボードです。
2. ライブのフィルターとピボットが使え、ホバーして内容を確認できます。グラフなどの可視化は Copilot が作成したものです。
3. What-if のシナリオで、店舗に置くべき在庫を検討できます。自然言語でビューを変更できます。
4. 自転車の在庫が 42 台と少ない、という表示が出ています。通常の Excel ワークシートなので、そのデータを直接書き換えると、戻ったときに Interactive Content がライブで更新されます。
5. すべてブックに含まれるため、同僚や顧客に共有するときも、リンクされた権限を気にする必要はない、と説明されています。

#### PowerPoint

1. Copilot で新しい interactive slide を作成し、自転車のデータがあるワークシートを取り込みます。受け取った人が操作できるビューが、1 つのプロンプトで作られます。クリックでき、アニメーションする体験で、通常の PowerPoint では作るのが非常に難しいものだと説明されています。
2. 次に PowerPoint Live in Teams と組み合わせます。PowerPoint Live は、Teams の通話中にプレゼンを共有すると、各参加者が **ローカルなコピー** を持つ仕組みです。そのため高品質で高精細に描画され、参加者が自分のペースで見られます。見逃したスライドに戻ることもできます。
3. 発表者が interactive slide を共有すると、参加者は発表者のクリックに合わせて見られます。自分で調べたい参加者は、スライド上の好きな場所をクリックして操作できます。1 つのボタンで、いつでも発表者との同期に戻れます。
4. ここでも内容はファイルに収まっているので、勝手に変わることはなく、送る内容が分かっているという点を強調しています。

#### Word

28 ページの戦略文書から、経営陣に送って意思決定を促すための interactive view を作ります。1 つのプロンプトで、視覚的で対話的な、文書内のビューが作られます。経営陣に判断してもらうための意思決定が適切に提示されているか、製品の出荷に向けてどこまで進んでいるか、という点を、クリックしながら確認します。

### 5.9 Copilot アプリの中の Office

Derek Johnson 氏は、仕事を Copilot アプリで始め、情報を集めながらアーティファクトを作成、編集する人も多いと述べます。そして、「今日、いや正確には昨日」発表したこととして、**Office のフルの機能を Copilot アプリに持ち込む** と説明します。対象は Chat、Cowork、Code で、どの製品の機能も、すべての場所で使えます。Excel で深い作業をしたければ、Copilot から Excel に引き継いで作業を続けられます。企業のセキュリティ、プライバシー、コンプライアンスもそのまま適用されます。

デモの流れは次のとおりです。

1. Copilot アプリで、収益やビジネスのデータを含むグラフ入りの文書の作成を依頼し、概要文書を作ります。
2. クリックするだけで、本物の Microsoft Word が Copilot の中に並んで表示されます。同僚に共有する流れは今と同じで、同僚は同じメールを受け取り、文書に現れてコメントを残します。相手はデスクトップクライアントでも、スマートフォンでも、Copilot アプリでもかまいません。
3. 「文書に残されたコメントに対応して」と頼むと、Copilot が実行し、Copilot 内のライブな共同編集キャンバスに更新が反映されます。
4. スプレッドシートに成長予測があるので、Copilot が Excel を呼び出し、ワンクリックで Word 文書が Excel に切り替わります。成長率をより積極的な値に直接編集します。
5. 経営陣向けに、PowerPoint のプレゼンで話をまとめます。先ほどの予測の文脈と概要文書を使うよう頼むと、プレゼンが作られ、Copilot アプリ内に並んで表示されます。
6. 発表では、**Word、Excel、PowerPoint の 100% の機能が Copilot で使える** と説明され、Copilot に最適化されています。選択した部分を自然言語で変更でき、新規作成ではなく **既存のファイルを編集** します。変更はストリーミングで反映されます。
7. 画像生成（Image Generation）でブランドのアイコンを追加し、Brian 氏が見せた Brand Kits を使えます。これらが数分でつながります。
8. 翌日戻ったときは **Library** に作成したコンテンツがまとまっています。100 のチャットがあると、どれにそのスプレッドシートがあったか分からなくなりますが、Library から成果物をクリックすると、それを作ったチャットの文脈に戻って作業を続けられます。

### 5.10 Today

最後は、毎日何をすべきかを先回りして示す体験として、Copilot に登場する **Today** です。Derek Johnson 氏は、今日の発表を見てもらえていればよいがと前置きしたうえで、「製品に加わったものの中で最もワクワクするものの 1 つ」と述べています。背景には、エージェントを多数設定すると情報や提案が大量に届き、「エージェントを管理するエージェントがほしい」という気持ちになる、という課題があります。

Today の説明は次のとおりです。

- 受信箱に届くもの、文書内のコメント、飛び交うチャットなどを 1 か所に集める。
- 集めるだけではなく、あらかじめ仕事を進めておく。たとえば承認依頼なら、承認すべきかを調べて少し調査し、返信メッセージの下書きまで用意して、クリックするだけにする。
- **設定は不要**。Work IQ の洞察を使って、ユーザーにとって重要なワークストリームを判断し、まとめる。
- 会話形式で調整できる。

デモは次の流れです。

1. 朝に大量のメールと 100 件ほどのチャット、会議の重複を見て「うわあ」となる状況から、Today の画面に切り替えます。注意すべき項目が示され、対応を Copilot が支援します。
2. Copilot の提案が外れていたり、文脈を足したくなったりしたときは、1 クリックで Copilot との会話に移れます。推奨の文脈もそのまま引き継がれます。項目はそのまま完了にできます。
3. 会議の重複では、Copilot が Work IQ で空き時間を調べて変更を提案し、1 クリックで実行します。
4. Inbox Zero を目指す人向けに、時間を割かなくてよいものも示されます。ここでは、定期的なニュースレターなどと思われる 23 件が見つかり、1 クリックでアーカイブしています。

Teams、Outlook、文書を横断して見ており、対象は今後も広げていくと説明されています。

## 7. 注意点・発表者の気付き

- **コントロールが採用の鍵**: 重要なファイルを Copilot に任せることへの不安に対し、変更箇所の網掛け、承認と取り消し、変更履歴での監査可能性が必要だと説明されています。
- **Copilot の回答は完璧ではない**: Today の説明で、Copilot が毎回正しいとは限らないこと、文脈を足したいことがあるので、ワンクリックで会話に戻れるようにしている、と話しています。
- **Excel の数式は検査できる**: ダッシュボードの数式は固定値ではなく、中身を検査できると説明されています。
- **Interactive Content は文書内で完結**: 共有時にリンクされた権限を気にしなくてよく、受け取った側で内容が勝手に変わることがない、という点が利点として挙げられています。
- **機能の発見が課題**: 利用が定着した人は毎週使うが、いまの大きな課題は、人々に機能を見つけてもらうこと、と話しています。
- **提供時期や対象の範囲**: 各機能の提供開始時期、対象プラン、制限などは発表では触れられていません。

## 8. 利用者にとっての利点

発表で語られた効果は次のとおりです。

- 機能の使い方を知らなくても、成果を説明すれば Copilot が機能を組み合わせて実行する。難しい機能（例: Power Query、Fabric に接続したピボットテーブル）を誰でも使える。
- 作業の流れの中（右クリックの Rewrite、数式の提案など）で使え、新しい作業方法を覚え直す必要がない。
- Copilot の編集を確認、承認、取り消しでき、変更履歴で人とエージェントの編集を区別できる。他の人の編集を残したまま、特定の人の編集だけを取り消せる。
- 業種別スキルや、自社のスキル、Brand Kits で、自社の業務やブランドに沿った動きをさせられる。
- LSEG、Moody's、Harvey、Fabric、Mercury、SharePoint などのデータに接続して、Excel や Word の作業に使える。
- Microsoft 365 Copilot ライセンスは固定の月額で、使う量に左右されない。
- Interactive Content により、データと連動した対話型の資料を、ファイル内で共有できる。
- Today により、受信箱、チャット、文書のコメント、会議の重複を 1 か所で整理し、返信の下書きまで用意できる。

利用状況として具体的な数値が示されたのは、財務分野での 50% 超というプロンプトの割合だけです。顧客事例や導入効果の数値は、発表では触れられていません。

## 9. まとめ

Copilot は、操作方法を答える存在から、アプリの中で作業を実行し、さらに成果を伝えれば仕事を進めてくれる存在に変わりました。Brian Jones 氏のパートでは、財務の差異分析から契約書の起案まで、スキル、データ接続、カスタムスキル、Brand Kits、監査という形で、自社の業務に合わせて任せられることが示されました。Derek Johnson 氏のパートでは、文書の中に収まる Interactive Content、Copilot アプリの中で動く本物の Word、Excel、PowerPoint、そして先回りで仕事を整理する Today が紹介されました。両氏に共通するメッセージは、時間と手間を減らしつつ、ユーザーがコントロールを保つことです。
