# BRK491 Frontier Transformation: The Trillion-Dollar Partner Opportunity

## 1. はじめに

このセッションは、Microsoft のパートナー企業（SME&C 顧客を担当するチャネルパートナー、AI ネイティブなパートナーなど）に向けて、AI による「Frontier Transformation」が生み出すサービス ビジネスの機会と、それを実際に事業にするための道具立てを紹介する 45 分の講演です。技術的な機能解説やデモは中心ではなく、市場の見方、パートナー向けプログラムと投資、そして Frontier 向けの実践（プラクティス）を立ち上げるための具体策が語られます。

話は 3 人の登壇者のリレーで進みます。最初に市場機会とサービスの収益構造の変化、次に Microsoft AI Cloud Partner Program などの支援策と投資、最後にスキル育成（Frontier Transformation Engineer バッジ）と、顧客に提案するオファーの組み立て方です。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/BRK491](https://ignite.microsoft.com/en-US/sessions/BRK491)

## 3. 何に関する発表か

発表の軸は「Frontier firm（AI を前提に変革した企業）を、パートナーがどう作っていくか」です。Microsoft はプラットフォームを用意したが、成果（outcome）は箱に入って出荷されるものではなく、導入・スキル・サービスを担うパートナーが必要だ、というのが出発点になっています。

流れは次のとおりです。

1. 市場の現状（AI の導入は進むが、信頼と価値の実感はこれから）
2. Microsoft のプラットフォームの 3 つの柱（人の野心、インテリジェンス、信頼）
3. 過去のビジネスモデルの「天井」と、AI 時代の収益機会
4. 収益の成長要因と阻害要因、サービスの種類（アドバイス／導入／マネージド）
5. パートナーが取るべき 4 つのシフトと、AI ネイティブなパートナーから得た学び
6. パートナーの支援策（プログラム、スキル、マーケティング、新ツール、投資）
7. Frontier プラクティスの作り方（スキル、HVE、Frontier transformation partner offer、学んだ教訓）
8. パートナーの声と、自己診断、次のステップ

## 4. 発表者が伝えたいメッセージ

最初の登壇者の主張は、**AI 時代のパートナー収益は「ライセンスの数」ではなく「どれだけの仕事が行われ、価値が出るか」に結び付くため、天井がない**という点です。すべての Copilot の利用、エージェント、ワークフローがパートナーの収益源になると述べ、これを「1 兆ドルの機会」と呼んでいます。

ただしその機会は自動では手に入りません。生産性の圧縮による収益減、先行投資の必要、商談期間の長期化、技術のコンシューマ化による収益化の圧縮といった阻害要因もあるため、パートナー自身が「Customer zero（まず自社で使い、価値を証明する）」から始め、サービスの作り方と売り方を変える必要があるというのが一貫したメッセージです。Heather と David も、この Customer zero を土台に置いています。

## 5. 発表内容の詳細

### 5.1 市場の現状: 導入は進むが、信頼と価値は追いついていない

最初に、次の数値が示されました。

| 内容 | 数値 |
| ---- | ---- |
| 今後 12 か月で AI への支出が 10% を超えて増えると見込む | 71% |
| AI エージェントを大規模に展開中 | 32% |
| すでに自社でソリューションを構築している SMB | 67% |
| すでに AI を使っている人 | 66% |
| AI から大きな、または変革的な価値が出ていると答えた CIO | 13% |
| AI が自分で判断することを信頼している消費者 | 31% |

使うことへの慣れ（comfort）は高い一方で、信頼（trust）と価値の実現はまだ高くない、という対比です。登壇者は、この緊張関係への答えが Microsoft のプラットフォームだとして、次の 3 つの柱を挙げています。

- **人の野心（Human ambition）**: Copilot はかつて「AI の UI」と説明されていたが、今は「OS for work（仕事の OS）」になり、すべての Frontier firm にとっての入口になる。なお、この箇所で語られた Copilot の個別の呼び名（"home"、"code"、"autopilot" と聞こえる）は、音声認識の都合で表記が確定できません。
- **インテリジェンス（Intelligence）**: レジストリ、コンテキスト、そして Microsoft IQ が提供する基盤。顧客の IP（Frontier firm の "alpha"）を保つことが重要だとしています。
- **信頼（Trust）**: エージェントの統制、保護、管理。Agent 365 と、それに付随する FinOps の機能に期待していると述べ、パートナーの収益機会はここで加速するとしています。

### 5.2 パートナーに求められること

登壇者は、Microsoft 自身が社内で Frontier company を作って大企業の顧客を支援してきたが、中堅・中小企業については、パートナーが Frontier firm 作りを担う必要があると述べています。パートナーが提供できるものとして、まずスキル習得（営業、技術、非技術の全員）、次に成果の実現、そしてセキュアな AI の機会を挙げました。

セキュリティについては、セキュリティだけのパートナーにも完全なポートフォリオが用意されているとし、perception によって「機械で機械に勝つ」答えがある（音声認識の都合で製品名の表記は確定できません）と述べています。また Frontier モデルが提供しないものとして FinOps 機能を挙げ、「メーターを回すためではなく、価値を引き出すことが目的」だと説明しています。Agent 365 を通じてコストを管理でき、そこにサービスやプラクティスを作る余地がある、という流れです。

### 5.3 各時代の「天井」と AI 時代の収益機会

過去のモデルを次のように振り返っています。

| 時代 | 収益の考え方 | 天井 |
| ---- | ---- | ---- |
| リセール | 数量が増えれば成長するが、スキル投資が必要 | 価格の下落とコモディティ化 |
| モバイル | デバイス単位のモデル | デバイスの台数と、それが人の手に渡る数 |
| SaaS | サブスクリプションと利用者数（人数） | 利用者数・人員数 |

（トランスクリプトでは "SAS" と表記されていますが、文脈から SaaS を指します。）

これに対して、クラウドと AI が組み合わさると、シート（利用者数）と消費量の両方を管理する機会になり、仕事が増えるほど収益機会も価値も増えるため、天井は「どれだけの仕事が、どのように行われるか」で決まり、限りがないと説明しています。TAM（獲得可能な市場）は、4 億 5,000 万の Microsoft 365 シートの上にあり、これらのシートはまず Copilot を採用することから始める必要があるとしています。

### 5.4 成長要因と阻害要因

**成長要因**は、1 兆ドルの機会と、発表では「3x の成長率」と述べられた伸び、新しいサービス提供とサービスの拡張、差別化と IP を作ることで生まれる新しい収益プール、そして継続的なイノベーションです。パートナーから「半年前に今日の内容を知りたかった」と言われるが、Microsoft 側も先は分からない、それこそがこの時代のおもしろさだと述べています。

**阻害要因**として、次の 4 点が挙げられています。

1. **生産性の圧縮**: AI により、パートナー自身の収益が圧縮される可能性がある
2. **先行投資**: スキル習得、FDE の採用、営業担当者を 1 日研修に出すことなど（FDE という略語の意味は、発表では説明されていません）
3. **商談期間の長期化**: Agentic GTM で短くする必要がある。これまでのチャネルは「ライセンスの動き」を中心に作られていたが、今後は価値を売るチャネルに変える必要がある。そのために、商談の組み立て（deal shaping）や deal clinic を通じ、パートナーと Microsoft の営業の足並みをそろえて商談期間を圧縮したい
4. **コンシューマ化による収益化の圧縮**: 技術が身近になり「簡単に見える」ため、価値が低く見積もられやすい。登壇者は、インテリジェンスはすべてエージェントの中にあると言われがちだが、実際はもっと複雑で、価値も大きいと述べています

### 5.5 サービスの種類とマージン

サービスの形は「Advise → Deploy → Manage」です。

| 区分 | 内容 |
| ---- | ---- |
| アドバイザリー | トレーニング、アダプション（定着）、チェンジマネジメント。調査では 20〜30% 程度のマージンとの話（どのサービスの数値かは、音声からは明確ではありません） |
| デプロイ | エージェントなどソリューションの開発と導入 |
| マネージドサービス | 下記の 3 つの機会。Agent 365 は、エージェントのコントロールプレーンであるだけでなく AI の観測性（observability）の層でもあり、多くのマネージドサービスの機会を生むと説明されています |

マネージドサービスの機会として、次の 3 つが語られました。

- **FinOps**: 顧客がコストを考えるのを助け、"home"、"code"、"autopilot" のどれをいつ使うか、何をするとメーターがどう回るかを教える（呼び名は音声認識の都合で表記が確定できません）
- **セキュリティオペレーション**: "perception" という製品名（音声認識の都合で表記が確定できません）によりゲームが変わる。「XDR は陳腐化する」「エージェントの脅威には人ではなくエージェントで戦う」と述べ、"ISOC" という運用の機会にも触れています
- **エージェントオペレーション**: エージェントがやがて Frontier firm の FTE（社員）のようになるため、その管理・統制・制御が必要になる

マージンは、プラクティスの作り方、差別化、自社 IP、"alpha" の作り方に依存するとしています。

### 5.6 パートナーが取るべき 4 つのシフト

1. プロダクト主導のオファーから、アドバイザリー主導の包括的なソリューション提供へ（ビジネス課題を解く）
2. 個別のソリューションから、エンドツーエンドのワークフロー変革へ（効率、体験、生産性といった KPI を何にするか）
3. 単一ワークフローの AI 導入から、ワークフロー横断のオーケストレーションへ（CRM や ERP など、業務が動く場所でのビルド済み・カスタムエージェントの連携）
4. プロダクトの利用促進から、ビジネス成果の実現へ

成果の話は、デジタルトランスフォーメーションの頃から言われてきたものの、成果に対する支払いを受ける契約では KPI に届くことが難しかった、という経験を語っています。AI、特に Agent 365 のようなツールにより、AI の事業やワークフローへの影響を把握しやすくなり、これが加速すると述べています。

### 5.7 AI ネイティブなパートナーから得た学び

Alex は、AI ネイティブな SI などの新しいパートナーから学んだこととして、次の 6 点を挙げています。

1. **まず社内で価値を証明する（Customer zero）**: 「Frontier を生きていなければ、Frontier は売れない」。こうしたパートナーでは、全社員に 3〜4 個のエージェントを割り当てて立ち上げている
2. **繰り返せるものをプロダクト化する**: 繰り返し売れるサービスを見つける。業種特化の場合もある（例として、サプライチェーンの発注、美容師の予約管理）
3. **人とエージェントを前提に、提供の仕方を作り直す**: エージェント（"autopilot" と聞こえる語）に名前を付けて組織図に載せ、会議にも参加させる、といった世界で、自社と顧客の仕事の組み立てを考える
4. **技術的な深さに投資する**: 営業を含め、技術系と非技術系の境界があいまいになってきている
5. **価値の売り方と測り方を変える**: 成果と KPI の定義に結び付く
6. **信頼とスケールを運用に落とし込む**

### 5.8 AI Transformation パートナーのフレームワーク（Build / Sell / Deliver）

Microsoft が社内で使っているフレームワークとして、Build、Sell、Deliver の 3 本柱が紹介されました。発表で詳しく説明されたのは Build と Sell です。

- **Build**: サービスプラクティスの作り方。自社固有の IP の開発
- **Sell**: 経済モデルを、継続課金と成果ベースへ転換する。Customer zero になるほど営業の動きが変わり、エージェントの営業コーチを営業活動に組み込むなど、営業の動きを描き直す

Deliver については、この部分では個別の説明はありませんでした。パートナーが自己評価できる診断は、5.12 に書きます。

### 5.9 Heather: 支援策と投資

Heather は、イノベーションの速さは Microsoft の株主としては誇らしいが、個人として全部を消化するのは圧倒されるほどだと述べ、整理するための公式として、**Build**（差別化された能力を作る）、**Go to market**（スケールとリーチを広げ、繰り返せるオファーにする）、**Investments**（投資）を示しました。Alex と使っている言葉として "precision velocity" を挙げ、適切な顧客に、適切なオファーを、適切なタイミングで、的確に届けることだと説明しています。土台は Customer zero で、Copilot や AI を自社でどう使い、従業員と顧客に価値を出しているかを、実感をもって語れることだとしています。

Customer zero については、世界各地のパートナーの発言をスライドで見せたとも述べています（読み上げはなく、内容は書き起こしからは分かりません）。

**IDC の調査**: 前日のメインステージで触れられた調査で、レポートが公開されたと述べています。印象的な数値として、AI の取り組みがより進んでいる企業は、そうでないパートナーに比べて、より高い収益の乗数を持つ（67% の企業）ことを紹介しました。

**Microsoft AI Cloud Partner Program** が Customer zero になるのを支えるものとして、次が挙げられました。

| 項目 | 説明 |
| ---- | ---- |
| 社内利用権（internal use rights） | 特典を通じて得られる。コミットメントのレベルにかかわらず、すべてのオファリングに Copilot を組み込み、自社内にデプロイできる |
| スキル習得 | 技術・営業・マーケティング向けに多数のリソース。時間のない人向けに、無料の小分け（bite-sized）マイクロスキルも用意 |
| Designations と specializations | 顧客から「パートナーが 50 万社もある中でどれを選べばよいか」と聞かれるため、技術検証済み、または営業準備ができていることを示す指標として案内している |

Heather は、Microsoft の提供範囲の広さは強みであると同時に、理解しにくさの原因でもあると認めています。年に 1 回どころか半年ごとでもなく、リアルタイムに新しいものが出る時代なので、パートナーが関与しやすく、自社のプラクティスに合うものを選びやすくしたい、という趣旨です。

### 5.10 David: Frontier プラクティスの作り方

David は「Frontier プラクティスをどう成功させるか」を、約 10 分で話すと切り出し、4 つの領域を示しました。

1. **Customer zero**: 自分で使っていないと売れない。さらに一歩進めて、サービスパートナーは、エージェント型のデリバリー能力（agentic delivery）を自社のプラクティスに組み込むべきで、それが差別化になるとしています。
2. **スキル**: Frontier Transformation Engineer バッジ。
3. **プラクティスの構築**: 顧客が適切な技術を評価し、導入し、さらにマネージドサービスにつなげるための支援。
4. **顧客との関わり方の FDE 的な能力**: Frontier transformation offer。

7 月に発表された「Frontier Co」（音声認識の都合で表記が確定できません）は、戦略アカウントの顧客を対象としたものだと説明し、企業（corporate）や SMB の分野でも FTE の能力をエコシステム全体に作ることが重要だとしています。なお、"FTE" と "FDE" はトランスクリプト上で混在して聞こえ、いずれも発表では略語の展開がありません。

#### Frontier Transformation Engineer バッジ

| 項目 | 内容 |
| ---- | ---- |
| 要件 | 3 つの認定資格（試験）と、約 80 時間のスキル習得 |
| 狙い | 専門分野を絞れ、と言われてきたこれまでと異なり、Frontier transformation の時代には各スキルが交差し、ソリューションをまたいで対応できる人材が必須になる。そうした「ユニコーン」型の人材を育てる |

David は、パートナーが高額なシニアエンジニアの採用を話題にすることに対し、**新卒など社会人初期の人材をこの道筋で育てる**という考え方もあると述べています。AI ネイティブ企業が、従来の意味でのデリバリー人材ではない新卒を採用して成果を出しているのを見ているそうです。このバッジの人材（"FTE light" と聞こえる語）は、顧客とビジネスやソリューションの構想を話し、デザイン思考を持ち、手を動かしてコードも書ける、と説明されました。

#### Hypervelocity engineering（HVE）

バッジで学べる SDLC の方法論で、Microsoft が数年かけて作ってきたものです。David は「アジャイルのステロイド版」と呼んでいます。反復的な開発に加え、エージェント型のデリバリーが組み込まれています。無料で、GitHub のリポジトリ（"hypervelocity engineering" または "HVE" で検索）に資料が公開されています。効果として次の数値が語られました。

- デリバリーサイクルの速度が 2〜3 倍になると見込んでいる

#### Frontier transformation partner offer

FTE のスキルを持つ人材ができたら、顧客のもとで次のことを行うオファーを作ることを勧めています。

1. 影響と ROI、そして必要な作業量（実装の難易度）をもとに、ユースケースを特定し、取り組みやすいものから順位付けする
2. 企業全体で使えるセキュアな AI ランディングゾーンを作る
3. Copilot を「AI の UI」および「仕事の OS」として位置付ける
4. 顧客が Frontier transformation の目標を実現するためのサービスのロードマップを作る

この取り組みは、パートナーによって約 6 週間から 16 週間で実施されており、顧客のセグメントや成熟度で変わります。成果としてマスターデータ管理、セキュリティ、次のユースケース展開など、その後数年分のサービスのパイプラインが生まれます。最初にこれを行うことで、顧客の信頼を得て、最も関連性の高いユースケースを特定でき、完全に安全なランディングゾーンを持てると説明しています。また、初期のユースケースを個別に作ったパートナーでは、最初のユースケースの後にランディングゾーンを作り直す必要があった（単一目的で設計されていたため）という教訓も語られました。さらに、バックエンドだけに注力すると、Copilot を「仕事の OS」として保護する機会を逃すとしています。

## 7. 注意点・発表者の気付き

- **ライセンス中心から価値中心へ**: これまでのチャネルは「ライセンスの動き」で作られていたが、価値を売るチャネルへの転換が必要で、そのために商談の組み立てや deal clinic が要るという認識が語られています。
- **コンシューマ化の影響**: AI が身近になったことで「簡単に見える」ため、価値が低く見積もられ、収益化が圧縮される恐れがあります。
- **ランディングゾーンの作り直し**: 最初のユースケース用に単一目的で作ったランディングゾーンは、後で作り直しになったパートナーがいます。最初から企業全体で使えるセキュアな設計にすることが勧められています。
- **ガバナンスは最初から**: 概念実証では厳密さは不要でも、本番展開時のガバナンスとセキュリティの戦略が必要です。
- **展開後の管理**: エージェントは継続的な評価と最適化が必要です。
- **投資の分散に注意**: Microsoft 側の方針として、全方位に薄く投資する方法は機能しなかったため、重点分野に集中させるとしています。
- **将来機能の提供時期**: Sales recommender は現在限定提供で、1 月に全員へ提供。Partner Center for Sales は 1 月に提供予定と述べられています。

## 8. 利用者にとっての利点

このセッションの「お客様」は、顧客企業に AI を提供するパートナーです。発表で語られた利点と成果は次のとおりです。

- **収益機会**: Copilot の利用、エージェント、ワークフローごとに収益源ができ、天井が限られない。TAM は 4 億 5,000 万の Microsoft 365 シート上にある
- **AI を進めている企業の収益**: IDC の調査で、AI の取り組みが進んでいる企業は収益の乗数が高いという結果（67% の企業）

## 9. まとめ

AI 時代のパートナー ビジネスは、ライセンスや台数ではなく、仕事の量と価値に収益が結び付くため、天井が限られないというのがセッションの主張です。そのためには、パートナー自身が Customer zero として自社で使い、アドバイザリー主導・ワークフロー横断・成果重視へサービスを組み替える必要があります。

Microsoft 側は、AI Cloud Partner Program の特典（4 つ目のレベルの新設）、無料のマイクロスキル、Partner Marketing Center Pro、1 月に登場予定のツール群、FY27 で 19% 増の投資を用意しています。実践面では、約 80 時間と 3 つの認定資格からなる Frontier Transformation Engineer バッジ、HVE、そして 6〜16 週間の Frontier transformation partner offer を軸にプラクティスを築くことを勧めています。出発点として、約 30 分・30 問の自己診断アセスメントが案内されました。
