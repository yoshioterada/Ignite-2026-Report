# THR955 Pro Badge: The credential you've been asking for

## 1. はじめに

このセッションは、GitHub Copilot の日々の使い方を評価して認定する新しい資格「Pro Badge」を紹介する、シアター形式の発表です。従来の認定資格が「知っていること」を証明するのに対し、Pro Badge は「毎日の仕事の中で実際にどう使っているか」を証明します。

発表者は、これを**業界初**の資格タイプだと説明しています。評価は試験ではなく、製品の利用状況を示すテレメトリ（利用データ）から行われます。参加は完全に任意（オプトイン）で、既定では非公開です。発表では、評価の枠組み、5 つのレベル、現在の提供範囲、今後の予定、獲得後の共有方法が順に語られました。画面を使ったデモは行われていません。

## 3. 何に関する発表か

テーマは、開発者のスキルを「知識」と「技（わざ）」の 2 面で捉え、これまで測りにくかった「技」の側を測る資格を作った、という話です。ここでの「開発者」は、地下室でコードを書く昔ながらの開発者ではなく、GitHub Copilot によって参入の壁がほとんどなくなった現在の「誰もが開発者」という意味で使われています。

発表の流れは次のとおりです。

1. 動機：履歴書や LinkedIn では語れない「日々の仕事の実績」
2. 知識と技（ラバーダック・デバッグの例え）、既存の資格との関係
3. Pro Badge と「熟練度検証フレームワーク」（3 つの要素）
4. 5 つのレベルと、評価する 5 つの観点
5. 毎日評価される仕組み（有効期間 6 か月、直近 30 日の集計）
6. 自分のレベルを確認する方法と、配布される帽子
7. 今後の予定
8. バッジの共有（Credly、LinkedIn）と他製品への展開

## 4. 発表者が伝えたいメッセージ

最大のメッセージは、資格は「一度取って終わり」の節目ではなく、**毎日の使い方が見える形で評価され、育っていくものになる**ということです。Tiffany は、長年資格の仕事をしてきて、1〜2 年ごとの更新では「毎日その仕事をしている」ことを示せないという課題があったと述べています。Pro Badge はそれに応える、製品の中での実際の行動に基づく評価です。

もう 1 つの重点は、評価の目的が使用量ではなく**使い方の質**にあることです。プロンプトを大量に送って「今月はたくさん使った」と言うのではなく、効果的に使えているかを見る、と Aaron は強調しています。評価を通じて、これまで使っていなかった機能に気づき、製品の活用範囲を広げてほしいという狙いも語られました。

プライバシーについては、完全に任意でオプトインであり、既定で非公開という点が繰り返し強調されました。評価の対象は利用の仕方であり、コードそのものは見ません。

## 5. 発表内容の詳細

### 5.1 動機：履歴書が語らない「日々の仕事」

Aaron は、すべての開発者には履歴書では語れない物語がある、と話を始めました。LinkedIn には実績、節目、認定資格を載せられ、履歴書を見れば職業人生の概要がつかめます。しかしこの発表が扱うのは、そこに載らない「日々の仕事の流れの中での実践」です。

### 5.2 知識と技、既存の資格との関係

優れた開発者を 2 つの側面で捉えています。

| 側面 | 内容 | 現状 |
| --- | --- | --- |
| 知識 | 理解していること。認定資格や Applied Skills で証明できる。暗記が必要な規則や方針も含む | 長年うまく測れている |
| 技（クラフト） | 毎日の仕事で実際にやっていること | 熟練度を測る試みはあったが、大きな課題が残っていた |

技の側を表すために、画面にはアヒルのアニメーションが映されました。開発の世界には、机の上の無生物に話しかけて問題を整理する「ラバーダック・デバッグ」という習慣があり、毎日の作業そのものが「技」だという例えです。

既存の資格は、役割への習熟を示す認定資格（Certification）が長く提供されてきました。最近になって、パフォーマンスベースで工程重視、製品をまたげるマイクロ資格の Applied Skills が加わっています。Tiffany は、認定資格を引き続き推進し、多くの投資を続けると断っています。そのうえで、今回の新しい資格は「役割を理解している」「意思決定や規則を知っている」という側に加えて、「現場で実際に使っている」ことの証明を足し、資格の全体像を完成させるものだと位置づけています。

Tiffany はパイロットの例えを使っています。パイロットには天候や管制の知識が必要ですが、同時に飛行機を安全に着陸させられることも求められます。Pro Badge は、後者を製品内の行動から評価する取り組みです。

### 5.3 Pro Badge と熟練度検証フレームワーク

Pro Badge は、獲得する資格（バッジ）の部分を指します。その下には「熟練度検証フレームワーク（Proficiency Verified Framework）」があり、次の 3 つの要素で構成されると説明されました。

1. **基準を定める熟練度フレームワーク**：評価のロジック。専門家、製品チーム、認定資格チームなど社内の多くの関係者と数か月かけて作った。
2. **検証された熟練度**：実際に測定する部分。利用者が毎日行う操作が対象で、製品を使っていなければデータがなく、バッジも得られない。
3. 3 つ目：下の補足を参照。

> 補足：発話で内容が説明されたのは 1 つ目と 2 つ目です。3 つ目の要素が何かは、音声からは確認できません。Pro Badge は資格の部分で、その下にフレームワークがあるという関係は語られています。

### 5.4 5 つのレベル

オプトインすると、製品のテレメトリが分析され、次の 5 つのレベルのどれかに割り当てられます。

| レベル | 発表時点の状況 |
| --- | --- |
| 初級（beginner） | 提供中 |
| 中級（intermediate） | 提供中 |
| 熟練（proficient） | 提供中 |
| 上級（advanced） | 開発中 |
| エキスパート（expert） | 開発中 |

上位 3 つのレベルがスライドで緑色に強調され、Pro Badge が得られる対象だと説明されています。一方で、提供済みなのは初級・中級・熟練の 3 つで、上級とエキスパートは開発中だとも述べられています。この 2 つの説明の対応関係は、発話だけでは整理できません。

提供開始について、Aaron は Universe（GitHub のイベント）で 2 週間前に一般公開したと述べています。熟練（proficient）に達すると認定バッジが得られ、LinkedIn に送れます。AI Skills Navigator との連携もあります。共有するかどうかは本人次第で、データは既定で非公開です。

### 5.5 評価の観点と測り方

評価は「どれだけ使ったか」ではなく「どう使っているか」を見ます。観点は次の 5 つです。

1. **AI との協働**：どう計画し、反復し、アイデアを磨いているか。
2. **効果的なプロンプト**：チャットに入力して返答を待つだけでなく、リポジトリのコンテキストを与えているか。
3. **コードの検証**：コードそのものは見ません。差分のレビュー、エッジケースのテスト、品質の確認など、Copilot とどう関わっているかを見ます。
4. **エージェントの構成**：カスタム指示を使っているか、それとも何も設定せずに送って良い結果を期待しているか。
5. **コンテキストの統合**：github.com だけでなく、IDE、CLI、モバイルを含め、あらゆる利用環境を横断して見る。人によって使い方が違うため、特定のワークフローに誘導しないことが目的です。

Aaron は、コードの中身は一切見ず、見るのは Copilot との関わり方だと念を押しています。

測り方の枠組みは、ブルームのタキソノミー（教育目標の分類）に着想を得て作ったとのことです。初級では「認識しているか。定義、特定、所在の確認ができるか」を見ます。進むにつれて「理解、応用、評価ができるか。試しているか」となり、最終的には「オーケストレーションできるか、規模を広げているか、ソリューションを構築しているか」へと向かいます。

### 5.6 毎日測られる評価の仕組み

認定資格は意図的に長期間安定していますが、Pro Badge はオプトインした人を**毎日**評価します。レベルは保たれることも、上がることも、下がることもあります。

- バッジとして獲得した資格は **6 か月**間安定して有効です。
- 日々の評価は、毎日の使い方に応じて変動します。
- 新機能は頻繁に追加され、そのたびに評価に取り込まれます。
- 現在の集計対象は**直近 30 日間のローリングウィンドウ**です。6 か月前にたくさん使っていても、オプトインした日からのデータを使えるわけではなく、今の使い方が反映されます。この期間は将来拡大する予定です。

毎日の更新は、利用者に次の行動を促す意図もあります。初級の人は「次のレベルに必要なことはこれだ」と分かり、翌日にはもう少し頑張ろうと考えられます。維持のために何が要るかも日々分かります。一度設定すれば（GitHub Copilot のアカウントでオプトイン）、あとは自動で検証が続き、オン・オフは本人が切り替えられます。

### 5.7 自分のレベルの確認方法と特典

確認手順は次のとおりです。

1. 画面の QR コードを読み取り、learn.github.com のページを開く（発話での表記）。このページには GitHub の認定資格、実践的なスキル習得の案内、熟練度フレームワークの情報があります。
2. GitHub アカウントでサインインする。
3. 緑色のボタンをクリックして、熟練度レベルを計算する。

ダッシュボードが表示され、自分のレベルが何を意味するかも見られます。GitHub Copilot を使ったことがない場合は機能しません。

熟練（proficient）に到達した人は、会場のブースで特典の限定帽子を受け取れます。数は会期全体で 200 個で、なくなったら終了と説明されました。発表者は、自分たちがその帽子をかぶっていると話しています。

### 5.8 今後の予定

直近の追加として、次の項目が挙げられました。いずれも発表時点では**未提供の計画**です。日付は示されていません。

| 項目 | 説明 |
| --- | --- |
| 上級・エキスパートのレベル | 開発中。「非常に近い」が日付は示さない |
| EMU アカウント | Enterprise Managed User。複数の個人 GitHub アカウントを束ねて 1 つの熟練度スコアにするマルチアカウント対応の位置づけ。組織がテレメトリを収集していれば、その情報も本人に渡せるようにする |
| データ検証期間の拡大 | 現在の直近 30 日より長くする |
| 個人別のテレメトリ記録 | 製品をどう使っているか、使っていない領域は何かを詳しく一覧化する。評価が低いと伝える趣旨ではなく、知らなかった機能に気づくためのもの |
| カスタム学習の提供 | 最終的に Microsoft Learn、AI Skills Navigator、LinkedIn Learning を通じて、スキル向上のための学習を案内する |

さらに、Pro Badge を他の製品領域へ拡大する計画があるものの、内容は公開できない、と Tiffany は述べています。Aaron も、GitHub Copilot は開発者中心のペルソナ向けの「始まり」であり、GitHub 製品や Microsoft 製品を超えて広げていくと話しました。

### 5.9 バッジの共有

獲得後の共有について、次の点が語られました。

- **Credly バッジ**：Credly のバッジが再び利用可能になったと、このセッションで初めて発表されました。認定資格のバッジもまもなく復活し、Applied Skills も利用可能になります。Pro Badge の Credly バッジは「いままさに発行中」とのことです。
- **LinkedIn**：専門家としての実績を LinkedIn で示すことを強く勧めています。

共有の方法を示すスライドも用意されていますが、内容は発話から詳しくは確認できません。

## 7. 注意点・発表者の気付き

- **オプトインが前提**です。オンにするまで測定は行われず、オン・オフは本人が切り替えられます。
- **製品を使っていなければバッジは得られません**。テレメトリがないと測定できません。
- 評価は現在、**直近 30 日**のデータが対象です。以前の利用実績は反映されません。
- **使用量ではなく質**を見ます。プロンプトを大量に送るだけでは評価につながりません。
- バッジの有効期間は 6 か月ですが、日々のレベルは変動します。
- 熟練の帽子は 200 個限りです。
- 提供済みなのは初級・中級・熟練のみで、上級・エキスパート、EMU 対応などは将来の計画です。
- 現時点の対象は GitHub Copilot です。他製品への展開は計画のみで、詳細は非公開です。
- 発表者は、早期アクセスを提供した同僚やパートナー、顧客の多くから、「製品にこんな機能があるとは知らなかった」「狭い範囲でしか使っていなかったが、使っていない領域が見えた」という声があったと述べています。

## 8. 利用者にとっての利点

- 毎日の実際の使い方が資格として可視化され、LinkedIn などで示せます。
- 現在のレベルと、次のレベルに必要なことが毎日分かります。
- 使っていなかった機能に気づき、製品の活用範囲を広げられます。
- 個人の判断で公開・非公開を選べ、コードの中身は見られません。
- 将来は、個人別の利用記録に基づく学習の案内が計画されています（未提供）。

## 9. まとめ

Pro Badge は、GitHub Copilot を毎日の仕事でどう使っているかを、テレメトリから評価して認定する新しい資格です。初級・中級・熟練の 3 レベルが Universe で公開済みで、learn.github.com で自分のレベルを確認できます。評価は使用量ではなく質を見て、直近 30 日のデータで毎日更新され、バッジの有効期間は 6 か月です。上級・エキスパート、EMU 対応、検証期間の拡大、個人別の記録、他製品への展開は、これからの計画です。
