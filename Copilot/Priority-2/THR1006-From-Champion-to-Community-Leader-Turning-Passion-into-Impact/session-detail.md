# THR1006 From Champion to Community Leader: Turning Passion into Impact

## 1. はじめに

このセッションは、Microsoft のコミュニティで活動する 4 人が壇上で語り合う、約 25 分のパネルトーク（開始時に「24 分ある」と司会が述べています）です。テーマは、コミュニティのリーダーになるまでの道のりです。最初のきっかけ、貢献の方法、MVP への道、キャリアについての助言が、体験談を交えて語られました。

製品の機能や技術の解説はなく、**「好きなことを人に見せて、発信を続ける」ことがコミュニティへの入口になる**という点が全体を通した話の中心です。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/THR1006](https://ignite.microsoft.com/en-US/sessions/THR1006)

## 3. 何に関する発表か

Microsoft の技術コミュニティで、参加者から貢献者、さらにリーダーへと進むとはどういうことかを、MVP などの経験者が語るパネルです。会場の参加者にも、初めてのイベントか、地域のイベントやユーザーグループに行ったことがあるかといった質問が投げかけられ、対話形式で進みました。

流れは次のとおりです。

1. 自己紹介と、MVP の人数などの数字
2. コミュニティに入った最初の瞬間
3. 好きな貢献の方法
4. Regional Director プログラムと MVP になる方法
5. 「はい」と言った瞬間と、MVP の利点、不採択の経験

7. 締めのあいさつ

メッセージは 3 点にまとめられます。1 つ目は、司会が述べた**始める場所は今、始める時は今日**ということ。2 つ目は、頭の中の「もし〜だったら」を気にせず、自分が好きな内容を発信すること。3 つ目は、Martina の体験談に対して司会が受けた、情熱があれば反対する人の意見は重要ではないということです。

## 5. 発表内容の詳細

### 5.1 コミュニティに入った最初の瞬間

司会は「自分が何か面白いものの一員だと感じたのはいつか」と尋ねました。

1 人は、SharePoint Saturdays（SharePoint をテーマにした週末の地域イベント）を挙げました。仕事とは別に、自費で各地へ移動して教えに来る人たちがいて、同じ製品に同じ熱量を持つ人がほかにもいると分かったそうです。この集まりを 25 年間、家族の再会のように感じていると話しました。

Martina は、SharePoint のコミュニティの人たちのよさを語り、ヨーロッパでは土曜に人が集まりにくいため、SharePoint Saturday が金曜に開かれることもあったと話しました。そして、**知識は共有しても減らず、ほかの人の中で増えていく**ことが自分にとって大切だと述べています。

Jeremy も SharePoint Saturday を挙げ、元 SharePoint 開発者だと述べました。続けて、ソーシャルメディアを通じて .NET の新しい C# の機能について話すうちに、世界中の .NET 開発者が同じ悩みと関心を持っていると知ったと語りました。新型コロナの流行期にはオンラインの .NET ユーザーグループが各地で開かれ、世界中の人が .NET で作ったものを発表していることに驚いたそうです。.NET Foundation の一員になったのは .NET に成功してほしかったからで、ユーザーグループの運営も手伝いました。収録を回す人がいないときに自分で担当したこともあるという話です。コミュニティに還元しながら刺激ももらえる点を、貴重だと話しています。

### 5.2 好きな貢献の方法

司会は、会場の参加者にも、初めてのイベント参加者、大きなイベントへの参加者、地域イベントやユーザーグループ、Community Days のような 1 日のイベントへの参加経験者を挙げてもらいました。その後、各自の好きな貢献の方法を尋ねました。

- **登壇と記事（話者の特定は発話では確認できません）**：できれば毎日カンファレンスで登壇していたいほど登壇が好きだと話しました。MVP の資格を保つための実績は主に LinkedIn の記事で、そこから技術者から「考えを引っ張るリーダー（ソートリーダー）」へ立場が変わったそうです。読者が増えて、フォロワーとして会いに来てくれるのがうれしいという話です。司会は「LinkedIn が新しいブログなのか」と会場に尋ね、Substack は文化や政治の話題に寄っていて技術向けではないと触れました。
- **Martina**：カンファレンスでの登壇と知識の共有が好きで、新しいことを試して書くのも好きだと述べました。最初は自分のブログに記事を載せていたそうです。ほかの人が考えつかなかった難しい質問に取り組み、解決策を見つけることにも魅力を感じていると話しています。LinkedIn は苦手と言いつつ、コンテンツの投稿は続けています。
- **ソーシャルメディア中心の登壇者（話者の特定は発話では確認できません）**：ソーシャルメディアで新しい技術を紹介するのが好きで、基調講演では会場に入れなかったため、配信を見て、驚いた内容を共有したと述べています。交流に加えて、.NET や Microsoft のプロジェクトへの GitHub 上の貢献を挙げました。例として PowerToys を何度も紹介し、自分のデバイスで正しく動かなかったため ARM64 に移植したと話しています。人に貢献のやり方を教え、会話を始めて人をつなぐことが好きだそうです。話者の特定は上と同じく発話では確認できません。

司会は、メンタリング、ユーザーグループの手伝い、製品へのフィードバックなど、貢献の方法は 1 つではないとまとめました。

### 5.3 Regional Director プログラムと MVP になる方法

Martina が Regional Director プログラムを説明しました。MVP とは別の、Microsoft のコミュニティ影響者向けプログラムです。

- 特定の製品に限られません。Foundry の Regional Director や M365 の Regional Director という区分ではなく、プラットフォームやシステムをまたぎます。Google の経験がある人もなれる、という説明がありました。
- 人数は約 200 人と少なく、経営層に近い場面を扱います。
- 同じ配布リストに Microsoft の上位の人たちがいて、適切なフィードバックの仕方を学べたそうです。有名な人が多く、圧倒される感覚もあると話しています。

MVP になる方法は 2 通りです。**既存の MVP か Microsoft の社員に推薦される**ことです。目指す人は、mvp.microsoft.com で自分の地域の MVP を探し、イベントで声をかけたり、LinkedIn などで連絡を取ったりしてほしいと司会は呼びかけました。地域のイベントを運営している MVP も多いそうです。

司会はここで、自分の経験を話しました。MVP になりたいという人に時間を取って手順を説明し、推薦のために本人についての質問に答えてもらう段階になると、多くの人が止まってしまうそうです。その理由が自己不信（インポスター症候群）かどうかを問いかけました。

### 5.4 「はい」と言った瞬間

登壇者の答えは次のとおりです。

- 自分の中で迷う気持ちから抜け出すことを勧めました。MVP になった後も、ときどき「どうしてここにいるのか分からない」と感じるが、ここにいる理由は何も自分を止めなかったことだと述べています。頭の中にアイデアがあれば進めること、誰かに嫌われたら、投稿にいくつ「いいね」が付くかといったことを気にしないことを挙げました。
- 開発者なら Microsoft のリポジトリへの貢献や、自分のオープンソースのリポジトリ公開を勧めています。投稿して外に出せば、見て動いてくれる人がいるためです。自分のためになることが、結果としてコミュニティのためになるので、自分が好きな内容を出すことが必要だと話しました。自分が持つ疑問は、ほかの人も持っているはずだという考えです。
- 司会が「はい」と言った瞬間を尋ねると、ある登壇者は Zoe さんの推薦を挙げました。周りは何年も前から MVP だと思っていたが、自分は申請が怖かった。Zoe さんが推薦して「45 日ある」と言われたことで、ようやく進む気になったそうです。
- 登壇者は、MVP の利点として、**Redmond の製品グループと直接つながり、フィードバックを出せて、新しいことを先に学べる**ことを挙げました。NDA（秘密保持契約）があるため、内容は話せませんが、製品に影響を与えられる生涯の人脈が得られるという説明です。
- 別の登壇者は、Windows Insider プログラムが最初のきっかけだったと話しました。Windows の不具合を見つけるたびに Feedback Hub を使い込み、多くのフィードバックが対応され、エンジニアから直接連絡が来たそうです。そのプログラムでの活動を理由に Windows Insider の MVP に推薦され、さらに Windows 向けの開発も進めたと述べています。
- 同じ登壇者は、推薦されても不採択になることがあると語りました。2020 年に Windows Developer MVP に推薦されたが、手を広げすぎて、どれも十分に強くなかったため不採択だったそうです。落胆せず、推薦してくれた人が自分に価値を見たと考え、コミュニティに関わり、SNS で出会った人と連絡を取り、「どうすれば良くなるか」を尋ねて助言を得て取り組みました。**落胆せずに続けること**を呼びかけています。

### 5.5 キャリアの最良・最悪の助言

- **最良の助言（話者は発話では確認できません）**：「好きなことをやり、やることを好きになる」。そうすれば 1 日も働かなくてよい、という有名な言葉に司会が触れ、出典を会場に尋ねました。登壇者の 1 人が「父が言っていた」と答えています。
- **最悪の助言（Tiffany）**：以前の上司に、あるクライアントに対しては「Tiffany スケールで 3」になってほしいと言われたそうです。当時はステージで側転をしながら登壇していた、という前置きがありました。3 で働く場所は望まず、常に 10（または 11）でいたいと考えたと話しています。
- **最良の助言（Jeremy）**：2 人の女性から得たと話しました。1 人は上司で、常に自分を推してくれています。もう 1 人は Donna Sarkar と聞こえますが、綴りは確認できません。2018 年の Build で、考えすぎず進めば成果を出せると声をかけられたそうです。そこから、自分も皆を引き上げ、皆に自分以上になってほしいと考えるようになったと述べています。
- **最良の助言（別の登壇者）**：「自分が持っている権限よりも大きな権限があると考えなさい。周りは自分が思う以上に高く評価している。許可を求めるのをやめなさい」。キャリアのある時点からは、自分で引き受けるべきだという内容です。
- **最悪の助言（Martina）**：2008〜2010 年にクラウドサービスを始めたとき、「クラウドで稼げない」「顧客はクラウドへ行かない」「自分の会社なので、自分のお金を無駄にしている」と 3 年間言われ続けたそうです。続けられた理由は、**興味と情熱**でした。司会は、情熱があれば、反対する人の意見は重要ではなく、すでに正しい道にいると受けました。

### 5.6 締めのあいさつ

司会は登壇者に拍手を求め、会場にも、今週に人と出会えたか、まだなら居心地のよい範囲から出て新しい人に話しかけてみてほしいと呼びかけました。会場の参加者の中にも優れた人がたくさんいる、という言葉でした。

このセッションでは、画面を使ったデモは行われていません。スライドは、MVP の人数などの数字と、「はい」と言った瞬間を問う質問の提示に使われたことが発話から分かります。内容はパネルでの会話が中心です。

## 7. 注意点・発表者の気付き

- MVP への推薦は、本人が質問に答える段階で止まる人が多いことが司会から指摘されています。登壇者は MVP になった後も、自己不信を覚えることがあると話しました。
- 推薦されても不採択になることがあります。ただし、不採択は終わりではなく、関わりを増やす動機にもなる、という経験が語られました。
- MVP の特典として得られる製品グループとの接点には NDA が伴い、内容を口外できないと登壇者が説明しています。
- Regional Director プログラムは MVP とは別のプログラムです。

## 8. 利用者にとっての利点

製品の導入効果や顧客事例は、このセッションでは語られていません。聞き手にとっての利点として語られたのは、コミュニティ活動から得られるものです。

- 同じ関心を持つ人との出会いと、生涯続く人脈
- MVP の場合は、Redmond の製品グループへの直接のフィードバックと、新しい情報を先に学べる機会
- 発信による認知の広がり（LinkedIn の記事によってソートリーダーへ立場が変わった例）
- 所属意識が強い人は仕事の成果が 56% 高いというスライドの数字

## 9. まとめ

このパネルは、コミュニティ活動の入口を、体験談で具体的に示しました。SharePoint Saturday や .NET のユーザーグループのように、同じ関心の人と出会う場から始まります。貢献の形は、登壇、記事、ソーシャルメディア、GitHub での貢献、メンタリングなど様々です。

MVP になるには、既存の MVP か Microsoft の社員の推薦が必要です。迷って動けなくなる人が多いため、考えすぎずに出すこと、不採択になっても続けることが勧められました。最後は、情熱を持ち続けること、そして今日から始めることが、司会の言葉として強調されています。
