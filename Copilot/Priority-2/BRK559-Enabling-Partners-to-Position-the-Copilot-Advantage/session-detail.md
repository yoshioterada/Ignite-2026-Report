# BRK559 Enabling Partners to Position the Copilot Advantage

## 1. はじめに

このセッションは、Microsoft パートナー向けに、顧客から出る「なぜ Microsoft 365 Copilot なのか。Anthropic の Claude や ChatGPT ではだめなのか」という競合比較の反論に、どう向き合うかを整理したものです。スライドを順に読み上げる形式ではなく、仕組みを見せるデジタルのホワイトボード動画を挟みながら進みます。Ignite 最終日の午後のセッションです。

中心となる考え方は、顧客の反論の裏にある本当の目的を見つけ、その目的を 5 つの不変の柱のどれかに対応づけ、最後に顧客の事業価値へつなげる、という 3 段階の流れです。発表では 5 つの柱のうち、Work IQ、マルチモデルと auto、セキュリティと管理の 3 つを掘り下げています。機能ごとの比較に入らず、モデルの順位表が毎週変わっても揺らがない土台の話に引き戻す、というのが一貫した主張です。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/BRK559](https://ignite.microsoft.com/en-US/sessions/BRK559)

## 3. 何に関する発表か

パートナーが顧客と話すとき、会話はしばしばモデルの優劣に流れます。発表は、その流れを「顧客の目的」と「Copilot の不変の価値」に引き戻す方法を扱います。アジェンダは次の順です。

1. 市場の変化と競合の状況
2. 顧客との会話の捉え直し（リフレーム）と、目的を引き出す質問
3. 5 つの不変の柱の紹介
4. 3 つの柱の詳細（ホワイトボード形式）
5. 次の顧客との会話に使う方法

## 4. 発表者が伝えたいメッセージ

最も強調されたのは、**反論をそのまま答えに変換せず、まず裏にある目的を聞く**ことです。顧客が「このモデルが好き」「あのツールが良い」と言うのは、言葉にされていない目的を隠した懸念だ、という整理です。モデルや機能の比較は競合の土俵であり、今日勝っても明日の順位表で変わるかもしれません。そこで、プラットフォーム、ガバナンス、統合、仕事の流れの中での AI という、動かない土台に話を移します。

もう 1 つのメッセージは、技術の仕組みを説明できることが信頼につながる、という点です。Copilot の総コストが競合より低いと伝えて顧客に「なぜ」と聞かれたら、Work IQ、マルチモデルの auto、そしてホワイトボードの内容を見せて説明するよう勧めています。

## 5. 発表内容の詳細

### 5.1 ウォームアップのクイズ

Mayank は挙手式のクイズを 3 問出しました。

| 問い | 答え | 理由 |
| --- | --- | --- |
| AI ツールの競争では、最良のモデルを持つ側が勝つ | 誤り | モデルが顧客の仕事とどう統合されるか、セキュリティの境界、ガバナンスなど、問うべきことが他に多い |
| エンドユーザーが競合製品を好んでいると、考えを変えさせるのはまず無理 | 誤り | Microsoft には競合対策の専門チーム（グローバル・ブラックベルト）があり、獲得する案件の多くは競合製品が既に導入されている顧客から始まっている |

なお、冒頭の「ジャケットを着ず髭も剃っていないが、プロフェッショナルに見えるか」という質問は、場を和ませるための冗談です。

### 5.2 市場の変化と競合の状況

Beth は、市場が非常に競争の激しい状態にあると説明しました。競合の立ち位置として、次のものを挙げています。

- セキュリティ分野に注力する企業
- 統合型のスイート製品
- AI ファーストのアシスタント

競合は、印象的なデモ、開発者向けツール、独自性のある価格設定で評判を築いてきました。経営層との強い関係を持つ競合もあります。さらに Copilot については、ブランドの認知や過去の体験が顧客の見方を形作っています。「3 か月前、4 か月前に試したが、体験も UI も良くなかったので競合にする」という声はよく聞かれます。これは無視せず、認めたうえで話を進めないと信頼を失う、と注意しています。

顧客の購買行動も変わっています。ここ数年は複数の AI ツールを試してきましたが、今はプラットフォームを標準化する段階に移っています。一方で、新しいフロンティアモデルの公開、エージェントの提供、新しいツールの登場が続き、ツール、領域、重複、コストが増えています。順位表は動き続けます。

顧客が必要とするのは、**後から説明がつく（防御できる）決定**です。目先の目新しいものではなく、データ、ID、ガバナンスが整っていて、利用が広がってもコストを管理できるプラットフォームを選びたい、という整理です。ところが顧客が持ち込むのは、気に入っているツール、モデル、競合の話です。パートナーの課題は、経営層に長期のアーキテクチャを考えてもらう土台を作ることだと説明されました。

### 5.3 反論から目的へ：3 つの動き

Beth は、フレームワークを左から順に説明しました。

1. **聞く**：ツールやモデルの話が出たら、まず受け止めます。「そのモデルが気に入っているのですね。どこが良いのですか。何を解決しているのですか」と聞き、さらに「長期的に解決したい問題は何か」まで掘り下げます。
2. **差別化要素に対応づける**：目的が分かったら、Copilot の価値の柱（動かない土台）に結びつけます。
3. **事業価値につなげる**：その差別化要素が、顧客にとって関係のある価値や、短期と長期の目標にどうつながるかを示します。

競合案件では「先に質問し、深く掘り下げた側が会話の形を決める」と述べられています。質問の例として、ニーズは満たされているか、時間軸はどうか、短期と長期で何を見ているか、といった方向が示されましたが、個々の質問文は読み上げられていません。目的は、顧客に視点を一段上げて考えてもらい、解決策の捉え方を長期の視点で見直してもらうことです。

### 5.5 柱 1：Work IQ

**反論**：他の AI システムもエージェント的な仕事をする。Microsoft 365 のデータをそれらにつなげばよい。

**裏にある目的**：自社の事業とその動き方を理解し、仕事を完了してくれる AI がほしい。

**差別化要素**：Work IQ。組織の洞察と文脈、記憶、パーソナライズ、スキル、統合、オーケストレーションを備えたプラットフォームです。Beth は、パートナーの声として「これが最大の差別化要素だ」と聞いていると述べ、顧客が話題にしなくても、こちらから持ち出すよう勧めています。セキュリティとガバナンスも同様です。

Beth が挙げた Work IQ の強みは 3 つです。

1. **ファイルだけでなく仕事を理解する**。人や関係、つながりを理解します。コネクターでつなぐ方法は「細いストロー」を何度も通すようなもので、トークン数とコストが増え、遅くなり、個別の取得の寄せ集めになります。Work IQ は洞察と合わせてまとめて取得します。
2. **過去の仕事を覚えている**。誰がそのファイルに関わり、誰が触り、その人の上司は誰か、といった人まで把握します。成果物は、共同作成者として自分と一緒に Word、Excel、PowerPoint に出力されます。
3. **統制の範囲内で仕事を届ける**。権限、ラベル、設定済みのガードレールが、各自の権限に基づいてそのまま保たれます。コネクター経由では、これが常に維持されるとは限りません、という説明です。

結論は「どんなツールでもデータに向けることはできるが、理解できるのはプラットフォームと Work IQ だけ。アクセスがすべてではなく、洞察が大事」です。

#### ホワイトボード動画での解説（Mayank）

Mayank は、このホワイトボードが Cowork と Code で作られたと述べました。プロンプトと動画を渡すと、Cowork が自力で作成したそうです。

**同じモデル、同じファイルでも答えが変わる**：価格提案書を作る顧客の例です。モデルにファイルを渡し、「18% の割引で何が更新されたか」「どんな決定が必要か」を尋ねます。しかしファイルには、割引について Teams で交わされた議論や、上司の承認がまだ必要だという文脈は入っていません。これらは Teams のチャット、メール、Web サイト、CRM ツールなど、別々の場所にあります。モデルを替えても、この文脈は手に入りません。同じモデルを使う別々の会社でも、結果は文脈の違いで変わります。モデルは学習データで訓練されているだけなので、提案書を以前に誰が編集したか、どの版が議論されているか、上司が Teams でどんな指導をしたか、といったことは知らないからです。Work IQ が解こうとしているのはこの問題です。

**Work IQ が集める信号**：メール、会議、CRM ツール、ファイル、さらにそのファイルを誰がいつどのように編集したかといった活動を集め、モデルに文脈として渡します。規模の例として、Fortune 500 の典型的な企業は、Microsoft 365 の文脈に 600 テラバイトを超えるデータを持つと述べられました。これが解こうとしている、事業面でも技術面でも難しい問題です。

**価格提案書の例の続き**：版履歴の確認（たとえば版 4 に重要な変更がある）、誰がアクセスしたか（たとえば Priya が木曜日にデッキを開き、重要な提案をした）、財務の承認はあるか、Teams やメールに記録はあるか、録画された Teams 会議で割引の議論があったか、といった文脈を Work IQ が集めて整え、モデルに渡します。この間、モデルにはまだ触れていません。

**作業セット（working set）と記憶（メモリ）**：

- 作業セットは、いま取り組んでいる最新のファイルを選ぶ仕組みです。古いファイルや、別チームが使っているファイルではありません。日ごと、週ごとに、作業に合わせて変わります。
- 記憶は、作業が変わっても持ち越したい文脈です。例として、割引を大きく変えるときは、顧客に送る前に CELA と上司の承認が必要だ、と Copilot が覚えています。毎回のプロンプトで繰り返す必要はありません。

**従来の API との違い（1 回の処理で集める）**：従来の API で Microsoft 365 につなぐと、ファイル、メール、Teams メッセージ、調査用の Web と、取得のたびに呼び出しが発生します。呼び出しごとに時間とトークンが増えます。Work IQ は、これらの信号を 1 回の処理でまとめて自動的に集めるため、コストも時間も大きく下がります。

**必要な量の文脈だけを渡す**：文脈が少なすぎるとモデルは正しい結果を出せず、多すぎると不要なトークンを消費します。ちょうどよい量にする判断を Work IQ が自動で行います。

**数値**：Microsoft は一般的なシナリオについて 20 種類の評価を実施し、従来の API と比べて、Work IQ の API では**トークン使用量が 80% 減り、速度が 2 倍**になったと述べています。「N+1 パターン」（個別の呼び出しの積み重ね）が起きないことも理由に挙げられました。

最後に Mayank は、モデルが重要でないとは言わないが、**文脈のほうがもっと重要**で、文脈が欠けていれば同じモデルでも結果が変わる、とまとめています。

### 5.6 柱 2：マルチモデルと auto

**反論**：このモデルが一番性能が良い。最先端のモデルなのだから、それに標準化すればよい。

**裏にある目的**：特定の 1 社に仕事の流れを固定せず、タスクごとに最適なモデルを使いたい。

**差別化要素**：タスクに見合った大きさのモデルを選べるマルチモデルの選択肢と、**用途に応じたモデルを自動で選ぶ auto**。Beth は次の点を説明しました。

- 多くの主要モデルが 1 つのプラットフォームで使えます。顧客が好きなモデルを挙げたら、「それはおそらくあるか、これから来る」と答えられる、という方針です。Satya が今後登場するモデルとして 7 つほど挙げたことにも触れています。
- auto は、モデルを選ぶ負担を従業員から取り除きます。例として、1 つのプロンプトの中で、画像生成が得意なモデル、調査のモデル、PowerPoint を作るモデルと、役割が分かれることがあります。選択は品質、コスト、性能に基づきます。
- 最も強力なモデルは、2〜2.5 倍のコストがかかることがあります。また、フロンティアモデルのコストは 1 年ほどで約 90% 下がるとも述べられました。
- モデルが行う仕事は、ID、データ保護、セキュリティ、ガバナンスの枠内で動きます。auto は、管理者が選んだモデルだけを使います。「X や Y は使いたくない」という指定も可能です。
- 会話は「どの提供元が一番賢いか」から「このタスクにはどのモデルが適切か」へ移ります。

#### ホワイトボード動画での解説（Mayank）

Mayank は、Charles Lamanna（役職は発話で「vice president」とされています）が LinkedIn に投稿した内容をもとに動画が作られたと説明し、LinkedIn でフォローするよう勧めました。仕組みの詳細は、その投稿で詳しく解説されているそうです。

「最良のモデル」というものは存在せず、モデルごとに強みが異なります。推論が得意なモデル、視覚が得意なモデル、速度と軽快さに優れ低コストなモデルがあります。

**例：顧客の契約更新の判断**：契約更新を前に、拡大するか、現状維持か、割引を出すかを Copilot の助けで判断したい、という場面です。プロンプトはそのままモデルに行かず、Work IQ が文脈とファイルを集めたうえで、**auto** を通ります。auto はモデルを選ぶ分類器の役割を持ちます。

auto が考慮する点は次のとおりです。

- 管理者が提供しているモデル。顧客は Agent 365 の機能を使って、サブグループ単位でモデルを定義でき、モデルは管理者の設定を継承します。
- 処理の工程や地域。すべてのモデルがすべての地域で許可されているわけではありません。
- どのモデルが稼働していて使えるか。
- 総コスト。最適なモデルが、全体で最も強いモデルとは限りません。最強のモデルは費用がかさみ、小さなモデルでは品質が足りないためです。

**例の流れ**：auto が最初のモデルとして Claude Opus 5.5 を選んだとします。auto の背後には「チョイス（choice）」と呼ばれるモデルがあり、数千件の評価と一般的な顧客シナリオを各モデルに対して実行して、どのモデルがどの仕事に向くかを学習しています。例として、ChatGPT 2.5 は視覚デザインと画像作成に最適だと把握しています。新しいモデルが出たときも、同じ評価を行って、タスクと優先度のどこに当てはまるかを見極めます。

> 補足：モデル名の Claude Opus 5.5 と ChatGPT 2.5 は発話で聞こえた表記です。音声認識の都合で表記が確定できません。

契約更新の例では、サブタスクが複数あります。

| サブタスク | 割り当てられるモデル |
| --- | --- |
| ファイルを探す | 小規模言語モデル（SLM）。速く、トークンも少なく済む |
| Web で調査する | 推論が必要なので、最初のモデル（Claude Opus 5.5）のまま |
| 視覚資料を作る | ChatGPT 2.5。現時点で業界最高の視覚モデルと説明された |
| スライドにまとめる | 推論に強い Claude Opus 5.5 |

主となるモデルがこれらの連携を取りまとめますが、全部の仕事を 1 つのモデルが行うわけではありません。ここでコストと時間の効率が生まれます。新しいモデルが使えるようになれば、スタックに追加され、auto がタスクに応じて選びます。

**数値**：Microsoft の評価では、すべてのタスクに最も強いモデルを選ぶと、適切なモデルを適切な仕事に選ぶ場合と比べて、**トークンが 2.5〜5 倍**かかります。強いモデルは品質は高くてもコストと速度を犠牲にし、能力不足のモデルは品質が落ちます。

**キャッシュ**：主となるモデルは、ファイル全体とその文脈を保持するメモリキャッシュを持ちます。サブタスクに引き継いでいる間も、データと文脈を既に持っているため、時間とお金を節約できます。作業の途中でモデルを切り替えると、新しいモデルが最初からやり直すため、作業量もトークンも増えます。評価では、キャッシュと、主となるモデルがデータを保持する仕組みで、事前読み込みの機能を含め**コストが 10〜20 倍下がる**と述べられました。こうした判断を顧客に任せるべきではなく、そのために auto がある、という位置づけです。

最後に、1 つの最良モデルは存在せず、タスクとサブタスクで適したモデルは変わる、ことを顧客に伝えるよう勧めています。

#### 総コストの話へのつなぎ

Mayank は、Ignite で何度か見たはずの「Copilot の日常業務と高度なタスクの総コストは、競合より安い」というスライドに触れました。顧客から「なぜか」と聞かれたら、Work IQ、マルチモデルの auto、ホワイトボードを見せて、これらがそれを支える技術だと説明するよう勧めています。技術の仕組みを説明できるほど、顧客からの信頼が増える、という理由です。

### 5.7 柱 3：セキュリティと管理

**反論**：自分たちのチームは別の AI を使っている。管理のためにプラットフォームを増やす理由があるのか。

**裏にある目的**：AI を拡大したいが、統制を 1 つにまとめ、支出を予測できるようにしたい。

Beth は、この領域は顧客から話題に出ないことが多いが、「すべて」であり信頼そのものだと述べました。

- **信頼の境界を 1 つにする**：他のものを導入すると、1 つの信頼の境界から外れます。Microsoft の信頼の境界内に収め、管理や統制の対象となる環境を増やさないことが重要です。
- **既存の統制がそのまま効く**：顧客が既に持ち、信頼している ID、権限、秘密度ラベル、Purview の監査が自動的に適用されます。
- **支出を管理できる**：支出ポリシー、ユーザーごとの上限、コストの帰属（誰の費用かの割り当て）で、信頼の境界の中でコストを制御します。

#### 予測できる支出と変動する支出

経営層の関心は、使用量と支出について「何が予測でき、何が変動し、結局、制御できるのか」の 3 点です。Cowork や、Autopilot などの利用量に応じた機能が出てきて、顧客は「どう制御するのか」と問うています。

| 区分 | 内容 | 課金 |
| --- | --- | --- |
| 予測できる（日常の AI） | 幅広く繰り返し使う用途で、計画や予算化がしやすい。auto、チャット、Word、Excel、PowerPoint、これまでに説明したモデルの選択肢を含む。新しい機能やモデルも、この枠に取り込む方針。通常は IT が支払う部分 | 発話では触れていません |
| 変動する（高度なエージェント作業） | 利用に応じて消費され、事業価値や ROI（投資対効果）に見合うよう拡大すべき部分。Cowork、Code、Autopilot、長時間動くエージェント機能など | Copilot credits（Copilot のクレジット）による従量課金 |

#### FinOps と新機能

Mayank は、Microsoft が計画、制御、最適化の考え方で FinOps の機能を提供すると説明しました。顧客の支出の予測と予算化、支出に対する上限・アラートなどのガードレールの設定、支出の最大活用と価値の確認が柱です。**Agent 365** が観測と制御のプラットフォームとして、FinOps を集中管理します。Cowork、Code、Autopilot Studio など、利用に伴うコストは 1 つのシステムに集約されます。

パートナーのフィードバックを受けて、次の新機能が発表されると紹介されました。

1. **モデルの選択**：管理者、顧客、そしてパートナーが、サブグループ単位でモデルの選択を決められます。ユーザーが実際に使えるモデルを指定できます。
2. **API**：制御とガードレール、レポートを、Microsoft が提供するダッシュボードだけでなく、顧客独自のダッシュボードから行えます。パートナーが特に求めていた機能です。
3. **部門別チャージバックの組み込み**：過去 3 か月の顧客との会話で最も多かったのは、チャージバックは事業部門に対して行う必要があるという声です。IT は Copilot の 30 ドルの SKU（ライセンス）の費用を管理し、資金も出しますが、利用に伴うコストは事業部門に生じています。IT が事業部門に請求し直す手段が必要で、この機能がそれに応えます。
4. **マルチテナント管理**：パートナーセンターから GDAP 連携で Microsoft 管理センターに入り、複数の顧客のテナントに同時にアクセスして、ガードレールを設定できます。パートナーにとって最も重要な機能と位置づけられています。

> 注意：これらの新機能が一般提供済みか、いつから使えるかは、発話では説明されていません。「発表する新機能」として紹介されたものです。

## 7. 注意点・発表者の気付き

- 反論から直接答えに飛ばないこと。深掘りの質問をする時間を取らないと、長期の価値を語る機会を逃します。
- 顧客が過去に Copilot を試した体験（UI が良くなかったなど）は認めてから進めます。無視すると信頼を損ないます。
- 機能比較やモデル比較は競合の土俵です。今日勝っても、順位表が変われば会話をやり直すことになります。
- コネクターで他の AI につなぐ方法は、トークンとコストが増え、遅くなり、権限やラベルが維持されない場合があります、という指摘です。
- 作業の途中でモデルを切り替えると、新しいモデルが最初からやり直すため、作業量とトークンが増えます。
- Mayank の説明では、評価の数値（80%、2 倍、2.5〜5 倍、10〜20 倍）は Microsoft の評価結果です。評価の条件や方法の詳細は、発話では説明されていません。

## 9. まとめ

- 顧客の反論は、まだ言葉になっていない目的の表れです。答えに飛ばず、先に目的を聞きます。
- 目的は、動かない 5 つの柱のどれかに対応づけ、長期の事業価値につなげます。このセッションでは、Work IQ、マルチモデルと auto、セキュリティと管理を詳しく扱いました。
- Work IQ は、ファイル単体ではなく、周辺の文脈を 1 回の処理で集めます。20 種類の評価で、従来の API に比べ、トークンは 80% 減、速度は 2 倍と説明されました。
- auto は、管理者の設定、地域、稼働状況、コストを踏まえて、サブタスクごとにモデルを使い分けます。
- 支出は、予測できる日常の AI と、Copilot credits で課金される変動部分に分けて捉えます。Agent 365 を中心に、モデル選択、API、部門別チャージバック、マルチテナント管理が紹介されました。
- 次の一歩として、競合対策サイト、プラクティス開発ガイド、Frontier Accelerate の資金とデリバリーガイドが案内されています。
