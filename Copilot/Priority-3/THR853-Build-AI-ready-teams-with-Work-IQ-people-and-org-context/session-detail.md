# THR853 Build AI-ready teams with Work IQ people and org context

## 1. はじめに

このセッションは、Work IQ の中でも「people and org context（人と組織のコンテキスト）」の層を扱う約 25 分の短いセッションです。Copilot が、誰が誰に報告するのか、「headcount（人員数）」「senior（シニア）」といった言葉がその会社でどう定義されているのかを理解したうえで、リーダーや HR、従業員の質問に答えられるようにする仕組みを紹介しています。

前半は、背景と Work IQ の位置づけの説明です。後半で、Copilot への質問、Cowork での組織分析とダッシュボード作成、Microsoft 365 admin center での組織データの品質確認と取り込み、Frontier の Workforce Insights agent でのコンテキスト設定という流れで、実際の画面を使ったデモが行われます。

発表の要点は、**Copilot が組織について正確に答えるには「質の高い人事データ」と「自社の用語や指標の定義（コンテキスト）」の両方が必要であり、その両方を整える導線が用意されている**ことです。

## 5. 発表内容の詳細

### 5.1 Work IQ と people and org context

Work IQ は、前回の Ignite で発表され、その後も機能追加が続いていると説明されています。データ項目を単につなぐだけでなく、社内コミュニケーション、ファイル、会議といった Microsoft 365 のシグナルに加え、Dynamics 365 のようなビジネスアプリや Microsoft 外のシステムへのコネクタも取り込み、ビジネス全体像を理解するものです。Work IQ は次の 3 つの役割を持ちます。

| 役割 | 内容 |
| --- | --- |
| Context（コンテキスト） | 情報同士を結びつける。people context と org intelligence を含み、Copilot が、組織にとって、またユーザー自身にとって何が関連するかを理解する |
| Memory | Copilot の記憶。重要なことを思い出すので、Copilot とやり取りするたびに最初からやり直す必要がない |
| Skills | 理解を成果につなげる |

これらは、Copilot、Copilot Studio、カスタムエージェントを動かします。このセッションで扱うのは、そのうち **people and org context** の層です。Copilot の体験の中で、リーダーとチームに、信頼できる、文脈化された組織の情報を届けるもので、次の 3 つの柱で成り立っています。

- **Intelligent：** 自然言語の深い分析、高度な推論、組織データに対する計算を使い、組織レベルの洞察を出す
- **Governed：** 既存の権限を尊重し、外部から取り込んだものも含めて、質の高い信頼できる組織データに基づく回答を返す
- **Contextualized：** 回答が、組織・人のデータ、自社の用語、指標、ガイドラインを反映する。データの品質と、データの上に置くコンテキストを磨くことが前提で、管理者がそれを実現する方法もデモで示される

利用者ごとの価値は、次のように説明されています。

- **従業員：** 自社の定義に沿った回答（「senior」の意味は会社によって異なる）、組織構造やチームを反映した回答（headcount の定義、誰が誰に報告するか、典型的な構造）
- **リーダーと people チーム：** 詳細な staffing summary や、span of control の分析。結果が自社のベストプラクティスや組織のガイドラインと合っているかを確認できる

これらを実現するための 3 つの手順も示されています。

1. **データをつなぐ：** 信頼できる HR データを people connectors で取り込む。方法は Microsoft 365 organizational data service か Copilot connectors
2. **コンテキストを設定する：** 取り込んだデータを解釈するための用語とビジネスルールを定義する。エージェントを使うと、提案を受けながら繰り返し調整し、改善の効果を確認できる
3. **コンテキストを検証する：** テストクエリを実行し、用語とガイドラインがどう適用されるか確認する。注目すべき領域や機会についての提案も得られる

### 5.2 Copilot での質問例

Stephanie 氏は、Copilot が従来から、ユーザーのコンテンツ、ドキュメント、他の人とのやり取りに基づいて答えられると述べたうえで、人と組織を深く理解していると、さらに多くの質問に答えられると説明しました。取り上げられた質問と、語られた内容は次のとおりです（デモの流れは 6 章に記載）。

- **「What are the managers in Lydia's org?」：** 回答には報告階層（誰が誰に報告し、誰がマネージャーか）の理解が必要
- **headcount：** 組織ごとに数え方が違う（正社員、ベンダー、インターン、契約社員を含めるか）。このテナントでは、正社員を既定としてコンテキストが設定されているため、質問すると正社員の数が返る。「ベンダーを含む headcount」と聞けば、その回答も得られる。既定の回答を設定することで、一貫性のある回答になる
- **average team size：** レポートの確認やデータのエクスポートなしで、定義に沿ったチーム平均人数が返る
- **PM とエンジニアの比率：** PM と engineering がそれぞれ取り込んだデータ上で何を指し、どの職種に対応するかを理解したうえで、比率を計算している。従来は複数のデータセットを横断して調べる必要があった。同様に、比率のほか、平均、最小、最大、ランキング、高度なフィルタリングにも対応する
- **スキル：** 「機械学習のスキルを持つのは誰か」にとどまらず、「AI スキルが集中している場所を、拠点と職種別に分けて見せて」と聞ける。Copilot は、ユーザープロファイルのスキル（HRIS から取り込んだもの、または、仕事の内容に基づいてスキルプロファイルを定期的に最新化する skills intelligence である **people skills**）を使い、内訳を表示して拠点・職種で絞り込む

スキルに関しては、現時点では公開データ（public data）に対して動作していると述べています。さらに、権限データやアクセス制御データなどを取り込むためのプライベートプレビューを開始するところで、これが入ると、マネージャーが自分の部下に関する機密情報（部下のレベル、特定のレベルの人数など）について質問できるようになる、と説明しました（一部の語は音声認識の都合で表記が確定できません）。

### 5.3 Cowork の workforce intelligence plugin

Stephanie 氏は、リーダー向けのより深いシナリオとして、**Frontier で workforce intelligence plugin を導入する**と説明しています。これは、people and org context という基盤の上に、リーダー向けに作られた skills を組み合わせ、Cowork の推論と合わせて使うものです。特定の指標を聞く代わりに、組織構造、組織規模、自社のポリシーとの照らし合わせといった、気になる問いを直接投げられます。最初の skills は次の 3 つで、今後増えていく見込みです。

| スキル | 内容 |
| --- | --- |
| Org dashboards | 関心のある指標を、繰り返し開いて使える形のダッシュボードにまとめる |
| Org structure guide | headcount、チーム構造と構成、組織の階層、人材の構成といった共通の領域の分析パターンを扱う |
| Skills guide | 組織内のスキルの全体像と、スキルアップの機会を見る |

### 5.4 データの品質確認と取り込み（admin 側）

質の高い回答の土台は、(1) 質が高く網羅性の高いデータをシステムに入れること、(2) その上にコンテキストを載せること、の 2 つです。1 つ目は Microsoft 365 admin center から始まり、Copilot control のセクションで品質に関する洞察を確認できます。注意が必要な項目は、上部のアクションカードに優先順位つきで並びます。

デモの例では、**マネージャー階層**のカードが強調され、このテナントの約 4 分の 1 が適切な報告階層を持っていないと示されます。Stephanie 氏は、Copilot が組織の質問に正確に答えるには報告階層が必要なので、これは問題であり、回答の品質に影響すると説明しています。

カードから **Microsoft 365 Org Data service** に進むと、取り込み済みの人・組織データの品質概要や、クリーンアップできる重要な属性を確認できます。チャットから **Microsoft 365 admin agent** に、修正方法を尋ねることもできます。デモでは、エージェントがデータの出どころと修正方法を説明し、組織の報告ツリー全体が反映されていないことを指摘して、新しいデータを取り込む修正を提案しました。

新しいデータは、データ接続（data connections）から取り込みます。新しいインポートを始めると、自動化されたコネクタが複数表示されます。コネクタの設定は詳しく扱われませんでした。追加で、ソースシステムの属性を Microsoft 365 に対応づける（マッピングする）ツールと、取り込んだデータを本番に公開する前に確認・管理できる **ステージング** の機能を拡張していると述べています。取り込みが終わると、データ概要で、解決した項目が解決済みとして表示され、外部システムから入ったデータに新たな問題があれば、ここに表示されます。

### 5.5 コンテキストの設定と検証（Workforce Insights agent）

データが入ったら、次に必要なのは、Copilot がデータを推論できるビジネスコンテキストです。headcount は何を指すか、senior manager は何か、Microsoft の場合なら principal は何か、span of control やガイドラインをどう計算・適用するか、といった内容です。ここは通常、HR BI や people analytics チーム、または権限を持つ管理者に引き継がれ、データと重要な指標を深く理解したうえで検証する作業になります。

現在これを可能にしているのが、**Frontier の Workforce Insights agent** で、検証と設定のための専用の場所と説明されています。トップ画面では、下部の setup and management から直接設定するか、質問から始められ、Stephanie 氏は後者のほうが簡単だと述べています。デモの流れは 6 章にまとめます。

設定には、チャットを使う方法のほかに、設定画面で直接変更する方法もあります。画面では **org context** を開いて、設定済みの内容を確認でき、既存の説明との矛盾がないかを確認する **quality checks** を実行できます。**attribute descriptions**（属性の説明）についても同様に扱えます。つまり、実際の設定内容を確認することと、チャットで繰り返し調整することの両方ができます。

最後に Stephanie 氏は、データの取り込みからコンテキストによる接地までを通して、people and org の理解という土台を作ることが、従業員向けの質問への回答だけでなく、マネージャーやリーダー向けのより深い分析（チームの洞察とパターンの把握）につながると述べました。

## 6. デモ・手順

このセッションでは、Copilot、Cowork、Microsoft 365 admin center、Workforce Insights agent の画面を使ったデモが行われました。録音は音声のみのため、語られた範囲で、語られた順に整理します。画面の細部（ボタン名、入力欄、レイアウトなど）は音声からは確認できません。

### 6.1 Copilot で組織の質問をする

> 注意：以下は、Stephanie 氏が質問を読み上げながら説明した内容です。回答画面の細部は音声からは確認できません。

1. Copilot で「What are the managers in Lydia's org?」と質問する。報告階層の理解が必要な質問として紹介された
2. このテナントで headcount を質問する。正社員の数で回答される（既定のコンテキストが正社員のため）と説明された
3. 「ベンダーを含む headcount」と質問すれば、その回答も得られると説明された
4. 「What is my average team size?」と質問する。取り込んだデータと定義に基づく平均チーム人数が返ると説明された
5. PM とエンジニアの比率を質問する。職種の対応づけと、比率の計算の両方が行われると説明された
6. 「AI スキルが集中している場所を、拠点と職種別に見せて」と質問する。ユーザープロファイルのスキルを使った内訳が表示され、拠点・職種で絞り込めると説明された

### 6.2 Cowork で組織構造を分析し、ダッシュボードを作る

1. Cowork で「analyze my org structure and how that fits with company guidelines that I have（自分の組織構造を、会社のガイドラインとの適合の観点で分析して）」と依頼する。特定の指標を指定する必要はなく、スキルが、設定済みのコンテキストをもとに分析を進めると説明された（そのコンテキストの設定は、後半のデモで示される）
2. 追加情報が必要な場合は、Cowork が追加の質問を返す
3. 回答では、まず「何を見て、何を測ったか」の要点が示される。報告数値だけでなく、意味のある差異、組織のガイドラインとの比較、リーダーがチームとさらに調べたほうがよい点が示され、データの制約も明示される
4. 会話形式なので、細部を掘り下げたり、追加の質問をしたりできる
5. 可視化したい場合は、dashboard skill を使ってダッシュボードを作成する。再利用でき、データへのアクセス権がある経営陣向けに公開できる
6. 作成されたダッシュボードを開く。横のチャットで内容を更新して調整できる
7. ダッシュボードには、見るべきハイライト、組織構造、提供されたコンテキスト（ガイダンス）に対するチェック、概要のスナップショットが含まれる。カスタマイズでき、Copilot と Cowork に組み込まれているので、フォローアップの会議の設定などのアクションも取れる

### 6.3 admin center でデータ品質を確認して取り込む

1. Microsoft 365 admin center の Copilot control セクションで、品質に関する洞察のアクションカードを確認する
2. マネージャー階層のカード（このテナントの約 4 分の 1 に適切な報告階層がない）をクリックして、Microsoft 365 Org Data service に移動する
3. 人・組織データの品質概要、マネージャー階層、強調された重要な属性を確認する
4. チャットで Microsoft 365 admin agent に、データの問題の修正方法を尋ねる。データの出どころ、修正方法、データで確認された内容（報告ツリー全体が欠けている）、新しいデータを取り込む提案が返る
5. 取り込み方法など、データ品質の診断と改善について、チャットで質問を続ける
6. 変更するため、data connections から新しいデータを取り込む。新しいインポートを開始すると、自動化されたコネクタが複数表示される（設定は詳しく扱われない）
7. 取り込みが完了したら、データ概要に戻り、課題が解決済みになっていることを確認する。外部システムから入ったデータに新たな問題があれば、ここに表示される

### 6.4 Workforce Insights agent でコンテキストを設定する

> 補足：Stephanie 氏によると、この設定は時系列では、6.1 の Copilot デモより前に行う手順にあたります。

1. Frontier の Workforce Insights agent のトップ画面を開き、質問から始める
2. 「How many employees report to somebody?」と質問する。データに基づいて「Carol's org に 962 人」と返る。データとしては正しいが、自社の文脈では正社員だけを返してほしい（人名は音声認識の都合で表記が確定できません。前のデモでは "Lydia's org" と聞こえています）
3. 「our company employee headcount only should include regular employees（会社の従業員 headcount には、正社員のみを含める）」と伝える
4. エージェントが、その場合の答えと理由を説明し、今後このテナントの回答で既定として使えるよう、更新後のコンテキストを提案する
5. コンテキストの文書やファイルが既にあればそれを取り込んで参照させられる。そうでなければ、チャットに直接コンテキストを入力できる
6. エージェントは、既に提供済みの内容に加えて、追加の提案を出す。追加・明確化を行える
7. エージェントは、既存のコンテキスト、既存の説明、今回提案する変更を確認し、矛盾がないかを見る。データ自体の説明と、指標などに対する追加コンテキストが区別されているかも確認する
8. 提案を受け入れるか、修正を加える。エージェントは保存前に確認を求め、行ってほしい変更の内容をまとめて提示する。その後もう一度、保存前の確認を求められるので、変更を保存する
9. 設定画面では、org context を開いて内容を確認し、quality checks を実行して既存の説明との矛盾がないかを確認する。attribute descriptions も同様に扱える

## 7. 注意点・発表者の気付き

- **管理者データの品質が回答の品質を左右する。** 報告階層が欠けていると、Copilot は組織に関する質問に正確に答えられません。デモでは、テナントの約 4 分の 1 でマネージャー階層が適切でない例が示されました。
- **正確なデータでも、自社の定義に合うとは限らない。** データに照らして正しい回答（962 人）でも、自社の定義（正社員のみ）には合わないことがあります。そのため、コンテキストを設定して、回答を自社の文脈に合わせる必要があると説明されています。
- **コンテキストの変更は、矛盾の確認と確認ステップを経て保存される。** 既存のコンテキスト・説明と矛盾しないかを確認し、保存前に確認を挟む作りです。
- **スキル分析の対象は、現時点では public data。** 権限・アクセス制御データを取り込んだ、マネージャー向けの機密情報（部下のレベルなど）の質問は、プライベートプレビューを始める段階です。
- **提供状況。** Workforce Insights agent と workforce intelligence plugin は、発表では Frontier の機能として紹介されています。それ以外の提供時期、価格、ライセンスについては、発表では触れられていません。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- 従業員は、自社の定義（例：senior の意味、headcount の範囲）や組織構造に沿った回答を得られる。
- リーダーは、レポートの確認やデータのエクスポートをせずに、平均チーム人数、PM とエンジニアの比率、拠点・職種別のスキルの集中度などを質問できる。従来は複数のデータセットを横断して調べる必要があった。
- 特定の指標を指定しなくても、Cowork が組織構造を自社のガイドラインに照らして分析し、差異、データの制約を示す。再利用できるダッシュボードにして、経営陣向けに公開できる。
- 管理者は、データ品質の問題を admin center で把握し、チャットで修正方法を確認できる。取り込んだデータを公開前に確認できるステージングの機能も拡張されている。
- 回答は、ユーザーの既存の権限と、組織のガバナンスを尊重する。

## 9. まとめ

Work IQ の people and org context は、Copilot に「誰がどこに報告し、headcount や senior が自社でどう定義されているか」を理解させて、従業員にもリーダーにも自社の文脈に沿った回答を返すための層です。実現には、(1) 質の高い HR データを取り込む、(2) 用語とビジネスルールをコンテキストとして設定する、(3) テストクエリで検証する、の 3 段階が必要です。デモでは、データの品質確認と取り込みを Microsoft 365 admin center と Org Data service で、コンテキストの設定と検証を Frontier の Workforce Insights agent で行う流れが示されました。

その上で、Cowork の workforce intelligence plugin が、組織構造の分析、ダッシュボードの作成、スキルの全体像の把握といった、リーダー向けのより深い分析を支えます。
