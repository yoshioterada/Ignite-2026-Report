# BRK226 Built for work: What sets Copilot apart

## 1. はじめに

このセッションは、「AI ツールを仕事で使うとき、何を基準に選ぶべきか」を、Microsoft 365 Copilot と Claude の比較を通して見せる内容です。登壇者は、ベンチマークのスコアやパラメーター数、コンテキストウィンドウの大きさではなく、「火曜の午後や金曜日に、実際の仕事を終わらせてくれるか」で評価すべきだと主張します。

評価の軸は **Do（実行する）、Know（知っている）、Protect（守る）、Share（共有する）、Choose（選べる）** の 5 つです。登壇者は 5 つの業務シナリオで Copilot と Claude に同じプロンプトを与えた結果を見せ、0〜5 点で採点しました。最終スコアは **Copilot 25 点、Claude 5 点** です。

比較は Microsoft の登壇者が Copilot 側の立場から行ったものです。この文書でも、結果は「発表者がそう説明した」内容として書いています。比較では、画像生成、Work IQ による同僚の特定、機密ラベルの継承、共有ブックの変更履歴といった具体的な場面が示されました。最後の Q&A では、Work IQ を使った比較かどうか、Claude や ChatGPT に移った顧客を Copilot に戻すための比較指標、auto モデルの透明性、機密ラベルの扱いなどの質問が出ています。

## 5. 発表内容の詳細

### 5.1 AI ツールを評価する 5 つの観点

登壇者は、「覚えておいてほしい短いリスト」として次の 5 つを提示しました。

| 観点 | 問い |
| --- | --- |
| Do（何をするか） | 頼んだことを実際にやってくれるか。やり方を説明するだけで終わらないか |
| Know（何を知っているか） | 自分、チーム、プロジェクトの文脈を理解しているか |
| Protect（守るか） | 保護が組み込まれているか。データを守るために特別なことをしなくてよいか |
| Share（共有できるか） | 同僚と共有しやすいか。生産性・コラボレーションの場にそのまま届くか（ダウンロード→再アップロードによるバージョンの乱立を避けられるか） |
| Choose（選べるか） | ツール内でモデルを選べるか。単一のモデルファミリーに閉じ込められないか |

### 5.2 Copilot を「仕事の OS」と位置づける導入

登壇者は、Work IQ が「Copilot を定義するレイヤー」だと説明しています。実験では、他のツールは一緒に働いている相手を取り違えたり、やり取りの多い人を同僚だと推測したりするが、Work IQ にはその曖昧さが無い、という主張です。続いて、モデル選択とセキュリティを Copilot の差別化点として挙げました。セキュリティについては、プラットフォームであるだけでなく各段階のガバナンスのレイヤーであり、後から付け足すものではないと述べています。出力は既定でラベルを継承するため、共有してよい文書かどうかを利用者が考える必要がない、という説明です。

### 5.3 比較のルール

各ラウンドで Copilot と Claude に同じプロンプトを与え、0 点（まったく達成できない）から 5 点（満点）で採点します。手元のノート PC で試したい参加者向けには、「自分たちのテナントは皆さんの環境と設定が違うので、同じ結果にならない可能性が高い」という注意がありました。

### 5.4 Round 1：Do（PowerPoint で業務向けの画像を作る）

評価の問いは 3 つです。(1) アプリの「横」ではなく「中」で作業できるか（資料の内容とフィードバックがある場所で AI が働けるか）。(2) ループを閉じられるか（フィードバックや修正を反映して、実際に使える結果にできるか）。(3) 何かが変わったとき、人がプロンプトを思い出さなくても作業が始まるか（登壇者はこの点は今回の例では見えないと断っています）。

シナリオは、デッキに入れるための「プロらしい」画像を、ストック画像サイトを探し回らずに作ることです。

- **Copilot**：PowerPoint 上で Copilot に、フォトリアルな画像を含むスライドの作成を依頼し、ストック写真やデザインツール無しで業務に使える画像ができたと説明しています。登壇者は「経営層（leadership team）に送っても恥ずかしくない」と評しました。
- **Claude**：同じ PowerPoint、同じプロンプトで、何度かやり取りしても、画像生成のツールが無いため必要なものが得られなかったと述べています。出てきたのは牛のイラストで、業務向けではなく、結局自分で画像を探す作業が残ります。

コストの話もあります。Copilot で PowerPoint 内で行った作業はユーザーのシートライセンスに含まれ、追加費用は発生しない、一方 Claude は使った分だけ課金される従量課金で、トークンを消費したのに欲しいものも得られなかった、という説明です。

**採点**：Copilot 5 点（デッキの文脈から画像を生成し、追加のプロンプトも不要、そのまま上司に見せられる品質）。Claude 3 点（何かは作れたので部分点だが、リーダーシップ向けの品質ではなく、追加プロンプトでトークンも消費した）。

### 5.5 Round 2：Know / Choose（プロジェクトに適した同僚を探す）

評価の問いは次の 3 つです。

1. メール、チャット、ファイルを見られるか（権限の範囲内で、文脈を集めてくれるか）
2. 組織内の誰がどんな人かを知っているか（名前や肩書きの検索ではなく、関連する経験があり、なぜ適任かまで分かるか）
3. 毎回文脈を説明し直さなくてよいか

シナリオは、大きなプロジェクトを渡された登壇者が、社内の誰かが過去に似た経験をしているはずだが誰か分からない、という状況です。具体的には、ドキュメンタリーシリーズのための撮影クルーの許可（clearance）を取れる人を探します。

- **Copilot**：モデルは auto が最適なものを選び、GPT や Anthropic のモデルから選ぶこともできます。Work IQ が働き、探していた同僚を正確に特定しました。この回答は、登壇者自身は参加していなかったチームの会議から得た文脈に基づいている、と説明しています。「Work IQ は仕事のデータにアクセスするだけでなく、仕事を理解している」というのが登壇者の表現です。
- **Claude**：Claude ファミリー以外のモデルは選べません。M365 のデータコネクターはあるものの Work IQ は無いため、提示されたのは「宝探しの出発点になるかもしれない推測」で、適任者は示されず、スタート地点に戻ったと述べています。

続けて登壇者の一人が補足として、Claude が M365 コネクターで同様のことをできる場合もあるが、成功したり失敗したりすると述べています。コネクターは読み取り専用で、メタデータが多く抜け落ちるため、組織構造に関するプロンプトのたびにコネクターへ取りに行き、トークンを消費する、という説明です。

**採点**：

| 項目 | Copilot | Claude |
| --- | --- | --- |
| Know | 5 点（文脈と一緒に働く相手を理解し、「適切な人」を特定した） | 0 点（適任者を見つけられず、完了に近づかなかった） |
| Choose | 5 点（プロバイダーをまたぐ主要モデルから選べ、今後もモデルが追加される） | 0 点（Claude のモデルに限られ、画像生成のように向かない作業があっても別モデルを使えない） |

### 5.6 Round 3：Protect（機密情報を含むブリーフの作成）

登壇者は「保護は Microsoft が非常に真剣に取り組む分野」と前置きし、業務用の AI は組織のガードレールの中で動かなければならないと述べました。問いは 3 つです。

1. 各ユーザーが見てよい情報だけを見るか（例として、あるテナントにある特定の人物の情報が AI 経由で組織全体に知られてしまうのは大きな失態、という説明）
2. ラベルと DLP ポリシーが出力まで引き継がれるか（機密性の高い、暗号化された情報を Copilot は読まず、出力にも含めない。他社製品は読み取り専用のコネクターで秘密度ラベルを見落とし、情報をそのまま出す、という主張）
3. プロンプトが実行可能（actionable）で、監査可能か（機密性の高いやり取りを、必要に応じて調査できるログがあるか。管理者が統制しているか）

デモは映像（"Let's go to the video" と案内されています）で示されました。Word のドキュメント内で、あるテーマに関する情報を集めたブリーフの作成を Copilot に依頼する、という流れです。

- **Copilot**：ブリーフを作成する際、機密の取締役会メモは含めませんでした。新しいブリーフには、秘密度ラベル（このケースでは保護ラベル）が自動で付きました。利用者は何もする必要がありません。
- **Claude**：同じデータ、同じプロンプトで、機密の取締役会メモを取得し、ブリーフにそのまま書き込みました。価格、投票、発表日、さらに削減対象のポジションまで含まれていた、と説明しています。ラベルも暗号化も無く、上部に小さな「厳秘」のテキストが付くだけで、組織内の誰でも消せる状態です。

登壇者は「一方は秘密を守り、もう一方は書き写してくれた」とまとめました。

**採点**：Copilot 5 点（機密を守り、ブリーフも有用で、ラベルが出力に引き継がれた）。Claude 1 点（上部の小さな厳秘テキストのみ。ドラフトの質は良いが、秘密度ラベルを無視して全部コピーした）。

### 5.7 Round 4：Share（共有ブックの変更履歴の把握）

問いは 3 つです。(1) 1 つの「ライブな」バージョンになるか（ダウンロードと再アップロードによるバージョンの乱立を避けられるか）。(2) チームメンバーが AI と一緒に共同編集できるか。(3) 会社のナレッジベースに自動的に反映されるか。

シナリオは、チーム全員が触っているフォーキャストの Excel ブックです。署名（承認）の前に、誰が何を変更したかを知りたい状況です。

- **Copilot**：ブックの現在の内容だけでなく、背後の履歴（誰が、いつ変更し、その変更がフォーキャスト全体にどう波及したか）を読みます。登壇者は、同僚の Mauricio さんの編集を緑、Mauricio さんが Copilot と一緒に行った編集を青でハイライトするよう依頼し、「人の作業」と「AI が一緒に行った作業」が明確に見えたと説明しています。
- **Claude**：ファイルは開けるものの、誰が何を変更したかは分からず、人の編集も AI を使った編集も見えません。そのため全セルを自分で確認することになり、問題の無い変更を消したり、後でやり直したりする摩擦が生じる、という説明です。

ここでも、Copilot の作業はシートライセンスに含まれ、追加費用は発生しない一方、Claude では手作業が残りトークンも消費する、と繰り返しています。

**採点**：Copilot 5 点（共同作業に加え、チームメンバーの更新と AI 支援の更新を追跡し、色分けもできる）。Claude 1 点（ファイルでの共同作業はできるが、変更が追跡できないため 1 点が上限）。

### 5.8 Round 5：Choose（モデル選択を超えた選択肢）

このラウンドはデモではなく、Copilot が提供するもの（登壇者の言葉では「他のモデルが持っていないもの」）の説明です。

**モデルと料金の見せ方**

- Copilot には OpenAI と Anthropic のモデルがあり、切り替えられます。
- 登壇者は、まず **auto モデル** から始めることを推奨しています。auto は月額 30 ドルの課金に含まれ、トークンを消費しないためです。
- より深いリサーチなど、洗練が必要なタスクは、別のモデルに切り替えられます（音声では "cohort model"、"Cowork model" と聞こえ、どのモデルを指すかは確定できません）。その場合、auto で作成した文書をそのモデルが仕上げる形なら、最初から作るよりトークンの使用が少なく済む、という説明です。
- モデルは今後も追加され、テストが続いています。登壇者は、モデル選択を最初に提供したのは Microsoft Copilot で、他社も追随していると述べています。
- 何がサブスクリプションに含まれ、何が従量課金か、別のモデルを選ぶとトークンがかかる、といった点は明確にラベル表示されるため、「推測ゲームではない」と説明しています。
- 対比として、「チームメイトにメッセージを送る」「不在通知を設定する」「届いた返信への簡単なメールを書く」といった小さな依頼でも、Claude ではお金がかかる、という主張です。

**ツールの選択**：どのモデルを選んでもセキュリティは標準でついてくる。他のツールで選ぶモデルは同じセキュリティレベルとは限らず、Microsoft のエンタープライズ・セキュリティは他社を超える、と述べています。

**Researcher の 2 つのモード（Critic と Council）**

登壇者は Researcher を Copilot の優れたツールとして紹介し、「期待した結果が出ない」と相談されたら「Researcher を試したか」と聞くようにしていると話しています。

- **Critic**：プロンプトに対し、まず 1 つのモデル（例として GPT 系）が回答を生成します。その回答を 2 つ目のモデル（音声では「Opus ベース」と聞こえます）に渡し、すべての情報が正確か、信頼できるか、ハルシネーションが無いかを批評・検証します。
- **Council**：ChatGPT（OpenAI）と Claude の 2 つのモデルの出力を、同じウィンドウに並べて表示します。2 つのモデルが一致した点と食い違った点を、それぞれ主要な領域ごとに整理した要約レポートも出ます。「二重に確認したいときに、モデル同士を直接比べられる」という使い方です。

### 5.9 合計スコアとまとめ

5 ラウンドの合計は、**Copilot 25 点、Claude 5 点** でした。登壇者は、自分たちは Copilot ファンだと断ったうえで、Claude を使っている、または使いたいユーザーがいる場合に、考えておくべき事例だと述べています。まとめとして挙げた Copilot の結果は次のとおりです。

- PowerPoint の中で、追加のプロンプトなしに、仕事に使える画像を作った
- ドキュメンタリーの撮影クルーの許可に必要な、適任の人を見つけた
- 機密の取締役会メモをブリーフから除外し、ブリーフに適切な秘密度ラベルが継承された（情報漏えいのリスクがない）
- 共有ブックで、誰が何を変更したか、人による変更と AI 支援による変更の区別を示した
- プロバイダーをまたぐ主要モデルから選べ、Critique（音声ではこう聞こえます）や Council といったツールもエンタープライズセキュリティ付きで使える

### 5.10 Q&A

**Q1：今週発表された「サードパーティ AI ツールでの Work IQ」を使った比較か、従来の M365 コネクターを使った比較か**

回答：テストは約 2 週間前に実施した。現在も結果は同様で、Claude の M365 コネクターは読み取り専用のままだと説明しています。結果が安定するよう、10 回実行し、5 回同様の結果が出るまで確認したそうです。Claude は多くの場合に取りこぼしやハルシネーションがあり、1 回は拾えても次回は逃すなど一貫性が低い、という主張です。質問者が、Claude や OpenAI で使えるコネクターの変更について重ねて尋ねたのに対し、登壇者は、それでも読み取り専用であり、Copilot に組み込まれたものと同じ水準にはならないと答えました（選択肢はあるが結果の水準が違う、という説明です）。

**Q2：パートナーとして Copilot を顧客に勧めているが、Claude や ChatGPT に移った顧客を Copilot に戻すのが難しい。比較の指標はあるか**

回答：最後のスライドにある **TCO レポート** を勧めています。比較のパラメーターは **速度、正確さ、信頼、コスト** で、Copilot 対 Claude だけでなく ChatGPT や Gemini など主要各社も含まれており、顧客との会話の出発点になる、という説明です。

**Q3：auto モデル選択は、どのモデルにルーティングされたかを透明にできないか**

回答：現状はモデル選択の画面で、auto がデフォルトであること、特定のモデルを選ぶとトークンがかかることが分かるようにしている、という説明です。モデルをどこまで見せるか、精度を重視するかといった点は社内でテスト中で、現時点で主要な要因はコストだと述べています。続けて登壇者の一人は、auto は GPT になると思う、透明性への要望は多いだろうが、どう提供する計画かは分からないので今後の情報を待ってほしい、と答えました。また、Copilot のチャットモードでは、ホーム画面で auto を選んだ状態のとき、下部に Cowork ボタンがあり、これを選ぶとトークンを使い、選ばなければ使わない、と説明しています。

続いて会場の参加者から、前日のセッションで、新しい Copilot Studio の harness に、サブエージェントを選ぶ機能が来ており、どのモデルにルーティングされたかが透明に表示される、という共有がありました。

**Q4：機密性のデモは、何を示す演習だったのか（Claude の利用が定着している組織を動かす材料になるか）**

回答は 2 点です。

1. Copilot で AI が文書を生成する際、Work IQ が参照するソースに秘密度ラベルがあれば、新しい文書にそれが自動的に継承される。制限付きや機密の文書は尊重され、回答に情報が出ない。Claude はラベルを（メタデータだとして）読まずに、ソースのすべてを取り込み、出力にも警告がない、という主張です。
2. ファイルが暗号化されている場合、Copilot はファイルを読んだうえで、暗号化されているため情報を取り込まなかったと詳しく理由を伝える。Claude は理由を示さず、空白（TBD が並ぶ表示）を出す、と説明しています。

さらに、秘密度ラベルがある情報をチームメイトと共有しようとすると、プライバシーラベルがあるため共有されず、相手はアクセスできない、とも述べています。質問者が「それは事前に識別されたユーザーのグループに基づくのか」と確認すると、「そのとおりで、管理センターでアクセスを設定したとおりに動く」と答えました。ただし、これらがすべて機能するのは Work IQ が関わる場合だけで、Purview が秘密度レベルの情報を運び、Purview と Work IQ が連携してそれを引き継ぐ、という説明でした（この直前に SharePoint への言及がありますが、文が途切れていて詳細は聞き取れません）。

最後に、同様の動作を Claude にプロンプトで組み込めないかという質問がありました。回答は、Microsoft 側が API やコネクターで制限しているわけではなく、Claude 側ができるのに優先していないだけ、というものです。

## 6. デモ・手順

このセッションの Round 1〜4 は、Copilot と Claude に同じプロンプトを与える比較デモで、画面の映像を見せながら進行したと読み取れます（Round 3 は発話で "video" と案内されています。Round 1・2・4 も画面を見せる語り口ですが、映像かライブかは音声からは確認できません）。画面上のボタンや入力したプロンプトの文言は、語られた範囲しか分からないため、ここには書きません。Round 5 は、登壇者が明確に「デモではありません」と述べています。

語られた順に、各比較は次のとおりです。

1. **Round 1（PowerPoint）**：Copilot にフォトリアルな画像を含むスライドを依頼 → 業務向けの画像が作成された。同じ操作を Claude で行うと、何度かやり取りしても、画像ではなくイラストが出た。
2. **Round 2（同僚探し）**：ドキュメンタリーシリーズの撮影クルーの許可を取れる人を、Copilot と Claude に尋ねた → Copilot は Work IQ により、参加していなかったチーム会議の文脈から適任者を提示。Claude は推測ベースで適任者を示せなかった。
3. **Round 3（Word のブリーフ）**：Word の中で、あるテーマの情報を集めたブリーフを Copilot に依頼 → 機密の取締役会メモは含まれず、保護ラベルが自動付与された。Claude に同じデータとプロンプトを与えると、メモの内容（価格、投票、発表日、削減対象のポジション）がそのまま書き込まれた。
4. **Round 4（Excel ブック）**：共有フォーキャストの変更履歴を Copilot に確認 → Mauricio さんの編集を緑、Mauricio さんが Copilot と行った編集を青でハイライトするよう依頼し、人と AI の作業が区別して見えた。Claude ではファイルは開けるが、誰が何を変えたかは分からなかった。

## 7. 注意点・発表者の気付き

- **テスト条件**：登壇者は、自分たちのテナントは参加者の環境と設定が異なる可能性が高く、同じ結果にならないことがあると断っています。
- **実施時期と再現性**：Q&A で、比較テストは約 2 週間前に行ったものと説明されました。Claude 側の結果の一貫性を確認するために 10 回実行し、5 回同様の結果が得られるまでやり直したと述べています。

- **auto の透明性は未解決**：auto がどのモデルを選んだかの表示方法については、発表では未定（今後の情報待ち）という回答でした。
- **自己評価の偏り**：登壇者自身も「Copilot ファンなので」と断っています。この文書の採点結果は発表者側の評価であり、第三者による検証ではありません。
