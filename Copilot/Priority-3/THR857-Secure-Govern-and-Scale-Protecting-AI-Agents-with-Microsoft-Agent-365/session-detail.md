# THR857 Secure, Govern, and Scale: Protecting AI Agents with Microsoft Agent 365

## 1. はじめに

このセッションは、**Microsoft Agent 365** を使って、組織内で動いている AI エージェントを「見つけ、守り、統治し、増やしていく」流れを、ライブデモ中心で紹介する短い登壇です。Microsoft の Agent 365 のセキュリティ・ガバナンス担当チームの Brendan Powers 氏が、自分のデモテナントを使って画面を操作しながら説明します。途中で、パートナー 2 社（発表中の発音は "Sierra"、そして Darktrace）が、それぞれの製品と Agent 365 の連携を紹介します。

Brendan 氏が示す流れは、1 つのエージェントを題材にして 2 つの判断を行うものです。1 つ目は「何を調査すべきか」、2 つ目は「それを動かし続ける価値があるか」です。最後に、エージェントが大量に増える前提で、どうやって Agent 365 に取り込むか（スケール）を 3 つの方法で説明します。

このセッションでは、**画面を使ったライブデモ**が行われます。Brendan 氏は、クリックはライブの操作なので読み込みに少し時間がかかる、と断っています。パートナー 2 社もそれぞれ画面付きのデモを見せ、Sierra 側は発表者自身が「動画（video demo）」と説明しています。

## 5. 発表内容の詳細

### 5.1 Action center と高リスクエージェントの確認

デモ環境に入ると、最初に Agent overview が表示され、そこからすぐに **Action center** に移ります。Action center は、IT、セキュリティ、ビジネスのいずれの担当者であっても、環境内のエージェントの「観測された現実」を把握しやすくするための画面だと説明されています。

画面を下にスクロールすると、環境内で動作している高リスクのエージェントが表示されます。デモ環境では、高リスクのエージェントは合計 **160** 件で、リスクへの対応（risk responses）が時間とともに増えていることが示されました。

### 5.2 サードパーティエージェントの詳細：Entra agent ID

次に、Microsoft 以外から来ていて Agent 365 に取り込まれたエージェントとして、**ServiceNow 上で作られた multi-agent coordinator** を開きます。詳細画面で重要なものとして挙げられたのが **Entra agent ID** です。これは、ユーザーに割り当てられるユーザー ID やメールアドレスに相当するもので、組織内で動くエージェントに付く識別子です。Brendan 氏は、これがエージェントにガバナンスとセキュリティの統制をかけるための土台だと説明しています。

同じエージェントのインスタンスは、組織内に複数存在し得ます。例として、営業チームが使うインスタンスや、監査チームがレビューするインスタンスが挙げられ、組織全体にエージェントへのアクセスを連携（federate）できる点が示されました。

### 5.3 セキュリティ：動的なエージェントリスクスコアと 3 つの観点

このエージェントには、Agent 365 の**動的なエージェントリスクスコア**によって、全体として高リスクという判定が付いています。スコアは次の 3 つの観点で構成されます。

| 観点 | 意味（発表での説明） |
| --- | --- |
| Runtime risk | エージェントが動作中に、実際にさらされているリスク |
| Exposure risk | エージェントが内部・外部の双方から受ける脆弱性 |
| Blast radius risk | このエージェントが侵害された場合に、組織のミッションをどれだけ損なうか |

それぞれ掘り下げて確認できます。

- **Runtime risk**：このエージェントでは、Microsoft Defender で検出された「不審なツール呼び出し（suspicious tool invocation）」と、関連するケースが表示されます。セキュリティアナリストは、ここから Microsoft Defender に移り、このエージェントに関する関連アラートを確認します。
- **Exposure risk**：具体的な露出の指標として、データ流出（data exfiltration）、間接プロンプトインジェクション（indirect prompt injection）、権限昇格（privilege escalation）の 3 つが挙がりました。
- **最後の 3 要素**：Brendan 氏は、このエージェントが組織に大きな被害を与えうる特徴として Agent 365 が最も影響が大きいと判断した 3 つの要素にも触れています（どの観点の画面かは、音声からは断定できません）。

セキュリティの締めくくりとして、**権限**の画面も確認されました。このサードパーティエージェントが持つ Microsoft Graph 上のコンポーネントと、リソース固有（resource specific）の権限を、具体的に見ることができます。

### 5.4 パートナー 1：Sierra（データとインテントの観点）

ここで Brendan 氏が Devin 氏を紹介し、ビジネス上の問い（データとインテント）を説明してもらいます。

**会社の背景**：Devin 氏によると、同社は DSPM から始まり、DLP、アイデンティティへと広げ、いまはエージェントに取り組んでいます。それぞれの製品で学んだことを 1 つにまとめており、Agent 365 との組み合わせでそれが最もよく生きる、という説明でした。

**考え方**：出発点は常にデータの発見（data discovery）です。データがどこにあり、それが何かを把握し、分類し、情報を付加（enrich）します。たとえば社会保障番号を含むサンプルファイル 1 つだけでは、それほど機微ではありません。しかしそれを ID、ユーザー、組織内の他のファイルと結びつけると、文脈が分かり、誤検知（false positive）、合成データ、学習用データと、本当に懸念すべきものを見分けられます。これにより、誤検知を減らして真の脅威を優先的に扱えます。

**エージェントへの適用（Agent Guardian）**：同じデータ発見と文脈の構築を、エージェント向けにも行います。誰がどのデータにアクセスできるかだけでなく、「ランタイムで何をしているか」が焦点です。たとえばプロンプトに社会保障番号が入力された場合、それがユーザー本人のものならエージェントの誤用に近く、顧客のデータであればエージェントがそのデータで何をしているかというリスクになる、という例が挙げられました。

**数値**：delivery time（提供までの時間）は「数か月や数年ではなく数日」（何の時間かは発表では詳しく語られていません）、precision（適合率）は **96%** と説明されています。AI を使って誤検知を最小限にし、本当の脅威だけを提示することを強調していました。

**動画デモ**（6 章を参照）のあと、データがどう Agent 365 に届くかも説明されました。

1. ユーザーがエージェントで何をしているか、エージェントが何にアクセスできるか、何が起きているかを発見する
2. そのデータを、Microsoft がすぐ解釈できるスキーマ（構造）に変換する（Microsoft 側が API 呼び出しを解析する必要がないようにするため）
3. データを **Microsoft Sentinel** に送る
4. Agent 365 がそれを受け取り、Microsoft Defender のアラートや管理オプションと並べて表示する

### 5.5 ガバナンス：動かし続ける価値があるか

セキュリティと権限の確認が終わり、ここからガバナンスに移ります。問いは、「そのエージェントは、組織で動かし続けるだけの投資に値するか」です。

**アクティビティとユースケース**：まず、エージェントのアクティビティを見ます。Brendan 氏は、ユースケースに注目してほしいと述べています。アクティビティの判断は人気投票ではなく、どのユースケースがより価値を持つかを見極めることだからです。

**コスト**：ServiceNow のエージェントについて、稼働中のコストの内訳が示されました。Microsoft が課金するエージェントではなくサードパーティのエージェントでも、組織で発生している費用を正確に追えると説明されています。コストは、アクティブユーザー、使われているモデル、そしてそのモデルに基づく**セッションあたりのコスト**で分解できます。

**価値**：より重要な指標は価値です。アクティビティで確認したユースケースに、エージェントのコストを正確に割り当てることで、設定した仕事に対してそのエージェントがどれだけ効率的かを測ります。

**類似エージェント**：複数のチームがそれぞれエージェントを作る状況で、重複をどう抑えるかについては、similar agents 機能が使えます。類似度は、使っているユーザー、呼び出しているツール、そしてアクティブユーザー数とセッション数の比率で測り、同じ目的に対してどちらが効率的かを判断します。

**エージェント評価（agent assessment）**：以上の結果が、エージェント評価につながります。IT 管理者やセキュリティ担当が、このエージェントの稼働を許可するか、ブロックするかを判断するためのものです。デモのエージェントは、11 の重要なチェックのうち合格が 3 つで、残りは不合格でした。

### 5.6 パートナー 2：Darktrace（行動ベースの検知）

次に Brendan 氏が、普段は正常に動いているエージェントが「いつもと違う」状態になったことを見つける例として、Darktrace を紹介します。登壇したのは Director of Technical Alliances の Justas Zaborowskis 氏です。

**Darktrace の位置づけ**：英国のサイバーセキュリティ企業で、組織内の「正常な行動」を理解する、行動面のセキュリティを 10 年以上手がけてきたと説明しています。ネットワークセキュリティから始めてメールセキュリティに広げ、その両分野で Gartner のリーダーに位置づけられているとのことです。ハイブリッドネットワークのインフラや、メールでの言語を扱ってきた研究開発と知見を、AI 資産の保護に応用しました。**Secure AI** 製品は、発表の約 2 か月前（"just over two months ago"）に発表されたと述べています。

**特徴**：ルール、シグネチャ、ポスチャといった静的な仕組みではなく、行動を出発点にします。適応型 AI が、顧客自身のデータ（そのテナントに分離されたもの）から正常な行動を学習します。エージェントの「宣言された意図」よりも、運用・本番で実際に何をしているかを検証し、AI・人・インフラをまたぐ 1 つの可視化レイヤーを作ることで、リスクが拡大する前に的確に対応できる、という考え方です。

**Agent 365 との補完関係**：Microsoft のツールは、AI をどう使うかという「意図」を統治するもので、Darktrace は学習した正常な行動と照らして「振る舞い」を検証する、という関係だと説明しています。エージェントはタスクが特化しているため、行動の監視に向いているとのことです。2 つを組み合わせて埋められるのが、**権限の境界内で動いているのに、組織にリスクを持ち込んでいるエージェント**というギャップです。

**連携のしかた**：Darktrace の Secure AI による行動ベースのリスクの知見は Agent 365 に送られます。アナリストは統一された 1 つのダッシュボードで確認でき、Microsoft 側はその知見に対して下流のポリシーや独自の動的リスク計算を適用できます。画面では、このエージェントに対する Microsoft の検知と Darktrace の行動インサイトが並んで表示され、動的リスクスコアを調整している様子が示されました。

デモの内容は 6 章に書きました。Justas 氏は、より長いデモや質問を希望する人には、セッション後に残るよう呼びかけています。

### 5.7 スケール：エージェントを取り込む 3 つの方法

最後に Brendan 氏が、スケールの話に移ります。前提として、Fortune 500 企業 1 社あたり、来年末までに約 **150,000** のエージェントが動くと見込まれている、と述べています。突然これだけ増える「人員」を、管理者や組織、経営層がどう扱うのか、という問いです。Agent 365 には、エージェントを組織に取り込む方法が 3 つあります。

1. **ファーストパーティのエージェント**：社内の誰かが Copilot Studio のエージェントを作るたびに、そのすべてが自動的にレジストリ（registry）に登録されます。
2. **SDK**：ソフトウェア開発キットを使って、エージェントを Agent 365 に接続します。Brendan 氏は、ミッションクリティカルなエージェント、つまり事業の運営に欠かせない、高度にカスタマイズされたエージェントには SDK を強く勧めています。
3. **Connected platforms**：この 6 か月間、最も力を入れてきた部分です。ハイパースケーラーや主要なラボと個別の取り決めを結んだ成果で、Agent 365 の顧客はエージェントの群れ（数千のエージェント）を 1 クリックで持ち込めます。

Claude を例にすると、レジストリに取り込まれた時点で、管理者は数千のエージェントに対してまとめて操作を行えます。現時点で、組織の 1,000 の Anthropic Claude エージェントを Agent 365 に取り込むと、コストの可視化、セキュリティ上の価値、可観測性（observability）が得られます。画面上には「今後提供される機能（features that are coming）」も表示されていた、とのことです（具体的な内容は語られていません）。

### 6.3 Darktrace の Secure AI デモ（Justas 氏）

1. 概要ダッシュボード：AI を展開する組織が抱える 4 つの問い（何が使われているか、どう使われているか、危険か、どう統治するか）に答える。
2. 検出（detection）ページ：リスクが検出されたセッションを優先度順に表示する。
3. セッションを開くと、問題のあるプロンプトを確認でき、セッション全体に展開できる。セッションの各ターンには脅威タグ（threat tags）が付与されている。
4. セッション内のリスクや行動の異常がどこにあるかを素早く把握する。
5. セッションの背後にあるエージェントに移ると、リソースグラフ上に配置され、エージェントのインテントと指示、最近のアクティビティ、監査ログを確認できる。
6. アイデンティティ：AI エージェントは新しい種類のアイデンティティであり、Entra agent ID などがある。Darktrace はこれらの権限をモデル化し、blast radius を理解して、行動の検知に文脈を与える。
7. リスクのある振る舞いが検出されたアイデンティティに対して、エージェントの隔離やユーザーのログアウトといった対応アクションを実行できる。自律的な対応アクションと、有効または保留中のアクションの一覧も表示される（途中で少し先に進めています）。
8. Shadow AI：組織内で使われている未承認の AI サービスを検出する。シグナルは Darktrace の network detection and response 製品、メール製品、および Entra GSA などの secure access service edge 連携から得られる。個別のサービスと利用の状況、関与している資産を一覧で確認できる。
9. ポリシー管理：自由記述の AI 利用ポリシー文書をアップロードすると、ルールセットに分解される。これを適用・測定・追跡し、組織の AI 活動が、定めた安全な AI 利用ポリシーにどれだけ沿っているかを確認できる。

## 7. 注意点・発表者の気付き

- Brendan 氏は冒頭で、このセッションのために自分のプライベートなデモテナントの使用許可を得たこと、クリックはライブなので画面の読み込みに少し時間がかかることを断っています。
- Agent 365 の価値は、サードパーティや競合のエージェントとどれだけうまく動くかにかかっている、と強調されました。
- 活動量（アクティビティ）の判断は、利用の多さではなく、ユースケースごとの価値で行うべきだとされています。
- Sierra の側では、同じ機微データでも、ID やファイルとの関係によって、誤検知か本当の懸念かが変わるという点が強調されました。
- Darktrace の側では、権限の境界内にいるエージェントでもリスクを生みうるため、「権限」だけでなく「行動」を見る必要がある、と説明されています。
- connected platforms で現時点で得られるのは、コストの可視化、セキュリティ上の価値、可観測性です。追加の機能は「今後提供される」と示されただけで、時期や内容は発表では触れられていません。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- Action center とエージェントの詳細画面で、高リスクのエージェント、ID、リスクの内訳、権限、コスト、価値を確認でき、稼働を許可するかブロックするかの判断につなげられる。
- Microsoft 以外（ServiceNow、Anthropic の Claude など）のエージェントも、同じ台帳で管理できる。
- Sierra については、delivery time が数日、precision が 96% という数値が示され、誤検知を減らして本当の脅威に集中できる。
- Darktrace との連携では、Microsoft の検知に行動ベースの知見が加わり、権限の境界内で起きるリスクの把握にも役立つ。
- 取り込みの 3 つの方法（Copilot Studio の自動登録、SDK、connected platforms）により、数千のエージェントでもまとめて管理できる。

## 9. まとめ

Agent 365 は、エージェントの台帳と Microsoft のセキュリティシグナルを結び、ServiceNow 上のエージェントのようなサードパーティ製であっても、Entra agent ID を軸に、リスク（Runtime、Exposure、Blast radius）、権限、コスト、価値、類似性、評価までを 1 か所で確認できるようにする製品として紹介されました。Sierra と Darktrace との連携は、データとインテント、行動の観点から、そのリスク判断を補強する位置づけです。

スケールについては、Fortune 500 企業 1 社あたり来年末までに約 150,000 のエージェントという見通しを前提に、Copilot Studio の自動登録、SDK、connected platforms の 3 つの取り込み方法が示されました。Brendan 氏は、Agent 365 にとってこの 1 年は observability が特徴だったが、2027 年は governance、security、business value が主題になると述べて締めくくりました。
