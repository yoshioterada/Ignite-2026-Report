# BRK211 Secure and Govern Microsoft Copilot Chat and Cowork

## 1. はじめに

このセッションは、Microsoft Copilot の Home タブに統合された **Copilot Chat と Cowork** を、組織として安全に展開し、統制するための「ツールと新機能」をまとめて紹介する内容です。IT 管理者やセキュリティ／Purview／データ管理者を主な対象に、Microsoft 365 管理センター、Microsoft Purview、SharePoint Advanced Management（SAM）という 3 つの領域から、Microsoft の 3 人が順番に登壇します。

話の骨格は、「Copilot が**アクセスできるもの**を守る」「Copilot とのやり取りの**最中**に機密データを守る」「AI に使わせるコンテンツ（コンテンツ資産）を**統治**する」の 3 点です。Natalia 氏は、Copilot はリスクを新しく作るのではなく、もともとデータとアクセス権の中にあるリスクを、速く簡単にアクセスできることで増幅させるのだと説明しています。

発表された主な新機能は次のとおりです。

- Cowork のスキル、プラグイン、MCP サーバー、コネクターを管理する **Microsoft Tool Governance for Copilot Cowork**（Microsoft 365 管理センターで一般提供）
- Copilot のグラウンディング（根拠データの参照）を、ラベルだけでなく**機密情報の種類（Sensitive Information Type、以下 SIT）**で止める DLP の拡張
- Copilot へ貼り付けたファイルや添付ファイルまで広げたプロンプト内 SIT の DLP 検査
- Copilot メモリに対するデータライフサイクル管理（保持と削除）の一般提供
- SharePoint admin agent、Content Governance Hub、カタログ管理など、SAM の拡張

## 5. 発表内容の詳細

### 5.1 信頼の 2 本柱：組み込みのコミットメントとツール（Sophie 氏）

Microsoft Copilot の信頼は 2 本柱で成り立つと説明されました。1 つ目は**組み込みのコミットメントと保護**で、設定不要で Copilot に付いてくるものです。2 つ目は、組織ごとの要件に合わせて構成するための**ツール**で、このセッションではこちらが中心です。

組み込みのコミットメントとして挙げられたのは次の項目です。

| 項目 | 説明された内容 |
| --- | --- |
| プライバシー | データはお客様のもの。基盤モデルの学習・改善には使わない |
| データ主権 | データ処理とデータレジデンシー（今後の EUDB を含む）、責任ある AI の原則に従う |
| デジタルセーフティ | プロンプトインジェクションの検出とブロックが組み込み済み。検出時のシグナルは例えば Microsoft Defender に流れ、SOC チームが検知できる |
| 規制コンプライアンス | ISO のコンプライアンス認証を持ち、サイバーセキュリティを中核にしている。Microsoft Security First initiative（聞き取った表記のまま）が Copilot の改善にも反映されている |

ツール側では、Copilot のライセンスに含まれる **SharePoint Advanced Management** と、Microsoft Security の製品群が挙げられました。これらで、Copilot のアクセス、リスクと脅威の検出、共有と権限、監査調査、データ保護、データコンプライアンスを統制できるという説明です。

信頼を築くために、守る対象は 3 つに整理されました。

1. **AI がアクセスできるものを守る**：グラウンディングデータとなるデータやツールを管理し、オーバーシェア（過剰共有）のリスクに対処して、機密コンテンツを Copilot の回答に出さないようにする
2. **やり取りの最中に機密データを守る**：ユーザーが Copilot にプロンプトを入れる際に、機密情報を検出・ブロックする。Copilot が関連するメモリをどのくらいの期間覚えておくかも対象
3. **AI に使わせるコンテンツ資産を統治する**：オーバーシェアを継続的に見つけて直し、サイト所有者に対応を促し、IT 管理者が手作業にならないよう自動化する

### 5.2 Microsoft Tool Governance for Copilot Cowork（Sophie 氏）

最初に、会場へ「Cowork をすでに展開したか」「展開を検討中か」と挙手を求めたうえで、**Microsoft Tool Governance for Copilot Cowork** が発表されました。Cowork が使えるツール、スキル、プラグインを管理するための機能で、Microsoft 365 管理センターに **Tools タブ**が加わります。ここには、Cowork やほかのエージェントが利用できるプラグイン、スキル、MCP サーバー、コネクターが一覧で表示されます。

管理者は、スキルを 1 つ選び、横に出るサイドパネルでそのスキルの内容を確認できます。さらに Users タブで、そのスキルを「全ユーザーに許可」「誰にも許可しない」「特定のユーザーとグループにだけ許可」のいずれにするかを決められます。Cowork のツールに対して、細かい粒度で制御できるという位置づけです。この機能は Microsoft 365 管理センターで**一般提供（GA）**になっています。

### 5.3 リスクの捉え方と 4 つの問い（Natalia 氏）

Natalia 氏は、Purview の詳細は別のセッションで深く扱ったため、一部は重複するとしたうえで、ここでは Purview の機能が SharePoint の保護・統制とどう組み合わさるかを見せると説明しました。

Copilot を展開、またはスケールするときに自問すべき問いとして、機密コンテンツから始まる次の順序が示されました。

1. 自分の機密情報（機密コンテンツ）は何か。なぜ守るべきか
2. それに誰がアクセスできるか。どこまで広がってよいか
3. 人にそのデータで何をさせてよいか。Copilot には何をさせてよいか
4. データはどう使われているか（Purview はデータの発見から DLP、Insider Risk Management まで複数の層のデータセキュリティを扱う）

これに答えるための手順は、「データを発見して分類する」→「ラベルを適用する」→「データを保護する（Copilot が見て使えるものを選ぶ）」→「やり取り（インタラクション）に対する保護を適用する」の順です。ラベルは、ファイルの前に来るたびに「それが何なのか」を示す名札のようなもので、透かしや暗号化も付けられると説明されました。

Purview が Copilot のセキュリティ領域で差別化される点は、Microsoft 365 と Copilot にネイティブに統合されていることです。データの読み取り、やり取りへの保護、やり取りで起きたことの確認が、すべて Microsoft 365 の境界内で行われ、データがコンプライアンス境界の外に出ることはないと述べています。

### 5.4 DSPM で見える化する：objectives、リスクパターン、データリスク評価

Purview の **Data Security Posture Management（DSPM）**は、データの状況とリスクを横断的に把握する「タウンスクエア」だと説明されました。昨年の Ignite で紹介された **objectives**（データセキュリティ態勢で重視すべきこと）の 1 つに「Copilot の保護」があり、その中に、すぐ使えるインサイトとして**リスクパターン**が用意されています。例として次が挙げられました。

- AI の利用に関するリスク
- 機密情報を含むユーザープロンプトが Copilot に送られた件数
- 機密情報を含みながら**ラベルが付いていない**項目が Microsoft 365 にどれだけあるか（ラベルが名札であるため、重要な情報の種類にラベルが付いていない状況を把握することが大切だと説明）

リスクパターンの修復計画（remediation plan）では、見るだけでなく、実行すべきアクションが推奨として示されます。推奨の 1 つが**データリスク評価（data risk assessment）**です。Natalia 氏は、DSPM の既定の評価を選ぶと、上位 100 の SharePoint サイトについて、アクセスしている人数、ラベルのないファイルの数、項目数、そのサイトの秘密度ラベルが分かる様子を示しました。公開範囲が広いサイトを見つけたら、中にどんな機密情報タイプが多いかも確認し、重要なものに対してポリシーを作ります。

例として、製薬会社を想定し、過剰共有されたサイトに **DEA enforcement number**（発話では「DEA 番号」とも）という情報タイプが多いケースを取り上げました。

もう 1 つの新機能は、**分類子（classifier）の統合ビュー**です。以前は、すべての分類子とそれに適用されたポリシーを 1 か所で見られませんでしたが、今は見られます。この DEA の分類子を見ると、保護ポリシー、ラベル付けポリシー、自動ラベル付けポリシー、DLP ポリシーのいずれも未設定であり、これがラベル未設定の項目が多い理由だ、という流れで説明されました。

### 5.5 分類とラベル付けの強化（Natalia 氏）

分類とラベル付けの強化として、次の 2 点が紹介されました。

- **組み込み SIT の精度向上**：まず最もよく使われる上位 100 の組み込み SIT から始め、近く全ての組み込み分類子に広げる。分類子が信頼できなければ、発見も、それに基づくポリシーも期待どおりに動かないため、品質と精度に投資したという説明
- **自動ラベル付けのスケール**：自動ラベル付けできるファイル数の上限が 1 日 100K だったのを、**1 日 500K** に引き上げた。大規模組織からの要望が強く、プラットフォーム側で手作業の変更をしなくてもスケールできるようになる

分類については前日に専用のセッションがあり、オンデマンドでの視聴が勧められました。

### 5.6 DLP for Copilot：グラウンディングとプロンプトの保護

Natalia 氏は、**Copilot はユーザーがすでに持っているアクセス権を尊重する**ことが組み込みの価値だとしたうえで、データが過剰に露出している可能性がある以上、追加のガードレールが必要だと述べます。そこで DLP が登場します。

**(1) グラウンディングの制御**　Copilot がどのデータに到達できるかを選ぶ仕組みです。現在使える DLP ポリシーでは、**秘密度ラベル（例：Confidential）が付いたファイル**を Copilot のグラウンディングに使わせないようにできます。ラベルが Confidential のファイルを要約させようとしても、Copilot はそのファイルを処理しません。

ただし登壇者は、保護をラベルだけに頼ってはいけないと強調します。自動ラベル付けポリシーを実行し終わるまでには時間がかかり、設定後も毎日新しいデータが増え、それにはラベルが付いていないことがあるからです。そこで、**前日に発表された新機能**として、Copilot のグラウンディングを**機密情報の種類（SIT）**で制御する DLP が示されました。例として、ラベルのないファイルに機密情報の種類が含まれる場合、ポリシーがないと Copilot はそのファイルを使ってブリーフィングを作ってくれますが、ポリシーを作ると、同じ依頼でも、情報源がそのラベルなしファイルだけであれば Copilot は結果を返さなくなります。ラベル付けが完了していなくても保護でき、Copilot から安全に早く価値を引き出せる点が、IT 意思決定者の多い会場に向けた利点として強調されました。

**(2) プロンプトの保護**　DLP は、データが共有・転送・持ち出される不適切な利用を防ぐものです。Copilot では「プロンプトと応答」という新しいやり取りが加わりました。今日の時点で、プロンプト本文に SIT が含まれていればブロックできます。例として、DEA 承認の登録番号を含めて要約させるプロンプトは、ファイルがなくても SIT を理解して、処理されません。

**(3) ファイルと添付ファイルへの拡張（Ignite での発表）**　プロンプトはテキストだけではなく、ファイルを貼り付けて「要約して」と頼むことも多く、そのファイルにラベルがあるとは限りません。そこで、プロンプトのスキャンを、**テキストだけでなく、貼り付けたファイルや添付ファイル**にも拡張すると発表されました。例では、プロンプト自体に SIT が無くても、ファイルの中に SIT があるため、Copilot はブロックしました。

**(4) 運用面の改善**　1 つの DLP ポリシーに、これらのルールをまとめて入れられます。1 つのケースのために 5 つも 7 つも DLP ポリシーを作る必要はなく、管理しやすいと説明されました。また、数回の Ignite 前から要望のあった、**ポリシーチップ（ユーザーに表示される通知）にカスタム URL を設定する機能**の提供が始まっています（発話は「starting to do」）。これまで回答に出るポリシーチップは既定の内容でしたが、ポリシー設定時に URL を指定すれば、組織のガードレールや制限を説明する社内 SharePoint サイトなどに誘導でき、チェンジマネジメントや社内教育に役立つとのことです。

これまでに利用できた DLP のコントロールは次のとおりです。

- ラベル付きのファイルとメールをグラウンディングからブロックする（ベースラインとして Copilot に触らせない）
- 機密性の高いプロンプトをブロックする
- 機密データが Web 検索に送られないようにする（Copilot で Web 検索が有効な場合）
- 外部メールを応答から除外する（社内情報だけを使いたい場合）

今回、これに「添付ファイルとリンクに対する DLP の拡張」と「ラベルが付いていなくても SIT でグラウンディングを制御する DLP」が加わった、という整理です。

### 5.7 Insider Risk Management とデータライフサイクル管理（Natalia 氏）

保護の多くは「人が何かをする」ことで発生するため、**Insider Risk Management** にも触れました。リスクのある AI 利用ポリシーがあり、1 つのプロンプトだけでは危険でなくても、プロンプトの後にプロンプトインジェクションの試みが続き、さらにその後に「vector tracing」（音声認識の表記のまま。意味は発表からは確認できません）が続くような一連の挙動は、リスクの高いシーケンスになり得るという例が挙げられました。可視性を高めて、より多くの情報でアクションを取れるようにする、という位置づけです。

続いて保持の要件です。世界の規制が、監査や証拠のために Copilot の情報を保持するよう求める傾向にあるとして、**Copilot メモリに対するデータライフサイクル管理（保持と削除）の一般提供**が発表されました。Copilot を保持対象のコミュニケーションチャネルの 1 つとして扱えるだけでなく、本当に必要なものだけを保持し、重要でないものは保存しない選択もできると説明されました。

これらをまとめて、**エンドツーエンドのコンプライアンススタック**という枠組みが示されました。世界の規制への準備状況を評価し、すべてのプロンプトと応答を監査し、リスクのある、あるいはコンプライアンス違反・非倫理的な行動を検出し、データライフサイクル管理で保持するという流れで、監査人や規制当局に対する証拠も 1 か所で得られると説明されました。

### 5.8 SharePoint Advanced Management（SAM）によるコンテンツ統治（Dave 氏）

Dave 氏は、「なぜコンテンツ統治の機能を SharePoint に作るのか」という顧客からの問いに、Microsoft 365 のどのアプリでも、保存や共同編集は SharePoint に支えられているから、と答えます。SAM は、ここ 3、4 年かけて育ててきたスイートで、スライドの紫色の部分が新しい投資と、本日から順次ロールアウトされる新機能とのことです。時間の都合で詳しくは触れないものとして、次が挙げられました。

- **Inactive sites ポリシー**：非アクティブなサイトを継続的に見つける。これまで最大 6 か月までだったが、**最大 36 か月**に拡張された
- **Inactive file ポリシー**：要望の多かった新機能。現在も PowerShell でできるが、非アクティブなコンテンツからコンテンツ資産を素早く片付けられるようになる。Copilot やエージェントの品質向上や、使うトークンの管理にも重要だと説明された
- **ストレージ管理**：SAM に導入される大きな領域

#### SharePoint admin agent

SAM はツールやレポートが多く、顧客から「速く作りすぎて追いつけない」という声があり、レポートも大きくなって、管理者が何をすべきか理解するのに時間がかかるという課題があります。そこで **SharePoint admin agent** は管理者のアシスタントとして、テナントについて（まだ全てではないが多くを）理解し、すべてのレポートを把握して、評価・発見・優先順位付けを行います。アクションとしては、委任や完了をサポートしており、エージェントの行動を**監査目的で追跡**できるようになりました。

SharePoint admin agent は**宣言型エージェント（declarative agent）**で、Microsoft 365 内の Copilot ロゴがある場所からいつでも呼び出せます。SharePoint admin center では最初から組み込まれているため、呼び出す必要はなく、尋ねるだけで自動的に動きます。

#### Content Governance Hub

今年の大きな投資が **Content Governance Hub** です。エージェントが関わるアクションを集約するハブで、SharePoint admin center のホームに表示されます（従来の見た目に戻すことも可能）。エージェントが自動でレポートを実行・分析して findings（所見）を出し、レポートを手動でダウンロードすることもできます。干し草の山の中の針のようなインサイトを見つけ、エージェントを使って調査し、推奨を得て、アクションを実行し、それを追跡できます。監査が必要なら、エージェントが行ったことのレポートもダウンロードできます。

#### コンテンツカタログ管理（Content catalog management）

テナント全体のアクションを開始する前に、「ポリシーを動かした途端、質問が殺到してヘルプ担当のようになってしまう」と心配して、管理者がためらうことがよくあります。それに対応するため、コンテンツがどう構造化されているかを理解し、より戦略的かつ安全にガバナンスアクションを開始するためのカタログ管理が紹介されました。すでに利用可能です。

- **組み込みビュー**：設定不要。Entra、組織構造、コンテンツのアクティビティ、各種メタデータから自動作成され、更新は現時点で毎日（「I believe」という留保付き）
- **カスタムビュー**：組織の構成に合わせて作りたい顧客向けに、3 つの方法がある。(1) 分けたいサイトのリストをアップロードする、(2) サイトのカスタムプロパティを使う、(3) Entra の拡張属性（extended attributes）を使う
- **アクション**：バケット（カタログのグループやカテゴリ）を定義したあとで実行できる。最初のアクションは **restricted content discovery** で、今後、一括操作を増やしていく

近日提供予定として、アクションを開始したあとの 1 対 1 の問い合わせ対応を委任する **transformation champions** が紹介されました。多くの顧客には、管理者が進める連絡や変革活動を手伝う部署レベルの担当者がいます。この担当者を、管理体験の中でより自動的に指名・登録し、ガバナンスの整理活動を推進してもらえます。新しい機能やサービスの導入・浸透を進めるときの窓口としても有効だと説明されました。Microsoft 社内には、プライバシーレビューのチャンピオン、セキュリティレビューのチャンピオンなどがあり、基本的な質問に答えるよう訓練されているため、すべてが管理者に集中しなくて済むとのことです。これらの機能は、エージェントにも取り込まれ、アクティビティやエンゲージメントに基づいて割り当て候補を特定できるようにする予定です。

カタログ管理はこれまでサイトが対象でしたが、約 1 週間前から **OneDrive の列**も追加されました。部署などの構造ごとに全コンテンツを俯瞰できる場所を目指しており、エージェントの insights やレポート、ほかの所見もここに統合し、同じ画面からアクションを取れるようにする計画です。

#### サイト所有者向け Governance Hub

ここまでは管理者向けの機能でしたが、次はサイト所有者が管理者から依頼されたことを完了できるようにする領域です。**governance hub for site owners** は、管理者が依頼したアクションを 1 つの一覧にまとめて見せるもので、すでに**パブリックプレビュー**です。ワンクリックで修正する「fix it」シナリオにも対応しています。今後、管理者エージェントの機能をここにも統合し、エージェントがサイト所有者の作業も手伝えるようにする計画で、これは 2027 年の投資に当たるとのことです。

最後にロードマップのスライドが示され、SAM は現在ツール群のスイートであり、紹介したものはそのハイライトだと説明されました。

## 6. デモ・手順

冒頭で「ライブでデモスライドを見せる」と予告があり、Tool Governance、DSPM、DLP の挙動については、登壇者が画面を提示しながら説明しています（「ここでスキルのセクションに移り」「これが実際にどう動くか見てみましょう」といった発話）。録音は音声のみのため、ここでは**語られた範囲**に限って整理します。画面の細部（ボタン名など）は音声からは確認できません。また、ライブ操作か録画・スクリーンショットかは、音声からは判別できません。

**Tool Governance の画面（Sophie 氏）**

1. Microsoft 365 管理センターの Tools タブを開く（プラグイン、スキル、MCP サーバー、コネクターが一覧表示される）
2. スキルのセクションに移り、Microsoft Corporation でフィルターする
3. Cowork で使えるスキルが一覧で表示される
4. スキルを 1 つ選ぶと、サイドパネルが開き、そのスキルの内容を確認できる
5. Users タブで、全ユーザー、ユーザーなし、特定のユーザーとグループのいずれかを選べる

**DSPM のデータリスク評価（Natalia 氏）**

1. DSPM の「Copilot の保護」に関するリスクパターンと、修復計画の推奨を確認する
2. 推奨からデータリスク評価に入り、既定の評価を選ぶ
3. 上位 100 の SharePoint サイトについて、アクセス人数、ラベルなしファイル数、項目数、サイトの秘密度ラベルを確認する
4. 過剰共有されたサイトで目立つ DEA 番号の SIT を見て、統合された分類子ビューで確認すると、ポリシーが未設定だと分かる

**DLP の動作例（Natalia 氏。いずれも Copilot とのやり取りの例として説明）**

| 例 | 内容 | 結果 |
| --- | --- | --- |
| ラベルによるグラウンディング制御 | Confidential ラベル付きのファイルを要約させる（ラベルベースの DLP ポリシーあり） | Copilot はそのファイルを処理しない |
| SIT によるグラウンディング制御（新機能） | ラベルなしファイルに SIT が含まれる。ポリシーなしで「ブリーフィングを作って」と依頼すると作成される。ポリシーを作ったあと同じ依頼をする | 情報源がそのファイルだけの場合、Copilot は結果を返さない |
| プロンプト内の SIT | DEA 承認と登録番号を含めて要約させる | プロンプトの処理がブロックされる |
| ファイルの中の SIT（新機能） | プロンプトに SIT は無いが、貼ったファイルに SIT がある | Copilot がブロックする |

SAM の部分（SharePoint admin agent、Content Governance Hub、カタログ管理、サイト所有者向けハブ）は、画面のイメージやスクリーンショットを示しながらの説明が中心でした（「これは、いくつかの画面でどう見えるかの簡単な画像です」といった発言）。操作の手順は語られていません。

## 7. 注意点・発表者の気付き

- **ラベルだけに依存しない**：自動ラベル付けが完了するまでには時間がかかり、設定後も毎日新しいデータが増えます。ラベルのないデータを守るため、SIT によるグラウンディング DLP が必要だと述べています。またプロンプトはテキストだけではなくファイルの貼り付けも多いため、プロンプトの検査をファイルと添付ファイルにも広げたと説明しています。
- **分類子の品質が前提**：分類子が信頼できなければ、発見もポリシーも期待どおりに動かないとして、組み込み SIT の精度改善（まず上位 100）に取り組んでいます。
- **Copilot はリスクの原因ではなく増幅器**：アクセス権とデータの構造が整っていないと、Copilot の速さと手軽さがリスクを広げます。
- **管理者のためらい**：テナント全体のアクションを実行するとサポート窓口になってしまう懸念があり、カタログ管理や champions で段階的・安全に進めることが提案されました。
- **ロールアウトの時期**：Dave 氏は、紹介した新機能は「本日から」順次ロールアウトを始めるとしています。一部は近日提供（transformation champions）、一部は 2027 年の計画（サイト所有者向けハブへの管理者エージェント機能の統合）です。各機能の提供時期は発表の範囲でしか確認できません。
- **Cowork への適用**：Copilot Chat 向けの機能の多くが Cowork にも拡張されています。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。具体的な顧客事例や成果の数値は、このセッションでは紹介されていません。

- Cowork のスキルやプラグインなどのツールを、全員・なし・特定のユーザーとグループ単位で管理できる
- ラベル付けが終わっていなくても、SIT で Copilot のグラウンディングやプロンプトを保護でき、Copilot から早く安全に価値を得られる
- 1 つの DLP ポリシーに複数のルールをまとめられ、管理しやすい。ポリシーチップから社内の説明ページへ誘導して、チェンジマネジメントや教育に役立てられる
- 自動ラベル付けが 1 日 100K から 500K に拡大し、大規模組織でも手作業を減らしてスケールできる
- Copilot メモリを含む情報の保持・削除ができ、監査や規制対応の証拠を 1 か所で確保できる
- SharePoint admin agent と Content Governance Hub により、レポートの評価、優先順位付け、アクションと追跡を、管理者が手作業ですべて行わなくても進められる
- 非アクティブなサイトとファイルの整理で、Copilot やエージェントの品質、使用するトークンの管理に役立つ

## 9. まとめ

BRK211 は、Copilot Chat と Cowork の安全な展開を、「アクセスできるものを守る」「やり取りの最中に守る」「コンテンツ資産を統治する」の 3 つで整理したセッションでした。Microsoft 365 管理センターの Tool Governance（GA）で Cowork のツールを制御し、Purview の DSPM、分類、DLP で、ラベルの有無にかかわらず機密情報を Copilot から守ります。さらに、Copilot メモリの保持・削除（GA）と、SharePoint Advanced Management の admin agent、Content Governance Hub、カタログ管理で、コンテンツ資産の統治を継続的に進められるようにする、というのが全体像です。
