# BRK287 Trusted code at scale, from legacy to AI

## 1. はじめに

このセッションは、GitHub の **GitHub Code Quality** を紹介するものです。AI でコードの生産速度が上がるなか、レビューや品質の確認が追いつかなくなる問題に対して、「速度と統制はトレードオフではない」という考えで、コード品質の検出・修復・ガバナンスを GitHub のプラットフォームに組み込む方法を説明しています。

発表は、スライドで背景と製品の仕組み、効果の数値を紹介したあと、画面を共有したライブデモ（リポジトリでの有効化、ルールセット、プルリクエスト上の指摘、テストカバレッジ、バックログのスキャン、組織レベルのレポート）に進みます。その後、今後のロードマップ、ライセンスと価格、会場からの 4 つの質問への回答が続きます。この文書を読むと、Code Quality が何を検出し、どう修正まで進め、どうマージを止めるのか、そして価格の考え方を確認できます。

## 4. 発表者が伝えたいメッセージ

中心のメッセージは、**品質は最後に後付けするものでも、別のツールで扱うものでもなく、プラットフォームに組み込まれているべきだ**という点です。Subhash 氏は、ソフトウェア開発を F1 のドライビングにたとえています。F1 のドライバーは速く走らなければなりませんが、事故を起こさないよう制御も必要で、勝つには速度と制御の両立が欠かせません。ソフトウェアでは、直線区間がコードを作る反復にあたり、コーナーがコードレビューや品質・セキュリティのゲートにあたるというたとえです。冒頭では、元 F1 チャンピオンの言葉として、「速く見えるときは滑らかではなく遅い。遅く見えるときは滑らかで速い」という趣旨の引用が紹介されました（人名は発話では "Elaine Prost" と聞こえ、音声認識の都合で表記が確定できません）。

背景には、AI がソフトウェア開発を加速させたことがあります。数日かかった作業が数時間、数分、数秒になり、GitHub の Secret Protection のチームは、AI を使うだけで四半期あたりのバリデーターの出力を 10 倍にしたと述べています。そこで問われるのは、出力が 10 倍になったときに、コードレビューの一貫性をどう保つかです。速度に偏ると技術的負債と本番バグが増え、顧客の信頼と売上が落ちます。ブレーキを踏みすぎるとレビューが遅くなり、開発者のフローが途切れて、AI で得た速度を失います。

GitHub の答えは、すべてのコードが、誰が書いたかにかかわらず、既定でセキュアで高品質であるべきだという信念です。

## 5. 発表内容の詳細

### 5.1 会場への質問と GitHub Code Quality の位置づけ

Subhash 氏は、コード品質の測定・強制に何かツールを使っているかを挙手で尋ね、使っているツールを会場から聞いています。挙がったのは SonarCube（発話の表記。音声認識の都合で確定できません）と X-ray などで、SonarCube は市場で最も広く使われているツールの 1 つだと述べています。

既存の品質ツールには、プラグイン、コンテキストの切り替え、別々のダッシュボード、分断されたワークフローという課題があります。GitHub Code Quality は、チームが既に使っているプラットフォームにネイティブに組み込まれ、ほかのツールともうまく連携すると説明されています。

### 5.2 仕組み: 検出、修正、可視化、ガバナンス

**検出**は 2 つのアプローチの組み合わせです。

- **CodeQL**: ルールベースの検出エンジンで、決定的な品質ルールを提供するため結果は一貫していて信頼できます。もともとセキュリティ上の欠陥の検出に使ってきたもので、デッドコード、不正なフォーマット、非効率なパターンなど、保守性と信頼性に関わる実際の問題も見つけます。コストの面でも効率的です。
- **AI**: CodeQL が見逃しがちな、紛らわしい変数名や不適切なエラーメッセージなど、コードの作られ方や設計の文脈が必要なものを見つけます。

この 2 つで、コード品質の問題を見つける基盤エンジンになるという説明です。

**修正**は、すべての指摘が **Agentic Autofix** につながります（今月リリースされた機能です）。Copilot が問題を指摘するだけでなく、修正案を出します。エージェント的なループで、修正を特定し、実装し、コードの機能を壊していないかを検証し、レビューして取り込むだけでよいプルリクエストを作成します。

**可視化**は、主要なフレームワーク向けのテストカバレッジと、リポジトリ単位・組織単位のトレンドダッシュボードです。コードのどれだけをテストし、検証しているかを把握し、時間とともに改善・悪化を追えます。

**ガバナンス**は、プルリクエストの品質ゲートで、マージ前に基準を強制します。これらはすべて GitHub 上でネイティブに動き、追加のツールは要らないとされています。

### 5.3 コード品質の 4 つの観点

開発者が「コード品質」と聞いて思い浮かべるのは、次の 4 つだと説明されています。

| 観点 | 内容と結果 |
| --- | --- |
| 保守性 | 長く付き合いやすいコードか。デッドコードやドキュメントの欠如は、今日は壊さなくても、明日からのあらゆる変更を遅くする。結果として、デリバリーの遅れと長期的なコスト増になる |
| 信頼性 | 肝心なときにソフトウェアが動くか。未処理の例外、不安定な（flaky）テスト、欠けたテストが原因になりやすい。すり抜けると障害になり、取り戻しにくいユーザーの信頼を失う |
| テストカバレッジ | 重要な経路が未テストだったり、ユニットテストが不十分だったりすると「希望的観測で出荷する」ことになり、本番で回帰やバグとして表れ、そこが修正にもっともコストのかかる場所になる |
| AI 時代の課題 | AI は速くコードを書けるが、生成コードはブラックボックスになり得て、なぜ・どう動くのかを誰も完全には理解できない。複数の出所のコードが混ざると、開発者とエージェント、あるいはエージェント同士でスタイルがばらつく。レビュー（最大の安全網）が難しくなり、担当者が辞めたり、基準を満たさないエージェントが作られたりすると、保守が一層難しくなる |

### 5.4 SDLC のどこで動くか

Code Quality は、SDLC の複数の段階で動きます。

- **プルリクエストの作成時**: 指摘がコードの変更と同じ場所にインライン表示されます。Copilot の自動修正の提案により、レビューに出す前に品質の問題を直せます。
- **マージ時**: ルールセットで、技術的負債がコードベースに入るのを防ぎます。
- **既存のコード**: CodeQL と LLM によるリポジトリのスキャンが継続的に品質の問題を見つけ、Agentic Autofix で一括して修正できます。

### 5.5 効果の数値

発表で紹介された、顧客のコードベースでの効果は次のとおりです。

- プルリクエストでの指摘の **67% 超** に、Copilot の修正提案が付いている（目標は 100% で、修正提案の拡充を急いでいる）。
- 顧客組織のプルリクエスト上の指摘の **70% 超** が、同じ日のうちに修正されている。コード作成を遅くせずに、必要な品質基準に届いていることを意味する。
- 顧客からは、既存のツールだと数万件の品質バグが溜まり、直せないものの優先順位づけをせざるを得ない、という声が出ている。SDLC に組み込むと、コードベースに入る前に直せる可能性が高まる。
- Code Quality を有効にした顧客では、リポジトリのバックログが平均で **50% 減** っている。6 か月以内に技術的負債が少なくとも半分になる計算で、発表では、Agentic Autofix と Copilot の自動修正をバックログに適用し、エージェント的に継続して直していることが理由だと説明されています。

### 5.6 ロードマップ

今後数か月で力を入れる領域として、次の 3 点が挙がりました。

1. **レポーティング**: コードカバレッジ（テストカバレッジ）と品質指標のレポートは、特に CISO や CTO のための優先事項で、エージェント的なレポートを増やす。保守性と信頼性に加えて、テストカバレッジとコードカバレッジも時間軸で追えるようにしていく。
2. **コンプライアンス標準とレポート**: 自動車など規制の厳しい業界向けに、MISRA や AUTOSAR のようなコーディング標準のコンプライアンスレポートを生成できるようにする。
3. **追加の指標**: 顧客から要望の多い、循環的複雑度（cyclomatic complexity）などの業界標準の指標を追加する。

### 5.7 ライセンスと価格

Code Quality は GitHub Advanced Security（Secret Protection、Code Security、Supply Chain Security を含む製品群）に組み込まれていますが、**別ライセンス**が必要です。ライセンスは、コミッターごとの課金と、AI の部分に対する従量課金の組み合わせです。ライセンスを有効にすると、Secret Protection、Code Security、Dependabot の結果とあわせて、品質の結果がリポジトリに出ます。Code Security や Secret Protection と同様に、Code Quality のトライアル体験も準備中です。価格についての詳細は 5.9 の Q&A にまとめています。

### 5.8 まとめとして挙げられた 3 点

Subhash 氏は、Code Quality が「検出・修復・ガバナンス」のループ全体を、レガシー、AI 生成、新規のコードのいずれにも提供すると整理しています。

- **検出**: CodeQL と AI の検出が、開発者、エージェント、長年抱えてきたレガシーコードのいずれから来た変更も見る。
- **修復**: Copilot と Agentic Autofix が、指摘をレビュー可能な変更に変え、バックログが増えずに縮む。
- **ガバナンス**: ルールセット、マージゲート、レポートで、品質を組織全体の標準にする。

共通するのは「1 つのエンジンと 1 つのルールブック」で、セキュリティと品質が同じ基盤を共有するため、別々のツールや食い違う標準を扱わずに済むという説明です。

### 5.9 Q&A

**Q1. 組織独自のコーディング標準（カスタムのルール）を Code Quality に追加できるか。**（質問は "custom skill" と聞こえますが、聞き返しに対して、質問者が「組織独自のコーディング標準のようなもの」と補足しています）
回答: 一部の顧客は CodeQL で既に行っているとのことです。MISRA などの独自のクエリパックを作る顧客がおり、GitHub 側にも、そうした用途のカスタムクエリパックを作るチームがあります。CodeQL は拡張性が高く、特定の問題を見つけるクエリルールを作って組み込めば、その周りにマージゲートやルールセットを設定できます。

**Q2. AI が生成する greenfield のリポジトリなど、特に AI 生成コードを、なぜ Code Quality が自動でレビューしないのか。エージェントが Code Quality とループして、品質基準を満たすコードを生成できないのか。**
回答: 品質の維持は組み合わせだと答えています。コード生成にも品質が組み込まれており、Copilot coding agent を使うと、高品質なコードを生成するためのレビューツールが動きます。Code Quality が担うのは、技術的負債だけでなく、コーディング標準の強制です。開発者とエージェントのコード生成の両方に、同じコーディング標準を適用して、整合性を保つ手段だという説明です。Code Quality のような各段階でのチェックがないと、特定の標準に従う開発者と、別の標準に従うエージェントが混在し、その開発者（またはその開発者と一緒にエージェント）が去ると、組織全体の標準と異なる書き方のコードが残ります。PR より前の段階で高品質なコードを生成していても、組織全体で一貫していることを強制する必要がある、とのことです。開発者ごとにコーディングエージェントの標準が違い、書き方の好みも違うため、技術的負債を溜めないためのチェック・アンド・バランスだという位置づけです。

**Q3. この機能は Azure DevOps にも来るのか、GitHub に限られるのか。**
回答: 既に Azure DevOps にもあると思う、確認する、という答えです。GitHub Advanced Security に追加する機能は、GitHub でのリリースと Azure DevOps への提供の間に少し遅れがあるのが普通ですが、すべての機能を Azure DevOps にも提供するようにしているとのことです。

**Q4. 顧客が AWS への移行を検討していて、懸念は価格だという。Copilot の GitHub 側の価値を、どう伝え返せばよいか。**
回答: 価格は Copilot チームが管理しているため踏み込んだ話は避けつつ、Universe で発表した内容を要約しています。Copilot は GitHub の一部になり、別ライセンスは不要で、今年前半のトークンベースの変更や価格の変更でさらに簡単になりました。Code Quality 自体は、コミッターごとの部分と AI 利用の部分があり、**現時点ではコミッターあたり 10 ドル**で、価格は常に見直している、と述べています。従量課金の部分は、同じ Copilot の AI クレジットのプールから引き落とされます。したがって、Copilot が組み込まれ、AI クレジットのプールを使い、Code Quality と Advanced Security のスイートまで GitHub に埋め込まれる形になります。大きな変更は、数週間前の Universe で発表した、Copilot の利用に別ライセンスが不要になった点だと繰り返しています。

## 6. デモ・手順

このセッションには、画面共有によるライブのデモがあります（発話: "let's jump into a demo", "hopefully you're able to see my screen here"）。題材は、レース用テレメトリのダッシュボードを扱うリポジトリです（F1 のテーマに合わせたものと説明）。画面の細部は音声からは確認できないため、語られた範囲で、順に整理します。

### 6.1 Code Quality の有効化

1. リポジトリの Settings に、新しく「code quality」のセクションがある。
2. ボタンを有効にするだけで有効化できる（このリポジトリでは有効化済み）。
3. もう 1 つ、**AI findings** にオプトインできる。CodeQL がサポートしない言語のバックログに対して実行され、LLM と CodeQL の組み合わせで必要な言語を網羅する。
4. AI findings のスキャンを実行する頻度を選べる。プッシュごとでも、時間間隔でもよい。以上の 2 つのトグルで有効化は完了する。

### 6.2 ルールセット（ガバナンス）

1. rule sets に、作成済みの code quality ルールセットがある。
2. バイパスの設定と、対象ブランチを選べる（デモでは既定のブランチ）。
3. 品質結果をどう強制するかを選べる。デモでは有効化したうえで、**警告（warning）レベル以上の指摘があるプルリクエストは、マージをブロック**する設定にしている。

### 6.3 プルリクエストでの指摘と修正

1. 開発者としてプルリクエストを作る。デモのため、指摘のなかには作為的なものもあるが、実際に検出されるものだと断りがある。
2. プルリクエスト上に、**GitHub code quality bot** による指摘（品質アラート）が、該当コードの位置にインラインで表示され、アラートの内容が簡潔に説明される。
3. Copilot に、その指摘の詳細を尋ねられる。Copilot が実行されている間、インラインで修正案も表示される。
4. 修正案は、プルリクエストの変更のバッチに追加するか、提案を直接コミットできる。
5. 未使用のコードや未使用の変数など、種類の違う指摘がほかにもある。
6. 指摘への対応を通じて、開発者は、指摘の内容を学び、将来それを防ぐ方法を知り、Copilot でプルリクエストの作成中にインラインで修正できる。

### 6.4 テストカバレッジ

1. すべてのプルリクエストに、そのブランチのコードカバレッジの概要が付く。デモのリポジトリは、バックエンドとフロントエンドに分けてあり、main のテストカバレッジは前回の確認時点で **73%** である。
2. 最初に見たプルリクエストは、テストカバレッジを上げも下げもしないため、それが分かるようになっている。
3. AI を使って、テストカバレッジのハーネス（カバレッジのファイル）を生成するエージェントがある。サポートするフレームワークを増やしている最中で、現時点では **JaCoCo** に対応している（発話では "Jococo"）。ベースラインを生成し、Copilot の力でカバレッジを上げることもできる。
4. 別のプルリクエストを開く。バックエンド API のテストカバレッジを改善するもので、テストを追加するファイルの変更を見せる。
5. このプルリクエストには、新しい指標が出ており、バックエンドのテストカバレッジが **13% 上がり**、マージすると **86%** になる。フロントエンドのテストカバレッジへの影響はなく、そのように区別して表示する。

### 6.5 マージのブロック

1. まだ指摘が残っているプルリクエストに戻ると、マージの状態に X が付いており、「マージが現在ブロックされている」と表示される。
2. クリックすると理由が分かる。警告（warning）以上の重大度のコード品質の指摘が検出されているため、ブロックされている。
3. バイパスして上書きすることもできるが、監査ログに記録され、防ぐこともできる、と説明している。

### 6.6 バックログのスキャン

1. リポジトリ上部の **Security and quality** タブに、code quality のセクションがある。
2. CodeQL 由来の標準の指摘（standard findings）と、LLM 由来の **AI findings** に分かれている。
3. CodeQL 由来のバックログの例として、「useless assignment to local variable」、「length 変数の値が未使用（常に上書きされる）」などの指摘がある。このリポジトリでは約 **11 件**。
4. すべてを選択して「Assign to Copilot」を実行する。エージェント的なループで、アラートが Copilot に割り当てられ、Copilot が問題を見つけて修正し、コードが壊れていないことを検証する。Copilot が生成するプルリクエストを、レビューしてから取り込める。このプルリクエストの完成した画面は、発話では確認できません。
5. 処理が進む間に元のデモに戻り、Agentic Autofix で技術的負債を大きく減らせると説明している。
6. AI findings も、CodeQL と同じ精度で表示され、Copilot の Agentic Autofix で修正できる。文脈が必要な領域で CodeQL を補う。

### 6.7 組織レベルのレポート

1. 組織レベルで、リポジトリ全体のレポートと品質のトレンドを見られる。デモのリポジトリ（発話では "RevLetics"。音声認識の都合で表記が確定できません）は、大きな組織の中の 1 つのリポジトリという位置づけ。
2. リポジトリごとのスコア分布から、信頼性や保守性のスコアが低いリポジトリを特定したり、高いものを評価したりできる。
3. 最近追加された機能として、トレンドがある。リポジトリ全体の推移を、直近 14 日または 30 日で追える。ヘルススコアや重大度でグループ化できる。
4. ヘルスのテーブルに、保守性や信頼性などの観点でリポジトリのランキングが出る。うまくいっているチームや、修正に時間をかけるべきチームを把握し、Agentic Autofix で品質の指摘を解消できる。

## 7. 注意点・発表者の気付き

- **別ライセンスが必要。** Code Quality は GitHub Advanced Security の製品群の一部ですが、別ライセンスで、コミッターごとの課金と AI 部分の従量課金の組み合わせです。価格（コミッターあたり 10 ドル）は現時点のもので、常に見直していると述べています。
- **サポートの範囲は広がっている途中。** テストカバレッジのハーネス生成は、現時点で JaCoCo に対応し、フレームワークを順次追加していく段階です。Copilot の修正提案が付く指摘は 67% 超で、100% を目指している途中です。
- **デモの指摘の一部は作為的。** Subhash 氏は、デモ用に作った指摘もあるが、実際に検出されるものだと断っています。
- **マージブロックのバイパス。** 上書きは可能ですが、監査ログに記録されます。
- **Azure DevOps への提供。** Subhash 氏は、既にあると思うが確認すると答えており、確定した回答ではありません。GitHub に先行して出て、Azure DevOps への提供に少し遅れがあることが多いとも述べています。
- **AI 時代の保守性。** 生成コードがブラックボックス化し、開発者やエージェントごとにスタイルがばらつくと、レビューと保守が難しくなると指摘しています。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **追加ツールなしで品質管理ができる**: プラグインやコンテキストの切り替え、別のダッシュボードが不要で、GitHub のプラットフォーム内で完結します。
- **修正まで一続き**: プルリクエストの指摘の 67% 超に Copilot の修正提案が付き、70% 超が同日中に修正されています。
- **バックログの削減**: Code Quality を有効にした顧客のリポジトリのバックログは、平均で 50% 減り、6 か月以内に技術的負債が少なくとも半分になります。
- **一貫した標準**: マージゲート（ルールセット）で、開発者と AI エージェントの両方のコードに同じ基準を適用でき、担当者が替わっても組織全体で一貫した品質を保てます。
- **可視化**: リポジトリ単位・組織単位のスコア分布やトレンドで、品質が良くなっているか悪くなっているかを追えます。
- **セキュリティとの統合**: セキュリティと品質が 1 つのエンジンと 1 つのルールブックを共有し、別々のツールや食い違う標準を扱わずに済みます。
- **既存コードにも対応**: レガシーコードも、CodeQL と LLM のスキャン、Agentic Autofix で、一括して修正できます。

## 9. まとめ

GitHub Code Quality は、CodeQL による決定的なルールと AI による文脈の理解を組み合わせて品質の問題を検出し、Agentic Autofix で修正案と検証済みのプルリクエストまで作る機能です。マージ時にはルールセットで基準を強制し、リポジトリと組織のレポートで品質の推移を追えます。デモでは、2 つのトグルでの有効化から、プルリクエストへのインライン指摘、バックエンドのテストカバレッジが 13% 上がって 86% になるプルリクエストの表示、警告以上でのマージブロック、約 11 件のバックログの Copilot への一括割り当て、組織のスコア分布とトレンドまでが示されました。顧客での効果は、修正提案が付く指摘が 67% 超、同日修正が 70% 超、バックログが平均 50% 減です。今後は、テストカバレッジなどのレポート強化、MISRA や AUTOSAR などのコンプライアンスレポート、循環的複雑度の追加が予定されています。ライセンスは別途必要で、コミッターごとに現時点で 10 ドルと、Copilot の AI クレジットのプールから引かれる従量課金の組み合わせです。
