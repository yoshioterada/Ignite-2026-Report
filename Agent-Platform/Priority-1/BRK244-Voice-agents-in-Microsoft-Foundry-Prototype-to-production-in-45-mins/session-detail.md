# BRK244 Voice agents in Microsoft Foundry: Prototype to production in 45 mins

## 1. はじめに

このセッションは、Microsoft Foundry の音声エージェント（voice agent）が一般提供（GA）になったことを受けて、機能の全体像と、実際に本番で使っている顧客の事例を紹介するものです。前半は Microsoft の登壇者が、Foundry の Speech 関連の新機能と voice agent の GA 内容を説明します。後半は、Landis Technologies（Teams 向けコンタクトセンターの ISV）、ASUS（グローバルのコールセンター向け AI エージェント）、Leap Motor（車載音声アシスタント）の 3 事例が続きます。

発表の出発点は「デモから本番にどう進むか」という課題です。「2028 年までに 13 億を超えるエージェントが作られ、その 80% 以上が音声でやり取りされる」という市場予測を引きつつ、「現在、1 つの簡単な機能ですらスケールさせた企業は約 4 分の 1」と説明しています。この差を埋めるために、モデルの選択肢、ビルドからデプロイ・運用までのライフサイクル管理、電話連携が強化された、というのが発表の骨子です。

## 3. 何に関する発表か

Microsoft Foundry は、AI エージェントを構築・デプロイ・運用するためのプラットフォームと説明されています。Agent Service ではエージェントが動き、モデルが知能を担い、Foundry IQ がメモリやナレッジとの接続を、ツールがエージェントの行動を支え、その全体が安全性、セキュリティ、ガバナンスの上に築かれていると説明されています。音声や Speech の AI は、主に Agent Service の中に位置づけられています。Foundry の Speech には、次の 4 つの柱があります。

1. end-to-end の voice agent
2. speech-to-text
3. text-to-speech
4. speech translation

これらは公開 API としても、エージェントの MCP ツールとしても使えると説明されています。

発表の流れは次のとおりです。

1. 市場の背景と、Foundry の Speech 4 つの柱の新機能（speech-to-text、text-to-speech、アバター、Live Interpreter API）
2. voice agent の GA（モデルの選択肢、HD v3 の音声、ライフサイクル管理、ハンドオフ、電話連携、顧客の状況）
3. 顧客事例 3 件（Landis、ASUS、Leap Motor）
4. まとめとリソース

## 5. 発表内容の詳細

### 5.1 市場の背景

Archer 氏は、次の AI エージェントの波は voice first だと述べ、市場レポートの予測として、2028 年までに 13 億を超えるエージェントが作られ、その 80% 以上が音声でやり取りされるという数字を挙げています。そのうえで、デモから本番への移行が課題であり、1 つの簡単な機能であっても voice agent をスケールさせた企業は約 4 分の 1 にすぎない、と説明しています。

### 5.2 Foundry の Speech の新機能（Archer 氏）

Ignite のタイミングで、voice agent 以外の柱にも新しいリリースがあります。

**Speech-to-text**

| 項目 | 説明 |
| --- | --- |
| リアルタイム文字起こし API | ストリーミング音声向け。**一般提供（GA）**になり、50 言語のネイティブな多言語サポートを備える（今後さらに追加） |
| マルチ音声チャネル対応 | テレフォニーシステムやオンライン会議の文字起こしなどのユースケースで重要と説明されている |
| Fast transcription と LLM speech | ファイルベース。より高速・高精度になり、多言語サポートも拡大。Azure Speech のデフォルトモデルに加え、MAI のモデル（最新の MAI の文字起こしモデルを含むと説明）も選べる（モデル名は音声認識の都合で確定できません） |
| コンテナー | オンプレミスのコンテナーが Fast transcription に対応。コンテナーをダウンロードし、自前の GPU で推論して、クラウドと同じ品質・同じ機能で文字起こしできる |

**Text-to-speech**

- **HD Voices V3** が利用可能になりました。表現力が高くなり、カスタマーサービス向けの新しいスタイルが追加されています。リージョンと言語の拡大も行われたと説明されています。
- **partner voices** を発表しています。すでにある数百の音声（音声では「hundreds of agent previewed voice」と聞こえ、正確な意味は確定できません）に加えて、パートナーやコミュニティによる、さらに幅広い選択肢が使えるようになります。
- **VASA V2 photo avatar** がパブリックプレビューになりました（音声認識では「Vasa V2」と聞こえます）。1 枚の写真から、リアルな上半身のトーキングアバターを作れると説明されています。

**Live Interpreter API**

リアルタイムの speech-to-speech 翻訳 API が、LLM ベースになりました。説明されている改善は次のとおりです。

- 翻訳の品質: 以前の本番版と比べて、翻訳のエラーが 30% 減った（音声では「translation adverse 30%」と聞こえます）
- 速度: エンドツーエンドの翻訳の遅延は 3 秒程度。Archer 氏は、これはプロの通訳者と同等かそれ以上に速いと述べています
- 話者の声のスタイルを保てる personal voice も引き続き選べる

この API は昨年登場し、コンタクトセンターのエージェント支援、国際会議の翻訳、イヤホンや AI グラスなどのスマートデバイスで使われていると紹介されています。

### 5.3 Voice agent の GA（Yiwen 氏）

Yiwen 氏は、voice agent は Foundry で最も成長が速い分野の 1 つだと述べ、需要の例を挙げています。

- **カスタマーサービス**: 銀行や保険会社への技術的な問い合わせ。10 分待たずに、数分で応答するエージェントと話せる
- **自動車**: ハンズフリーの車内アシスタント。目的地へのナビゲーションや、行きたいレストラン探し
- **学習・教育**: スキルや新しい言語を教えてくれる学習コンパニオン
- そのほか、人事、公共サービス、パーソナルアシスタントなど

**本日、Foundry の voice agent が GA になりました。** 3 つの大きなアップグレードがあります。

1. モデルの選択肢
2. ライフサイクル管理のフルアップグレード
3. 電話連携

すべての機能が当日から使えると説明されています。2 か月前のパブリックプレビューからの包括的なアップグレードという位置づけです。価値の 6 つの柱として、次の点が挙げられています。

- **モデル**: コスト、品質、性能の異なる複数の生成 AI モデルを用意。フラッグシップの **GPT live** は、市場で最高水準の speech-to-speech モデルの 1 つで、自然な会話と適切な応答タイミングを備えると説明されています。コスト効率の高いモデルとして、**GPT Real-time Mini** と **Azure Real-time Flash** もあり、音声品質とエージェント機能が高いとのことです。
- **レイテンシ**: Azure Real-time のエンドツーエンドの音声レイテンシは **0.7 秒未満** で、業界でも最高水準のものの 1 つと説明されています。
- **音声とアバター**: 完全にカスタマイズ可能で、これは業界でも珍しいと説明されています。
- **電話連携**: ダイレクトな接続を導入して最適化（音声認識では「direct safe connectivity」と聞こえます）
- **開発ツール**: 開発者のツールの好みが幅広いことを踏まえ、「Azure development key」（音声認識の都合で名称が確定できません）と、voice agent 構築向けの GitHub Copilot サポートを提供
- **テンプレート**: prompt agent 向けに、一般的なユースケース用の事前構築済みテンプレートを 40 以上用意

### 5.4 モデルの選択

「実際の Foundry ポータルの UX」を示しながらの説明です（ナレーション付き。録画かライブかは発話から断定できず、画面の細部も音声からは確認できません）。説明された内容は次のとおりです。

- 幅広い speech-to-speech モデルと LLM があり、低レイテンシなら GPT Real Time または Azure Real Time、深い推論が必要なら GPT や自前のモデルを使う
- 本日の新モデル: **GPT Live One**（フラッグシップの full-duplex モデル。顧客の意図の理解と割り込みへの対応が向上）と、**Microsoft Real-Time Flash One**（音声品質を保ちつつコスト効率が最も高い）。モデル名は聞こえた表記で、音声認識の都合で確定できません
- ターン検出（turn detection）とノイズ抑制もアップグレードされ、通話の途切れを抑える

> 注意：Yiwen 氏は、モデルは音声体験の中核だがそれだけではなく、voice activity detection（VAD）の技術やほかの設定と組み合わせて、テスト・構成しながら最良の speech-to-speech 体験を目指してほしいと述べています。

### 5.5 HD v3 の音声

顧客サービスなどの voice agent 向けに、感情表現が豊かな HD v3 の音声がリリースされました。説明では、Speech playground で HD v3 を選び、customer service のサンプルを試せるとのことです。会場では、「お問い合わせありがとうございます。本日はお手伝いします。問題を詳しく教えてください」という趣旨のサンプル音声が再生されました。voice agent と組み合わせた HD v3 は、より表現力があり、感情が豊かだと説明されています。

### 5.6 Voice agent のライフサイクル管理

Foundry では、ライフサイクル全体をプラットフォーム内で完結できる、という説明です。

| フェーズ | 内容 |
| --- | --- |
| Build | 構築方法を選び、目的を定義する。1 つのエージェントか、協調する複数のエージェントかを選び、ツールを接続し、ガードレールを設定してテストする |
| Deploy | アプリケーションに応じて複数のチャネルを選び、エンドツーエンドでテストし、要件を満たすまで反復する |
| Operate | デプロイ後も、主要メトリクスの監視、問題の発見、根本原因の分析、修正の組み込み、修正の評価、デプロイを繰り返し、品質を継続的に改善する |

Foundry の UX を使った説明（ナレーション付きの映像）では、次のように語られています。

- Build: prompt agent か hosted agent を選ぶか、40 以上のテンプレートから構築する。システムプロンプトを書き、モデルと音声を選び、ナレッジ、ツール、ガードレールを接続する
- Deploy: 電話、Web、モバイルなどユースケースに合うチャネルを選び、エンドツーエンドでテストして反復する
- Operate: モニターダッシュボードで問題を見つけ、トレースで根本原因を調べ、評価で修正の品質を測る

### 5.7 ハンドオフと既存エージェントへの音声追加

**ハンドオフ**は、複雑なシナリオで専門化されたエージェント間に会話を移す機能です。特にエンタープライズの顧客から、専門化したエージェントを連携させるとレイテンシが下がり、品質が上がり、コストも下がるというフィードバックを繰り返し受けたため、この GA で agent handoff を可能にした、と説明されています。構成は 2 種類です。

1. **Frontline handoff**: リアルタイムエージェントが音声を処理し、テキストのリクエストを prompt agent、hosted agent、あるいは Copilot agent に渡す
2. **One session handoff**: voice agent がトリアージ役になり、請求、スケジュール、ナレッジベースなどのタスクを、それぞれの専門エージェントに引き渡す

すでに hosted agent を持っている場合に、そのテキストエージェントに音声体験を追加することもできます。voice agent とテキストエージェントの間を、非常に低いレイテンシで双方向にストリーミングする仕組みで、hosted agent を持つ人にとって音声体験を作る最速の方法だと説明されています。

### 5.8 電話連携

電話連携は、コンタクトセンター向け voice agent を作る顧客からの最優先の要望だったと説明されています。発表された内容は次のとおりです。

- Foundry voice agent の **ネイティブなテレフォニー対応**を発表。既存の電話システムとシームレスに接続できる（音声認識では「native SAP support」と聞こえ、正式な名称は確定できません）
- そのほかの選択肢として、Microsoft Teams phone extension、および Twilio などのサードパーティのテレフォニープロバイダー

### 5.9 顧客事例 1: Landis Technologies（Matt 氏）

Landis は、人間のエージェントと並んで AI エージェントを使えるコンタクトセンターを、Microsoft Teams 向けに提供する ISV です。Matt 氏が紹介した会社の概要は次のとおりです。

- 2014 年から Microsoft の顧客体験ソリューションを提供し、2021 年から Microsoft Teams の認定を取得
- 35 を超える国で、数千の顧客にサービスを提供
- 製品は 3 つ: Landis Contact Center for Microsoft Teams、interaction recording for Microsoft Teams、Landis attendant console for Microsoft Teams

**事例**: 人員の確保に苦労していたが、CD の金利や口座手数料といった一般的な質問を自動システムに任せることには消極的だった地域銀行（regional bank）が、Landis AI agent を試した。現在は通話の **30% をエンドツーエンドで処理**しており、より速く、24 時間対応できる。担当者は複雑で関係性が重要な会話に集中できる、と説明されています。Gartner が「2029 年までに agentic AI が一般的な顧客サービスの問題の 80% を自律的に解決する」と予測していることにも触れ、この銀行はすでにその道を進んでいると述べています。

**なぜ voice か**: 「チャットやテキストは多少のことを許してくれるが、音声は許してくれない」ため。さまざまなモデルを試す中で、次の 3 つの問題に直面したと述べています。

1. 割り込み（interruption）
2. 沈黙の検出（silence detection）と、AI エージェントの応答の遅さ
3. 処理中の中間応答と、全体としての自然なやり取り

Foundry Voice Agent のチームと協力して改善し、他のさまざまなソリューションを試した後に、新しい Foundry voice agent を使うと違いがすぐに分かったと述べています。

**構成**: 顧客が Landis contact center 経由で Microsoft Teams の音声に着信すると、Landis AI agent が Teams の音声メディアを Microsoft Foundry voice agent と相互に接続します。その際に使うのが、Teams phone extensibility と Azure Communication Services です。

Foundry voice agent によって、先の 3 つの問題が次のように解消したと説明されています。

- 呼び出し側が自然に割り込める
- エージェントは止まって聞くべきときに止まる
- 沈黙検出が、考えている間の間と、文の終わりを区別する

通話が Teams の外に出ないため、エスカレーションは、同じ通話の中で、コンテキストを持った人間の専門家へのハンドオフになります。Landis の CX エンジニアが、Teams の音声、顧客体験、AI 体験を組み合わせ、顧客自身の Azure 環境で Foundry のエージェントを設計・チューニングする支援もする、と述べています。

**顧客にもたらす 4 点**: (1) 人間のエージェントへのコンテキスト付きのシームレスなハンドオフ、(2) 人間と AI のやり取りを同じダッシュボードに表示する統一されたリアルタイム監視、(3) 人間でも AI でも 1 つの画面に集約される統一された履歴レポート、(4) リアルタイム監視と通話後のスコアリングによる継続的な改善。

### 5.10 顧客事例 2: ASUS（Marvin 氏）

Marvin 氏は ASUS Tech の立場で、コールセンター向けの AI エージェント「Voice Genio」（音声認識の表記。以下「Voice Genio」）を紹介しています。

**背景**: ASUS は世界的な PC 企業で、ユーザー基盤は 1 億人。コールセンターには 1 日に約 10 万件の電話がかかります。70 を超える国で、50 を超える言語で販売しているため、コールセンターの運営は複雑でコストも高く、そこで AI エージェントで品質と効率を高めたい、という動機です。

**経緯**: Voice Genio は、Microsoft Foundry を使ったカスタマーサポートのプロジェクトの第 4 世代です。

| 時期 | 内容 |
| --- | --- |
| 2023 年 | カスタマーサポート用のチャットボット（名称は音声では「Genium」）。70 を超える国で展開し、成功したと説明されている |
| 2024 年 | 製品情報、サービス照会、製品推薦などに答えられるよう拡張し、ブランドのチャットボットに |
| 昨年 | 音声コミュニケーションに挑戦し、「Store Avatar」を立ち上げ。店舗内の製品にソフトウェアを載せ、来店者がアバターに話しかけて製品について理解できる |
| 今年 | コールセンターに挑戦。今月から提供を開始し、今後 6 か月で 50 を超える国に展開する |

**従来のコールセンターの課題（4 点）**:

1. 離職率の高さ。AI エージェントなら 24 時間 365 日動き、この問題がない
2. 品質を監視しにくい。多くのコールセンターの記録がアナログの音声データだが、AI ならすべてデジタル化されるため、ほぼリアルタイムで品質を監視できる
3. アウトソーシングを制御しにくい。1 か国でサービスを開始できれば、多くの国に複製でき、内製で対応できる
4. 運用コストの高さ。人間のエージェントのコストは高く、AI でコストを削減できる

**技術的な課題（3 点）と、Foundry による解決**:

| 課題 | 解決 |
| --- | --- |
| リアルタイムのレイテンシ（2〜3 秒での応答を期待） | Microsoft のリアルタイムの speech-to-text API でレイテンシを大きく減らせた |
| 50 を超える言語への対応。国ごとの訛りや固有名詞、製品・ブランドの発音の違いがあり、高い認識率が必要 | 国ごとにモデルをファインチューニングできる柔軟性。英語圏の国同士でも訛りや名前、特定の語の発音が違う |
| 1 つの国で複数の言語が話される。会話の途中でも言語を切り替えたい | 自動言語検出（auto language detection） |

**デモ（通話の音声）**: 修理サポートに電話した顧客が、先週修理に出したノート PC の状況を確認する会話でした。エージェントが RMA 番号かシリアル番号を尋ね、顧客が RMA 番号を伝えると、製品が受領済みで診断ステージが完了している旨を回答しました。通話の最後に、満足度アンケートにつながるとの案内も流れました。Marvin 氏は、この顧客は台湾の方で、英語で話していても台湾なまりがあるが、モデルがそれを認識できていると説明しています。

**構成**:

1. 顧客が電話をかけると、コールセンターのゲートウェイが Voice Genio に引き渡す
2. Voice Genio は Microsoft Foundry を呼び出す。Foundry は voice agent のモニターなど、基盤となる重要な機能を提供する
3. ASUS はマルチエージェントのシステムを構築。master agent が意図を認識して会話全体を管理し、意図に応じて sub-agent に引き渡す
4. 3 つの sub-agent が、それぞれ異なる意図を担当する。各 sub-agent はナレッジ検索システムから回答を得て返し、master agent がそれをより会話的な内容にして TTS でユーザーに返す
5. AI が対応できないサービスだと判断した場合は、人間のエージェントに引き継ぐ
6. 会話の履歴とログを保持し、さらなる改善に使う

**展開計画**: 今月から数か国で開始し、第 1 波は英語圏の国。この 5 か国だけでも、5 つの異なるファインチューニング済みモデルを作る必要があります。次の四半期には 44 か国に展開し、最終的には対応できるすべての国に、回答できる内容を増やしながら広げていくとのことです。最終ゴールは「すべての顧客を、あらゆる言語で、いつでも、どこでも助ける」と述べています。

### 5.11 顧客事例 3: Leap Motor（Alex 氏とビデオ）

Alex 氏（Microsoft China Auto Team）は、車内の体験を紹介しています。Leap Motor は「中国で第 1 位の新エネルギー自動車のスタートアップ」と紹介されています（社名は音声では「Limoto」「LeapMotor」などと聞こえます）。

**CEO のビデオメッセージ**（氏名は聞き取れません）で語られた数字は次のとおりです。

- 年初からの 10 か月で 77 万 3,000 台を納車（前年比 66 と聞こえます。単位は聞き取りのままです）
- グローバルの販売網は 1,700 を超える拠点、50 を超える国
- Microsoft と、接続時もオフライン時も使える、自然な多言語の音声対話を検討している

**デモ**: 今年末に欧州市場で発売する量産車で録画された短いデモです。納車チームが少数言語に堪能でないため、ビデオでは録音済みの音声で音声対話を起動していると説明されています。ドライバーは 1 つの会話の中で、設定を切り替えずに任意の言語を話せます。映像の内容については、音声からはナビゲーションを開始する場面があること以外は確認できません。

**グローバルな車載音声の課題**: 同時に超えるべき「6 つの境界」として、「Languages, connectivity, understanding latency, knowledge, trust」と述べています（「understanding」と「latency」の区切りは音声認識の都合で確定できません）。言語、アクセント、コードスイッチを理解し、オンラインでもオフラインでも信頼でき、低レイテンシで本当の意図を捉え、ローカルな知識とライブ情報を持ち、地域のプライバシー、安全、コンプライアンスの要件を満たす必要がある、という内容です。

**ハイブリッド音声アーキテクチャ**: Microsoft の Voice AI が共通の基盤を提供します。構成要素は、グローバルな言語カバレッジ、リアルタイムの知能のための Foundry voice agent service、オフライン用の embedded speech、新鮮な知識のための Web IQ、グローバルなスケールとガバナンスのための Azure です。ドライバーの音声は、クラウドとエッジで並行して処理されます。

- クラウド: Foundry の voice agent がリアルタイムの speech-to-speech を提供し、Agent Service と Web IQ が推論、ツール、最新情報を加える
- 車両側: embedded speech とファインチューニングされたオンデバイスの SLM が、オフラインの認識、意図、ローカルスキルを処理する
- 両方の結果は車内で調停され、安全ポリシーが適用されたうえで、ローカルで実行される（車両制御、ナビゲーション、音楽、天気、AI チャット）

**従来との違い（3 点）**:

1. **多言語**: ドライバーは英語で話し始め、設定を変えずに任意の言語に切り替えられる。店名や地名を小さな言語で言うことが多い欧州で特に重要で、従来のシステムは苦手だが「ここではうまく動く」と説明されている
2. **自然なターンテイキング**: セマンティック VAD が意味を理解し、考えて間を置いても割り込まない。さらに dialogue rejection model が、同乗者が突然話しかけるなどの会話を無視する。そのため、話す、割り込む、会話に入る・外れるを、人と話すように行える
3. **マルチモーダル**: 車が駐車禁止の標識を見て、質問を理解し、エージェントが駐車場を探してナビゲーションを開始する

## 7. 注意点・発表者の気付き

- **モデルだけでは体験は決まらない。** Yiwen 氏は、モデルに加えて VAD などの設定を組み合わせて、テストと構成を重ねるよう促しています。
- **音声は難しい。** Matt 氏は、チャットは多少のことを許すが音声は許さないとし、割り込み、沈黙検出、応答の遅さ、中間応答を課題として挙げています。
- **ASUS の指摘**: 英語圏の国同士でも、訛りや名前、特定の語の発音が違うため、国ごとにファインチューニングが必要で、第 1 波の 5 か国でも 5 つのモデルを作ることになります。1 つの国で複数の言語が話される場合の言語切り替えも課題として挙げられています。
- **Leap Motor の指摘**: 車載の音声は、言語、接続性、レイテンシ、知識、信頼（プライバシー、安全、コンプライアンス）を同時に満たす必要があり、そのため、クラウドとエッジのハイブリッド構成を取っています。
- 一部の機能名（モデル名、電話連携の名称、「Azure development key」など）は、音声認識の都合で確定できません。
