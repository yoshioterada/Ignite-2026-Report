# BRK256 Video AI at scale with Microsoft Foundry and fal

## 1. はじめに

このセッションは、Microsoft Foundry で動画・画像・音声の生成モデルを使う方法と、新たに始まった fal（生成メディア向けの推論プラットフォーム）とのパートナーシップを紹介するものです。Foundry 側の登壇者がパートナーシップの狙いと顧客事例を話し、fal の共同創業者が 3 つのモデルファミリー（Kling、MiniMax H3、LTX）の特徴を解説します。後半では、Foundry 上でモデルをデプロイするデモと、画像編集から動画化までをつなぐワークフローのデモが行われます。

読み取れる要点は次の 3 つです。

- 動画生成のモデルは用途ごとに得意分野が異なるので、**複数のモデルを試して選ぶ**のが前提になる。
- fal のモデルは **米国内でホストされ**、Foundry の data zone ガバナンスの下で使える。
- 画像モデル（MAI Image 2.7）、動画モデル、LLM を組み合わせて、1 つのフローとして自動化できる。

なお、モデル名（MiniMax H3、H3 Turbo、H3 Max、LTX 2.5 Pro、Kling V3、MAI Image 2.7 など）は音声認識の書き起こしに基づいており、正確な綴りは音声からは確定できません。登壇者の発話から聞き取れた表記で書いています。

## 4. 発表者が伝えたいメッセージ

**「1 つのプラットフォームで、あらゆるモデルを選び、組み合わせて使う」** が全体の主張です。Naomi 氏は、モデルの選択肢（choice）に加えて、どの推論プロバイダーを使うかを選べることも Foundry に持ち込みたいと述べています。そのうえで、テキスト・推論・コードのモデルと、画像・音声・動画のモデルを組み合わせることで、新しいワークフローが開けると説明します。

Burkay 氏は、生成メディアの分野はモデルの種類が LLM に比べて約 10 倍多様だと述べます。画像生成、画像編集、動画生成、動画編集、3D、3D リギング、音声（効果音、text to speech、speech to text など）があり、企業の用途では複数のモデルを使うのが普通だという考えです。

## 5. 発表内容の詳細

### 5.1 Foundry の位置づけとマルチモーダル創作

Naomi 氏によると、Foundry では 11,000 以上のモデルにアクセスできます。数が多いだけでなく、ユースケースごとにどのモデルが得意かを見つけられることが重要だと説明します。共通の基盤として、セキュリティ制御、全デプロイメントを見渡すコントロールプレーン、Azure スタックの利点があります。fal のモデルもこの基盤で使えます。

ほかにも Hugging Face との提携によるオープンソースモデルや、クローズドなプロプライエタリモデルも揃っています。画像モデルは動画制作の出発点になることが多く、「手持ちの画像を動画で動かす」使い方が顧客に多い傾向だと述べています。

### 5.2 顧客事例（Alex 氏）

Alex 氏は、Foundry でマルチモーダル体験を出荷している 4 社を紹介しました。いずれも Microsoft が過去に公開した事例で、「公開後に状況やモデルが変わっている」と断っています。

| 顧客 | 内容 |
| ---- | ---- |
| HyperCinema（ニュージーランドのスタートアップ） | 来場者が主役になるショーを、入場した瞬間にリアルタイム生成する。最初の展示「Enter the Multiverse」はオークランドの百貨店で実施。顔スキャンと短い性格診断のあと、最短 5 分で、画像と 30〜45 秒の動画を含む個別のストーリーが届く。事例公開時点で 1 日 5 万枚の画像と 6,000 本の動画を完全自動で生成。最初の米国顧客は 2024 年 8 月に 15 のタッチポイント（うち 2 つが動画体験）で稼働 |
| WPP（代理店 TNPM） | 初期の提案段階で、ストック画像や粗い絵コンテのせいで案が通らない問題があった。Foundry の API で、キャンペーンをアニメーション動画として早期にプレビジュアライズできるようになった。ドッグフードのブランドでは、飼い主が写真とストーリーを投稿すると、自分のペットが主役の動画になる。お米（rice）のブランドでは、ブランドガイドラインから、モデルがプロンプトを書き、レシピ・ターゲット・言語・プラットフォームごとの動画をバッチ生成する |
| Pixel Lab（シアトルのスタジオ） | Coldplay のアルバム「Moon Music」のビジュアルキャンペーンとして、ファンがリミックスできる体験を制作。映像は世界中のアーティストの 151 本のクリップで構成。全クリップを Azure AI Video Indexer にかけ、モデルで各シーンをテキスト化して、意味と感情で検索できるようにした。ファンが入力した気持ちを、ムードリングの仕組みで色と感情に対応づけ、パーソナライズされた動画リミックスをリアルタイムに組み立てる。同じリミックスは 2 つとない |
| CoStar Group | Homes.com（月間 1 億人超の訪問者）の検索を、フィルタ操作ではなくエージェントと話す感覚にするため、リアルタイムの音声検索を構築。会話のように感じられる低遅延が条件。real-time API の音声モデルと Mistral 3B（いずれも Foundry）を組み合わせた。開発チームは速度を「信じられないほど」と評し、ユーザーは回答の途中で割り込める |

WPP の事例で、提供された動画モデルの名前は音声認識で「Sor」と書き起こされており、確定できません。Stuart Ford 氏の言葉として、「ボタンを押して離れて、戻ってくると 5 本の新しい動画ができている」という発言が紹介されています。

Alex 氏は、Pixel Lab の事例を「動画を大規模に理解し、それを再び組み合わせる、逆方向のマルチモーダル」と位置づけています。

### 5.3 fal の紹介（Burkay 氏との対談）

Naomi 氏によると、fal は 2021 年に創業され、パートナーシップは「今月の初め」に発表されたと話しています。Burkay 氏の説明は次のとおりです。

- fal は **生成メディアの推論プラットフォーム**。約 3 年前に「generative media」という言葉を作った。当時は Stable Diffusion や DALL-E くらいしかモデルが無く、同社は汎用の機械学習モデルを動かしていた。
- LLM は推論や知能の未来を約束するが、インターネットで消費されるものの大半は視覚的なので、画像モデルも LLM と同じ軌道をたどると考え、画像モデルに注力した。
- 強みは、モデルを非常に高速に動かすことと、多様なユースケースに対応すること。顧客の業種はメディア・エンターテインメント、デザイン・生産性、EC、広告など。
- 最初はおもちゃのように見えた技術が、いまはコンテンツ制作の全体を生成メディアへ切り替える企業が出ている。

**イントロ動画**で語られた内容は次のとおりです。

- 単一の API で 1,000 以上のプロダクション向けモデルにアクセスできる。
- 独自の推論エンジンで、生成を最大 10 倍高速にする。
- モデルギャラリー、複数モデルを組み合わせるワークフロー、fal のサンドボックス（価格・速度・出力の並べて比較）がある。
- 新モデルが出たら追加の統合作業なしにすぐ使える。
- ユースケースとして、広告、EC（商品画像、バーチャル試着）、クリエイター向けの編集・アップスケール・リスタイル。
- エンタープライズ向けにプライバシー、継続的なセキュリティ監視、集中的なユーザー管理がある。
- 最大 10 倍の高速推論、99.99% のアップタイム、エンタープライズサポート。

### 5.4 fal on Foundry の 3 つのモデルファミリー

Foundry に載っているのは、次の 3 つのファミリーです。

**Kling（クローズドソース）。** プロ品質の高級な動画モデルです。バリアントは Pro、Standard、Turbo の 3 つ。

| バリアント | 特徴 |
| ---- | ---- |
| Turbo | はるかに高速だが、品質はやや落ちる。ドラフトや大量・低コスト向け |
| Standard | 中間の品質 |
| Pro | 2K 出力で、4K へのアップスケールも可能。物理表現や一貫性に優れ、プロ品質。Super Bowl のような広告にも使える水準という例えが出た |

**MiniMax H3（オープンソース）。** Burkay 氏によると、企業はロックインが少なくカスタマイズしやすいオープンソースを好む傾向があります。このモデルは当初あまり注目されていなかったものの、fal のリサーチ・エンジニアリングチームが調べて、非常に強力だと分かったそうです。大きなモデルで、多くの計算量とデータで学習されているため、ベースモデルとして活用の余地（研究用語で capacity）が大きいと説明します。

- キーフレームのサポートや、参照の与え方など、新しい機能を追加するポストトレーニングができる。
- 独自の IP（キャラクターなど）をポストトレーニングで細部まで扱えるようにできる。
- fal 側で高速化した。品質は Kling に迫るが、速度は約 20 倍。大量・低遅延のユースケースに向く。
- 数秒で再生成できるので、クリエイターが「フロー状態」で試行錯誤できる。

**LTX（オープンモデル）。** 品質に加えて、特に**制御性**を重視したモデルです。VFX スタジオや大手映画スタジオを主なターゲットとし、モデルを分解して自社のワークフローの一部に組み込めます。「1 回の出力でそこそこの結果を得る」ものではなく、高度なツールとして使うものだと位置づけています。

Naomi 氏は、クローズドとオープン、速いものと深く統合できるものがあるのが「モデル選択」の意味だと整理しています。

### 5.5 生成サンプルと、価格・速度・ホスティング

Naomi 氏と Burkay 氏は、各モデルで生成した動画を上映しながら話しました。画面の映像は音声からは分かりません。語られた内容は次のとおりです。

1. **MiniMax H3 Turbo**: ハイエンドのファッション編集写真の撮影風。2 秒の動画で、半年前は 2 秒の動画に 1 分近くかかっていたものが大幅に速くなった。この速度は、ジャストインタイム広告、「エージェンティックなコンテンツ」（数千本を生成して効果を見る、ハイパーパーソナライズ）につながる。
2. **Kling**: 光と影を生かした映画的なカット。VFX（リアルな爆発など）が得意。
3. **MiniMax H3 Max**: Burkay 氏が強く推奨するモデル。約 3 秒で生成され、以前は 2 分ほどかかった品質。**音声も出力する**ため、聞こえた会話はモデルが生成したもの。人の会話、表情、感情、物理表現に強い。複数シーンを記述するとシーン遷移も処理する。ユーザーからは見えないが、fal 側でプロンプトを詳細なものに強化（prompt enhancement）している。
4. **LTX Pro**: 接写の、層になった詳細な映像。レイヤーごとに定義でき、動きを正確に指定でき、3D モデルも入力できる。1 発出しではなくプロ向け。

**価格感**（Burkay 氏の発言）:

| モデル | 1 秒あたりの目安 |
| ---- | ---- |
| H3 Turbo | 1 セント未満 |
| Kling | 数十セント |
| 高価格帯の一部 | 最大で 1 ドル/秒に達することも |

それでも、VFX や CG で実際に作るのに比べると 100 倍から 1,000 倍安い、と述べています。

**米国ホスティング。** Kling と Microsoft、fal の連携の一環として、ここで見たものは**米国でホストされ、fal と Foundry のインフラ上で動いている**と説明されました。企業は機密データ、IP、プロンプトやワークフローを守るため、米国ホストを求める傾向があり、顧客の需要がこの取り組みを実現させたそうです。今後対象モデルを増やしたいとも述べています。

**ファインチューニング。** オープンな重みを使う目的は、(1) 新しい機能の追加、(2) 自社 IP への対応の 2 つが、企業から見える主なユースケースだと説明しています。

### 5.6 動画モデルの選び方

Burkay 氏の助言は、**すべて試す**ことです。LLM はベンチマークがあり、ある程度信頼できる一方、動画では「好み（taste）」が非常に重要です。同じプロンプトをすべてのモデルに投げて出力を比べると、どのモデルの動きや物理表現が好みかがすぐ分かる、という説明です。

### 5.9 ワークフローの例（Lovis 氏）

Lovis 氏は「プロの現場でプロンプトだけに頼ることは少なくなった」とし、次の 2 例を示しました。

**(1) 安全研修の動画化。** 「安全と頭部保護」についてのテキストを素材にします。

1. テキストを LLM に渡し、画像生成用と動画生成用のプロンプトを作らせる。
2. MAI Image で画像を生成する。
3. 画像を H3 Max に渡して動画化する。

Lovis 氏は、流れは複雑に見えても単純で、研修が多い企業なら Foundry API で完全自動にできると述べています。

**(2) 製品（車）の広告。** MAI Image で約 100 枚の画像を作り、気に入ったものを使ったという説明です。

- プロンプトだけでなく、鉛筆スケッチ、カラーパレット、ムードなど複数の参照を与えられる。
- 9:16 など、さまざまなサイズを一度に生成できる。テキストは単純な切り抜きではなく、画像を理解して各フォーマットに合わせて整えられ、文字の一貫性も保たれる。
- 「韓国語に」「中国語に」と指示するだけで、テキストと広告を各言語に適応させられる。ロケーションに合わせた画像のローカライズも可能。
- 生成した画像を、画像から動画へ変換して、パーソナライズ可能な広告にする。

Lovis 氏は、ここで見せたのは小さなパイプラインで、3D モデルを加えたり、生成を増やしたり、長い映像にしたりして、もっと大きくできるとも述べています。

動画モデルの比較としては、Kling V3 は遅いが高品質、LTX 2.5 Pro は動きの制御に強く、H3 Max は両者の特徴を併せ持ち、fal 側の最適化で速い（2〜3 秒、Kling V3 はそれより長め）と説明されました。

## 6. デモ・手順

このセッションは**デモがあります**。録音は音声のみのため、画面の細部（ボタン名など）は確認できません。以下は発話で語られた範囲です。

### 6.1 Foundry での fal モデルのデプロイ（Alex 氏）

1. Foundry のプロジェクトを開く。ここには MAI Image 2.7 の新しいモデルや、fal のモデルが並ぶ。
2. LTX 2.5 Pro のモデルカードから、デプロイメントを作成する。
3. 初回は、サブスクリプションの同意（opt-in）が必要。Azure portal で「fal enable deploy feature」（聞き取った表記）を検索し、サブスクリプションで有効にする。数秒で済む。
4. 有効化後は、他のモデルと同じようにデプロイできる。このデモでは作成済みのデプロイメントを使った。
5. プロンプトを入力する。内容は、「白く洗練された電気列車が、黄金色の夕方に、緑豊かな近代都市の湾曲した橋を滑るように走り、カメラが並走し、窓に反射が流れ、川から鳥が飛び立つ。シネマティックでフォトリアル」といったもの（音声から日本語で要約）。
6. LTX 2.5 Pro で動画を生成する（デモのために時間を短縮している）。
7. Foundry ポータル内に動画が生成される。コードも確認でき、アプリケーションに埋め込める。

### 6.2 画像編集と動画化（Alex 氏が操作、Lovis 氏と掛け合い）

1. Lovis 氏の画像を使い、MAI Image 2.7 のデプロイメントで、ジャケットの色を変えるプロンプトを与える。
2. Lovis 氏の希望で、デニムのジャケットに変える。
3. 編集した画像を、fal on Foundry の LTX 2.5 Pro に渡してアニメーション化する。

画像から画像、画像から動画の 2 つのモデルを使うフローだと確認しています。

### 6.3 画像編集と動画化（Lovis 氏が操作）

1. Alex 氏の画像をアップロードし、帽子を追加する。繰り返し編集しても一貫性が保てる。
2. 編集を重ねる。眼鏡についての会話もあったが、眼鏡を追加したのか元からあったのかは発話からは分からない。
3. API で、照明や環境、スタイルを、属性ごとに段階的に変え、最終的に「パリにいる」画像にする（編集は MAI Image 2.7）。
4. その画像を H3 Max でアニメーション化する。

登壇者は、紹介したモデルはすべて Foundry で使えると述べています。まとめでは、見せたモデルとして MAI Image、LTX 2.5、H3 Max、Kling、そして LLM 部分の GPT を挙げ、「1 つのプラットフォームで全モデルを使い、組み合わせられる」と話しました。

### 6.4 ワークフロー（Lovis 氏）

5.9 のとおり、安全研修の動画化と車の広告のフローを、画面を見せながら説明しました。

## 7. 注意点・発表者の気付き

- **動画モデルはベンチマークより好みが重要**なので、同じプロンプトで全モデルを試す。
- 高品質なモデルは高価です（数十セントから最大 1 ドル/秒）。一方で Turbo 系は 1 セント未満と、価格の幅が大きい。
- fal のモデルを初めて使う場合は、**サブスクリプションの有効化が必要**。
- 速いモデルは品質が下がる場合がある。Kling の Turbo は品質がやや落ち、MiniMax H3 の品質は Kling に「ほぼ匹敵する（almost as good）」という言い方だった。
- LTX はワンショットで使うものではなく、プロ向けのツールとして位置づけられている。
- 登壇者は、コンテンツセーフティのガードレールについて話せなかったと述べています（時間切れ）。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **選択肢**: Foundry に fal の複数モデル（クローズド・オープン）が加わり、用途に応じて選べる。
- **速度**: H3 Max は 3 秒前後で生成できる。以前は 2 分ほどかかったという説明。H3 は Kling より約 20 倍速い。
- **コスト**: VFX や CG で作る場合に比べ、100〜1,000 倍安い。
- **データの扱い**: 米国でホストされ、Foundry の data zone ガバナンスと安全プロファイルが使える。
- **カスタマイズ**: オープンモデルで、新機能の追加や自社 IP の対応ができる。
- **統合**: 画像、動画、LLM を 1 つの Foundry で組み合わせ、API で自動化できる。
- **事例の成果**: HyperCinema の 1 日 5 万枚の画像と 6,000 本の動画の自動生成、WPP の早期プレビジュアライズなど。

## 9. まとめ

Foundry は 11,000 以上のモデルに加え、fal のモデル（Kling、MiniMax H3、LTX）を提供し、動画・画像・音声の生成を同じ基盤で扱えるようにします。Kling は高品質、H3 は速度とカスタマイズ、LTX は制御性に強みがあり、選ぶには同じプロンプトですべて試すのが推奨です。デモでは、Foundry でのデプロイと、MAI Image 2.7 で編集した画像を動画へ変えるフローが示されました。

fal のモデルは米国でホストされ、Foundry の data zone ガバナンスの下で使えます。Naomi 氏は最後に、使いたいモデルを選び、デモで見た機能を試し、創作の実験だけでなく本番利用に進めるよう呼びかけています。
