# THR867 Turn a team conversation into a pull request

## 1. はじめに

このセッションは、チームのチャット（Slack と Microsoft Teams）の中で GitHub Copilot に作業を頼み、会話の文脈をそのまま使ってプルリクエストまで進める働き方を見せる、約 25 分のシアター形式の発表です。2 人の登壇者が、実際に自分たちが日常で使っている Slack と Teams の環境を使い、ほぼデモだけで構成されています。

内容は 3 つに分かれます。1 つ目は、各自が個人のプロジェクトでチャットから GitHub Copilot を使う様子、2 つ目は、チームで共同作業する様子、3 つ目は、Work IQ のコネクタを使って、GitHub と Microsoft 365 にまたがる文脈をチャットに戻す様子です。狙いは、チャットと開発ツールの間の手作業の受け渡しと、画面の切り替えを減らすことです。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/THR867](https://ignite.microsoft.com/en-US/sessions/THR867)

## 3. 何に関する発表か

GitHub Copilot は、好みの開発ツールの中で使えるのと同様に、チームのチャットアプリの中でも使えます。発表では、チャットアプリ上の GitHub Copilot を実際の環境で見せています。扱う要素は、Slack と Teams の GitHub アプリ（エージェント）、Slack のコードチャンネル、GitHub のクラウドエージェント、GitHub Copilot アプリ、そして Work IQ のコネクタです。

発表の流れは次のとおりです。

1. 動機：チャットとツールの間のコンテキストスイッチを減らす
2. 題材のアプリの紹介（Tiny Clips、フィットネスアプリなど）
3. Megan 氏の Slack でのデモ
4. 裏側の仕組み（GitHub のクラウドエージェント）
5. James 氏の Teams でのデモ（チャネル、チャット、会議）
6. Work IQ と GitHub Copilot のコネクタによる、Microsoft 365 の文脈の活用
7. 自動化と、試すための案内

## 4. 発表者が伝えたいメッセージ

担当者が同僚から「顧客がバグを報告した」と聞き、エラーメッセージをコピーして AI クライアントに貼り付け、追加の文脈を足してまた貼る、という作業は多くの人が経験します。発表者は、この手作業の受け渡しで文脈が失われることを問題として挙げ、仕事をしている場所、文脈がある場所で、ユーザーを迎えに行くことを目指していると説明します。ウィンドウの切り替え、頭の切り替え、認知的な負荷を減らして、管理することを 1 つ減らすのが狙いです。

終盤には、一度に多くの場所で多くのことができると見せたが、すでに自分たちはそうした複数のウィンドウを行き来しているのであり、その移動を減らして 1 か所に集約することが目標だ、と述べています。IDE、Teams、Slack、電話のどこにいても、シームレスにつながるという主張です。

## 5. 発表内容の詳細

### 5.1 題材のアプリ

デモで登場するアプリが先に紹介されました。

- **Tiny Clips**（James 氏）：Mac と Windows 向けの、スクリーンショットや動画を撮るアプリです。フルのスタジオ制作モードとエージェントモードの統合があり、編集機能で、グラデーションの背景、余白、角の丸み、大きな赤い矢印や絵文字などを加えられます。アプリストアに公開されている実在のアプリで、社内でデモを作るために複数人で共同開発しています。
- **フィットネスのトラッキングアプリ**（Megan 氏）：近くのフィットネスクラスを検索して申し込み、今後の予定や履歴を見られます。

### 5.2 Slack でのデモ（Megan 氏）

Megan 氏は、画面に映るのはアプリですが、操作しているのは Slack だと説明します。Slack のコードチャンネルで GitHub Copilot とやり取りしてアプリの修正を頼み、チームメンバーも会話に加わって、アプリの見た目について意見を出しています。

登壇の直前に、アプリ全体を「レトロなゲーム風」に作り直すよう頼み、会場へ歩く途中で依頼して、到着したときにはレビューの段階になっていたそうです。James 氏が会話に入って「緑は好きではないので、ホットピンクなどにできないか」と言うこともできる、という例えも語られました。Megan 氏の端末から James 氏の端末へ移って文脈を失うことがなく、共同で作業できるという説明です。

**コードチャンネル**は、通常のチャンネルと違い、エージェントにチャンネルの操作権限が多く与えられます。そのため、HTML を描画するキャンバスを開いたり、コードの差分を表示したりできます。チームメンバーにタグ付けしてレビューを頼み、小さな変更ならその場で見て確認できます。GitHub への直接のリンクなどのメタデータもあり、プルリクエストを開く、ブランチを見る、使うモデルを確認して変更する、といったことも Slack の中でできます。

### 5.3 権限と、チャンネルの共同作業

Megan 氏は X で James 氏が投稿した本セッションの予告を見かけました。その Tiny Clips のスクリーンショットで、スクロールキャプチャのときに新着メッセージのポップアップが消えずにノイズになっている問題が取り上げられました。Megan 氏が GitHub に修正を頼むと、リポジトリへの権限が足りないという応答が返りました。James 氏からの招待を受け入れていなかったためです。James 氏が代わりに修正を開始できます。

> 補足：これは **GitHub の権限に従う**ことを示す例として説明されました。Slack の中で権限が上がることはなく、そのユーザーが何にアクセスできるかが確認されます。

もう 1 つの例として、Web サイトのプロトタイプを共同で進めたチャンネルが示されました。プロトタイプを表示し、注釈が付く様子が見られ、Megan 氏が「問題ないので PR を開いて」と頼み、別のチャンネルで実行されました。デザイナーやプロダクトマネージャーなど、リポジトリにアクセスできない人も、依頼を始めて進捗のスレッドを見られます。100 人のチャンネルでも、全員が操作権限を持つわけではない、という点が強調されました。

### 5.4 裏側の仕組みと、セッションの見え方

裏側では **GitHub のクラウドエージェント**のプラットフォームが使われています。GitHub Copilot はどの接点でも使え、ここでは GitHub のクラウド環境のサンドボックス内で動いています。アクセス範囲や、エンタープライズのポリシーに従うかなど、多くの制御を設定できます。VS Code、GitHub Copilot、CLI アプリで使われているのと同じハーネスです。

DM で進めたセッションは GitHub 上だけでなく、GitHub Copilot アプリ、github.com の Copilot の画面、VS Code にも表示されます。

### 5.6 Teams の会議・チャットで同僚と一緒に使う

James 氏は Megan 氏に、リアルタイムで通話をかけます。このバグは以前 James 氏が起票したもので、Tiny Clips はエージェントから Copilot などに接続でき、動画や画面を撮影できます。ところが、カメラのオン、オフを切り替えられず、オンになっていてもオフにできません。プライバシーとセキュリティの観点から、オフにする能力を与えたい、という内容です。2 人で同意し、GitHub を呼び出して依頼します。

GitHub は、チャットのメンバー 2 人が参加する場に、「エージェントとアプリの追加」から加えられ、会議、チャットなどあらゆる場所に Copilot と GitHub を追加できます。James 氏はこの具体的なイシューを伝えておらず、チャットの文脈から把握されている点が強調されました。権限を与えているからできることです。

その後、キャンバスが開き、セッションが起動して、計画、変更、プルリクエストを確認できます（James 氏は、これがパブリックプレビューだと思う、と述べています）。Tiny Clips のチャットに戻ると、マージされていました。

最後に、VS Code の画面と、Teams の通常のチャットが並べて示されました。GitHub Copilot アプリからは、このリモートのクラウドセッションに接続できます。電話、Slack、Teams のどこからでも開始でき、進行を監視でき、ある場所で始めて別の場所で続きができる、と説明されています。

### 5.7 Work IQ と GitHub Copilot のコネクタ

チャットだけでなく、メールやドキュメントなど他の場所にも文脈があります。ここで GitHub Copilot と Work IQ、それに Slack コネクタなどの連携が重要になる、という流れです。Work IQ は、コミュニケーション、コンテンツ、人、業務データなどの仕事のシグナルを 1 つの層にまとめ、データを集めるだけでなく、アクションも実行できます。

セットアップは簡単で、VS Code または Copilot アプリにはコネクタがあり、GitHub Universe で認証を簡素化するために公開されたものだと説明されました。コネクタは「どこにでもついてくる」性質があり、Slack コネクタや Work IQ コネクタをクラウドまたはアプリで設定すると、Slack で GitHub と DM をしているときにも同じアクセスが使えます。

コネクタの使い方として、次の点が語られました。1 つ目と 2 つ目、4 つ目は Megan 氏の発言です。3 つ目は、発話から話者を特定できません。

- GitHub Copilot アプリで、自分のメール、ドキュメント、Slack、GitHub の PR を見て、今日いちばん重要な作業を聞く。そのうえで、完了させる、バグを調査する、顧客データを見るといった作業も実行させる。
- Azure のデータウェアハウスのコネクタで顧客データを取得し、「この機能を使っている人はどれくらいか」といった質問を、エージェントを使っている場所で聞く。
- 会議の文字起こし、メールなど、GitHub と Copilot を会話に追加し忘れた場所の情報や、後から必要になった情報を取り込む。メールや Teams で要約を投稿するなどの操作もできる。
- 特にお気に入りは、Teams 会議の文字起こしです。「誰がこれを言ったか」「いつこの決定をしたか」をエージェントに聞ける。

コネクタは、VS Code、CLI、GitHub Copilot アプリ、github.com のカスタマイズのタブに Work IQ として表示され、Slack もコネクタとして並びます。

### 5.8 Work IQ のデモ（James 氏）

1. Tiny Clips のプロジェクトで、Teams と Slack などをつなげ、Tiny Clips の Teams チャットでバグや機能要望を集めて、リポジトリと比較し、最後に新しい情報を Teams に投稿するよう頼む。フィードバック用のチャンネルがあれば同様に使える。実際の仕事用アカウントなので、画面の一部は隠している、と説明された。
2. 次に、翌日の複数のセッションで使うモバイルアプリ **Theater Log** の例を示す。James 氏と同僚が映画を見るために作ったアプリで、複数のリポジトリにまたがる。デザイン会議、Word の文書、Teams の文字起こし、仕事の情報から、やりたい改善のリストを Copilot アプリと Work IQ で集めて作った。
3. James 氏はそのリストを実装したが、レビューは誰にもしてもらっていない（本人の言葉では YOLO）。そこで「大きな更新をして、PR が多く、チーム通話や議論もあった。ウィッシュリストの項目について、Work IQ、Word の文書、GitHub のすべての情報をまとめて、出来栄えのレポートを作ってほしい」と依頼した。
4. エージェントが Work IQ を呼び出し、文字起こしを取得し、ソースコードを含めてすべて読み込み、推奨事項を含むレビューをまとめる。新しい PR も作り、Teams の Theater Log のチャットにメッセージも投稿した。
5. 最後の工程として、James 氏は、作業が終わったら「これを自動化にして」と頼み、2 日（48 時間）ごとに起動する自動化にして、自分で確認しなくて済むようにする、と説明しました。Copilot アプリ、Teams、Slack、Work IQ をつなげ、継続的に文脈を集めて報告する使い方です。実際にその設定を操作する様子は、発話では確認できません。

デモは 5.2 から 5.8 のとおりです。録音は音声のみなので、画面の細部（ボタン名、入力欄の配置など）は確認できません。要点だけを順に整理します。

## 7. 注意点・発表者の気付き

- チャットから使っても、GitHub のリポジトリ権限に従います。権限がなければ依頼は進まず、権限のある人が代わりに開始できます。
- リポジトリにアクセスできない人も、依頼を開始してスレッドで進捗を見られます。ただし、操作を制御できるとは限りません。
- 実環境でのデモのため、発表者自身が「少し怖い」と述べています。
- クラウドエージェントは GitHub のクラウド環境のサンドボックスで動き、アクセス範囲やエンタープライズポリシーの適用などを設定できます。
- キャンバスのセッション表示は、デモ用の Wi-Fi の上で動かしていると James 氏が述べています。キャンバスがパブリックプレビューかどうかは、本人が「そう思う」と述べている程度で、正式な提供状況は発話では確認できません。
- Theater Log の例は、レビューなしで実装した後に、Work IQ を使ってレビューのレポートを作る、という流れでした。

## 9. まとめ

GitHub Copilot は、Slack と Teams の中でも、チャンネル、チャット、会議のどこからでも使え、GitHub の権限に従ったままプルリクエストまで進められます。裏側は GitHub のクラウドエージェントで、セッションは GitHub Copilot アプリ、github.com、VS Code にも表示されます。

さらに Work IQ や Slack のコネクタを使うと、メール、文書、会議の文字起こしなどの文脈を取り込み、レポートの作成、PR の作成、Teams への投稿、定期的な自動化まで進められます。まずは GitHub アプリを Slack または Teams に入れ、チャンネルで頼んでみる、というのが発表者の案内でした。
