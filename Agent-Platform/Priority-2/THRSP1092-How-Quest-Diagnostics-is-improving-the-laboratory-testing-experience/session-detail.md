## 5. 発表内容の詳細

### 5.1 Project Nova の概要

Project Nova は、Quest が進める複数年の変革・近代化の取り組みです。患者の登録から結果を見るまでの 6 つの場面を対象にしています。発表者が特に重視した場面は、結果と請求です。支払う金額をできるだけ少なくしたい、何に払っているのかを明確に理解したいという患者の関心が、そこに集まるためです。

もう 1 つの特徴は「EHR（電子カルテ）に依存しない」ことです。クリニックはすでに多くのシステムを使っているため、何も作り直させず、変更もさせず、現在の環境のまま接続できるようにする、という方針です。

### 5.2 開発パートナーによる AI 活用の 3 つの取り組み

Neeraj は、自社が Quest と一緒に AI を使って開発の進め方を作り直していると話し、3 つの手法を挙げました。

| 取り組み | 発話で語られた内容 |
| --- | --- |
| 開発工程全体での AI 活用 | 開発者がコードの書き方、テスト、開発工程全体で AI を使い、各時点で成功を測定する |
| モダナイゼーション | 変革の規模に耐えるよう、すべてのアプリケーションをすばやく拡張できる状態にする。基盤を最初から組み込む |
| 品質 | ガードレールを作り、品質を測定し、成功を数値化してから次に進む |

試行から始め、各時点で成功を測り、品質を確保して進めるという順序が説明されています。

### 5.3 仮想の患者 Linda と、背後の複雑さ

Ravi は、仮想の人物 Linda を使って説明しました。Linda は複数の実在の患者を合成した人物で、毎日数百万人を検査する Quest のネットワークでは日常的に見かける患者像だと説明されました。54 歳です。医師が脂質検査と A1C を勧め、医師の診療所は EHR から電子オーダーを Quest の検査室へ送ります。Linda は生活のほとんどをスマートフォンで行い、結果について「これはどういう意味か」という疑問を持ちます。

患者から見た 6 段階の旅はシンプルで途切れなく見えますが、背後には内部と外部の多数のシステムが絡み合っています。Quest が目指す方向は 3 点です。従業員には直感的で効率の良いシステムを提供して摩擦をなくし、その従業員が消費者に最良の体験を届けられるようにすること。運用では、ボトルネックを取り除き、効率を高めて、継続的なイノベーションの道を空けること。検査室は毎日のように改善と自動化を進めており、これは不足を補うためではなく、効率を高め続けるための取り組みだと説明されています。

それでも改善を続ける理由は、患者に結果を待たせて不安にさせたくないからで、できるだけ分かりやすく、洞察のある情報を届けたいという考えです。

### 5.4 4 つの外部要因

注文から入金までの多数のシステムに加え、次の 4 つの力が同時に影響していると説明されました。

1. **消費者の期待の上昇**：AI の普及もあり、誰もがスマートフォンで生活しており、ノート PC すら使いたくない人もいる
2. **臨床的な洞察の高速化**：医師が診療の時点で、電子的に結果を受け取ることを期待している
3. **データの急増**：検査件数は毎日数百万件で、増え続けている。デバイスの多様化でデータはさらに増える
4. **信頼と規制への対応**：HIPAA などの規制遵守に加え、AI に対する信頼と監視の目が厳しくなっている

これらは Linda の旅のうち、特に結果と請求に影響します。

### 5.5 4 層の基盤アーキテクチャ

4 つの力に対応するため、Quest は 4 層の基盤アーキテクチャを作っています。

| 層 | 役割 |
| --- | --- |
| 最下層：弾力性 | クラウドの容量と、動的に拡張できる計算能力を活用し、検査件数の増加に対応する。この部分はすでに対応済みと説明されている |
| API とデータの層 | 統合基盤を構築済み。企業全体のデータ基盤を統一し、ほぼリアルタイムに、患者・パートナー・医療提供者が 1 つの正しい情報源にアクセスできるようにする。臨床連携と相互運用のため、HL7 や FHIR などの標準仕様の API を整備する |
| ガバナンスされた AI の層 | 信頼の課題に対応する層。バイアスなどへの懸念があるため（発話にはもう 1 語ありますが、聞き取りが不明瞭で確定できません）、多数のガードレールと管理を設ける。そのうえで高度なモデルや AI・機械学習のアルゴリズムを展開し、より良い洞察を提供する |
| 最上位：体験の層 | 患者や外部ユーザーが直接触れる層。リアルタイムの情報をモバイル中心で届ける。パートナーや医療提供者が、安全な API を使って情報をリアルタイムに取り込めるようにする |

この構成により、速度・セキュリティ・コンプライアンスのいずれも犠牲にせず、近道を取らずに戦略的に進められる、という説明です。

発表者は、この週ずっと語られてきたとおり、脆弱性が毎日見つかり、脅威アクターが組織を狙っていると触れました。同業の仲間と話すと、従業員の約 50% が脆弱性の修正や攻撃からの保護に当たっているという話が出る、とも述べています。だからこそ AI については、結果と速度、信頼、情報の届け方を、安全で責任ある形で管理することに力を入れていると続けました。

### 5.6 AI が行うことと行わないこと

Linda が9 時ごろに、ポータルとモバイルで結果を受け取る場面が例に使われました。同じ結果は医師にも届きますが、医師がすぐ連絡するとは限りません。Linda は結果を見て、意味が完全には分からず、不安になります。そこで AI が次のことを行います。

* 医療用語を平易な言葉で説明する。例えばコレステロール値が高いのか低いのか中程度なのかを、範囲の意味とともに示す
* 過去の情報と最新の結果をもとに、Linda が医師に尋ねるとよい質問を提案する
* さらに質問や相談があるときは、適切な担当者に振り分ける

一方で AI が**行わない**ことも明確に語られました。

* 結果の解釈や診断はしない
* 基幹システムが出した結果を変更したり、止めたりしない
* 医師の判断に代わらない。診断の権限は、認定された医師に残る
* 予測や検出もしない

発表者は、患者に害を与えかねないことには踏み込まず、慎重で保守的に進めると述べています。これを支えるのが、4 つの要素から成るガバナンス層です。プライバシーとセキュリティ、ガバナンス、人が関与する仕組み（ヒューマン・イン・ザ・ループ）が挙げられました。なお 4 つ目の要素は、発話では確認できません。

### 5.7 Linda の新しい体験

同じ Linda、同じ検査で、体験がどう変わるかが説明されました（発表者は、実際の画面ではなくイメージ図だと断っています）。

1. Linda はスマートフォンで予約を取る
2. 患者サービスセンターで検体を提供する。情報を再入力せず、到着を伝えるだけで済む
3. 採血担当者は、安全な電子形式の情報をすでに持っており、準備が整っている
4. Linda は数分で、摩擦なく退出する
5. 翌日の木曜日に、結果の通知を受け取る。平易な言葉による説明が付くが、診断ではなく、結果の意味の説明である
6. 結果は医師にも届いているため、Linda は安心して医師と話せる

注文から入金まで、医師・患者・パートナーのいずれから見ても 1 つの流れに見え、3 か所を回って情報を集める必要がなく、すべてが 1 か所でつながるのが狙いです。

### 5.8 得られた教訓

Ravi が挙げた教訓は 4 つです。

1. 技術だけを考えて変革を進めない。決定は、顧客や患者の体験を良くし、単純にすることにつながるものにする
2. サイロ化したソリューションではなく、プラットフォームを作る。AI の時代にはさらに重要になる
3. 早くからガバナンスを整え、採用を速める。整っていれば、開発者は自信を持って速く進める
4. パートナーと組んで規模を拡大する。1 社だけで進めると遅くなる

### 5.9 Microsoft 側から見た協業

Stephanie は、Quest、（発話どおり）HCL Tech、Microsoft が、検査を速く、安全に、より個人に合ったものにするという 1 つの目標で協力していると述べ、3 点を挙げました。

| 観点 | 語られた内容 |
| --- | --- |
| 速さ（基盤） | Quest は Azure で Epic の環境を動かすことを選んだ。これは世界で最大の単一の Epic 環境になる。2,000 を超える検査室にわたる Project Nova のデジタル基盤であり、Epic と Microsoft が 1 つのクラウドで、ミッションクリティカルな支援を提供する |
| 安全性 | 検査結果は医療で最も機微なデータの 1 つ。Entra がゼロトラストの ID を、Purview が患者と検査のデータの保護を担う。AI の拡大にあたり、Agent 365 が Quest の構築・購入するすべてのエージェントを 1 か所で管理する |
| 患者体験 | Copilot Studio のエージェントが、検査室のチームが 1 日中受けている質問（検査コード、採血管の選択、検体の状況）に答える |

### 5.10 進め方の提言と質疑応答

## 8. 利用者にとっての利点

発表で語られた、患者と医療提供者にとっての利点は次のとおりです。

* 予約からサービスセンターでの受付まで、情報を再入力せずに済み、数分で摩擦なく完了する
* 結果が平易な言葉の説明つきで届き、医師に尋ねる質問の提案も受けられるため、不安が減る
* 医師にも同時に結果が届き、複数の場所で情報を集めなくても、1 つの流れで見える
* 患者・パートナー・医療提供者が、安全な API で情報をほぼリアルタイムに利用できる
* EHR に依存しない方針により、クリニックはシステムを変更せずに接続できる

成果の数値（所要時間の短縮率など）は、発表では示されていません。

## 9. まとめ

Quest Diagnostics の Project Nova は、患者の登録から結果までの 6 つの場面を 1 つの体験にする、複数年の変革です。弾力性、API とデータ、ガバナンスされた AI、体験の 4 層の基盤で、消費者の期待、臨床の速度、データの増加、信頼と規制という 4 つの力に対応しています。

AI は結果を平易な言葉で説明し、質問を提案し、担当者に振り分けますが、診断や結果の変更は行いません。診断の権限は認定された医師に残ります。Azure、Entra、Purview、Agent 365、Copilot Studio が基盤・安全性・患者体験の各面で支えます。進め方は、体験から考える、プラットフォームを作る、早くガバナンスを整える、パートナーと拡大する、という 4 点と、30 日・30 日・拡大の手順に整理されています。
