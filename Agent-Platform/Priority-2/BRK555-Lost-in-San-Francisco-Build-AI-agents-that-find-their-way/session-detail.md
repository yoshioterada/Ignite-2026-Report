## 5. 発表内容の詳細

### 5.1 エージェントの構成とエージェントハーネス

Hank Bowman は、すべてのエージェントには入力と出力があり、その間で処理が行われると説明しました。今回構成する要素は次のとおりです。

| 要素 | 内容 |
|---|---|
| モデル | Microsoft Foundry から提供する |
| 指示 | MCP サーバーから取得する |
| ツール | Foundry IQ、MCP サーバー、A2A エージェント、メモリのヘルパー |

モデル単体では足りず、ソフトウェアで包む必要があります。このソフトウェアをエージェントハーネスと呼びます。このセッションでは Microsoft Agent Framework を使い、ハーネスの役割として、さまざまなツールへの接続、適切な指示をモデルに渡すこと、エージェントの動作をログで確認できること、エージェントのループの繰り返しを支えることを挙げています。

### 5.2 モデルへの接続と基本のエージェントループ

最初の手順は、Microsoft Foundry に接続するクライアントを作ることです。画面では Foundry の接続文字列とモデルの一覧が示されました。デプロイ済みモデルは 3 つで、GPT 5.6、GPT 6 Luna、そして埋め込みモデル（音声認識の都合で表記が確定できません）と説明されています。モデルの画面を開くと、エージェントで使う接続文字列が得られます。

クライアントを用意したら、エージェントを作ります。指示は「あなたは親しみやすいワークショップのエージェントです。簡潔に答えてください」で、名前をつけ、メッセージをやり取りするループを回します。ユーザーがメッセージを送り、モデルが返す、というものです。これを動かすと基本的なチャットボットになりますが、Hank Bowman は「全員に無料の GPT を配ってしまった」だけで、望んでいるものではないと言い、これがすべてのエージェントの土台になると述べました。

### 5.3 MCP：ツールとデータへの共通の接続口

MCP は、AI アプリケーションがツールやデータソースごとに独自の統合を必要としていた問題を解決するものです。オープンな標準で、どのエージェントやモデルも同じ仕組みでどのシステムにも接続できます。動き方は次のとおりです。

1. エージェントがサーバーに、持っているツールの一覧を求める。
2. MCP サーバーが、説明つきのツール一覧を返す。今回のゲームでは、クエストを開始する、プレイヤーの状態を取得する、回答を提出する、などのツールがある。
3. モデルが、与えられた指示を完了するために必要なツールを選ぶ。
4. エージェントが、必要なパラメーターをつけてツールを呼び出す。サーバーが「開始しました。ようこそ、Hank」のように結果を返す。

MCP はツールだけでなくプロンプトも公開できます。そのため、MCP サーバーの持ち主が、ゲームの遊び方を示すプロンプトをサーバー側で設定できます。

### 5.4 A2A：エージェント同士をつなぐ

最初のクエストは、ある地点から別の地点へ移動する手段を選ぶことです。サンフランシスコでは雨が降ることがあり、渋滞もあるため、状況によって徒歩や自転車のほうが適切な場合があります。そこで、天候と交通を考慮して経路と交通手段を出す Agent 42 を作ってあります。

A2A は、異なるフレームワークや異なるベンダーで作られたエージェント同士が接続できないという問題に対し、エージェントを発見して相互に通信するためのオープンな標準を提供します。Hank Bowman は、送れるのがテキストだけだと思っていたが、テキスト、構造化データ、ファイルの URL、生のデータ（例えばエージェントが生成した画像のデータ）の 4 種類を一度に送れると紹介しました。

Agent 42 の動きは次のとおりです。

1. 質問（A から B へはどう行くべきか）を受け取る。
2. 鍵が有効かを確認し、プレイヤー ID に対応づける。
3. バックグラウンドで Azure Maps を使い、主要な都市で提供されているリアルタイムの交通情報を比較する。
4. 天気の API で実際の天気を取得する。
5. 内部にモデルを持っているため、どの交通手段が最適かを推論し、構造化された形で返す。

最後に Hank Bowman は、MCP はエージェントをツールとデータにつなぎ、A2A はエージェントを他のエージェントにつなぐと整理しました。2 つは補い合い、MCP がエージェントに能力を与え、A2A が協調を可能にします。

### 5.5 Foundry IQ による文書検索

2 つ目のクエストは、都市ガイドに載っている情報から質問に答えるものです。数百の PDF に情報が入っており、全文検索（Ctrl+F）では解決しませんでした。ここで Foundry IQ を使います。

Hank Bowman の説明では、望むのは 1 つの窓口に質問して答えを返してもらうことです。エージェントごとに RAG（検索拡張生成）をカスタムで作る手間を避け、データソースに接続して、あとはクラウドに任せます。Foundry IQ は MCP サーバーとして公開され、質問を送ると答えが直接返ります。検索結果のエンティティが大量に返ってきて、それを自分で推論する必要はありません。2 年ほど前はどのセッションも RAG の作り方の話でしたが、いまは 1 つの製品で解決されていると述べています。

構築の手順は次のとおりです。今回のデータは約 20 個の Markdown ファイルです。

1. Microsoft Foundry の「Knowledge」タブで、ナレッジベースを作る。
2. 説明を入力し、モード（データをそのまま取り出す抽出型か、質問に答えてもらう型）を確認する。
3. モデルに接続し、設定を行い、データソース（Markdown ファイル群）につなぐ。所要時間は約 5 分。
4. エージェント側では、Azure AI Search のエンドポイント（Foundry IQ のエンドポイント）とナレッジベースを指定し、他の MCP サーバーと同じように接続する。これを「city guide」としてエージェントのツール一覧に加える。

### 5.6 Foundry でのホスティング

ここまでのエージェントは Hank Bowman のマシン上で動いており、顧客向けに作るならクラウドに置くべきだと述べました。Foundry のホステッドエージェントは、自前のインフラを構築して運用する必要をなくします。どのフレームワークで作ってもコンテナーに入れて Azure AI Foundry にデプロイでき、スケーリング、セキュリティ、可観測性は Foundry が扱います。

必要なのは Dockerfile を作り、Azure CLI のコマンドでデプロイすることです。デプロイは約 5 分かかるため、事前に済ませてありました。Hank Bowman は、今週の Foundry のホステッドエージェントに関するセッションも受講するよう勧めています。デプロイするたびに自動でバージョンが付き、既定にするバージョンを公開できます（デモ時点でバージョン 4）。

1. エージェントハーネスを選ぶ（または自作する）。モデルにつなぐ。

### 5.8 GitHub Copilot で課題を進める（Anthony Bartolo）

Hank Bowman のような人にいつでも聞けるわけではない、という前提で、Anthony Bartolo が VS Code の画面で GitHub Copilot の活用を紹介しました。ラボの参加者には、VS Code と GitHub Copilot が有効になったラボ環境が用意されます。ヒューマン・イン・ザ・ループは引き続き重要で、AI が勝手に作るのではなく、目的を満たしているかを人が確認します。

**スキル**

開発環境ではスキルを作れ、組織が守るべき規則に沿ってエージェントを作らせられます。ISO 標準を持つ組織、医療や教育のように機密データを扱う組織では、公開 API をそのまま使えないなど、守るべきセキュリティの条件があります。例として、プライバシーに関するスキルがあります。その規則の 1 つが「実名を要求・収集・抽出しない」です。ゲームでも Hank Bowman は実名ではなくハンドル名を使っていました。Copilot に業務ロジックを伝えれば、スキルを作ってもらえます。

スキルでは、使うリソースも指定できます。ガバナンスから「この Azure サブスクリプションにデプロイする」と割り当てられている場合、その指示を持たせられます。

**Foundry Toolkit**

VS Code の拡張機能の Foundry Toolkit により、Hank Bowman が Foundry の画面で見せた指示の設定を、IDE の中で使えます。画面を行き来せずに済み、自分のサブスクリプション向けの指示と有効にしたスキルが結び付いた状態で、Python のコードを IDE 内で書けます。

**課題の進め方**

ラボには、Microsoft Agent Framework で Python のエージェントを 1 つ作り、MCP、A2A、ナレッジ検索の 3 つの機能を 1 つずつ追加するという課題文があります。これをそのまま Copilot への質問として貼り付けます。ただし依頼は「これを作って」ではなく「作り方を教えて」とします。Anthony Bartolo は、これが重要な違いだと述べました。AI が作ったものを検証せずに使い、データ漏えいやセキュリティ侵害が起きたとき、責任を問われるのは AI ではなく人です。スキルはエージェントのルールブックになるが最終的な解決策ではなく、人が検証することが必要だと述べています。

デモでは、Copilot とのやり取りを実際には行わず、ラボで試してもらうとして画面を見せるにとどめました。

**用語の整理**

| 用語 | 説明 |
|---|---|
| 指示 | エージェントに何を達成するのかを伝える |
| スキル | 繰り返し使える規則（実名を取得せずハンドル名を使う、指定のサブスクリプションにデプロイするなど） |
| エージェント | 指示とスキルを理解し、役割を果たす成果物。Agent 42 は、A から B への行き方に特化した専門エージェント |

### 5.9 ラボと OpenHack

**ラボ**

このセッションは Lab 667 の事前準備として位置づけられています（冒頭で Anthony Bartolo が説明）。ラボは今週 4 回開催され、明日が 2 回、木曜日と金曜日に 1 回ずつです。ラボ環境のマシンが用意されるため、自分のノート PC は不要です。完成したコードは自分のリポジトリにフォークして学習を続けられます。ラボはオープンソースとして公開されており、QR コードから登録先やラボのリンクにアクセスできます。

**OpenHack**

ラボは実践的で好評ですが、「手順 1 はこれ、手順 2 はあれ」という形では何をやったかを覚えていられない、という意見があったと述べました。そこで OpenHack という形式があります。OpenHack は新しいものではなく、5〜6 年ほど続いています。昨年は「ピザ OpenHack」が大成功でした。

課題解決型では、手順は教えられず、「MCP サーバーに接続して X を行うエージェントを作る」というレベルで課題が示されます。やり方の情報が与えられないわけではなく、ドキュメントはすべて提供され、先の GitHub Copilot の使い方も使えます。課題をどう解くかを考える点が効果的だったと述べています。

昨年のピザ OpenHack の課題は Hank Bowman がオープンソースにしてくれたため、QR コードから自分のサブスクリプションで試せます。内容は、MCP サーバーに接続して注文できるピザを出し、実際にピザを注文するエージェントを作るものです。この課題は 2 年前の Build で始まり、900 人以上が参加し、その後の 1 年半でさらに 1,000 人が参加しました。

## 6. デモ・手順

画面を使ったデモがあります。Hank Bowman が自分のマシンで、Python と Microsoft Agent Framework を使い、同じエージェントのコードに機能を足していく形で進めました。画面の細部は音声からは確認できないため、語られた範囲を記します。

1. **デモ 1（基本のエージェント）：** Microsoft Foundry の画面で、接続文字列と、デプロイ済みの 3 つのモデルを示す。Foundry に接続するクライアントを作り、「親しみやすいワークショップのエージェント」という指示と名前を与えたエージェントを作成して、メッセージのループを用意する。実行すれば基本的なチャットボットになる（実行の結果は示されていません）。
2. **デモ 2（MCP）：** OpenAI クライアントを使い、MCP のストリーミング可能なツールを作成する。ゲームサーバーを指定し、認可キーを与える。MCP サーバーからゲームのプロンプトを取得してエージェントに渡し、ツール一覧にゲームの MCP サーバーを加える。メッセージのループを開始すると、MCP サーバーに接続してツールを検出し、「クエストの準備ができました。プレイヤーのセッションが接続されました」と表示された。開始を指示すると最初のクエストが出た。内容は、ある地点から別の地点への移動手段を選ぶこと。
3. **Agent 42 の説明を挟む：** 最初のクエストの途中でスライドを使って A2A と Agent 42 を説明した。今日の天気と交通について、雨が降りそうなのでスクーターはやめておく、交通量が多かったと話した。そのうえで「exit」と入力して一度終了する。
4. **デモ 3（A2A）：** ゲーム用 MCP サーバーに加えて、A2A エージェントへのツールを追加する。API キーつきで A2A エージェントの URL に向けたクライアントを作り、説明をつけて URL を指定し、ツールとして接続する。実行して「クエストを続けますか」に「はい」と答え、「help」と入力して助けを求める。Grand Avenue から Columbus Avenue への移動で、バックグラウンドで Agent 42 が Azure Maps により経路を計算した。返ってきた助言には天気（欧州式の表記で 40、米国式で 57 度と聞こえた。単位の詳細は音声認識の都合で確定できません）、距離、正確な経路の地図、すべての曲がり角つきの案内が含まれ、推奨は自転車。天気は晴れで、自転車が最速と示された。
5. ゲームの画面では、完全な助言、推論、推奨を確認できる（Anthony Bartolo がこの画面を後で見せると話しましたが、後半では確認できません）。答えとして「自転車」を提出すると、次のクエストに進めた。
6. **デモ 4（Foundry IQ）：** 2 つ目のクエストは、都市ガイドに関する質問で、例として書店の創業に関するものが出た。Microsoft Foundry の Knowledge タブで、ナレッジベース（説明、モード、モデル、データソースとなる Markdown ファイル群）を作る手順を示す。エージェント側で Foundry IQ のエンドポイントに接続し、city guide としてツール一覧に加える。ゲームを再開して質問を表示し、「調べてください」と指示する。バックグラウンドで MCP サーバーに質問が送られ、文書を調べて答えが返った。答えは City Light bookstore。

## 7. 注意点・発表者の気付き

- **ヒューマン・イン・ザ・ループ：** AI が作ったものが目的に合い、組織の規則を守っているかを人が確認する必要があります。規則を設定しても、組織が受け入れる範囲を外れることをする可能性があります。
- **責任の所在：** 検証せずに使い、データ漏えいやセキュリティ侵害が起きた場合、責任を問われるのは AI ではなく人です。
- **Copilot への依頼の仕方：** 学習目的では「作って」ではなく「作り方を教えて」と依頼します。
- **スキルは最終解ではない：** エージェントのルールブックとして重要だが、人の検証が必要です。
- **基本のエージェントだけでは足りない：** 指示とモデルだけのエージェントは単なるチャットボットで、Hank Bowman は望んでいるものではないと述べています。
- **ホステッドエージェントのデプロイ時間：** 約 5 分かかるため、デモでは事前に用意したものを使いました。
- ゲームの正解をすべて見せないよう、デモは途中で止めています。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

- **RAG を自前で作らずに済む：** Foundry IQ は、データソースに接続すれば MCP サーバーとして質問に直接答えを返します。Knowledge の設定は約 5 分で、20 個ほどの Markdown ファイルを読み込ませる例が示されました。
- **ツールは接続で用意できる：** MCP と A2A により、自分のコードでツールを作らず、既存のツールやエージェントにつなげます。
- **ホスティングの負担が小さい：** Foundry のホステッドエージェントが、スケーリング、セキュリティ、可観測性を扱います。バージョンは自動で付きます。
- **開発環境内で作業が完結する：** Foundry Toolkit により、画面を行き来せずに IDE の中でエージェントを作れます。
- **組織の規則を反映できる：** スキルでプライバシーのルールやデプロイ先のサブスクリプションを指定できます。
- **学習の機会：** Hank Bowman は課題を 28 分で完了し、ラボでは 75 分が用意されています。ラボと昨年の課題はオープンソースで、フォークして自分のサブスクリプションで試せます。

## 9. まとめ

「Lost in the City」は、モデル、指示、ツールを組み合わせて、都市の中で課題を解くエージェントを作る題材でした。ハーネスには Microsoft Agent Framework を使い、MCP でゲームサーバーとプロンプトに接続し、A2A で交通手段の専門エージェント Agent 42 を呼び出し、Foundry IQ で都市ガイドを検索し、最後に Foundry のホステッドエージェントとして動かしました。

GitHub Copilot とスキルを使えば、組織の規則に沿った形で課題を進められます。ただし、人が検証することは変わらず、学習目的では作り方を教えてもらう使い方が勧められています。ラボ（Lab 667、今週 4 回）と、ピザ OpenHack のオープンソース、北米・南米での 11 の課題イベントが案内されました。
