# THRSP1104 Strengthen Copilot agent security with trusted data

## 1. はじめに

このセッションは、Copilot のエージェントを試行段階から本番環境へ移すときに、「どのエージェントがあり、どの機微データに届き、目的外の動きをしたらどうなるか」をどう把握して制御するかを扱う、シアター形式の短い発表です。データセキュリティの Cyera と、Microsoft の Agent 365 チームの担当者が、人事向けエージェントを例に、Agent 365 の画面と Cyera の画面を使って見せました。

最後に、データの準備状況の評価、エージェントの発見、1 つの本番エージェントの検証、という 3 つの進め方が示されています。

セッション URL: [https://ignite.microsoft.com/en-US/sessions/THRSP1104](https://ignite.microsoft.com/en-US/sessions/THRSP1104)

## 3. 何に関する発表か

テーマは、Copilot のエージェントを本番で使うときのセキュリティの証拠づくりです。エージェントの数が急増する一方で、ガバナンスが追いついていないという問題意識から始まります。

発表の流れは次のとおりです。

1. Copilot のエージェント導入の規模と、アクセス制御の問題
2. エージェントを作る側（Copilot Studio、Microsoft Entra、Power Platform、Microsoft Purview）と、Cyera が補う部分
3. 人事向けエージェントの例（社員の給与情報が漏れる場面）
4. デモ 1：Agent 365 の画面で、採用担当エージェントのリスクを見る（Brendan）
5. デモ 2：Cyera の画面で、発見、データへの到達範囲、アクション単位の制御とエージェントの隔離を見る（Tafi）
6. 信頼できるデータを準備する流れと、進め方の提案

## 4. 発表者が伝えたいメッセージ

発表者は、組織が Copilot を試行から本番に移すとき、**エージェントの保護と、その証拠の提示**が課題になると述べています。AI エージェントの導入は、ガバナンスとセキュリティが追いつけない速さで進んでいると説明されています。

根拠として、Gartner の予測が引用されました。平均的な企業が使うエージェントは、2025 年の 15 から 2028 年には 15 万を超える、という内容です。もう 1 つ、強調された数字は「AI に関連する情報漏えいを経験した組織の 92% が、適切な AI のアクセス制御を欠いていた」というものです。これはデータをめぐる問題だと位置づけられています。

背景として、従来のセキュリティは端末、ネットワーク、メールに置かれてきたため、データの中身と文脈を理解して価値を付け、統制するのが難しかったと説明されています。AI エージェントは、それまで見えにくさに隠れていたアクセス制御の問題を、さらに大きくします。

## 5. 発表内容の詳細

### 5.1 エージェント導入の規模と、確認すべき 3 つの問い

組織が Copilot とそのエージェントを採用するとき、証拠を持って答えるべき問いとして、次の 3 つが挙げられました。

1. どのエージェントがあるのか
2. そのエージェントは、どの機微データに届くのか
3. エージェントが目的外の動きをしたら、何が起きるのか

Copilot の使い方は、文書の要約や質問への回答から、自律的に動いて多くの業務をこなすエージェントへ移っています。そのため 3 つ目の問いが重要になるという説明です。

### 5.2 Microsoft のプラットフォームと Cyera の役割

発表者は、Microsoft が優れたガバナンスを提供している部分と、Cyera との協業が効く部分を示すと述べ、エージェントの構成要素と管理する製品を次のように整理しました。

| 要素 | 構築・管理する製品 |
| --- | --- |
| 指示、トピック、チャネル | Copilot Studio |
| ID（ユーザーのサインイン、または作成者が与えた接続によるデータへの権限） | Microsoft Entra |
| ツールとアクション | Power Platform とそのデータポリシー |
| ナレッジ（知識として参照するデータ） | Microsoft Purview のラベルと DLP（情報漏えい防止） |

Cyera は、そのデータを発見し、文脈を付け加えたうえで Microsoft のエコシステムに渡し、Microsoft 側のセキュリティ制御を強化する、という位置づけです。

### 5.3 人事向けエージェントの例

組織が試行として最もよく使う例の 1 つとして、人事の質問に答える AI アシスタントが取り上げられました。

* 作成者の接続（作成者が与えた接続）でデータに接続しており、組織内の全員がその接続の権限を引き継ぐ
* 人事のサイトと Outlook に接続している
* 給与情報など、機微な人事記録に届く可能性がある

人事の規程を尋ねれば通常どおり答えが返ります。しかし、CEO の給与や同僚の給与を尋ねることも考えられます（発表者は、自分の給与交渉に使うために同僚の収入を知りたい人が出る、と例示しました）。Outlook に接続されているため、そうした記録をメールで外に送り出すこともできてしまいます。

だからこそ、機微な記録が露出していることを可視化し、アクション単位でアクセスをブロックするか、セキュリティ審査のためにエージェントを隔離するポリシーを適用することが重要になる、と説明されています。

### 5.4 Agent 365 の画面（Brendan によるデモ）

Brendan は、Agent 365 のセキュリティとガバナンスのチームに所属すると名乗りました。Cyera は、自社のアラートのテレメトリを Agent 365 のリスクの画面に取り込む取り組みの先駆けで、デモで見せるのは約 6 か月の共同作業の成果だと紹介しています。詳しくは 6 章に書きます。

### 5.5 アクション単位とエージェント単位の制御

Tafi は、人事向けエージェントがメールで機微な給与記録を外部へ送ろうとする場面で、Cyera はそれが制限対象の人事記録だと認識し、**その 1 つのアクションにだけ**ポリシーを適用できると説明しました。ほかの人は作業を続けられます。

多くの組織が悩むのは、制御をアクションに置くか、エージェントそのものに置くかです。エージェントをブロックすると、業務全体の生産性に響きます。DLP を使ったことがある人なら、従業員の作業を止めてしまう困難さを知っているはずだ、と述べています。Cyera は Microsoft と協力して、アクション単位とエージェント単位の両方でポリシーを使えるようにする、という説明でした。

### 5.6 信頼できるデータの準備の流れ

どこから始めるかという問いに対し、次の流れが示されました。

1. **データのスキャンと分類**：機微データが何で、どこにあり、誰または何がアクセスできるかを把握する
2. **Purview の秘密度ラベルを自動で適用**：Purview がそのラベルを、プラットフォーム内のデータポリシーに使う
3. **エージェントの一覧化**：Copilot Studio と Power Platform の管理画面にも一覧があり、Cyera 側の情報で、ID の観点のガバナンスと制御に必要な文脈を補う。Microsoft Entra が ID を提供し、データポリシーも適用できる
4. **ID とエージェントの紐づけ**：どの ID とどのエージェントが、そのデータにアクセスできるかを関連づける
5. **Copilot Studio の制御と組み合わせる**：アクションの観点で、エージェントに効くガバナンスポリシーを入れる
6. **継続的なコンプライアンス**：継続的にスキャンし、新しい ID やエージェントにも自動で文脈を付ける。年 1 回の検証と証明の作業は不要になる

結果として、適切なガバナンスポリシーと、それが機能している証拠を持って、Copilot のエージェントを安全かつ早く本番に移せる、という説明です。

### 5.7 進め方の提案と案内

発表者が示した順序は 3 段階です。

1. **Copilot のデータの準備状況を評価する**：Cyera は、無料の Copilot データリスク評価を提供している
2. **Copilot のエージェントを発見する**：Microsoft のツールとプラットフォームを使う
3. **1 つの本番エージェントを端から端まで検証する**：Microsoft と協力して支援する

会場のブース（番号は 551 と述べられたが、本人が自信なさげに確認している）で、プラットフォームのデモを見せるとのことです。QR コードから、無料の評価を申し込めると案内されました。

## 6. デモ・手順

デモは 2 つあり、発話で語られた順に整理します。画面の細部は、音声からは確認できません。

### 6.1 Agent 365 での確認（Brendan）

1. Agent 365 の「すべてのエージェント」の画面を開く。組織のエージェントの一覧で、どこで動いているか、どのエージェントに注意が必要かが分かる。所有者のいないエージェントのフィルターもある
2. 「所有しているつもり」ではガバナンスにならない、と述べたうえで、採用コーディネーターのエージェント（Tafi が少し前に話したもの）を開く。状態は「レビュー待ち」
3. セキュリティのタブを開く。全体のリスクは高。内訳は、実行時のリスクが高、露出のリスクが高、影響範囲が中。アナリストにとっては、観測された事実、インシデントが起きやすい要因、影響が及ぶ範囲という 3 点になる
4. 関連するケースの欄を見る。「承認されていないチャネルで、候補者のデータが共有された」という調査がある。個々のアラートを開いて経緯を組み立てるのではなく、ケースから始めて証拠に降りていく
5. 「ソース」の列で、Microsoft Defender と Cyera の Agent Guardian の信号が同じ画面に並んでいることを示す
6. Cyera のアラートで、何が関係し、どこへ渡ったかが分かる。承認されていない Teams のチャットに、採用のオファーの保留中の内容があった。また最終候補者の応募書類の要約が、外部の Gmail の宛先に送られていた。これで「このエージェントは危険」から「調査すべき内容」へ進める

### 6.2 Cyera の画面（Tafi）

発話では、デモを 3 つの問いと 2 部構成で行うと述べられています。

1. **発見**：Cyera 上にあるエージェントの一覧を表示する。エージェントごとのリスクと、関連するアラートも示される
2. **データへの到達範囲**：エージェントが届くデータの種類を、ID と所有者とあわせて示す。「エージェントと意図」の欄には、人事アシスタントという名前にもかかわらず、財務、法務、コンプライアンス、戦略、監査の各領域にわたる広範な機微文書に届く、という内容が表示されていた。さらに人事アシスタントは Outlook にも接続しているため、適切なプロンプトで代行させれば機微情報を送り出せる、と説明された
3. **範囲の絞り込みと証明**：こうして、エージェントが届くデータの範囲から見直して、範囲を絞り込み、監査人や規制当局に示し、早く本番に入れられるとされた
4. **アクション単位の制御**：実行時に、メール送信のアクションをポリシーに照らして確認する。エージェント、ID、データ、宛先を記録して関連づけ、Microsoft に渡す。ブロックされたか許可されたかという結果も示され、証拠になる。ほかのアクションは動いたままになり、悪意のある操作だけをブロックできる
5. **エージェントの隔離**：Cyera の運用担当者が開始できる。調査の間、エージェント全体に適用される。この実現には Power Automate のプレミアム機能が必要だと述べられた
6. アラートの画面では、ポリシーのイベントが生成され、エージェントの ID とデータの文脈、宛先とともにメール送信が確認され、アクションまたはエージェントを隔離できる

## 7. 注意点・発表者の気付き

* エージェントの隔離（エージェント単位の制御）を使うには、Power Automate のプレミアム機能が必要です。発表者は、エージェントの保護を強化できるため検討を勧めています。
* エージェントをブロックすると業務全体に影響するため、アクション単位の制御と使い分けることが重要だとされています。
* 作成者の接続を使うエージェントを全員に公開すると、全員がその接続の権限を引き継ぎます。
* エージェントの所有者が決まっていない状態は、ガバナンスとして成立しないと指摘されました。
* Gartner の予測は、発話では「15 万を超える（2028 年）」「2025 年は 15」と語られています。2025 年の 15 の単位（企業あたりの数かどうか）は、発話では確認できません。

## 8. 利用者にとっての利点

発表で語られた利点は次のとおりです。

* エージェントの一覧、リスク、届くデータ、ID と所有者を 1 つの流れで把握できる
* アクション単位でブロックでき、ほかの業務を止めずに済む
* 判断と対応の証拠を、監査人や規制当局に示せる
* 新しい ID やエージェントに、継続的なスキャンで文脈が自動付与され、年 1 回の検証作業が不要になる
* 適切なポリシーと証拠のもとで、エージェントを安全かつ早く本番に移せる

導入による数値の成果は、発表では示されていません。

## 9. まとめ

AI エージェントが急増するなか、組織は「どのエージェントがあるか」「どの機微データに届くか」「目的外の動きをしたらどうなるか」に、証拠をもって答える必要があります。Cyera は、データの発見と分類で文脈を作り、Microsoft の Copilot Studio、Microsoft Entra、Power Platform、Microsoft Purview、Agent 365 に渡して制御を強化します。

デモでは、Agent 365 上で Cyera のアラートを同じ画面に並べて調査する流れと、アクション単位の制御およびエージェントの隔離が示されました。進め方は、データの準備状況の評価、エージェントの発見、1 つの本番エージェントの検証の 3 段階です。
