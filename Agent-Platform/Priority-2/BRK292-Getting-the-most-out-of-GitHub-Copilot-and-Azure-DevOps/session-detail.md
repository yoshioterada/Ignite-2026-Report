## 5. 発表内容の詳細

### 5.1 基本：VS Code と Copilot で Azure DevOps のリポジトリを使う

最も基本的な使い方として、リポジトリをローカルにクローンし、VS Code で開き、Copilot のチャットから作業を始める流れが紹介されました。AI を使い始めたばかりの人向けの入口という位置づけです。

次の段階が MCP サーバーの追加です。MCP サーバーは、Azure DevOps に情報を出し入れするためのツール群です。これがないと、バグやストーリーとして Azure DevOps にある作業内容を、Copilot に渡すために手作業でコピー＆ペーストする必要があります。MCP サーバーを使えば、Azure DevOps の情報を Copilot の文脈として取り込めます。VS Code での設定は、`mcp.json` ファイルに組織の URL（mcp.dev.azure.com を使うもの）を書くだけだと説明されました。詳しい手順は 6 章に書きます。

### 5.2 Azure DevOps の MCP サーバー

Azure DevOps の MCP サーバーは 2 種類あります。最初に作られたのは、ローカルのクライアントに取り込んで使うローカル版です。**リモート版の MCP サーバーは 8 月に GA** になりました。リモート版は、さまざまなサービスに組み込みやすいことが特徴です。

利用できる場所として、次が挙げられました。

| 利用先 | 発表での説明 |
| --- | --- |
| Copilot Studio、Microsoft Foundry | コネクタが用意されている |
| GitHub Copilot CLI | とてもよく動く |
| Visual Studio、Visual Studio Code | ファーストクラスの統合 |
| Copilot Cowork、GitHub Copilot アプリ | 後述のとおり利用可能 |

利用状況の数値は次のとおりです。

- 1 日あたりのツール呼び出し：およそ 400 万〜500 万回
- 月間の利用ユーザー：約 30 万 5,000 人
- 利用している組織：約 2 万 7,000〜2 万 8,000

Dan は、利用が大きく伸びていると話しています。なお、コア製品の機能として、作業項目、クエリの実行、作業項目の更新、プルリクエストの参照、パイプラインの参照、Wiki ページの参照が MCP サーバーのツールとして使えます。

### 5.3 Copilot Cowork の Azure DevOps プラグイン

Dan は、数週間前にリリースした Microsoft Copilot Cowork 用の新しいプラグインを紹介しました。Cowork に力を入れた理由は、アプリ内に Copilot の体験を作る予定はあるのかと聞かれて VS Code を勧めると、不満が多かったからだと説明しています。誰もが VS Code を使いたいわけではなく、全員が技術者でもないため、Cowork のような場所にも Copilot AI の体験を広げることにしたそうです。

プラグインの実体は、**MCP サーバーを包んだもの（ラッパー）**です。スキルも 4 つ同梱されていますが、使っている人はあまり多くないという認識で、それでも追加したと話しています。接続はプラグインの画面で接続を押し、組織名を入力するだけです。組織名を入力しないと複数の組織をまたいで使えますが、その場合は指示文や各呼び出しの中でどの組織を使うかを明示する必要があります。

Dan が Cowork の面白い点として挙げたのは、**チームの Teams のチャット、会話、会議にアクセスできる**ことです。PM として多くの会話に参加し、その中で決まったことをバックログに載せたい場面が頻繁にあるが、これまでは内容を思い出し、録音の文字起こしを探してコピー＆ペーストする必要があったと説明しています。

### 5.4 GitHub Copilot アプリでの MCP サーバーとオートメーション

GitHub Copilot アプリでも、同様に低い敷居で使えます。MCP サーバーの追加は、アプリのカスタマイズ画面から新しいサーバーとして Azure DevOps を追加し、リモート MCP サーバーの URL を入れるだけです。組織名の指定は任意です。Dan のデモ環境では Work IQ も追加されており、これによって Teams のチャットや会話にアクセスできます。つまり、Cowork でできることは Copilot アプリでもできます。

さらに Dan は、普段使っている事例として**オートメーション**を紹介しました。5〜6 チームをまたいで仕事をしており、バックログをきれいに保ちたいという要望から、親の作業項目にひも付いていない作業項目を洗い出すクエリを、毎日または数日おきに実行していました。この作業に 5〜20 分かかり、チームが 5 つあると時間の無駄になっていたため、オートメーションにしたとのことです。オートメーションの中身は、クエリの実行、結果の取得、ルールに沿った関連付けを行う指示文で、実行すると最後に完了内容の要約が出ます。毎回 2〜3 分かかる、という説明でした。

Dave はこの事例を、Copilot を Azure DevOps の AI エンジンとして使う好例だと総括しました。バックログの整理や、Teams のチャットからの作業項目の作成を、Azure DevOps の中の AI で行えるという意味です。

### 5.5 GitHub Copilot アプリの Azure DevOps 連携（実験的機能）

Dan が「最近で最も楽しい取り組みの 1 つ」と紹介した（数日前に発表された）のが、Azure DevOps のリポジトリの文脈を GitHub Copilot アプリに持ち込む機能です。リポジトリに接続し、エージェントに作業を依頼し、プルリクエストやコマンドの確認までを、Azure DevOps と行き来せずにアプリ内で行えます。Dan は、アプリ自体の紹介セッションが今週ほかにもあり、Mario による導入もあったと触れ、会場に使っている人を挙手で尋ねています。

有効化は、設定の「実験的」の中のシステム項目にある、Azure DevOps 連携のスイッチをオンにするだけです。その後、Azure DevOps からリポジトリを追加できます。リポジトリを追加すると、そのリポジトリのプルリクエスト一覧が見られます。作業項目は今後追加予定で、現時点ではプルリクエストのみです。

主な機能は次のとおりです。

- プルリクエストからセッションを作成する。リポジトリを取得して、変更内容を開ける
- プルリクエストの画面で、チェック状況の確認、レビュアーの追加、承認状況の確認、説明の編集、コメント追加、承認ができる。見た目は GitHub と同じだが、実体は Azure DevOps のプルリクエスト
- Azure DevOps 上でプルリクエストを直接開くこともできる
- **エージェントマージ**：プルリクエストの「世話役」のような機能。レビューの指摘への対応、CI の失敗の修正、マージ競合の解消を行い、他のチェックを通れば自動的にマージする
- エージェントマージを全体で有効にしていない場合でも、手動でソースブランチの削除や関連作業項目の完了ができ、Azure DevOps と同じ操作になる

Dan は、**作業項目の操作には MCP サーバーのインストールが別途必要**だと注意しています。将来的には、この実験的機能の有効化と同時に自動でインストールされるようにする予定です。

作業項目に関する計画も語られました。今日のアプリでは 課題（Issue）からセッションを開始できますが、同じことを作業項目でも行えるようにしたい、という内容です。MCP サーバーで取得する代わりに、作業項目を開いてセッションを開始すると、内容を読み、実装し、レビューの準備ができたら知らせ、完了まで進めるイメージです。**この機能はプレビューで、数か月はプレビューが続く見込みです。アプリは毎日のように更新されており、GA は来年の初めごろを見込んでいます。**

### 5.6 Azure Repos の Copilot コードレビュー

Azure DevOps の製品内に GitHub Copilot の力を直接持ち込む機能として、Azure Repos 向けの Copilot コードレビュー（CCR）が紹介されました。6 月ごろからプレビューで、今週 GA が発表されました。

| 項目 | 内容 |
| --- | --- |
| ライセンス | Copilot のライセンスは不要 |
| 課金 | Azure サブスクリプションに請求される |
| プレビュー中の実績 | 約 2,000 のアクティブな組織、約 15 万件のレビュー |

Dan は、まだ足りない機能があることを認めています。GitHub の方が開発のスピードが速いため、Azure DevOps は 1〜2 か月遅れで追随する形になるものの、GitHub が進めているほとんどの機能に追随していくと話しています。

設定の階層は、組織、プロジェクト、リポジトリです。

1. **組織**：組織の設定のリポジトリ項目でコードレビューをオンにします。組織レベルのカスタム指示も設定できます。オンにすると、全プロジェクト・全リポジトリで有効にするオプションがありますが、数百のプロジェクト、数千のリポジトリを持つ大きな組織では「これは怖い」と感じるだろうと、Dan 自身が述べています。今後は、プロジェクトコレクション管理者が有効にするリポジトリやプロジェクトを選べる制御を追加する予定です。
2. **プロジェクト**：同じ場所で有効にします。プロジェクトレベルのカスタム指示と、既定の実行レベル（エフォートレベル）も設定できます。現在は軽量（`light`）とバランス（`balanced`）の 2 種類です。GitHub には最大（`maximum`）があり、Azure DevOps でも対応を進めています。
3. **リポジトリ**：そのリポジトリで Copilot を有効にし、既定の実行レベルを設定します。

カスタム指示の優先順位は、まずリポジトリ、次にプロジェクト、最後に組織の順に参照します。競合した場合は、コードに近いものが優先されます。

ブランチポリシーで、プルリクエストの作成時に自動でコードレビューを依頼するよう設定できます。ドラフト状態でも対象にできます。ただし、**コミットのたびには実行されません**。コミットが多いと費用がかさみ、行き過ぎだと判断したためです。初回のプルリクエストでのみ自動で実行され、その後は手動で実行します。

使い方は簡単で、プルリクエストの右側に GitHub Copilot コードレビューの依頼欄が表示され、実行レベルを選んで依頼します。内部では**動的パイプライン**が使われ、浅いクローンを作成し、差分ファイルをまとめて Copilot に送ります。Copilot がレビューした結果を、プルリクエストに追記する仕組みです。

完了したプルリクエストでは、Copilot からのコメントや提案が複数並びます。VS Code で開いて修正し、新しいコミットを作る方法のほかに、提案をその場で適用することもできます。複数の提案を適用してコミットするとき、コメントを自動で解決済みにできます。以前はコミット後に戻って、コメントを 1 つずつ解決していたため、これが大きく改善されたと説明されました。解決すると、誰が解決したかも表示されます。

プルリクエストのページには、コメントを個人や自動化ツールで絞り込む機能も追加されました。GitHub Copilot のコメントだけ、自分のコメントだけ、人のコメントと自動化ツールのコメントの区別などで表示を絞れます。

### 5.7 GitHub Advanced Security for Azure DevOps と Copilot Autofix

ここからは Dave の担当です。GitHub Advanced Security for Azure DevOps に、**Copilot Autofix がパブリックプレビュー**で加わりました。Copilot がアラートを数分で修正する手助けをするという位置づけです。Dave は、GitHub での実績として、昨年は約 40 万件の修復が行われ、セキュリティアラートの修正が速くなったためプルリクエストの処理時間が大幅に短縮したと紹介しています。

対応する内容は次のとおりです。

- コードスキャンの自動修正（内部は CodeQL、コードクエリ言語）
- 依存関係アラートの自動修正：オープンソースパッケージに CVE が発表されたとき、新しいバージョンへの更新や、特定バージョンへの固定を Copilot が支援する
- サードパーティのコードスキャンのアラート：他のツールが出力した SARIF ファイルを GitHub Advanced Security に取り込み、アラートを表示・管理する

課金はすべて Azure サブスクリプションに請求されます。カスタム指示とスキルを使い、自動修正がチームのベストプラクティスに従うようにできます。例えば、.NET アプリで Playwright を使ってテストし、Azure Kubernetes Service にデプロイする、とカスタム指示に書いておけば、Copilot が新しくテストを作るときに Playwright のテストを作ります。アラートをまとめて選択する機能は近日対応予定です。

### 5.8 Azure DevOps から GitHub へのリポジトリ移行ツール（ELM）

ELM は、Azure DevOps に用意されたリポジトリ移行ツールです。大きな顧客だと、移行中にリポジトリに触れないため、ダウンタイムが数日、ほぼ 1 週間かかった例もあったと Dan は説明しました。ELM は移行するリポジトリと移行先の GitHub 組織を選ぶと、まず同期を行い、その間も Azure DevOps で作業を続けられます。最後に切り替え（カットオーバー）を行い、**ダウンタイムは合計で約 30 分**です。

現時点の要件として、**データレジデンシー付きの GitHub Enterprise Cloud が必須**です。全員が使っているわけではないと認めたうえで、将来この制約を外したいとのことです。ELM は GA 済みです。

## 6. デモ・手順

### 6.1 VS Code と Copilot でリンクを修正する（録画）

Dan は「これは動画なので非常に速く進む」と断っています。

1. 作業項目の画面にあるカタログへ戻るリンクを、別のリンクに合わせて変えたい、という状況から始める
2. VS Code のチャットに、リンクを他のリンクに合わせて変えるよう依頼する
3. Copilot が文脈を確認し、必要な箇所を見つけて変更し、テストを実行して、完了を知らせる
4. アプリの画面を開き直し、修正が反映されたことを確認する

### 6.2 MCP サーバーで作業項目を取得して実装する（録画）

1. `mcp.json` を作り、組織の URL（mcp.dev.azure.com）を指定して MCP サーバーを開始する
2. 特定のプロジェクトで、特定のタグが付いたバグを取得するよう依頼する
3. Copilot が WIQL（作業項目クエリ）を作って実行し、作業項目の一覧（この例では 1 件）を返す
4. その作業項目を取得して実装するよう依頼する。タイトルと再現手順を取得し、変更を加え、テストを実行する
5. 修正後のサイトを開き、修正が適用されたことを確認する

### 6.3 Copilot Cowork での接続と Teams のチャットからの作業項目作成

1. Cowork のプラグイン画面で、Azure DevOps プラグインを検索して見つける
2. 接続を押し、デモ用の組織名を入力して接続する
3. 特定のプロジェクトの作業項目一覧を依頼する。作業項目 ID がリンクになるよう指定する
4. 作業項目を、ユーザーストーリーとして機能にひも付けたいので、まず関心のある機能の一覧を取得する（機能 243 を選ぶ）
5. 「Dave との直近のチャットを読み、バックログに載せる話をした内容から、先ほどの機能に対するユーザーストーリーを作ってほしい」と依頼する
6. Cowork がチャットを確認し、機能 243 を取得して内容を把握し、該当メッセージを見つけ、作業項目を作成する
7. 作成された作業項目を開くと、会話の内容から生成されており、親へのリンクと、会話があった Teams チャネルへのリンクが付いている

### 6.4 GitHub Copilot アプリでの MCP サーバー追加とチャットからの作業項目作成

1. カスタマイズ画面から新しいサーバーとして Azure DevOps を追加し、リモート MCP サーバーの URL を入れる（組織名は任意）
2. Work IQ も追加済みの状態で、Teams の特定のチャットを取得し、貼り付けて子の作業項目を作るよう依頼する
3. チャットを見つけ、子作業項目を作成し、元へのリンクも作られる

### 6.5 オートメーションでバックログを整理する

1. 親にひも付いていない作業項目を返すクエリがあり、該当する作業項目が複数ある状態を示す
2. Copilot アプリのオートメーションを開き、以前に作成したものを選ぶ（時間がかかるため過去の実行を見せている）
3. 内容は指示文のみで、クエリの読み込み、結果の取得、ルールに沿った関連付けが書かれている
4. 実行が進み、最後に完了した内容の要約が表示される

### 6.6 GitHub Copilot アプリで Azure DevOps のリポジトリを扱う

1. 設定、実験的、システムの順に開き、Azure DevOps 連携をオンにする（最初に別の場所を開いてしまい、やり直している）
2. Azure DevOps からリポジトリを追加する。検索が一時的にうまくいかなかったが、すでに追加済みのリポジトリがあったのでそれを使う
3. リポジトリの画面で、プルリクエストの一覧を確認する
4. 1 件のプルリクエストからセッションを作成する。リポジトリが取得され、変更内容とプルリクエストを開ける
5. プルリクエストの画面で、チェック、レビュアー、承認、説明の編集、コメント、履歴、承認操作を確認する
6. 別のセッションで、Contoso プロジェクトの作業項目 247 を読み、コードを実装し、状態を新規からアクティブに変更し、PR、コミット、ブランチを作業項目にひも付けるよう依頼する（MCP サーバーが必要）
7. 完了後、プルリクエストを開き、未解決のコメントが残っていることを確認する。Copilot コードレビューで指摘があった想定で、「未解決のコメントを修正して」と依頼する。1 度うまくいかず、個別のコメントに切り替え、プルリクエストを閉じてからもう一度試すと動いた（プレビュー機能のため）
8. 新しいセッションがコメントを確認して修正を適用し、コメントを解決済みにするところまで自動で行われる
9. エージェントマージの状態表示（作業中、マージ可能、マージ済み）を紹介する。実際のマージは行わず、手動で行う場合の操作（ソースの削除、関連作業項目の完了）を説明する

### 6.7 Copilot コードレビューの設定と使い方

1. 組織設定のリポジトリで、コードレビューをオンにし、組織レベルのカスタム指示を確認する
2. プロジェクトで有効にし、カスタム指示と既定の実行レベルを確認する
3. リポジトリで有効にし、既定の実行レベルを設定する
4. ブランチポリシーで、自動的にコードレビューを依頼する設定を確認する
5. プルリクエストを開き、右側の依頼欄から実行レベルを選んで依頼する（実際の完了には数分かかるため、完了済みのプルリクエストに切り替える）
6. 複数の提案を適用し、コミット時にコメントを自動で解決済みにする。解決者が表示されることを確認する
7. コメントを、個人、人、自動化ツールで絞り込めることを確認する

### 6.8 GitHub Advanced Security のデモ

1. 組織設定のリポジトリで、Advanced Security の設定を開く。シークレット保護プランをオンにし、Stripe や Terraform の API トークンの保存を防ぐ。AI で汎用のパスワードも見つけられるよう強化中
2. プッシュ保護をオンにする。開発者が API トークンを設定ファイルに入れ、「プッシュ前に Azure Key Vault へ移そう」と思いつつ忘れてプッシュしても、プッシュがブロックされ、ノートパソコンからクラウドに出ない
3. コードセキュリティのオプションで、依存関係アラート、マルウェアアラート、CodeQL の既定のセットアップ、セキュリティアラートの自動修正、カスタムセットアップ、独自のスキャンツールの持ち込みを確認する。組織、プロジェクト、リポジトリの順にオンにでき、CCR と同じ考え方
4. セキュリティの概要で、全プロジェクトとリポジトリのアラートを確認し、依存関係、コード、シークレットの各スキャンがすべての場所でオンかを見る。オンになっていない箇所は、チームに理由を確認する
5. 過去 90 日、特定のプロジェクト、重大度が重大のものに絞り込み、影響の大きいものから見る
6. リポジトリ単位でも確認する（Dan が作業しているリポジトリで、シークレットが数件見つかっている）。依存関係の一覧を、実行時と開発時で切り分ける。EPSS パーセンタイルで絞ると、「高」で扱いやすい件数になる。例として 84.7% の項目を開き、EPSS は今後 30 日以内に実際に悪用される確率の推定値だと説明する
7. 修正の生成ボタンを押す代わりに、すでに作成済みのプルリクエストを見る。GitHub Copilot が作成した修正で、説明が詳細に書かれている

## 7. 注意点・発表者の気付き

- **MCP サーバーの組織名**：組織名を入力しない場合は複数の組織にまたがって使えるが、指示文や呼び出しでどの組織かを指定しないと、どれを使うか分からない。
- **Cowork のスキル**：4 つ同梱したが、使っている人は多くないと認識している。
- **Copilot アプリの Azure DevOps 連携**：プレビュー中。作業項目の操作には、現時点で MCP サーバーの別途インストールが必要。デモ中にも、検索が遅い、操作が 1 度失敗するといった場面があった。
- **コードレビューの課金**：組織全体で有効にすると、大きな組織では多数のリポジトリに課金が及ぶため、慎重に使う必要がある。コミットごとの自動実行はコスト面で採用していない。
- **ELM の要件**：データレジデンシー付きの GitHub Enterprise Cloud が必要。
- **AI が書く説明**：Copilot が書いたプルリクエストの説明は詳細で、開発者が手で書くよりも丁寧になるという指摘がありました。
- **カスタム指示の質**：カスタム指示とスキルに適切な情報を入れるほど、望む結果に近づくという考えです。

## 8. 利用者にとっての利点

- リポジトリを移行せずに、既存の Azure Repos、作業項目、パイプラインで Copilot を使える。
- 技術者でない人も、Cowork や Copilot アプリから、Teams の会話を元にした作業項目の作成などができる。
- Dan の事例では、毎回 5〜20 分かかっていたバックログの整理を、オートメーションで 2〜3 分にまとめられた。
- Copilot のライセンスなしで、Azure サブスクリプションの課金だけでコードレビューを使える。コメントの一括適用と自動解決で、手間が減る。
- Copilot Autofix により、セキュリティアラートの修正を数分で支援でき、EPSS で優先順位を付けられる。
- GitHub への移行を希望する場合、ELM でダウンタイムを約 30 分に抑えられる。

## 9. まとめ

Azure DevOps は今後も続き、GitHub Copilot を AI エンジンとして組み合わせられます。VS Code での基本操作から、MCP サーバー（リモート版は 8 月に GA）、Copilot Cowork のプラグイン、GitHub Copilot アプリの Azure DevOps 連携（プレビュー、GA は来年初めの見込み）まで、使う人に合わせた入口が用意されています。製品内の機能としては、Copilot コードレビューが今週 GA になり、Copilot Autofix がパブリックプレビューで加わりました。リポジトリを GitHub に移したい場合は、GA 済みの ELM を使えます。
