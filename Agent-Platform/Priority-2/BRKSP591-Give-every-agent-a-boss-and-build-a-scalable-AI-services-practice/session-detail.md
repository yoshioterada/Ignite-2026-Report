# BRKSP591 Give every agent a boss and build a scalable AI services practice

## 1. はじめに

このセッションは、Microsoft パートナー（特に販売パートナーやサービス事業者）に向けた発表です。**「すべてのエージェントには上司（ボス）が必要であり、中堅・中小企業のお客様にとって、その上司の役割はパートナー自身が担える」**という考え方を軸に、AI エージェントの運用を事業機会として捉える方法を話しています。

構成は 3 部です。最初に Ingram Micro の発表者が、エージェントを取り巻く現状とパートナーの商機を説明します。次に Microsoft の発表者が、Microsoft 365 Copilot、Microsoft IQ、Agent 365 といったプラットフォーム側の機能を、「上司の仕事を支える道具」という視点で紹介します。最後に再び Ingram Micro の発表者が、上司の役割を 5 つの職務に分け、それを収益化する方法と Ingram Micro の支援内容を示します。

画面を使ったデモは行われておらず、スライドと口頭の説明が中心です。

### 5.2 プラットフォームの 3 つの柱

Sarita は、お客様がよく尋ねる 3 つの質問に沿って、「1 つのプラットフォーム」を説明しました。

土台には、オープンさ、モデルの多様性、異種混在の考え方があるという説明です。

### 5.3 Copilot にも上司が必要

Sarita は、スライドを作りながら、Copilot もエージェントの一種で、上司が要ると気づいたと話しています。Satya が火曜の基調講演で、Copilot は「仕事の新しいオペレーティングシステム」だと述べたこと、1 つの体験の中に 4 つのモードがあることを紹介しました。

- アシスト（支援）
- デリゲート（委任）
- ビルド（構築）
- オートメイト（自動化）

右へ進むほど、先回りして動く度合いと機能が増すため、上司の役割がより必要になります。Sarita は「オートパイロット」についても触れ、24 時間 365 日動き続け、独自の ID とツールを持つものだと説明しました。パートナーは、Copilot をエージェント型のソリューションとして運用する際にも、統制、検査、ガードレールの整備という機会があると述べています。

### 5.4 Microsoft IQ：エージェントに文脈を与える

Sarita は、新入社員のたとえで説明しています。新入社員にやることの一覧だけ渡して立ち去ることはしないはずで、この会社の仕事の進め方、チームの動き方、意思決定の仕方、すでに決まっていることを伝えるでしょう。エージェントにも同じ文脈が必要で、それを提供するのが各種の IQ です。

- Work IQ：メール、チャット、会議、すでに下された決定など、仕事のデータ
- Fabric IQ：ビジネスがどう運営されているか
- Foundry IQ：プロセスとポリシーの文脈（発話では「fabric foundry IQ」と聞こえますが、文脈から Foundry IQ のことと読み取れます）
- Web IQ とサードパーティの IQ：外の世界とつなぐ

これに Ingram Micro の IQ、お客様自身の IQ を組み合わせると、エージェントにとって非常に強力なインテリジェンス基盤になる、というのが Sarita の説明です。

### 5.5 モデルの多様性とルーター

Azure には 11,000 を超えるモデルがあると、今回のイベントで聞いたと Sarita は話しました。Microsoft は、使うモデルの配分を調整するルーターも提供しています。システムメッセージやユーザーメッセージなどの入力をもとに、簡単な依頼には最も高価なモデルを使わないようにする仕組みです。

プラットフォームがこの機能を提供しても、パートナーの役割は残ります。ルーティングがエージェントにとって最もコスト効率の良い結果になるよう、適切なポリシーを設定するのは上司の役割だからです。

### 5.6 Agent 365：信頼のための観測基盤

Sarita は、「AI だけではお客様の事業は変わらない。変えるのは、それを動かす仕組みと、それを率いる上司だ」と述べました。

昨年、Agent 365 を、すべてのエージェントのためのコントロールプレーン（統制の基盤）として発表した、と説明しています。しかしお客様からは、それだけでは足りないという声があったそうです。エージェントだけでなく、Copilot、さまざまな作業モード、そしてそれを作った人も見える必要がある、という要望です。セキュリティ担当は、エージェントが何にアクセスできるか、どう保護するかを知りたい。事業部門のリーダーは、コストと価値を知りたい。こうした観点で、Agent 365 を観測基盤として位置づけたと話しています。

上司のオフィスにたとえた 4 つの柱が紹介されました。

1. **見る**：見つけられなければ管理できない。Agent 365 では、エンドツーエンドで AI の状態を 1 つのプラットフォームで管理できる。
2. **統制する**：エージェントの所有者を設定し、権限と説明責任を構成する。
3. **守る**：リスクのあるエージェントを特定し、保護のためのガードレールと制御を設ける。
4. **事業価値**：上司の「役員室」にあたる部分で、従量課金の AI では「このエージェントにいくらかかっているか」「価値を出しているか」「ROI（投資対効果）をどう測るか」が最大の問いになる。

4 つめに関連して、火曜日にこのイベントで発表された **Agent 365 Business Analytics App for leaders** が紹介されました。事業部門のリーダーが、次のことをできるようにするアプリです。

- AI の消費と支出を把握する
- コストを事前に予測し、計画する
- 推奨事項に基づいて、AI の使い方を最適化する
- マネージャーに委任アクセスを与え、エージェントの価値とコストを管理させる

特徴は、**Teams の画面から使える**ことだと説明されました。Teams の利用者基盤の数字を挙げたのは、このためです。あわせて、この新機能は IT 担当者向けには Microsoft 365 管理センターでも利用できるようになる、とも話しています。

> 補足：発話では、これらが現時点で提供済みか、これから提供されるかの区別は明確ではありません。「発表した」「利用できるようになる（原文は is going to be available）」という表現が使われているため、提供時期の詳細はこのセッションでは確認できません。

### 5.7 エージェントを本番に出す前に必要なこと

数週間前に Irvine のオフィスで Ingram Micro と話し合ったことをもとに、Sarita は、エージェントを本番に出す前に整えておくべきものを次のように挙げました。

| 必要なもの | 内容 |
| --- | --- |
| 上司（オーナー） | エージェントに責任を持つ、名前が決まっている担当者 |
| 予算を持つ購入者 | 成果に対して対価を払う人 |
| データの責任者 | エージェントが許可されたデータにだけアクセスできるようにする |
| KPI | 成果や目標のないエージェントは作らない。現在の数字を基準に置き、価値を証明できるようにする |
| ガバナンス | ID、アクセス、制限、ガードレールを備え、安全な環境で動かす |
| 繰り返し使える展開方法 | お客様の最大の課題から始め、お客様が「この業務を生産的にしたい」と言う場面に向けてエージェントを作る |

最後に、Microsoft から Ingram Micro とパートナーへの約束として、上司が必要とするツールを備えたプラットフォームを提供し続ける、と述べています。

### 5.8 上司の 5 つの職務

Haley は、「良いマネージャーが行うことを、エージェントに当てはめる」ことが上司の仕事だと説明しました。

| 職務 | 内容 |
| --- | --- |
| 受け入れ（オンボーディング） | エージェントと ID を登録し、その仕事を定義する |
| 制限の設定 | 触れてよいデータ、ツール、操作、承認を決め、ガードレールを設定する |
| 監督 | 動きを見守り、挙動のずれ（ドリフト）やリスクを早期に見つける |
| 予算管理 | タスク単位、エージェント単位、お客様単位で消費を管理する |
| レビュー | 成果を測り、改善、再教育、あるいは廃止を判断する |

スライドの下部には、これらに対応する提供サービスが示されました。最初の 2 つ（エージェントの準備と展開、アクセスとポリシーの設計）は、**プロジェクト型**の案件です。残りの 3 つ（監督、予算管理、レビュー）は、**継続的なマネージドサービス**で、エージェントの成果を監視し、コストを抑え、事業が求める価値を出し続けているかを確認します。これが、拡大と更新につながると説明されました。

### 5.9 サービスの利益率

Haley は、サービスの種類別の利益率を次のように示しました。

| サービス | 利益率 |
| --- | --- |
| アドバイザリー、トレーニング、定着支援、変革管理 | 約 20〜30% |

| 運用管理（エージェント運用、FinOps、セキュリティ運用） | 約 40〜50%。継続的に発生 |

「アドバイザリーと展開は入口であり、エージェントの管理こそが、サービス事業で収益を生む部分だ」と述べています。出典は発話では語られていません。

### 5.10 Ingram Micro のフライホイールと Xvantage

Ingram Micro は、パートナーとともに、構築、拡大、運用の全段階を支援するとして、次のフライホイール（好循環）を示しました。

1. **インテリジェンス**：Ingram Micro のプラットフォームである Xvantage のインテリジェンスが起点。シグナルが需要とプリセールスの会話に変わり、どのお客様の準備ができているかが分かる。
2. **構築**：フォワードデプロイドエンジニア（FDE）が、難しいユースケースを共同で構築し、繰り返し使える型にする。
3. **拡大**：Ingram Micro が、パートナーと共同で、あるいはパートナーに代わって提供する。
4. **運用**：パートナーの管理下で動くエージェントを運用する。その利用状況が、次のシグナルになる。

（プラットフォーム名は「Xvantage」と「expandage」の 2 通りに聞こえます。音声認識の都合で表記が確定できません。ここでは Xvantage としました。）

「インテリジェンスから始める」のは、同社のモデルの大きな進化だと Haley は述べています。長年の流通は、発注書とベンダーカタログをつないで注文を処理する、システムをつなぐ仕事でした。それが、**システムをつなぐことから、インテリジェンスを組み合わせることへ**移っています。Xvantage の周りには、ベンダー、ハードウェア、ソフトウェア、エンドカスタマー、パートナー、サービス、ファイナンス、物流などがあり、それぞれのシグナルを組み合わせると、お客様が尋ねる前に、需要の行き先が分かるそうです。

Microsoft との組み合わせでは、Microsoft の IQ レイヤーと Ingram Micro のインテリジェンスを合わせます。すると、お客様が持つ環境全体と必要なものが見えて、どのお客様の準備ができているか、上司の職務のうち何が欠けているか、次に何をすべきかが分かるという説明です。これを Xvantage と同社の **MCP サーバー**を通じて、パートナーがすでに使っているツールに直接届けます。個別の連携を作る余力がないパートナーほど、効果が大きいとのことです。数字としては、**MCP サーバーを使っているパートナーは、使っていないパートナーの 4 倍の成長**を示している、と述べています。

### 5.11 フォワードデプロイドエンジニア（FDE）モデル

今年の Ingram Micro は、フライホイールのうち構築と拡大に投資しており、Microsoft と共同で FDE を提供するとのことです。

- 市場の FDE への投資は、AI が本番稼働するまで、お客様の現場にエンジニアを常駐させるものだが、そのモデルは大企業向けで、中堅・中小企業向けにはスケールしにくい。
- そこで、チャネル向けに作り直し、パートナーに対して FDE を展開する。難しいワークフローを共同で設計し、アーキテクチャ、運用手順書（ランブック）、運用能力を移転する。お客様と長期のサービスはパートナーが保持する。
- 成功の尺度は、複数のお客様に展開できる繰り返し可能な型を作ること。

### 5.12 パートナーの 3 つの関わり方

状況に応じて、次の 3 つがあると説明されました。いずれの場合も、お客様はパートナーのもので、パートナーが上司になります。

| 状況 | Ingram Micro の関わり方 |
| --- | --- |
| すでにチームがある | パートナーが率いて運用し、Ingram Micro が Xvantage のインテリジェンス、プログラム、資金で支える |
| 最初の成功体験が必要 | 自分たちで運用できるようになるまで、並走して一緒に実施する |
| チームより先に需要が出ている | パートナーのブランドで、パートナーに代わって実施する。その間にパートナーが能力を築く |

Haley は最後に、Microsoft がパートナーを支援する内容として、お客様の獲得、プロジェクトへの資金、成長に応じた支払いなどがスライドに示されていること、どれがどのお客様に当てはまるかを整理するのは自分たちの役割であることを述べました。

## 8. 利用者にとっての利点

発表で語られた利点は、主にパートナー（およびそのお客様）にとってのものです。

- パートナーは、再販に加えて、運用管理サービスを継続収益として得られる。運用管理の利益率は約 40〜50% と示された。
- 中堅・中小企業のお客様は、エージェントを管理する人材がいなくても、パートナーが上司として運用を引き受けられる。
- 事業部門のリーダーは、エージェントのコストと価値を Teams の画面から把握し、予測と最適化ができる（Agent 365 Business Analytics App for leaders）。
- パートナーは、Xvantage と MCP サーバーを通じて、どのお客様の準備ができているかというシグナルを、使い慣れたツールで受け取れる。MCP サーバーを使うパートナーは 4 倍の成長を示している。
- FDE モデルにより、アーキテクチャや運用手順を移転してもらい、お客様と長期のサービスは自分たちで保てる。

## 9. まとめ

エージェントは数も複雑さもコストも増えており、価値の置き場所は構築から管理へ移っています。**どのエージェントにも、方向を決め、仕事を確認し、結果に責任を持つ上司が必要**で、人手の足りない中堅・中小企業にとって、その上司はパートナーである、というのが発表の主張です。

Microsoft は、人（Copilot）、文脈（Microsoft IQ）、信頼（Agent 365）を 1 つのプラットフォームとして提供し、コストと価値を見るための Agent 365 Business Analytics App for leaders も加えました。Ingram Micro は、上司の 5 つの職務（受け入れ、制限の設定、監督、予算管理、レビュー）を、プロジェクト型とマネージドサービス型の提供内容にし、Xvantage、MCP サーバー、FDE モデルでパートナーを支援します。Haley の呼びかけは、最初のユースケースを持ち込んでほしい、一緒に作る、というものでした。
